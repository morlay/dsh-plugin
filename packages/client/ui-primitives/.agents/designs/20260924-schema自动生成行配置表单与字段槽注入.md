# 按 schema 自动生成行配置表单与字段槽注入（本包 client 半）

状态：已实现
范围：`packages/client/ui-primitives` 的 schema 表单那一面——接口面、槽契约、类型覆盖与装配；各插件如何把配置项交到
页面上（volatile 标注 + 现场读 + 字段槽文案）也在这里给判据。
约束：上游 `@deepseek-ai/*` 只读；跨插件协作只走 slots / cordis 服务；client 半是**普通 ESM 库产物**（随用到它
的 client 行内联，不是装配行）；UI 只消费官方 token 与 baseline 原语。

## 结论摘要

| 议题           | 结论                                                                                                                                    | 一句话理由                                                                        |
| -------------- | --------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------- |
| 表单从哪里长出 | 自动注册 `plugins.row.config`（keyed，`priority: 100`），key = `<bundle 包名>#<行 id>`；`autoGenerate` 且有 volatile 字段的行各生成一页 | 行配置页是既有落点；插件只标 `.volatile()`，客户端零代码                          |
| 与手写页的关系 | 手写项（默认 priority 0）遮住自动项，与加载顺序无关                                                                                     | slots 的 cell winner 是同 cell 最小 priority 的首个 live 项                       |
| 字段渲染       | 由 schemastery `schema.toJSON()` 树驱动，覆盖全部 `type`；`role` 给默认控件提示                                                         | schema 是 host 已投影好的唯一事实源                                               |
| 渲染形态       | 行式 JSON 结构视图：行号列固定、缩进只推内容；添加输入跟容器闭合括号同一行；值行内编辑（多行值自己长高）；行号可选中、行内可复制        | 与参考实现同形：结构一眼可见，编辑不离开这一行                                    |
| union 的呈现   | 按**选中变体**决定形状与值（数组画 `[`、标量画值行），行尾给变体切换：带 tag 的写标签值，无 tag 的写目标变体空值                        | 只按对象容器画，`access` 这类字段的值会整块丢掉                                   |
| 选择器         | 字段有候选（字面量集合的 `union`，或提示面 `select` 注册）就画下拉；`dependsOn` 声明的兄弟字段一变，投影时重算候选                      | 候选是运行期事实（选服务商 → 它的模型），schema 写不出来                          |
| 装配事实只读   | 想上页面又不可改的字段：`.volatile()`（进投影）+ `.disabled()`（页面只读）；给上游基类的那份配置先解包                                  | 复用 schema 的既有 meta，不新增 host 面                                           |
| 自定义输入     | chain 槽 `settings.schema-form.field`：业务方按 `role` 或 `ns+path` 路由，命中即用其组件与文案，未命中落默认控件                        | 一个机制同时承载「role 默认路由」与「path 精确覆盖」                              |
| 多行共享字段槽 | 字段槽的 children 声明收在 Factory `settings.schema-form.form` 上，行项经 `renderFactorySlot` 渲染                                      | 子槽声明 per key 只能一次，N 个行项逐行声明同 key 必冲突                          |
| 写盘           | 暂存 + 保存（复用上游 `SettingsForm` 与 shell 状态形状），按 path op 一次 `mutate` 并带 revision 栅栏                                   | 与现有卡片、上游表单外观一致                                                      |
| 文案           | 字段 key 驼峰拆词兜底；`meta.description`（可本地化）/`meta.comment` 作说明；业务方可经字段槽给 label/hint                              | 不动 host schema，也不引第二个数据面                                              |
| 外部原语       | 直接用 baseline 的 `@deepseek-ai/dsh-client-ui-primitives`                                                                              | 它在 devkit client baseline 里是 external，UI 与上游逐帧一致                      |
| 装配           | **不是装配行**：client 半随用到它的 client 行内联，`apply` 由那些行各自调用（按服务在场幂等去重）                                       | 取舍见 [ADR 基础面暂时内联而不是装配行](../adrs/20261001-暂时内联而不是装配行.md) |

## 事实基线

### host（settings 服务，只读上游）

- 表单 schema 是 volatile 投影：`volatileForm()` / `projectForm()`，secret 的 default 被剥掉、default 被
  redact（`vendor/deepseek-harness/packages/settings/settings/src/schema.ts:37-77`）。
- 客户端视图字段：`ns` / `schema` / `value` / `base` / `user` / `revision` / `autoGenerate` / `secrets`
  （`.../settings/src/types.ts:20-52`）。
- `autoGenerate` 来自插件的 `configure({ auto: false }, ctx.fiber)`，默认 true
  （`.../settings/src/index.ts:302-316`）；**当前没有任何客户端消费它**（全仓 `autoGenerate` 只出现在测试里）。
- 写盘：`mutate(ns, ops, expectedRevision)` 按 path 校验 `isVolatilePath`；`unset` 落在非数组父节点时回填
  继承值，落在数组索引上即删除该元素（`.../settings/src/index.ts:367-380`）。
- host 的 settings 描述只认带 `toJSON()` 的 schema（`.../settings/src/index.ts:425-427`），所以 Config 只能
  是 schemastery 之外无路可走（判据见「可调项上页面的判据」）。

### client（上游共享面）

- `ctx.configForms.get(ns)` → `ConfigForm`：`getSnapshot/subscribe` + `mutate/set/unset`（revision 栅栏、
  memory 模式下拒写）（`vendor/deepseek-harness/packages/client/ui-settings/src/client/config-form.ts:40-180`）。
- `ctx.configForms.describe()` → describe mirror 的 `getSnapshot/subscribe/ensure`
  （`.../ui-settings/src/client/settings-mirror.ts:37-60`）；`whileServed(namespaces, register)` 用于「服务了
  才注册」（`config-form.ts:280-310`）。
- `ctx.settingsSchema`：`rehydrate/validate/getPath/hasPath/setPath/deletePath`
  （`.../ui-settings/src/client/schema.ts:29-158`）。
- 上游表单原语：`SettingsForm`（不可用 / 只读 / 保存中 / 保存失败 + 保存按钮，离开页面丢弃草稿）、
  `SettingsValueField` / `SettingsSecretField`（`ui-primitives/src/settings-form/*`），均随 baseline 提供。

### slots（上游，只读）

- keyed cell 的 winner = 同 cell 最小 priority 的首个 live 项（`ui-slots/src/index.ts:1221-1228`、`1342-1362`）。
- children 声明 per key 只能一次，第二次抛 `already declared`（`index.ts:1229-1234`）。
- 渲染子槽的授权按注册项自己的 `children`（`ui-renderer/src/client/scoped-slots.tsx:75-110`）。
- Factory：`renderFactorySlot` 对每个 renderer-created 组件可用（`ui-slots/src/index.ts:494-497`、`609`），
  Factory 的 children 授权其组件渲染子槽（`scoped-slots.tsx:128-130`）。
- 落点契约：`plugins.row.config` keyed by `<包名>#<行 id>`
  （`ui-plugin-manager/src/client/slot-contract.ts:96-102`、`config-ledger.ts:30-38`）；行 id 即 settings
  namespace（`BundleInfo.rows[].rowId`，`vendor/deepseek-harness/packages/boot/plugin-manager/src/types.ts:35-44`）。
- 字段文案的本地化可用 `ctx.locale.resolveText(LocalizedText)`
  （`vendor/deepseek-harness/packages/client/locale/src/client/index.ts:209-219`）。

以上 `ui-*` 与 `settings` 路径的前缀都是 `vendor/deepseek-harness/packages/{client,settings,boot}/`。

### schemastery（只读）

- `type` 全集：`is` / `any` / `never` / `const` / `string` / `number` / `boolean` / `bitset` / `function` /
  `array` / `dict` / `tuple` / `object` / `union` / `intersect` / `transform`（`defineMethod` 表，
  `vendor/deepseek-harness/vendor/schemastery/src/index.ts:924-960`）；`lazy` 由 `Schema.lazy` 造（`:576-584`）。
- `natural()` = number().step(1).min(0)；`percent()` = number().step(0.01).min(0).max(1).role('slider')；
  `date()` = union(is(Date), transform(string().role('datetime'), …))（`:588-600`）。
- meta：`default/required/volatile/disabled/collapse/badges/hidden/loose/role/extra/link/description/comment/pattern/max/min/step`（`:112-136`）。
- `validateVolatileSchema` 不许 volatile 出现在数组项、dict 值、union 成员里，也不许祖先链上再有 volatile
  （`:488-509`）。

### 接缝

**槽契约**（本包 client 入口声明合并，[`slot-contract.ts`](../../src/client/schema-form/slot-contract.ts)）：

```
SlotMap:
  'settings.schema-form.field': { kind: 'chain'; scope: 'root'; owner: SchemaFieldOwnerProps }
SlotFactoryMap:
  'settings.schema-form.form': {
    scope: 'root';
    props: SchemaFormProps;
    children: { 'settings.schema-form.field': { kind: 'chain'; scope: 'root' } }
  }
```

- `SchemaFieldOwnerProps`：`ns`、`path`（string[]）、`node`（类型摘要：`type` / `role` / 枚举值 / 界限 /
  secret / 只读原因）、`label`、`hint`、`value`、`overridden`、`invalid`、`disabled`、`onChange(value)`、
  `onReset()`。
- 注册项形状：`ctx.slots.register({ name: 'settings.schema-form.field', select, priority?, inject?, locale? }, Component)`。
  `select(owner)` 返回 `matched | null`（`null` 才是不认领，`undefined` 不是）；命中组件收到 `matched`。
- 兜底：`renderSlotChain('settings.schema-form.field', owner, { fallback: <默认控件/> })`。

**自动注册面**（[`rows.ts`](../../src/client/schema-form/rows.ts)）：

- 数据：`ctx.configForms.describe()` 的 namespaces × `ctx.remote.pluginManager.listBundles()` 的 `name` ×
  `rows[].rowId`。
- 条件（全部满足才注册）：`view.autoGenerate === true`；`rows[].rowId === view.ns`；schema 可 rehydrate；
  顶层是 object。
- 注册：`priority: 100`（`FALLBACK_PRIORITY`）的 keyed 项，key = `<bundle 包名>#<ns>`，
  `locale: 'settings.schema-form'`，`inject` 面给该行的控制器 hooks 与动作。
- 注销：mirror 或 bundle 列表变化时按集合差分（`ctx.effect` 管理生命周期）。

**表单模型与控制器**（本包自有面，[`controller.ts`](../../src/client/schema-form/controller.ts)、
[`draft.ts`](../../src/client/schema-form/draft.ts)）：

- `SchemaFormController`（per ns）：`face()` 给出 `{ hooks: { schemaForm: Store<RowFormState> }, ...actions }`，
  `dispose()` 释放订阅。
- 草稿编辑面：`edit(path, value)`、`resetField(path)`、`appendItem(path)`、`removeItem(path)`、
  `addKey(path, key)`、`removeKey(path, key)`、`save()`、`discard()`。
- 状态：`shell()` 给出上游 `SettingsFormShell` 同形状态（`available/writable/dirty/invalid/saving/failed`），
  由此直接喂上游 `SettingsForm`。

**出口**（[`client/index.ts`](../../src/client/index.ts)）：

- `.`：host 半空 `apply` + `findReferences` / `parseReferenceToken`（引用解析的 host 面）。
- `./client`：`apply` + 槽契约类型（`SchemaFieldOwnerProps` / `SchemaFormProps`）＋ `SchemaFieldDefault`；
  schema 表单那一面以命名空间 `schemaForm` 具名导出（`export *` 会与 settings-form 的样式 / token 重名）。
- `./locale/*.json`（插件清单文案）。

**装配**：本包**不是装配行**——client 半是随消费行内联的普通 ESM 库（清单标 `dsh.client.inline`），`apply` 由
内联它的 client 行各自调用、按服务在场与否幂等去重。落点与取舍见
[ADR 基础面暂时内联而不是装配行](../adrs/20261001-暂时内联而不是装配行.md) 与[本包 README](../../README.md)。

- 业务方要注入字段：`ctx.slots.inject('settings.schema-form.field', () => ctx.slots.register(...))`，并在自己的
  `dsh.client.inject` 里列本包名（保证 Factory 的 children 声明先到位）。

### 类型覆盖

| schema 节点     | 默认呈现                                      | 备注                                                                                                    |
| --------------- | --------------------------------------------- | ------------------------------------------------------------------------------------------------------- |
| `object`        | 字段分组；`collapse` 默认折叠                 | 嵌套按 path 递归                                                                                        |
| `dict`          | 键值列表，键按 `sKey` 校验                    | 增删键                                                                                                  |
| `array`         | 可增删列表（`inner` 逐项渲染）                | 删项发 `unset`（host 语义即移除元素）                                                                   |
| `tuple`         | 定长逐项                                      |                                                                                                         |
| `string`        | 文本输入                                      | `pattern` 提示；`role: 'secret'` 走密码控件（写才生效）；`role: 'datetime'` 走日期时间；`hidden` 不渲染 |
| `number`        | 数字输入（`step` 决定整数/小数；`min`/`max`） | `role: 'slider'` 走滑块                                                                                 |
| `boolean`       | `Switch`                                      |                                                                                                         |
| `bitset`        | 位名复选组                                    | 值为位组合的 number                                                                                     |
| `const`         | 只读值                                        | 不可编辑                                                                                                |
| `union`         | 字面量成员 → 选择器；对象成员 → 判别式选择    | 判别键取成员里唯一的 const 字段                                                                         |
| `intersect`     | 合并成员字段渲染                              |                                                                                                         |
| `transform`     | 只读展示（`inner` 的类型摘要）                | `callback` 不可逆                                                                                       |
| `any`           | JSON 文本（可编辑，写 JSON 值）               | 非法 JSON 视为非法草稿、阻止保存                                                                        |
| `never`         | 不渲染                                        |                                                                                                         |
| `function`/`is` | 只读                                          | 不可序列化                                                                                              |
| `lazy`          | 按 `uid` 解引用共享节点；递归引用限深         | 防渲染循环                                                                                              |

### 行式视图

配置页是**行式 JSON 结构视图**（不是逐字段的上下表单），行由 `editorLines()` 产出
（[`lines.ts`](../../src/client/schema-form/lines.ts)）：

```
 1 │ {
 2 │   // 新会话用哪个模式
 3 │   default: "coding"
 4 │   modes: {
 5 │     coding: {
 6 │       // 能用的工具
 7 │       allowTools: [ "read" ]      ← 闭合行自带添加入口
 8 │     }
 9 │   }
10 │   models: {}                    ← 还没配的键在这个入口的候选里
11 │   access: [ ]  ▾                ← 值本身就是下拉的触发
12 │   cwd: "/Users/morlay/repo"     // 相对路径的基准目录 · 只读
13 │ }
```

- **出现哪些字段**：必填字段始终占行（值还没有也看得见"必须填"）；非必填的按值出现——值里没有就不占行，
  它出现在所在容器闭合行的添加入口候选里，选中才加成。判据只有一条：**`undefined` = 这一层没有这个字段**
  （不渲染，去候选里）；**`null` = 有字段、值还没填**——那一格直接是一个等着输入的位子。加进来的项初值因此
  是：有默认值给默认值、容器给空的容器、其余标量给 `null`；host 侧也认这个语义。
- **行**：行号 + 折进 + `key: value`。缩进只作用在行内容上（行号列固定在左边，第一层就缩进一格）；容器是
  `{` / `[` 的开启行与 `}` / `]` 的闭合行，可折叠（`collapse()` 决定默认，点 chevron 反转）。点行号选中这一行。
- **改过的行看得出来**：本页改了还没保存的字段左边一道强调色，悬停里是「撤回」；已经存进用户层的用一道浅灰，
  悬停里是「恢复默认」。两种状态之外还有「复制」与成员行的「移除」。
- **值**：语法色 token（字符串带引号、数字、布尔、`null`），点开即改——点开后行里只留输入框：官方 `Input`，
  旁边常显确认（✓）/ 取消（✕）；Enter 提交 / Esc 撤销同理；带换行的值给同一观感的多行输入。非法输入在行内
  给出消息并挡住保存。细线与描边取官方那档变量（`var(--dsw-elevation-stroke-color)`）。
- **行内文本都不撑宽（注释 / 校验消息 / 值）**：三处的盒子都带 `min-width: 0` + `overflow: hidden` +
  `text-overflow: ellipsis`——注释（`LineComment`）与它同一位置上的行内校验消息（`LineInvalid`）是 `flex: 1 1
  auto` / `flex: 0 1 auto`，值的位置是 `ValueSlot`（`flex: 0 1 auto`，不生长：短值保持自然宽度，不被拉伸也不被
  压短）。行里其余项（键名、结构符、动作按钮）都是 `flex: none`，所以长文本在行内收缩并截断，不会把整行与表单
  壳撑宽。真几何在浏览器里量过（jsdom 没有布局）：窗口 760 时行 `client = scroll = 664`，长注释 `584/894`、
  长校验消息 `584/757`、长值 `487/893`（前者可用宽度、后者内容宽度，都截断）；窗口 1100 时行 `960/960`，长注释
  `880/894` 截断、长校验消息 `757/757` 与值槽 `783` 放得下就不截。
  **官方 `Tooltip` 不在 DOM 里加包裹层**（它返回克隆后的子元素 + 挂 body 的气泡），注释位元素因此仍是行 body 的
  直接 flex item，上面这些声明都落在它自己身上——这条同样在浏览器里核对（`parentElement` 就是 `[data-role=body]`）。
- **注释行**：`// …` 画在对应行上方——`description` / `comment` 与业务文案（提示面给的 label/hint），以及
  「只读」这类一眼看不出的状态；「已覆盖」不在这里（它是行尾那个「恢复默认」按钮的事）。
- **只有被截断的文本才挂官方 `Tooltip`**：注释位（含行内校验消息）与值被 `ellipsis` 截断时，全文由 baseline 的
  `Tooltip`（`side: bottom` + `portal`，浮层挂 body 以躲开面板裁剪）承载；放得下就一个浮层也不挂
  （[`TruncatedTooltip.tsx`](../../src/client/schema-form/TruncatedTooltip.tsx)）。判据是**元素自己的几何**——
  `scrollWidth > clientWidth` 才叫「被截断」，不用字符数之类的估计；宽度变化由 `ResizeObserver` 盯着那个元素重测
  （窗口、面板、字段槽都会改变元素宽度），盒子没变、只是换了内容（值改了、注释换了）时每次提交再重量一次。没截断
  时走 `Tooltip` 自己的 `disabled` 而不是「不渲染 `Tooltip`」：页面表现等价（气泡不进 DOM、hover 也不弹），但
  `disabled` 不换锚元素——按截断与否切换包裹层会在状态翻转时把锚重挂一遍。原来只挂原生 `title`，而真机悬停
  **没有出现任何详情浮层**；DOM 与命中侧都不成立：`title` 就在被 `ellipsis` 截断的那个元素上（浏览器里
  `elementFromPoint` 命中的正是它），行内没有元素遮住它，祖先也没有 `title` 覆盖它——原生 `title` 在本环境无法
  复现，所以改由官方原语承载。hover 的目标就是那处被截断的元素，气泡里是同一份全文（值用显示态的 token 文本，
  与行里看到的一致）；注释行（含行内校验消息）、添加入口的候选说明、值都走这一套。
- **secret 位不在这套里**：那一格显示的是「已配置」的 `••••••`（不会截断），`owner.hint` 是说明而不是「被截断文本的
  全文」，按口径不该弹气泡——那里回到非侵入的原行为：挂原生 `title`，不挂浮层。判据（三处盒子的可收缩契约 +
  截断与不截断两种状态下的气泡）落在 `src/client/__tests__/editor.spec.tsx` 与 `src/client/__tests__/value.spec.tsx`。
- **添加入口跟容器的闭合括号同一行**（输入框与行内编辑同一观感）：对象列的是还没配的声明字段（带说明），
  字典列的是业务注册的候选键（也能自己敲键名），数组是「追加一个空项」；粘一整段 `{…}` / `[…]` 则整层覆盖。
  对象只认 schema 声明过的字段——敲一个没声明的键不会被写下去（host 也会挡）。
- **选择器**：字段有候选（字面量集合的 `union`，或提示面注册的候选值）时，值本身就是下拉的触发，点开是官方
  菜单；候选依赖的兄弟字段一变就换一批。
- **变体切换**：`union` 的字段行尾给一个小触发——判别式 union 挂在标签行上（`type: "sqlite" ▾`，切到
  `postgres` 就换一整套字段），没有标签的按值的形状切（`access` 在 `[ ]` 与 `""` 之间）。
- **只读字段**：`.disabled()` 的字段（装配事实这类）照常画出值、注释里标「只读」，但点不开编辑。
- **控件都是官方的**：行内输入用 `Input`、下拉与候选用 `Menu`，视觉与键盘行为跟设置页其余部分一致。

### 提示面：文案、候选键、候选值

业务知道、schema 表达不了的三类信息都放这里（`ctx.schemaFormHints`，
[`hints.ts`](../../src/client/schema-form/hints.ts)）：**字段文案**（`describe`，行式视图画成注释行）、
**dict 的候选键**（`suggestKeys`，进的是这一层添加入口的候选）、**字段的候选值**（`select`，字段画成选择器）。
三类注册都按路径定位，路径里的动态段写 `*`（模板路径）就覆盖每个模式、每个键；精确路径优先于模板。

```ts
const hints = ctx.get("schemaFormHints");

// 文案
hints?.describe("session-mode", ["models", "*", "provider"], () => ({
  label: "服务商",
  hint: "providers 里的键",
}));

// dict 的候选键（取到清单之后再注册，注册本身会通知一次）
hints?.suggestKeys("session-mode", ["models"], () => roster.modes.map((row) => row.id));

// 候选值：`dependsOn` 里声明的兄弟字段一变，候选就重算
hints?.select("session-mode", ["models", "*", "model"], {
  dependsOn: [["provider"]],
  options: (read) => modelsOf(read(["provider"])),
});
```

读数必须**同步**（投影发生在渲染帧里）：异步来源（HTTP / remote）由业务自己取好再注册；数据变了但没重新
注册时主动调一次 `hints.refresh()`。选模型那一套（provider 目录 + 模型清单）的落点见
[`dsh-session-mode`](../../../../profile/dsh-session-mode/README.md)。

**按 role 认领的候选源**：字段自己说清"这是什么选择"，业务不去记行 id 与路径——schema 上写
`role('select', { source })`，客户端注册那个**具名源**（源可以被多行、多个字段复用）：

```ts
// schema 侧
provider: z.string().role("select", { source: "llm-providers" }),
model: z.string().role("select", { source: "llm-models" }),

// client 侧（一次注册，两个源各管一件事）
hints?.source("llm-providers", { options: () => providers.map((p) => ({ value: p.id })) });
hints?.source("llm-models", {
  dependsOn: [["provider"]],
  options: (read) => modelsOf(read(["provider"])),
});
```

`kind` 是 `unknown` 的值、字段名换了行，源照样对得上——认领靠 role，不靠 `ns + path`。没写 `source`、或那个
源没注册时，退回按路径登记的那份（`hints.select(ns, path, …)` 仍然有效）；两者都没有就还是文本编辑。

### 声明自定义属性

schemastery 的自定义属性位是 **`meta.extra`**（`any`），公开设置方法是 `.role(名字, extra)`——上游自己也这么用
（`percent()` 给 `role: 'slider'`、`regExp()` 给 `role: 'regexp'` + `extra.flag`）。本包认的两个约定都走这个通道：

```ts
z.array(z.object({ id: z.string() })).role("items", { mergeKey: "id" }); // 数组项的项身份
z.union([z.object({ kind: z.const("a") })]).role("union", { tag: "kind" }); // union 的判别标签
```

约束：自定义属性要能被 JSON 序列化——host 发的是 `schema.toJSON()`（`JSON.parse(JSON.stringify(...))`），函数会
静默消失、`Map`/`Set` 变成 `{}`、循环引用会抛。所以 `extra` 里只放数据（字符串、数字、纯对象）。

想注册**自定义类型**（新的 `type` + 解析器）是另一件事：`Schema.extend(type, resolve)`，进程级全局注册。

### 可调项上页面的判据

页面上的可编辑面只有一种来源：**插件行 `Config` 里标了 `.volatile()` 的字段**（host 的 `volatileForm()` 只投影
这些分支）。所以「这个插件可配」要成立，三件事缺一不可：

1. **字段在行 `Config` 的固定对象路径上**：`validateVolatileSchema` 不许 volatile 出现在数组项、dict 值、union
   成员里，也不许祖先链上再有 volatile（`vendor/deepseek-harness/vendor/schemastery/src/index.ts:488-509`）。要整段
   可编辑就把那个容器字段（数组 / dict）自己标 volatile，表单再按索引与键写元素。
2. **生效靠 Loader 重挂这一行**：settings 写完经 `reconcileProfilePatches`
   （`vendor/deepseek-harness/packages/boot/app-boot/src/index.ts:271-296`）更新根 Include 的 config 并
   `ctx.loader.await()`，被改的行**重新 apply**，于是"改配置 = 用新 config 重装"。所以插件不必在运行期反复读
   volatile 引用：装配时取一次快照即可；要在**不重挂**的前提下改（长生命周期对象、或重挂代价大的行）才需要现场
   读 `.get()`（provider / 沙箱规则属于这类）。
3. **装配期决定的项默认不进页面**：能力清单、转换数据、工具行清单这类改了要重挂、页面上又没有判断
   依据的，留在配置文件里。要只读可见就用 `.volatile().disabled()`：`volatile` 让它进投影，`disabled` 让页面
   只画值不给编辑——代价是解析后的值变成**引用**（`.get()`），所以交给上游基类的那份配置要先解包
   （`upstreamConfigOf`，落点见 [`dsh-sandbox-local`](../../../../sandbox/dsh-sandbox-local/README.md)）。

另外两处限制：**Config 只能是 schemastery**（host 的 settings 描述只认带 `toJSON()` 的 schema，
`vendor/deepseek-harness/packages/settings/settings/src/index.ts:425-427`，客户端再用 `new Schema(json)` 重建，
所以别的校验库写的 Config 进不了这扇门；loader 写回配置时另用 `Config.simplify`，
`vendor/deepseek-harness/vendor/loader/src/index.ts:117`）；**能当页面根的**只有对象段、相交段（判别式那种）与带
tag 的 `union`（成员都是对象），字面量 `union`（整段是标量）会把写盘变成整段替换。host 的 `volatileForm` 只认对象段
与顶层 volatile，所以判别式行 Config 要写成 `z.intersect([...]).volatile()`（或包一层 `z.object`）才会被描述出来
——原因与销账条件见[债务 判别式行 Config 要靠顶层 volatile 才被 describe](../debts/20260924-判别式行Config要靠顶层volatile才被describe.md)。

按这三条落到各包：

| 行                      | 上页面的字段                                                                                                                  | 说明                                                                                                            |
| ----------------------- | ----------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------- |
| `web-search-ollama`     | `apiKey` / `apiKeyEnv` / `baseURL` / `maxResults`                                                                             | provider 用 getter 现场读引用                                                                                   |
| `sandbox-local`         | `access` 可改；`runnerCommand` / `runnerFailureSignatures` / `probeTimeoutMs` / `cwd` / `diffBasisMaxBytes` 只读              | 规则按当前 access 重算；五个装配事实只读可见（上游基类拿解包后的值）                                            |

| `session-mode`          | `default` / `modes`（各模式的 `defaultModel` 是里面的可加字段；顶层 `models` 是退役形状，配了在装配期报错）                   | 各模式默认模型是选择器：候选来自部署里的 LLM 目录                                                               |

## 取舍

| 选项                                                    | 为什么否掉                                                                          |
| ------------------------------------------------------- | ----------------------------------------------------------------------------------- |
| 每个插件自写卡片（`plugins.row.config` 一项一份）       | 同一套 schema→控件逻辑复制 N 份，字段增删要改 N 处                                  |
| 注册到 `settings.plugins.tab`（设置页 Plugins）         | 与现有卡片落点不同，且要再造一份入口；行配置页才是「这一行的 Config」的位置         |
| 字段槽的 children 声明放在每个行注册项上                | slots 硬约束：同一 key 只能被声明一次，N 个行项必冲突                               |
| 让业务方各自声明字段槽                                  | 声明权与渲染授权绑在注册项上，业务方无法为别人的行声明                              |
| 用 cordis 服务承载字段文案或自定义控件                  | 跨插件 value import 被 client bundle purity gate 禁                                 |
| 用本包 fork 过来的设置表单原语（`styled` + `dsw` 那套） | 那份是为「fork 包源码直接加载」而搬的；这一面用 baseline 原语更省，且 UI 与上游同源 |
| 即时写（控件变更即 mutate）                             | 与上游表单框形态不符；高频字段会产生多次写与多次 revision 栅栏失败风险              |

## 开放问题

- 数组项重排与字典键重命名：只做追加与删除（键名只读显示）。
- 字面量 `union` 顶层的 `Config`（整段就是一个标量）：写盘会变成整段替换，暂不支持。
- 判别式行 Config 必须靠顶层 `.volatile()` 或包一层对象才被 host 描述出来（两处根形状判据不同宽）：见
  [债务 判别式行 Config 要靠顶层 volatile 才被 describe](../debts/20260924-判别式行Config要靠顶层volatile才被describe.md)。
- 选择器只覆盖「候选是已知清单」的情况（字面量集合或提示面读数）；要触网发现候选（问端点有哪些模型）得由业务包
  自己取好再注册，本包不做异步。
- 变体切换只写「那一支的代表值」：无标签的 union 写目标变体的空值，用户可能还要再补字段——不做逐字段的迁移
  （把旧支的值搬到新支）。
- `autoGenerate` 有 host 侧的写面但没有客户端消费点：多行共享一份表单时按什么粒度关掉自动页，还没定。
