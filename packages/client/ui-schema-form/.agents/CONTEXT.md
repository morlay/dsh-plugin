# 插件配置表单（schema 生成）

把一个 profile 行的 `Config`（只取标了 `.volatile()` 的那部分 schema）渲染成那一行的配置页，并把字段级的
自定义输入开放成一个 chain 槽。它只在浏览器半：host 侧的事实（schema 投影、共享配置表单、schema 服务）都是
上游 settings 那套，本包不新增 host 面。边界见仓库根 `.agents/CONTEXT-MAP.md`。

## 术语

**行配置项**（row entry）：
本包为一行注册到 `plugins.row.config` 的那个槽位项，key 是 `<bundle 包名>#<行 id>`。它只是**入口**：页面
标题与描述来自包自己的 locale，项里画的是这张表单。

**页读数**（row form state）：
渲染层读的一份投影：表单壳状态（可用 / 可写 / 脏 / 非法 / 保存中 / 失败）、字段树、每个具体路径的草稿状态、
secret 槽的「已配置」标记。它与 `ctx.configForms.get(ns)` 的快照不是一回事：后者是 host 的读写两层，
页读数是「这些值加本页草稿」之后的渲染视图。
_避免使用_：表单状态（会与 shell 混淆）

**字段树**（field tree）：
schema 投影出的**结构**（`FieldNode`）：类型、路径、归一化 meta、只读原因。它不含值，也不含文案——值在草稿
模型里，文案在渲染时解析。
_避免使用_：表单 schema、字段模型

**动态段**（`*`）：
字段树里 dict 的值、数组的项这类「按值才有具体地址」的层级，投影时用 `*` 占位；渲染层按真实键或索引替换后
再交给字段槽。所以字段槽拿到的 `path` 总是具体路径。

**模板路径**（template path）：
提示面注册时写的带 `*` 的路径（`["models", "*", "provider"]`）：一次注册覆盖每个动态键。读侧按具体路径查，
精确路径优先于模板——业务不必知道运行期有哪些键。

**候选键**（suggested keys）：
某个 dict 字段"可能出现哪些键"的运行期清单（模式清单、可选 provider）。schema 是静态的、写不出来，所以由业务在
客户端注册同步读数（`ctx.schemaFormHints`）；表单一侧把"候选里有、值里没有"的键列为**可添加项**（就在 `models`
那一层闭合行的添加入口里），选中才加成——这是"已定义的配置看得见"的来源。

**可添加项**（addable）：
所在容器**声明了、非必填、值里又还没有**的那一项（对象的声明字段、字典的候选键）。它不占行，出现在容器闭合行
添加入口的候选里，选中才加成——「非必填的字段选着加、必填的直接显示」的落点。

**行**（editor line）：
配置页的最小单位：结构行（`{` / `[` / `}` / `]`）、字段行（`key: value`）、注释行（`// …`）。行序 = 视觉顺序，
行号即下标——渲染层只按行画，不递归。缩进只作用在行内容上（行号列固定），行内控件是官方的 `Input` / `Menu`。

**注释行**（comment line）：
画在对应行上方的 `// …`：schema 的 `description` / `comment`、字段槽给的 label/hint，以及「只读」这类一眼看不出的
状态。它不放"必填"这类结构信息（那是 schema 的常规），也不放「已覆盖」（那是行尾「恢复默认」按钮的事）。

**添加入口**（add input）：
跟在容器**闭合括号同一行**的输入框（外观与行内编辑同一套）：对象从**可添加项**里选（选中才加成，敲没声明的键不
写），字典能自己敲键名（也能从候选里选），数组是追加一个空项；粘贴 `{…}` / `[…]` 则整层覆盖。

**成员行**（member line）：
动态容器的成员（array 的项、dict 的键）在页面上自己的那一行：名字（项身份或 `#序号` / 键名）与移除按钮。
容器成员的名字画在它的标题行里，叶子成员另起一行——所以「哪个字段属于哪一项/哪个键」不必猜。

**未填位**（missing slot）：
值还是 `null` / `undefined` 的那一格——页面把它画成**等着输入的位子**，而不是一个空值的呈现。判断位只有一条：
`undefined` 是"这一层没有这个字段"（不渲染，进**可添加项**）；`null` 是"有字段、值还没填"。所以加进来的项初值
是：有默认值给默认值、容器给空的容器、其余标量给 `null`。

**草稿**（draft）：
本页尚未写盘的一处编辑。编辑只落在草稿上，`save` 是唯一的写盘点；保存时整段过一遍 schema 校验，被挡下的
草稿留在屏幕上。与 host 的「用户层」（user layer）区分：草稿在这台浏览器上，用户层在配置文档里。页面上两者
分得开：草稿是强调色竖条 + 「撤回」，用户层是浅灰竖条 + 「恢复默认」。

**覆盖**（overridden）：
这一字段的用户层里有条目——**presence 判据**，不是值比较：覆盖值恰好等于默认值也算覆盖。恢复默认就是让
用户层不再有这个字段。

**字段槽**（field slot）：
`settings.schema-form.field`，chain 槽。注册项的 `select(field)` 按 `node.meta.role` 或 `ns + path` 认领字段，
命中即渲染它的组件；没人认领就渲染默认控件。同一个机制也能只给文案（拿默认控件包一层）。

**兜底 priority**：
自动项用 `100` 注册。手写卡片用默认 `0` 注册时，按 slots 的 cell winner 规则成为该 key 的赢家——两种页面
因此可以并存，迁移不必一次做完。

**项身份**（mergeKey）：
数组成员的「名字」取自它自己的哪个字段：显式声明（`role('items', { mergeKey })`）优先，否则 item 上的 `id`。
它决定页面上的项标题与「同一层不重名」的本地校验；**写盘仍按索引**（host 的 path op 没有按身份寻址的语义）。

**判别标签**（tag）：
union 按哪个字段的值挑变体：显式声明（`role('union', { tag })`）优先，否则所有对象成员共有的唯一常量字段。
schemastery 没有 tag 机制（union 按声明顺序逐个试），所以标签是渲染与校验层的约定。

**变体切换**（variant control）：
union 字段行尾的那个小下拉：带标签的挂在**标签行**上（选它等于写标签值），没有标签的按值的形状切（写目标变体的
空值）。它也是 union 的**形状依据**——`access` 的 `[ ]` / `""` 就是当前落在哪一支。

**候选值**（select spec）：
某个字段"可以选哪些值"的运行期读数（业务经提示面 `select` 注册）：字段据此画成下拉；`dependsOn` 里声明的
兄弟字段一改，投影时就用新值重算候选——「换服务商就换模型清单」即此。字面量集合的 `union` 自带候选，不用注册。

**只读字段**（read-only fact）：
标了 `.disabled()` 的字段：值照画、注释标「只读」，但不给编辑入口。装配事实（进程 cwd、runner 命令这类）用它
上页面——`volatile` 让它进 host 的投影，`disabled` 让页面只读。

**只读原因**（readOnly）：
节点不能编辑的原因：`transform`（callback 不可逆）、`function`、`constructor`（`is` 判定）。`const` 不是原因，
它是类型本身。

**递归收口**（recursive 节点）：
自引用 schema 回到祖先的那一层：投影在那里停下，渲染成一行只读提示。
