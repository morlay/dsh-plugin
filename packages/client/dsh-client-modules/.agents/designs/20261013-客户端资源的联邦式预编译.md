# 客户端资源的联邦式预编译（开发态）

**一句话**：按「包 × 出口」请求触发一次转换——**输入是一个说明符**，**输出是一组文件**（JS / CSS / 资产 / chunk），浏览器按 `/@client-modules/<pkg>@<version>/<file>` 取。

## 分层总表

| 层     | 输入                                | 做什么                                                      | 输出                                           |
| ------ | ----------------------------------- | ----------------------------------------------------------- | ---------------------------------------------- |
| ① 请求 | `pkg`、`version`、`entry`（出口名） | 定位包根与清单；算说明符                                    | `pkg` / `pkg/sub`                              |
| ② 解析 | 说明符 + 解析根                     | 交给 rolldown 的 resolver（`exports` 条件、`main`、扩展名） | 落点文件（绝对路径）                           |
| ③ 分类 | 落点文件                            | 扩展名 + 最近 `package.json`                                | JS 模块 / CSS / 资产 / 数据                    |
| ④ 转换 | 落点文件                            | 按类型各走各的插件；JS 再定导出面                           | 产物字节                                       |
| ⑤ 输出 | 产物字节                            | 落盘 + 清单                                                 | `<entry>.js`、`chunks/…`、`assets/…`、CSS 文件 |
| ⑥ 服务 | 请求路径                            | 按清单取文件、按扩展名给 content-type                       | HTTP 响应                                      |

## ① 请求：只有一个键

- 地址：`/@client-modules/<pkg>@<version>/<entry>`；`pkg` 里的 `/` 转成 `+`，`entry` 是出口名 + `.js`（根出口是 `index`）。
- `version` 只是外置时写下的提示；**版本与出口一律以包清单为准**。
- 解析根：dev 是仓库根，打包形态是 profile 根（`$DSH_HOME/profiles/desktop`）。两者都**不用 `process.cwd()`**（桌面宿主 cwd 是 profile 目录）。
- 包根由 node 的解析得到（`packageRootOf`），**不猜 `.pnpm` 目录名**：工作区/闭包里 link 进来的包，目录名是 `file++++<路径>`，猜出来会把一串路径写进 URL。

## ② 解析：说明符交给 rolldown

- 入口是**说明符**：根出口 = 包名；子路径 = `包名/子路径`（`katex/dist/katex.min.css`）。我们**不写死"具体是哪个文件"**。
- 入口由调用方按清单解析（`exportTargetOf`：`exports` 键与条件 `import` → `default` → `require` → `types`；没有 `exports` 时 `module`（打包器约定，ESM）→ `main`）。
- **不用 rolldown 的 `this.resolve` 当入口解析**：在 `resolveId` 钩子里对裸说明符调用它，pnpm 的严格布局下返回 `null`（实测 `@deepseek-ai/cordis` 等全部如此），整条链会以 `UNRESOLVED_ENTRY` 失败。入口仍是"清单解析出的文件"，模块类型由同一份落点判。
- 解析不到就**报错**（404 + `unresolved-entry`），不回空模块。空模块只会把问题推成浏览器里一句没头没尾的 `does not provide an export named …`。

## ③ 分类：产物形态由落点决定

判定只看**入口文件的扩展名 + 最近的 `package.json` + （必要时）源码语法**（`moduleKindOf`），规则与
Node 的模块判定一致：

| 入口                                              | 类型     | 产物面                                                   |
| ------------------------------------------------- | -------- | -------------------------------------------------------- |
| `.mjs` / `.mts`                                   | `esm`    | 原样（见 ④.1）                                           |
| `.cjs` / `.cts`                                   | `cjs`    | default + 具名（见 ④.1）                                 |
| `.js` + `type: "module"`                          | `esm`    | 原样                                                     |
| `.js` + `type: "commonjs"`                        | `cjs`    | default + 具名（显式声明优先，不做语法检测）             |
| `.js` + 没有 `type`，源码有顶层 `import`/`export` | `esm`    | 原样（Node 的语法检测，`--experimental-detect-module`）  |
| `.js` + 没有 `type`，源码没有 ESM 语法            | `cjs`    | default + 具名                                           |
| `.ts` / `.tsx` / `.jsx`                           | `source` | 原样（转译面）                                           |
| `.css`                                            | `style`  | CSS 文本；被 JS 引用时构建期内联成"注入 `<style>`"的模块 |
| 图片 / 字体 / `.json` …                           | `asset`  | 原文件 / JSON 模块                                       |

**只有 `cjs` 需要导出面适配**；`esm` / `source` 一律原样，不补 default、不枚举具名。

**没有"CSS 特殊入口"这条规则**：入口是什么类型，产物就是什么类型。唯一与工具链有关的限制是 rolldown 的入口管线要求入口有 JS 文件名（虚拟 id 会在 oxc 解析时报 `filename must be … absolute path`），所以"包装入口"只在需要时存在，且必须是真实文件；这不是"CSS 是例外"，是"入口管线只吃 JS 文件"。

## ④ 转换

### ④.1 JS 模块

- **包内**（相对导入、同包引用）inline；**跨包**（裸说明符）external 成对方出口的 URL；node 内置走求值安全的空替身；装饰器固定 legacy；`process.env` / `import.meta` 按浏览器口径替换。
- **样式引用的例外**：`import "pkg/x.css"` 这类裸说明符**不能 external 成 URL**——浏览器把 `text/css` 当 ESM 模块加载会直接报 MIME 错误。联邦构建里先用 `dsh-css-specifiers` 把它解析成真实文件，再交给 `cssInlinePlugins` 在引用方内联；dev 链里 `depsUrl` 对 `.css` 返回 undefined，交给 vite 的 CSS 管线。
- **导出面 = 入口的忠实投影**：
  - **CJS 入口**：`default = module.exports` + 具名导出（求值枚举键；剔除 JS 保留字，`export const function` 是语法错误）。
  - **ESM 入口**：**原样**。入口没有 default 就不补——命名空间/默认对象的适配只属于 CJS 那一侧。
  - **仓库源码包**：原样。
- 消费方若对“只有具名的 ESM 包”写默认导入，那是消费方的问题：按具名面改（`rrule` 的消费方就是这么处理的，见 `rrule-namespace-import.patch`）。
- 入口补偿只在需要时做：CJS 判 CJS、ESM 判 ESM；判定看**解析落点的扩展名 + 最近 `package.json`**（`.mjs`/`.cjs`、`type`、`module` 字段），node 求值（`[object Module]`）只作兜底。
- **dynamic import**：交给 rolldown 拆 `chunks/`，文件名带内容 hash；块进清单，服务侧按 `chunks/` 前缀取。
- 拆分配下限（`advancedChunks.minSize/minShareCount`）：`import()` 该拆就拆，静态共享的小模块不值得各自一次请求。

### ④.2 样式

- JS 里 `import "x.css"` / `import styles from "x.module.css"`：构建期 inline 成"注入 `<style>`"的 JS 模块；`.module.css` 另导出 class map。**这条不变**。
- **直接请求 CSS 出口**：产物就是 **CSS 文本**，`content-type: text/css`；`url()` 资产按内容 hash 落到 `assets/<name>-<hash>.<ext>` 并改写成联邦地址。不包装成 JS、不注入 `<style>`。
- CSS 出口的入口解析走 **node**：rolldown 的 resolver 会先被样式插件接成虚拟 JS 模块，拿不到真实文件；这不影响"JS 入口由 rolldown 解析"。
- 入口/占位模块的虚拟 id **不能以 `.css` 结尾**：样式插件按后缀命中后会把它当真实文件读。

### ④.3 资产

- `threshold`：小图 inline（base64），大图落 `assets/<name>-<hash>.<ext>`，URL 指联邦地址。
- 文件进清单；路由只按清单服务（顺带挡住凭 URL 读任意文件）。

## ⑤ 输出：文件与清单

- 出口产物文件名 = `<出口名>.js`（`entryFileNameOf` / `exportNameOfFileName` 是**唯一**一处命名规则，地址生成与路由解析都调它）。
- `chunks/` 与 `assets/` 各有独立前缀：它们不是"包的出口"，没有源码对应文件；与出口共用一段 URL，服务端只能当出口、落空。
- `.files.json` 是"这个包产出里有什么"的**唯一真相**：键是文件名，值是相对缓存根的路径。

## ⑥ 服务与缓存

- 路由按清单取文件；content-type 按扩展名（JS / CSS / 资产）。
- 缓存按"这份产物还会不会变"分：三方包（`node_modules` 里，dev 期间不变）`public, max-age=31536000, immutable`；仓库内的包（随时可能改）`no-cache` + `ETag`；资产（文件名带内容 hash）`immutable`。
- 地址里的 `?v=` 是**构建器规则指纹**（`BUNDLER_REV`），一次会话内所有地址一致——同一个包只有一个 URL，多一个就多一份模块实例。
- **不用"目标包的内容指纹"做 `?v=`**：引用方写下的指纹会停在旧值，同一包出现两个 URL（react 的 `Cannot read properties of null (reading 'useContext')`）。内容变化交给协商缓存。

## ⑦ 缓存与失效

- 目录键：`<pkg>@<version>`（包级）；`.files.json` 按出口增量合并。
- `rev` = 规则版本（`BUNDLER_RULES`）+ **包根路径** + watch 指纹（与出口无关，同包各出口共享）。包跟着 app 换目录后，不会复用指向旧入口的 shim。
- 命中要求"指纹没变，且**这次要的出口都在**"；否则重建（指纹变了才整包作废）。
- 同一个包的构建**排队串行**：产物目录包级、重建会清理，首屏几十个请求同时飞会互相删产物。
- **改解析 / 改写 / 导出面规则就 bump `BUNDLER_RULES`**：否则旧缓存继续发上一世代的字节。

## ⑧ 两种形态

- **dev**：解析根是仓库根；开发模块逐文件走 vite（改它要 HMR），三方与 `dsh.dev.exclude` 点名的非开发模块走联邦产物。
- **打包 / `--prod`**：解析根是 profile（deploy 闭包）；一律走联邦产物，不读 `dsh.dev.exclude`。
- `--prod` 只装配 deploy 闭包并拿它当 profile/runtime；不跑整条 seed 装配，装配面剔掉 `.dsh-client-modules`。
- 闭包只有一份：`prepareSeed` 产出 `<buildCache>/deploy`，`afterPack` 原样复制到 `Resources/profile`；不再第二次 `pnpm deploy`（两次结果会不一致）。
- **两种形态都跑源码**：宿主入口按 node 解析取 `src/index.ts`；部署里不落 `dist` 载荷。

## ⑨ 现状差距（按本规则待收敛）

- ~~CSS 出口包装成 JS~~：已销账。CSS 出口产出 CSS 文本 + 资产改写；JS 里的 CSS import 仍内联。
- ~~入口双轨~~：**不成立**（已回退）。rolldown 的 `this.resolve` 在 pnpm 严格布局下解析不到裸说明符，不能当入口唯一真相；入口仍由 `exportTargetOf` 从清单解析，`moduleKindOf` / CJS 包装 / CSS 判定都用这份落点。- **文档旧条目已过时**：`declaresCjs`、用 `chunk.exports` 追加 `export default { … }`、给 ESM 入口补 default、把 CSS 入口当作"库模式限制的例外"，都不再是现行规则。

## 判据与坑

- 出口名 ↔ 产物文件名只有一处规则（`entryFileNameOf` / `exportNameOfFileName`）。
- 三方包的指纹看它的清单（`root/src` 对 `node_modules` 里的包常常是空目录，所有包会共用一个空哈希）。
- 上游包的指纹要同时看 `src/` 与 `lib/`：`exports` 的 `./typert` / `./remote` / `./client/typert` 指向 `lib/typert.*.ts`（`just vendor prebuild` 生成），只盯 `src/` 会让旧 descriptor 继续被浏览器拿到。
- 外置名单只有一个 home（`esmExternalRequirePlugin` 的 `external`）；顶层 `external` 不能再列同一个模块，否则插件整块跳过、产物里留下 `__require(...)`。
- 样式裸说明符要绕开外置名单（先在 `resolveId` 里解析成文件），否则浏览器会收到 `text/css` 的模块脚本。
- `@/…` 是仓库根的文件；不要写 `@/vendor/…` 或相对路径指到 vendor：开发态目录层级恰好吻合、闭包面深度对不上就解析不到。
- 版本元数据（`DSH_CLIENT_*`）先读宿主环境，再读 `<vendor>/.dsh-build/client-build-environment.json`，最后才现算。
