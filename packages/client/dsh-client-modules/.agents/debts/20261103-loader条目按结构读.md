# Loader 条目按结构读，不吃上游的类型面

**状态**：接受中。**触发**：上游升级（`dsh-plugin-upstream-sync` 的适配评估）。

## 是什么

`clientRowsOf`（[`src/index.ts`](../../src/index.ts)）的参数只声明 `{ entries(): Iterable<unknown> }`，
条目在循环里窄化成包内那四个字段（`disabled` / `fiber` / `options.name` / `parent.tree.ctx.baseUrl`）再读。
上游 `Entry` 的类型面不参与签名。

## 为什么接受

这条链读的是 cordis Loader 的**内部形状**（"装了哪些行"），上游每次重排 `Entry` 的类型都会让结构
签名报错：0.2.2-alpha.3（cordis-loader 4.0.6-alpha.2）把 `entries()` 的生成器参数换了一轮，
`Generator<Entry, void, void>` 就不再能赋给我们那份 `Generator<LoaderEntry>`，而我们读的四个字段一个没变。

代价说清楚：**类型层面失去了"上游改字段就报错"的保护**。字段改名 / 删掉只会在运行期表现为该行被跳过
（`clientRowsOf` 的每个 `continue` 都是静默的），症状是客户端少装配一块，而不是编译错误。想收这条债时
的姿势：显式依赖 `@deepseek-ai/cordis-plugin-loader`，用它的 `Entry` 类型做签名，并在包清单里声明这条
peer——那样每次上游改字段都会在 `just lint` 上红。
