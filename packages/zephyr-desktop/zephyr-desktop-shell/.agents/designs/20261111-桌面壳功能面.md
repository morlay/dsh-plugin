# 桌面壳功能面

状态：已实现（窗口与外观、自定义协议、preload 桥、目录选择器、快捷键桥、登录 shell 环境、调试面）；主进程的按键拦截与开发者菜单未做。
范围：`packages/zephyr-desktop/zephyr-desktop-shell/src/`：窗口、协议、preload、IPC 桥、环境与调试面。
非目标：业务页面与渲染（页面前端）、宿主的装配（归 `zephyr-app` 与 apps 的清单）、打包与签名（归 zephyr-desktop-bundle）。
关联：[设计 桌面两包与单进程壳](../../../zephyr-desktop-bundle/.agents/designs/20261110-桌面两包与单进程壳.md)、[设计 宿主装配面与 client-modules](../../../../zephyr/zephyr-app/.agents/designs/20261022-client-modules-重写.md)。

## 一、决定

| #   | 议题                       | 决定                                                                                                                                      | 一句话理由                                 |
| --- | -------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------ |
| 1   | 形态差异只走外部环境       | `ZEPHYR_DESKTOP_MODE` / `_DEBUG` / `_NO_SANDBOX` / `_USER_DATA` / `_URL` / `_WORKSPACE` / `_DATA_DIR` / `_HOST_ENTRY` / `_RESOURCES_ROOT` | 中间逻辑不为形态分叉，壳与宿主同一套跑法   |
| 2   | 协议特权在 ready 之前登记  | `registerSchemesAsPrivileged` 是启动前的动作                                                                                              | 过了 ready 就没机会了                      |
| 3   | 越界由协议层挡             | `resourcePathOf` 归一化 + `isInside` 二次校验，越界返回 `undefined`                                                                       | 自定义协议能读到什么，是这个壳的安全边界   |
| 4   | preload 用 ESM             | 与 `main.mjs` 同一条构建链；代价是 `sandbox: false`（隔离靠 `contextIsolation` + `nodeIntegration: false`）                               | sandboxed preload 只认 CJS，开了就加载失败 |
| 5   | 设备偏好的规则不重写       | 快捷键语义复用上游 `ShortcutPersistence`（读写、编辑、冲突判定都在它那儿）                                                                | 壳只做「原生侧的那一段」                   |
| 6   | 环境继承全量、日志只打数量 | 登录 shell 的环境整份并进来（缺的才补），日志说「补了几项」                                                                               | 登录 shell 里有凭证，日志不该带键名        |

## 二、现状事实

| 能力                 | 落点                                                                                   | 现状                                                                                                                                                                    |
| -------------------- | -------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 窗口外观             | `src/window.ts` 的 `windowFrameOf(platform)` / `windowOptionsOf(...)`                  | mac：`hiddenInset` + 红绿灯位 + 透明底；win / linux：`frame: false`（win 另给 `titleBarOverlay`）；`sandbox: false`、`contextIsolation: true`、`nodeIntegration: false` |
| 自定义协议           | `src/protocol.ts`（`SCHEME = "zephyr"`、`resourcePathOf`、`mimeOf`、`isInside`）       | 页面与资源从产物目录读；越界一律 `undefined`                                                                                                                            |
| preload 桥           | `src/preload.ts`                                                                       | `__DSH_DIRECTORY_PICKER__.pick()`（走 IPC，返回绝对路径或 `null`）                                                                                                      |
| 文档标记             | `src/document-marks.ts` 的 `markDocument(target, platform, titlebar = "hidden")`       | 写 `<html data-platform data-titlebar>`；侧栏折叠由前端按这两个属性做                                                                                                   |
| 目录选择器           | `src/app.ts` 的 `installDirectoryPicker` + `src/ipc.ts` 的通道名                       | 只认拥有窗口的 renderer、同一窗口的选择去重、窗口最小化先恢复再弹                                                                                                       |
| 快捷键（桥）         | `src/shortcuts.ts` 的 `installShortcuts({ electron, userData, getWindow, platform? })` | 读写 `shortcuts.json`、广播快照、录制中 `setIgnoreMenuShortcuts(true)`、`closeWindow` 三重判据（revision 一致、非录制、窗口在前台且可用）                               |
| 快捷键（主进程拦截） | —                                                                                      | **未做**：没有 `before-input-event` 的过滤，页面侧拿到的是原始按键                                                                                                      |
| 登录 shell 环境      | `src/shell-env.ts`                                                                     | 跑 `<shell> -ilc "env"` 全量继承，`mergeMissingEnv` 只补缺的                                                                                                            |
| 调试面               | `src/debug.ts` 的 `shellDebugOf(env)`                                                  | 只有 `ZEPHYR_DESKTOP_DEBUG=1` 才开（渲染进程 console 转发 + DevTools + 生命周期日志；错误永远输出）                                                                     |
| 失败上报             | `src/failure.ts`                                                                       | 启动失败走一条统一的出口（带事件名与原因），不留白窗口                                                                                                                  |

启动前必须处理的两个环境变量（`desktop dev` 与打包形态都要）：

- `ELECTRON_RUN_AS_NODE`：**摘掉**，否则 Electron 以 Node 身份跑（没有 `protocol`、没有窗口）。
- `NODE_OPTIONS`：**换成本仓库的 loader**（`@morlay/dsh-oxc-node`），不是摘掉——壳里要能 `import` 带类型语法的 `.ts`。pnpm 那份是 `@oxc-node/core/register`，它初始化要 `new Worker()`，Electron 的 V8 平台不支持，会崩在启动前。

## 三、模块边界与接口

| 模块                                                      | 拥有（职责与不变量）                           | 不拥有（明确排除）                             | 依赖方向                                                             | 接缝 / 适配器         |
| --------------------------------------------------------- | ---------------------------------------------- | ---------------------------------------------- | -------------------------------------------------------------------- | --------------------- |
| 窗口（`window.ts`）                                       | 各平台的框与标题栏形态、安全开关               | 页面内容；窗口内的业务                         | ← `electron` 的 `BrowserWindow` 面（`provide.ts` 的 `ElectronLike`） | 纯函数 + 声明面       |
| 协议（`protocol.ts`）                                     | URL → 产物路径的归一化、MIME、越界判据         | 产物怎么产生（zephyr-app 的联邦链）            | 无                                                                   | 纯函数                |
| preload（`preload.ts`）                                   | 暴露给页面的极薄面（目录选择）                 | 业务 IPC                                       | ← `ipcRenderer`                                                      | `contextBridge`       |
| IPC 桥（`ipc.ts` + `shortcuts.ts` + `app.ts` 的 handler） | 通道名、读写与广播、录制与关窗判据             | 快捷键的编辑规则（上游 `ShortcutPersistence`） | ← `electron`                                                         | 契约 `ShortcutsHost`  |
| 环境（`shell-env.ts`）                                    | 登录 shell 环境的采集与合并                    | 业务对某个变量的解释                           | ← 系统 shell                                                         | 纯函数（可注入 exec） |
| 文档标记（`document-marks.ts`）                           | 把平台与标题栏形态交给前端                     | 前端怎么用这两个属性                           | 无                                                                   | 纯函数                |
| 启动与生命周期（`app.ts` / `main.ts` / `failure.ts`）     | 协议登记、桥安装、dev 开窗、打包装配宿主、退出 | 宿主行树的装配细节                             | ← 上面各模块 + 闭包里的 `@morlay/zephyr`                             | —                     |

**接口**：`windowFrameOf(platform)` / `windowOptionsOf(...)`；`resourcePathOf(url, root)` / `mimeOf(file)` / `isInside(candidate, root)`；`installShortcuts(options): { dispose }`；`markDocument(target, platform, titlebar?)`；`shellDebugOf(env)`。
不变量：协议只读产物根内的文件；打包形态的 `cwd` 是 `Resources/runtime`；壳与宿主共用闭包里那份 `@morlay/zephyr`。

**深度**：删掉壳，页面就没有无标题栏窗口、越界安全的协议、目录选择与快捷键桥——这些都不是页面能自己做的事。

## 四、行为与边界

- 正常（dev）：`main.ts` → `app.ts` 装环境与桥 → 开窗口指向 `ZEPHYR_DESKTOP_URL`。
- 正常（打包）：`chdir(Resources/runtime)` → 从闭包解析 `bootstrapApplication` → 装配清单 → 等 http → 开窗口 → `window-all-closed` 时 `dispose` 并退出。
- 错误：启动失败经 `failure.ts` 统一上报（带事件名），窗口不会停在白屏。
- 取消：`window-all-closed` 是唯一的正常退出路径；`desktop dev` 把信号转发给壳。
- 并发：目录选择按窗口去重（同一窗口只开一个对话框）。
- 边界：快捷键录制中不拦键，且把菜单快捷键让给页面。

## 六、取舍

- 不采纳「宿主跑在独立子进程、走字节管道」：与单进程壳的取舍相反（见[桌面两包](../../../zephyr-desktop-bundle/.agents/designs/20261110-桌面两包与单进程壳.md)）。
- 不采纳「profile 种子 / 运行时归档」：本仓库不维护发布式 profile 体系。
- 不采纳「壳里 spawn 宿主的 shell 包装」：单进程不需要；终端类子进程由业务包自己 spawn，环境已由壳继承。
- 不采纳「mac 用 `ELECTRON_RUN_AS_NODE` 起 Helper.app 避免多余 Dock 图标」：单进程不 spawn 宿主，没有这个问题。

## 七、不做与已知债

- **主进程的按键拦截未做**：页面侧拿到的是原始按键；已绑定的快捷键目前不会在原生层被拦。要做的话判据来自上游那套状态机（已绑定、无冲突、无问题才拦；组合键按下与抬起成对处理；死键与 composing 放行；录制中不拦）。
- **开发者菜单未做**：dev 形态目前用 `openDevTools`（`ZEPHYR_DESKTOP_DEBUG=1` 时）。
- **桌面流载体未做**：单进程下页面直接 fetch 宿主即可。

## 八、开放问题

- 按键拦截要不要做、做到哪一档（只拦已绑定的、还是也接管菜单快捷键），未定。做之前先给一条可判定的用例（录制中不拦、组合键成对、死键放行）。
- 页面侧 `provideShortcuts()` 依赖 `window.dshDesktop.shortcuts` 存在：非桌面形态没有这个对象，目前靠「不装那一行」规避。要不要给一个空实现让清单统一，未定。
