# 桌面壳功能面

状态：已实现（窗口与外观、窗口状态、产品菜单、单实例、导航与外部链接、preload 桥、目录选择器、快捷键桥、登录 shell 环境、调试面）；主进程的按键拦截未做。
范围：`packages/zephyr-desktop/zephyr-desktop-shell/src/`：窗口与状态、菜单、单实例、导航、preload、IPC 桥、环境与调试面。
非目标：业务页面与渲染（页面前端）、宿主的装配（归 `zephyr-app` 与 apps 的清单）、打包与签名（归 zephyr-desktop-bundle）。
关联：[设计 桌面两包与单进程壳](../../../zephyr-desktop-bundle/.agents/designs/20261110-桌面两包与单进程壳.md)、[设计 desktop 功能面](../../../zephyr-desktop-bundle/.agents/designs/20261114-desktop功能面.md)、[设计 宿主装配面与 client-modules](../../../../zephyr/zephyr-app/.agents/designs/20261022-client-modules-重写.md)。

## 一、决定

| #   | 议题                       | 决定                                                                                                                                                   | 一句话理由                                               |
| --- | -------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ | -------------------------------------------------------- |
| 1   | 形态差异只走外部环境       | `ZEPHYR_DESKTOP_MODE` / `_DEBUG` / `_NO_SANDBOX` / `_USER_DATA` / `_URL` / `_WORKSPACE` / `_DATA_DIR` / `_HOST_ENTRY` / `_RESOURCES_ROOT` / `_DESKTOP` | 中间逻辑不为形态分叉，壳与宿主同一套跑法                 |
| 2   | 页面只有一条链             | 壳不注册自定义协议：页面来自壳自己的 http 源（dev 是工作区 dev server，打包形态是宿主同进程起的 vite）                                                 | 第二条链要在壳里再养一套 MIME 与越界规则，没有第二个收益 |
| 3   | preload 用 ESM             | 与 `main.mjs` 同一条构建链；代价是 `sandbox: false`（隔离靠 `contextIsolation` + `nodeIntegration: false`）                                            | sandboxed preload 只认 CJS，开了就加载失败               |
| 4   | 原生能力只经声明面         | 新增能力（菜单、单实例、窗口状态、导航）先加进 `src/electron-like.ts` 的 `ElectronLike`，不静态 import electron 的类型                                 | `electron` 是可选 peer，声明面就是壳真正调用的那一小块   |
| 5   | 设备偏好的规则不重写       | 快捷键语义复用上游 `ShortcutPersistence`（读写、编辑、冲突判定都在它那儿）                                                                             | 壳只做「原生侧的那一段」                                 |
| 6   | 窗口状态是用户数据         | 位置、尺寸、最大化存 `userData/window-state.json`；配置里的 `desktop.window` 只当第一次启动的尺寸                                                      | 配置是部署数据，运行期不该被改写                         |
| 7   | 菜单只给 role              | 菜单模板里的项全是 Electron 的 `role`，Reload / DevTools 只在调试面打开时出现                                                                          | 自实现标准项只会与平台漂移，而调试项不该进打包形态       |
| 8   | 单实例不装配第二份宿主     | `requestSingleInstanceLock()` 拿不到锁就聚焦已有窗口后退出                                                                                             | 第二份宿主会抢同一个数据根（快捷键配置、宿主库）         |
| 9   | 环境继承全量、日志只打数量 | 登录 shell 的环境整份并进来（缺的才补），日志说「补了几项」                                                                                            | 登录 shell 里有凭证，日志不该带键名                      |

## 二、现状事实

| 能力                 | 落点                                                                                        | 现状                                                                                                                                                                                                                                    |
| -------------------- | ------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 窗口外观与选项       | `src/window.ts` 的 `windowFrameOf(platform)` / `windowOptionsOf(desktop, platform, sizing)` | mac：`hiddenInset` + 红绿灯位 + 透明底；win / linux：`frame: false`（win 另给 `titleBarOverlay`）；`sandbox: false`、`contextIsolation: true`、`nodeIntegration: false`；位置与尺寸来自窗口状态，没有状态就不给位置（让 Electron 居中） |
| 窗口状态             | `src/window-state.ts`（`windowStateOf` / `loadWindowState` / `saveWindowState`）            | 关窗存 `getNormalBounds` + `isMaximized`；启动时按主屏 `workArea` 夹回可见区域；存档是外部输入，形状不成立就当没有存档                                                                                                                  |
| 产品菜单             | `src/menu.ts` 的 `menuTemplateOf({ platform, appName, debug })`                             | 应用（仅 mac，含 About / Services / Hide / Quit）、编辑、视图、窗口四个菜单；项全是 `role`；调试面关时视图菜单没有 Reload / Force Reload / Toggle DevTools                                                                              |
| 单实例               | `src/single-instance.ts` 的 `focusWindowOf(target)` + `src/app.ts` 的锁                     | 锁按 userData 认；拿不到锁 → 聚焦已有窗口 → 退出，不装配宿主；聚焦顺序是最小化时先恢复、再显示、再聚焦                                                                                                                                  |
| 导航与外部链接       | `src/navigation.ts` 的 `navigationPlanOf(url, origin)` + `src/app.ts` 的接线                | 本源放行（vite 的换页与 reload 都走这条）；`http(s)` / `mailto` 交系统浏览器；`file:` / `javascript:` / `data:` / 其它 scheme 与解析不出的目标一律拒；`setWindowOpenHandler` 一律拒新窗口                                               |
| preload 桥           | `src/preload.ts`                                                                            | `__DSH_DIRECTORY_PICKER__.pick()`（走 IPC，返回绝对路径或 `null`）；`dshDesktop`（`protocolVersion`、`shortcuts`、`keyboard`）；`markDocument` 写平台与标题栏形态                                                                       |
| 文档标记             | `src/document-marks.ts` 的 `markDocument(target, platform, titlebar = "hidden")`            | 写 `<html data-platform data-titlebar>`；侧栏折叠由前端按这两个属性做                                                                                                                                                                   |
| 目录选择器           | `src/app.ts` 的 `installDirectoryPicker` + `src/ipc.ts` 的通道名                            | 只认拥有窗口的 renderer、同一窗口的选择去重、窗口最小化先恢复再弹                                                                                                                                                                       |
| 快捷键（桥）         | `src/shortcuts.ts` 的 `installShortcuts({ electron, userData, getWindow, platform? })`      | 读写 `shortcuts.json`、广播快照、录制中 `setIgnoreMenuShortcuts(true)`、`closeWindow` 三重判据（revision 一致、非录制、窗口在前台且可用）；退出时由 `quit()` 调 `dispose`                                                               |
| 快捷键（主进程拦截） | —                                                                                           | **未做**：没有 `before-input-event` 的过滤，页面侧拿到的是原始按键                                                                                                                                                                      |
| 登录 shell 环境      | `src/shell-env.ts`                                                                          | 跑 `<shell> -ilc "env"` 全量继承，`mergeMissingEnv` 只补缺的                                                                                                                                                                            |
| 调试面               | `src/debug.ts` 的 `shellDebugOf(env)`                                                       | 只有 `ZEPHYR_DESKTOP_DEBUG=1` 才开（渲染进程 console 转发 + DevTools + 菜单里的调试项 + 生命周期日志；错误永远输出）                                                                                                                    |
| 失败上报             | `src/failure.ts`                                                                            | 启动、加载页面、打开外链、收起宿主的失败都落到同一份 `shell-entry.log`（打包形态没有 stderr）                                                                                                                                           |
| 生命周期             | `src/app.ts` 的 `start()` / `quit()`                                                        | `whenReady().then(start)`（不在模块顶层等 ready）；`window-all-closed` 只注册一处 → `quit()` 释放快捷键持久化、收宿主树、再 `quit`（重入有闸）                                                                                          |
| 声明面               | `src/electron-like.ts`                                                                      | 壳对 `electron` 的全部调用：app / BrowserWindow / webContents / dialog / ipcMain / screen / Menu / shell                                                                                                                                |

启动前必须处理的两个环境变量（`desktop dev` 与打包形态都要）：

- `ELECTRON_RUN_AS_NODE`：**摘掉**，否则 Electron 以 Node 身份跑（没有窗口、没有 app 生命周期）。
- `NODE_OPTIONS`：**换成本仓库的 loader**（`@morlay/dsh-oxc-node`），不是摘掉——壳里要能 `import` 带类型语法的 `.ts`。pnpm 那份是 `@oxc-node/core/register`，它初始化要 `new Worker()`，Electron 的 V8 平台不支持，会崩在启动前。

## 三、模块边界与接口

| 模块                                                      | 拥有（职责与不变量）                                             | 不拥有（明确排除）                                   | 依赖方向                                 | 接缝 / 适配器          |
| --------------------------------------------------------- | ---------------------------------------------------------------- | ---------------------------------------------------- | ---------------------------------------- | ---------------------- |
| 窗口（`window.ts`）                                       | 各平台的框与标题栏形态、安全开关、位置尺寸的唯一来源（窗口状态） | 页面内容；窗口内的业务；状态存在哪                   | ← `ElectronLike` 的 `BrowserWindow` 面   | 纯函数 + 声明面        |
| 窗口状态（`window-state.ts`）                             | 存档的校验与夹回、读写 `window-state.json`                       | 窗口怎么建；配置里的初始尺寸                         | ← 文件系统                               | 纯函数 + 薄读写        |
| 菜单（`menu.ts`）                                         | 三平台的菜单结构、哪些项进调试面                                 | 菜单项的行为（全是 `role`）、页面动作                | 无                                       | 纯函数                 |
| 导航（`navigation.ts`）                                   | 一次跳转的分类（本源 / 外链 / 拒）                               | 浏览器怎么开外链；页面怎么用链接                     | 无                                       | 纯函数                 |
| 单实例（`single-instance.ts`）                            | 已有窗口怎么被抬到前台                                           | 锁本身（归 Electron 的 `requestSingleInstanceLock`） | 无                                       | 纯函数（假窗口可替身） |
| preload（`preload.ts`）                                   | 暴露给页面的极薄面（目录选择、`dshDesktop`、平台标记）           | 业务 IPC                                             | ← `ipcRenderer`                          | `contextBridge`        |
| IPC 桥（`ipc.ts` + `shortcuts.ts` + `app.ts` 的 handler） | 通道名、读写与广播、录制与关窗判据                               | 快捷键的编辑规则（上游 `ShortcutPersistence`）       | ← `electron`                             | 契约 `ShortcutsHost`   |
| 环境（`shell-env.ts`）                                    | 登录 shell 环境的采集与合并                                      | 业务对某个变量的解释                                 | ← 系统 shell                             | 纯函数（可注入 exec）  |
| 文档标记（`document-marks.ts`）                           | 把平台与标题栏形态交给前端                                       | 前端怎么用这两个属性                                 | 无                                       | 纯函数                 |
| 启动与生命周期（`app.ts` / `main.ts` / `failure.ts`）     | 单实例准入、桥与菜单安装、开窗、打包装配宿主、唯一退出路径       | 宿主行树的装配细节                                   | ← 上面各模块 + 闭包里的 `@morlay/zephyr` | —                      |

**接口**：`windowFrameOf(platform)` / `windowOptionsOf(desktop, platform, { preload, state })`；`windowStateOf(saved, workArea, fallback)` / `loadWindowState(userData)` / `saveWindowState(userData, state)`；`menuTemplateOf({ platform, appName, debug })`；`navigationPlanOf(url, origin)`；`focusWindowOf(target)`；`installShortcuts(options): { dispose }`；`markDocument(target, platform, titlebar?)`；`shellDebugOf(env)`。
不变量：渲染进程没有 node 权限；打包形态的 `cwd` 是 `Resources/runtime`；壳与宿主共用闭包里那份 `@morlay/zephyr`；窗口位置与尺寸只有一个来源（窗口状态）。
原生能力只在 `src/electron-like.ts` 的声明面上调用；打包期字段（asar、`afterPack`、`extraResources`、签名、更新源）与命令面归 `zephyr-desktop-bundle`，两边的批次与判据见[设计 desktop 功能面](../../../zephyr-desktop-bundle/.agents/designs/20261114-desktop功能面.md)。

**深度**：删掉壳，页面就没有无标题栏窗口、记住位置与尺寸、产品菜单、单实例、导航判据、目录选择与快捷键桥——这些都不是页面能自己做的事。

## 四、行为与边界

- 正常（dev）：`main.ts` → `app.ts` 拿单实例锁 → 补环境 → 装桥与菜单 → 开窗口指向 `ZEPHYR_DESKTOP_URL`。
- 正常（打包）：`chdir(Resources/runtime)` → 从闭包解析 `bootstrapApplication` → 装配清单 → 等 http → 开窗口 → 关窗时 `quit()`。
- 单实例：拿不到锁的进程聚焦已有窗口后退出；已有窗口还没有（正在启动）时什么也不做，锁的持有者继续。
- 错误：启动、加载页面、打开外链、收起宿主的失败都经 `failure.ts` 落文件；窗口不会停在白屏。
- 取消：`window-all-closed` 是唯一的正常退出路径；`desktop dev` 把信号转发给壳。
- 并发：目录选择按窗口去重（同一窗口只开一个对话框）；窗口状态的写入发生在 `close` 上，退出路径不会重入。
- 边界：快捷键录制中不拦键，且把菜单快捷键让给页面；页面点外链不在应用内开窗。

## 六、取舍

- 不采纳「自定义协议读 `Resources/dist` 出页面」：与宿主自己的 vite 重复，还要在壳里养 MIME 与越界规则（[desktop 功能面](../../../zephyr-desktop-bundle/.agents/designs/20261114-desktop功能面.md) 第 8 条）。
- 不采纳「窗口状态写进配置」：配置是部署数据；写成可变文件会让「同一份配置打出来的包」不再一致。
- 不采纳「宿主跑在独立子进程、走字节管道」：与单进程壳的取舍相反（见[桌面两包](../../../zephyr-desktop-bundle/.agents/designs/20261110-桌面两包与单进程壳.md)）。
- 不采纳「profile 种子 / 运行时归档」：本仓库不维护发布式 profile 体系。
- 不采纳「壳里 spawn 宿主的 shell 包装」：单进程不需要；终端类子进程由业务包自己 spawn，环境已由壳继承。
- 不采纳「mac 用 `ELECTRON_RUN_AS_NODE` 起 Helper.app 避免多余 Dock 图标」：单进程不 spawn 宿主，没有这个问题。

## 七、不做与已知债

- **主进程的按键拦截未做**：页面侧拿到的是原始按键；已绑定的快捷键目前不会在原生层被拦。要做的话判据来自上游那套状态机（已绑定、无冲突、无问题才拦；组合键按下与抬起成对处理；死键与 composing 放行；录制中不拦）。
- **桌面流载体未做**：单进程下页面直接 fetch 宿主即可。
- 债：`preload.ts` 本体没有测试面——`src/__tests__/preload.spec.ts` 只覆盖 `markDocument`，桥暴露了哪几个全局、参数与返回值靠真机。销账条件：`contextBridge` 的调用能被替身接住并断言暴露面。

## 八、开放问题

- 按键拦截要不要做、做到哪一档（只拦已绑定的、还是也接管菜单快捷键），未定。做之前先给一条可判定的用例（录制中不拦、组合键成对、死键放行）。
- `dshDesktop` 现在挂着 `shortcuts` 与 `keyboard` 两组：B 批收 IPC 通道表时要不要把它收成一个全局、一个通道表（[desktop 功能面](../../../zephyr-desktop-bundle/.agents/designs/20261114-desktop功能面.md) 第八节）。
- 页面侧 `provideShortcuts()` 依赖 `window.dshDesktop.shortcuts` 存在：非桌面形态没有这个对象，目前靠「不装那一行」规避。要不要给一个空实现让清单统一，未定。
