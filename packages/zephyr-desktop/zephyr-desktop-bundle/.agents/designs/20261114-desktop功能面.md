# 桌面功能面（壳、bundle 插件与应用配置的能力边界）

状态：A 批已实现（窗口状态、产品菜单、单实例、外部链接与导航），库面（页面协议 + 壳清单）已删；A5 的稳定 origin 一半已实现（T8 的 dev userData 默认值、T9 的端口粘住、T7 的壳只 setPath）；B 批（IPC 通道表、菜单动作回传）未做；C 批按决定不做。真机人工门未跑（见第五节）。
范围：`packages/zephyr-desktop/` 两包合起来的桌面能力面——命令（`desktop dev` / `desktop bundle`）、打包链（electron-builder 配置、闭包、图标、安装）、壳的原生面（窗口、菜单、单实例、窗口状态、导航与外部链接、preload 桥、生命周期）。
非目标：页面与渲染（前端）、宿主装配清单（`zephyr` 与 apps）、证书与发布通道的具体配置、上游桌面应用的复用。
关联：[设计 桌面两包与单进程壳](20261110-桌面两包与单进程壳.md)、[设计 桌面壳功能面](../../../zephyr-desktop-shell/.agents/designs/20261111-桌面壳功能面.md)、[设计 框架层](../../../../zephyr/.agents/designs/20261113-框架层.md)、[ADR 自研离线桌面打包器而非直接用上游桌面应用](../adrs/20260917-自研离线桌面打包器而非直接用上游桌面应用.md)、[桌面术语表](../GLOSSARY.md)、[定义权地图](../../../../../.agents/GLOSSARY-MAP.md)。

## 一、决定

| #   | 议题                         | 决定                                                                                                                                                                                                           | 一句话理由                                                                        |
| --- | ---------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------- |
| 1   | 能力分三处                   | 原生能力（窗口、菜单、单实例、窗口状态、导航与外部链接、桥、生命周期）归壳；打包期字段（asar、`afterPack`、`extraResources`、签名、更新源）与命令面归 bundle 插件；值（id / name / icon / 窗口尺寸）归应用配置 | 一处一个 owner：壳不读工作区配置，插件不碰 electron 运行时                        |
| 2   | 配置契约不开二口             | `desktop` 段只在 `packages/zephyr/zephyr-cli/src/config/contract.ts` 的 `ZephyrDesktopConfig` 上加字段，两包都不自己发明字段                                                                                   | 配置只有一个 home，`desktop.json` 是它的落盘形态                                  |
| 3   | 批次顺序                     | A 批（窗口状态、产品菜单、单实例、外部链接与导航）只改壳：不新增配置字段、不加环境变量；B 批（IPC 通道表、菜单动作回传）动桥的契约；C 批不做                                                                   | 改壳能独立验收与回滚，不与 `zephyr-cli` 的发版节奏绑在一起                        |
| 4   | 不重复 Electron 默认         | 菜单用 `role`（复制粘贴、窗口、退出）不自己实现；不重画窗口按钮；不自造更新器                                                                                                                                  | 自实现的标准项只会与平台漂移                                                      |
| 5   | 形态与行为分开               | 形态只走 `ZEPHYR_DESKTOP_*` 环境变量；窗口状态与快捷键配置落 `userData`                                                                                                                                        | 环境变量是启动期的形态开关，不该承载用户状态                                      |
| 6   | 窗口状态总是记忆             | 不给 `desktop.window` 加「是否记忆」开关：位置与尺寸一律存 `userData/window-state.json`                                                                                                                        | 配置是部署数据、状态是用户数据；一个开关只为关掉一条默认行为，不值                |
| 7   | 新能力扩声明面               | 新增原生能力一律加进壳的 `ElectronLike`，不静态 import electron 的类型                                                                                                                                         | `electron` 是可选 peer，声明面只覆盖壳真正调用的部分                              |
| 8   | 页面只有一条链               | 删掉页面协议（`protocol.ts`）与壳清单（`provideDesktopShell`）：两种形态都从壳自己的 http 源进页面                                                                                                             | 第二条页面链（自定义协议读 `Resources/dist`）与宿主自己的 vite 重复，风险高于收益 |
| 9   | 发布类能力不做               | 自动更新、签名 / 公证、深链、文件关联不做；要做先定发布通道与证书策略（签名另立 ADR），深链另选 scheme                                                                                                         | 四者都绑发布链，而产物现状是不签名的应用目录                                      |
| 10  | 桌面用户数据的目录契约归本包 | 各形态的 `userData` 默认值、显式覆盖与「谁算」的规矩写在本包（第十一条与第三节）：`userData` 是**桌面侧部署值**，不是 `AppEnv` 的字段                                                                          | 底层不描述上层：这套路径只服务桌面形态，别处不该知道它                            |
| 11  | 桌面用户数据的四种来源       | dev 默认 `<appData>/<desktop.id>/dev/electron`；bundle / preview 默认 `<appData>/<desktop.id>/electron`；test 用临时目录（用例自己指定）；显式 `ZEPHYR_DESKTOP_USER_DATA` 优先。**不做**工作区哈希隔离         | 目录名要可读；多工作区并行走显式值，不靠「悄悄换一个身份」                        |
| 12  | 桌面词归本包                 | 桌面形态 / 桌面身份 / 桌面插件 / 壳 / 打包期字段 / 窗口状态的定义放[桌面术语表](../GLOSSARY.md)；根表的桌面行由层维护者加                                                                                      | 有自己一套词的包在包内立表，别处只链接                                            |

## 三、目标矩阵

结论：A 批四项是「没有就不可用」的桌面基线，已落；B 批要动桥的契约；C 批要么与「窗口即宿主生命周期」相冲，要么绑发布链，不做。

| 候选                          | 批次 | 决定 | 理由                                                                                                                                     | 归属                                  |
| ----------------------------- | ---- | ---- | ---------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------- |
| 窗口状态持久化                | A    | 已做 | 每次启动回到配置尺寸与系统默认位置，桌面基线缺失；状态是用户数据（`userData/window-state.json`），不进配置                               | 壳（`window-state.ts` + `window.ts`） |
| 产品菜单                      | A    | 已做 | 默认菜单是英文且打包形态也带 Reload / Toggle DevTools；现在由 `menuTemplateOf` 裁成产品菜单，开发者项只在调试面开时出现                  | 壳（`menu.ts`）                       |
| 单实例锁                      | A    | 已做 | 起两次 = 两份宿主、两份 vite、同一个数据根（`shortcuts.json` 与宿主库并发写）；现在第二次只把已有窗口抬到前台                            | 壳（`app.ts` + `single-instance.ts`） |
| 外部链接与导航                | A    | 已做 | `http(s)` 锚点会开默认新窗口、非 http 的跳转会把窗口导航走（桌面窗口没有浏览器 chrome 可退）；现在按本源白名单放行、其余交系统浏览器或拒 | 壳（`navigation.ts`）                 |
| 稳定 origin（前端存储跨重启） | A5   | 待定 | 页面端口每次随机 → origin 每次都变，`localStorage` 与页面 shim 的 IndexedDB 都读不到；做法取决于持久化根归谁（等 AppEnv 目录契约）       | bundle（端口）/ 壳（`userData`）      |
| IPC 通道表与准入              | B    | 待做 | 目录选择器与快捷键各写一份 `senderId` 判据；再加能力就会漂，收敛成一张表 + 一个准入函数                                                  | 壳（`ipc.ts` + 各 handler）           |
| 菜单动作回传页面              | B    | 待做 | 菜单只有 role 时够用；一旦有「打开设置」这类页面动作，需要 `dshDesktop` 加一条下行通道                                                   | 壳 + 页面半（页面侧归页面所在包）     |
| 权限请求策略                  | C    | 不做 | 现在没有需要权限的 Web API 用例；默认拒会把剪贴板 / 通知一并拒掉，症状是页面静默失败                                                     | —                                     |
| 多窗口                        | C    | 不做 | 单工作区单数据根；壳里 `primaryWindow` 是单数（选择器去重、快捷键广播、聚焦、关窗判据都按它写），多窗口要先摊开这几处                    | —                                     |
| 托盘                          | C    | 不做 | 与「关窗即收宿主树」的生命周期相反；没有常驻诉求                                                                                         | —                                     |

## 四、模块边界与接口

结论：四块各有一个 owner；跨块只经「配置契约」与「壳的声明面」两个接缝，任一处出现第二种说法就是边界没划。

| 模块                                                              | 拥有（职责与不变量）                                                                                                                                       | 不拥有（明确排除）                   | 依赖方向                                                                 | 接缝 / 适配器                                      |
| ----------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------ | ------------------------------------------------------------------------ | -------------------------------------------------- |
| 壳（`packages/zephyr-desktop/zephyr-desktop-shell/src/`）         | 窗口与外观、窗口状态、菜单模板、单实例准入、导航与外部链接策略、preload 桥与 IPC 准入、生命周期；不变量：渲染进程没有 node 权限、原生面只经 `ElectronLike` | 业务行、页面、打包期字段、工作区配置 | ← `electron`（可选 peer，经声明面）+ 打包形态下闭包里的 `@morlay/zephyr` | `ElectronLike` 声明面 + 注入；纯函数可单测         |
| bundle 插件（`src/`）                                             | 命令面、构建编排、electron-builder 配置推导、app 目录装配、图标、安装                                                                                      | electron 运行时行为、页面、宿主装配  | ← `@morlay/zephyr-cli`（命令 / 配置 / 布局 / 构建步骤）                  | `Packager` 契约 + `electronBuilderConfigOf` 纯函数 |

| 配置契约（`packages/zephyr/zephyr-cli/src/config/contract.ts`）   | `ZephyrDesktopConfig` 的字段与语义                                                                                                                         | 字段怎么落盘、怎么读                 | ← 无                                                                     | 三处共用的唯一声明                                 |

接口（形状已落在壳的出口上）：

- `windowStateOf(saved, workArea, fallback) -> { bounds, maximized }`：存档是外部输入，坏掉就当没有存档；越界夹回工作区。读写是 `loadWindowState` / `saveWindowState`（`userData/window-state.json`）。
- `menuTemplateOf({ platform, appName, debug }) -> 模板数组`：项一律 `role`，调试面关时没有 Reload / DevTools。
- `navigationPlanOf(url, origin) -> { kind: "allow" } | { kind: "external", url } | { kind: "deny" }`：本源放行、`http(s)` / `mailto` 交系统浏览器、其余拒。
- `focusWindowOf(target) -> "focused" | "none"`：先恢复再显示再聚焦；锁本身是 `requestSingleInstanceLock()`，拿不到就**不装配宿主**。
- `windowOptionsOf(desktop, platform, { preload, state }) -> WindowOptions`：位置与尺寸只从状态来（没有状态就不给位置，让 Electron 居中）。

**userData 目录契约**（桌面侧部署值；框架层的目录契约把这块指到这里）：

| 形态                 | 默认值                                                                                                      | 谁来定                                                                                             |
| -------------------- | ----------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------- |
| dev（`desktop dev`） | `<appData>/<desktop.id>/dev/electron`                                                                       | `zephyr-desktop-bundle` 的 `src/desktop-dirs.ts`（`appRootOf({ form: "dev" })` + `userDataDirOf`） |
| bundle / preview     | `<appData>/<desktop.id>/electron`                                                                           | 同上（`form: "packaged"`）；打包形态由启动器 `bootstrap.mjs` 在 ready 之前算                       |
| test                 | 临时目录（用例自己给）                                                                                      | 用例传 `mkdtemp` 的路径（`page-port` 的用例就是这么做的）                                          |
| 显式指定             | `--user-data-dir <目录>`（flag）> `ZEPHYR_DESKTOP_USER_DATA`（环境变量）；多工作区并行、临时 profile 都走它 | flag 比环境变量具体，所以排在它前面；两者都没有才用缺省值                                          |

规矩四条：① **壳只 `app.setPath("userData", 部署值)`**，不自己拼 appData、不读第二个变量兜底（缺值即启动失败）；② **只有 bundle 算**（`desktop-dirs.ts` 一处，`grep -rn` 的 `getPath("appData")` 也只在这里）；③ 端口偏好落 `<userData>/page-port`——它与 userData 同生命周期（删它 = 让用户丢一次页面存储）；④ **不给工作区哈希**：目录名可读，并行靠 `--user-data-dir`。

**页面端口的三条规矩**（origin 就是页面存储的身份，见 `src/page-port.ts`）：

- **同一个 userData 的第二个实例**：单实例锁挡住，走不到端口冲突这一步。
- **被外部进程占着**：**不自动换端口**，抛 `CliError` 并给三条出口——关掉占用进程（`lsof -nP -iTCP:<端口> -sTCP:LISTEN`）/ `--port <新端口>`（origin 会变，页面存储另起一份）/ `--user-data-dir <目录>`（并行多个工作区）。自动换端口等于把「锁定」作废。
- **只有「第一次」（没有 page-port）与「记录损坏」才重新选并写回**；损坏时日志明说「已重新选择（页面存储将另起）」。
- **`--port` 写回**：用户显式选的 origin 就是新的归属；日志明说「origin 已变，页面存储将另起」。不写回的话，下次会悄悄改回旧端口，等于让页面存储再丢一次。

不变量：`userData` 与数据根是两份数据——`userData` 放 Chromium 的东西（页面存储、窗口状态、快捷键、GPU cache），数据根放宿主的东西（会话、设置、凭证）；删一边不该动另一边。

深度：删掉壳，页面就没有无标题栏窗口、窗口状态、产品菜单、单实例与导航策略、目录选择与快捷键桥；删掉插件，桌面形态要自己写一份 electron-builder 配置与 deploy 编排。四项原生能力各占一个薄模块，是因为它们的判据各自可单测（窗口状态 / 菜单模板 / 导航表 / 聚焦顺序），混在 `app.ts` 里就只能靠真机。

## 六、取舍

- 否掉「壳里跑独立宿主进程（两进程 + 字节管道）」：与单进程壳的取舍相反（[桌面两包](20261110-桌面两包与单进程壳.md)）。
- 否掉「窗口状态写进 `desktop.window`」：配置是部署数据、状态是用户数据；混在一处会让 `desktop.json` 变成可变文件。
- 否掉「协议读 `Resources/dist` 作为第二条页面链」：与宿主自己的 vite 重复，且要在壳里再养一套 MIME / 越界规则；一条 http 链更少地方会错。
- 否掉「先做托盘再定退出语义」：托盘要求关窗不退，等于把退出语义改两遍。
- 否掉「自己实现编辑菜单项」：`role` 已经给了平台本地化与快捷键，自实现只会与平台漂移。
- 否掉「`zephyr://` 兼做深链」：页面协议只读产物根，深链带外部输入，两种信任级不共用一个 scheme。
- 否掉「为菜单引入一份本地化词表」：菜单项全是 `role`，没有产品文案要翻。
- 否掉「按工作区哈希隔离 dev 的 userData」：目录名要可读；多工作区并行靠显式 `ZEPHYR_DESKTOP_USER_DATA`，不靠「悄悄换一个身份」（换了等于换一份页面存储）。
- 否掉「本地签名」：见 [ADR](../adrs/20260917-自研离线桌面打包器而非直接用上游桌面应用.md)。

A5（前端存储跨重启）落成了「稳定 origin」这一半：四条路线先按**持久化根**分——浏览器存储（`localStorage` / IndexedDB / Chromium 的缓存与偏好）归 `userData`，宿主数据（会话库、上传、日志）归 `dataDir`；这一半只动 dev 端点与壳的取数方式，页面侧一行没改。

| 路线                     | 做法                                                                                                                      | 值落在哪（持久化根）                                                                    | 与既有约定的相容性                                                                                                                                                                                                | 结论                   |
| ------------------------ | ------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------- |
| 稳定 origin：粘住端口    | `desktop dev` 记住上次用过的页面端口，下次优先用它，被占用才换                                                            | **`userData`**：值是 Chromium 自己在 profile 里写的 Local Storage / IndexedDB，壳不搬运 | 随机端口本来只为「两个工作区 / 残留 server 不撞」，粘住之后只有冲突那一次回落到今天的表现；单实例锁按 userData 认，窗口即宿主生命周期都不受影响                                                                   | **推荐**（等目录契约） |
| 固定 origin：自定义协议  | 恢复 `zephyr://` 一类的页面协议出页面                                                                                     | `userData`（同 session，origin 换成协议）                                               | 与决定 8（页面只有一条 http 链）冲突，要在壳里再养 MIME 与越界规则                                                                                                                                                | 否                     |
| preload 同步桥           | preload 里 `defineProperty(window, "localStorage", …)`，`sendSync` 读、异步写                                             | 主进程写 **`userData`** 下的一个文件（浏览器侧状态跟着 profile 走，**不是 `dataDir`**） | **不可行**：`contextIsolation: true` 下 preload 在隔离世界，改不到页面世界的 `window`；`webFrame.executeJavaScript` 注入主世界有竞态，且页面启动时 `installStorageShim` 会再定义一次 `localStorage`，注入必被覆盖 | 否                     |
| 页面 shim 换后端         | 把 `installStorageShim` 的 IndexedDB 换成 preload 暴露的异步桥（它已经是「同步内存 + 异步落盘」的形状，换后端不动调用方） | 主进程写 **`userData`**；页面的 IndexedDB 退化成缓存                                    | 与随机端口解耦，窗口生命周期 / 单实例无关；但页面半在 `packages/zephyr/zephyr-app` 与 apps，不在本包写域                                                                                                          | 方向（见第八节）       |
| 壳内固定 origin 反向代理 | 壳起一个固定端口的代理转发到 vite（含 HMR 的 ws）                                                                         | `userData`（origin 是代理端口）                                                         | 多一层代理与 ws 转发，且 origin 稳定性仍受代理端口冲突影响                                                                                                                                                        | 否                     |

选「粘住端口」的三条理由：只动 dev 端点（不动页面、不复活协议）；失效有界（冲突那一次等于今天的行为）；与单实例锁、窗口生命周期正交。`userData` 的落点由本包的目录契约（第三节）定，所以壳那边只多了一句话：缺部署值就启动失败。

- 不做：托盘、深链、文件关联、系统通知、多窗口、自动更新、签名 / 公证、权限请求策略、主进程按键拦截、macOS 关窗不退（见第三节 C 批）。
- 债：`preload.ts` 本身没有测试面——`packages/zephyr-desktop/zephyr-desktop-shell/src/__tests__/preload.spec.ts` 只覆盖 `markDocument`，桥暴露了哪几个全局、参数与返回值靠人工门。销账条件：`contextBridge` 的调用能被替身接住并断言暴露面。

- 债：打包形态的启动器（`bootstrap.mjs`）只有单测覆盖到「源码该有哪些行」，没在真机打过包——`just custom bundle` 之后双击能不能起，留待下一次打包门。销账条件：打包门跑一次且窗口出、页面有内容。
- 债：dev 的几个工作区**共用**一份 profile（`<appData>/<desktop.id>/dev/electron`），并行起第二个会被单实例锁挡住。销账条件：不需要还——并行就用显式 `ZEPHYR_DESKTOP_USER_DATA`（见第三节）。

## 八、开放问题

- **B 批的通道表长什么样**：方向（渲染 → 主 / 主 → 渲染）、参数形状与准入判据怎么在一张表里表达，`dshDesktop` 的多全局要不要收成一个。
- **深链的 scheme 名与工作区校验**：若哪天要做，先定 scheme 与「只允许打开已登记的工作区」这条判据。
- **打包形态要不要彻底不跑 vite**：现在宿主在打包形态也起 vite（页面与源码面一致），代价是启动多一步；换成静态面就回到「第二条链」，与第 8 条决定相反，要动就整条重来。
- **显式 userData 的入口要不要做成 CLI flag**：现在只有 `ZEPHYR_DESKTOP_USER_DATA`（环境变量）。要 `--user-data <路径>` 就得动 `desktop dev` 的参数表，等真有第二个消费方再加。
- **打包形态 3080 被占怎么办**：现在会启动失败（端口是身份，不该悄悄漂）。要不要改成报错文案里给出 `PORT` 的用法，留待真机踩一次再定。
- **前端存储要不要与 origin 解耦**：即便粘住端口，origin 仍绑端口（冲突那一次换一套值）。要彻底解耦就走「页面 shim 换后端」（第六节第 4 条），页面半在 `zephyr-app`，得先在那儿立设计。
