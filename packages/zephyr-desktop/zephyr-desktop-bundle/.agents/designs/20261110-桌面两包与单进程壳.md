# 桌面两包：插件与壳

状态：已实现——`zephyr-desktop-bundle` 是 CLI 插件（追加 `desktop dev` / `desktop bundle`），`zephyr-desktop-shell` 是被打进应用的 Electron 壳。
范围：`packages/zephyr-desktop/zephyr-desktop-bundle/`（命令、electron-builder 配置推导、打包动作、图标）与 `packages/zephyr-desktop/zephyr-desktop-shell/`（壳的窗口、协议、preload、桥）之间的分工。
非目标：宿主装配面本身（归 `zephyr-app` 与 apps 的清单）、壳的功能面细节（见[设计 桌面壳功能面](../../../zephyr-desktop-shell/.agents/designs/20261111-桌面壳功能面.md)）、安装包的签名与分发。
关联：[设计 桌面壳功能面](../../../zephyr-desktop-shell/.agents/designs/20261111-桌面壳功能面.md)、[设计 命令内核与四阶段](../../../../zephyr/zephyr-cli/.agents/designs/20261110-命令内核与四阶段.md)、根 [ADR-自研离线桌面打包器而非直接用上游桌面应用](../adrs/20260917-自研离线桌面打包器而非直接用上游桌面应用.md)。

## 一、决定

| #   | 议题                  | 决定                                                                                          | 一句话理由                                                            |
| --- | --------------------- | --------------------------------------------------------------------------------------------- | --------------------------------------------------------------------- |
| 1   | 两个包                | 插件（CLI 侧：命令 + 打包）与壳（Electron 侧：窗口 / 协议 / 桥）分成两个 manifest             | 壳的依赖面（`electron`）不能进插件的依赖图                            |
| 2   | 打包形态是一个进程    | 壳启动后 `chdir` 到 `Resources/runtime`，从闭包解析 `@morlay/zephyr` 并装配宿主清单           | 一张清单一个生命周期，诊断能把窗口与宿主一起拍下来                    |
| 3   | dev 形态是两个进程    | `desktop dev` 起 `zephyr dev` 子进程跑宿主，Electron 只当浏览器                               | dev 期的宿主需要 CLI 的重载护栏与 vite 的 HMR，塞进壳只会让两边都难调 |
| 4   | 配置推导是纯函数      | `electronBuilderConfigOf` 只做「字段从哪来」的判断，不碰文件系统、不起子进程                  | 「配置对不对」可以单测，「能不能打包」才需要真机                      |
| 5   | 真实动作在 `Packager` | `electron-builder` / `electron` 都是**可选 peer**，走动态 import，缺了给明确的 CliError       | 不打包的人不必装它们                                                  |
| 6   | 桌面身份与窗口尺寸    | dev 由 `ZEPHYR_DESKTOP_*` 直传；打包写 `desktop.json` 并作 `extraResources` 落进 `Resources/` | 环境变量只覆盖 dev，打包形态得有一份文件可读                          |
| 7   | 每次 bundle 都重建    | `desktop bundle` 无条件先 `runBuild`                                                          | 用旧产物打出来的包会带着已经改掉的代码                                |

## 二、现状事实

- **插件清单**：`packages/zephyr-desktop/zephyr-desktop-bundle/src/provide.ts` 的 `provideDesktopBundle = provide([DesktopCommand, DesktopDevCommand, BundleCommand, PackagerDefault])`；装配面只写 `plugins: [...provideDesktopBundle()]`。
- **命令**：`src/commands/{desktop,dev,bundle}.ts`。`desktop` 是父命令（`path: ["desktop"]`），`dev` / `bundle` 挂在它下面（命令树要求父路径有对应命令）。
- **配置推导**：`src/electron-builder.ts` 的 `electronBuilderConfigOf`（`Input = { resolved, layout, electronVersion, icons? }`）：`appId ← desktop.id`、`productName ← desktop.name`、输出 `<layout.root>/app`、`asar: true` + `asarUnpack: ["**/*.node"]`、`npmRebuild: false`、`files: ["dist/**","entry.mjs","package.json"]`、`afterPack` 把 `layout.runtime` 拷到 `Resources/runtime`、`extraResources` 放 `dist` 与 `desktop.json`、不签名（`identity: null`）。
- **打包动作**：`src/packager.ts` 的 `PackagerDefault`：清空 app 目录 → `pnpm --filter @morlay/zephyr-desktop-shell deploy --prod --ignore-scripts` → 写一份空的 `pnpm-workspace.yaml`（让 electron-builder 的包遍历停在 app 目录）→ 校验宿主闭包里有 `entry.mjs` → 删清单与 `node_modules` 里的 `electron`、把 `main` 改成 `./dist/main.mjs` → 动态 import `electron-builder` 并 `build({ config, dir: true })`。每步写一行到 `<layout.root>/bundle.log`。
- **图标**：`src/icons.ts` 的 `prepareIcons`（sharp 生成 512 png；macOS 上再生成 iconset 交给系统 `iconutil` 出 `.icns`），产物落 `<layout.root>/icon/`，配置里显式给 `mac/win/linux.icon`。
- **壳的入口**：`packages/zephyr-desktop/zephyr-desktop-shell/src/main.ts` → 同目录 `app.ts`。dev 形态只开窗口指向 `ZEPHYR_DESKTOP_URL`；打包形态 `chdir(resourcesPath()/runtime)` → 从闭包解析 `@morlay/zephyr` → 装配宿主清单（`entry.mjs` 的 default / `providers`，可以是清单或 `(mode) => 清单`）→ 等 http 端口 → 开窗口。
- **壳的产物**：`packages/zephyr-desktop/zephyr-desktop-shell/tsdown.config.ts` 出 `dist/main.mjs` 与 `dist/preload.mjs`（Electron 只认 JS）；壳其余模块照旧走 TS 运行时。

## 三、模块边界与接口

| 模块                              | 拥有（职责与不变量）                                     | 不拥有（明确排除）                    | 依赖方向                                                                     | 接缝 / 适配器                                                                                |
| --------------------------------- | -------------------------------------------------------- | ------------------------------------- | ---------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------- |
| 插件命令（`src/commands/`）       | `desktop dev` / `desktop bundle` 的编排、退出码、日志    | 宿主怎么装配；electron-builder 的内部 | ← `@morlay/zephyr-cli`（`Command` / `CliMode` / `Workspace` / `BuildSteps`） | 命令契约（插件只追加命令）                                                                   |
| `electronBuilderConfigOf`         | 「字段从哪来」的推导与不变量（asar、输出目录、资源落点） | 文件系统；子进程；签名                | ← `ResolvedConfig` / `ZephyrLayout`                                          | 纯函数，可单测                                                                               |
| `Packager`                        | 备 app 目录、调 electron-builder、安装                   | 配置该长什么样（上一个模块的事）      | ← `pnpm`、`electron-builder`（可选）                                         | 契约 + `PackagerDefault`（测试换替身）                                                       |
| `prepareIcons`                    | `desktop.icon` → 三平台图标                              | 主题与视觉                            | ← `sharp`、系统 `iconutil`                                                   | 纯函数 + 外部命令                                                                            |
| 壳（`zephyr-desktop-shell/src/`） | 窗口与外观、自定义协议、preload 桥、宿主装配与生命周期   | 业务行；CLI 的四阶段                  | ← `electron`（可选 peer）                                                    | 见[壳功能面](../../../zephyr-desktop-shell/.agents/designs/20261111-桌面壳功能面.md)的边界表 |

**接口**：`provideDesktopBundle()` 返回 `ProviderList`；`electronBuilderConfigOf(input): ElectronBuilderConfig`；`Packager.pack(config, input): Promise<{ appDir }>`；`Packager.install(result): Promise<string>`。
不变量：壳的 `node_modules` 里不能有 `electron` 包；宿主闭包只在 `Resources/runtime`；`asar` 只拆 `*.node`。

**深度**：删掉插件，桌面形态要自己写一份 electron-builder 配置与 deploy 编排；删掉壳，页面就没有自定义协议、preload 桥与单进程生命周期。

## 四、行为与边界

- 正常（dev）：`desktop dev` 探空闲端口 → 起 `zephyr dev` 子进程（`PORT`）→ 等 http 就绪（上限 60s）→ 起 Electron → 用户关窗则子进程一起收。
- 正常（bundle）：`runBuild` → 写 `desktop.json` → 生成图标 → 推导配置 → `Packager.pack` → 可选 `--install`。
- 错误：端口 60s 内没起来 → CliError 并提示先单独跑 `zephyr dev`；electron / electron-builder 没装 → CliError 说清缺哪个；宿主闭包里没有 `entry.mjs` → CliError 提示先 `zephyr build`。
- 信号：`desktop dev` 把 SIGINT / SIGTERM 转发给壳，再退出（130 / 143）。
- 生命周期（打包形态）：`window-all-closed` → `app.dispose()` → `quit()`。

## 六、取舍

- 否掉「宿主跑在独立子进程、走字节管道」：与「一张清单一个生命周期」冲突，且「窗口先出、宿主后到」会留下一个白窗口。
- 否掉「壳与插件共用一个 manifest」：`electron` 会被拉进插件的依赖图。
- 否掉「在 `packager` 里手拷壳的产物」：electron-builder 只按 deploy 出来的依赖图收集，手拷的包它不认。
- 否掉「本地签名」：产物是给自己 / 内测用的目录，签名只引入钥匙串与证书依赖。
- 否掉「bundle 复用现成产物」：｢有没有产物｣判断不出它是否与当前源码一致。

## 七、不做与已知债

- 不产安装包（dmg / nsis / AppImage）与自动更新。
- 不做 profile 种子与发布式 profile 体系。
- 不做「桌面形态的 e2e 自动化」：壳的行为靠纯函数单测 + 真机手跑。

## 八、开放问题

- `desktop dev` 起的是 `pnpm exec zephyr dev` 子进程，发布形态里 CLI 是 `dist` 的 js、开发期是 TS：｢用哪种形态起子进程｣目前靠 `pnpm exec` 隐式决定，没有显式判据。
- 打包形态里宿主自己起 vite 提供页面（与 dev 同一套跑法）：这条链在闭包里跑得通，但 ｢为什么打包后还要 vite｣只写在代码注释里，没有单独的取舍记录。
