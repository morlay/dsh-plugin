# preset 行清单归本包（复制上游四份，删掉与 agent-team 冲突的子代理工具行）

状态：已采纳

背景：本包原先只按行 id 覆盖配置值，行清单归 web-app 的四份 shipped preset。`@deepseek-ai/dsh-experimental-agent-team-profile`
只停宿主平面的 `tool-subagent-control` / `tool-subagent` / `tool-subagent-fork`，preset realm 里的同名行不受影响：
模型会同时拿到 legacy 子代理控制与 Team 的九件工具，同名工具互相遮蔽。上游 `vendor/**` 只读，而官方明说 preset 的
`config.plugins` 覆盖是整段替换。

**决定**

四份 shipped preset（`standard` / `ptc` / `minimal` / `cordis`）逐行复制进本包的 patch（按行 id 覆盖 `config.plugins`），
唯一改动是删掉 `delegation` 组里的 `tool-subagent-control` / `tool-subagent` / `tool-subagent-fork`；
`agent-preset-registry.default` 仍不配，新会话继续用 web-app 的 `standard`。

**考虑过的选项**

- 只在宿主平面停行：preset realm 里的同名行不受影响，冲突还在。
- 新建一份自己的 preset id 并设默认：官方四份仍在 roster 里可选，冲突照旧可能发生。
- 直接改 vendor 的 preset 文件：越过只读红线。
- 连 `workflow-ptc` / `tool-workflow` 一起删：Workflow 的 `agent()` 起 fresh 子代理与 Team 不冲突，删了平白丢能力。

**后果**

- 上游升级时四份行清单要人工对齐：`src/__tests__/patch.spec.ts` 拿本包四份与 vendor 原文件逐行比对（冲突三行按装配树剔除后比较），漂移会红。
- 计划模式的英文规则段与各工具行参数现在由本包持有（原样复制，不改文案）。
- Agent Teams bundle 关掉后，四份 preset 里没有 `subagent` / `subagent_fork` 直连委派工具，只剩 Workflow 的 `agent()` 起子代理；要恢复直接委派得改本包。
