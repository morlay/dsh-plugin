# 会话编辑闭环装配

状态：**已实现**（四层服务 + 装配 bundle 已落地，示例工作区的 web 与 desktop 两种模式可跑）
范围：本包（`bundles/better-session/`）聚合的**会话编辑四层的职责、分层、装配与操作语义**——契约层 / 编排层 /
实现层 / 聚合层与会话 UI 接管；各包内部实现见各自包层 `.agents/`，仓库布局与其他上下文的装配见
[设计 20260917-系统设计](../../../../../.agents/designs/20260917-系统设计.md)，包清单与门面见根
[`README.md`](../../../../../README.md)，术语与边界见 [`.agents/CONTEXT-MAP.md`](../../../../../.agents/CONTEXT-MAP.md)。
官方两条外发通路（`session-telemetry-otel`、`session-log-deepseek`）**不在本 bundle 范围内**：它们仍在装配里，
要不要关是部署层的取舍，不由会话编辑这一层替它决定。
约束：**不改上游、不改 vendor**（`@deepseek-ai/*` 与 `vendor/**` 只读，扩展只走 cordis 插件层与本地 patch）。

分支式会话编辑：在不修改上游 `@deepseek-ai/*` 代码的前提下，为 DeepSeek Harness
会话提供 **就地编辑 / 重试 / 撤回 / 分支**（rewind / retry / recall / fork）闭环——GUI
里撤回用户消息到输入框或就地重写、重试任意回合，重写**同一会话**（session id 不变），只有分支才派生新 id。

## 结论摘要

| 议题                             | 结论                                                                                                                                                                                                                                                                                                                                                                                                           | 一句话理由                                                                      |
| -------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------- |
| 分支面                           | `SessionBranchProvider` 是与上游 `SessionHandle` **平行**的额外 provider 抽象，rdb 同时实现两者并自动注册 `ctx.sessionBranch`（[ADR-20260917-分支面作为与上游SessionHandle平行的provider抽象](../../../../session/session-branch/.agents/adrs/20260917-分支面作为与上游SessionHandle平行的provider抽象.md)）                                                                                                   | append-only 与「显式回退 + 闭合边界派生」是两种写入语义，分开后上游不必改       |
| 就地编辑                         | edit / retry / reroll 用 `rewind` 截断 + `append` 重写**同一会话**，session id 不变、版本树单根；只有 `fork` 创建新 id（[ADR-20260917-就地编辑重写同一会话而非新建会话](../../../../session/ui-conversation-message-actions/.agents/adrs/20260917-就地编辑重写同一会话而非新建会话.md)）                                                                                                                       | 会话身份不变，历史才可追溯                                                      |
| 撤回（recall）                   | 只 `rewind` 截断到目标消息边界（轮首到前一轮 `turn/end`，轮内 followup 与轮外 user 消息 exclusive drop），不重写、不重放、不写版本效果，文本由 client 回填 composer（[ADR-20260917-编辑入口不依赖轮次归属](../../../../session/ui-conversation-message-actions/.agents/adrs/20260917-编辑入口不依赖轮次归属.md)）                                                                                              | 用户要「改完自己发」，重放等于代替用户决定                                      |
| rewind 支持 live 会话            | 截断 RDB 与内存 log、对齐 handle cursor、重置 agent 轮次游标；截断前先停止运行中的 loop（`cancel` + `whenIdle`）（[ADR-20260917-rewind绕过handle模型直接截断](../../../../session/session-rdb/.agents/adrs/20260917-rewind绕过handle模型直接截断.md)、[ADR-20260917-rewind前主动停止运行中的loop](../../../../session/ui-conversation-message-actions/.agents/adrs/20260917-rewind前主动停止运行中的loop.md)） | GUI 打开中的会话也要能就地编辑，且不能与 agent 写内存 log 并发                  |
| 版本效果（类型保留、写侧不产出） | 版本效果事件与其读侧投影已删除，类型只作历史形状保留（识别旧会话）；写侧不再产出（[ADR-20260920-删除版本树投影并停止写版本效果](../../../../session/session-branch/.agents/adrs/20260920-删除版本树投影并停止写版本效果.md)）                                                                                                                                                                                  | 没有读者的写入不值得留；旧数据凭信封安全跳过                                    |
| 配置覆盖                         | 配置就是行 config（bundle patch / profile patch / 设置页改的那份 entry config）——上游 settings 只投影 volatile 字段做表单编辑，不再覆盖插件 config（[ADR-20260922-跟随上游session-format-v4](../../../../session/session-rdb/.agents/adrs/20260922-跟随上游session-format-v4.md)）                                                                                                                             | 运行期可改，不必重装 patch；旧 settings.yaml 由上游启动时一次性导入到同 id 的行 |
| 原地重写日志的派生水位           | 截断后主动失效 `ctx.tokenMeter` 折叠与投影单元缓存（能力探测 + 告警），并用 `balanceRewindPrefix` 配平保留前缀（[债务 20260917-token-meter水位按位置前进需主动失效](../../../../../.agents/debts/20260917-token-meter水位按位置前进需主动失效.md)）                                                                                                                                                            | 上游水位按位置前进而非事件身份，不失效就会在错位处继续折叠                      |
| 对话 UI 接管                     | 官方 `ui-conversation` 行**照旧启用**：编排层的 client 半只经官方槽位替换 `conversation.chat.node` 的 `user` / `steering`（[ADR-不fork上游前端组件只做插槽扩展](../../../../../.agents/adrs/20261001-不fork上游前端组件只做插槽扩展.md)）                                                                                                                                                                      | 有槽的才做：fork 的同步与失效成本不该付；组件内部的改点不再做                   |

## 事实基线

### 分层模型

三层 cordis plugin，依赖单向向下：

```
契约层  @morlay/session-branch                provider 抽象 + SessionBranch 服务
   ▲        ▲
   │        │
编排层  @morlay/ui-conversation-message-actions   SessionEditor 编排 + client UI（chat 节点替换 + composer 统计行覆盖）
   │        │
实现层  @morlay/session-rdb                  RDB 持久化 + branch provider 双服务
```

| 层     | 包                                        | 职责                                                                                                                                             |
| ------ | ----------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------ |
| 契约层 | `@morlay/session-branch`                  | `SessionBranchProvider` 抽象（rewind / forkFrom / readBranchPrefix）+ `SessionBranch` 服务                                                       |
| 编排层 | `@morlay/ui-conversation-message-actions` | `SessionEditor` 编排（edit / retry / recall / fork 完整功能）+ client bundle（`conversation.chat.node` 的 `user` / `steering` 渲染替换）         |
| 实现层 | `@morlay/session-rdb`                     | RDB 持久化（实现上游 `SessionHandle` 模型）+ 分支 provider（实现 `SessionBranchProvider`）+ storages 接管（投影缓存服务与 workspace 域 KV 后端） |
| 聚合   | `@morlay/better-session`（本包）          | profile bundle：`cordis.patch.yml` 一次性装配以上全部到 web profile                                                                              |

client 半（浏览器）除编排层自己的 bundle 外，还依赖样式基础（`client/ui-primitives`，随用它的 client 行内联），
并在官方行之上替换 / 覆盖上述两个槽位——形态见
[ADR-不fork上游前端组件只做插槽扩展](../../../../../.agents/adrs/20261001-不fork上游前端组件只做插槽扩展.md)，
操作语义与浏览器半细节见
[设计 20260917-编排层操作语义](../../../../session/ui-conversation-message-actions/.agents/designs/20260917-编排层操作语义.md)。

### 装配（本包 bundle patch）

`cordis.patch.yml` 一次装配四层服务：持久化（RDB，替换官方 jsonl）、分支数据、edit / retry / recall / fork 编排、
`conversation.chat.node` 渲染替换，并插入编排层那两行（对话外壳仍走官方行）。

服务面（行 id ↔ 服务）：`session-rdb` → `ctx.sessionPersistence` 与 `ctx.sessionProjectionCache`；
`session-branch` → `ctx.sessionBranch`；`ui-conversation-message-actions` → `ctx.sessionEditor` 与 client 半的
槽位替换；`reference` → 引用展开；`ui-conversation-manager` → 「对话管理」页。基础面
（`@morlay/dsh-client-ui-primitives`：基础面（布局原语 / 控件 / 按 schema 自动注册各行的配置页 `plugins.row.config`））随用到它的
client 行内联，不是装配行（[ADR-基础面暂时内联而不是装配行](../../../../client/ui-primitives/.agents/adrs/20261001-暂时内联而不是装配行.md)）。逐行以
[`cordis.patch.yml`](../../cordis.patch.yml) 为准，rdb 替换的起因与权衡见
[ADR-20260917-rdb替换官方jsonl持久化](../adrs/20260917-rdb替换官方jsonl持久化.md)。

默认配置为 SQLite（`$DSH_HOME/sessions/sessions.sqlite`）；`session-rdb` 行 config 的 `type: postgres` + `connectionString` 可切 PostgreSQL；
官方 `session-persistence-jsonl` 被禁用（`disabled: true`）。

同批接管的官方行由 session-rdb 提供同名服务：`storage-json` / `session-projection-cache`（workspace 域 KV 与投影
checkpoint 落 RDB 语义表）与 `session-query-sqlite`（精确读 / 过滤 / 血缘复用上游 `SessionQueryEngine` 基类，全文检索维持
disabled）——起因与权衡各在
[ADR-20260917-接管storages到rdb语义表](../../../../session/session-rdb/.agents/adrs/20260917-接管storages到rdb语义表.md) 与
[ADR-20260917-接管会话查询服务所有权](../../../../session/session-rdb/.agents/adrs/20260917-接管会话查询服务所有权.md)。

装配面判据（patch 的每个 insert 行可解析到真实包且属本 bundle 依赖、依赖不漏装配、插入的 client 包声明
`client-modules` 需要的入口与平台）与守护测试见 [本包规范 how-to-verify](../standards/how-to-verify.md)。

本 bundle 在 profile 平面的位置（能力包 patch 先插行；配置层 [`@morlay/mydsh-profile`](../../../mydsh-profile/README.md)
只按行 id 配值，排在最后）见 [设计 20260917-系统设计](../../../../../.agents/designs/20260917-系统设计.md)。

### 操作语义

`edit` / `retry` / `reroll` 就地重写同一会话（`rewind` 截断 + `append` 重放，session id 不变）；`recall` 只 `rewind` 截断
并把消息文本交回 composer（不重放）；只有 `fork` 派生新 id。落在被截断区间里的**完整压缩事务会在重写时补回**（重排为
standalone 形态，保证摘要仍生效、压缩仍可再触发，见
[ADR-20260917-压缩事务在重写时补回](../../../../session/ui-conversation-message-actions/.agents/adrs/20260917-压缩事务在重写时补回.md)）。
各操作的完整语义见
[设计 20260917-编排层操作语义](../../../../session/ui-conversation-message-actions/.agents/designs/20260917-编排层操作语义.md)。

## 取舍

被否掉的路线（理由的 home 是各自的 ADR / 债务，这里只列结论）：

- **替换上游 `SessionHandle`**、而不是平行加分支面：rdb 会被 coordinator 私有实现绑住
  （[ADR-20260917-分支面作为与上游SessionHandle平行的provider抽象](../../../../session/session-branch/.agents/adrs/20260917-分支面作为与上游SessionHandle平行的provider抽象.md)）。
- **保留官方 JSONL 持久化**、只在上面旁路截断：顺序介质给不了原子截断
  （[ADR-20260917-rdb替换官方jsonl持久化](../adrs/20260917-rdb替换官方jsonl持久化.md)）。
- **接管官方 `ui-conversation` 行（薄壳 fork 对话外壳）**：能改组件内部（输入框引用插入与装饰、队列行
  「编辑=撤回」），代价是每次上游同步逐文件判定冲突、上游 client 契约换代即静默失效——不值这份长期成本
  （[ADR-不fork上游前端组件只做插槽扩展](../../../../../.agents/adrs/20261001-不fork上游前端组件只做插槽扩展.md)）。

## 开放问题

还没定的事，各自的 home 是包层 / 仓库层债与包层设计：

- 上游是否提供 meter 失效 / 回退 API，决定我们侧的 duck-type 失效能否删
  （[债务 20260917-token-meter水位按位置前进需主动失效](../../../../../.agents/debts/20260917-token-meter水位按位置前进需主动失效.md)）；
- 放弃的 fork 能力（输入框 raw markdown 与引用插入归一、队列行「编辑=撤回」）是否要换个形态做回来——上游若给出
  对应的扩展面（编辑器插入决策可插 / composer 草稿结构化 / 组件级替换）再评估
  （[ADR-不fork上游前端组件只做插槽扩展](../../../../../.agents/adrs/20261001-不fork上游前端组件只做插槽扩展.md)）；
- client 侧测试 harness 的来源（上游 test runtime 或自建），决定 slot 装配面何时有测试
  （[债务 20260917-对话UI的槽注册面缺真装配用例](../../../../session/ui-conversation-message-actions/.agents/debts/20260917-对话UI的槽注册面缺真装配用例.md)）；
- client 引用渲染与队列的未做项（思考块 Markdown、队列去 inline edit）
  （[设计 20260917-对话UI重构](../../../../session/ui-conversation-message-actions/.agents/designs/20260917-对话UI重构.md) 的「未决问题」）。
