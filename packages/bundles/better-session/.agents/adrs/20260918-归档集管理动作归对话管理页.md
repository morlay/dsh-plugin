# 归档集管理动作归对话管理页

状态：已采纳

背景：归档集是「已归档会话」那一批数据。上游设置页那份「已归档会话」列表（能力只有搜索 + 取消归档）在上游
0.1.7 已随包删掉，归档行与过滤落到侧边栏视图选项（`ArchivedFilter`：默认隐藏 / 显示 / 只看）。同一份归档集还需要
删除（`@morlay/session-rdb` 的 `POST /api/session.delete`，只限已归档）与导入（`POST /api/session.import`）：
上游那套没有这两个动作，而会话头部那条导入的语义是**覆盖当前会话内容**，与「管理归档集」不同源。

**决定**

归档集的管理动作（取消归档 / 删除 / 导入成新会话）只有一个入口：`@morlay/ui-conversation-manager` 的「对话管理」页
（`sidebar.panellist` + `main` keyed 成对注册）。导入落成**新会话**（不带 `sessionId`）；侧边栏视图过滤只负责查看与
行内取消归档。

**考虑过的选项**

- 扩展上游设置页：上游 `@deepseek-ai/*` 只读，改不了。
- 设置页与新页面并存：同一份归档集两个入口，删除 / 导入只在其一，用户要先知道该去哪一页。
- 保留头部的覆盖式导入：覆盖需要一个「当前会话」目标，管理页没有这个上下文，且它与取消归档 / 删除不同源。
- 删除放开到未归档会话：与
  [ADR-20260917-会话删除仅限已归档且硬删](../../../../session/session-rdb/.agents/adrs/20260917-会话删除仅限已归档且硬删.md)
  冲突；未归档会话可以先在工作区归档、再到本页删除。

**后果**

- 归档集的删除与导入只在管理页：搜到的行即可取消归档、删除，或按 zip 导入成新会话。
- 覆盖式导入不提供：zip 只能落成新会话。要在已有会话上覆盖内容需另立入口，当前没有这个需求。
