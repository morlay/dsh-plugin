# 本部署自己注册一份 agent preset

状态：已采纳

背景：行清单（工具 / 命令 / 压缩 / 委派 / skill 发现）住在 agent preset 的 `config.plugins` 里。复用官方
shipped preset 给两个会话模式（`coding` / `chat`）供行，有三处要还的账：

- `chat` 的白名单是提问 + 联网三件，而官方 `minimal` 的行清单里**没有 `tool-web`**——收口之后一件都不剩，
  联网能力直接没有；
- 官方 preset 自带的上游注入（`agent-instructions` / `tool-skill`）在会话开关之外，要在我们这一侧另做
  「让位」与「抢面」，两个动作都得按"官方预设长什么样"来判；
- 抢 `skill` 面意味着目录的 kind 必须换成我们自己的（`context-assembler`），可见标签跟着变。

自己注册一份 preset 让这三笔账在**我们自己的 preset 会话**里不存在；留给官方 preset 会话的兜底（让位 / 抢面）
保留，官方四个 shipped preset 照旧可选、不禁。

**决定**

`bundles/session-mode-profile`（装配入口那一层）插一行 `@deepseek-ai/dsh-agent-preset`：行 id
`preset-mode-switch`，`config.id` 是 `mode-switch`，`config.plugins` 直接引用
[`@morlay/dsh-agent-toolkit/rows`](../../../../profile/dsh-agent-toolkit/src/rows.ts) 的
`TOOLKIT_PRESET_ROWS`（preset 平面那一套功能行的唯一真源）；展示元数据 `name` / `description` / `order: 5`
写在这一行上（自定义 id 不吃上游的内置字典）。两个模式都声明 `preset: mode-switch`
（[`MODE_PRESET_ID`](../../../../profile/dsh-session-mode/src/mode-sources.ts)），**共享是刻意的**：差异
全由会话级收口表达（persona / `allowTools` / `instructions` / `runtimeContext`）。新会话的默认 preset 在配置层
（`@morlay/mydsh-profile`）把 `agent-preset-registry` 的 `default` 指向它。

preset 里**不放注入面**：不放上游 `agent-instructions`、不放上游 `tool-skill`（这两面由
`@morlay/dsh-context-assembler` 的通道提供），也不放本仓库的 `tool-guidance`——它往通道这个 host 单例注册用法
正文，属于 host 平面（上游判据：一行只属于一个平面，
`vendor/deepseek-harness/scripts/verify-cordis-config.ts` 的 `validatePresetPlaneSeparation`）。

**考虑过的选项**

- **继续复用官方 preset，只把 `chat` 换成 `standard`**：联网回来了，但 `chat` 会连带拿到文件与 Shell 工具的行，
  收口变成"靠白名单兜住"，而官方行升版时我们看不出差异。
- **覆盖 shipped preset 的 `config.plugins`**：官方明说覆盖是整段替换、不合并后续内置变更，等于把官方清单复制进
  本仓库，还要在别人的 id 上做维护（`packages/bundle/web-app/presets/cordis.patch.yml:1-3`）。
- **把行清单摊在 host 平面（每个模式一套 isolate 子树）**：与官方"一行只属于一个平面"的校验对抗，且官方 web-app
  已把那些行在 host 平面设成 `disabled` 交给 preset。
- **给两个模式各注册一份 preset（不共享）**：两份 `config.plugins` 的差异只有 `instructions` 之类的会话开关，
  而开关本来就按会话生效——多一份声明只是多一份要同步的清单。

**后果**

- 行清单的所有权在我们这边：上游行升版时要人工对齐 `TOOLKIT_PRESET_ROWS`（包名 / 行 id / `config`），
  漏一处由 `bundles/session-mode-profile/src/__tests__/patch.spec.ts` 的逐行比对与真装配探针
  （[`tool/verify-preset-plane.mts`](../../../../desktop/dsh-desktop-host/tool/verify-preset-plane.mts)）显形。
- `preset` 不再要求一对一（`configProblem` 只校验"空串=不挂"与其余字段）：预设 → 模式的反查只在映射唯一时
  回答，共享时 `SessionModes.modeForPreset` 返回 `undefined`，模式由会话事实决定（投影 → 继承 → 部署默认）。
- 「选模式就换 preset」这条路只在目标 preset 与当前不同时才走（本部署两个模式共享，所以切 chip 不会重挂行清单）。
- **计划模式的规则段由我们自己维护**：`planning` 组（`plan-mode` 行 + `isolate: { planMode: true }`）照上游的
  组形装进 `TOOLKIT_PRESET_ROWS`，但 `config.section` 是我们自己的**中文**契约
  （`@morlay/dsh-agent-toolkit/rows` 的 `PLAN_MODE_SECTION`）——上游那个 `section` 是部署自有的**必填**项
  （`vendor/deepseek-harness/packages/plan/plan-mode/src/index.ts:70-117`：缺 / 空 / 多键都在装载时抛，没有默认
  文案），所以这一项躲不开"谁来写"。代价：上游改 `plan-mode` 的契约（`section` 的形状、`exit_plan_mode` 的提交与
  `plan-review` 的批准语义）时要人工核对这段中文；契约锚点（只读探索、规则压过工具说明、`exit_plan_mode`
  唯一且最后、评审驳回与通道中断）由 toolkit 的 `rows.spec.ts` 钉住关键短语。
- 官方四个 shipped preset 照旧可选；用户显式选它们时，工作区指令让位与 skill 抢面那两条逻辑按原样生效
  （见 [ADR-工作区指令让位skill面由通道抢面](../../../../context/dsh-context-assembler/.agents/adrs/20260929-工作区指令让位skill面由通道抢面.md)）。
- 判据：本 bundle 的 `patch.spec.ts`（声明形状、行清单逐行同形、注入面不在其中、两个模式都挂它、配置层的默认
  指向它）、`dsh-session-mode` 的 `preset-plane.spec.ts`（真装配：chat 三件可用 / 注入 0 条 / 一份技能目录 /
  官方 preset 会话不受影响 / 切模式不重挂）与真 profile 探针。
