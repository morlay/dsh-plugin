# 行清单与注入面的装配（session-mode-profile）

状态：**已实现**（preset 声明、模式行、subagent 接管行、注入通道与收口行、工具说明都由本 bundle 展开）
范围：`packages/bundles/session-mode-profile/` 装什么、数据从哪来、两个模式怎么共享一份 preset、注入面按会话判归谁；
门面与安装方式见该 bundle [`README.md`](../../README.md)。
约束：本 bundle 不持有行数据——它只把各能力包的 `rows` 出口按装配顺序展开（`tsdown.config.ts`），patch 是生成物。

## 结论摘要

| 议题        | 结论                                                                                 | 一句话理由                                                     |
| ----------- | ------------------------------------------------------------------------------------ | -------------------------------------------------------------- |
| 行清单      | 由本包声明的 preset（`preset-mode-switch`）引用各能力包的 `rows`                     | 行清单只有一份真源：数据住在能力包里                           |
| 模式        | `coding` / `chat` 都挂同一份 preset，差异全由会话级收口表达                          | preset 回答"这个 agent 有哪些行"，模式回答"这个会话怎么用它们" |
| 注入面      | 不在 preset 行清单里：`agent-instructions` 与 `tool-skill` 由通道提供                | 通道是 host 单例，两个平面各一份会互相顶掉                     |
| 工具说明    | `tool-guidance` 留 host 平面                                                         | 它往通道注册用法正文，同上                                     |
| 官方 roster | 保留（`ui-agent-preset`）；我们的模式 chip 挂 `conversation.input.left`（list 槽位） | 槽位单注册，官方管"挂哪套行"、我们管"会话级扩展"，两套并存     |
| 切模式      | 官方 preset 该换还是要换（`SessionModes.select` 只在目标与当前不同时才换）           | 模式开关只收得住通道这一侧，官方 preset 自带的注入在它之外     |

## 事实基线

### 装什么、数据从哪来

| 装什么                                          | 数据从哪来                                                                                                         |
| ----------------------------------------------- | ------------------------------------------------------------------------------------------------------------------ |
| `ui-primitives-fork`（共享 client 行）          | 每个 client bundle 各插一次：同 id 重复插入是幂等的（Loader 复用同一 Entry，后者胜）                               |
| `preset-mode-switch`（本部署的 agent preset）   | [`@morlay/dsh-agent-toolkit/rows`](../../../../profile/dsh-agent-toolkit/src/rows.ts) 的 `TOOLKIT_PRESET_ROWS`     |
| `session-mode`（模式定义 + `preset` 映射）      | [`@morlay/dsh-session-mode/rows`](../../../../profile/dsh-session-mode/src/rows.ts)                                |
| `subagent` 行（按官方行 id 复用换实现）         | [`@morlay/dsh-subagent/rows`](../../../../subagent/dsh-subagent/src/rows.ts)                                       |
| `context-assembler` + `context-assembler-scope` | [`@morlay/dsh-context-assembler/rows`](../../../../context/dsh-context-assembler/src/rows.ts)                      |
| `tool-guidance`（汉化 + 用法分组）              | [`@morlay/dsh-agent-toolkit/rows`](../../../../profile/dsh-agent-toolkit/src/rows.ts)                              |
| 官方 roster 保留（`ui-agent-preset`）           | 官方管"挂哪套行"的选择面；我们的模式 chip 挂 composer 工具行左侧（`conversation.input.left`，list 槽位），两套并存 |

### 一个 preset，两个模式

`coding` / `chat` 都挂 `preset-mode-switch`（`config.id` 就是会话里记的身份），差异全由**会话级收口**表达
（persona / `allowTools` / `instructions` / `runtimeContext`）。行清单里**不放注入面**：`agent-instructions` 与
`tool-skill` 由通道提供，`tool-guidance` 是 host 平面行（它往通道这个 host 单例注册用法正文，两个平面各一份会互相
顶掉）。新会话的默认 preset 在配置层指向它（[`@morlay/mydsh-profile`](../../../mydsh-profile/README.md) 的
`agent-preset-registry.default`）。理由与代价见 [`ADR-自己注册preset`](../adrs/20260929-自己注册preset.md)。

### 注入面按会话判归谁

`context-assembler` 这一行装的是通道本体 + `agent-instructions` + `skill-catalog`——官方 preset 自带工作区指令那一行
时我们**让位**；`skill` 工具与目录反过来由通道按会话注册（**抢面**）。我们自己的 preset 行清单里这两面都不放。理由与
上游判据见
[`ADR-工作区指令让位skill面由通道抢面`](../../../../context/dsh-context-assembler/.agents/adrs/20260929-工作区指令让位skill面由通道抢面.md)。

模式开关（`instructions: false`）只收得住这一行这一侧；官方 preset 自带的注入在它之外，所以切模式时官方 preset 该换
还是要换（`SessionModes.select` 只在目标与当前不同时才换）。

## 取舍

- **能力包只发 `rows`、patch 住 bundle**：能力包换一种平面装配不用改自己，行清单的两处装配（host / preset）也不会漂移。
- **不把注入面放进 preset**：通道是 host 单例，放两个平面会互相顶掉用法正文与目录。
- **不替换官方选择面**：槽位 `conversation.hero.agentPreset` 是单注册的，抢它就要把官方 roster 整套停掉，而模式与
  preset 说的不是同一件事。

## 开放问题

- 官方 shipped preset 被显式选中时的模式扩展：本部署只给自己那份 preset 写扩展，官方那四个按官方原样跑。
