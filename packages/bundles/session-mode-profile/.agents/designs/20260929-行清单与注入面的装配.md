# 行清单与注入面的装配（session-mode-profile）

状态：已实现（本 bundle 只装 host 平面那几行；行清单与注入面都归会话挂着的 shipped preset）
范围：`packages/bundles/session-mode-profile/` 装什么、数据从哪来、行清单归谁、注入面归谁、模式与 preset 的关系、
切模式时换什么；门面与安装方式见该 bundle [`README.md`](../../README.md)。
约束：本 bundle 不持有行数据——它只把各能力包的 `rows` 出口按装配顺序展开（[`tsdown.config.ts`](../../tsdown.config.ts)），
patch 是生成物；上游 `@deepseek-ai/*` 只读，扩展走 cordis 插件层。

## 结论摘要

| 议题                            | 结论                                                                                                                                                   | 一句话理由                                                                  |
| ------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------- |
| 装什么                          | 装配入口那四段 `insert`：`session-mode`、`subagent` 接管行、通道、`tool-guidance`                                                                      | 一行只属于一个平面：注入通道与用法正文是 host 单例的服务面                  |
| 行清单                          | 归会话挂着的 shipped preset；新会话是官方 web-app 的默认 `standard`                                                                                    | 自持一份要跟上游行升版逐项对齐包名 / 行 id / `config`                       |
| 注入面：工作区指令              | 官方 `@deepseek-ai/dsh-agent-instructions`（会话挂的那份 preset 里的行）；我们的通道不注入它                                                           | 一面一个 home：同一份内容只从一条路径到模型                                 |
| 注入面：技能目录与 `skill` 工具 | 官方 `@deepseek-ai/dsh-tool-skill`（preset 行）；`tool-guidance` 只把用法分组注册进 `ctx.skills`                                                       | 目录的发布与按需加载是官方那一行的职责                                      |
| 注入面：我们通道                | 只剩"装配结果改写 + 降级 section 注入 + `instructions` 开关"（`contextChannel()`，不带 config）                                                        | 通道不再认识"常驻内容"，它的 config 就三样：`keep` / `suppress` / `replace` |
| 注入面：用法正文                | `base` 组常驻由 `tool-guidance` 自己挂 `agent/pre-step` 送达，其余组按需经官方目录加载                                                                 | 正文按这一步实际可见的工具渲染，与工具表同源                                |
| 模式与 preset                   | `config.modes.<id>.presetsOnly` 可选、本部署三个模式都留空（不限制）；`coding` 不设收窄但禁掉改意图那条上游规则（`denyPolicies: [fs/edit-intent]`），`chat` 收成提问 + 联网三件 | preset 回答"这个会话有哪些行"，模式回答"这个会话怎么用它们"                 |
| 切模式                          | 不换 preset（无声明可换），只换会话级收口（工具名单 + policy 判据按会话现算）                                                                          | 用户在官方 roster 里选的那份行清单不被模式 chip 覆盖                        |
| 官方 roster                     | 保留（`ui-agent-preset`）；我们的模式 chip 挂 `conversation.input.left`（list 槽位）                                                                   | 槽位单注册，官方管"挂哪套行"、我们管"会话级扩展"，两套并存                  |

## 事实基线

### 装什么、数据从哪来

| 装什么                                | 行 id               | 数据从哪来                                                                                                                         |
| ------------------------------------- | ------------------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| 模式定义（会话级扩展）                | `session-mode`      | [`@morlay/dsh-session-mode/rows`](../../../../profile/dsh-session-mode/src/rows.ts)                                                |
| `subagent` 接管行（同 id 复用换实现） | `subagent`          | [`@morlay/dsh-subagent/rows`](../../../../subagent/dsh-subagent/src/rows.ts)                                                       |
| 注入通道本体                          | `context-assembler` | [`@morlay/dsh-context-assembler/rows`](../../../../context/dsh-context-assembler/src/rows.ts) 的 `contextChannel()`（不带 config） |
| 工具说明（汉化 + 用法分组）           | `tool-guidance`     | [`@morlay/dsh-tool-guidance/rows`](../../../../profile/dsh-tool-guidance/src/rows.ts) 的 `toolGuidanceRow()`                       |

基础面（`@morlay/dsh-client-ui-primitives`）随用到它的 client 行内联，本包不插这一行
（[ADR-基础面暂时内联而不是装配行](../../../../client/ui-primitives/.agents/adrs/20261001-暂时内联而不是装配行.md)）。

判据：[`patch.spec.ts`](../../src/__tests__/patch.spec.ts)（六条）——生成物与 `renderPatch()` 同形；这几行 id 都在场；
装配里没有 `@deepseek-ai/dsh-agent-preset`（行清单不归我们）；`tool-web` / `tool-fs` / `plan-mode` / `compaction-basic`
这类**行数据**的 id 一件都不在。

### 新会话挂哪份行清单

registry 的默认由官方 web-app 给 `standard`（`vendor/deepseek-harness/packages/bundle/web-app/cordis.patch.yml:565`），
本部署不覆盖它。官方 `standard` 那份行清单
（`vendor/deepseek-harness/packages/bundle/web-app/presets/standard.patch.yml`）里与本 bundle 的口径有关的是：

| 面              | 那份 preset 里的行                                                                                          |
| --------------- | ----------------------------------------------------------------------------------------------------------- |
| 工作区指令      | `agent-instructions`（`@deepseek-ai/dsh-agent-instructions`，`maxBytes: 65536`）                            |
| 时钟            | `time-context`（`@deepseek-ai/dsh-time-context`，0.2.1-alpha.1 起）：每步往请求历史注入一条时间读数         |
| 技能发现与加载  | `skill-filesystem` + `tool-skill`（目录与 `skill` 工具都由它发布）                                          |
| 文件 / Shell    | `tool-fs`、`tool-fs-search`、`tool-bash`（非 win32）、`tool-pwsh`（win32）、`tool-jobs`                     |
| 自动化任务      | `tool-schedule`（四个 `schedule_*` 工具；`schedule` / `ui-schedule` 两行由 web-app 挂，preset 只管工具面）  |
| 计划模式        | `planning` 组（`plan-mode` + `isolate: { planMode: true }`，`config.section` 是官方那套英文契约）           |
| 压缩            | `compaction` 组（`compaction-basic` / `command-compact` / `tool-result-pruner`）                            |
| 委派 / workflow | `delegation` 组（`tool-subagent*`、`workflow-ptc`、`tool-workflow`、`tool-ralph`；子代理那几行 deny 了 `schedule_*`） |
| 其余            | `persona`、`command-goal` + `tool-goal`、`tool-ask-user`、`tool-todo`、`tool-web`、`tool-present`           |

`tool-guidance` 不在任何 preset 里：它往通道这个 host 单例注册内容，进了 preset realm 会与 host 那份互相顶掉。

**0.2.1-alpha.1 起上游把自动化任务默认打开**（`schedule` / `ui-schedule` 由 web-app 挂，preset 声明 `tool-schedule` 与
子代理行的 `schedule_*` deny）：本部署**接受这份默认**——两行与四个工具都留，`coding` 模式照旧"不设收窄"因而看得见
它们，中文短描述与用法分组已经在 `tool-guidance` 的 `flow` 族里（四个 `schedule_*` 的名字与语义核对过上游
`tool-schedule` 的 README 与源码）。那一行打开的是官方 `schedule` **存储域**：`storage-domain` 的 backend 路由在
`@morlay/better-session` 里指向 `rdb`，所以这个域由 `@morlay/session-rdb` 的 KV 后端服务（落 `t_schedule_tasks`；
判据见该包 `schedule-row.spec.ts`）——不服务它，那一行装载即报
`rdb storage backend serves only the 'workspace' domain`。

### 两个模式（差异全在会话级收口）

| 模式     | `preset` | `allowTools`                                     | `denyTools`        | `denyPolicies`                                            | `instructions` | `runtimeContext` | `role`             |
| -------- | -------- | ------------------------------------------------ | ------------------ | --------------------------------------------------------- | -------------- | ---------------- | ------------------ |
| `coding` | 不写     | 不写（不设收窄，用那份 preset 的全部工具）       | 不写（一件都不禁） | `fs/edit-intent`（免"先读后改"；写那条的 CAS 安全网留着） | 缺省（要）     | 缺省（要）       | `main`、`subagent` |
| `chat`   | 不写     | `ask_user_question` / `web_search` / `web_fetch` | 不写（一件都不禁） | 不写（两条上游规则都照旧生效，这个模式没有文件工具）      | `false`        | `false`          | `main`             |

真源是 [`mode-sources.ts`](../../../../profile/dsh-session-mode/src/mode-sources.ts)（`MODE_SOURCES` / `DEFAULT_MODE`），
由 `sessionModeRows()` 渲染成 `session-mode` 行的 `config`。`allowTools` / `denyTools` 与两份 policy 名单都是
"留空 = 不参与"（空数组不进 config），`deny` 优先（
[ADR-allowTools留空即不设收窄](../../../../profile/dsh-session-mode/.agents/adrs/20260929-allowTools留空即不设收窄.md)）；
按模式的 policy 拦截（`modes.<id>.allowPolicies` / `denyPolicies`）也住这份模式定义里——上游
`fs/write-intent` / `fs/edit-intent` 上的裁决由 `session-mode` 那一行在链首改写，本 bundle 里没有
`fs-intent-relax` 这一行（[设计 按模式的 policy 拦截](../../../../profile/dsh-session-mode/.agents/designs/20260929-按模式的policy拦截.md)）。

### 注入面归谁

| 面                                | 谁送                                                                                           | 我们做什么                                                            |
| --------------------------------- | ---------------------------------------------------------------------------------------------- | --------------------------------------------------------------------- |
| 工作区指令（`AGENTS.md` 那类）    | 官方 `agent-instructions`：baseline 进 durable context，增量在 `agent/pre-step` 里 append      | 不做（通道里没有 `agent-instructions` 这个 capability 了）            |
| 时钟                              | 官方 `time-context`：`agent/pre-step` 里追加一条带时间读数的 `user/message`                     | `chat` 的 `runtimeContext: false` 在瀑布上丢掉它（`coding` 照旧带时钟） |
| 技能目录                          | 官方 `tool-skill`：`agent/pre-step` 发布 `kind: skill-catalog` 的目录，随 `skill` 工具可见性   | 只把用法分组注册进 `ctx.skills`（目录由官方列）                       |
| 用法正文                          | `tool-guidance`：`base` 组自己挂 `agent/pre-step` 常驻，其余组走官方目录按需加载               | 按这一步实际可见的工具渲染正文                                        |
| 其余 section                      | 我们通道：`keep` / `suppress` / `replace` + 把非 keep 的 section 降级成紧随用户消息的 reminder | 本 bundle 装的是这条通道本体                                          |
| 工具说明（一行中文 + 剥参数说明） | `tool-guidance` 改 `system-prompt/assemble` 的结果投影                                         | 不碰注册表（同名重注册会触发 `tools/change` 装配风暴）                |
| 动态快照                          | 上游 runtime context                                                                           | `session-mode` 的收口按会话调 `systemPrompt.suppressRuntimeContext()` |

判据都在包内真装配用例里，不靠探针：preset 平面与注入面由
[`preset-plane.spec.ts`](../../../../profile/dsh-session-mode/src/__tests__/preset-plane.spec.ts) 观察
（真 `Loader` + 真上游行），`allowPolicies` / `denyPolicies` 的落地面由 `session-mode.spec.ts`（替身上游）与
本 bundle 的 `patch.spec.ts` 分担；`packages/desktop/dsh-desktop-host` 因此不必为观察 `agent/pre-step` 加依赖。

同一份口径写在这几处、内容一致：本 bundle 的 `package.json` `description` 与 `locale/{zh,en}.json`（行清单归会话挂着
的 shipped preset、本包不自建 preset），以及 `dsh-session-mode` 的[验证规范](../../../../profile/dsh-session-mode/.agents/standards/how-to-verify.md)
与[设计 20260924-会话模式](../../../../profile/dsh-session-mode/.agents/designs/20260924-会话模式.md)（模式不限 preset、行清单归那份 preset）。

`instructions: false` 与 `skills: false` 由 `session-mode` 的收口在 `agent/pre-step` 上收：前者丢官方 `agent-instructions`
的注入、后者丢官方 `skill-catalog` 的注入（`skills` 缺省按模式的工具名单推导）。`tool-guidance` 的常驻正文收不到那个开关
（它按"常驻就是常驻"定义自己）。真实装配里的判据见
[`preset-plane.spec.ts`](../../../../profile/dsh-session-mode/src/__tests__/preset-plane.spec.ts)（真 `Loader` + 真上游行：
新会话挂 `standard` 且模式是 `coding`；`chat` 收成三件、官方三条注入面（工作区指令 / 技能目录 / 时钟）都不进；`coding` 用行清单的全部工具、目录由官方
一行发布；切模式一次 `recompose` 都不发生；行清单里缺工具的 preset 上白名单一件都收不到）。

### 与 `subagent` 行的关系

同一行 id（`subagent`）复用换实现：Loader 对同 id 的条目复用同一个 Entry、后者替换入口 options，所以行 id 与
settings namespace 都还是 `subagent`（官方设置卡照常可用），换掉的只是实现包，顺序前提是本包排在
`@deepseek-ai/dsh-base` 之后。中文回报指引**不限 preset**（不传 `localizedReturnGuidancePresets`）：官方四个
shipped preset 与还没绑 preset 的会话都用我们的中文文案，判据是 `patch.spec.ts` 里那一行没有 `config`。

## 取舍

- **不持有行清单**：省掉"上游行升版要人工对齐包名 / 行 id / `config`"这笔债，判据也不再逐行比对（
  [`ADR-不再持有行清单`](../adrs/20260929-不再持有行清单.md)）。代价照实：计划模式的规则段是官方那份英文契约、
  委派行的 `modelSelectionSettings` 由官方定、"先读后改"的放宽只能改由 `session-mode` 的 policy 拦截表达。
- **`base` 常驻由 `tool-guidance` 自己实现，不扩通道的扩展点**：正文按这一步**实际可见的工具**渲染（`when` 过滤），
  这件事的输入在工具表里、不在通道里；通道一旦要接"常驻内容"，就得重新持有注入排程与可见性判定。代价是模式的
  三个开关对它无效（它按"常驻就是常驻"定义自己）。
- **让位与抢面两条逻辑随自建 preset 一起消失**：两面的 home 都在会话挂的那份 preset 里，我们既不让位也不抢面，
  通道只剩文本转换。
- **`chat` 的三条官方注入面都收住了，代价是每步仍付一次重算**：官方 `agent-instructions` 每步都会重读 `AGENTS.md`
  重算要送的那条消息，我们只是把结果丢掉（实测每步 1 次 fs 读，inbox 不积压、日志 0 条，见
  [设计 抑制官方注入面](../../../../profile/dsh-session-mode/.agents/designs/20260929-抑制官方注入面.md)）；`skill-catalog`
  同理；`time-context`（时钟）只在瀑布上丢一条消息，没有额外开销。`tool-guidance` 的常驻正文收不到那三个开关（它按"常驻就是常驻"定义自己）。
- **行清单缺工具的 preset 上，白名单收不到东西**：`chat` 的三件在 `standard` / `ptc` / `cordis` 上都齐，在官方
  `minimal` 上一件不剩（那份只有 `persona` 与 `persistent-shell`），目录为空是**行清单缺行**，不是收窄出错。
  同理 `minimal` 上工作区指令与技能目录都没有（那两行不在它里面）。
- **不替换官方选择面**：槽位 `conversation.hero.agentPreset` 是单注册的，抢它要把官方 roster 整套停掉，而模式与
  preset 说的不是同一件事；我们的 chip 挂 `conversation.input.left`（list 槽位），两套并存。

## 开放问题

无。`base` 常驻与模式开关的关系已在 [设计 抑制官方注入面](../../../../profile/dsh-session-mode/.agents/designs/20260929-抑制官方注入面.md)
里定死：`base` 常驻按"常驻就是常驻"定义自己，不读模式的三个开关（代价写在那份设计的代价清单里）。
