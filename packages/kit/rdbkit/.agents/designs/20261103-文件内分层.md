# 文件内分层与值归一

状态：审计完成（2026-11-03）；**批次 1（纯搬移）已执行**，批次 2-5 待执行。

范围：`packages/kit/rdbkit/src/`（生产 2316 行，测试 1163 行）。
判据：`codebase-design` 的词汇。**接口已经足够小**（`openDatabase` / `Database` / `TableHandle` / `E`），
深度是够的；问题在实现层的文件划分与「同一事实多个 home」。

## 结论摘要

| 问题             | 证据                                                                                                                                                                                                                                               | 影响                                               |
| ---------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------- |
| 单文件多概念     | 审计时的 521 行单文件（现拆成 [table/index.ts](../../src/table/index.ts)）= 行类型 + 表句柄 + 6 类 SQL 渲染 + 聚合 + 值归一；502 行单文件（现拆成 [database/index.ts](../../src/database/index.ts)）= 接口 + 两种方言 + 事务串行 + 库级操作 + wrap | 找东西靠记忆；同文件里改 A 会碰到 B                |
| 事务机制两份     | SQLite 的 `BEGIN IMMEDIATE` / 保存点（拆开前同一文件的 SQLite 分支与 PostgreSQL 分支各写一遍，嵌套判定也各一份；现两方言各自实现 [executor 原语](../../src/database/types.ts)）                                                                    | 改事务语义要改两处，容易只改一边                   |
| 值归一 3 个 home | `src/table/select.ts` 的 `normalize`（只归列，不归聚合）、`src/database/postgres.ts` 的驱动解析、`read` 完全不归；结论不一致                                                                                                                       | 同一列在 `select` 与 `read` 两条读取路径上类型不同 |
| 类型映射 6 处    | `defs.ts` 的类型名、`src/table/types.ts` 的 `ColumnValue` / `InsertRow`、`dialect.ts` 的 `columnType`（两种方言）、`src/database/postgres.ts` 的 int8 解析、`expr.ts` 的 `__value`                                                                 | 加一个列类型要改 5-6 个地方                        |
| 假接缝 / 死导出  | `write()` 就是 `read()`；`wrapDatabase` 生产零调用；`onQuery` 零调用；`aliasedTable` 死导出（`toProperty` 已删）；`MigrationRegistry` 业务只传裸数组                                                                                                     | 接口面比真实使用宽                                 |
| 同名两义         | `columnSql` 在 `expr.ts`（列引用）与 `dialect.ts`（列定义 DDL）各有一个                                                                                                                                                                            | 搜索与阅读都要先判断是哪一个                       |
| 业务被迫学实现   | `E.inSubquery(ref, Fragment)`：调用方要会 `select(...).toFragment()`（session-rdb 内 14 处）                                                                                                                                                       | 表达式接口漏了实现细节                             |

## 审计期间已修的缺陷

`SUM(bigint)` 在 PostgreSQL 上返回 `numeric`（驱动给字符串），与 `Aggregate<number | bigint>` 的声明不符
（实测：`typeof === "string"`）。`sum()` 现在按方言渲染：SQLite `SUM(x)`、PostgreSQL `SUM(x)::bigint`；
`src/__tests__/pg.spec.ts` 加了一条 `SUM(bigint)` 的断言。列类型只有 integer / bigint，cast 不丢小数。
