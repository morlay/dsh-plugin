# 替换官方进程沙箱与 fs 围栏，以支持额外可写根、只读根与拒绝项

状态：已采纳——采用方必须同时剔掉官方两个实现（`without(SandboxDefault)` + `without(FsSandbox)`）。

背景：上游沙箱策略只有 `mode` / `workspaceRoot` / `additionalWritableRoots`：`workspace-write` 的可写集合是「工作区 + 显式额外目录 + `/tmp` + `os.tmpdir()`」（`vendor/deepseek-harness/packages/sandbox/sandbox/src/roots.ts` 的 `writableRoots`），而 `confine(argv, policy)` 是契约、不能扩容。同一个 `writableRoots` 同时喂 Seatbelt profile（`vendor/deepseek-harness/packages/sandbox/sandbox-local/src/profiles.ts`）与进程内围栏（`vendor/deepseek-harness/packages/fs/fs-sandbox/src/index.ts`）。「让 agent 能写 `XDG_CACHE_HOME`，但永远不许碰项目里的 `mise.*.toml`」这类诉求因此只能整块放弃隔离。

**决定**

`@morlay/configurable-sandbox` 用自有实现替换官方 `ctx.sandbox`（进程沙箱）与 `ctx.fs`（文件系统围栏）：

- 进程沙箱继承官方 `LocalSandboxProvider`，`confine` 先走 `super.confine()`，再按方言把规则追加到返回的 argv；
- fs 侧继承官方 `LocalFileSystem`，在 `resolve` 入口拦 `--`、在五个写面上先过规则再过官方模式围栏；
- 规则来自 `{DSH_HOME}/sandbox.toml` 的 `access` 条目：`rw <path>` 追加可写根、`r- <path>` 只读、`-- <pattern>` 拒绝。

两个服务必须一起换——上游把可写集合同时喂给 Seatbelt profile 与进程内围栏，只改一侧会造出「bash 能写、write 工具不能写」的裂缝。

**考虑过的选项**

| 选项                                                   | 否掉的理由                                                                                                                                                         |
| ------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 只改官方行的 config（`sandbox` / `sandbox-policy`）    | `mode` / `workspaceRoot` 表达不出「追加可写根」与「拒绝某个子路径」                                                                                                |
| 用官方 `sandbox-local.runnerCommand` 注入 profile 参数 | 它会断言 full enforcement 并跳过平台探测，拒绝签名退化为固定两条，而且官方只承诺「追加 bwrap 兼容的 profile 参数」——Seatbelt / Landlock / Windows 的表达能力都失去 |
| 改上游 `profiles.ts`                                   | 触碰「上游代码不可修改」红线；规则本身是用户配置而不是上游缺陷                                                                                                     |
| 在隔离域里注册第二个 provider（`ctx.isolate`）         | 同一 scope 重复注册同名服务本来就 fail loud；用隔离域换实现需要额外的 loader 语义与卸载时序，收益只是避免一次 `without`                                            |

**后果**

- 跨平台表达能力不对称，加载期告警而非静默失效：Seatbelt 表达全部三类条目；bwrap 把 `--` 退化成「只拒写」；Landlock 无法减除子路径；Windows ACL runner 的 argv 没有承载额外 grant 的入口。`ctx.fs` 侧在所有平台语义一致，降级只影响 bash 等子进程。
- `ctx.fs` 侧仍是**策略检查**，与它替换掉的官方围栏同一威胁模型（受信代码 + 模型可控路径）；内核级隔离仍归 `ctx.sandbox`。
- `--` 与 `r-` 在 `danger-full-access` 下仍然生效（用户规则不是模式推论）；`rw` 只在 `workspace-write` 下追加。
- 自定义 runner 与规则互斥：无法识别的 runner argv 会让规则在 `confine` 抛错——宁可失败也不让规则静默失效。
- 模型看到的两段运行时文本（`sandbox:policy` / `approval:policy`）由本包按 agent 作用域接管（见 [设计 20260929-可配置沙箱的规则面与平台降级](../designs/20260929-可配置沙箱的规则面与平台降级.md)）。
- 装配要求官方两个实现从清单里剔掉：`provideConfigurableSandbox(without(SandboxDefault), without(FsSandbox))`；判据在 `src/__tests__/assembly.spec.ts`——上游改名 / 移动这两行时它失败（提示同步），而不是让替换静默失效。
