# 规则面与平台降级（`access` 条目、两个入口、方言与策略文本）

状态：**已实现**——三类 `access` 条目替换官方两个服务后生效；Seatbelt 全表达，其余平台按方言降级并在装配期告警。
范围：`access` 规则语义与命中优先级、两个服务入口（`ctx.sandbox` / `ctx.fs`）、平台方言能力表与降级告警、两条运行时上下文（`sandbox:policy` / `approval:policy`）的接管。
非目标：规则从哪读、坏文件怎么退化（`{DSH_HOME}/sandbox.toml` 的口径见 [设计 20261106-配置来源与替换形态](./20261106-配置来源与替换形态.md)）；类名与装配形态（同上）；bash 与文件工具本身的实现（归 `packages/agent/dsh-sandbox` / `packages/agent/dsh-fs`）。
关联：可写根的上游真源 `vendor/deepseek-harness/packages/sandbox/sandbox/src/roots.ts`（`writableRoots` / `workspaceWritableRoots`）与同一个函数喂的围栏 `vendor/deepseek-harness/packages/fs/fs-sandbox/src/index.ts`；[ADR-替换官方进程沙箱与 fs 围栏以支持额外可写根与拒绝项](../adrs/20260917-替换官方进程沙箱与fs围栏以支持额外可写根与拒绝项.md)。

## 二、现状事实

- **规则解析与判定**：`src/rules.ts`——`ACCESS_LINE`（`rw` / `r-` / `--` 三种前缀）、`expandEnvTemplates`（`{{ env.NAME }}` 加载期展开，未设置或为空即抛）、`globToRegexSource`、`parseAccess` / `ruleSourceOf`、`compileRules`（相对路径相对会话工作区绝对化，`rw` 带通配符编译期抛）、`writableRootsWith`、`isDenied` / `isReadOnly` / `blocksWrite`。
- **glob 语法**：`*` / `?` 不跨 `/`，`**` 跨层级、`**/` 也匹配零层，`[!ab]` 取反；生成的正则同时用于进程内匹配与 SBPL 的 `(regex #"…")`，所以只用两者共有的语法。字面（无通配）的 `r-` / `--` 条目命中自身**及其全部后代**。
- **方言能力表**：`src/dialects.ts` 的 `DIALECT_CAPABILITIES`——Seatbelt 四类都表达；bwrap 表达 `rw`（`--bind-try`）与 `r-`（`--ro-bind-try`），`--` 退化为「只拒写」；Landlock 只有 `--rw`（allow-list 无法减除子路径）；Windows ACL runner 无表达。`extendConfinedArgv()` 对空规则原样返回、对认不出的 runner **抛错**（规则不能静默失效）。
- **两个入口的行为**（`src/sandbox.service.ts` / `src/fs.service.ts`）：

| 条目        | `ctx.fs`（read / write / edit）            | `ctx.sandbox`（bash 等子进程）                                                                      |
| ----------- | ------------------------------------------ | --------------------------------------------------------------------------------------------------- |
| `-- <path>` | 任何模式下读与写都拒（`resolve` 入口即拦） | Seatbelt：读 + 写；bwrap：只拒写；Landlock / Windows：无表达                                        |
| `r- <path>` | 任何模式下读放行、写拒绝（优先于可写根）   | Seatbelt：`(deny file-write* …)`；bwrap：只读挂载；Landlock / Windows：无表达                       |
| `rw <path>` | `workspace-write` 下计入可写根             | Seatbelt：`(allow file-write* (subpath …))`；bwrap：`--bind-try`；Landlock：`--rw`；Windows：无表达 |
| 无条目      | 与官方围栏一致                             | 与官方 argv 逐字一致（不做任何改写）                                                                |

- **fs 侧的顺序**：`#checkedTarget` 先过本包规则（`--` / `r-`），再过官方模式围栏——`danger-full-access` 原样返回、`read-only` 一律拒写、`workspace-write` 要求重新规范化后的目标落在 `writableRootsWith` 之下。
- **策略文本**：`src/policy-text.ts` 的 `renderPolicyContext`（三种 mode 的中文语义 + 三类条目的尾巴）、`renderApprovalContext`（`ask` / `never` 两段）；`src/runtime-contexts.service.ts` 的 `SandboxRuntimeContexts`——`agent/created` 时在 `agent.ctx.get("systemPrompt")` 上注册，并遍历 `ctx.get("agents").list()` 覆盖已存在的 agent；有效审批策略 = `approval.overrideOf(session)` 优先，否则 `approval.config.policy`，再退 `ask`；没有审批服务时那一段是空串。
- **告警**：`ConfigurableSandbox.onInit` 在非 darwin 平台对有 `r-` / `--` 或（win32 上）有 `rw` 的规则各打一条点名 warn。

**接口**（调用方要知道的）：

- 规则条目：`rw <path>` / `r- <path>` / `-- <pattern>`；数组与多行文本两种写法等价，空行忽略；缺前缀或前缀后没路径即抛。
- `compileRules(source, workspaceRoot)` 按工作区编译并缓存：换工作区就是另一份，规则源本身不再变。
- `extendConfinedArgv(argv, rules)`：空规则返回原 argv 的副本；有规则但认不出方言时抛错，调用方不能当成「没加规则」。
- `renderPolicyContext(policy, rules)` / `renderApprovalContext(policy)`：纯函数，供 agent 作用域的上下文回调调用。

## 四、行为与边界

1. **正常路径**：bash 执行 → `confine` 拿官方 argv → 按方言追加规则 → 子进程在规则下运行。
2. **读 / 写**：文件工具经 `ctx.fs`：`resolve` 拦 `--`；写面先过 `--` / `r-`，再过模式围栏。
3. **错误**：认不出的 runner 且规则非空 → 抛（宁可失败，也不让规则静默失效）；`rw` 带通配符 → 编译期抛；未设置的环境变量 → 加载期抛。
4. **降级**：非 darwin 平台上有 `r-` / `--` 时 warn；win32 上有 `rw` 时另有一条 warn；文本里仍然照实列出这些条目（模型看到的是规则，不是平台能力）。
5. **agentless 装配**：没有 agent 上下文时 `sandbox:policy` 的回调返回空串，上游全局那条照旧生效。
6. **取消与并发**：本包不持异步操作；规则编译按工作区缓存，同一 agent 的两次装配共用一份。

## 六、取舍

- **规则追加到官方 argv，而不是自建 runner**：官方 runner 探测 / 选择、Windows ACL 私有 temp、拒绝方言与失败规则全部保留；自建 runner 要跟住平台链的每一次变化。
- **三类条目共用一个 `access` 列表**：用户一次写完，语义由前缀决定；拆成三组字段会让「同一路径既声明只读又声明可写」无处表达优先级。
- **可写根与拒绝项分开表达（`rw` 只做追加）**：`workspace-write` 的可写根来自官方 `writableRoots`，本包只在其上追加；`read-only` 下不追加。
- **`ctx.fs` 侧是策略检查，不是内核边界**：与它替换掉的官方围栏同一威胁模型（受信代码 + 模型可控路径）；内核级隔离仍归 `ctx.sandbox`。
- **策略文本按 agent 作用域覆盖**：全局层同名注册会抛错，且 agentless 装配要保持官方那条，作用域遮蔽是上游给的官方路径。
- **注册提前到 agent 创建**：装配瀑布跑在 `contexts` merge 之后，在那里注册只能从第二次装配起生效（会话里表现为「先英文后中文」）；代价是注册时机与「agent 已知」绑在一起，所以本行晚挂载时用 `ctx.get("agents").list()` 补一遍。

## 七、不做与已知债

- **Windows 额外授权不实现**：官方 ACL 能力可以做预授权，但没有接进 `confine` 的现成路径，本版只告警。
- **`r-` / `--` 不隐藏目录项**：`ls` 仍能看到被保护文件的名字，被拦的是内容读取（仅 `--`）与写入。
- **策略文本是照上游语义重写的**：上游改了模式集合或措辞时，本包的用例不会自动发现。

## 八、开放问题

- **bwrap 参数顺序未实测**：`--bind-try` / `--ro-bind-try` 的「后挂载覆盖先挂载」与 `-try` 缺路径语义来自 bwrap 文档而非本仓库的测试证据（本机为 macOS）。
- **本行晚挂载时覆盖既有 agent 没有真装配用例**：`SandboxRuntimeContexts` 的「`agent/created` 时注册、第一次装配就是中文、无审批服务时空串」由 `runtime-contexts.spec.ts` 覆盖；`existingAgents`（行重挂 / HMR 时覆盖已存在 agent）仍只有代码路径。
- **策略文本要与上游措辞对照**：同步上游时要读一眼 `vendor/deepseek-harness/packages/sandbox/sandbox-policy/src/index.ts` 的 `renderPolicyContext`。
