# 子代理接管面：只改两处模型可见文本（`src/subagent/**`）

状态：**已实现**——两条瀑布各改一处文案，spec 在 `src/__tests__/subagent-guidance.spec.ts` 与 `src/__tests__/subagent-wording.spec.ts`。
范围：本包替上游 `@deepseek-ai/dsh-subagent` 那一行所做的两件事——中文**回报指引**与中文**委派范围说明**——以及为什么只改装配结果、不 fork 上游实现。
非目标：`ctx.subagents` 的注册表与工具行（本仓不拥有，见边界表）；子代理的调度、并发与生命周期；外部 backend（ACP / SDK）在别的进程里装配的子代理。
关联：上游三处真源 `vendor/deepseek-harness/packages/subagent/subagent/src/manager.ts`（回报指引的拼接点）、`vendor/deepseek-harness/packages/subagent/subagent/src/child-agent.ts`（`subagent:delegation` 的注册点）、`vendor/deepseek-harness/packages/subagent/subagent/src/continuation-messages.ts`（英文正文）；事件类在 `src/events.ts`；部署 preset 的语义见 [设计 20260928-preset平面与模式收口](./20260928-preset平面与模式收口.md)。

## 二、现状事实

- **三条文件**：`src/subagent/return-guidance.ts`（英文块的识别 `UPSTREAM_OPENING` / `UPSTREAM_PARENT`、`rewordReturnGuidance()`、`rewordGuidanceContent()`、`localizedGuidanceApplies()`、`localizedReturnGuidanceText()`）；`src/subagent/delegation-context.ts`（`DELEGATION_CONTEXT_NAME = "subagent:delegation"`、`DELEGATION_CONTEXT_TEXT`、`isDelegatedAgent()`、`rewordedContext()`）；`src/subagent/subagent-guidance.service.ts`（`SubagentGuidance`：两条 waterfall + `Config`）。
- **事件类**：`src/events.ts` 的 `AgentPreStep`（`@mode waterfall`，参数表带 `agent` / `messages` / `turn` / `step` / `signal`，返回 `enter` 或 `reject`）与 `SystemPromptAssemble`（返回 `PromptPresentation` 的 `sections` / `contexts` / `variables`）。
- **装配**：`src/subagent.provide.ts` 的 `provideSubagentGuidance`；headless 面（`src/session-mode.provide.ts`）也挂了同一行。
- **子代理判据**：`agent.session.header.parentSession !== undefined`；父会话自己的装配与消息表因此不会被改。
- **preset 的入参**：`SubagentGuidanceConfig.preset`，规范化时落 `DEFAULT_PRESET`（该常量定义在 `src/session-mode.service.ts`）。
- **上游正文位置**：`vendor/deepseek-harness/packages/subagent/subagent/src/manager.ts` 在把首条任务交给子代理时拼接英文指引；`.../child-agent.ts` 在子代理作用域注册 `subagent:delegation` 的运行时上下文。

## 三、模块边界与接口

| 模块                           | 拥有（职责与不变量）                               | 不拥有（明确排除）                                       | 依赖方向                                         | 接缝 / 适配器                                         |
| ------------------------------ | -------------------------------------------------- | -------------------------------------------------------- | ------------------------------------------------ | ----------------------------------------------------- |
| `SubagentGuidance`             | 两处文案的改写、语言开关、幂等（重复装配不重复改） | `ctx.subagents` 的注册表 / 工具行 / 调度；上游文案的来源 | 依赖上游事件名（`src/events.ts` 的类与上游同名） | `agent/pre-step` 与 `system-prompt/assemble` 两条瀑布 |
| `return-guidance`（纯函数）    | 认出上游英文块、生成中文正文、名单判定             | 消息从哪来、什么时候送达                                 | 无                                               | 纯函数，spec 直测                                     |
| `delegation-context`（纯函数） | 上下文名、中文正文、子代理判据                     | 上下文注册（上游在子代理作用域做）                       | 无                                               | 纯函数，spec 直测                                     |

**接口**（调用方要知道的）：

- `localizedGuidanceApplies(preset, configured)`：`configured` 留空 → 一律中文；非空 → 仅当 `preset` 在名单内。
- `rewordReturnGuidance(text)` / `rewordedContext(entry)`：不命中返回 `undefined` / 原条目，调用方据此决定「这条别动」。
- 不变量：改写只发生在 `parentSession` 存在的 agent 上；父会话的装配结果与消息表不受影响。
- 契约变更：无。

**深度**：删掉这一行，两处模型可见文本回到上游英文，且没有第二个地方能改它们（上游没有替换面）——它换来的是「一处判定 + 一处接线」而不是两千行 fork。

## 四、行为与边界

1. **正常路径**：子代理的首条任务进来时，`agent/pre-step` 的 `decision.messages` 里那条英文指引被换成中文，父 id 原样带过来。
2. **语言**：名单留空 → 中文；配了名单 → 只有名单包含部署 preset 才中文，否则保持上游英文（这是使用方的显式选择，不是故障）。
3. **委派说明**：子代理的装配里，`contexts` 中同名的 `subagent:delegation` 换成中文；其余上下文与父 agent 的装配原样。
4. **认不出就不动**：起始句不匹配、父 id 不是字符串、上下文名不同——原样返回，绝不猜父 id。
5. **幂等**：消息里没有那块英文时返回原数组；同一份装配重复跑不会二次改写。
6. **生命周期**：不持自有资源，跟随行卸载。

## 六、取舍

- **不 fork 整包薄壳**：那要复制 `manager.ts` 与 `index.ts`（前者 import 后者），两处文案换来两千多行的跟随负担，还会让同一份 `ctx.subagents` 出现两个提供者。
- **不本地 patch vendor**：patch 留给构建约束与上游缺陷（`AGENTS.md` 红线），常规接管走插件层。
- **不给上游提可配置化**：等版本，不可控。
- **不 fork `child-agent.ts` 改委派说明**：那条 context 注册在子代理自己的 agent 作用域上，同层重复注册同名直接抛（`NamedEntries.insert`）；外部 backend 的子代理在别的进程里装配，fork 对本进程之外无效。改装配结果一次覆盖两条派发路径。
- **不用自研 `send_message` 工具触发文案**：那是改模型可见的工具契约，为一句文案动契约不值得。
- **不靠「第一次装配」的时序取巧**：瀑布按消息内容认，英文块不在就原样返回，重复装配幂等；`delivery: 'caller'` 的一次性派发消息里没有那段英文，这里也就不会动它。
- **不搬源部署的 `rows.ts`**：本仓库不生成 `cordis.patch.yml`，装配就是代码里的清单；唯一有信息量的配置（名单）落在 `Config` 上。

## 七、不做与已知债

- 委派说明的中文只覆盖**本进程装配**的子代理；外部 backend（ACP / SDK）里装配的那条仍是上游英文——目前没有消费方要求覆盖。
- 两处文案的中文正文是照上游语义手写的；上游改了措辞或结构（起始句、上下文名）时本行不会自动跟随，**认不出就不动**是这一点的兜底。

## 八、开放问题

- `SubagentGuidance.Config.preset` 与 `SessionModeDefault.Config.preset` 是同一个事实的两个字段（两处各有缺省值）：装配时改了一个、漏了另一个，语言判定就会用旧 preset 判断名单。收敛成一处（只读 `SessionMode`）还是保持各自可装配，等有第二份 preset 的需求时再定。
