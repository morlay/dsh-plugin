## 一、决定

| #   | 议题             | 决定                                                                                                          | 一句话理由                                                                                      |
| --- | ---------------- | ------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------- |
| 1   | 流程的七段       | 选模式（chip）→ 看现状（面板）→ 逐项改 → 应用到会话 / 保存为默认 → 立即重装、下一 turn 生效 → 反馈 → 模式增删 | 这七段就是用户实际走的路；缺任何一段，前一段的结果就无处确认                                    |
| 2   | 第八段：生效名单 | 面板工具组**增加一个「只看本会话可调用」的过滤开关**（默认关）                                                | 「我能调什么」是靠三态自己推的，而规格 4 条用户故事都在问这件事                                 |
| 3   | 会话级覆盖存哪   | 接 `StorageDomain`，新域 `session_mode`，按 `SessionId` 一条记录                                              | 现在只有 `WeakMap<Agent, ModeConfig>`，重启即丢，与「应用到会话」这个措辞矛盾                   |
| 4   | hydrate 时机     | **首次 `activeState(sessionId)` 时懒加载**，不挂在会话恢复上                                                  | 不是每个会话都会打开面板，恢复到没人看的会话等于白读一次盘                                      |
| 5   | 改模式定义的入口 | **只走「另存为」**，不补行配置页 / `schemaFormHints` 那一层                                                   | 三个内置模式 + 用户另存的已够用；补一套通用表单是再造控件（YAGNI）                              |
| 6   | 面板的组         | 五个折叠组全画（`general` / `persona` / `tools` / `skills` / `policies`）；本仓缺的是 `persona` 段的渲染      | `SectionKey` / `Draft.persona` / `applyDraft` 的分支都在，只差把 `section("persona", …)` 调起来 |
| 7   | 反馈文案         | 面板与 chip 的状态文案一律走 `locales.ts`，不再硬编码                                                         | `saveFailed` / `saved` / `applied` / `loading` 四个 key 已存在却没人用                          |
| 8   | chip 的只读态    | 读 `sessionModeEditable` 投影，不再用 `useState(true)`                                                        | 现在刷新后已开 turn 的会话仍显示可点，点了才被服务端拒，错误只挂 tooltip                        |
| 9   | 面板跟随         | `useEffect` 依赖加上 `sessionMode` 与 `agentPreset` 投影；会话切换**只重拉正文，不 `openTab`**                | 别处切了模式、换了会话，面板显示旧态就是误导；但每次打开会话都激活侧边栏是打扰                  |
| 10  | noop 的边界      | `deletable` 判据加「不是保留 id」；`noop` 不可删、不可另存为覆盖                                              | 现在能从 UI 删掉 noop，删完要重启才恢复                                                         |
| 11  | 逐字段回退       | 每个被覆盖的字段给一个「恢复默认」按钮（`setModePatch(id, null)`）                                            | 「重置」只清本地草稿，用户无法把单个字段退回默认                                                |
| 12  | 另存为           | 补 code + name 的输入面（Modal），接 `saveAs` 端点                                                            | 现在按钮 disabled，用户在 UI 上无法新建模式                                                     |

## 二、现状事实

- **入口**：chip 在 `src/ui/session-mode-slots.ts` 的 `conversation.input.left`，面板在 `sidebar.right.pane.tab`（`PANEL_ID`），
  tab 类型另在 `src/ui/session-mode-panel-tab.ts` 注册；装配落点 `apps/zephyr-custom/src/client/client.provide.ts`。无命令、无 slash、无配置页。
- **面板**：`src/ui/session-mode-panel.view.tsx` 有 5 个 `SectionKey`，实际只渲染 4 组；`persona` 段的 `section(...)` 从未被调用。
- **两个写动作**：「应用到会话」→ `applyConfig` → `this.overrides.set(agent, …)`，`overrides` 是 `WeakMap<Agent, ModeConfig>`（纯内存）；
  「保存为默认」→ `saveConfig` → `writeMode()` + `overrides.delete(agent)`，落 `{dshHome}/modes/<id>.toml`。
- **持久化缺口**：全仓没有 `session_mode` 存储域；`session-mode` 包未接 `StorageDomain`。存储域的声明器是上游 `defineDomain` + `domainTable`，
  现成用法见 `packages/agent/dsh-storage/src/__tests__/storage.spec.ts`。
- **生效时序**：`select` / `applyConfig` / `saveConfig` / `deleteMode` → `installFor` → `scope.apply` → `tools.restrict`，服务端调用返回前已重装；
  模型面下一次 turn 才见。UI 无「下一 turn」提示。
- **反馈**：失败文案 `"保存失败: " + String(cause)` 硬编码；chip 的错误只挂 `SeatButton` 的 `title`。
- **面板跟随**：`useEffect` 依赖只有 `[sessionId, store]`，`useSessions` 传进来但未使用；无 `openTab` 联动。
- **测试面**：`src/ui/__tests__/` 两个文件共 8 条（面板 6、chip 2）；`src/__tests__/` 31 个文件覆盖数据面与装配；
  真装配入口是 `src/__tests__/support/mount-app.ts`（`bootstrapApplication` + 真 cordis 根 ctx）；wire 面没有 handler 级用例。

## 三、模块边界与接口

| 模块                           | 拥有（职责与不变量）                                                               | 不拥有（明确排除）                  | 依赖方向                                                                           | 接缝 / 适配器                                         |
| ------------------------------ | ---------------------------------------------------------------------------------- | ----------------------------------- | ---------------------------------------------------------------------------------- | ----------------------------------------------------- |
| `SessionModePanel`（浏览器半） | 五个折叠组的渲染、草稿与提交、来源标注、过滤开关、逐字段回退、另存为与删除的 Modal | 模式数据的合成；工具面的收口        | ← `SessionMode` 契约                                                               | `SessionModeStore`（读面 + 写动作，测试替身在这一层） |
| `SessionModeSeat`（chip）      | 模式选择、只读态、失败提示                                                         | 面板的字段编辑                      | ← `SessionMode` 契约 + `sessionModeEditable` 投影                                  | 同上                                                  |
| `SessionModeDefault`（宿主半） | 模式清单、按会话的选择与覆盖、`installFor` 编排、hydrate                           | 面板与 chip 的呈现                  | ← `SessionStore` / `SessionProjectionStore` / `SessionScope` / **`StorageDomain`** | `SessionMode` 契约                                    |
| `session-mode-store`（新）     | `session_mode` 域的声明、按 `SessionId` 的读写、坏记录不阻断启动                   | 模式定义本体（那在 `modes/*.toml`） | ← `StorageDomain`                                                                  | 存储域即接缝；测试用临时 `DSH_HOME` + 真 json 后端    |

**接口**（调用方要知道的一切）：

- `activeState(sessionId)` 是面板的唯一读面：返回 `config`（当下生效）、`session`（覆盖了哪些字段）、`catalog`（全量目录）、`overriddenFields`。
  **首次调用会触发一次 hydrate**（从 `session_mode` 域读回这个会话的覆盖）；之后的调用读内存。
- `applyConfig(sessionId, config)` 写覆盖 + 落存储 + 重装，返回新的 `activeState`；失败抛错，**不写半份**。
- `saveConfig(sessionId, config)` 写 `modes/<id>.toml` + 删该会话的覆盖 + 删存储里的那条记录。
- `setModePatch(sessionId, patch)` 里 `null` = 清掉这个字段的会话覆盖，回落到模式默认。
- `deletable` 的判据：不是部署默认模式、不是保留 id（`noop`）、清单里多于一个。

## 四、行为与边界

1. **选模式**：chip 只对空白会话可点（`sessionModeEditable` 投影）；已开 turn 的会话 chip 只读并给出原因。
2. **看现状**：面板打开即 `activeState(sessionId)`；首次会 hydrate。每个字段标「会话覆盖 / 模式默认」。
3. **改与提交**：「应用到会话」一次提交整份草稿；逐字段「恢复默认」走 `setModePatch(id, null)`。两者都立即重装。
4. **保存为默认**：写 `modes/<id>.toml`，删掉该会话的覆盖（已经等于默认了），notice「已保存，对新会话生效」。
5. **持久化**：覆盖写进 `session_mode` 域；`applyConfig` 成功才写，写失败则整次调用失败。
6. **模式增删**：「另存为」收 code + name（形状校验 + 重名拒绝）；删除二次确认，`noop` 与默认模式不可删。
7. **反馈**：所有状态文案走 locales；chip 失败给一条可见的错误条（不只 tooltip）。
8. **跟随**：会话切换 → 面板正文重拉；`sessionMode` / `agentPreset` 投影变化 → 面板重拉。
   **不自动打开**：右栏选中哪一页由用户决定，会话切换不调 `openTab`；入口是标签条的 guide 一条（`SessionModePanelTab`）。
9. **错误**：`activeState` 读失败给整块错误态；写失败给 notice 且不清草稿（用户可以重试）；hydrate 读到坏记录按「没有覆盖」处理并 warn 一条。

## 六、取舍

- **不补行配置页 / `schemaFormHints`**：三个内置模式 + 用户另存的足够；补一套通用表单是再造控件。代价是「改模式定义」必须另存为新模式再改。
- **持久化走存储域而不是会话事件流**：会话事件流是 append-only 的对话记录，配置混进去会污染它的语义。
- **hydrate 懒加载**：不挂在会话恢复上，因为不是每个会话都会打开面板；代价是第一次打开面板多一次读盘。
- **noop 用保留 id 而非标记位**：`mode-store` 已经在拒绝覆盖 `noop`，UI 沿用同一个判据即可，不加新字段。
- **「只看可调用」是过滤而非新视图**：复用已有的 `catalog` + 三态，不加第二个列表。
- **会话切换不自动打开右栏面板**：早先的跟随会 `openTab(PANEL_ID)`，等于每次打开会话都把侧边栏顶到模式面板上，打扰用户；
  现在只重拉正文，入口留在标签条的 guide 一条。代价是面板不如以前显眼，用户要多点一下。

## 七、不做与已知债

- 不做真实浏览器 E2E（判据用 vitest + RTL + 真存储后端已能覆盖）。
- 已知债：wire 面（`sessionMode/*` 十个方法）仍没有 handler 级用例，现在只有面板 store 替身与类型契约在守；
  销账条件是补一组「装到 wire 上逐个 invoke」的用例。
- 已知债：`buildCatalog` 没有参考实现的 `fsActive` 适用性降级（policy 组全列，不按「这个会话有没有文件工具」收窄）。

## 八、开放问题

- 「只看可调用」这个开关的默认值：现在定的是关（保持与现有面板一致），若用户反馈噪声大再改默认开。
- `saveAsDefault`（把当前会话覆盖写回模式）端点已存在但 UI 零调用：要不要在 chevron 菜单里加一条，等这一轮面板改完再定。
