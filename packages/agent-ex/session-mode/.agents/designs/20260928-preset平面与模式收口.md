# preset 平面与模式收口（session-mode 的宿主半）

状态：**已实现**——`provideSessionMode()` 装出模式本体、收口、工具说明与提示词通道，`provideSessionModeEndpoints()` 装 `sessionMode/*` 端点。
范围：本包宿主半的三件事——**preset 只有一个**（`Config.preset`）、**模式是一份数据**（`ModeConfig` 与它的三个来源）、**按会话收口**（工具 / 技能 / policy 三对名单、`dropSections`、三个注入开关、默认模型）。
非目标：preset 的行清单（归上游 preset）；浏览器半的面板与 composer chip（`./ui` 自有实现）；工具说明分组的正文与它的送达（组表在 `src/guidance/packs/**`，送达由 `ToolGuidance` 负责，本文只写它与收口的交界）；提示词通道的文本转换细节（`src/context-assembler.service.ts`）。
关联：上游 preset 真源 `vendor/deepseek-harness/packages/preset/agent-preset/src/index.ts` 与 `vendor/deepseek-harness/packages/preset/agent-preset-registry/src/index.ts`；[ADR-preset 写死在 config](../adrs/20261109-preset写死在config不恢复roster.md)；词义见[会话数据面术语表](../../../../agent/dsh-session/.agents/GLOSSARY.md)（会话 / 轮次 / 闭合边界 / live 与 cold）。

## 一、决定

| #   | 议题             | 决定                                                                                                                   | 一句话理由                                                                                                  |
| --- | ---------------- | ---------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------- |
| 1   | preset 从哪来    | 行 config 的 `preset`，缺省 `DEFAULT_PRESET = "ptc"`；本行只装那一份行清单，不向官方 roster 询问                       | 本部署只有一份行清单，「换预设」这个能力不存在（[ADR](../adrs/20261109-preset写死在config不恢复roster.md)） |
| 2   | 模式是什么       | preset 之上的**会话级收口**：persona、工具 / 技能 / policy 三对名单、`dropSections`、三个注入开关、可选 `defaultModel` | preset 回答「这个 agent 有哪些行」，模式回答「这个会话怎么用它们」                                          |

| 5   | 什么时候能换模式 | 只在本会话还没落过 `turn/start`（`sessionModeEditable` 投影）                                                          | 历史是在旧模式的工具面与提示词下产生的，换了就解释不通                                                      |
| 6   | 子代理怎么定模式 | 继承父会话当前模式，并把继承写进自己的会话日志                                                                         | fork / 冷恢复靠日志重建，不靠进程内状态                                                                     |
| 7   | 默认模型         | 只在会话没有任何模型事实（无请求头、无 pending 选择）时兜底这次请求                                                    | 模式是配置事实，不该覆盖用户选过的模型                                                                      |

## 二、现状事实

- **形状的唯一模型**：`src/endpoint/mode-config.ts` 的 `ModeConfig`——`presetsOnly` / `name` / `description` / `role` / `persona` / `allowTools` / `denyTools` / `allowSkills` / `denySkills` / `allowPolicies` / `denyPolicies` / `instructions` / `skills` / `dropSections` / `runtimeContext` / `defaultModel?`，全部必填（`defaultModel` 除外）；`derivedSkills()` 在 `skills` 缺省时按工具名单推导。
- **归一化与校验**：`src/modes.ts` 的 `normalizeMode()` / `configProblem()` / `policyInForce()`；装配期 fail loud，错误文案点名模式与字段。
- **内置模式**：`src/mode-sources.ts` 的 `MODE_SOURCES`（`coding` 用全部工具、排除两件载荷工具与三件 Office 技能、禁两条写意图 policy；`chat` 只留提问 + 联网三件、关 `instructions` 与 `runtimeContext`；`noop` 全空）与 `DEFAULT_MODE = "coding"`；三条都**不写** `presetsOnly`。
- **服务本体**：`src/session-mode.service.ts` 的 `SessionModeDefault`（`@Injectable({ name: "sessionModes" })`），`Config = configWithDefaults`（`preset` 缺省 `"ptc"`；`modes` 缺省时展开 `MODE_SOURCES`）。
- **收口**：`src/session-scope.service.ts` 的 `SessionScopeDefault`；persona 经 `src/persona.ts` 的 `installPersona()` 注册 `deployment:persona-prefix` / `-suffix` 两个 section（遮蔽部署级那层）。
- **通道**：`src/context-assembler.provide.ts` 的 `ContextChannel` + `src/context-assembler.service.ts` 的 `ContextAssemblerDefault`；三份可覆盖清单在 `src/defaults.ts`。
- **会话事实**：`src/session-mode.projection.ts` 的三个投影——`sessionMode`（`session-mode/selected` 的 fold）、`sessionModeEditable`（`turn/start` 之后恒 `false`）、`agentPreset`（读 header 的 `agentPreset`，缺省 `config.preset`）。
- **持久化**：`src/mode-store.ts` 读写 `{dshHome}/modes/<id>.toml`；`noop` 是保留 id，写盘不能覆盖它。
- **装配**：`src/session-mode.provide.ts` 两个函数——headless 面（通道 → 收口 → 工具说明 → 子代理文案 → 模式本体）与 wire 面（端点行）。
- **不依赖上游 preset 包**：`@deepseek-ai/dsh-agent-preset-registry` 不在本包 `dependencies` / `devDependencies` 里；`AgentPresets` 只在 `packages/agent/dsh-agent/src/contract/composition-vocabulary.contract.ts` 再导出，目前没有消费方。

**接口**（调用方正确使用它要知道的一切）：

- `select()` 只接受 `role` 含 `main` 的模式，且只对空白会话成功；其余抛可读错误。同一个值重复选不写第二条事实。
- `setModePatch()` 的 `null` 表示「清掉这个字段的会话覆盖」，回落到模式默认；`activeState()` 的 `config` 是当下生效的那一份，`session` 只记覆盖了哪些字段。
- `definition()` 对未知 id 抛错（消息列出可用 id），调用方不需要自己判空。
- 收口的幂等语义：同一 agent 再 `apply` 就是换一份，旧的那份由该 agent 的 account 收回——调用方不必先卸。

## 四、行为与边界

1. **正常路径**：`agent/created` → `installFor(agent)` 先卸上一份 account，再装 persona、默认模型兜底与收口；会话的第一次装配已经在用本模式的 persona（注册早于 preset 行的装配）。
2. **切换**：`select()` 写一条 `session-mode/selected` 并按新模式重装；**不换 preset**——本部署只有 `config.preset` 那一份行清单。
3. **幂等**：同一模式反复 `applyTo` 只重装一次；`account.release()` 同步且幂等，行卸载与 agent 卸载任一处先到都收干净。
4. **错误**：装配期 `configProblem()` 拒绝装载的情形——`modes` 为空、`default` 不在清单、某模式 `role` 为空、`default` 不含 `main`、policy 名字未知、模式里还配着退役的 `preset`、顶层还配着退役的 `models`、`defaultModel` 缺 `provider` 或 `model`。
5. **生命周期**：换模式 / 行重挂必须先收回上一份 `tools.restrict`——否则第二次 `apply` 从已收窄的 `definitions(agent)` 起算，白名单里的名字会凭空消失。
6. **覆盖与写盘**：`setModePatch` 只动会话覆盖；`saveConfig` / `saveAsDefault` / `saveAsNewMode` 写盘（写完整定义，不写差异）、`saveAsNewMode` 校验 id 形状与重名、`deleteMode` 拒绝删部署默认模式且删完会话回落到默认。
7. **policy 拦截**：三条 policy 名字的 waterfall 一律 `{ prepend: true }`；模式禁用某条时仍调 `next()`，再把结论（连上游抛出的拒绝）一起丢掉。
8. **取消与并发**：本行不持异步操作——没有可取消的任务，也没有需要串行化的写。

## 六、取舍

- **不恢复 preset roster**：本部署没有第二份行清单，roster 只能靠假 registry 演；代价是「换预设」这个动作不存在（理由与边界见 [ADR](../adrs/20261109-preset写死在config不恢复roster.md)）。
- **模式不持有行清单**：只声明名单与开关，工具从会话挂着的 preset 来；因此缺件的 preset 上模式要的工具会自动跳过（不报错）。
- **收口走 `tools.restrict` 而不是改 preset 行**：行清单归线上游；收口是会话事实，必须能随会话切换。
- **三对名单而不是一份 deny 列表**：工具、技能、policy 各有各的目录来源与拒绝理由，合成一份会让错误文案说不清是哪一类。
- **通道只做文本转换**：官方 `agent-instructions` / `skill-catalog` / `time-context` 在通道之外 append，通道不替它们送达，只在 `agent/pre-step` 最外层按会话丢掉不要的条目。
- **策略拦截放在 `prepend`**：这三条 waterfall 的决策槽被上游 `fs-observation-policy` 占着，不抢最外层就轮不到我们。
- **默认模型不写会话事件**：它是配置事实，写进日志就会盖住用户的选择。

## 七、不做与已知债

- `src/system-remainder.ts` 不接生产通道：保留它是与源部署核对 remainder 信封的锚，两套幂等语义（按 id / 按正文）**不许合并**（见文件头）。
- 子代理的中文文案只覆盖本进程装配的子代理；外部 backend 在别的进程装配的那条仍走上游英文（见 [设计 20261106-subagent接管面只搬两处文案](./20261106-subagent接管面只搬两处文案.md)）。
- 模式的浏览器半（面板 / chip）不在本文范围，行为判据在 `src/ui/__tests__/**`。

## 八、开放问题

- `sessionMode/*` 的宿主实现（`src/server/session-mode-endpoint.service.ts`）没有 handler 级 spec：面板 spec 注入的是 store 替身，端点只经类型契约被引用。要补的是「装到 wire 上之后逐个方法 invoke」的那类用例。
- 缺件的 preset（官方 `minimal` 那类）上模式要的工具会被自动跳过；要不要在面板上提示「这个预设缺这些工具」，等有实际反馈再定。
- `presetsOnly` 现在三条内置模式都不写：反查路径只在用户自建模式声明它时才成立，是否需要给面板一个可见的说明。
