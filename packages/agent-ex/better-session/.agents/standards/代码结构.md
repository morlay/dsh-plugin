# 代码结构规范

状态：已定——按面四块 + 文件粒度 + 依赖方向；判据是「读代码时不需要先知道历史」。
范围：`packages/agent-ex/better-session/src/**` 的目录、文件粒度、命名与依赖方向。
非目标：包出口形状（`.` / `./endpoint` / `./server` / `./ui` 不变）；上游 `dsh-*` 契约与 `zephyr-rdb` 内部结构。
关联：[完整设计](../designs/20261120-完整设计.md)、[读路径口径](./rdb-读路径.md)、[如何验证](./how-to-verify.md)。

## 一、决定

| #   | 议题     | 决定                                                                                                                                                                                                | 一句话理由                                 |
| --- | -------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------ |
| 1   | 目录维度 | 按**面**分：`data/`（落盘·事件·分支·日志）、`admin/`（查询·统计·一致性·导入导出·运维）、`editor/`（编辑计划与编排）、`storage/`（接管·投影检查点）；`contract/ endpoint/ server/ ui/` 保持          | 结构跟设计的三块走，读代码先判「哪一面」   |
| 2   | 文件粒度 | 每文件 ≤ 300 行；一个文件一件事（一句话说得出，且不含「和」）                                                                                                                                       | 超过 300 行基本等于混了两件事              |
| 3   | 命名     | 数据面用名词（`handles` / `write-path` / `live-routing`）；管理面用对象或动作（`import-export` / `maintenance` / `consistency` / `observe-cache`）；纯函数不带后缀；`*.service.ts` 只用于装配注入点 | 后缀是分类，不是装饰                       |
| 4   | 依赖方向 | `contract` ← `data` ← `admin` ← `endpoint` / `server`；`ui` 只依赖 `endpoint` + `contract`；`storage` 依赖 `data`，`data` 不反向依赖                                                                | 反向 import 即错                           |
| 5   | 测试     | spec 按接缝命名并**按面放**在 `<面>/__tests__/`；根 `src/__tests__/` 只放跨面集成与共享 `support/`；单文件 ≤ 500 行                                                                                 | 测试文件按接缝组织，不按历史事件           |
| 6   | 移动纪律 | 一次只做「移动」或「改名」或「拆文件」之一；每次跑整包门禁                                                                                                                                          | 三件事混在一起时，红了你不知道是哪件引起的 |

## 二、现状事实

- `src/` 根只有 `index.ts` / `cordis.ts`；面分 `data/`（`store/`、`entities/`）、`admin/`（`import-export/`、`stats/`）、`editor/`、`storage/`，加既有的 `contract/ endpoint/ server/ ui/`。没有平铺的 `rdb/`。
- 写队列与库身份都由 rdbkit 提供：`data/store/open.ts` 直接复用 `database.transaction`（rdbkit 按库身份共享写队列），身份走 `identityFingerprint` + `claimLibrary`，本包没有第二份实现。
- spec 按面放在 `<面>/__tests__/`（决定 5）：根 `src/__tests__/` 只剩跨面集成与 `support/`，宿主半的面各有自己的 `__tests__/`，浏览器半在 `src/ui/**/__tests__/`。
- 非 spec 18 个文件超 300 行、spec 6 个文件超 500 行（清单与行数见判据 2 的存量）；这就是「继续拆」与「spec 拆包」两条债的存量。
