# 如何验证

通用规则（证据矩阵、失败处理、发布纪律）见根[如何验证](../../../../../.agents/standards/how-to-verify.md)；
这里只写本包的接缝、落点与环境门控。

命令入口：`pnpm exec vitest run packages/agent-ex/better-session`（整包全绿；计数以命令输出为准，记录里不抄）、
`pnpm exec oxlint packages/agent-ex/better-session`。测试都走**包名**
（`@morlay/better-session` / `@morlay/better-session/endpoint` / `@morlay/better-session/server`），
等于顺手守住 `exports`。

## 装配辅助

`src/__tests__/support/**` 的分层与判据见 [测试支撑的分层](./testkit.md)——**本文不复述**。要点：
宿主半的 spec 从 `support/host.ts` 的 `startHarness()` / `startHarnessWithAgent()` 起装配，
浏览器半的全链路 spec 从 `support/e2e-host.ts` + `e2e-client.ts` + `e2e-render.tsx` 起装配，
对话管理页的 L3 spec 从 `support/manager-flow.ts` 起装配（真宿主 + 真端点客户端 + 真 controller）；
`e2e-host.ts` 的 `workspaces` 是宿主侧替身 `FakeWorkspaceRegistry`（工作区记录归 workspace 域，跨工作区复制只调它的 `attach`），
造导入包走 `support/zip.ts` 的 `zipOf(entries)`（用例只拼目录形状，压缩算法本身不是判据），
`manager-flow.ts` 另给工作区列表的客户端快照替身与 `targetWorkspace`（真目录 + 工作区域里的一行），复制用例从它取目标。

## 未覆盖（有明确原因）

- **PostgreSQL 方言（其余部分）**：日常回归只跑 SQLite；`search-filter.pg.spec.ts` 用 `TEST_PG_URL` 门控 + `createPostgresTestDatabase` 覆盖本包的三个方言依赖点（前缀段不命中索引 + `Index Cond` 对照、两段式搜索与结构化过滤的结果、`bulkDelete` 逐条结算），容器不在时整组 skip。其余方言差异——连接与库身份、聚合的 int8、JSON 提取、本地日、事务串行、自定义 schema——由 `packages/zephyr/zephyr-rdb` 自己的用例覆盖。
- **真实模型用量的数值**：`endpoint.spec.ts` 覆盖 `usage` 的形状、子代理拆分与范围语义，但测试日志里没有模型 usage 行——活动计数按「会话有用量行」的口径过滤，所以那些断言是全零。真实数值要在有模型事件的数据上才能验。
- **旧世代格式的迁移链**：`legacy-shape.spec.ts` 覆盖旧代消息形状的读取与 ignorable 跳过，但没有「跨世代逐版迁移」的用例——本包没有可造的旧世代数据。
- **内核级隔离**：本包不碰沙箱；Seatbelt / bwrap 的真机行为归 `packages/agent-ex/configurable-sandbox` 的规范。

## 测试分层

四层，业务票必须同时有 L2 与 L3：

| 层  | 形态                                                                                           | 设施                                                                                                                               | 不覆盖                            |
| --- | ---------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------- | --------------------------------- |
| L1  | 纯函数与 SQL 渲染断言                                                                          | 直接调函数、`render()`                                                                                                             | 真实数据与装配                    |
| L2  | **headless 服务端自闭环**（真装配 + 真库 + 真接口：`handlers.invoke` 或契约面入口，不渲染 UI） | `__tests__/support/host.ts` 的 `startHarness` / `startAt`                                                                          | 浏览器与页面状态                  |
| L3  | **UI + server 真实 flow（mock LLM）**：真装配 + 真库 + 真 remote + 渲染真页面，只 mock 模型    | `startHarnessWithAgent`（`loopTestProviders` + FakeAdapter）、`support/e2e-{host,client,render}`、`support/manager-flow`（管理页） | 模型行为本身                      |
| L4  | 真 PostgreSQL（`TEST_PG_URL` 门控）                                                            | `tool/pg` compose、`createPostgresTestDatabase`（`@morlay/zephyr-rdb/testing`）                                                    | 日常回归（容器不可用时整组 skip） |

纪律：L3 不 mock 服务端与数据层（只 mock LLM）；L2 不渲染 UI；L1 不碰装配。
