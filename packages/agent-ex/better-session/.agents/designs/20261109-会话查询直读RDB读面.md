# 会话查询直读 RDB 读面（`sessionQuery` 那一行）

状态：**已实现**——判据见 `src/__tests__/query.spec.ts` 与 `src/__tests__/session-query.spec.ts`；整包 38 文件 / 377 通过。
范围：`sessionQuery` 的读面（列表 / 筛选 / 事件 / 表面 / 轨迹 / 标题 / 观测）落在哪个读路径上，以及 `observeSession` 的缓存与筛选下推的形状；并说明分支面「撤回后检查点写回」为什么读内存 log。
非目标：写路径与落盘（[设计 20261106-RDB复用边界与Remote端点形状](./20261106-RDB复用边界与Remote端点形状.md)）；条件与列引用的写法规则（[如何写读路径](../standards/rdb-读路径.md)）；`sessionQuery` 的 wire 面（本包不提供）。
关联：上游 `SessionQueryEngine` 的真源 `vendor/deepseek-harness/packages/session-query/session-query/src/observation.ts`；契约 `packages/agent/dsh-session/src/contract/session-query.contract.ts`；词义见[会话数据面术语表](../../../../agent/dsh-session/.agents/GLOSSARY.md)（live / cold / 轮次）。

## 一、决定

| #   | 议题                              | 决定                                                                    | 一句话理由                                                                                          |
| --- | --------------------------------- | ----------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------- |
| 1   | 是否继承上游 `SessionQueryEngine` | **不继承**，只复用它的纯函数                                            | 它自带第二份语料视图（`SessionCorpus` + 持有完整 `Session` 的观察缓存），同库同事件读两遍、缓存两份 |
| 2   | live 会话怎么读                   | 先 `sessions.flush(live)`，再从**库**读                                 | 一个事实只有一个 home（库）；读内存是第二条读路径                                                   |
| 3   | `observeSession` 缓存             | 自建有界缓存，键是 `(persistenceIdentity, revision)`，租约 pin 住不淘汰 | 要的是「同一 revision 不重读」，不是那套「完整 `Session` 对象」的缓存层                             |
| 4   | 筛选条件放哪                      | 下推进 SQL（`src/rdb/query-filters.ts`）                                | 一万条事件按 seq 筛只物化命中那几行                                                                 |
| 5   | 事件列表的 surface                | 无 replace 时按四列坐标判两态；有 replace 才读全量折叠                  | `foldSurface` 要求从 seq 0 连续，命中行单独折不了                                                   |
| 6   | 搜索                              | 显式失败（`SESSION_QUERY_SEARCH_DISABLED`）                             | 本装配没有全文索引；「搜到空」会让模型以为会话里没有这个词                                          |
| 7   | 撤回后的检查点写回                | 以 live 会话的**内存 log** 为源                                         | 那是派生状态重算：落库失败也要写回，否则页面停在撤回前                                              |

## 二、现状事实

- **服务本体**：`src/session-query.service.ts` 的 `SessionQueryRdb extends SessionQuery`（契约是抽象类，少一个成员编译期就报）。
- **库读面**：`asRdbStore(persistence)` 的 `load` / `readRawEvents` / `readModel` / `selectSessionRows` / `selectEventRows` / `headerOf`；条件翻译在 `src/rdb/query-filters.ts`（`sessionFilterCondition` / `eventFilterCondition`），列引用来自 `src/rdb/storage-takeover/read-model.ts` 的 `columns`。
- **`session/flush` 是上游公开的落库同步点**：本包的监听器在 `src/rdb/live-routing.ts`，它 `drainLive()` 后再 `flush()`；所以 `await sessions.flush(live)` 返回时，库里的日志等于内存里的日志。
- **复用的纯函数**（`@morlay/dsh-session/contract`）：`buildSessionEventRecords` / `buildSessionEventSearchDocuments` / `filterSessionEventDocuments` / `materializeSessionResultFilters` / `materializeSessionEventResultFilters` / `extractSessionEventText` / `currentSurfaceEvents` / `traceSession` / `traceEvent` / `snapshotSessionEvent` / `interruptedTurnClosers` / `SessionQueryError`；标题折叠来自 `@morlay/dsh-conversation` 的 `foldSessionTitle`。
- **归档集合**：优先读 `workspaceRegistry`（与页面归档动作同源），registry 不在时退回 `asRdbStore(persistence).archivedSessionIds()`（持久化里的标记）。
- **缓存容量**：`preparedSessionCacheSize` 由落盘行的配置透传，缺省 1（每次命中把条目移到队尾，LRU；`refs > 0` 的条目不淘汰）。
- **观测切面**：`observeSession` 返回 `source`（`live` / `prepared`）、`cursor`（最后一条事件的 seq）、`revision`、可选 `projections`、以及 `retain()` / `Symbol.dispose`。
- **读窗口**：`readEvent` 的 `before` / `after` 必须是 `0..SESSION_QUERY_READ_WINDOW_MAX` 的整数，越界显式报错。

**接口**（调用方要知道的）：

- `observeSession` 的切面在租约期间不变；`retain()` 之后要自己 `Symbol.dispose`，否则该条目永不淘汰。
- `filterSessions` 的 `availability` 不是列：要 `live` 才遍历内存表、要 `persisted` 才查库，两者都要取并集。
- `listEvents` 只给四列坐标（seq / type / time / surfaceOp），不物化事件体；要事件体请走 `readEvent` / `load`。
- 搜索两个方法一律 reject（同一错误码），调用方不需要再判空。

## 四、行为与边界

1. **正常路径**：`listSessions` 先取持久化行、再用 live 覆盖，按创建时间倒序 + id 升序，最后按归档集合过滤。
2. **live 读**：`readSession` / `readSurface` / `listEvents` / `filterEvents` / `observeSession` 都先 `flushLive()` 再读库；冷读补上中断轮次的闭合事件（与上游 cold read 同一口径）。
3. **筛选**：条件进 WHERE，命中行才物化；surface 分类来自全量坐标（只有四列），文本抽取只对命中行做；有 replace 的会话退回全量日志折叠。
4. **错误**：会话不存在 → `SESSION_QUERY_SESSION_NOT_FOUND`；事件位置不存在 → `SESSION_QUERY_EVENT_NOT_FOUND`；窗口越界 → `SESSION_QUERY_INVALID_WINDOW`；搜索 → `SESSION_QUERY_SEARCH_DISABLED`。
5. **取消**：接受 `AbortSignal` 的成员在读前与读后各查一次；`readTitleSnapshots` 逐个结算，一个会话失败不连坐其它会话。
6. **生命周期**：观测条目按容量淘汰，`refs` 归零时触发一次淘汰；`dispose` 之后 `retain()` 抛错。
7. **派生重算不同于查询读**：撤回后的检查点写回读 live 会话的内存 log（`liveEventsOf`），因为撤回已经把内存与库截到同一水位，检查点要基于刚改过的那个对象；查询读只认库。

## 六、取舍

- **保留 live 内存读 + 一处 lint 豁免** → 否：一个事实两个 home，豁免只是把分叉写进注释；代价是 live 读多一次 flush 往返。
- **命中行直接 `buildSessionEventSearchDocuments`** → 否：`foldSurface` 要求从 seq 0 连续，部分行直接报错。
- **把 `SessionObservationReader` 装回来做观测缓存** → 否：要的只是「同 revision 不重读」，它额外维护一份完整 `Session` 缓存。
- **继承引擎但绕开 `SessionCorpus`** → 否：引擎在构造与读路径里就会建语料视图，绕不开。
- **撤回后按库写检查点** → 否：`session/flush` 允许失败且不该阻断检查点，按库写会把「落库失败」升级成「检查点不更新」。

## 七、不做与已知债

- 搜索不做：没有全文索引，两个方法固定 reject；要搜索是另一个能力（索引与它的生命周期）。
- `observeSession` 的 `projections` 依赖 `SessionProjectionStore`：装配里没有注册表时观测仍给日志与游标，只是没有投影。
- 归档过滤仍在内存：归档集合是 workspace 域的 global，不是会话行的列。

## 八、开放问题

- `headerOf()` 只由 `SessionRdbStore` 契约承诺、包内没有调用方；首个「只读会话行」的消费方出现时它才是接线点。
- `readTitleSnapshots` 对每个会话各读一次日志：会话多时是线性读放大，要不要按批合并成一条查询。
