# 不做版本树投影，也不写版本效果事件

状态：已采纳——本包不产出 `session-branch/version`，也没有 timeline 读面。

背景：就地编辑 / 重试 / 撤回只需要「截断到闭合边界再重写」（根术语表的「就地编辑」与「撤回」），派生新会话只需要 fork。版本树投影（timeline）服务的是「编辑了什么、从什么改成什么」与撤销 / 重做链；它的读侧在浏览器半没有消费方（`./ui` 只有消息动作与管理页，没有版本导航），而版本效果事件是每次就地编辑多写的一条记录，写它依赖读侧「一个会话只有一个版本效果」的不变量——该不变量与 fork 冲突：fork 子会话上再做一次就地编辑就会恒冲突。

**决定**

本包不提供版本树投影、也不写版本效果事件：`SessionBranch` 没有 timeline 成员，`sessionEditor` 组没有 timeline 方法（`GET` 一类读面不存在），`./ui` 没有版本导航。`src/endpoint/branch.ts` 只保留该事件的**形状版本常量**（`SESSION_BRANCH_VERSION_SCHEMA`）用于识别既有日志，`src/rdb/log/repair.ts` 把它列为「已知但本包不产出」的事件类型，读侧原样跳过。

**考虑过的选项**

| 选项                        | 否掉的理由                                                             |
| --------------------------- | ---------------------------------------------------------------------- |
| 只删读侧、保留写侧落库      | 留一条只写不读的事件——每次编辑多一条永久记录，价值为零                 |
| 接上版本导航 UI             | 能力本身没问题，但当前没有需求，且它的读侧不变量与写路径矛盾（要先修） |
| 保留一个 GET 读面作将来入口 | 那个读面只服务 timeline，留着就是死路由                                |

**后果**

- 会话不记录操作历史：旧会话里已落库的该事件原样保留（写路径零转换），新操作不写。
- `sessionEditor` 组只有六个动作方法，没有读面；编辑后的界面重建靠会话窗口，不靠 timeline。
- 将来要做版本导航，要先重建读侧并把「同一会话多个版本效果」当正常形态——那是另一条决策。
