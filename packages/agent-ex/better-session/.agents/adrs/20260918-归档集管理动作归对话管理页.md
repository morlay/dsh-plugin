# 归档集的管理动作只落在对话管理页

状态：已采纳——归档集的删除与导入成新会话只有这一处入口。

背景：归档是 workspace 域上的会话集合（`archivedSessionIds`）：上游按它过滤会话列表、在别处显示「已归档」状态（`vendor/deepseek-harness/packages/api/session-controller/src/archived-session-gate.ts`、`vendor/deepseek-harness/packages/client/ui-schedule/src/client/session-link.ts`），但**没有**「管理已归档会话」的入口——删除与「导入成新会话」这两个动作在客户端侧都不存在；而会话头部那条导入的语义是**覆盖当前会话内容**，与「管理归档集」不同源。

**决定**

归档集的管理动作（取消归档 / 删除 / 导入成新会话）只有一个入口：本包 `./ui` 的对话管理页（`sidebar.panellist` 的 nav 行 + `main` 的 keyed 面板成对注册）。导入落成**新会话**（不带 `sessionId`）；删除只对已归档会话开放；侧栏与会话列表那侧的归档过滤只负责查看与行内归档 / 取消归档。

**考虑过的选项**

| 选项                     | 否掉的理由                                                                                                     |
| ------------------------ | -------------------------------------------------------------------------------------------------------------- |
| 扩展上游设置页           | 上游 `@deepseek-ai/*` 只读，改不了                                                                             |
| 设置页与新页面并存       | 同一份归档集两个入口，删除 / 导入只在其一，用户要先知道该去哪一页                                              |
| 保留会话头部的覆盖式导入 | 覆盖需要一个「当前会话」目标，管理页没有这个上下文，且它与取消归档 / 删除不同源                                |
| 删除放开到未归档会话     | 与「会话删除仅限已归档且硬删」冲突（`deleteSession` 的 `SESSION_NOT_ARCHIVED` 守卫）；未归档会话可以先归档再删 |

**后果**

- 归档集的动作面收敛在一页：搜到的行即可取消归档、导出、删除，或按 zip 导入成新会话。
- 覆盖式导入不提供：zip 只能落成新会话；要在已有会话上覆盖内容需另立入口，当前没有这个需求。
- 两道守卫：页面禁用「删除」（未归档行）与宿主 `deleteSession` 的三条拒绝理由（带码回 wire），任一处改动另一处立刻红（`src/ui/conversation-manager/__tests__/**` 与 `src/__tests__/admin.spec.ts`）。
- 归档集合的真相仍在 workspace 域：`syncSessionFlags()` 把它写穿到会话行的 `f_archived_at`，列表与删除读会话行（[设计 20261109-投影检查点与storage接管的两个名字](../designs/20261109-投影检查点与storage接管的两个名字.md)）。
