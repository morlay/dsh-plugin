# spec 超 500 行的六个文件

状态：未销账——宿主半与浏览器半各有超 500 行的 spec：单文件把多条接缝的判据堆在一处，红一条要读完整个文件才知道它守的是哪个接缝。
位置：`packages/agent-ex/better-session/src/__tests__/rdb.spec.ts`（2077 行）、`src/data/__tests__/branch.spec.ts`（1377 行）、`src/ui/conversation-manager/__tests__/conversation-manager-page.spec.tsx`（967 行）、`src/storage/__tests__/projection-cache.spec.ts`（724 行）、`src/storage/__tests__/storage-takeover.spec.ts`（624 行）、`src/endpoint/__tests__/endpoint.spec.ts`（588 行）；口径与完整清单见[代码结构](../standards/代码结构.md)判据 2 的存量。

**现象**

- 六个 spec 各自超过 `代码结构.md` 决定 5 的 500 行上限；其余 spec 都在 500 行以内，非 spec 是另一档（300 行），清单不混在一起。
- 行数来自包根的一次 `wc -l`：`find src \( -name '*.spec.ts' -o -name '*.spec.tsx' \) | xargs wc -l | sort -rn`。

**影响**

- 改一条判据要在上千行里找锚点；同文件里的 `beforeEach` / 装配夹具被多组用例共享，新增一条要先读懂别人怎么起装配。
- 失败信息只给文件与行号，读的人没法从文件名判断这条红的是哪一面。

**触发条件**

动到这六个文件里任意一个的判据之前先还（改断言、加用例、换装配夹具都算）；新票要挂判据时优先放进新文件或已有接缝的小文件，不再往这六个里堆。

**销账条件**

Done when：这六个文件都 ≤ 500 行，且拆出的每个文件按接缝命名（`代码结构.md` 决定 5），整包回归与浏览器半不回退。

**不修的理由**

它们是本轮之前就存在的存量，行数来自「多条接缝共用一个装配夹具」；拆它要先定每个新文件的接缝与夹具归属，属于结构改动，和本轮的功能面改动不能混在一次（`代码结构.md` 决定 6）。
