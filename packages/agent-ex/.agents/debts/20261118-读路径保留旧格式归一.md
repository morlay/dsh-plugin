# 债：读路径保留旧格式归一（`read-view/legacy.ts`）

**状态**：已知且被接受。**owner**：`@morlay/better-session`（读视图）。

## 事实（决定这条债为什么存在）

1. **迁移链不是必跑**：迁移是独立链（`session-format-v0-to-v1` … `v3-to-v4`），只在**显式导入/升级**动作里跑；
   日常读路径不跑迁移。
2. **兜底是抛错**：上游 catalog 是严格校验器，不迁移、不降级——
   `session-format-catalog/src/current.ts:18-22`：`header.version !== SESSION_FORMAT_VERSION` 直接 `throw`；
   同文件 `:39` 对 artifact 同样抛。
3. **上游把「要不要迁移」作为事实暴露**：`session-persistence/src/index.ts:55` 的
   `formatStatus?: 'current' | 'migration-required'`。

合起来：用户机器上的存量产物可能是 v3 及更早，而读路径不会自动迁移——`read-view/legacy.ts` 是**读路径对旧产物的
唯一通路**。删了，读旧会话就抛。它是债，不是可以顺手清掉的中间态。

## 保留条件

保留到「存量产物里不再有非当前格式版本的会话」。

## 判据（可执行：直接查库，不看 `formatStatus`）

**为什么不看 `formatStatus`**：它由 `admin/query.ts` 组装，其中**两条来源是硬编码 `"current"`**——
`:128` 与 `:179` 给 `live` 会话写死 `formatStatus: "current"`（语义是「运行中的会话必然是当前格式」，不是
「判定它是不是」）。所以 `formatStatus` 在 live 会话上**恒为 current**，拿它当判据会永远通过。
→ **改成查落库的原始版本号**（`t_sessions.f_version`，见 `data/entities/v3/sessions.ts:10`）。

```sh
# SESSION_FORMAT_VERSION 的来源：@morlay/dsh-session/contract 的再导出（上游 SESSION_FORMAT_VERSION）
node -e "import('@morlay/dsh-session/contract').then(m=>console.log(m.SESSION_FORMAT_VERSION))"
```

```sql
-- 期望输出 0（所有会话都已是当前格式）；把 <VER> 换成上面打出的数字
sqlite3 <dataDir>/sessions/sessions.sqlite \
  "select count(*) from t_sessions where f_version != <VER>";
```

**注意**：统计的是**已落库的会话**（`t_sessions`），不含内存中的 live 会话——live 的版本由构造它的代码保证，
不在「存量产物」范围内。

## 回归保证

在判据满足之前，`src/data/__tests__/legacy-shape.spec.ts` **必须全绿**——它钉的就是「v3 形状能被读出来」。
删 `legacy.ts` 时必须同笔删这个 spec（否则 spec 会红，红就是提醒你判据没满足）。

## 删它的前置

上游读路径对 `migration-required` 给出**官方迁移入口**，且该入口能在我们的读路径上跑通（有 spec 钉）。
届时 `read-view/legacy.ts` 与 `legacy-shape.spec.ts` 一起删，本债记录一并删。
