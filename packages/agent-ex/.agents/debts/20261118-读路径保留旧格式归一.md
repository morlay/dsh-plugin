# 债：读路径保留旧格式归一（`read-view/legacy.ts`）

**状态**：已知且被接受。**owner**：`@morlay/better-session`（读视图）。

## 事实（决定这条债为什么存在）

1. **迁移链不是必跑**：迁移是独立链（`session-format-v0-to-v1` … `v3-to-v4`），只在**显式导入/升级**动作里跑；
   日常读路径不跑迁移。
2. **兜底是抛错**：上游 catalog 是严格校验器，不迁移、不降级——
   `session-format-catalog/src/current.ts:18-22`：`header.version !== SESSION_FORMAT_VERSION` 直接 `throw`；
   同文件 `:39` 对 artifact 同样抛。
3. **上游把「要不要迁移」作为事实暴露**：`session-persistence/src/index.ts:55` 的
   `formatStatus?: 'current' | 'migration-required'`（`SessionPersistenceSnapshot` / `SessionRecord` /
   `SessionSummary` 都带）。

合起来：用户机器上的存量产物可能是 v3 及更早，而读路径不会自动迁移——`read-view/legacy.ts` 是**读路径对旧产物的
唯一通路**。删了，读旧会话就抛。所以它是**债**（不是历史包袱，也不是可以顺手清掉的中间态）。

## 保留条件

保留到「存量产物里不再有 `formatStatus !== 'current'` 的会话」。

## 判据（可执行）

**入口**：`formatStatus` 是**算出来的**（`admin/query.ts` 按快照填，不是落库的列），所以不看表、看快照：

```sh
# 对一份用户数据目录，列出所有非 current 的会话（期望：空）
node -e "const {SessionPersistenceRdb}=await import('./packages/agent-ex/better-session/src/index.ts');"  # 占位说明
```

更可直接照做的两步：

```sh
# 1) 列出该数据目录下的全部会话快照
dsh session ls --data-dir <dataDir>            # 或调用 SessionPersistence.listSnapshots()
# 2) 逐个看 formatStatus；期望输出里没有 'migration-required'
dsh session stat <sessionId> --data-dir <dataDir>
```

**判定**：`#2` 的输出里 `formatStatus` 全部为 `current`（或 `undefined`）且**没有任何 `migration-required`** →
保留条件已满足，可以进入「删它的前置」。

## 回归保证

在判据满足之前，`src/data/__tests__/legacy-shape.spec.ts` **必须全绿**——它钉的就是「v3 形状能被读出来」。
删 `legacy.ts` 时必须同笔删这个 spec（否则 spec 会红，红就是提醒你判据没满足）。

## 删它的前置

上游读路径对 `migration-required` 给出**官方迁移入口**，且该入口能在我们的读路径上跑通（有 spec 钉）。
届时 `read-view/legacy.ts` 与 `legacy-shape.spec.ts` 一起删，本债记录一并删。
