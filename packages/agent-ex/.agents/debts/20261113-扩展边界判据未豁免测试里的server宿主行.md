# 测试装配要别的包的 `/server` 宿主行：扩展边界判据不豁免 `__tests__`，固定报 14 处

状态：触发中——`just audit` 的「扩展边界」每次报 14 处，全部落在 `__tests__`；生产代码 0 处
位置：判据 `devpackages/audit/src/package-audit.ts` 的 `group === "agent-ex"` 分支（遍历 `imports` 时不跳 `__tests__`，同文件「面边界」与「上游包唯一化」两处都显式跳过并写了理由）；命中集中在 `packages/agent-ex/better-session/src/__tests__/**`（9 处）与 `packages/agent-ex/session-mode/src/__tests__/**`（5 处）

**影响**

`just audit` 恒红、退出码 1，真越界（生产代码把宿主实现拖进扩展）会被这 14 条噪声盖住；改测试装配的人会把「测试装整应用」当成越界，从而绕开 `/server` 抄一份宿主行——那正是「同一个事实两个 home」。

**触发条件**

动扩展层的测试装配（`src/__tests__/support/**`）、动扩展边界判据、或按 `just audit` 绿来收尾之前。

**销账条件**

Done when：下面任一条落地后 `just audit` 的「扩展边界」只对生产代码报红——① 判据与同文件另两条对齐，跳过 `src/**/__tests__/**`（自引用也一并豁免：同包的 `/server` 不是「扩展之间」的依赖）；② 各 owning 包的 `testing` 面把测试要的宿主行转出来（`@morlay/dsh-session/testing`：`provideSession` / `provideSessionProjection` / `SessionStorePlugin` / `SessionProjectionRegistry` / `TokenMeter`；`@morlay/dsh-agent/testing`：`LlmAdapter` 或让 `FakeLlmAdapter` 可配 `stream`；`@morlay/dsh-conversation/testing`：`scheduleDomain`；本包加 `./testing` 出口给 `provideBetterSession`），测试改从 `testing` 取。

**不修的理由**

改 import 在扩展层内不成立，每一条都指回 owning 包写明的消费口：

- `packages/agent/dsh-session/src/server/index.ts`：装配函数「只从这里取 `provideXxx`」；`TokenMeter` 是上游 `@deepseek-ai/dsh-token-meter` 的转出，「放这里避免把上游 index 拖进 client」。`packages/agent/dsh-session/src/testing/index.ts` 只有 fixtures、契约套件与 `createSessionContext`，没有宿主行。
- `packages/agent/dsh-agent/src/index.ts`：「消费方不直接引 `@deepseek-ai/dsh-llm`，一律从本包取」，值面（`LlmAdapter`）在 `./server`；`./testing` 的 `FakeLlmAdapter` 只覆盖 `stream`（固定一句回复），三处子类要 `usage` / `resolveModel` / 失败注入，接不上。
- `packages/agent/dsh-conversation/src/server/index.ts`：`scheduleDomain`「属 conversation 的面，下游从这里取」——直连 `@deepseek-ai/dsh-schedule` 会造出第二个 owner。
- 自引用那三处（`host.ts` / `e2e-host.ts` / `exports.spec.ts`）：`.agents/standards/how-to-write.md` 要求「包内测试走包名（`@morlay/<包>/<面>`）：测试是唯一每次 CI 都跑的消费方，它顺带守住 `exports`」；`exports.spec.ts` 的判据本身就是用包名把 `exports` 当接缝。

判据侧同样是已知不一致：同文件「面边界」与「上游包唯一化」都跳过 `__tests__` 并写明「测试装配整应用是正当的」，`.agents/standards/how-to-write.md` 也写「判据只覆盖生产代码」；只有扩展边界这一条没跳。改判据属 tooling 写域，本层只报需求。
