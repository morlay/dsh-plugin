# 对话管理页（侧栏面板的形态、数据位与动作面）

状态：**已实现**——`provideBetterSessionUi()` 装出侧栏「对话管理」页；判据见 `src/ui/conversation-manager/__tests__/**` 与 `src/ui/session-editor/__tests__/user-message.view.spec.tsx`（共用反馈面）。
范围：`@morlay/better-session` 的 `src/ui/conversation-manager/**`——页面框架、会话视图与统计视图、`data-*` 标注面，以及它对 `sessionAdmin` 组与 `uiWorkspace` 的依赖；宿主实现（`src/server/session-admin-endpoint.service.ts`）的形状见 [设计 20261106-RDB复用边界与Remote端点形状](./20261106-RDB复用边界与Remote端点形状.md)。
非目标：归档状态的 owner（workspace 域）、会话行的读法（`src/admin/**`：`rows-query.ts` 的条件构造与 `session-ops.ts` 的取数）、消息动作（`src/ui/session-editor/**`，见包 `README.md` 与 `src/ui/session-editor/__tests__/session-editor.store.spec.ts`）。
关联：词义见[会话数据面术语表](../../../../agent/dsh-session/.agents/GLOSSARY.md)（会话 / 轮次 / live）与[会话编辑术语表](../GLOSSARY.md)（归档集在会话管理组一节）；[ADR-归档集管理动作归对话管理页](../adrs/20260918-归档集管理动作归对话管理页.md)；读写与失败面的宿主侧见[设计 20261120-会话读写与失败面的健壮性](./20261120-会话读写与失败面的健壮性.md)。

## 一、决定

| #   | 议题           | 决定                                                                                                                                                                                                             | 一句话理由                                                                               |
| --- | -------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------- |
| 1   | 注册形态       | `sidebar.panellist` 的 nav 行 + `main` 的 keyed 面板（`conversation-manager.view.tsx` 两个视图类）                                                                                                               | 与官方 ui-plugin-manager 同一种注册方式，不新造壳                                        |
| 2   | 列表取数       | 走 `sessionAdmin/rows`（完整语料，含归档）                                                                                                                                                                       | 官方列表按部署策略排除已归档，管理动作需要完整集合                                       |
| 3   | 搜索与分页     | 都在宿主：输入停 250ms 再发；每页 20 条，服务端上限 200                                                                                                                                                          | 归档集是全量语料，前端过滤随会话数线性变慢                                               |
| 4   | 统计视图       | 一次全库聚合（`sessionAdmin/usage`），换时间范围才重新请求，维度切换本地折叠                                                                                                                                     | 聚合口径归宿主（`src/data/usage.ts` 与统计表），页面只做展示与折叠                       |
| 5   | 页面形态       | 框架与上游一级页面同款（960px 居中列 + 标题行 + 过滤 chip 行 + 搜索行）；切换与过滤一律是**筛选 chip**（`role="group"` + `aria-pressed`）                                                                        | 上游没有这套框架的共享原子，不另造 tab 条原子                                            |
| 6   | 状态态         | 读取 / 一份会话都没有 / 读列表失败三种**整屏居中**且不画框架；搜索无结果不算（框架留着，用户要能改搜索）                                                                                                         | 前三种时候页面没有别的内容可做                                                           |
| 7   | `data-*` 标注  | 只标「最小身份 + DOM 读不出的状态」                                                                                                                                                                              | 沟通与 e2e 要能指着某一行说，而不必复述页面文案                                          |
| 8   | 查询状态       | 列表的取数、搜索防抖、分页、在途、失败保留旧行、过期响应丢弃与页码夹取收进 `useRowsQuery`；页面只渲染                                                                                                            | 这些状态互相牵连，散在页面里时每加一个动作都要重算一遍依赖                               |
| 9   | 反馈面         | 成功 `role="status"`、失败 `role="alert"`、在途 `aria-busy` 收进共享 `Feedback` 与 `useActionFeedback`；列表、统计、消息行共用                                                                                   | 三处各写一份 role 与重试按钮时，语义很快分叉                                             |
| 10  | 破坏性确认     | 删除与覆盖导入的确认按钮用 `tone="danger"`（`data-tone="danger"`），在途禁用；未归档会话的删除按钮用 `aria-disabled` + 点击给理由                                                                                | 危险动作要读得出是危险的；无理由的原生 `disabled` 让用户不知道为什么点不了               |
| 11  | 焦点与播报     | 动作成功后焦点落在列表标题；分页条是 `nav` + `aria-label`；翻页 / 搜索 / 筛选落地后有 `role="status"` 播报                                                                                                       | 行被重拉后按钮已卸载，焦点不能还给旧元素；列表变化要能被听见                             |
| 12  | 请求身份       | 列表（`useRowsQuery`）与统计（页面的 `usageRequest`）各带自增身份：只有最后发出的响应能落地，慢的旧响应丢弃；失败保留旧行并给重试                                                                                | 没有身份时慢的旧响应会覆盖新响应；失败清空会把「读不到」和「没有会话」混成一个空态       |
| 13  | 多选与批量删除 | 选择只覆盖当前页（全选本页 + 行复选框），批量删除**一次请求**、逐条结果；结算后清空选择并重拉，行重拉后选择只保留仍在当前页的 id                                                                                 | N 次单删要页面自己拼结果与失败原因；选择指向已删的行时批量条会说谎                       |
| 14  | 体检入口       | 标题行一颗「数据体检」（`data-action="consistency"`）；报告落在列表上方的面板：在途 / 干净 / 不一致清单三态，逐条 `data-issue`（检查项）+ 主体 + 期望与实际的差                                                  | 体检是全库只读扫描，属于页面级观察，不是行上动作                                         |
| 15  | 修复入口       | 行上「修复」（`data-action="repair"`）先开确认弹窗，弹窗里只有两个日志修法（`data-action="repair-drop-tail"` / `repair-rewrite`，危险语义）与取消；删除不进弹窗                                                  | 删除已有自己的入口与守卫，弹窗里再放一次就是两套删除语义                                 |
| 16  | 批量导出       | 标题行一颗「导出筛选结果」（`data-action="export-filtered"`）：动作面把当前搜索与归档筛选原样带走，先逐页收全命中集 id，再一次 `sessionAdmin/exportMany`（宿主逐条给上游 format 的 zip），页面逐条落成下载       | 筛选结果可能跨多页，页面不该自己拼导出；逐条结算才报得出「导出了几条、几条失败」         |
| 17  | 跨工作区复制   | 行上「复制到工作区」（`data-action="copy"`）→ 确认弹窗里选目标工作区（列表来自 workspace 域的快照）→ 宿主 `copyToWorkspace`（`fork` + workspace 的 `attach`）；源会话保留                                        | 工作区记录的 owner 在 workspace 域，页面只读快照；复制不是移动，「源会话原样保留」是判据 |
| 18  | 失败文案       | 只认宿主给的码（`failure.ts`）；`SESSION_CONCURRENT_WRITER` 折成「该会话正在别处运行；请先停掉那个实例，再重试这次操作。」，不显示库里的位点细节                                                                 | 位点对用户没有下一步；能做的事只有「停掉那边再重试」                                     |
| 19  | 批量归档       | 多选条上「归档 {count} 条会话」（`data-action="bulk-archive"`）→ 确认弹窗（`data-action="bulk-archive-confirm"`）→ 页面**逐条**委托 `uiWorkspace` 的归档动作，失败条聚合成一条提示；结算后清空选择并重拉         | 归档的 owner 在 workspace 域，本页不造第二套归档；可逆动作用确认但不给 danger 语义       |
| 20  | 事件定位       | 行上「定位」（`data-action="locate"`）→ 弹窗（`locate-modal.tsx`）：文本 / 类型 / 角色 / 工具名四栏 + 时间两栏，空栏不下推；结果区 `data-locate="results"`（`data-locate-window`）与逐条 `data-locate-hit`，只读 | 定位是排障的第一步：只回 seq 与片段，坏会话也能先看坏在哪一行                            |
| 21  | 批量导入       | 文件输入带 `multiple`：一个文件仍走单条导入（含覆盖导入与阶段回调），多个 zip 一次走 `sessionAdmin/importMany`，失败条按**选中的文件名**给原因，整批不回滚                                                       | 批量导入的语义是「一次请求、逐条结果」；按文件名报错才认得出坏的是哪一个包               |
| 22  | 时间窗口口径   | 时间 chip 映射到 `updatedAfter` 时用**本地自然日**的零点（`localDayWindowStart`）：近 7 / 30 天 = 今天零点往前 6 / 29 天，与宿主统计的本地日同一口径                                                             | 自然日口径才和统计页、用户说的「昨天」对得上；滚动窗口跨零点会前后不一致                 |

## 二、现状事实

- **文件**：页面 `conversation-manager-page.tsx`（+ `conversation-manager-page.module.css`）、查询状态 `rows-query.ts`、动作面 `conversation-manager.controller.ts`、失败文案映射 `failure.ts`、统计视图 `usage-view.tsx`、体检报告面板 `consistency-panel.tsx`、修复弹窗 `repair-modal.tsx`、定位弹窗 `locate-modal.tsx`、过滤 chip `filter-chip.tsx`、反馈面 `../shared/feedback.tsx` 与 `../shared/action-feedback.ts`、wire 客户端 `session-admin-endpoint.client.ts`、视图与槽位 `conversation-manager.view.tsx` / `conversation-manager-page.slot.ts`、字典 `locales.ts` + `conversation-manager-locales.contribution.ts`、数字格式 `format.ts`。
- **装配**：`src/ui/better-session.provide.ts` 的 `provideBetterSessionUi()`，字典与端点客户端先、store / 贡献 / 视图后。
- **页面只读注入面**：`t` + `ConversationManagerFace`（`listRows` / `archive` / `unarchive` / `remove` / `bulkDelete` / `exportZip` / `exportFiltered` / `importZip` / `importMany` / `locateEvents` / `listWorkspaces` / `copyToWorkspace` / `organizeData` / `loadUsage` / `checkConsistency` / `repairSession`）；`importZip(file, options?)` 的第二个参数带覆盖目标 `sessionId` 与阶段回调 `onStage`（`reading` → `committing`）；批量归档**不新增**注入面方法——页面逐条调已有的 `archive`（归档的 owner 在 workspace 域）；wire、base64、zip 字节与下载细节全在 controller 里。
- **行形状**：宿主给 `SessionRowsItem`（`sessionId` / `title` / `origin` / `cwd` / `createdAt` / `updatedAt` / `archived` / `workspace`，见 `src/endpoint/session-admin-endpoint.ts`）；`useRowsQuery` 折成 `ConversationRow`（标题兜底、工作区摊平、`origin === "subagent"` 判子代理）。
- **框架**：`.page` / `.listPane` / `.pageScroll`（`data-scroll="page"`）/ `.pageContent`（960px 居中列）/ `.pageHeading` / `.filters` + `.filterTabs` + `.filterTab` / `.searchField`；整列一起滚，页面根不滚。
- **会话视图**：视图 chip（会话 / 统计）→ 子代理开关 → 时间 chip（全部时间 / 近 7 天 / 近 30 天）与归档 chip（全部 / 仅已归档 / 未归档）→ 搜索行 → 列表 → 分页条（子代理开关及其后的各行只在会话视图）；行上「归档 / 取消归档」互斥、导出恒有、修复恒有（先确认再选修法）、定位恒有（只读弹窗）、覆盖导入恒有（先确认）、删除只在已归档行可用（宿主同样守卫）、「复制到工作区」恒有（先确认、再选目标工作区）；标题行另有「导出筛选结果」与「数据体检」；多选后批量条上有「批量归档」与「批量删除」两个动作。
- **筛选**：三组 chip 都下推到宿主——子代理是 `includeSubagents`，时间映射成 `updatedAfter`（**本地自然日**：近 7 / 30 天 = 今天本地零点往前 6 / 29 天，`rows-query.ts` 的 `localDayWindowStart` 按日历日回退、不是减 N × 24h；与宿主统计的本地日同一口径，时间窗在 chip 变化时钉住一次，列表与批量导出共用），归档映射成 `archived: "only" | "unarchived"`；三者与搜索进同一个 WHERE（`src/data/store/rows-query.ts`），任何筛选变化都回到第 1 页并播报。
- **搜索两段式**：标题先前缀（对 `lower(f_title)` 做范围比较 `>= ? AND < ?`（SQLite）/ `like(lower(f_title), 'x%')`（PG），与全文段同一大小写口径；索引当前不参与前缀段，见[标题前缀搜索用不上 idx_sessions_title 那条债](../debts/20261120-标题前缀搜索用不上idx_sessions_title.md)），这一段没命中才退全文（`LIKE '%x%'`，接受扫描）；workspace 标题命中的会话 id 两段都算命中；宿主在 `searchStage` 回报实际走的那一段（`prefix` / `contains` / `none`），页面挂在列表容器的 `data-search-stage` 上。
- **多选与批量动作**：行复选框（`data-select`）+ 列表顶部「全选本页」行（`data-bulk`：无选中 `idle`、有选中 `active`）；有选中时该行多出条数、「归档 {count} 条会话」（`data-action="bulk-archive"`）与「批量删除 {count} 条会话」（`data-action="bulk-remove"`）。
  - **批量删除**：弹窗与单条删除同一套危险语义（`data-tone="danger"`），确认前不发请求；一次 `bulkDelete` 请求，逐条结果聚合成一条提示（`已删除 {deleted} 条会话，{failed} 条未删除` + 失败项的「会话：原因」），结算后清空选择并重拉。
  - **批量归档**：确认弹窗（`data-action="bulk-archive-confirm"`，可逆动作不用 danger 语义）确认后页面**逐条**调 `archive(id)`（归档委托 `uiWorkspace`，经 storage 接管写穿到会话行），失败条聚合成「已归档 {archived} 条会话，{failed} 条失败。」+ 失败项的「会话：原因」，结算后清空选择、重拉并把焦点收回标题。
- **批量导出（按筛选结果）**：标题行「导出筛选结果」（`data-action="export-filtered"`，列表为空或在途时禁用）→ `exportFiltered(rowsQuery.filters)`：controller 先按同一组条件逐页打 `sessionAdmin/rows`（每页 200）收全 id，再一次 `sessionAdmin/exportMany`；成功的每条落成一次下载（文件名由宿主给，`<会话>.zip`），失败条聚合成一句「已导出 N 个会话；M 个失败」，不逐条弹。
- **批量导入**：同一个文件输入（`multiple`）既服务单条也服务批量——选一个文件走单条导入（「导入为会话」，覆盖导入另经确认），选多个 zip 时一次 `importMany(files)`（`sessionAdmin/importMany`）；好包各落成一条新会话，坏包按**选中的文件名**给原因（宿主只回包里的 artifact 名，认不回用户选的是哪一个），整批不回滚；提示是「已导入 {imported} 个会话，{failed} 个失败。」+ 失败项。
- **事件定位**：行上「定位」（`data-action="locate"`）→ `locate-modal.tsx`；四栏文本 / 类型 / 角色 / 工具名 + 时间两栏（`datetime-local`，发请求前换成毫秒，空栏与解析不出来的都不下推）；「定位」（`data-action="locate-run"`）在途时按钮 `aria-busy`；结果区 `data-locate="results"` 带 `data-locate-window="<from>-<to>"`，命中逐条 `li[data-locate-hit="<seq>"]` 显示 seq · 类型 · 角色 · 工具名与命中片段；没有命中给一句空态。只读：不写库、不改日志，命中列表里没有动作按钮（修法归 `repair`），失败走 `Feedback`（`source="locate"`）。
- **复制到工作区**：行上「复制到工作区」（`data-action="copy"`）→ 先 `listWorkspaces()` 读 workspace 域快照（弹窗里先显示「正在读取工作区…」），确认弹窗（`data-action="copy-confirm"`，`data-copy-workspace` 是目标工作区下拉）里选目标工作区后才能点「复制」；成功后提示「已复制到「{工作区}」」、重拉列表、焦点回标题，失败按码给文案。
- **反馈与焦点**：提示由 `../shared/feedback.tsx` 的 `Feedback` 呈现（不是裸 `p`）：成功 `role="status"`、失败 `role="alert"`、可重试的带同一个重试按钮；动作在途在 `../shared/action-feedback.ts` 的 `useActionFeedback`，确认按钮 `disabled` + `aria-busy`，行内动作与导入入口同时禁用；消息行 `session-editor/user-message.view.tsx` 用同一个 `Feedback`，在途由它的 `acting` 表示；动作成功（归档 / 取消归档 / 删除 / 批量删除 / 导出 / 导入 / 整理 / 修复）后焦点落在列表标题（`h1` 可聚焦）；未归档会话的删除按钮 `aria-disabled="true"`、点击给 `failure.notArchived`；分页条是 `nav` + `aria-label`，翻页 / 搜索 / 筛选落地后经 `role="status"` 播报页码与条数。
- **请求身份**：列表在 `rows-query.ts` 的 `useRowsQuery`（自增 `requestId`，只有最后发出的响应落地）；统计在页面的 `usageRequest`（同一口径）。
- **失败文案**：`failure.ts` 的 `failureCopy` / `failureText` 只映射会改变用户下一步的码（`SESSION_NOT_ARCHIVED` / `SESSION_LIVE` / `SESSION_CONCURRENT_WRITER` / `SESSION_NOT_FOUND` / `SESSION_IMPORT_LIVE` / `SESSION_IMPORT_NOT_ARCHIVE` / `SESSION_IMPORT_TOO_LARGE`）；`SESSION_ROWS_INVALID_PAGE` 与 `SESSION_USAGE_INVALID_RANGE` 没有专属文案，落到 `failure.other`（显示宿主原文）。`SESSION_CONCURRENT_WRITER` 折成「该会话正在别处运行；请先停掉那个实例，再重试这次操作。」——位点细节（「另一个写者追加到 seq N」）不给用户。
- **长任务**：导入在途按 `reading` / `committing` 两段给提示并写明不能取消；整理运行期弹窗不可关闭，正文写明不能取消。
- **体检**：标题行按钮 → `checkConsistency` → 报告进 `consistency-panel.tsx`：在途（`Feedback` + `aria-busy`，`data-notice="consistency"`）/ 干净 / 不一致清单三态；不一致项是 `section[data-consistency="issues"]` 下逐条 `li[data-issue="<kind>"]`，显示「检查项 · 主体」与「期望与实际的差」。只读：不写库、不重算，报告不落库（刷新即清），面板上没有修复按钮。
- **修复**：行上「修复」→ `repair-modal.tsx`（`tone="warning"`）→ 选「丢坏尾部」/「整段重写」（都是危险语义）→ `repairSession`；确认前不发请求，在途两个按钮都禁用；成功后提示「保留 N 条事件，丢弃 M 条」并重拉列表、焦点回标题，失败按域码给文案（`SESSION_LIVE` / `SESSION_NOT_FOUND` 各自有专属文案）。删除不在弹窗里。
- **统计视图**：时间范围 chip（`day` / `week` / `7d` / `30d` / `90d` / `all`，默认 `day`）→ 维度 chip（`overview` / `models` / `sessions`）→ 按会话维度时的「只看子代理」开关；总览两行（全部 / 其中子代理），按模型把人类与子代理的桶折进同一行，按会话取用量前 20；失败横幅带重试（重拉当前范围）。

**接口**（调用方要知道的）：

- `listRows(request)` 的 `page` 从 1 起、`pageSize` 缺省 20（服务端上限 200）；返回 `{ items, total, page, pageSize, searchStage? }`，`useRowsQuery` 按 `total` 算页数并把当前页夹在范围内。
- 过滤参数都走同一个 `rows` 请求：`updatedAfter` / `updatedBefore`（与行 `updatedAt` 同列：`f_last_event_at`，没有事件回落 `f_created_at`）、`origin`（`human` / `subagent`，与 `includeSubagents` 同时给时 `origin` 优先）、`archived`（`only` / `unarchived`）；`searchStage` 是宿主回报的**实际**搜索段（`prefix` / `contains` / `none`）。
- `bulkDelete(sessionIds)`：整批一次请求，返回 `{ items: [{ sessionId, ok, code? }] }`；拒绝（未归档 / 运行中 / 不存在）是**结果里的码**而不是整批失败，整批不回滚。
- `importZip(file, options?)`：不给 `sessionId` 是新建导入，给了就是覆盖该会话（整段替换）；`onStage` 报 `reading` / `committing`。
- `importMany(files)`：多选 zip 一次请求（`sessionAdmin/importMany`），返回 `{ items: [{ ok, code?, sessionId?, filename? }] }`（顺序与入参一致，失败条没有 `sessionId`——没有身份不等于空串），页面按 `files[i].name` 给失败原因；单个文件不走它（仍走 `importZip`，带阶段回调）。
- `locateEvents(sessionId, query)`：只读定位，`query` 是 `text` / `types` / `role` / `name` / `fromTime` / `toTime` / `fromSeq` / `toSeq` / `limit` 的子集（空栏不出现）；返回 `{ window: { fromSeq, toSeq }, total, items: [{ seq, type, role, name, time, snippet }] }`。
- `exportFiltered(query?)`：按当前筛选批量导出。动作面先把命中集逐页收全（`rows` 每页上限 200），再一次打 `sessionAdmin/exportMany`；返回 `{ items: [{ sessionId, ok, code?, filename?, zip? }] }`，成功的每条落成一次下载，失败条按整批聚合成一句提示。
- `listWorkspaces()`：读 workspace 域的客户端快照列表（`{ workspaceId, title }`），只做复制弹窗的选择项；本页不直连库，也不造第二份工作区记录。
- `copyToWorkspace(sessionId, workspaceId)`：跨工作区复制，返回 `{ sessionId, workspaceId }`（新派生的子会话与目标工作区）。宿主侧是 `fork` + workspace 的 `attach`：子会话 `cwd` 换成目标路径、源会话保留；工作区不在注册表给 `SESSION_COPY_WORKSPACE_NOT_FOUND`，attach 失败撤掉子会话并给 `SESSION_COPY_ATTACH_FAILED`。
- 动作失败一律抛 `ConversationManagerRequestError`（带宿主 `code`）；`failure.ts` 把 `SESSION_NOT_ARCHIVED` / `SESSION_LIVE` / `SESSION_NOT_FOUND` / `SESSION_IMPORT_LIVE` / `SESSION_IMPORT_NOT_ARCHIVE` / `SESSION_IMPORT_TOO_LARGE` 折成字典文案；`SESSION_ROWS_INVALID_PAGE` 与 `SESSION_USAGE_INVALID_RANGE` 没有专属文案，落到 `failure.other`（显示宿主原文），其余码同样保留原文。
- 列表与统计的请求各带自增身份：只有最后发出的响应能落地；列表失败保留旧行并给重试，统计失败保留上一份报告并给重试。
- 删除只对已归档行可用（页面 `aria-disabled` + 点击给理由，宿主守卫）；归档 / 取消归档委托 `uiWorkspace`，本页不提供第二套；批量归档同样逐条委托它（页面只负责确认、聚合与重拉）。
- `checkConsistency()`：只读体检，返回 `{ ok, checked: { sessions, events, bridges, usageRows, countRows }, issues: [{ kind, subject, detail }] }`；不写库、不重算，修法各自入口（重算归 `organizeData`，坏会话归 `repairSession`）。
- `repairSession(sessionId, action)`：`action` 是 `drop-tail` / `rewrite` / `delete`；返回 `{ sessionId, action, keptEvents, droppedEvents }`。两个日志修法在运行中的会话上给 `SESSION_LIVE`、不存在给 `SESSION_NOT_FOUND`；`delete` 沿用未归档 / 运行中的删除守卫。

## 四、行为与边界

1. **正常路径**：进入页面拉第一页 → 行按最近活动降序（宿主排序）→ 动作成功后重拉当前页，焦点回到列表标题。
2. **搜索**：输入停 250ms 才发请求并把页码重置为 1；宿主先前缀后全文，回报实际走的那一段（页面挂在 `data-search-stage` 上）；有查询时出现清空按钮，点了清空并还原列表；搜索无结果时框架留着，空态落在列表位置；落地后播报页码与条数。
3. **分页**：每页 20 条，翻页即重新请求；页数按 `total` 算，当前页夹在 `1..pageCount`（末页被删空自动回落）；分页条是 `nav` + `aria-label`。
4. **子代理**：默认不列（真实库里占多数，既不可删也多数无意义）；勾选后真全量并带标记，筛选变化回到第 1 页并播报。
5. **错误**：读列表失败 → 整屏失败态（`role="alert"` + 重试）；刷新失败保留旧行、横幅给重试；动作失败 → 提示行 `role="alert"`，删除 / 覆盖导入弹窗收掉，列表不重拉。
6. **GC**：确认后进入不可关闭的运行期弹窗，正文写明不能取消；成功后提示三项计数并重拉列表。
7. **统计**：进入统计视图时拉一次（默认本日、总览）；换范围带参数重新请求；维度切换不请求；失败时 `role="alert"` 给原因与重试（重拉当前范围），已拿到的报告不被清空。
8. **覆盖导入**：行上「覆盖导入」→ 选文件 → 确认弹窗（危险语义）→ 确认后才发请求（带目标会话）；在途时行内入口禁用，成功后重拉并提示。
9. **请求身份**：列表与统计各以自增身份发出请求，最后发出的响应落地、慢的旧响应丢弃；失败保留已显示的数据（列表旧行 / 统计上一份报告）并给重试。
10. **取消与并发**：页面不取消在途请求——请求失败只落到提示行；同一时刻只允许一个删除确认或一个 GC 流程；导入与整理没有取消面（[债](../debts/20261120-导入与整理没有取消面.md)）。
11. **结构化过滤**：时间 chip（全部 / 近 7 天 / 近 30 天）映射成 `updatedAfter`（**本地自然日**的零点：近 7 天 = 今天零点往前 6 天，跨月 / 跨夏令时也落在本地零点；不是滚动 N × 24h），归档 chip（全部 / 仅已归档 / 未归档）映射成 `archived`；两者与搜索、子代理筛选进同一个 WHERE，变化回到第 1 页并播报。
12. **多选与批量删除**：全选本页 / 行复选框 → 批量条 → 确认弹窗（危险语义）→ 一次 `bulkDelete`；逐条结果显示为一条提示（删掉几条、几条未删 + 失败项原因），结算后清空选择并重拉；行重拉后选择只保留仍在当前页的 id。
13. **体检**：点「数据体检」→ 在途提示（按钮 `aria-busy`、面板显示「正在体检…」）→ 报告落到面板；不一致项逐条列检查项、主体与期望和实际的差，干净时只给一句「没有发现不一致」。只读：不写库、不重算，报告不落库；失败走提示行（`role="alert"`），上一次的报告保留。
14. **修复**：行上「修复」→ 确认弹窗（`tone="warning"`，确认前不发请求）→ 选「丢坏尾部」/「整段重写」→ 在途两个按钮都禁用；成功后提示保留 / 丢弃条数、重拉列表、焦点回标题，失败按域码给文案并收掉弹窗。删除不在弹窗里：走既有的删除入口与守卫。
15. **批量导出**：点「导出筛选结果」→ 动作面按当前搜索与归档筛选逐页收全命中集 → 一次 `exportMany` → 成功的每条落成一次下载，失败条聚合成一句「已导出 N 个会话；M 个失败」；列表为空或动作在途时按钮禁用。
16. **复制到工作区**：行上入口 → 弹窗先读工作区快照（在途显示「正在读取工作区…」）→ 选目标工作区 → 「复制」（未选时禁用、在途两个按钮都禁用）→ 成功提示「已复制到「{工作区}」」并重拉列表、焦点回标题；失败按域码给文案，弹窗收掉。
17. **批量归档**：勾选若干行 → 「归档 {count} 条会话」→ 确认弹窗 → 确认后逐条调归档动作（每条各自成败，互不影响）→ 聚合提示「已归档 N 条会话，M 条失败」+ 失败项的会话与原因 → 清空选择、重拉、焦点回标题；取消弹窗不发请求。
18. **批量导入**：文件输入选多个 zip → 一次 `importMany` → 好包各落成一条新会话、坏包按选中的文件名给原因 → 聚合提示「已导入 N 个会话，M 个失败」→ 重拉列表；选一个文件时仍是单条导入（阶段提示不变）。
19. **事件定位**：行上「定位」→ 填条件（空栏不下推）→ 「定位」→ 结果区给出窗口 `[from, to]`、命中总数与逐条（seq · 类型 · 角色 · 工具名 + 片段）；换条件再定位会整段重取。只读：不写库、不改日志，命中列表没有动作按钮；失败走弹窗内的提示，上一次的结果保留。

## 六、取舍

- **不借官方 `session/list`**：它按部署策略排除已归档、且没有标题与最后活动时间；两条路混用会让「缺席即删除」的语义与归档集判定互相污染。
- **不做前端过滤 / 分页**：成本随会话数线性增长，后端已经有完整语料与分页参数通道。**例外**是统计按会话维度的「只看子代理」——数据已在手上，过滤不产生新请求。
- **页面框架不自造原子**：上游没有共享的 `pageHeading` / `filterTabs` 原子，各家一级页面在 CSS Modules 里写同一套度量；本包是唯一消费者，照写一份比往基础面加导出便宜。
- **按模型不拆子代理**：模型行的价值是「哪个模型花了多少」，子代理用的是同一个模型，拆行只会把同一模型的成本打散。
- **不做常驻刷新**：这是只读面板，动作成功后重拉一次即可。
- **批量删除一次请求、结果逐条**：N 次单删要让页面自己拼结果与失败原因；宿主逐条复用同一套守卫（已归档 / 非运行中），页面只读结果。
- **选择只覆盖当前页**：跨页选择要在行被删、翻页、筛选变化时逐条对账，而批量条的计数必须说得准；「全选本页」的语义小且不会说谎。
- **不用 tab 条表达视图切换**：切换与过滤都是筛选 chip（`aria-pressed`），与上游一级页面的视觉一致。
- **查询状态收进 `useRowsQuery`**：请求身份、搜索防抖与页码夹取互相牵连，散在页面里时每加一个动作都要重算一遍依赖；页面只渲染。
- **反馈面收成共享 `Feedback`**：上游 `Text` 只认自己那几个 props（`role` / `aria-busy` 落不到 DOM），三处各写裸 `p` 会让 role 与重试按钮分叉。
- **体检只报不修**：自动重算会把「账不对」和「读不出来的会话」混成一个动作；报告要能被复述，修法各自入口（重算归整理，坏会话归修复）。
- **删除不放进修复弹窗**：删除已有自己的入口与守卫（已归档、非运行中），弹窗里再放一次就是两套删除语义。
- **破坏性确认用 `Button` 的 `tone="danger"`**：危险配色只在上游那一档存在，不另造一套红色。
- **未归档删除用 `aria-disabled` 而不是原生 `disabled`**：原生禁用不可聚焦，读屏也读不出原因；可聚焦 + 点击给理由才说清「为什么不能删」。
- **动作成功后焦点落在列表标题**：行会被重拉，触发按钮可能已卸载；标题是页面上稳定的落点。
- **导入与整理只给阶段与「不可取消」，不画假取消**：wire 上没有取消面，画一个取消按钮等于骗人；真取消留给债。
- **否掉「页面失败时清空列表」**：清空会把「读不到」和「没有会话」混成同一个空态。
- **否掉「请求加 `AbortController`」**：wire 上没有取消面，取消只是丢弃响应；身份比取消少一半状态。
- **否掉「整屏空态保留原样、只在文案里提示导入」**：导入按钮在标题行，被短路之后无处可点。

## 七、不做与已知债

- 排序只有「最近活动在前」一种，没有分组；批量动作只有删除与「导出筛选结果」两种（归档仍是逐条，批量导入没有页面入口）。
- 子代理会话可见后仍不可删除（它们未归档）——要删先归档，符合「删除仅限已归档」的口径。
- 统计是一次全库聚合，只在进入统计视图时请求；按会话的行是各会话自己的日志口径（fork 子会话含继承前缀），所以各行之和 ≥ 总量。
- 导入只接受含会话日志 artifact 的 zip；导出只导出该 artifact，不含附件等旁路数据。
- 导入与整理没有取消面：[债](../debts/20261120-导入与整理没有取消面.md)。
- 体检是点一次跑一次的全库扫描：报告不落库（刷新即清），没有常驻巡检，也不比较两次报告。
- 事件级定位（`sessionAdmin/locate`）没有页面入口：它是端点能力（排障先定位再修复），页面上只有体检与修复。

## 八、开放问题

- 统计视图按会话维度只取前 20：超过时目前只能靠时间范围收窄，要不要给分页或导出。
- 体检报告要不要留历史与常驻巡检（现在只保留当前一次，失败时保留上一次）。
- 事件级定位要不要页面入口（现在只能从端点调；页面上「坏在哪一行」靠体检与修复的回报间接知道）。
- 导入与整理的进度：导入只有 `reading` / `committing` 两段、整理只有一条「正在整理」，长库上的耗时不可见（取消面见[债](../debts/20261120-导入与整理没有取消面.md)）。
- 导入与整理各有一套在途呈现（导入的阶段提示、整理的不可关闭弹窗）；要不要收成同一个「进行中的长任务」入口。
