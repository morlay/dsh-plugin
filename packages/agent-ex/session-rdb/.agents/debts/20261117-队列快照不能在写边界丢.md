# 队列快照事件只能在 `Session.append` 处丢，不能在写边界丢

状态：接受中（已按「不重写」收口，字面意义的「不落库」暂时做不到）。

位置：`packages/agent-ex/better-session/src/editor/plan.ts`（`keptOutsideTurn` / `QUEUE_SNAPSHOT_EVENT_TYPES`）。

**现象**：`agent/inbox/spliced` 是 inbox 的队列快照（插入 / claim），它本该只在内存里，却被当「轮外事实」
重写回日志（`appendSeedSuffixLive`），于是 replay 会重放、`plan.ts` 还要专门写一条忽略规则去遮它。

**为什么不能按字面「不落库」**：本包的存储坐标与内存 log **一一对应**——`write-path.ts::appendEventTail`
按 `head + 1` 追加，`log/rows.ts` 读回时用存储位置覆盖 `seq`，`branch/rewind.ts` 又用同一坐标截断内存 log。
**在写边界丢行会让之后每一次撤回错位**。真要丢，只能在 `Session.append`（`vendor/**`）里丢，那是上游面。

**现在的收口**：`keptOutsideTurn` 不再保留这类快照（`QUEUE_SNAPSHOT_EVENT_TYPES`），重放需要保留的输入由
`plan.queuedUsers` 重新 followup 一次。实测：一次编辑/重试的 `inserted` 从 2 条降到 1 条，
`user/message` 的 `source.rpcId` 保住。

**销账条件**：上游提供「不落库的运行时快照」通道（或 `Session.append` 支持标记为易失），
使 `t_events` 里不再出现队列快照，同时撤回/截断的坐标语义不变。
