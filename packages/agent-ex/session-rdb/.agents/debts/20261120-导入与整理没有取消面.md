# 导入与整理没有取消面

状态：未销账——导入与整理都是长任务，页面只有阶段提示与「不可取消」说明；wire 上没有取消方法，中途离开只能等它跑完。
位置：`packages/agent-ex/better-session/src/ui/conversation-manager/conversation-manager-page.tsx`（导入阶段提示、不可关闭的运行弹窗）、`src/ui/conversation-manager/conversation-manager.controller.ts`（`importZip` 的阶段回调）、`src/endpoint/session-admin-endpoint.ts`（`import` / `organize` 没有取消参数）。

**现象**

- 导入：页面按 `reading` / `committing` 两段给提示，文案写明不能取消；用户没有中断动作的入口。
- 整理：运行期弹窗不可关闭（mask 与 Escape 都走空 `onClose`），只有成功或失败才收掉。
- 两者都没有量化进度：导入只有两段，整理只有一条「正在整理」。

**影响**

长库上的整理与大会话包的导入期间，用户既不能取消也不能判断还要多久；误触发只能等。

**触发条件**

要给取消按钮、进度条或「后台继续」之前必须先有取消面；整理起手就停掉了运行中的 Agent，取消还要决定是否恢复它们。

**销账条件**

Done when：`sessionAdmin` 面有取消方法（或 `import` / `organize` 返回可中断的 job 身份），页面据它给取消按钮与进度；整理被取消时给出「哪些会话已重算 / 哪些没动」的结果；且有「取消后目标会话保持原样」与「取消整理后 Agent 恢复」两条用例。

**不修的理由**

取消要改 wire 契约与宿主侧的写入协议（导入的截断 + 重写、整理的孤儿回收事务），并把「停 Agent」的可逆性设计清楚；本轮只做页面侧的可读性与在途防重。
