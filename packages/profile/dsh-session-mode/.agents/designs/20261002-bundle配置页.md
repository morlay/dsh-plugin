# bundle 配置页（`plugins.bundle.config` 的形态与落点）

状态：**已实现**（插件管理页里本 bundle 的详情页出现"默认模式 + 每个模式一张可折叠卡片"的表单）
范围：`packages/profile/dsh-session-mode/src/client/` 的 bundle 配置页（`bundle-config.ts` 的数据面、
`BundleConfigPage.tsx` 的布局与控件、`bundle-locales.ts` 的文案）与它的注册面。
约束：不新增装配行；上游 `@deepseek-ai/*` 与 `vendor/**` 只读；页面读写的仍是本行的 settings 命名空间。

## 结论摘要

| 议题       | 结论                                                                                                         | 一句话理由                                                                                         |
| ---------- | ------------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------- |
| 注册面     | `plugins.bundle.config`，key = bundle 包名 `@morlay/session-mode-profile`                                    | 页面按 bundle 包名取注册项，这就是那个 slot 的约定（`ui-plugin-manager` 的 keyed 槽）              |
| 注册方     | **`session-mode` 行的 client 半**，不是 bundle 包自己                                                        | bundle 不是 Loader 的行：它要带 client 半就得在 patch 里插自己一行，插件页会多出一行可禁用的同名行 |
| 读写面     | 仍是 `session-mode` 命名空间（`ctx.configForms.get`），页面不发明配置                                        | bundle 装的就是这一行，两个面说的是同一份配置                                                      |
| 表单形态   | 顶部一个"新会话的默认模式"选择器 + 每个模式一张可折叠卡片，卡片内按六组分字段                                | 行页那套按 schema 平铺的 JSON 结构视图在"十几个模式各十几个字段"上不好用                           |
| 草稿       | 复用通用 schema 表单的控制器（`SchemaFormController`）：编辑落草稿，底部保存是唯一写盘点，整段校验挡在保存前 | 暂存、整段校验、覆盖标记、一次写入都是现成的，自己再写一份只会分叉                                 |
| 增删模式   | 支持：新增 = 字典的 `addKey`（名称默认成 id），删除 = `removeKey`                                            | `modes` 是一个字典，模式的增删就是它的增删                                                         |
| 删除保护   | `noop` 不给删（卡片上只留一句说明），其余模式可删                                                            | 它是"与上游一致"的对照档，删掉就没有"什么都不加"的那个选项                                         |
| 跨字段校验 | 页面自己那三条（至少一个模式、默认模式在清单里、默认模型成对），消息挂在出错的那一行                         | 与 host 装配期的 `configProblem` 同向；schema 表达不了这些关系，但保存前必须能立刻说出来           |

## 事实基线

### 页面结构

- 顶部「新会话的默认模式」：下拉，选项来自当前模式清单（值 = 模式 id、显示名 = 模式名）；值不在清单里时页面就地
  标红（保存也会被这条规则挡下）。
- 模式区：每个模式一张卡片。卡片头（官方 `DisclosureRow`）从左到右是：**模式名 + 模式 id**，右侧一组 **一行摘要 +
  删除入口**（摘要形如 `禁 1 件 · 跟随全局模型`，受保护的模式在同一个位置给一句说明）。**默认全部收起**，点开才出现
  字段；展开区里只有六组字段——id 与角色都不再重复（id 已在头部，角色由「角色」那两个按钮表达）。删除按钮在折叠开关
  那一行里，所以它先拦下这次点击（`stopPropagation`），别顺手把卡片收起来。
- 底部是官方表单壳（`SettingsForm`）：保存 / 丢弃 / 只读 / 命名空间不可用 / 上次保存失败，文案来自本页字典。

### 字段与分组

| 组             | 字段                                                                            | 控件                                                               |
| -------------- | ------------------------------------------------------------------------------- | ------------------------------------------------------------------ |
| 标识           | `name` / `description` / `role` / `preset`                                      | `SettingsValueField` / 同左 / 角色按钮（`main`、`subagent`）/ 同左 |
| 提示词         | `persona.prefix` / `persona.suffix`                                             | 多行文本                                                           |
| 工具与技能     | `allowTools` / `denyTools` / `allowSkills` / `denySkills`                       | 标签输入（`Input` + `Tag`）                                        |
| 上游规则       | `allowPolicies` / `denyPolicies`                                                | 标签输入 + 「从候选里选」（候选 = `POLICY_NAMES` 里还没加的）      |
| 请求里注入什么 | `instructions` / `skills` / `runtimeContext`                                    | `Switch` / 三态 `SegmentedControl`（不写·开·关）/ `Switch`         |
| 默认模型       | `defaultModel.provider` / `.model` / `.reasoningEffort`（整块可"跟随全局模型"） | `Menu` 选择器 / `Menu` 选择器 / `SettingsValueField`               |

### 排法与控件

两种排法，按控件的宽度选：

- **上下排（输入类）**：`标签 / 控件 / 说明` 同列——就是官方 `SettingsValueField` 的排法。用于文本、多行文本、标签
  输入、候选选择器。
- **右置排（切换类）**：左列是 `标签 + 说明`，控件贴最右（`justify-content: space-between`）。用于开关（`Switch`）、
  三态（`SegmentedControl`）与多选的角色按钮。顶部**「新会话的默认模式」**也是这种排法（左侧标签与说明，右侧
  `Menu` 选择器贴最右）。

数值全部取自官方设置面的 `fields.module.css`：标签 13px / wt500 / 主文本色，说明 12px / 第三级文本色，字段上下各
12px 留白，相邻字段之间一条 0.5px 的分隔线（`--dsw-alias-border-l2`）。字段容器只管分隔线，留白交给内层（文本字段
交给官方控件自己的 `padding: 12px 0`），所以两类字段之间不会出现"一条线两种间距"。

控件也一律用官方 primitives：文本字段是 `SettingsValueField`（标签、说明、「已覆盖」标记、恢复默认、非法提示都在它
里面），候选选择是 `Menu`，开关是 `Switch`，三态是 `SegmentedControl`，角色是两个 `Button`（选中的用 `primary`、未
选的用 `outline`，`aria-pressed` 表达选中），标签输入由 `Input` + `Tag` + `Button` 拼，删除确认是 `Modal`，表单壳是
`SettingsForm`——**整页只有按钮、菜单、输入、标签四种控件**，视觉与上游设置面同一套 token。唯一自造的是多行文本
（官方通用表单只有单行 `SettingsValueField`），它按官方输入框的 `padding` / 边框 / 圆角 / 背景 / 字号画。

危险动作按官方那套 CSS 变量换色：卡片里的删除按钮是描边 + 错误色（`color` 与 `--dsw-alias-interactive-bg-hover`），
弹窗里的确认按钮把 `--dsw-alias-button-primary-fill` 换成错误色——与上游插件页的卸载按钮同一种做法，不另造按钮外观。

### 名单字段（标签输入）

六份名单都是**名字的集合**，页面上是标签输入：**一个带边框的框**（与官方输入框同一套边框/圆角/背景）**包住所有标签与
内联的那一个输入框**，放不下就换行（`flex-wrap`）；框内的输入没有自己的边框与背景，候选菜单按钮在框外右侧。

- 敲一个回车确认一个；空串忽略。
- **粘贴逗号分隔的一串会拆成多个标签**（中英逗号、分号、换行、制表符都是分隔符），去空白、去重、保序。解析出两个以上
  才拦截粘贴——单个名字照旧落进输入框，粘完还能改。
- 每个标签自带移除按钮；有候选的名单（两份 policy）另给一个「从候选里选」菜单，列出还没加进去的那些。
- 写的是整段数组（一次 `set` 替换），所以一次粘贴就是一次草稿编辑。

- 候选值走与行页同一份提示面（`schemaFormHints`）：`llm-providers` / `llm-models` 两个具名源与 policy 名单的候选，
  所以页面不必自己知道 LLM 目录。
- "三态"是 `skills` 的真实语义：**不写**由这个模式自己的工具名单推导（`derivedSkills`），写 `true` / `false` 才是
  显式覆盖。控件把这三档画成一段分段控件，选"不写"写的是 `unset`（清掉用户层）。
- 候选读不到时（例如没有任何可配置的 provider）选择器退回文本输入：否则这条字段在页面上没有可选项，是个死胡同。

### 数据面

- 一个模式命名空间一个控制器（`SchemaFormController`），依赖是 `ctx.configForms`（读 + 带栅栏的写）、
  `ctx.settingsSchema`（rehydrate + 校验）与上面那份提示面；读数经 `hooks.bundleConfig` 交给框架绑成
  `useBundleConfig`，动作（`set` / `editText` / `clear` / `appendItem` / `removeItem` / `addMode` / `removeMode` /
  `save` / `discard`）是同一份注入面里的函数。
- **提示面服务要先解包再用**：cordis 把服务值包成追踪代理（`Symbol.for("cordis.original")` 指回原实例），代理上的方法调用
  以代理为 `this`，而提示面实现用的是 JS 私有字段（`#texts` …）——私有字段只认声明它的实例，于是整块 slot 直接崩
  （`Cannot read private member #texts from an object whose class did not declare it`，页面只剩一个空的错误边界）。
  所以读候选、订阅变化、登记候选之前都先 `unwrapService` 解包成原实例。判据是一条真 cordis 服务的用例：代理上直呼
  会抛、解包后读得到。
- **候选（服务商 / 模型）现取现读**：提示面由基础面异步装上，可能比这一页晚到，所以读候选时每次 `ctx.get` 一次，
  不缓存"那一刻还没有"；提示面一到、或它的候选变了，就重投影一次（`refreshPage`）。这样模型那两个字段不会静默退回
  手输——它们与行页读的是同一份具名源（`llm-providers` / `llm-models`，后者按当前服务商换模型清单）。
- 字段路径就是真实路径：`modes.<模式 id>.<字段…>`（列表项再带索引），`default` 是它自己。字段的"有没有值"由
  投影时该路径是否在字段树里判定——缺值的可选字段照常出现在页面上（显示"没写"），用户一填即是写。

## 取舍

- **注册方是行包，不是 bundle 包**：`dsh-client-modules` 只扫 Loader 的行来组 client 行清单，而我们的 bundle 是
  patch 来源、不是行。让 bundle 自带 client 半就得在它的 patch 里插一行指向自己，代价是插件页里这个 bundle 多出一
  行同名行（可禁用、可配置，读起来绕）。行包那边已经在装 `ui-primitives`、已经知道 bundle 归属的 key 约定，注册代码
  放那里既省装配又不新增面。
- **复用通用表单的控制器，不复用它的渲染**：草稿、整段校验、revision 栅栏、保存失败保留草稿这些语义行页已经踩过；
  渲染必须换——行页那套 `key: value` 的行式视图适合"随便什么 schema"，不适合"一眼看出这个模式收窄了什么"。
- **只做 `session-mode`**：本 bundle 另外三行里，`subagent` 在插件页有官方设置卡，`context-assembler` 与
  `tool-guidance` 的字段**不在 volatile 面上**（设置面按设计只允许写 volatile 字段），放进来只能是只读展示。
- **不做模式模板**：新增模式 = 一个 id + schema 默认值（名称默认成 id），其余字段展开后逐个填。模板选择是
  "再发明一套模式语义"，等到真有人要再说。
- **摘要只给两层信息**（工具面 + 模型面）：卡片头要能回答"这个模式收窄了什么"，但不该变成第二份字段清单。
- **控件一律复用官方 primitives，名单用标签输入**：这一页是"另一个设置面"，自己发明输入框外观会让同一份配置在两个
  页面上长得不一样；名单是名字的集合，从文档或另一份配置里**粘贴一串**是一次真实动作，一个输入框一个回车太慢。
- **多选与开关做成按钮（`Pill` / `Switch`）而不是复选框**：整页的交互语汇因此只有"按钮、菜单、输入、标签"四种，
  与官方设置面的按钮化选择一致；复选框只出现在真正"勾选多个"才自然的场合（本页没有）。
- **删除走确认弹窗，确认按钮用错误色**：删一个模式是这一页唯一不可逆的动作（改字段、加模式都能丢弃），所以它过一次
  `Modal` 确认；确认按钮沿用官方 `primary` 按钮、只把填充色换成错误色，避免页面上出现第二种按钮外观。
- **跨字段规则在页面侧再说一遍**：schema 校验管不到"默认模式必须在清单里"，host 侧要等到重挂才报错；页面在保存前
  说出来，消息挂在出错的那一行（默认模式选择器 / 那个模式的模型组）。

## 已知限制

- 模式**改名不支持**：改 `name` 只改显示名；改 id 得删掉再加一个（`modes` 的键就是 id）。
- 模式的增删与字段编辑都只在**重挂这一行之后**对新会话生效（与行页同一条语义）：页面底部保存的是配置，不是正在
  运行的会话。
- 页面只列当前存在的模式；`noop` 的"不给删"是页面侧的保护（配置里删它当然还是能删，那是改文件的事）。

## 开放问题

- 字段级"继承值"提示：`base`（组成层）与 `user` 层现在都拿得到，页面上只画了"覆盖了"这一个标记。
