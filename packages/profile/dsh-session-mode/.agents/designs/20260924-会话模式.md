# 会话模式：模式作为数据，按会话应用

状态：已实现（2026-09-24）。形态沿革与决策见
[ADR 模式不再是 Cordis 子树](../adrs/20260924-模式不再是cordis子树.md)；被取代的旧形态见
[设计 预设生成与装配](./20260917-预设生成与装配.md)。

范围：`packages/profile/dsh-session-mode/` 的模式来源、应用时机、会话 ↔ 模式的选择，以及页面上的选择面。
工具行本身在 [`@morlay/dsh-agent-toolkit`](../../../dsh-agent-toolkit/README.md)，收口的执行在
[`@morlay/dsh-context-assembler`](../../../../context/dsh-context-assembler/README.md)，装配层的禁用与默认值在
[`@morlay/dsh-profile`](../../../dsh-profile/README.md)。

约束：不放宽「上游代码不可修改」——只用上游公开的服务面（`systemPrompt.section`、`ctx.sessions`、
`sessionProjections`、`tools.guard`）与装配行。

## 结论摘要

| 议题           | 结论                                                                                | 一句话理由                                                                     |
| -------------- | ----------------------------------------------------------------------------------- | ------------------------------------------------------------------------------ |
| 模式来源       | `session-mode` 行的 `config.modes`（`tool/modes.ts` 是真源，构建期渲染进 patch）    | "支持自定义"就是改一份 config，不是加行                                        |
| 官方那一套     | 全部禁用（registry / 四个 shipped preset / 客户端三个面）                           | 模式用不着子树，留着就是两套并行的机制                                         |
| 提示词         | `agent.ctx` 上注册 `deployment:persona-prefix` / `-suffix`                          | 跨层遮蔽部署级那层；这条路上游给子 agent 也在用                                |
| 工具与注入开关 | 推给 `ctx.sessionToolScope`（`context-assembler-scope` 行）                         | 谁注册了工具与"这个会话能用什么"无关；同时保持依赖单向                         |
| 应用时机       | `agent/created`（切换时对已有 agent 再应用一次）                                    | 早于任何一次提示词装配，persona 必在首次装配前注册好                           |
| 会话 ↔ 模式    | session 事件 `session-mode/selected` + 投影 `sessionMode`（`null` = 没选过）        | 模式决定模型看到的工具与提示词，按仓库规矩必须进日志                           |
| 切换判据       | 只有空白会话（`turnBoundary` 的 `openTurnStartSeq === null && lastTurn === 0`）     | 与上游 `agentPresets.select` 同一条：跑过的历史属于旧装配                      |
| 页面通路       | `GET/POST /session-mode`（清单与切换）+ `projectionValues.sessionMode`（当前值）    | 客户端的 remote 清单由上游硬编码，我们的服务不在里面；投影随会话列表免费到页面 |
| 模式角色       | `role`：`main`（用户选择器）/ `subagent`（可作子代理 mode 的候选），缺省 `["main"]` | "谁能用这个模式"是一份声明，不是散在各处的判断                                 |
| 默认模型       | 模式的 `defaultModel`：只在会话**尚无模型事实**时接管请求路由，不写会话事件         | 它是配置事实；用户的选择与会话已有历史优先                                     |
| 子代理的模式   | 继承父当前模式，并把继承写进子会话日志；`subagent` 角色只管"可被指定"的候选         | 模式决定工具与提示词，子代理那边同样得是一条可重建的会话事实                   |
| 先读后改       | `fs-observation-policy` 在装配层禁用，`relax-intent` 退出                           | 官方 preset 退出后，"按模式抵消"不再是唯一能按模式表达的做法                   |

## 事实基线

### 数据形状

`src/modes.ts` 给形状与校验（`Config` schema + `configProblem`）：`default` 必须在 `modes` 里、必须是 `main`
角色，每个模式至少给一个 `allowTools`——空名单是写错了，不是"全都要"，装配期直接抛（旧形态里这条判据在
scope 行上，错误会吞在模式子树里没人看见）。另外两条同批加入的判据：`role` 不能是空数组（缺省等于
`["main"]`），写了 `defaultModel` 就得同时给 `provider` 与 `model`。

`role` 与 `defaultModel` 是**模式的两个新面**：

- `role: ("main" | "subagent")[]`（缺省 `["main"]`）：`main` 进用户选择器（`list()` / `roster()` 只列它，
  `select` 拒绝非 `main` 的模式）；`subagent` 声明"它可以作为子代理的 mode"——目前只是候选集，因为按角色
  指派还没做（见下）。
- `defaultModel?: { provider, model, reasoningEffort? }`：这个模式的默认模型，形状与全局
  `agent-default-model` 一致；不写就跟着全局。`tool/modes.ts` 是生成物的真源：`tool/patch.ts` 把它渲染进 `cordis.patch.yml`，
  `patch.spec.ts` 比对两者。

### 应用

`agent/created` 事件里做，两件事：

1. `installPersona` 在 `agent.ctx.systemPrompt.section(...)` 注册两个 section（`prefix` / `suffix`，suffix
   缺省是空串——与上游 persona 行同语义：空串遮蔽部署级那层）。注册与注销都会发 `system-prompt/change`。
2. `ctx.sessionToolScope.apply(agent, mode)`：`context-assembler-scope` 行收到后做三件事——装配期投影
   （`tool:<名字>` section 与工具目录同源过滤）、执行层 guard（挂在 `agent.ctx` 上）、通道开关
   （`setInstructions` / `restrictTools`）与动态快照抑制。
3. `mode.defaultModel` 的兜底：在 `agent.ctx` 上挂一个 `agent/request` waterfall，**只在会话尚无模型事实**
   （投影 `modelSelection` 的 `pending` 为空、且 `session.requestHeader()` 还没落）时把这一请求的
   provider / model / reasoningEffort 换成模式配的那份。它不写会话事件——模型选择是配置事实，会话里那条
   `model/selection`（由上游设置面写）才是用户的选择。

每个 agent 记着"当前装的是哪个模式"，模式没变就是空操作。切换模式时：先收回旧的一份（persona 的 effect、
scope 那边的 effect 树），再装新的。

### 会话与模式

`select(sessionId, mode)` 是唯一的写路径（HTTP 路由与本地服务同一份实现）：校验模式存在、会话存在、还没跑过
turn，然后 append `session-mode/selected`，最后对已有的 agent 重新应用。投影 `sessionMode` 是读路径：
`stateOf(session, "sessionMode") ?? config.default`。恢复（resume）与 fork 都从日志重建这条投影，不需要
header 字段。

**落点**（我们的部署是 [`@morlay/session-rdb`](../../../../session/session-rdb/README.md)）：事实是
`t_events` 里一条 `f_type = 'session-mode/selected'` 的事件行（`f_data` 是整条事件信封），按
`t_session_events` 的 `f_sequence` 挂在该会话上；`sessionMode` 的投影值另存 `t_session_projcache_row`
（`f_key = 'sessionMode'`，`f_val` 是 `"chat"` 或 `null`）——那是折出来的缓存，不是事实。表结构见
[设计 表结构](../../../../session/session-rdb/.agents/designs/20260917-表结构.md)。**header 里没有这个字段**
（上游 agent preset 那套的 `t_sessions.f_agent_preset` 我们不写）；默认模式来自装配 config，不落库。

**这个事件类型上游不认识**（上游的已知类型表由它自己仓库的声明生成），所以要靠 `ignorable` 信封过持久化校验
——信封由 [`@morlay/session-rdb`](../../../../session/session-rdb/README.md) 的 `OWN_EVENT_TYPES` 补（落库前补 +
读回时兜底）。本包**新增事件类型时必须同步登记**，否则写入就被拒，见
[设计 自造事件类型的信封](../../../../session/session-rdb/.agents/designs/20260924-自造事件类型的信封.md)。

### 子代理与继承

子代理是**新会话**（`session.header.parentSession` 指向父），所以它的模式不能靠"读投影 + 默认"决定——那样
每个子代理都会掉回部署默认模式。规则是：

- **默认继承父当前模式**：创建时（`agent/created`）若该 agent 有 durable 父会话且父还在场，就取父的当前
  模式，并把 `session-mode/selected` **写进子会话**——继承是一条会话事实，冷恢复与 fork 必须能重建它
  （读路径仍只认投影）。父不在场（孤儿会话、父已卸载）时不继承，回落部署默认。
- **继承不看 `role`**：`subagent` 角色声明的是"可被指定的候选"，不是"继承的白名单"。父在 chat 里派发的
  子代理仍然是 chat——否则同一个任务在父子两边跑着两套工具与提示词。
- **指定 mode 的入口还没做**：本包把接缝留在服务上——`applyTo(agent, mode, { record })`（不要求空白会话，
  子代理继承走的就是它）与 `modesFor("subagent")`（候选集）。将来无论是模型侧参数还是配置，都从这里进。

### 页面

client 半与 host 半同包（`./client` 入口，浏览器模块工厂加载）。两个槽位：
`conversation.hero.agentPreset`（顶部占位的 chip，点开是切换列表）与
`conversation.session.header.actions`（只读标签，id `session-mode`，`order: -10`）。清单在页面生命周期里是
静态的（装配事实），模块级缓存一次；当前值由 `useSessions` 读投影，切换后跟着会话列表快照刷新。

## 取舍

- **不在页面里改模式清单**：它是装配配置。设置面因此比官方少一块，换来"模式清单只有一个 home"。
- **切换只在空白会话**：不是懒，是语义——历史与装配必须对得上。想要"中途换模式"，正确做法是新开会话。
- **推模型而不是拉模型**：依赖方向保持单向（装配层 → 能力包）。代价是 `session-mode` 要认识
  `ctx.sessionToolScope` 的最小接口，而不是反过来。
- **HTTP 而不是 Typert Remote**：客户端能发现的服务清单由上游硬编码（`@deepseek-ai/dsh-api-remotes/client`），
  我们的服务不在里面。HTTP 路由是这个仓库既有的跨半通路（见 `/session-editor`）。
- **`defaultModel` 不写会话事件**：它是配置事实，重启后仍由 config 决定；把它写成会话事实会让"部署改了
  默认模型"对已有会话失效，也会与用户自己在设置里选的那份（`model/selection`）混成一件事。
- **兜底条件苛刻（无 pending、无 header）**：宁可不动，也不覆盖用户的选择或会话已经跑过的历史模型。
- **两个模式共享一套 host 平面**：工具行、通道、压缩都装一次，模式只声明"能用哪些"。代价是"模式"不再能
  各自带不同版本的同名行；收益是加工具只改一处。
