## 结论摘要

| 议题        | 结论                                                                                                                | 一句话理由                                                                                                  |
| ----------- | ------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------- |
| preset 来源 | 我们的清单（`tool/presets/*.ts`）渲染进 patch 里的两行 `@deepseek-ai/dsh-agent-preset`（`coding` / `chat`）         | 清单里只留我们要的行；0.1.7 起上游 preset 就是声明式行，没有目录可放                                        |
| 官方 roster | 官方四行（`preset-standard` / `preset-ptc` / `preset-minimal` / `preset-cordis`）保持启用                           | 它们各自是完整 composition，与我们的模式并存可选；不去禁用就少一处跟着上游 preset 名单走的耦合              |
| persona     | 每个模式的 preset 行自带 `persona`（`tool/presets/persona.ts`），在 agent 作用域遮蔽部署级同名 section              | 模式之间要的腔调不同；host 层一行 persona 会覆盖掉所有模式                                                  |
| `default`   | `agent-preset-registry` 的 `config.default` 取清单首项（`coding`），与清单同包                                      | "注册了什么模式"与"哪个是默认"是同一个事实的两半                                                            |
| 注入通道    | 每个模式一行 `@morlay/dsh-context-assembler`（包的**组装出口**）**住在一个 `isolate` 组里**；装哪些能力由 config 给 | 通道住 host 时它的注册表不分 scope，我们的注入会漏进官方 preset 的会话（实例见 ADR）                        |
| 读前置策略  | host 那层 `fs-observation-policy` 不动；`coding` 自带一行 `relax-intent` 抢在它的 waterfall 前丢弃结果              | 它是模式取舍不是部署事实：禁用 host 行会连官方 preset 一起关掉，而 preset 里的行动不了 host 行              |
| 动态快照    | `chat` 的 `context-scope` 声明 `runtimeContext: false`，按 scope 抑制沙箱/审批策略那两条 context                    | 对话模式没有文件与 shell 工具，"能改工作区哪些文件、要不要走审批"对它全是噪音；抑制按 scope，别的模式照旧收 |
| 工作区指令  | 上游 web-app bundle 已把 host 的 `agent-instructions` 设在 preset 平面；`coding` 用我们的实现接管                   | 我们按 `mtime:size` 对账、一条文件一条 id；官方那套的 touch 跟踪用不上                                      |
| 沙箱 / 搜索 | 不在本包：沙箱替换与搜索后端都住 host 层（见 `@morlay/dsh-profile`）                                                | 替换 `ctx.fs` / `ctx.sandbox` 与"选哪个 provider"都是部署级决定，preset 层要么解析不到、要么撞 id           |

## 事实基线

### 清单与 patch

模式定义由 `tool/presets/*.ts` 的**显式行清单**给出：`tool/patch.ts` 把它
渲染成一行 `@deepseek-ai/dsh-agent-preset` 的 `config.plugins`（`js-yaml` 用 include 的 `entryListSchema`
输出，`!!js` 表达式由 `jsExpr()` 从一个无参函数取函数体——平台开关这类运行期判断因此仍是编译器检查过的
代码）。

行清单是我们**按需列**的，不从上游 composition 派生。派生只在上游默认集合就是我们要的时候才划算；
现在定制已经很多（不装 planning、外部 agent CLI（codex / claude-code）、ralph、plugin-manager，还要追加
注入相关的行），派生等于每次都在「读上游 → 禁用/收窄」。上游改动改由覆盖性测试提醒：清单里的行必须仍在上游
存在（`patch.spec.ts` 逐项比对 `cordis.patch.yml` 与清单）。

patch 落在包根的 `cordis.patch.yml`，由 tsdown 的 `build:done` hook 重写（`tsdown.config.ts` 挂
`patchHooks()`）。必须挂 `build:done` 而非 `build:prepare`——tsdown 时序是 `build:prepare` → `clean()`
（清空 outDir）→ rolldown → `build:done`，写在 clean 之前会被删掉。

生成器显式设 `quotingType: '"'`：`yaml.dump` 默认单引号而仓库 oxfmt 偏好双引号，不指定会让生成器与
formatter 来回改。

`package.json` 的 `files` 含发布所需的 `cordis.patch.yml`、`dist` 与 `tool`。

### roster 与展示名

选择器里有 `coding`（registry 的 `default`）与 `chat`，外加官方四个模式（原样保留）。展示名与描述直接来自
行的 `config`（`name` / `description` / `order`）——0.1.7 起上游没有再拿 `BUILT_IN_PRESET_KEYS` 去套客户端
语言字典这一层，自造 id 与官方 id 一视同仁。

### 提示词分层

`persona` 行在 agent scope 注册 `deployment:persona-prefix` / `-suffix`，**按 scope 遮蔽**部署级值（上游
`core/system-prompt/tests/scoped.spec.ts` 固化了该语义），所以按模式给提示词只走 section：部署级
`system-prompt` 行发布 `ctx.systemPrompt`（进程全局服务），preset 里的行不允许发布它（上游 `leakedServices`
会拒绝装载整块 preset）。

`personaPrefix` 位于 order 0（prompt 最前）：声明指令优先级（直接用户指令 > 工作区 `AGENTS.md` > 本系统提示词）
与执行协议。其中点名 `AGENTS.md` 是**强制约束**——官方 `agent-instructions` 注入模板的措辞（"may be
relevant" / "as guidance" / "do not override…"）是上游的通用保守表述，会让模型把仓库规则当参考而不是规则，
所以这里显式反制。`personaSuffix` 位于 order 10200（prompt 最后）：把最关键的约束在近因位置复述一次；细节
只在 prefix 维护，避免两处重复。

### 注入通道与它的消费者同住一个 isolate 组

通道（`@morlay/dsh-context-assembler/assembler`）发布进程全局服务 `ctx.contextAssembler`。preset 子树里的服务要么
声明 `isolate`、要么被上游拒（`Preset services require isolate realms`），所以它有两条路：

| 路           | 结果                                                                                                                             |
| ------------ | -------------------------------------------------------------------------------------------------------------------------------- |
| 住 host      | 一行覆盖全部 preset——**包括官方那四个**。它的注册表（rules / skills / 装配改写）不分 scope，我们的注入于是漏进官方 preset 的会话 |
| `isolate` 组 | 通道与消费者只在这棵子树里解析得到；别的 preset 拿不到它（真装配判据见 [规范](./../standards/how-to-verify.md)）                 |

**现状（2026-09-23）：通道改为在 profile 平面装一次、不隔离。** 跨包的消费者——
[`@morlay/dsh-agent-toolkit`](../../../dsh-agent-toolkit/README.md) 的工具说明行——`inject` 不到被关在 `isolate` 组里的
通道（行停在 waiting，汉化与用法分组没生效）；而隔离的原始理由（挡住注入漏进官方 preset 的会话）也随官方四个
preset 被禁用而消失。模式差异改由 `context-scope` 收口（工具白名单同时管工具目录与 `tool:` 说明 section、
`instructions`、动态快照），见 [ADR 通道作为全局服务装配不隔离](../../../../context/dsh-context-assembler/.agents/adrs/20260923-通道作为全局服务装配不隔离.md)。下面是隔离时期的形态，保留作沿革。

**当时选了后者**（2026-09-22）：住 host 的那段时间里，官方 `standard` / `ptc` / `cordis` 的会话照样收到我们的
工作区指令、skill 目录、工具用法分组与引用材料，连中文替换文案都作用在它们身上——静态断言看不见（它只看行
清单），只有真装配的会话能看见。走 `isolate` 的必要条件是**通道与它的全部消费者在同一个组里**：落一个消费者
在组外，它的 `inject` 就永远等不到服务（行停在 waiting，不报错）。所以清单里所有
`@morlay/dsh-context-assembler*` 行都必须在这个组内（引用展开 `@morlay/dsh-reference` 不在此列——它由 `@morlay/better-session` 装配），`patch.spec.ts` 把这条钉住。

（沿革）当时的组形态是 `channelGroup([contextChannel(config?), guidanceRow(config?)])`：一行组装出口 + 工具说明行，`isolate`
声明在组行上、覆盖整棵子树。这条形态已不再使用——隔离要求消费者与通道同组，而消费者现在跨包；`isolate` 的 label 按
服务名给、与组 id 无关这一点仍然成立。

### 读前置策略（`relax-intent`）按模式抵消

上游 `fs-observation-policy` 是 event-only 插件（不注册服务），住 host 层、对所有 preset 生效；它在
`fs/write-intent` / `fs/edit-intent` 这两个 waterfall 上**不调用 `next()`**、独占决策槽。而 preset 里的行
**禁用不了 host 行**（preset 是独立 EntryTree；`Entry.id` 按树的 owner entry 前缀化，两棵树 id 空间不重叠）。

所以「本模式不要先读后改」只能抢在它前面：`src/relax-intent.ts` 用 `prepend`
站链首，先让它算完（它抛的拒绝也接住），再对**属于本 preset 的 actor** 丢弃结果——`intent` 为 `undefined`
就是上游 bare default 的「无条件编辑」。归属判据走 scope（本行的 scope 就是该 preset 的 standing key，actor 的
agent scope 沿 parent 链必然经过它），**不能**靠事件过滤：`fs/*` 的派发不传 thisArg，`resolveListeners` 因此
不过滤监听者，预设外的会话也会命中我们这一行（`relax-intent.spec.ts` 把这个判据与 `prepend` 顺序都钉住）。

### skill：provider 用上游行，工具与目录用我们的

上游 web-app 的 patch 注释（`vendor/deepseek-harness/packages/bundle/web-app/cordis.patch.yml:454-467`）写明
registry 的形状：**host + per-scope 分层**——host 的 `skill-filesystem` / `tool-skill` 在 web 组合里被禁用
（local discovery 归 preset），preset 自己装 `skill-filesystem`（本地发现 provider）与 `tool-skill`（把目录与
加载器交给该 agent）。

我们的 coding 沿用这个形状，只换掉「工具与目录」那一半：provider 仍是上游 `skill-filesystem`（`skill` 是 host
面服务，provider 与工具是两件事，不同 scope 不会抢名字），`tool-skill` 换成 `@morlay/dsh-context-assembler/skill-catalog`
（目录做规则块 + 自己的 `skill` 工具）。这也解释了为什么 host 层**不需要**再禁一次那两行：上游自己已经把它们设
在 preset 平面。

### 工具说明降级为 reminder

上游把每个工具的跨调用说明（`tool:bash`、`tool:read`、…）、Agent Teams 协作规则、harness 源码位置、Web GUI
说明都注册成系统提示词的 section。本部署实测它们占 9200 字符里的约 7400：条数多、篇幅大、挤在上下文最前面，
稀释真正要遵守的那几行纪律。通道因此在装配时按 `keep` 名单留下部署 persona，其余 section 按处置分流——丢弃
（平台运维说明）、改写（两段中文文案）、或降级捕获；pre-step 时把要送的内容**逐条**以 `<system-reminder>`
user 消息注入，紧随本轮用户消息之后（每条按文本幂等，只有变化的那条重发）。机制与取舍见
[ADR-20260921-提示词注入只有一个通道且按需内容走skill](../../../../context/dsh-context-assembler/.agents/adrs/20260921-提示词注入只有一个通道且按需内容走skill.md)
与该包 README。

这一层现在**只在我们的模式里发生**（通道住 isolate 组）：官方 preset 的 section 不再被降级、改写或丢弃。

### 工作区指令

`coding` 里的 `agent-instructions` 行是我们的实现（`@morlay/dsh-context-assembler/agent-instructions`），它按
`mtime:size` 对账、一条文件一条 id（官方那套的 touch 跟踪用不上）。上游 host 层那行由 web-app bundle 自己
禁用，所以两份不会撞。

### 装配

`agent-preset-registry` 行的 `config.default` 指向 `coding`；两个模式各自一行
`@deepseek-ai/dsh-agent-preset`（`preset-coding` / `preset-chat`，`config.plugins` 是清单渲染出的装配行）。
官方那四行保持启用（与我们的模式并存）。三处都是同一份 `cordis.patch.yml` 里的行，没有运行期解析、没有
`!!js` 路径表达式，也没有桌面专属的目录挂载点。

## 取舍

- **不动官方的 preset 行**：官方那四个 shipped preset 都是各自 scope 里的完整 composition（官方工具与提示词），
  与我们的模式并存即可；按 id 禁用会让我们跟着上游的 preset 名单走，收益只是少四个选项。
- **每个模式一份清单**：`coding` 列编码形态的行，`chat` 只列对话要的那几行（工具三个、`context-scope` 收白名单
  并关掉 instruction、不要用法分组）。两份清单各自声明，不从一个上游 composition 派生。
- **id 全用自造名（`coding` / `chat`）**：0.1.7 起展示名不再经客户端语言字典套官方 id，自造 id 与官方 id
  一视同仁；代价是旧会话里记的 `standard` 需要在恢复时重选模式，见
  [ADR preset 改用上游声明式行](../adrs/20260922-preset改用上游声明式行.md)。
- **按需列行而不是派生上游 composition**：代价是上游新增行不再自动跟随——换成覆盖性测试来提醒复核。
- **通道按模式 isolate，而不是留在 host 当"唯一通道"**：代价是每个模式各一份通道实例（内存与装载成本 ×N），
  换来的是模式之间零泄漏；真要让注入机制全局唯一，就得先解决"它的注册表按 scope 分层"（见
  [ADR 通道与注入行按模式 isolate 装配](../adrs/20260922-通道与注入行按模式isolate装配.md)）。
- **读前置策略由模式自己抵消，而不是 host 层禁用**：host 禁用是全局动作（官方 preset 一起关），而 preset 里的行
  动不了 host 行；抢 waterfall 是唯一能"按模式"的机制，代价是多一个插件行与一条顺序敏感的测试。
- **reminder 用独立插件而不是 `persona` 行的 `complete: true`**：`complete` 会连 suffix 一起丢，且子 agent 自己
  注册同名 persona 时 `complete` 语义消失，保留 / 降级会不一致；插件按 `keep` 名单匹配 section 名，两种 agent
  行为一致。
