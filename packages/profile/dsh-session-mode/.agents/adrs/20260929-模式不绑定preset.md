# 模式不绑定 preset

状态：已采纳（部分取代 [ADR-选模式就换preset](./20260928-选模式就换preset.md) 的**适用范围**：机制照旧，本部署不再走它）

背景：模式原本声明的 `preset` 有两层意思——「这个模式挂哪份行清单」与「选这个模式时把 preset 切过去」。第二层让模式与
preset 强绑：会话一旦挂着官方 preset（用户在 roster 里选的），切模式就会把 preset 拽回 `mode-switch`，**覆盖用户对
行清单的选择**；模式本身其实不需要这份绑定——`allowTools` 收口、persona、三个开关都是会话级的，不认 preset。

实测（真装配：`preset: ""` + 会话挂官方 `standard`）确认了边界：persona 注册在 agent scope，preset 是它的**父**层
（`standingMountFor`：agent key 的父是 preset key），所以我们的 persona 遮蔽上游那份；`allowTools` 收口在装配期
过滤工具与 `tool:<名字>` section、执行层加 guard，与 preset 无关；`runtimeContext: false` 用
`systemPrompt.suppressRuntimeContext()`，按 scope 链判「有没有抑制器」，也成立。

原本唯一不成立的是 `instructions: false`：那时它只关**我们通道**这一侧，而官方 `standard` / `ptc` / `cordis` 自带
上游 `agent-instructions` 行（在 `agent/pre-step` 里自行 append，不经通道）——这正是 ADR-选模式就换preset 当初换
preset 的理由。现在这一条也收住了：官方那两条注入面（`agent-instructions` 与 `skill-catalog`）由收口在
`agent/pre-step` 上按 `instructions` / `skills` 丢掉，代价是官方每步仍重算一次要送的内容（结果被丢掉），见
[设计 抑制官方注入面](../designs/20260929-抑制官方注入面.md)。

**决定**

`config.modes.<id>.preset` 保留在 schema 里但**本部署不再声明它**：两个模式都不写 preset（行 config 里没有这个键，
schema 归一化成空串），`mode-sources.ts` 的 `ModeSource.preset` 变成可选。行清单的来源是会话挂着的 shipped preset
——registry 的 `default` 由官方 web-app 给（`standard`），本部署不再自建、也不再覆盖它（
[ADR-不再持有行清单](../../../../bundles/session-mode-profile/.agents/adrs/20260929-不再持有行清单.md)，那份自建的
`mode-switch` 与它的行数据已删除）。

**考虑过的选项**

- **把 upstream 注入面留在会话级收口之外**（换 preset 或让 preset 的行清单替我们关）：那会覆盖用户在官方 roster
  里选的行清单，而且"按模式开关"不是 preset 的行清单能表达的东西。**改走**：在 `agent/pre-step` 外层（`prepend`）
  丢弃上游注入的消息——见 [设计 抑制官方注入面](../designs/20260929-抑制官方注入面.md)。
- **只绑 `chat`、`coding` 不绑**：绑定是"这个模式要用哪套行"的声明，两个模式的差异本来就不用行清单表达（共享一份
  是刻意的），只绑一个只会让 chip 的行为在两者之间不一致。
- **连自己那份 preset 一起删掉**（行清单全交官方 shipped preset）：汉化 guidance、plan-mode 中文契约、subagent
  换实现、各工具行的 `config` 调参、先读后改豁免全随行丢失；host 平面又补不了（官方已把这些行 `disabled`，且
  `validatePresetPlaneSeparation` 校验一行只属于一个平面）。

**后果**

- 选模式**不换 preset**：`SessionModes.select` 里那段换 preset 的代码只在模式声明了 preset 时才走（本部署不再走到，
  但配置层可以给某个模式写回去）。官方 roster 选的那份 preset 不再被 chip 覆盖。
- 代价照实：官方那两行每步仍会重读 `AGENTS.md`、重算要送的消息（我们只是把结果丢掉），`tool-guidance` 的常驻正文
  也读不到模式开关（它按"常驻就是常驻"定义自己）。模式描述与 README 按这个口径写。
- 行清单里没有的工具照旧"收口时自动跳过"：`chat` 的三件在官方 `standard` / `ptc` / `cordis` 上都齐（那三份都有
  `tool-web` 与 `tool-ask-user`），在官方 `minimal` 上一件都不剩。
- 子代理的中文回报指引**不限 preset**：装配里不传 `localizedReturnGuidancePresets`（不配名单 = 官方四个 shipped
  preset 与还没绑 preset 的会话都用我们的中文文案），判据是 `patch.spec.ts` 里那一行没有 `config`；要按 preset 或按
  模式收窄得改 `@morlay/dsh-subagent` 那一侧，这次不动。
- 判据：`preset-plane.spec.ts`（模式不绑 preset 时切模式一次 `recompose` 都不发生 + 官方 `standard` 会话里切 `chat`
  仍收成三件、官方两条注入面成对（chat 都不进 / coding 都在）+ 真 `fs-observation-policy` 行上成对判 policy 拦截）、`session-mode.spec.ts`
  （空 `preset` 不碰 registry）、`patch.spec.ts`（渲染出的两个模式都不带 `preset`、装配里不再有 agent preset 行）。
