# 选模式就换 preset

状态：已采纳（2026-09-28）。

背景：行清单归官方 preset，模式只回答"这些行怎么被用"（[ADR-模式是preset的会话级扩展](./20260928-模式是preset的会话级扩展.md)）。
新会话挂的是 registry 的默认 preset（`standard`），而模式 chip 走 `POST /session-mode` → `SessionModes.select`，
先前只写 `session-mode/selected` 并重装 persona 与工具收口——preset realm 仍留在 `standard`。于是声明挂
`minimal` 的「对话模式」会话里依旧装配着 `standard` 的行：上游 `agent-instructions` 那类注入在 preset 那一侧、
不经通道，`chat` 的 `instructions: false` 收不到它，模型照样看到 `<system-reminder>` 形态的工作区指令。

**决定**

`SessionModes.select` 在落 `session-mode/selected` 之前，先把官方 preset 切到这个模式声明的 `preset`
（`ctx.get("agentPresets")` 的 `select`，空白窗口判据由它自己把关）；模式没声明 `preset`、或 registry 没装时
跳过这一步，只落会话事实。

**考虑过的选项**

- 在装配层收口 preset 内那类注入：它不是 section、也不经过通道（上游自己在 `agent/pre-step` 里 append 消息），
  我们的层没有可收的地方。
- 让 `chat` 不声明 `preset`、靠 registry 的默认给行：默认是 `standard`，工具被收口砍到三件，但 preset 内的
  注入与行照旧进来。
- 把行清单搬回 host 平面：ADR-模式是preset的会话级扩展 已经否掉（与官方"一行只属于一个平面"的校验对抗）。

**后果**

- 模式与 preset 在装配上一致：切到 `chat` 会卸下旧 preset 的行（含上游 `agent-instructions`）、装上 `minimal`
  的行；反向同理。
- 换 preset 靠官方 `recompose`（空白会话才允许），官方 `agent-preset/selected` 事件经既有监听把模式落成会话
  事实——同一个值不写第二条。
- headless 部署（没装 registry）退化成"只落会话事实"，preset 由部署自己决定。
- 判据：`session-mode.spec.ts`（切了、只写一条事实、空 `preset` 不切、没 registry 不炸）与
  `context/dsh-context-assembler` 的 `preset-plane.spec.ts`（真 registry：选 `chat` 之后上游那条工作区指令不再注入）。
