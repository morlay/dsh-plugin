# 选模式就换 preset

状态：已采纳（机制保留；**本部署不走它**——三个模式的 `presetsOnly` 都留空 = 不限制，见
[ADR-模式不绑定preset](./20260929-模式不绑定preset.md)）

背景：行清单归 agent preset，模式只回答"这些行怎么被用"
（[ADR-模式是preset的会话级扩展](./20260928-模式是preset的会话级扩展.md)）。模式 chip 走 `POST /session-mode` →
`SessionModes.select`，而注入面分两侧：preset 自带的上游注入（`agent-instructions` 那类）不走通道，收口要按
`agent/pre-step` 外层丢掉它们（[设计 抑制官方注入面](../designs/20260929-抑制官方注入面.md)）。名单写 `minimal` 的会话
若留在别的 preset 上，模型照样看到 `<system-reminder>` 形态的工作区指令。

**决定**

`SessionModes.select` 在落 `session-mode/selected` 之前，先按模式的白名单（`config.modes.<id>.presetsOnly`）把会话的
preset 落到位：当前那份不在名单里就换成名单第一个，已经在名单里就不动（`ctx.get("agentPresets")` 的 `select`，空白
窗口判据由它自己把关）；名单留空、或 registry 没装时跳过这一步，只落会话事实。

**考虑过的选项**

- 在装配层收口 preset 内那类注入：它不是 section、也不经过通道（上游自己在 `agent/pre-step` 里 append 消息），
  我们的层没有可收的地方。**已改走**：在那条 waterfall 外层按模式开关丢掉它。
- 让 `chat` 不写名单、靠 registry 的默认给行：默认 preset 的工具被收口砍到三件，但 preset 内的注入与行照旧进来。
- 把行清单搬回 host 平面：ADR-模式是preset的会话级扩展 已经否掉（与官方"一行只属于一个平面"的校验对抗）。

**后果**

- 模式与 preset 在装配上一致：落点与当前不同时会卸下旧的行（含上游 `agent-instructions`）、装上新的。
- 换 preset 靠官方 `recompose`（空白会话才允许），官方 `agent-preset/selected` 事件经既有监听把模式落成会话
  事实——同一个值不写第二条。
- headless 部署（没装 registry）退化成"只落会话事实"，preset 由部署自己决定。
- 判据：本包 `src/__tests__/session-mode.spec.ts`（当前那份不在名单里就落第一个、名单内的选择不换、名单留空不切、
  没 registry 不炸）与 `src/__tests__/preset-plane.spec.ts`（真 registry：模式留空名单时切模式一次 `recompose` 都不发生，
  而 `chat` 的上游工作区指令照样不注入——那条面由收口在 `agent/pre-step` 上丢，不是靠换 preset 掉行）。
