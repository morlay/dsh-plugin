# 选模式就换 preset

状态：已采纳

背景：行清单归 agent preset，模式只回答"这些行怎么被用"
（[ADR-模式是preset的会话级扩展](./20260928-模式是preset的会话级扩展.md)）。模式 chip 走 `POST /session-mode` →
`SessionModes.select`，而注入面分两侧：preset 自带的上游注入（`agent-instructions` 那类）不走通道，`chat` 的
`instructions: false` 收不到它。声明挂 `minimal` 的会话若留在别的 preset 上，模型照样看到
`<system-reminder>` 形态的工作区指令。本部署两个模式共享 `mode-switch`（registry 的 `default` 也指向它），
所以切 chip 常走到"目标与当前相同"的空转分支。

**决定**

`SessionModes.select` 在落 `session-mode/selected` 之前，先把 preset 切到这个模式声明的 `preset`
（`ctx.get("agentPresets")` 的 `select`，空白窗口判据由它自己把关）；模式没声明 `preset`、或 registry 没装时
跳过这一步，只落会话事实。

**考虑过的选项**

- 在装配层收口 preset 内那类注入：它不是 section、也不经过通道（上游自己在 `agent/pre-step` 里 append 消息），
  我们的层没有可收的地方。
- 让 `chat` 不声明 `preset`、靠 registry 的默认给行：默认 preset 的工具被收口砍到三件，但 preset 内的注入与行
  照旧进来。
- 把行清单搬回 host 平面：ADR-模式是preset的会话级扩展 已经否掉（与官方"一行只属于一个平面"的校验对抗）。

**后果**

- 模式与 preset 在装配上一致：目标那份 preset 与当前不同时会卸下旧的行（含上游 `agent-instructions`）、装上新的；
  本部署两个模式共享一份，所以通常不换。
- 换 preset 靠官方 `recompose`（空白会话才允许），官方 `agent-preset/selected` 事件经既有监听把模式落成会话
  事实——同一个值不写第二条。
- headless 部署（没装 registry）退化成"只落会话事实"，preset 由部署自己决定。
- 判据：本包 `src/__tests__/session-mode.spec.ts`（切了、只写一条事实、空 `preset` 不切、没 registry 不炸）与
  `src/__tests__/preset-plane.spec.ts`（真 registry：选 `chat` 之后上游那条工作区指令不再注入）。
