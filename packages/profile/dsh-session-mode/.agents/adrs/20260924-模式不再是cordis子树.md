# 模式不再是 Cordis 子树，官方 agent preset 退出部署

状态：已采纳（2026-09-24）。取代 [ADR-20260922-preset改用上游声明式行](./20260922-preset改用上游声明式行.md)、
[ADR-20260922-通道与注入行按模式isolate装配](./20260922-通道与注入行按模式isolate装配.md) 与
[设计 预设生成与装配](../designs/20260917-预设生成与装配.md) 描述的整套形态。

背景：模式曾是一行 `@deepseek-ai/dsh-agent-preset`，`config.plugins` 里装 `persona`、
[`@morlay/dsh-context-assembler/scope`](../../../../context/dsh-context-assembler/README.md) 与
`relax-intent`，靠 preset 的 scope 子树对会话生效。为此部署里必须常驻官方 registry
（`@deepseek-ai/dsh-agent-preset-registry`：声明式行、每个 revision 一棵 Loader 子树、`isolate` realm、
`bindScopeParent` 的会话绑定、客户端三个面）。而我们的模式其实只用得到其中两件事：**一段提示词**与
**一组能力开关**——子树是它的装载方式，不是它要表达的东西。

## 决定

四件事：

1. **禁用官方那一整套**：`agent-preset-registry`、四个 shipped preset 行
   （`preset-standard` / `preset-ptc` / `preset-minimal` / `preset-cordis`）与客户端
   `ui-agent-preset`（选择器 / 头部标签 / 设置页 roster）。这些是装配层的动作，归
   [`@morlay/dsh-profile`](../../../dsh-profile/README.md) 的 patch。
2. **模式是一份数据**：`session-mode` 行的 `config.modes`（`name` / `description` / `persona` /
   `allowTools` / `instructions` / `runtimeContext`，形状与校验在 `src/modes.ts`）。自定义就是改这份 config，
   不需要任何插件行。
3. **应用落在会话自己的作用域上**，分两处：
   - persona：装配前把 `deployment:persona-prefix` / `-suffix` 注册到**该 agent 的 scope**
     （上游给子 agent 装 persona 走的就是这条路）；
   - 工具与注入开关：推给 `ctx.sessionToolScope`（`@morlay/dsh-context-assembler/scope` 出口，行 id
     `context-assembler-scope`）：装配期投影、执行层 guard、`setInstructions`、`suppressRuntimeContext`。
4. **会话当前模式进日志**：一条 session 事件（`session-mode/selected`）+ 一条投影（`sessionMode`），
   切换仍只允许在空白窗口（判据用上游的 `turnBoundary` 投影）。

顺带一个简化：`relax-intent`（按模式抵消上游「先读后改」waterfall 的那一行）退出——本部署直接禁用
`fs-observation-policy`。它是部署级取舍，之前只能按模式抵消是因为要避开官方 preset；官方 preset 退出后，
禁用行就是最直接的做法。

## 考虑过的选项

- **保留官方 registry，只换模式定义与 UI**：代价全留着（每 revision 一棵子树、`isolate`、两个客户
  端面），换来的只是"不用自己记会话与模式的关系"——而那条关系本来就只有一行投影。
- **自己实现一棵子树**（复刻 registry 的 scope 绑定）：把官方的机制照抄一遍，复杂度与原样不动相同。
- **收口出口读 `ctx.sessionModes`**（拉模型）：`dsh-context-assembler` 的类型面就要引用
  `dsh-session-mode`，而后者已经引用它（`scopeRow()`）——反向依赖成环即是错（见
  [规范 how-to-write](../../../../../.agents/standards/how-to-write.md)）。推模型让方向保持单向。
- **把收口并进 `dsh-session-mode`**：少一个出口，但"工具怎么收口"是上下文注入自己的事；那一行留在
  `context-assembler`，模式只是把定义递过去。

## 后果

- `ctx.agentPresets` 在部署里**不存在**：会话创建走 `composeAgent` 的无 preset 分支（不写
  `header.agentPreset`），子 agent 不再继承父的 preset（我们的工具行在 host 平面，不依赖它）。
- 模式之间不再各有自己的服务实例/子树：两个模式共享同一套 host 平面（工具行、通道、压缩）。
- 设置页少了「Agent presets」那一块；改模式清单要动装配配置（`session-mode` 行的 `config`）。
- 切换模式的语义与上游一致（只有空白会话能换），但记录的键换了名字：旧会话里记的
  `agentPreset` 不再被读，恢复时按 `sessionMode`（没有就回落到默认模式）。
- `session-mode/selected` 是**上游不认识的**事件类型：它靠 `ignorable` 信封过持久化校验，信封由
  [`@morlay/session-rdb`](../../../../session/session-rdb/README.md) 的 `OWN_EVENT_TYPES` 补（落库前补、读回时
  兜底）。本包新增事件类型要同步登记，见
  [设计 自造事件类型的信封](../../../../session/session-rdb/.agents/designs/20260924-自造事件类型的信封.md)。
- 判据落在：`patch.spec.ts`（两行与源数据同形）、`session-mode.spec.ts`（persona / 收口 / 投影 / 切换判据）、
  `context-assembler-scope.spec.ts`（按会话收口与换一份）、真装配探针（见[规范](../standards/how-to-verify.md)）。
