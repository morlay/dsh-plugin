# 模式是 preset 的会话级扩展，官方 preset 留在装配里

状态：已采纳（2026-09-28）。

背景：会话级的选择有过两套机制——官方 agent preset（一行 `@deepseek-ai/dsh-agent-preset` 声明子插件清单，
`agent-preset-registry` 持有每代际的 scope 与 Loader 树，agent 把自己的 scope 链到选定代际）与我们的
`session-mode`（一份数据 + 按会话应用）。此前关掉官方整套、由我们把功能行装到 host 平面，代价是行清单的
所有权落在我们这边：与官方 base 同 id 的行靠"后者胜"静默接管，与官方"一行只属于一个平面"的校验
（`vendor/deepseek-harness/scripts/verify-cordis-config.ts:121-137`）对抗。

## 决定

1. **官方 preset 整套留在装配里**：`agent-preset-registry`、四个 shipped preset 行与 `ui-agent-preset` 都由
   上游层装配，`@morlay/dsh-profile` 不再按 id 禁它们。
2. **模式 = preset 的会话级扩展**：`config.modes.<id>.preset` 声明这个模式挂哪份 preset，扩展只有四项——
   persona、`allowTools` 收口、instruction / 动态快照开关、`defaultModel`。行清单（工具 / 命令 / 压缩 / 委派…）
   由那份 preset 的 `config.plugins` 提供。**几个模式可以共享同一份 preset**（装配期不再要求一对一）：本部署
   两个模式都挂我们自建的那份 `mode-switch`，差异全由这四项表达；理由与代价见
   [ADR-自己注册preset](../../../../bundles/session-mode-profile/.agents/adrs/20260929-自己注册preset.md)。
3. **选择面归我们**：`conversation.hero.agentPreset` 这类槽位是**单注册**的
   （`vendor/deepseek-harness/packages/client/ui-slots/src/index.ts:1218`，第二个注册直接抛错），所以官方
   `ui-agent-preset` 行在装配层停掉；模式的选择由本包的 chip 与 `GET/POST /session-mode` 提供，
   落成会话事实。`modeForPreset` 只在 preset → 模式的映射**唯一**时回答（共享时返回 `undefined`：模式由会话事实
   决定，预设选了什么不改变这个会话是哪个模式）。
4. **`sessionMode` 事件与投影保留**：模式是会话级扩展的事实，恢复、子代理继承与服务端读取都读它；官方的
   `agentPreset` 说的是"挂了哪套行"，两者不是同一个事实。
5. **注入通道留在 host 平面、不隔离**（`@morlay/dsh-context-assembler`），工具说明也只在 host 平面装一行
   （`@morlay/dsh-agent-toolkit` 的 `guidance`）。

## 考虑过的选项

- **把通道装进 preset realm**：realm 内的服务 host 侧读不到
  （`vendor/deepseek-harness/packages/preset/agent-preset-registry/src/mount.ts:129-166`），工具说明与会话收口
  这两个 consumer 都得跟着搬进 realm，收益只是"形态更官方"。
- **覆盖 shipped preset 的 `config.plugins`**：官方明说整段替换、不合并后续内置变更
  （`vendor/deepseek-harness/packages/bundle/web-app/presets/cordis.patch.yml:1-3`），等于把官方清单复制进本仓库，
  上游每次升级都要人工对齐。
- **让官方 roster 当选择面**：它的 seat 受「代码工作工具」偏好门控（关闭时不渲染），而那个偏好落不到桌面形态的
  settings（持久化降级成 memory），入口等于没有；文案也是官方的。

## 后果

- 工具行由 preset 提供：`allowTools` 里那份 preset 没有的工具自动跳过。本部署的行清单自己声明
  （`preset-mode-switch`），所以 `chat` 的联网三件真的在——复用官方 `minimal` 时那三件一个都不在。
- 上游行升版要人工对齐 `TOOLKIT_PRESET_ROWS`（包名 / 行 id / `config`）：这是自己持有行清单的代价，
  由 bundle 的 `patch.spec.ts` 逐行比对与真装配探针兜住。
- 要加/减一行工具，动的是 preset 的 `config.plugins`（官方机制内的扩展），host 平面不再有第二份。
- 官方 roster 的三个客户端面回来（选择器 / 头部标签 / 设置页 roster）；我们的 client 半只剩本行配置页的
  字段文案与候选源。
- 判据：`patch.spec.ts`（preset 声明与行清单同形、两个模式都挂它、注入面不在其中）、`session-mode.spec.ts`
  （persona / 收口 / 投影 / 继承 / 共享 preset 的合法性与幂等）、`preset-plane.spec.ts`（真装配：chat 三件可用、
  注入 0 条、一份技能目录、官方 preset 会话不受影响、切模式不重挂）与真 profile 探针
  （见[规范](../standards/how-to-verify.md)）。
