# 模式是 preset 的会话级扩展，官方 preset 留在装配里

状态：已采纳

背景：行清单（工具 / 命令 / 压缩 / 委派 / skill 发现）只有一处能声明——agent preset 的 `config.plugins`。
官方 agent preset 与我们的 `session-mode` 因此各管一半：preset 说"这个 agent 有哪些行"，模式回答"这个会话怎么用
它们"。行清单若由我们装到 host 平面，会与官方 base 同 id 的行靠"后者胜"静默接管，与官方"一行只属于一个平面"的
校验（`vendor/deepseek-harness/scripts/verify-cordis-config.ts:121-137`）对抗。

**决定**

1. **官方 preset 整套留在装配里**：`agent-preset-registry`、四个 shipped preset 行与 `ui-agent-preset` 都由
   上游层装配，本部署不按 id 禁它们。
2. **模式 = preset 的会话级扩展**：`config.modes.<id>.presetsOnly` 是**可选**白名单（允许挂哪些 preset），扩展是那几项会话级
   的东西——persona、工具名单（`allowTools` / 禁用的 `denyTools`）、上游 policy 名单（`allowPolicies` /
   `denyPolicies`）、instruction / 技能目录 / 动态快照三个开关、`defaultModel`。行清单（工具 / 命令 / 压缩 / 委派…）
   由会话挂着的那份 preset 的 `config.plugins` 提供。名单可以共享（装配期不再要求一对一），也可以留空——**本部署三个模式
   都留空**（不限制）：行清单由会话挂的那份提供，新会话的默认那份由官方 registry 的 `default` 指过来（shipped
   `standard`），理由与代价见
   [ADR-模式不绑定preset](./20260929-模式不绑定preset.md)：本部署曾经自建过一份 preset 给两个模式当默认行清单，
   那份与它引用的行数据都已删除
   （[ADR-不再持有行清单](../../../../bundles/session-mode-profile/.agents/adrs/20260929-不再持有行清单.md)），
   行清单现在完全归 shipped preset。
3. **选择面两套并存**：官方 roster 占 `conversation.hero.agentPreset`（**单注册**：
   `vendor/deepseek-harness/packages/client/ui-slots/src/index.ts:1218`），管"挂哪套行"；本包的 chip 走 list 槽位
   `conversation.input.left` 与 `GET/POST /session-mode`，管"会话级扩展"，落成会话事实。`modeForPreset` 只在
   preset → 模式的映射**唯一**时回答（共享时返回 `undefined`：模式由会话事实决定，预设选了什么不改变这个会话是
   哪个模式）。
4. **`sessionMode` 事件与投影保留**：模式是会话级扩展的事实，恢复、子代理继承与服务端读取都读它；官方的
   `agentPreset` 说的是"挂了哪套行"，两者不是同一个事实。
5. **注入通道留在 host 平面、不隔离**（`@morlay/dsh-context-assembler`），工具说明也只在 host 平面装一行
   （`@morlay/dsh-tool-guidance` 的包根）。

**考虑过的选项**

- **把通道装进 preset realm**：realm 内的服务 host 侧读不到
  （`vendor/deepseek-harness/packages/preset/agent-preset-registry/src/mount.ts:129-166`），工具说明与会话收口
  这两个 consumer 都得跟着搬进 realm，收益只是"形态更官方"。
- **覆盖 shipped preset 的 `config.plugins`**：官方明说整段替换、不合并后续内置变更
  （`vendor/deepseek-harness/packages/bundle/web-app/presets/cordis.patch.yml:1-3`），等于把官方清单复制进本仓库，
  上游每次升级都要人工对齐。
- **把模式的选择面也交给官方 roster**：它那个 seat 是 preset 的选择面（受「代码工作工具」偏好门控），文案也是
  官方的；模式是另一个事实，借它的 seat 表达不了。**否**：我们自己的 chip 走另一个槽位。

**后果**

- 工具行由 preset 提供：`allowTools` 里那份 preset 没有的工具自动跳过。**默认那份是 shipped `standard`**，所以
  `chat` 的联网三件真的在——`minimal` 那类缺行清单里那三件一个都不在。
- ~~上游行升版要人工对齐 `TOOLKIT_PRESET_ROWS`~~：这条债随自建 preset 的删除一起消失（见
  [ADR-不再持有行清单](../../../../bundles/session-mode-profile/.agents/adrs/20260929-不再持有行清单.md)）。
- 要加/减一行工具，动的是 preset 的 `config.plugins`（官方机制内的扩展），host 平面不再有第二份。
- 官方 roster 的三个客户端面都在（选择器 / 头部标签 / 设置页 roster）；本包 client 半是模式 chip、本行配置页的
  字段文案与候选源。
- 判据：`patch.spec.ts`（装配里不再有 agent preset 行、行数据类行一件都不在、两个模式都不声明 `preset`、注入面不在其中）、
  `session-mode.spec.ts`（persona / 收口 / 投影 / 继承 / 空 `preset` 的合法性与幂等）、`preset-plane.spec.ts`
  （真装配：chat 三件可用、注入 0 条、一份技能目录、官方 preset 会话照旧、切模式不换 preset）——三层口径见
  [规范](../standards/how-to-verify.md)。
