# 通道与注入行按模式 isolate 装配（从 host 层搬进 preset）

状态：已采纳（2026-09-22）

背景：本次修的是一个**真装配才看得见的**污染：`context-assembler` 住 host 层时，它的注册表（rules /
auto skill / 装配改写）**不按 scope 分层**，而 host 行对所有 preset 生效——于是我们的注入漏进了官方
`standard` / `ptc` / `cordis` 的会话：工作区指令、skill 目录、工具用法分组、引用材料全都在，`assembler:rules`
那段中文说明也在，连 `replace` 的两段中文文案都把官方英文原文换掉了。

为什么会漏成这样：`0bfc793`（恢复官方四个 shipped preset）之前，那四个官方 preset 行是被我们禁用的，
选择器里只有我们的模式——「通道住 host、一行覆盖全部 preset」当时无害。官方 preset 回来之后，这条装配
前提（只有一个模式会用到通道）已经不成立，而静态断言只比对行清单，看不见会话级的事实。

**决定**

1. `context-assembler` 与它的**全部消费者**（`context-agent-instructions` / `context-skill-catalog` /
   toolkit 的 `toolkit-guidance` / chat 的 `context-scope`）同住一个
   `group("context-assembler-channel", …, { isolate: { contextAssembler: true } })`，由每个模式自己的清单声明：
   `coding` 与 `chat` 各一份。（当时的第六个成员 `context-reference` 后来独立成
   [`@morlay/dsh-reference`](../../../../../.agents/adrs/20260923-引用展开拆成独立包并按profile装配.md)——它不依赖通道，
   因此不在这个组里。）
2. 模式注册从 `@morlay/dsh-profile` 拆成独立包 `@morlay/dsh-agent-preset`（连同生成器与设计/ADR/规范）；
   `@morlay/dsh-profile` 收缩为 host 层的部署配置（llm route / 搜索后端 / 沙箱）。
3. host 层同时撤掉几处"所有 preset 一起受影响"的动作，它们各自的替代见下：`agent-instructions` /
   `tool-skill` 的按 id 禁用（上游 web-app bundle 自己已设在 preset 平面）、`system-prompt` 的
   `includeHarnessIdentity` / `includeRuntimeContext` 覆盖、`office-to-pdf` 的禁用。

**考虑过的选项**

- **把通道留在 host，改成注册按 scope 记录**（`registerRule(ctx, …)` 之类）：能让"谁注册的只对谁的会话生效"，
  但要动通道的整个公开面（四个注册 API 加 ctx），并让"部署级一份"的策略（keep / suppress / replace）也跟着
  按 scope 分裂；改动面比 isolate 大，且 isolate 是上游为一等服务提供的那条路。
- **按 preset id 白名单收窄通道**：`contextAssembler` 记一份"生效的 preset id"，非白名单会话跳过全部动作。
  改动最小，但把 preset id 硬编码进一个通用通道里，新增模式要记得改它。
- **只让 `assembler:rules` 按需出现**（最小修补）：消掉误导性的中文说明，但 skill 目录、工作区指令、引用
  材料照旧漏——症状在规则块，问题在通道的全局注册表。
- **保留 host 层禁用 `fs-observation-policy`**：那是模式取舍（`coding` 不要先读后改），host 禁用会连官方
  preset 一起关掉；改成 `coding` 自带一行 `relax-intent` 抢在它的 waterfall 前（见设计文档）。

**后果**

- 官方 preset 的会话回到上游原味：section 不降级、不 suppress、不中文替换，没有我们的任何 reminder。
  代价是**它们也不再享有我们的提示词改造**（工具说明降级、中文文案）——那本来就是部署偏好，按模式给才对。
- 通道实例按模式各一份（内存与装载成本 ×N）：换来模式之间零泄漏。判据固化成真装配探针
  `verify-preset-isolation.mts`（`just profile` 里跑）：root realm 读不到 `contextAssembler`，只有我们自己的
  preset mount 里有它。
- 一个模式里多一行、少一行注入行都得待在同一个 isolate 组里：落一个在组外，它的 `inject` 会永远等不到服务
  （行停在 waiting，不报错）——`patch.spec.ts` 把"所有 `@morlay/dsh-context-assembler*` 行都在组内"钉住。
- `@morlay/dsh-profile` 变薄之后，"我们的模式装了什么"与"部署级配置是什么"分属两个包：改模式的行清单只动
  `dsh-agent-preset`，改 llm route / 搜索后端 / 沙箱只动 `dsh-preset`。

（后续：2026-09-23 起通道那份清单的 home 移到了 `@morlay/dsh-context-assembler`，本 ADR 的结论不变——preset 仍把整组关进 `isolate`，见 [ADR profile 层三分](../../../../../.agents/adrs/20260923-profile层三分（配置初始化与提示词开关与能力清单）.md)。）
