# @morlay/dsh-tool-gating

把编码 Agent 的工具使用收成「基础组 + 按需启用」的 cordis 插件。**工具目录恒定**：全部工具 schema 始终在
请求里（因此档位变化永不触发重算）；档位决定两件事——**现在能调用哪些**（执行层拒绝未启用的组）与
**随任务追加哪一段中文用法提示**。

## 为什么

两个成本，各用一招：

| 成本                                                                                                                                                     | 办法                                                                   |
| -------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------- |
| 上游把每个工具的跨调用说明都塞进提示词（本部署实测占系统提示词 9200 字符里的约 7400，见 [dsh-prompt-reminder](../dsh-prompt-reminder/README.md)）        | **按组给**：遮蔽上游逐个工具的说明，改成一组一整段中文提示，随档位渲染 |
| 工具目录一变，该次请求整段重算（上游：_"A schema or composition change invalidates reuse from the first altered request token"_，而 tools 排在请求最前） | **目录恒定**：不再裁剪 schema，档位只改提示与执行判定                  |

## 行为

| 环节            | 做什么                                                                                         |
| --------------- | ---------------------------------------------------------------------------------------------- |
| `agent/created` | 从会话历史重建档位；遮蔽上游逐工具说明；用中文短描述覆盖工具定义；注册执行层 guard             |
| `system-prompt` | 注册能力目录与按组用法提示两个 section（随档位渲染，中文）                                     |
| `tools.guard`   | 未启用组的调用被拒，拒绝文案写明它属于哪一组、怎么解锁                                         |
| `enable_tools`  | 模型侧只增，一次可给多组                                                                       |
| `/tools`        | 用户侧切换：不带参数回到基础组，带组名即把档位设为这些组（可增可减），并落一条可重建的切换消息 |

- **目录恒定**：`tools` 参数逐字不变——启用前后完全一致，这就是缓存稳定的前提（有用例断言）。
- **短描述**：工具 schema 常驻，所以 `description` 换成一行中文（[`SHORT_TOOL_DESCRIPTIONS`](./src/groups.ts)）。
  改写发生在**装配投影**（`system-prompt/assemble` 的 `assembly.tools`），**不写注册表**——在 agent 作用域注册同名
  工具会同步触发 `tools/change`，与上游 `tool-subagent` 的 composition reconcile 互相回响（曾把 session 创建卡死）。
- **执行层拒绝**：归组但未启用的工具被拒并给出解锁路径；**未归组的工具一律放行**（`enable_tools`、host plane
  的机制工具、上游新增还没归组的工具——它们不是档位管理的对象，拒绝只会造成静默失效）。
- **模型只增、用户可切**：`enable_tools` 只做并集；`/tools` 是集合语义。

## 组

| key    | 中文名   | 工具                                                                                                                                                                                                                            |
| ------ | -------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `base` | 基础     | read / write / edit / glob / grep / bash（或 pwsh）/ ask_user_question / job_* / read_image / web_fetch / skill                                                                                                                 |
| `flow` | 流程     | todo_write / exit_plan_mode / goal 三件套 / present                                                                                                                                                                             |
| `web`  | 联网检索 | web_search                                                                                                                                                                                                                      |
| `team` | 协作编排 | 委派与编排：subagent / subagent_fork / list_subagent_models / spawn_teammate / workflow；队友协同：list_agents / send_message / wait_agent / interrupt_agent / team_task_*（按本部署实际装配渲染，见「与 Agent Teams 的关系」） |

组的唯一 home 是 [`src/groups.ts`](./src/groups.ts)：工具名、中文描述、按组提示、工具的短描述、
被忽略的上游说明清单都在那里。

## 提示词怎么给

| 内容                                           | 来源                                                                                                                                              |
| ---------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------- |
| 能力目录（**分批**）                           | `tool-gating:catalog` section：已启用的组给用途 + 成员工具，未启用的组只给 key、标题与一句话用途，随档位渲染                                      |
| 组用法提示（一组一段中文）                     | `tool-gating:guidance` section，只渲染当前档位里的组                                                                                              |
| 上游逐工具说明                                 | **遮蔽**（`IGNORED_SECTIONS`），不再进提示词                                                                                                      |
| 平台运维两段（harness 位置、Web GUI/HMR 约定） | **遮蔽**：讲 dev server 与本地 checkout 这类运维约定，和本部署的模型任务无关                                                                      |
| 文档路径两段（`@` 引用语义、输出链接规范）     | **保留但改中文**：注册层不归我们（前者在 agent 作用域），所以在装配投影里替换文本（`REPLACED_SECTION_TEXTS`）                                     |
| `plan:policy`（计划模式规则）                  | 保留：它是行为约束而不是工具用法说明，遮蔽会让计划模式静默失效                                                                                    |
| `team:policy`（Agent Teams 协作规则）          | **按档位改投影**：team 组启用时给中文版规则，未启用时不注入。它注册在 **agent 作用域**（遮蔽会抛 `already registered in this scope`），只能改投影 |

两个 section 都会被 [dsh-prompt-reminder](../dsh-prompt-reminder/README.md) 降级成紧随用户消息的
`<system-reminder>`，所以它们的变化走"追加"而不是"改写前缀"。

## 与 Agent Teams 的关系

本仓**不装配** Agent Teams——它是官方实验性 bundle，装不装由 profile 的 `bundles` 开关决定：

| 形态                                                           | 委派工具                                              | 队友协同                                                                              |
| -------------------------------------------------------------- | ----------------------------------------------------- | ------------------------------------------------------------------------------------- |
| 不装（默认）                                                   | `subagent` / `subagent_fork` / `list_subagent_models` | host 侧 `tool-subagent-control` 的 `send_message` / `list_agents` / `interrupt_agent` |
| 装 `agent-team-profile`（要界面再加 `agent-team-web-profile`） | `spawn_teammate`                                      | `list_agents` / `send_message` / `wait_agent` / `interrupt_agent` / `team_task_*`     |

`team` 组同时容纳两套工具名，**渲染时按实际存在的过滤**：没装的工具不进能力目录、也不进组用法提示
（`guidanceByTool` 的句子按存在拼——装哪套就讲哪套）；整组都没装时该组从目录里消失。门控判定按组进行，
所以两种形态下行为一致（`/tools team`、协作模式的起始档位都一样）。

## 模式

由 [dsh-preset](../dsh-preset/README.md) 的生成器从上游 `standard` 生成两个 preset，差别只在起始档位：

| preset 产物     | 展示名   | 起始档位                |
| --------------- | -------- | ----------------------- |
| `standard`      | 标准模式 | 基础组（默认）          |
| `collaboration` | 协作模式 | 基础 + 协作编排（team） |

## 配置

| 字段      | 默认 | 含义                                                                     |
| --------- | ---- | ------------------------------------------------------------------------ |
| `initial` | `[]` | 起始档位：基础组之外默认启用的组（模式 preset 在这里给出自己的默认能力） |

`initial` 出现未知组名时装配立刻失败（不静默跳过）。

## 前缀缓存

判定与实测数据见 [ADR-工具schema恒定而说明动态化](./.agents/adrs/20260920-工具schema恒定而说明动态化.md)
（schema 扰动 = 命中率 94% → 0~3.2%；prompt 前部的文本改动代价更彻底，所以说明走 append 通道）。

| 变化                       | 后果                                                             |
| -------------------------- | ---------------------------------------------------------------- |
| **档位切换**               | **不破坏缓存**：`tools` 参数不变，只有 append 通道的说明消息变化 |
| 上游工具集变化（部署升级） | 破坏一次（schema 变了），与档位无关                              |
| 会话内容本身               | 正常追加，前缀复用                                               |

代价换成**常驻开销**：全部工具的 schema 一直在请求里（用一行中文短描述压缩），
换掉的是"每次切换一次全量 prefill"。长会话里这笔账明显划算；短会话里差别不大。

## 已知限制

- **全量 schema 常驻**：省不了工具定义本身的开销，只是让它稳定。想把开销也压下来得改上游工具的描述与参数。
- **模型看得见未启用的工具**：约束靠 guard（拒绝 + 解锁提示）与能力目录的标注，模型偶尔会碰壁一次。
- **短描述由本仓库维护**：上游改工具职责时要跟着改 `SHORT_TOOL_DESCRIPTIONS`（上游只改参数不需要动）。
- **子 agent 从起始档位起步**：不继承父档；`team` 组的派发能力在子代理里本就不该用。
