# 没有客户端挂载时，人类提问会挂起（不失败、不超时）

状态：已知未销账——`ask_user_question` 会把调用挂在 `pendingRemoteEvents` 上，直到有客户端连上
范围：`packages/agent/dsh-permission/src/server/tool-ask-user.service.ts`（工具行）、装配面的 headless 清单；
上游行为是 `@deepseek-ai/dsh-api-remotes` + `dsh-api-gateway` 的转发事件源
非目标：上游提问语义（`user-questions/request` 的 waterfall）；浏览器卡片（上游 `ui-user-questions`）
关联：[出口边界与浏览器半](../designs/20261113-出口边界与浏览器半.md)

## 一、事实

答案不在工具里：`ask` 走 `user-questions/request` 那条 Agent-scoped waterfall，**应答者是事件监听者**——
浏览器只是其中一种来源（`ui-user-questions/client` 的 `remote.$on`，由 `api-remotes` 在宿主侧桥接）。
在本进程里直接 `ctx.on('user-questions/request', …)` 同样有效，与浏览器没有区别。

所以结果只取决于**这个 agent 的 scope 里有没有应答者**，三种拓扑各不一样：

| 拓扑                               | `ask` 的结果                                                                                  |
| ---------------------------------- | --------------------------------------------------------------------------------------------- |
| 有客户端（`$events` 流开着）       | 正常往返，卡片作答                                                                            |
| 装了转发事件源、暂时没有客户端     | 请求存进 gateway 的 `pendingRemoteEvents`，**挂起**；客户端连上时 `openRemoteEvents` 回放补发 |
| 没装转发事件源、也没有程序化应答者 | 立刻以 `NO_PROVIDER` 失败（上游 `noAnswerer` 兜底）                                           |

本部署的装配面（`provideApiGateway()` 里有 `RemoteEventsSource`）属于第二种：**没有页面挂载时调用会一直挂着**，
既不会失败，也不会超时。`ask-user.spec.ts` 用真栈分别锁住第一/第三种拓扑。

## 二、为什么不顺手修

把工具行从 headless 清单里去掉会让 GUI 会话同样拿不到它：可见性只能按「这次会话有没有应答者」判，
而工具域没有「有没有前端」的服务可注入。
反过来给工具行配 `timed` 模式也不对：超时只把阻塞变成 `pending` 结果帧，人不在，答案仍然不会来。

## 三、销账形态

给 headless 清单挂一个程序化应答者（例如转发到外部客户端、或按策略直接作答），它与浏览器等价；
或按「有没有活动客户端」决定这条行装不装（`without` 掉它）。两条路都要保留 `ask-user.spec.ts` 的判据：
「挂上应答者 → 结构化答案成为模型文本」这条继续守 GUI 与 headless 两条链路。
