# 出口边界与浏览器半（`dsh-permission`）

状态：已实现——包根只出宿主面；两个 remote descriptor 在 `./endpoint`，浏览器半从那里取
范围：本包四个出口各自能出什么、浏览器半从哪取远端身份、判据怎么跑
非目标：远端 wire 形状本身（归 `./endpoint` 的契约类，见 [包内子域拆分与注册抽象](../../../.agents/designs/20261028-包内子域拆分与注册抽象.md)）；批准/提问的界面行（住 `dsh-conversation`）
关联：设计 20261028-包内子域拆分与注册抽象（面矩阵）· [dsh-conversation 的对话域边界](../../../dsh-conversation/.agents/designs/20261109-对话域边界与交付物归属.md)

## 一、决定

| #   | 议题                             | 决定                                                                                                                     | 一句话理由                                                                                                                                                                                                       |
| --- | -------------------------------- | ------------------------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | 两份 remote descriptor 放哪      | 放 `./endpoint`（`PERMISSION_PRESETS_REMOTE` / `USER_QUESTIONS_REMOTE`），**不放包根**、也不新开 `./ui`                  | descriptor 是**两端共用**的 wire 身份：宿主注册与浏览器 `$mount` 读同一份；兄弟域 `@morlay/dsh-setting/endpoint` 的 `SETTINGS_REMOTE` 就是这条先例，而 `ui-permission.service.ts` 本来就同时从那个 endpoint 取值 |
| 2   | 为什么不单开 `./ui`              | 本包**没有**浏览器实现行（批准/提问的界面行在 `dsh-conversation`）；为一个常量开一个"浏览器半"出口，名字会指向不存在的面 | 出口名要说清谁消费；没有消费方的面就是空壳（同上设计的决定 1）                                                                                                                                                   |
| 3   | 包根出什么                       | 只出宿主面：三个契约 + 三个默认实现 + `./contract` 的转出                                                                | 包根带宿主 service，浏览器半引一次就把它们带进前端 bundle（`node:*` 与上游宿主行随后被拉进来）                                                                                                                   |
| 4   | `./endpoint` 的 client-safe 约束 | 只允许**纯值常量**与 `import type`（上游类型走 `/types` 子路径）；禁 `@deepseek-ai/*` 包根的值导入                       | 值导入（哪怕只用在类型位置）会给打包图收一条运行时边（`permissionPresets/catalog` 的 `PermissionCatalog` 就是这样漏的）                                                                                          |

## 二、出口矩阵（现状）

| 出口         | 能出什么                                                                     | 消费侧                                                 | client-safe            |
| ------------ | ---------------------------------------------------------------------------- | ------------------------------------------------------ | ---------------------- |
| `.`（包根）  | `Permission` / `Approval` / `UserQuestions` 契约与默认实现、`PermissionMode` | 宿主装配（`apps/zephyr-custom/src/zephyr.provide.ts`） | **否**（宿主 service） |
| `./contract` | 进程内端口（三个契约 + `cua`）                                               | 宿主、别的域的 server 面                               | 是（只有类型与令牌）   |
| `./endpoint` | 两组远端契约、wire 端点名、两份 remote descriptor                            | 宿主注册 + **浏览器半 `$mount`**                       | 是（纯值 + 类型）      |
| `./server`   | 宿主实现与 `providePermissionFor()`                                          | 宿主装配                                               | 否                     |

## 三、行为与边界

- **浏览器半的唯一来源**：`@deepseek-ai/dsh-client-ui-permission-presets/client` 的行 `$mount(PERMISSION_PRESETS_REMOTE)`、`@deepseek-ai/dsh-client-ui-user-questions/client` 的行 `$mount(USER_QUESTIONS_REMOTE)`。行本身住 `dsh-conversation/src/ui`（`ui-permission.service.ts` / `user-questions-slots.ts`），只从本包 `./endpoint` 取常量。
- **漏进来的样子**：从包根取常量 → `user-question-queue.service.ts` / `approval.service.ts` / `permission.service.ts` 进 client 图 → 上游宿主面（`interaction/user-approval`、`core/session`、`schedule`）随 `node:*` 一起进，构建立刻红（`MISSING_EXPORT`，vite 把 `node:*` 映射到 node-stub 时缺 `randomUUID` / `isAbsolute`）。

## 四、验收判据

| #   | 判据（Done when）                              | 证据（命令 / 用例名）                                                                                                                                                                                                                                          |
| --- | ---------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | 浏览器半不从本包包根取任何东西                 | `grep -rn 'from "@morlay/dsh-permission"' packages/*/*/src/ui \| grep -v __tests__` 零命中                                                                                                                                                                     |
| 2   | 两个 descriptor 只在一个 home                  | `grep -rn 'USER_QUESTIONS_REMOTE\|PERMISSION_PRESETS_REMOTE' packages --include='*.ts' \| grep 'export '` 只有 `src/endpoint/index.ts`                                                                                                                         |
| 3   | 客户端产物里没有三个宿主 service 与上游宿主面  | `just custom build` 绿；`grep -rlF 'ApprovalDefault\|PermissionDefault\|UserQuestionQueueDefault\|UserQuestionService\|ApprovalService\|PermissionPresetService' apps/zephyr-custom/node_modules/.zephyr/dist` 零命中；`@deepseek-ai/dsh-user-approval` 零命中 |
| 4   | 两份 descriptor 真的到了浏览器（常量没被搬丢） | 同一产物里 `permissionPresets/catalog` 与 `userQuestions/answer` 命中（descriptor 的 wire 名）                                                                                                                                                                 |
| 5   | 端点面与契约面在本包内可跑                     | `pnpm exec vitest run packages/agent/dsh-permission`                                                                                                                                                                                                           |

## 五、剩余风险

- `./endpoint` 依赖 `@morlay/zephyr-app/remote`（框架的 `@RemoteGroup` / `@RemoteMethod`）：那是两端共用的装饰器面，当前图里不带 `node:*`；框架若把它拆成 host/client 两份，本包要跟着换。
