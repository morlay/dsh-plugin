# 深层模块审计（packages/agent）

状态：已实现（结论与取舍都是当前形态；判据见「事实·一」的复核命令）
范围：`packages/agent/*` 32 个包的模块身份、接口深度、接缝真假与测试表面。
约束：判据用 `dsh-plugin-design` 的词汇（模块 / 接口 / 实现 / 深度 / 接缝 / 适配器 / 杠杆效应 / 局部性）。

## 结论摘要

| 议题 | 结论 | 一句话理由 |
| ---- | ---- | ---------- |
| 包的身份 | 32 个包里 5 个含真模块（`dsh-session` / `dsh-workspace` / `dsh-session-persistence` / `dsh-storage` / `dsh-command`），其余 27 个是装配行 + 模块壳 + 令牌 | 非 spec 最大文件 37 行，内容是 `fromCordis` 行 + `mount` 交依赖 |
| 契约的深度 | 43 份契约的成员是上游类型的逐条投影，深度 0，只剩令牌作用 | 见「事实·一」的复核命令 |
| 真接缝 | 5 条：`SessionPersistence`、`SessionWorkspace`、`DirectoryPickerBackend`、`FileSystem`、`CommandCatalog` / `CommandRunner` | 生产 1 + 测试 ≥1，两处以上真适配器 |
| 假想接缝 | 其余全部，多数是「生产 1 / 测试 0」 | 一个适配器的接缝只是间接层 |
| 契约的完整性 | 契约必须覆盖上游服务的**全部**公开成员（`AssertCovered` 守卫，漏一个编译失败）；唯一例外是 `ui/session-controller` 的 5 个成员，仍按实供收窄 | 上游插件按 `ctx.<service>.<member>` 取用，缺一个那条插件在运行期就是 `undefined` |
| 正面 | 契约之间零跨包引用；`dsh-upload` 与 `dsh-web-access` 是「行该有的样子」（不做第二份真源） | 见「事实·六」 |
| `@Command()` | 保留，记 `债务 命令装饰器生产零使用` | 删它会连带削掉 `CommandRegistry.register` 的撤销语义，而上游 3 个插件行真依赖它 |

## 事实

### 一、规模与量化

```
32 包 · 50 份 *.contract.ts · 45 个 spec · 43 份契约带覆盖守卫
```

- **投影式契约 43 份**（成员逐条写成 `UpstreamService["member"]`，每份带 `AssertCovered` 覆盖守卫；另 7 份是自己立的接缝或纯行，没有上游可覆盖）。复核：
  `grep -l "AssertCovered" -r packages/agent --include='*.contract.ts' | wc -l`
- **实现体分布**：非 spec 最大的几个文件是 `dsh-session` 与 `dsh-workspace` 的两份 ui controller 与 host 行（`session-controller.service.ts` 426 行量级、`session-controller.host.ts` 232 行、`session-persistence.service.ts` 163 行、`workspace-broadcaster.service.ts` 84 行）；其余包的单文件上限 48 行。
- **断言**：源码与 spec 里都没有 `as never` / `as unknown as`（复核：`grep -rn "as never\|as unknown as" packages/agent | grep -v "//"`）。剩下唯一一处是 `dsh-command/src/command.decorator.ts` 里泛型装饰器返回子类的 `as T`——TS 不认「类型变量的 `extends` 结果仍是 `T`」，就地收窄，注释写明了原因。

### 二、包的三类身份

1. **装配行**（19 个）：一个 `@Injectable() class X extends fromCordis(上游插件)`，`onInit` 里 `mount(ctx, undefined, deps)`。例 `dsh-agent/src/llm-retry.service.ts`、`dsh-goal/src/command.service.ts`。它们是**适配器**，不承担深度——把上游的构造期 `ctx` 依赖改成 zephyr 的构造期登记式注入，这件事只能靠一段代码做，删掉后复杂度会在装配点原样重现。
2. **令牌**（8 个）：契约存在、成员投影、无自有语义，价值在「让消费方不写上游包名」。例 `dsh-fs/src/contract/file-system.contract.ts`（16 个成员全投影，实现 0 行，实现在 `dsh-sandbox` 的 `FsSandbox`）。
3. **真模块**（5 个）：见下节。

### 三、五条真接缝（生产 1 + 测试 ≥1）

| 契约 | 生产适配器 | 测试适配器 |
| ---- | ---------- | ---------- |
| `SessionPersistence` | `SessionPersistenceDefault`（真落盘 `<dataDir>/sessions/<id>/{meta.json,events.jsonl}`） | 真持久化 + `FakeAppEnv`（各 spec 用临时 `dataDir`） |
| `SessionWorkspace` | `SessionWorkspaceHost` | `FakeSessionWorkspace`（`sessions-host.spec`） |
| `DirectoryPickerBackend` | `DirectoryPickerNative` | `FakeNativePicker`×2、`NoopPicker`×2 |
| `FileSystem` | `FsSandbox` | `LocalFs`×4（`fromCordis(FileSystem, LocalFileSystem)`） |
| `CommandCatalog` / `CommandRunner` | `RemoteCommandCatalog` / `RemoteCommandRunner` | `RegistryCatalog` / `RegistryRunner`（同进程）+ `FakeCatalog` / `FakeRunner` |

`SessionPersistence` 与 `SessionWorkspace` 是本层仅有的两条「接口小而实现深」：前者把 revision→不透明 token、只读句柄拒绝、路径编码藏在 163 行里；后者把 attach 的互斥与时序不变量藏在 1 个方法后面。

### 四、假想接缝

- **`@Command()` + `CommandContribution`：生产 0 使用**（`债务 命令装饰器生产零使用`）。唯一使用者是 `dsh-command/src/__tests__/command-contribution.spec.ts` 里的 `GoalCommand`。仓内三条命令都是上游命令插件的行：`inject(CommandRegistry)` 后把令牌交给上游 `mount`，由上游自己登记。`CommandRegistry` 本身不是假想接缝——它有生产适配器 `CommandRegistryDefault` 与 3 个消费方。
- **`WorkspaceController`（生产 1 / 测试 0）**：宽度由上游 `IWorkspaces` 钉死，浏览器侧只有一份实现。
- 其余投影式契约均为生产 1 / 测试 0。它们的令牌价值在于「消费方不写上游包名」，删掉会把上游包名散布到装配点。

### 五、契约的完整性

上游插件按 `ctx.<service>.<member>` 取用，所以**契约必须覆盖上游服务的全部公开成员**，缺一个那条插件在运行期读到的就是 `undefined`。每条契约文件里有一行守卫：

```ts
export type XxxCovered = AssertTrue<AssertCovered<UpstreamService, Xxx>>;
```

`AssertCovered` 把「上游有、契约没列」的成员名变成编译错误（`@morlay/zephyr` 的 `contract-coverage.ts`，排除 `Service` 基类的 `name` 与 symbol 键）。上游加成员时这一行会先红，再补声明。

写法：`abstract class` 逐条声明，每条直接取 `Upstream["member"]`；不用 `Pick` 中间面、不用 `interface` 同名合并、不开 `no-unsafe-declaration-merging` 豁免——那条豁免换掉的是「子类漏实现即编译失败」。

**唯一例外**：`dsh-session/src/ui/session-controller.contract.ts` 的 5 个成员（`list` / `retain` / `scope` / `sessionOf` / `binding`）仍按本仓实供收窄成 `SessionCatalog` / `SessionRetainHandle` / `SessionScope` / `SessionView`。要改成上游真类型（`SessionListState` / `SessionReference` / `AgentContext` / `SessionFace` / `SessionBinding`），前提是这几个成员由上游 `ClientSessions` 实现——它要的 `remote` 面（`session.follow` 的流式通路、`commands`、`subagents`、泛型 `$stream`）本仓还没补齐，硬塞「访问即抛错」会让 UI 每次渲染都炸。见开放问题 1。

### 六、正面（要保留的东西）

1. **契约之间零跨包引用**：50 份契约的 `import` 只有 `@morlay/zephyr` 与上游包，没有一份引用另一个包的契约（复核：`grep '^import' --include='*.contract.ts' | grep '@morlay/'`）。接缝彼此独立，改一条不会带动另一条。
2. **`dsh-upload` / `dsh-web-access` 是「行该有的样子」**：`fromCordis(契约, 上游)` 之后不叠加策略、不做第二份真源；上游的行为（含它没做的事）就是本包的行为，README 的「事实」段写清边界。
3. **`CommandRegistry.register` 返回撤销函数**：返回结果而非产生副作用，生命周期归属清楚。
4. **装配面只认 Module 与契约**：`apps/dsh-custom-next` 不 import 任何业务实现类（唯一的 `SessionControllerRow` / `RemoteGapsHost` 是本应用自己的行）。

## 取舍

- **契约统一用 `abstract class` 逐条声明，不用「空令牌类 + `interface` 同名合并」省行数**：后者要开 `no-unsafe-declaration-merging` 豁免，换掉的是「实现类漏一个成员就编译报错」这条真保障。
- **不在 `fromCordis` 行 ctx 上补齐 cordis 的全部 static symbol**，只补了服务隔离表（`Context.isolate`）。它是 scoped 事件派发的必要条件；其余 symbol 没有消费方，补了就是假想接缝。
- **不按消费方把 `SessionController` 拆成 host / client 两份窄契约**：它的宽度由上游 `ui-*` 组件的 `ISessions` 期望钉死，拆窄只能拆到「我们自己的调用点」。
- **不给 `WorkspaceBroadcaster` 立契约**：它只有 2 个包内消费者，立契约会新增一条 0 替身的假想接缝。
- **不合并装配行回大包**：那会退回单体；行本身是适配器，浅是它的职责而非缺陷。
- **不替上游补它没做的事**：上游删掉的行为（如抓取的地址策略）本仓不代为实现——我们的包是适配层，叠上去之后「上游是什么样」和「我们是什么样」就分不清了。

## 开放问题

1. **`ui/session-controller` 的 5 个成员**：要完整就得接上游 `ClientSessions`，前置是补齐 wire 面（`session.follow` 的客户端流式通路、`commands` / `subagents` 命名空间、`$stream` 的泛型签名）与宿主侧 `subagents/*` 端点。缺口在 wire 契约与宿主能力，不是这一层的写法。
2. **`dsh-agent` 里两条没有消费者的行**：`TimerDefault` 在 `AgentModule` 里（上游工具执行会用到），`LaunchEnvironmentDefault` 在包里但不进模块（读者是上游 `launchEnvironmentOf`，而装它的 `llm-deepseek-account` 行还不在装配里）。
3. **`SessionController` 两份实现的空壳成员要不要收口**：`retainInfo` 空 observable、`searchResultLimit = 20`、`fork` 抛错各写两遍（host 与 client 各一份）。收口到一个共享的「不支持」基类会引入一条新接缝，收益是两份实现各少 30 行。
4. **`fromCordis` 的 `providerInstance` 类型是 `object | undefined`**：调用方（`dsh-workspace` 的 directory picker 行）因此用运行时类型谓词收窄。改成 `PluginService<P> | undefined` 是一行的事，但目前只有一处消费方。
