# 深层模块审计（`packages/agent/*`）

状态：已实现——审计结论就是当前形态；本文的数字与清单按当前代码复核，可随 `grep` 重算
范围：`packages/agent/*` 23 个包的模块深度、接缝真假与测试面
非目标：`apps/*` 与框架包（`packages/zephyr/*`）的模块评价；契约的写法规范（home 在根 `.agents/standards/`）
关联：设计 20261028-包内子域拆分与注册抽象 · 设计 20261109-核心能力与BFF分层 · 债务 命令装饰器生产零使用

## 一、决定

| #   | 议题                              | 决定                                                                                                | 一句话理由                                                 |
| --- | --------------------------------- | --------------------------------------------------------------------------------------------------- | ---------------------------------------------------------- |
| 1   | 投影式契约留不留                  | 留（60 份里 40 份是逐成员投影上游）                                                                 | 它们的价值不是可替换性，是令牌、编译期钉住上游面、测试表面 |
| 2   | 怎么钉住上游面                    | 每份投影契约带一行 `AssertCovered` 守卫                                                             | 上游加成员时先红，而不是运行期读到 `undefined`             |
| 3   | 什么叫真接缝                      | 只认「生产 ≥1 且测试 ≥1 个适配器」（本文列 6 条）                                                   | 一个适配器只是间接层；删除它复杂度不会在别处重现           |
| 4   | 窄契约要不要按消费方拆            | 不拆 `SessionController` / `WorkspaceController`：宽度由上游 `ClientSessions` 与 `IWorkspaces` 钉死 | 拆窄只能拆到我们自己的调用点，接缝仍在别人的形状上         |
| 5   | `WorkspaceBroadcaster` 立不立契约 | 不立：它是包内 2 个消费者的实现细节                                                                 | 0 个替身的契约是假想接缝                                   |

## 二、现状事实

- **规模**：23 包 · 60 份 `*.contract.ts`（40 份带守卫；其中 2 份是 `ui/` 的界面端口）· 68 个 spec 文件。复核：`find packages/agent/*/src -name '*.contract.ts' | wc -l`、`grep -rl AssertCovered packages/agent --include='*.contract.ts' | wc -l`、`find packages/agent/*/src -path '*__tests__*' -name '*.spec.ts*' | wc -l`。
- **测试面**：`pnpm exec vitest run packages/agent` → 144 files / 837 tests（9 skipped），整批约 70s。
- **契约之间的跨包引用只有品牌值**：`src/contract/*.contract.ts` 里对 `@morlay/` 的引用 3 处，全部是从 `@morlay/dsh-session/endpoint` 取 `SessionId`（`dsh-command` 的 catalog / runner、`dsh-conversation` 的 session-controller）。跨包只共享「身份怎么铸」，不共享实现。
- **投影契约的例外**：`dsh-command` 的 4 份契约（`command-catalog` / `command-registry` / `command-runner` / UI 面的 `command-ui`）没有上游服务可覆盖——它们是本域自己立的接缝；`dsh-agent` 的 4 份 `*-vocabulary.contract.ts` 是词汇出口（类型与纯函数），不是端口。

**接口**：契约是 `@Injectable()` 抽象类，成员类型逐条取上游实例（`abstract x(): Upstream["x"]`），并有一行 `AssertCovered<上游实例, 本契约>` 把「上游有、契约没列」变成编译错误。写法理由见根 [`.agents/standards/ui-module.md`](../../../../.agents/standards/ui-module.md) 与设计 20261028-包内子域拆分与注册抽象。

**深度**：本层的深度在三处，都不在契约里——1）**适配行**（135 处 `fromCordis`）：把上游「构造期读 `ctx`」改成「装配期交 deps」，删掉它复杂度会在装配点原样重现；2）**两个 ui 控制器**（`dsh-workspace/src/ui/workspace-controller.service.ts` 194 行、`dsh-conversation/src/ui/session-controller.service.ts` 199 行）：接流、转命令、把状态机让给上游；3）**契约套件**（`runPersistenceContract` / `runCoordinatorContract`）：它们把「可替换」这件事变成可判定的。契约本身是投影，浅是它的职责；真正的深实现在上游（`vendor/deepseek-harness`），不在本层——所以本层不拿「接口小、实现深」自居。

## 四、行为与边界

- **上游加了成员**：`AssertCovered` 先编译报错，补声明；不会等到运行期读到 `undefined`。
- **替换实现**：装配面用 `without(默认实现)` 剔掉默认行，再接同契约的另一份实现（RDB / 可配置沙箱是现成的两条）。
- **假件的位置**：可复用的替身进 `./testing`；一次性的假件留在 spec 里。`dsh-agent/testing` 明确不造十几个成员的空壳 fake。

## 六、取舍

- **按消费方把 `SessionController` 拆成 host / client 两份窄契约**：宽度由上游 `ClientSessions` 与 `ui-*` 组件的期望钉死，拆窄只是把我们的调用点收窄。
- **给 `WorkspaceBroadcaster` 立契约**：2 个包内消费者、0 个替身。
- **在 `fromCordis` 行 ctx 上补齐 cordis 的全部 static symbol**：只补服务隔离表（`Context.isolate`），其余 symbol 没有消费方。
- **把装配行合并回大包**：退回单体；行本身是适配器，浅是它的职责。
- **契约用「空令牌类 + `interface` 同名合并」省行数**：要开 `no-unsafe-declaration-merging` 豁免，换掉的是「子类漏实现即编译失败」。

## 七、不做与已知债

- 不评价浏览器半的模块（`ui/` 的 store / 视图）——那需要以「渲染与状态」为对象另开一轮。
- 债务 [命令装饰器生产零使用](../debts/20261029-命令装饰器生产零使用.md)：`@Command()` 是 0 个生产适配器的接缝。
- **契约与实现同包，但包级图只有单向边**：`dsh-agent-loop → dsh-sandbox` 是生产边（循环期的工具执行要沙箱），反向的 dev 边（沙箱的 spec 拉 agent-loop）已不存在。判据：`pnpm -r --filter './packages/*/*' exec true` 通过（不声明 `ignoreWorkspaceCycles`）。

## 八、开放问题

1. **`ToolExecutor` 没有本地令牌**：它是 `@morlay/dsh-agent/contract` 的词汇类型（`tool-vocabulary.contract.ts` 从上游 re-export），两行实现（`ToolExecutorNative` / `ToolExecutorPtc`）由装配二选一。要不要给它一条本地端口，等出现第三个实现再定。
2. **接口里的性能特征没写进契约**：`SessionQuery` 的读一次代价（只读命中行 vs 读全量再筛）只写在实现注释里，新调用方要读实现才知道。
