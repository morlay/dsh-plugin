# 上游基础装配（`packages/agent/*`）

状态：形态已实现——四层与出口纪律是当前代码；「contract / endpoint 面 client-safe」这条判据本轮收口 5 处（2 份端点面改 `import type` + 上游 `/types`、3 条 contract 值转出挪包根，见 [dsh-permission 的出口边界](../../dsh-permission/.agents/designs/20261113-出口边界与浏览器半.md)），其余 54 条按本文 ticket 收

## 一、决定

| #   | 议题               | 决定                                                                                                                                                                           | 一句话理由                                                                                                                       |
| --- | ------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------- |
| 1   | 基础装配分几层     | 固定四层：上游插件行 → 本地契约（`./contract`）→ 默认实现 / 适配行（`fromCordis`）→ 基础清单（`provideXxx()`）                                                                 | 四层的消费方与允许出现的东西各不相同；少一层就有一类事实没有 home（行散进装配面、上游类型散进 ui）                               |
| 2   | 清单与差异值       | 清单只**声明条目**；域默认值走 `provide(list, defaults)` 的第二个参数，部署差异走调用方 feature                                                                                | 调用方 feature 排在域默认值之后，所以默认值可被覆盖，而实现类的 `static Config` 推导不丢                                         |
| 3   | 二选一怎么表达     | 装配面：`without(默认实现)` + 另一域 / 扩展层的 `provideXxx()`；清单内不写 if/else                                                                                             | 同名服务在同一作用域注册两次直接抛错；二选一必须显式，且只能由知道部署的装配面决定                                               |
| 4   | `configure` 的边界 | 只改**值**，不换实现；换实现只能换条目                                                                                                                                         | `configure` 按实现类定位既有条目——目标不在清单里时它是空操作（见现状事实的缺陷 1）                                               |
| 5   | 出口按谁消费分档   | `./contract`：类型与令牌，client 可引；`./endpoint`：纯值 + 类型，client 可引；`./server`：宿主实现，client 禁；包根：宿主面（有 `./server` 的包只放契约聚合与 headless 装配） | 出口是**编译期**边界；同一个词放错面，浏览器 bundle 会多一整棵上游宿主树                                                         |
| 6   | 上游值词汇放哪     | client 不需要 → 包根（宿主面）；client 需要 → 上游 `/types`、`/client`、`/remote` 子路径，或本仓形状（`./testing` 的 fake）                                                    | 上游 branded 铸造函数（`SessionId` / `MessageId` / `ToolCallId` / `ScheduleId`）都在宿主包根上，按值转出就是一条到宿主的运行期边 |
| 7   | `./testing` 何时开 | 有**第二个消费方**（下游域的装配 spec 或替换实现）才开；契约套件（`run*Contract`）当接缝的第二适配器用                                                                         | 空 `./testing` 是空壳出口；契约套件写在 spec 里等于每个 spec 抄一遍夹具                                                          |

## 二、现状事实

- **规模**：23 个包 · 62 个 `provideXxx()`（`./server` 35 / 包根 14 / `./ui` 13）· **适配行 122 个类**（双参 59 / 单参 63，其中 2 个包在 `settingRow(...)` 里）· 60 份 `*.contract.ts`（40 份带 `AssertCovered`）· 68 个包内 spec（其中 20 个装整个域）· 5 个 `./testing` 出口。
- **`fromCordis` 的计数口径**：`grep -rn "fromCordis(" packages/agent --include=*.ts`（去 `__tests__`）命中 **135 行**，拆开是 **122 个类声明** + **12 行注释**里提到 + **1 处装饰器基类工厂**（`dsh-agent/src/contract/mcp-client.decorator.ts` 的 `const Base = fromCordis(McpClientPlugin)`）。**数适配行只数类声明**（`class X extends [wrapper(] fromCordis(...)`，跨行也算）；把注释与工厂算进去就是 135。

**接口**：装配面只认 `provideXxx()`（一个装配单元一行）；差异化只给 `configure`（值）与 `without`（条目）。消费方只认 `./contract` / `./endpoint` / `./testing`，不写 `deepseek-ai/*`，也不引别的域的 `./server`。

**深度**：删掉某一层的装配函数，那个域的条目清单、域默认值与面归属就得在装配面重写一遍（当前 34 条面导入、10 处 `configure` 会摊进 `customProvidersOf`）；删掉契约，跨域消费方直接写上游包名与上游类型（60 份契约、40 份守卫全失效）。

## 四、行为与边界

- **顺序即依赖**：适配行的契约面在它自己的 `onInit` 之后才就位（同步 `new` 时就做 inject 检查），所以「要某服务的面」的行必须排在提供它的行之后；装配面按十组给顺序，顺序只在 `customProvidersOf()` 里出现一次。
- **漏 `deps` 的失败形态**：装配期不报错，上游第一次读它时 `Cannot read properties of undefined`，失败点离装配点很远——所以 `deps` 按上游**实现**核，不按 `static inject`。
- **二选一的失败形态**：两个同令牌条目都装 → `service "x" has been registered`；两个执行器都装 → 上游 `setExecutor` 抛「Only one tool executor may be registered in each scope」。所以 `without` 不是可选项。
- **越界的样子**：`./contract` 里出现一条到上游包根的**值**转出 → 引用它的 ui 把整棵上游宿主树带进浏览器图 → 构建立刻红（`MISSING_EXPORT`：vite 把 `node:*` 映到 node-stub 后缺具名导出）。实测：这一条把 338 个错误带进过 client 图，收口后为 0。
- **扩展层的两种合法替换形态**：①同令牌换实现（`provideSessionPersistence(without(SessionPersistenceDefault))` + `provideBetterSession(configure(SessionPersistenceRdb, …))`）；②在能力层清单之上叠行为（`provideSessionMode()` 接管工具 / 技能 / policy 的按会话收口）。两者都只经契约与 `./testing`，不改能力层的实现类。

## 六、取舍

- **把四层压成两层（适配行自带清单）**：一个域的条目与默认值会散进装配面，`configure` 的目标类也就没有 home。
- **让调用方直接装上游插件**：上游服务名与 `deps` 知识散到装配面，client 侧还会跟着上游包名漂。
- **用 if/else 在装配面选实现**：两份清单都要静态可读、类型可推导；`provide` 的 feature 链已经能把「剔一个、装一个」表达清楚。
- **给每个上游 branded 值在契约面按值转出**：一条值边就把宿主树带进 client 图（338 个错误的成因）。
- **建一层 `export *` 转发出口**：同一份东西列两遍，上游结构一变就跟着改（与 owner 拓扑的决定 3 同一条）。

## 七、不做与已知债

- 不维护「每域清单」的生成表：清单随部署变（`without` 组合在装配面），可守的是出口与判据。
- 债务 [provideApproval() 装的是空 apply](../../dsh-conversation/.agents/debts/20261113-provideApproval装的是空apply.md)。
- 债务 [契约面仍值转出宿主根（dsh-session）](../../dsh-session/.agents/debts/20261113-契约面仍值转出宿主根.md)。
- 债务 [命令装饰器生产零使用](../debts/20261029-命令装饰器生产零使用.md)（`@Command()` 与基础装配的注册面重叠）。
- 框架 `provide` 的类型保守性：`without()` 剔掉的条目在类型层仍算「提供过」——所以「漏装」这类错误只能靠运行期 spec 抓。

## 八、开放问题

1. **`./contract` 的值转出要不要一刀切禁掉**：client 真需要的上游 branded 铸造函数（`MessageId` / `ToolCallId`）若上游没有 `/client` 或 `/types` 出口，只能「本仓自带一份等价形状」或「经 `./endpoint` 出」——两条路都要先定一条判据（批次 0 的一部分）。
2. **`dsh-command` 的 4 份契约 0 份覆盖守卫**：命令面是唯一没有 `AssertCovered` 的域，是否补守卫取决于上游那个服务的成员是否还动。
3. **`./testing` 的第 6 个出口**：`dsh-permission` / `dsh-command` / `dsh-upload` 的整装 spec 各造一份最小 fake，是否收敛成 `./testing` 的契约套件（同 `runPersistenceContract` 形态）。
4. **`@morlay/zephyr-app/client/remote` 缺两个符号**：`RemoteMethod`（应作为 `Remote` 的别名转出）与 `RemoteResultWire`（类型，应从 `src/remote/remote-result.ts` 转出）。补齐后，`./endpoint` 面剩下的 10 条 `/remote` 行可以同一条命令迁完；在那之前它们只能留在宿主面（当前构建绿，但这 5 个包的 `./endpoint` 不是纯 client 面）。
5. **装配面的十组要不要升级成「域装配函数」**：现在 `agentProviders()` / `sessionCoreProviders()` 这类组函数住在应用里；如果第二个部署出现，它们应下沉为各包的 `provideXxx(headless)` 组合（`dsh-agent` 的 `provideAgent()` 是唯一先例）。
