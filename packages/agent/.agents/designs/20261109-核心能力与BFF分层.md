# 核心能力与 BFF 分层（`packages/agent/*`）

状态：已实现——三类包的判据与归类就是当前形态；唯一的 BFF 聚合包是 `dsh-conversation`
范围：23 个 agent 包各承载什么能力、属于哪一类（能力包 / BFF 聚合包 / 无本域契约的行包），以及跨域依赖该走哪个本地包
非目标：上游包逐个归属（home 在设计 20261109-上游依赖的owner拓扑）；包内的面与写法（home 在设计 20261028-包内子域拆分与注册抽象）
关联：设计 20261028-包内子域拆分与注册抽象 · 设计 20261029-深层模块审计 · 设计 20261109-上游依赖的owner拓扑 · 根 [`GLOSSARY-MAP.md`](../../../../.agents/GLOSSARY-MAP.md) 的「agent 能力层」「对话域（BFF）」两行

## 一、决定

| #   | 议题                 | 决定                                                                                                                                                                                              | 一句话理由                                                                             |
| --- | -------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------- |
| 1   | 包的粒度             | 一个包 = 一个能力域；能力先有名字（`src/contract/*.contract.ts`），再有装配行                                                                                                                     | 一个域两个包 = 没人说得清这块归谁                                                      |
| 2   | BFF 拥有什么         | 只拥有**自己场景**的端点聚合与界面槽位；领域能力一律从下层 `dsh-*` 能力包取                                                                                                                       | 删掉 BFF，装配知识在 N 个装配点重现；留着它，领域实现仍只有一份                        |
| 3   | 跨域依赖走哪         | 走本地能力包（`@morlay/dsh-*`），不走它背后的上游包                                                                                                                                               | 上游包 owner 唯一，换实现只动一个包                                                    |
| 4   | 界面槽位住哪         | 按「这块界面是谁的场景」分：会话界面、设置面板、权限面板与交付物住 `dsh-conversation`；命令面板住 `dsh-command`、技能入口住 `dsh-skill`、侧栏终端住 `dsh-shell`、工作区与会话树住 `dsh-workspace` | 页面位置由布局的 owner 决定，域自己的面板由域自己注册；同一 Definition 只能有一个 home |
| 5   | 设置页的浏览器半住哪 | 住 `dsh-conversation`（`ui/settings-*-slots.ts`、`ui/setting-ui.provide.ts`）；设置文档与 schema 在 `dsh-setting`（契约面转出 `@morlay/zephyr-app`）                                              | 页面的位置由布局的 owner 决定，配置的读写由设置域决定                                  |

## 二、现状事实

- **三类包的归类**（契约数 = `*.contract.ts` 的份数，含 `ui/` 的界面端口）：

  | 类别            | 包                                                                                                                                                                                                                                                                                                                                                                             | 判据                                                                                                                                                              |
  | --------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------- |
  | 能力包（19）    | `dsh-agent`(13) · `dsh-agent-loop`(1) · `dsh-attachment`(1) · `dsh-auth`(1) · `dsh-command`(4) · `dsh-compaction`(1) · `dsh-fs`(2) · `dsh-job`(1) · `dsh-permission`(4) · `dsh-ptc`(1) · `dsh-sandbox`(2) · `dsh-session`(11) · `dsh-session-persistence`(2) · `dsh-shell`(3) · `dsh-skill`(1) · `dsh-storage`(2) · `dsh-upload`(1) · `dsh-web-access`(1) · `dsh-workspace`(3) | 本域有契约（能力的名字），实现与装配行都在本包                                                                                                                    |
  | BFF 聚合包（1） | `dsh-conversation`(5)                                                                                                                                                                                                                                                                                                                                                          | `server` + `ui` 两面都在，装的是**别的域**的端点与界面：会话组端点（上游 `api/session-controller`）、会话引用、文件引用、日程、交付物四条 HTTP 路由、会话界面槽位 |
  | 无本域契约（3） | `dsh-agent-instruction` · `dsh-agent-team` · `dsh-setting`(契约面转出框架)                                                                                                                                                                                                                                                                                                     | 包里只有行（一条指令行 / 一行服务 + 一套上游工具与界面 / 设置文档的 loader 与端点），能力名由装配类本身或框架契约承担                                             |

- **`dsh-conversation` 的聚合面**：`src/server/api-session.provide.ts`（会话组端点 + 文件引用服务）、`src/server/session-reference.provide.ts`、`src/server/deliverable.provide.ts`（`/api/present.*` 与 `/api/changes.*` 四条路由）、`src/server/session-remote.provide.ts`（`remote.session` 与 `remote.schedule` 两组 wire 的宿主行，日程实现由上游 `@deepseek-ai/dsh-schedule` 提供、从 `src/server/index.ts` 转出）、`src/ui/`（会话界面与各域槽位的注册点）。
- **BFF 的状态机不在本仓**：`src/ui/session-controller.service.ts` 组合上游 `ClientSessions`、`packages/agent/dsh-workspace/src/ui/workspace-controller.service.ts` 组合上游 `ClientWorkspaceModel`——目录、增量合并、scope 计数都在上游实现里。
- **`dsh-setting` 的契约面**：`src/contract/index.ts` 整份转出 `@morlay/zephyr-app`；本包出 `SettingLoader`（唯一 IO 出口）、`@Setting` 声明与 `settingRow` 模板、`settings` 端点。
- **槽位的实际分布**（`find packages/agent/<包>/src/ui -name '*slot*.ts*' | wc -l`）：`dsh-conversation` 24 个（会话内卡片、交付物、权限 chip 与批准、用户提问、模型选择、设置两页、侧栏骨架、输入区触发器）、`dsh-workspace` 4 个（工作区行与会话树、侧栏文件、上下文菜单、目录选择）、`dsh-command` / `dsh-shell` / `dsh-skill` 各 1 个。权限与设置的**判定与文档**在 `dsh-permission` / `dsh-setting`，**面板**在对话域。
- **跨域依赖的例子**：`dsh-sandbox` 的宿主行把工作区文件能力交给上游工具行时用的是本仓的装配面（`packages/agent/dsh-workspace/src/server/workspace-files.provide.ts`），而不是直接引 `@deepseek-ai/dsh-api-workspace-files`。

## 三、模块边界与接口

| 模块                             | 拥有（职责与不变量）                                                             | 不拥有（明确排除）                                                                                                                                                                             | 依赖方向                                                                             | 接缝 / 适配器                                                 |
| -------------------------------- | -------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------ | ------------------------------------------------------------- |
| 能力包（19 个）                  | 本域契约与默认实现、本域的宿主行与浏览器行                                       | 别的域的端点聚合、别的域的界面槽位                                                                                                                                                             | 框架（`zephyr` / `zephyr-app`）+ 别的域的 `./contract` / `./endpoint`                | 契约令牌；上游插件的 `fromCordis` 适配行                      |
| BFF 聚合包（`dsh-conversation`） | 对话场景的端点聚合（会话组、会话引用、文件引用、日程、交付物路由）与会话界面槽位 | 会话存储 / 查询 / 投影（`dsh-session`）、持久化（`dsh-session-persistence`）、权限判定（`dsh-permission`）、上传与附件存储（`dsh-upload` / `dsh-attachment`）、工作区注册表（`dsh-workspace`） | 下层 `@morlay/dsh-*` 能力包 + 框架 client / host 面 + 本场景的上游端点与 client 插件 | 上游会话端点行与 client 插件行的适配；`provideXxx()` 装配函数 |
| 无本域契约的行包（3 个）         | 装配片段（一行或一组行）与它的 `provideXxx()`                                    | 能力名（没有需要按能力注入的消费方）、领域状态                                                                                                                                                 | 上游插件 + 目标注册表（工具注册表 / 设置文档 / 指令装配面）                          | 适配类自身即令牌                                              |

**接口**：能力包对外是「契约令牌 + `./endpoint` 的 wire 形状 + `./server` / `./ui` 的装配函数」（`dsh-agent` 另在包根出 headless 装配，见设计 20261028-包内子域拆分与注册抽象）；BFF 对外是 `provideApiSession()` / `provideSessionRemote()` / `provideDeliverables()` / `provideDeliverablesUi()` 这类装配函数，**不导出可注入的领域能力**——装配面按需从下层包取。

**深度**：删掉能力包，复杂度会在它的消费方逐点重现（每个消费方都要自己写上游适配）；删掉 BFF，复杂度回到 `apps/zephyr-custom` 的清单里（装配知识从一处散到多处）——两边都有深度，但方向不同：能力包提供杠杆，BFF 提供局部性。

## 四、行为与边界

- **同一 Definition 只能装一次**：交付物槽位、命令面板槽位、侧栏终端槽位各自只有一个 owner 包，装配面各调一次。
- **BFF 的端点行缺依赖**：会话组的宿主行少给一个上游服务，第一次调用（如上传下载路由）才报 `Cannot read properties of undefined`，不是装配期失败。
- **装配顺序**：BFF 的 ui 行要求 `provideSessions()` 先于它（它按服务名读 `session-controller`），顺序由装配面固定。

## 六、取舍

- **把「会话端点」与「会话界面」拆成两个包**：同一个 `conversation` Definition 只能有一个 home，两处注册会撞 `Definition "conversation" is already registered`。
- **让能力包直接 import 上游同名包**：上游包会出现两个 owner，换实现时要改两处。
- **为设置页单独建一个 BFF**：设置页只有一组槽位，且与会话界面共用布局；拆开就把布局 owner 一分为二（`provideSettingUi()` 已并回一个装配函数）。
- **给「无本域契约」的三个包补空契约**：没有按能力注入的第二个消费方，令牌只会多一次跳转。

## 七、不做与已知债

- 不按「上游包名」给本地包命名（`dsh-api-session-controller` 这类名字不进本仓）：名字写的是场景，不是它所代理的包。
- 债务 [命令装饰器生产零使用](../debts/20261029-命令装饰器生产零使用.md)。
- 债务 [建会话时 workspace 挂载失败不回滚 agent](../../dsh-conversation/.agents/debts/20261030-建会话时-workspace-挂载失败不回滚-agent.md)（BFF 的适配层里只留痕）。

## 八、开放问题

1. **`dsh-conversation` 仍直接 import 34 个上游包**（会话组端点、各域 client 插件）：它们是「本场景的 wire 与界面」还是「别的域的能力」？若走「全部收回各域」，设置页槽位要回 `dsh-setting`、技能槽位回 `dsh-skill`，会与「页面位置由布局 owner 决定」冲突——先定这条判据，再动代码。
2. **`dsh-agent-team` 要不要能力名**：它对外只有一套工具与一个团队服务，第二个消费方出现前不立契约。
