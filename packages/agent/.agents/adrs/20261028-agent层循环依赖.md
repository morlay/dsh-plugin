# 解环只删零符号的边，不为跨域契约新建包、也不改成事件：`packages/agent` 保留有符号支撑的环

状态：已采纳——现存一组环（`dsh-agent-loop ↔ dsh-sandbox`，一条 dev 边）按本决策保留，代价记在债务 包级依赖图有故意的环
背景：`packages/agent` 23 个包的依赖图里，环由「契约与实现同包」造成——A 用 B 的契约，在包级就是 A 依赖 B，而 B 又用 A 的契约。任何 `pnpm -r` 的调用（`just build` / `just clean-dist` / `just update` / `just version`）都会因此拒跑（`ERR_PNPM_TASK_CYCLE`），而运行期不受影响：cordis 的令牌注入与包级依赖图无关。

**决定**

环里**有符号支撑的边保留**（它是真实需求，删不掉也不该删），只删「manifest 声明了、源码一处也没 import」的零符号声明边；解环不靠新建中立契约包，也不靠把依赖改成事件 / 回调。

**考虑过的选项**

| 选项                                                                                                  | 否掉的理由                                                                                                                               |
| ----------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------- |
| 中立契约包：把跨域符号下沉成独立包（如 `@morlay/dsh-contract`），两边各依赖它                         | 为单个消费方建包是提前抽象；包数、发布面（CI 逐包发布）、`AssertCovered` 守卫都要跟着搬，而它不解决「manifest 声明比源码需求多」这个真因 |
| 事件 / 回调：命令侧不注入 `AgentDirectory`，改由调用方给 agent，或发事件自建 `sessionId → agent` 映射 | 把显式依赖换成隐式顺序依赖：订阅者顺序、会话销毁时的清理都要额外约定，与「装配只认 Module」相悖                                          |
| 把注册表与实现分包（`dsh-command/contract` 拆成独立包）                                               | 今天 `dsh-agent` 不依赖 `dsh-command`，不构成环；拆包只增加发布面                                                                        |
| 零符号边也留着（当作「顺手拿到整层」的入口）                                                          | 那正是环的成因；`dsh-agent` 不该是整层入口                                                                                               |

**后果**

- `dsh-agent` 不是整层入口：要用某个域就自己声明它。`apps/zephyr-custom/package.json` 自己列了 33 个 `@morlay/*` 依赖。
- 现状的环与出边：
  - 环：`dsh-agent-loop`（`dependencies` → `@morlay/dsh-sandbox`）与 `dsh-sandbox`（`devDependencies` → `@morlay/dsh-agent-loop`，3 个跨域 spec 用）。
  - 不成环的单向边：`dsh-session` → `dsh-storage`；`dsh-workspace` → `dsh-session`；`dsh-agent` → `dsh-fs` / `dsh-session` / `dsh-setting`。
- 看依赖告警必须强制解析：`pnpm install --offline` 走「Already up to date」快速路径时不打印警告，`pnpm install --offline --force --lockfile-only` 才复现。
- `pnpm-workspace.yaml` 没有声明 `ignoreWorkspaceCycles`：`pnpm -r` 的递归命令因此不可用，代价与出口见债务 包级依赖图有故意的环。
