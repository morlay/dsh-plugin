# agent 层只留 `dsh-session ↔ dsh-workspace` 这一组环，不为解环新建契约包

状态：已采纳

## 决定

`packages/agent` 的循环依赖只处理**零符号的声明边**：manifest 声明了、源码一处也没 import 的，删掉。有符号支撑的边保留原样——它代表真实需求，删不掉也不该删。

不为跨域契约新建中立包，也不把依赖改成事件 / 回调来「解环」：那会把显式依赖换成隐式顺序依赖，与「装配只认 Module」相悖。

## 事实

`pnpm install --offline --force --lockfile-only` 当前只报一组 agent 层的环：

```
packages/agent/dsh-session, packages/agent/dsh-workspace
```

两边都由真实引用闭合：

| 边 | 符号 |
| --- | --- |
| `dsh-session` → `dsh-workspace` | 6 处（会话↔工作区绑定、`SessionWorkspace` 的消费面） |
| `dsh-workspace` → `dsh-session` | 5 处（`SessionStore`、`SessionProjectionStore`、会话行） |

已经是单向、不再成环的：

- `zephyr-app → dsh-auth`：`zephyr-app` 依赖 `@morlay/dsh-auth`（`connection.service.ts` 要 `Credentials`），反方向没有边。
- `dsh-agent` 的出边只剩真实引用（`dsh-session`、`zephyr`、`zephyr-app`），其余包与它没有边。

**环本身要靠动契约归属才解**：`SessionStore` 与 `Workspace` 互相要对方的东西——这不是清单纠偏能解决的，留给下一篇 ADR。

## 考虑过的选项

| 选项 | 改动面 | 代价 | 是否引入新的隐式装配 | 取舍 |
| --- | --- | --- | --- | --- |
| 清单纠偏：删掉零符号的声明边 | 各包 `package.json` 若干行 + 锁文件 | 无运行期影响；只是被删的包不再是「顺手拿到整层」的入口 | 否 | **采纳**：解环用的正是没有符号支撑的边，其余都对应真实 import |
| 中立契约包：把跨域符号下沉成独立契约包，两边各自依赖它 | 新增包的 `src/`、`tsdown.config.ts`、`exports`、`engines.dsh`；所有消费方改写 import | 多一个包的版本与发布面（CI 逐包发布），契约与实现分居两包 | 否（仍按 class token 注入） | 否掉：为单个消费方建包是提前抽象，且不解决「manifest 声明比源码需求多」这个真因 |
| 注册表与实现分包：把 `dsh-command` 的 `./contract` 出口拆成独立包 | 拆包 + 三个消费方改依赖与 import | 包数 +1、发布面 +1，`@morlay/dsh-command/contract` 出口要跟着搬 | 否 | 暂不做：今天没有 `dsh-agent → dsh-command` 这条边，不构成环 |
| 事件 / 回调：命令侧不再注入 `AgentDirectory`，改为调用方给 agent，或发事件自建 `sessionId → agent` 映射 | `dsh-command` 的 wire 形状 + host 三个实现 + 两侧客户端 | 会话作用域解析要在两处各自维护，事件顺序成为正确性前提 | **是**：订阅者顺序、会话销毁时的清理都要靠额外约定 | 否掉：把显式依赖换成隐式顺序依赖 |

## 后果

- `dsh-agent` 不再作为「整层入口」；要用某个域的包必须自己声明它。`apps/dsh-custom-next/package.json` 就是这样写的。
- 看警告必须强制解析：`pnpm install --offline` 走「Already up to date」快速路径时不打印警告，`pnpm install --offline --force --lockfile-only` 才复现。
- 触发条件：出现第三个包需要 `CommandRegistry`、或 `dsh-agent` 真要用到命令能力（那时会出现 `dsh-agent → dsh-command` 反向边）、或 `dsh-command` 对 `dsh-agent` 的依赖扩到 `AgentDirectory` 以外——任一成立就改走「注册表与实现分包」。
