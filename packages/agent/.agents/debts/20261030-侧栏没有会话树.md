# 侧栏没有会话树（权限 / 模型切换因此全链路早退）

- **状态**：已知，未修
- **影响**：侧栏只有壳（品牌 / 新建会话 / 自动化任务 / 工作区 / 设置），**没有会话列表**。
  于是点不到会话 → `sessions.binding(id)` 为空 → 上游权限 chip 在
  `if (live === undefined) throw 'this session is not materialized yet'` 处抛错，又被它自己的
  `.catch(() => false)` 吞掉 → 用户看到的是「权限切换 / 模型选择点了没反应」。
- **已确认的事实**
  - 数据面正常：`session/list` 返回 `{"ids":["session-39",…]}`（console 可见）。
  - `sessions` 行本身正常：`list.getSnapshot()` 有 `ids`/`byId`，`binding()` 与 `binding.session.command()`
    都有 spec 覆盖（`dsh-session/src/ui/__tests__/sessions-binding.spec.ts`，2 条绿）。
  - 渲染面缺：`document.querySelectorAll('[data-session-id]').length === 0`。
  - 位置族：上游 `ui-sidebar` 用 `ctx.slots.inject('sidebar', …)` 注册，并在注册时声明
    `children: { 'sidebar.workspaces': … }`；上游 `ui-workspace` 用 `ctx.slots.inject('sidebar.workspaces', …)`
    挂会话树（`vendor/.../client/ui-workspace/src/client/index.ts:292`）。
- **试过并回退**：在应用层用 `@View({ name: "root", root: true })` 加一个 `ShellView`，用
  `View.seat(SidebarView)` / `View.seat(MainView)` 声明 `sidebar`/`main`。
  最小装配下能让 `sidebar.workspaces` 出现条目，但**实机装配失败**：
  `✗ layout: single slot … 重复声明` —— 说明实机里 `root` 已有占据者且已声明 `sidebar`，再加一个是重复声明。
- **下一步**：先确认实机 `root` 的占据者是谁（`[slots] renderRoot entries=1` 的那一条），
  在**它的** `children` 里补 `sidebar.workspaces`（若缺），而不是新加一个 root 占据者。
  判据：`slots.entriesOfSlot("sidebar.workspaces").length > 0`。
