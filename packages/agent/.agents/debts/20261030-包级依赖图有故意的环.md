# 包级依赖图有故意的环

状态：触发中（`pnpm -r` 默认拓扑排序会拒绝；已在 `pnpm-workspace.yaml` 声明 `ignoreWorkspaceCycles: true`）

**现象**

两条环，都在 `dependencies`（运行期，不是测试边）：

```
dsh-agent → dsh-session → dsh-working-directory → dsh-agent
dsh-auth  → zephyr-app  → dsh-auth（后者是 zephyr-app 的 devDependencies，spec 用）
```

`pnpm -r … exec` / `-r run` 报 `The tasks form a dependency cycle`（`just clean-dist` 就是这么被挡住的）。

三条边各自都在源码里真实使用，不是误加：

- `packages/agent/dsh-agent` 的 `AgentLoopDefault` inject `SessionStore` / `SessionProjectionStore`（`@morlay/dsh-session`）；
- `packages/agent/dsh-session` 的 `SessionSkillCatalog` / `FileReferences` inject `WorkingDirectory`（`@morlay/dsh-working-directory`）；
- `packages/agent/dsh-working-directory` 的 `WorkingDirectoryDefault` inject `SystemPrompt`（`@morlay/dsh-agent`）。

环的成因是**契约与实现同包**：`@morlay/dsh-*` 既是契约（`abstract class` 令牌）的 home，也是适配实现的 home，
所以「A 用 B 的契约」在包级就变成「A 依赖 B」，而 B 又反过来用 A 的契约。

**影响**

`pnpm -r` 的拓扑排序不可用：递归命令按任意顺序执行（构建时并发跑、依赖的产物可能还没出）。
运行期不受影响——cordis 的令牌注入与包级依赖图无关。

**触发条件**

新加一条「跨域 inject 对方契约」的边（几乎每次加域都会碰到），或需要 `pnpm -r` 的拓扑顺序（构建）。

**销账条件**

Done when：把三方共用的契约抽到独立包（例如 `@morlay/dsh-contract`：`SystemPrompt` / `SessionStore` /
`WorkingDirectory` 三个令牌搬进去），各域包只依赖契约包、实现包之间不再互相依赖；
`pnpm-workspace.yaml` 的 `ignoreWorkspaceCycles` 可以删掉且 `pnpm -r exec true` 通过。

**不修的理由**

抽契约包要动三个包的令牌 import、所有 `inject(...)` 的调用点、上游适配行的 `fromCordis` 泛型，以及
`@morlay/zephyr` 的 `AssertCovered` 覆盖守卫；这是一次跨域重构，收益只是「拓扑排序可用」。
现状用一条显式声明承认环、把风险写在这里，比半途改一半更安全。
