# `pnpm -r` 因包级环拒跑（`dsh-agent-loop ↔ dsh-sandbox`，一条 dev 边）

状态：触发中——`pnpm -r --filter './packages/*/*' exec true` 报 `ERR_PNPM_TASK_CYCLE`；`pnpm-workspace.yaml` 没有 `ignoreWorkspaceCycles`
位置：`packages/agent/dsh-agent-loop/package.json`（`dependencies` → `@morlay/dsh-sandbox`）、`packages/agent/dsh-sandbox/package.json`（`devDependencies` → `@morlay/dsh-agent-loop`，被 3 个 spec 使用：`packages/agent/dsh-sandbox/src/__tests__/{subagent,subagents-endpoint,tools}.spec.ts`）

**现象**

一条环：`dsh-agent-loop` 运行期依赖 `dsh-sandbox`（工具执行与沙箱策略），而 `dsh-sandbox` 的测试要装 `@morlay/dsh-agent-loop` 才有真 agent 栈（`provideSubagent` / `AgentLoopDefault` / `ToolExecutorNative`）。环因此是 **prod 边 + dev 边**，不是声明笔误。

命中的命令（实测）：`pnpm -r --filter './packages/*/*' exec true`、`pnpm -r --filter @morlay/dsh-sandbox --filter @morlay/dsh-agent-loop exec true`。

**影响**

所有 `pnpm -r` / `pnpm exec -r` 的递归命令不可用：`just build`、`just clean-dist`、`just update`、`just version` 一旦覆盖到这两个包就直接退出（`The tasks form a dependency cycle`）。运行期不受影响：cordis 的令牌注入与包级依赖图无关。

**触发条件**

眼下就卡在这里（构建与批量清产物都要 `pnpm -r`）。任何一次发布前的 `just build` 都会撞上。

**销账条件**

Done when：不声明 `ignoreWorkspaceCycles` 的前提下，`pnpm -r --filter './packages/*/*' exec true` 通过。两条候选路线，选一条——

1. 把 `dsh-sandbox` 里那 3 个跨域 spec **收口**（按根 [`how-to-verify.md`](../../../../.agents/standards/how-to-verify.md) 的新口径：apps 不设测试门禁，组合由 `just custom build` + 装配清单评审守——它们判的是整装组合，不属能力包）：只留判域行为的断言，其余删掉，dev 边随之消失；
2. 在 `pnpm-workspace.yaml` 声明 `ignoreWorkspaceCycles: true`，把「任意顺序执行」这条风险写进构建说明。

**不修的理由**

路线 1 要判定这 3 个 spec 里哪些断言属域行为：它们同时装沙箱、agent、agent-loop、shell，属整装冒烟，而组合现在没有用例门禁可依（只有 `just custom build` 与清单评审），删之前得先确认同一批断言没有别的用例覆盖——否则等于把「组合装得起来」这条观察一起丢掉。路线 2 会让新出现的环一并被掩盖——递归命令按任意顺序跑，构建可能先跑消费方。先用一条显式记录承认它，比半途改一半安全。
