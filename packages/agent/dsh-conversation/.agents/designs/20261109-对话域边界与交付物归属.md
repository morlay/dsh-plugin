# 对话域边界与交付物归属（`dsh-conversation`）

状态：已实现——宿主半三段（数据面 + 会话引用 + 会话端点）与浏览器半四段（布局 + 骨架 + 界面 + 输入区）都是当前形态；交付物的两端都在本包
范围：本包拥有什么、不拥有什么；交付物（四条 HTTP 路由 + 卡片与标签）为什么住在这里；会话组的端点为什么用上游行、适配层补了什么
非目标：会话数据面（`dsh-session`）、工作区（`dsh-workspace`）、权限判定（`dsh-permission`）、设置文档与 schema（`dsh-setting` + `@morlay/zephyr-app`）
关联：设计 20261109-核心能力与BFF分层（BFF 的判据与 23 包归类）· 设计 20261029-深层模块审计 · [dsh-workspace 的远程面](../../../dsh-workspace/.agents/designs/20261027-workspace远程面与流式wire.md) · 债务 建会话时 workspace 挂载失败不回滚 agent

## 二、现状事实

- **宿主半三段**（`packages/agent/dsh-conversation/src/server/conversation-server.provide.ts`）：`provideSessionRemote()`（会话数据面 + `toolResults`，自带三份 root）→ `provideSessionReference()` → `provideApiSession()`。**不要再并列装 `provideSession()`**：第一段已带真 store 行，重复注册会抛 `service "sessions" has been registered`。
- **浏览器半四段**（`src/ui/conversation-ui.provide.ts`）：`provideSessionShell()`（`SessionLayout` 包装上游 `ui-session`，产出 `uiSession`）→ `provideSessionShellSlots()`（侧栏骨架，要 `uiWorkspace`）→ `provideSessionSlots()`（主视图 / 内容渲染 / 会话内卡片，产出 `conversation`）→ `provideSessionInputSlots()`（输入区触发器、命令 UI、`@` 引用，要 `remote.commands`）。
- **装配顺序由调用方负责**：`provideWorkspaceUi()` 与 `provideCommandUi()` 必须排在 `provideConversationUi()` 之前（同一份函数注释里写明）。
- **会话端点行的依赖面**（`src/server/api-session.provide.ts`）：`mount` 交 13 个上游服务名；`depConnection` 是上游 `static inject` 里没有、但代码里会读的那一个。行在 `onInit` 里把调用描述登记进 `Typert.remotes`——服务端不知道 `mode` 的话，流式端点会被当 unary 打开并被上游拒。
- **交付物的装配点各一处**：`apps/zephyr-custom/src/zephyr.provide.ts` 装 `provideDeliverables()`、`apps/zephyr-custom/src/client/client.provide.ts` 装 `provideDeliverablesUi()`。
- **交付物标签的现状**：`DeliverablesSlots` 把标签类型注册进侧栏右面板的**独立实例**，面板读的是它自己那一份——所以标签不进标签条，卡片本身照常渲染（`src/ui/deliverable.slot.ts` 的文件头写明）。
- **设置面板在本包**：`src/ui/setting-ui.provide.ts`、`settings-*-slots.ts`、`settings-host.ts`；配置的读写与 schema 在 `@morlay/zephyr-app` 的 `Setting`（`dsh-setting` 提供 loader 与 `@Setting` 声明）。
- **日程已全移除（决定 9）**：`endpoint/schedule.group.ts`、`contract/schedule.contract.ts`、`ui/conversation/schedule-slots.ts` 与 `provideSessionSlots()` 里的 `ScheduleSlots` 已删；包根 / `./server` 的 `ScheduleId` / `createAtScheduleRecord` / `ScheduleTask` / `ScheduleService` / `scheduleDomain` 导出全部去掉；`@deepseek-ai/dsh-schedule` 与 `@deepseek-ai/dsh-client-ui-schedule` 两个依赖也摘掉（`grep -rn schedule packages/agent/dsh-conversation/src` 为 0）。

**接口**：装配面只认 `provideConversationServer()` / `provideConversationUi()` / `provideDeliverables()` / `provideDeliverablesUi()`；`provideConversationServer(...features)` 的变参只作用于第一段（应用里用 `without(SessionQuerySqlite)` 换成 RDB 查询）。浏览器半与宿主半**不共享实现类**：跨域只经 `./contract`（`SessionController` / `conversation-client` 契约）与 `./endpoint`。

**契约面的 client-safe 判据**（决定 8 的落地形态）：`./contract` 的每个文件对 `@deepseek-ai/*` 只允许 `import type` / `export type`；要转出上游宿主包根上的**值**时，落包根（`src/index.ts`）。当前包根承担三处：`SessionSkillCatalog`、`ScheduleId` + `createAtScheduleRecord`、`foldSessionTitle`——它们在上游没有 client-safe 子路径，只能住宿主面。**越界的代价是构建立刻红**，不是"体积大一点"：vite 把 `node:*` 映射到 node-stub，缺具名导出即 `MISSING_EXPORT`。历史上这条路（`better-session` 的 ui → 本包 `./contract` barrel → `schedule.contract.ts` 的值转出）把 `schedule` / `core/session` / `interaction/user-approval` 三个宿主树带进 client 图，`just custom build` 报 338 个错误；按本判据改完为 0。

**深度**：删掉本包，会话组的端点装配与「建会话后归工作区」要回到 `apps` 的清单里，交付物的四条路由与卡片注册也要各写一遍——装配知识与界面知识散到多处，所以它有深度；但它不产生领域能力（会话内容、权限、工作区状态都在下层），所以它对上层是**局部性**而不是杠杆。

## 四、行为与边界

- **正常路径（建会话）**：`session/create` → 上游建会话 + 起 agent → 本行的包装按 `workspaceId`（没给就按 `cwd`）`attach` 到工作区 → `workspace/follow` 推 `upsert`，侧栏出现会话行。
- **错误（归属失败）**：`attach` 抛错只 `console.warn` 留痕、不抛——「建会话」这个动作不因归属失败而失败。会话因此可能不在任何工作区的 `sessionIds` 里，见债务 建会话时 workspace 挂载失败不回滚 agent。
- **交付物路由的参数错**：`/api/present.host` 回 200，其余三条在参数不对时回 400；**404 表示路由没注册**（`webServer` 前缀没装或 `workspaceChanges` 缺行）。
- **生命周期**：`SessionControllerDefault` 在 dispose 时收敛上游 scope 与 manager 的静默期；`LiveSessionRemotes.$stream` 的流按上游 `RemoteStream` 的生命周期随连接换代重发基线。

## 六、取舍

- **本仓重写一份会话端点**：上游那一族的语义靠踩坑得来（`follow` 只发一帧、`control` 的投影增量没人推、`(request, signal)` 的签名分派），重写等于把坑再踩一遍。
- **为交付物单独立包**：同一 `conversation` `Definition` 只能有一个 home；立包要么两份注册、要么再开一条转出口。
- **把 `FileReferenceServiceRow` 移出清单换「会话能建」**：`@` 候选是输入区的一等能力，移出去只会让端点没有实现。
- **会话界面留在 `dsh-session`**：界面与会话端点属对话场景，数据面才属会话域；两边混在一起就是「会话包同时是界面装配站」。
- **per-agent 的行各装一份实例**：分层需要全局实例（上游用 `scopeOf(ctx)` 读层），按实例分身会把状态分错层。

## 七、不做与已知债

- 不实现会话数据面（store / 查询 / 投影 / token 计量）——那是 `dsh-session` 的。
- 不实现工作区状态机与目录选择——那是 `dsh-workspace` 的。
- 不实现设置文档与 schema——那是 `@morlay/zephyr-app` 的 `Setting` 与 `dsh-setting` 的 loader。
- 债务 [建会话时 workspace 挂载失败不回滚 agent](../debts/20261030-建会话时-workspace-挂载失败不回滚-agent.md)。
- 债务 [包级依赖图有故意的环](../../../.agents/debts/20261030-包级依赖图有故意的环.md)。

## 八、开放问题

1. **交付物标签不进标签条**：`DeliverablesSlots` 注册到侧栏右面板的独立实例上，面板读自己那一份。要么让面板读同一个实例（上游 `ui-sidebar-right` 的注入面），要么接受「卡片有、标签没有」。
2. **本包直接 import 34 个上游包**：与设计 20261109-核心能力与BFF分层 的开放问题 1 同一条（哪些该收回各域）。
3. **契约面的框架说明符**：`api-session.contract.ts` / `session-title.contract.ts` 的 `AssertCovered` / `AssertTrue` 仍从 `@morlay/zephyr-app` 包根取，按定稿（覆盖断言走 `@morlay/zephyr-app/client`）应换成后者。`session-controller.contract.ts` 的 `Injectable` 从 `@morlay/zephyr` 包根取是**定稿口径**（DSL 两端共用包根，没有浏览器专用第二说明符），不用改；契约面里要造适配行时 `fromCordis` / `kFace` 走 `@morlay/zephyr/compat`。
4. **`@` 候选的 per-agent 分层是否够**：`FileReferenceServiceRow` 靠 `@AgentScoped()` 声明 + 上游的 `scopeOf(ctx)` 落地；出现第二个 per-agent 行时要不要在框架层做机械核对（当前只有标记与注释）。
