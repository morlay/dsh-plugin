# 上游 `session` 的 5 个端点本仓没有声明（无消费方，需要时补）

状态：未销账——契约里不声明 `observeEvent` / `observeProjections` / `observeState` / `state` / `wait`；宿主是上游控制器（端点本来就在），缺的只是**我们的 wire 描述符**（`remote.session` 面由本仓 `SessionEndpointClient` 的 `$mount` 决定）
位置：`packages/agent/dsh-session/src/endpoint/session-endpoint.ts`（`@RemoteGroup({ name: "session" })` 契约）；上游出处 `vendor/deepseek-harness/packages/api/session-controller/src/index.ts`（`@Remote` 方法）与 `lib/typert.remote-client.ts`（`session/*` 的 25 个端点）

**现象**

上游 `session` 组有 25 个端点；本仓契约声明 20 个。差集是这 5 个：`observeEvent`、`observeProjections`、`observeState`、`state`、`wait`（`rg 'remote\.session\.(observeEvent|observeProjections|observeState|state|wait)\(' vendor/deepseek-harness/packages --glob '!**/tests/**'` 零命中）。

**影响**

现在没有消费方，所以没有可观察故障。风险在于「上游某天开始用它们」：届时 `ctx.remote.session` 上找不到这个方法（面由我们的描述符建），报的是 `is not a function`，而错误点离装配面很远。

**触发条件**

上游客户端（`ui-*` / `api/session-controller/client`）开始调用这 5 个中的任意一个，或本仓要读 `state` / `wait`（例如做「等这一轮结束」的状态机）。

**销账条件**

Done when：契约里补上这 5 个端点（类型直接取上游别名、位置形参 + `parameters`，客户端形态跟着加），且 `AssertWireFace` 的覆盖清单从 20 变 25；`rg 'observeEvent|observeProjections|observeState|wait\(' packages/agent/dsh-session/src/endpoint/session-endpoint.ts` 有命中。

**不修的理由**

YAGNI：没有消费方就先不声明。声明它们意味着契约、客户端形态、替身、判据一起扩（`state` / `wait` 还要想清「谁来等」的语义），属于「有需求再做」的一类，不该混进 wire 对齐那一轮。
