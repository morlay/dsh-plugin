# 上游会话端点：适配面剩下的缺口

- **状态**：已按新 zephyr（cordis DSL）落地；本文件只记仍然成立的缺口。

## 现状（已不是债，记下来免得重踩）

- `session` 组的端点由上游 `@deepseek-ai/dsh-api-session-controller` 的 `SessionController` 提供
  （`packages/agent/dsh-session-api/src/server/api-session.provide.ts` 的 `ApiSessionControllerHost`）。
- 上游 `apply` 里 `ctx.plugin(...)` 挂的子插件（`file-references` / `media-references` / `skill-catalog` /
  `archived-session-gate`）**在行 ctx 下自己装载**：`fromCordis` 的 `mount` 把 `plugin` 绑到真 ctx。
  清单里不要再复制它们——复制就是重复注册（`/api/file` 注册两次，整行装不上）。
- 适配行不再有"第二个令牌"：`Conversation` 这类上游内部服务是上游行的实现细节，消费方用那一行发布的
  装配面契约（`UiConversation` 等）。按名字转发（`namedRoot` / `publishServiceNameOf`）那套已删除。

## 仍然成立的缺口

1. **上游会读没写进 `static inject` 的服务**（`ctx.connection.fetch`、`ctx.invocation`）：
   这类必须在 `mount` 的 deps 里显式给。漏了不会立刻失败，而是在第一次用到时
   报 `Cannot read properties of undefined`——失败点漂得远。装上游行时按它的**代码**（不只是 `static inject`）
   核一遍 deps。
2. **`session/prompt` 经 `typertGateway` 返回 `undefined`**（断言期待 `{ accepted: true }`）：
   命中已确认是 `sessionController`、实参也按 `(request, signal)` 传了，怀疑 `@Remote('prompt')`
   装饰器包装后丢了返回值（见 `typert/protocol` 的 `Remote` 实现）。未修。
3. **`fromCordis` 单参形态待淘汰**：`fromCordis(上游插件)` 不带契约时令牌从插件名派生，
   类型面是上游实例，跨包消费方失去"契约即令牌"的约束。补法是照抄 `api-session.contract.ts` 的样板：
   抽象类 + 成员类型取上游实例 + `AssertCovered` 守卫。
