# 通道只做转换（`packages/context/dsh-context-assembler` 的职责边界与内容转换数据）

状态：已实现（包根即通道本体；通道只剩三个消费者面与两处送达；三份默认清单是现行转换数据）
范围：本包两个出口（`.` = 通道本体 / `./rows`）的边界、通道留什么与为什么、三份默认清单的归属与跨包接缝、
`setInstructions` 的真实语义与代价、验证判据。
包内算法（信封渲染、幂等判定、工具面过滤、黑名单优先级）不在本文；按会话的工具收口与两个注入抑制面归
[`@morlay/dsh-session-mode`](../../../../profile/dsh-session-mode/README.md)（那边
[设计 抑制官方注入面](../../../../profile/dsh-session-mode/.agents/designs/20260929-抑制官方注入面.md)）。
约束：上游 `@deepseek-ai/*` 只读（`vendor/**`）；通道不引用注入方（工具说明的数据住
[`@morlay/dsh-tool-guidance`](../../../../profile/dsh-tool-guidance/README.md)）；行清单的真源在
[`src/rows.ts`](../../src/rows.ts)。

## 结论摘要

| 议题              | 结论                                                                                                                                        | 一句话理由                                                                                  |
| ----------------- | ------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------- |
| 通道的职责边界    | 留三个消费者面（`replaceSection` / `suppressSection` / `setInstructions`）与两处送达（降级 section 的按步注入、`agent/request-error` 补投） | 改装配结果只有 `system-prompt/assemble` 一个位置，按步送达只有 `agent/pre-step` 一个接缝    |
| 包根与出口        | 包根（`.`）就是通道本体；**没有别的插件出口**                                                                                               | 只剩一项时它是同义反复，最薄的做法是包根即那一份                                            |
| 通道公开面        | 不给扩展点：没有注册面，消费者面只有 `replaceSection` / `suppressSection` / `setInstructions`                                               | 现在没有生产者/消费者（接管上游 kind 的诉求随"两面归官方行"一起消失）                       |
| 三份默认清单      | 住 [`defaults.ts`](../../src/defaults.ts)，由包根的 `Config` 缺省引用；跨包接缝走**运行期** `suppressSection`                               | 清单是插件 config 的缺省（谁装这一行谁得到这份转换）；`drops` 是 `tool-guidance` 自己的数据 |
| 按会话收口        | **不在本包**：收口的输入是模式定义、唯一消费者也是模式，所以它住 `session-mode` 行内部（`SessionScope`，不是服务）                          | 只为一个消费者发布进程级服务，是白拿一份必须对齐的公开面                                    |
| `setInstructions` | 只关通道这一侧的降级注入；官方那两行的注入由 `session-mode` 在 `agent/pre-step` 上丢                                                        | 通道没有官方注入的接缝；两个抑制面各有各的收法                                              |
| 各面的归属        | 工作区指令 → 官方 `agent-instructions` 行；技能目录与 `skill` 工具 → 官方 `tool-skill` 行；工具说明汉化与用法分组 → `tool-guidance` 的包根  | 官方行自带注入方式，本包只做装配结果上的文本改写与丢弃                                      |
| 验证              | 包内 5 个 spec + 装配静态 2 个 + 真装配探针 1 个 + 链接检查 1 条                                                                            | 每条结论都有可核查的断言点或探针                                                            |

## 事实基线

### 通道保留的动作与上游判据

| 动作                                           | 代码位置                                                                                              | 上游机制                                                                                                           | 为什么只能在这里                                                                                                                         |
| ---------------------------------------------- | ----------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------- |
| `replaceSection`：装配结果上换 section 文本    | [`channel.ts`](../../src/channel.ts)、[`index.ts`](../../src/index.ts)                                | `system-prompt/assemble` 是 `ctx.waterfall`（`core/system-prompt/src/index.ts`）                                   | section 名唯一、**同层**重复注册抛错，scoped 才遮蔽 global；host 平面改不了 preset scope 里注册的 section                                |
| `suppressSection`：丢弃 section                | [`channel.ts`](../../src/channel.ts)、[`index.ts`](../../src/index.ts)                                | 同上                                                                                                               | 同上；"这条不该进提示词"是装配期事实，越早丢越省 token                                                                                   |
| 降级：`keep` 之外的 section 改以 reminder 送达 | [`index.ts`](../../src/index.ts)                                                                      | `agent/pre-step` 的 `decision.messages` 就是上游按步注入的接缝（官方 `agent-instructions` 与 `tool-skill` 都走它） | 降级文本来自**本步装配结果**（随会话变），注册表里没有它，官方也没有"装配剩余物"的送达面；注入点紧随本步认领消息之后（对齐官方行的落点） |
| `agent/request-error` 补投                     | [`index.ts`](../../src/index.ts)                                                                      | 上游只在**首次尝试**落库 `decision.messages`，重试是同一批消息的再请求                                             | 压缩会吃掉早期 reminder，重试不重跑 `pre-step`——不补写进会话，这次请求就没有这份内容                                                     |
| `setInstructions`：按会话关掉降级注入          | [`channel.ts`](../../src/channel.ts)、[`scope.ts`](../../../../profile/dsh-session-mode/src/scope.ts) | 通道自己的按 agent 状态（`session-mode` 的收口拨过来）                                                             | 上游没有"按会话关注入"的面；这是通道唯一按 agent 的状态                                                                                  |
| 规则声明常驻提示词                             | [`index.ts`](../../src/index.ts)、[`rules.ts`](../../src/rules.ts)                                    | 系统提示词 section（固定文本）                                                                                     | 声明一次，每条 reminder 只带 id 与正文；固定文本不随会话变、不付缓存代价                                                                 |

边界外侧（本包不做的）：注册 section（除自己的规则声明）、发布目录、注册 skill、注册规则、读工作区指令、
按会话修剪内容与工具面。工具的投影与执行收口是 `session-mode` 的收口那一侧的事，不是通道的事。

### 三份默认清单

| 清单                                                         | 内容                                                                                                        | 判据（为什么是它）                                                                                                                              | 覆盖                                                                                                       |
| ------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------- |
| `DEFAULT_KEEP`（[`defaults.ts`](../../src/defaults.ts)）     | 上游 persona 前缀 / 后缀常量 + `assembler:rules`                                                            | persona 是"权威 + 要插值"的文本：装配结果是**未插值**文本，而 reminder 正文按原样送达、不再插值——把带 `{{cwd}}` 的 persona 降级会漏出字面量令牌 | [`defaults.spec.ts`](../../src/__tests__/defaults.spec.ts)（只断言非空，**弱**）                           |
| `DEFAULT_SUPPRESS`（[`defaults.ts`](../../src/defaults.ts)） | harness 开场白 / 平台运维说明 / `app:web-surface` / 本部署不装配的五个工具说明                              | 身份由模式 persona 给（开场白进提示词就是重复）；不装配的工具不该送它的用法                                                                     | [`defaults.spec.ts`](../../src/__tests__/defaults.spec.ts)（`harness:*` 的名字从上游源码取，上游改名会红） |
| `DEFAULT_REPLACE`（[`defaults.ts`](../../src/defaults.ts)）  | 两段上游说明的忠实中译（`context:file-reference` 在 agent 层、`ui:deliverable-file-references` 在 host 层） | 这两段 section 的注册层不归我们，换文本只能发生在装配结果上                                                                                     | 无专门 spec（由 `replaceSection` 的行为测试覆盖）                                                          |

**没兜住的**：`tool:lsp` / `tool:pty` / `tool:session-query` / `tool:cordis` / `tool:ralph` 是字面量，上游改名
不会红（只有 `harness:*` 那两条走了源码比对）。

清单归属的三条事实：

- 它们住包根（`Config` 的缺省）而不是 `./rows`：`rows` 出的是**装配层引用的那一行**（形状与 id 见
  [`rows.ts`](../../src/rows.ts)），清单是插件 config 的缺省——引用方向相反，装配层引用 `rows`，
  插件自己引用 `defaults`；
- `keep` / `suppress` / `replace` 是可覆盖的 config（[`index.ts`](../../src/index.ts)），但
  `z.array` / `z.dict` 的缺省只在 `undefined` 时生效：部署要覆盖就得**重列**默认清单。本部署三处都没覆盖
  （通道那一行不带 config，[`rows.ts`](../../src/rows.ts)）；
- 跨包接缝走运行期，不走 config：谁维护"被丢弃的上游说明"谁列 `drops`，见下节。

### 跨包接缝：`tool-guidance` 的 `drops` → `suppressSection`

方向是单向的：通道不引用注入方；`tool-guidance` 行 `inject` 里含 `contextAssembler`
（[`index.ts`](../../../../profile/dsh-tool-guidance/src/index.ts)），装配期把每组的
`drops` 逐条注册成抑制项（同上）。数据住
`tool-guidance`（例：`group-team.ts` 的 `team:policy`、`group-delegation.ts` 的三条）——判据是"要点已吸收进该组正文，
原文不再进提示词"。这是通道在别的包里的两个消费者之一（另一个是 `session-mode` 收口的 `setInstructions`）。

### `setInstructions` 的真实语义与代价

**语义**：`session-mode` 的收口把 `mode.instructions !== false` 拨给通道
（[`scope.ts`](../../../../profile/dsh-session-mode/src/scope.ts)），通道按 agent 记下来，`collect` 直接返回空
（[`channel.ts`](../../src/channel.ts)）——它管的**只有降级 section 的按步注入**。

**这条开关之外的两条注入面由 `session-mode` 在 `agent/pre-step` 上收**（同一个 `instructions` 开关管官方
`agent-instructions`，`skills` 开关管官方 `skill-catalog`）；**收不到的**只有 `tool-guidance` 的工具投影与 `base` 组
常驻正文——那一条是按"常驻就是常驻"定义的，不读任何模式开关。

| 内容                             | 谁送                         | `instructions` / `skills` 开关管得到吗                                                 |
| -------------------------------- | ---------------------------- | -------------------------------------------------------------------------------------- |
| 降级 section（通道自己的规则块） | 本包通道                     | 管得到（`setInstructions`，`collect` 返回空）                                          |
| 工作区指令（`AGENTS.md`）        | 官方 `agent-instructions` 行 | 管得到（`instructions: false`，收口在 `agent/pre-step` 上丢掉那条消息）                |
| 技能目录（`<available_skills>`） | 官方 `tool-skill` 行         | 管得到（`skills: false`，同上）；`skill` 工具的可见性归 `allowTools`                   |
| 工具描述汉化与 schema 精简       | `tool-guidance` 的包根       | **管不到**（装配投影上按名字改写，`drops` 按 section 名抑制，都不认会话开关）          |
| `base` 组常驻正文                | `tool-guidance` 的包根       | **管不到**（正文按这个会话装配结果的最终目录过滤，但过滤不读开关——它按"常驻"定义自己） |

动态快照另有开关（`runtimeContext: false` → 收口按 agent 调 `systemPrompt.suppressRuntimeContext()`，
[`scope.ts`](../../../../profile/dsh-session-mode/src/scope.ts)），与上面两个不是一件事。

### 装配面（行与出口）

- 通道行 `context-assembler`（[`rows.ts`](../../src/rows.ts) 的 `contextChannel()`）由
  [`@morlay/session-mode-profile`](../../../../bundles/session-mode-profile/cordis.patch.yml) 的 patch 渲染（拼装在它的
  `src/index.ts`，构建期由它的 `tsdown.config.ts` 写出包根那份 `cordis.patch.yml`），**行不带 config**——包根就是
  通道本体，config 是那三份缺省。
- 现行出口两个：`.`（包根 = 通道本体，[`src/index.ts`](../../src/index.ts)）与 `./rows`（那一行，不是插件）；
  入口由 [`tsdown.config.ts`](../../tsdown.config.ts) 的 `entries` 推导，写回 `exports` / `publishConfig.exports`。
- 通道装一次、不隔离：跨包消费者（`tool-guidance` 的包根、`session-mode` 的收口）靠 `inject` 或 `ctx.get` 拿到
  同一个服务，理由见 [ADR-通道作为全局服务装配不隔离](../adrs/20260923-通道作为全局服务装配不隔离.md)。

## 取舍

| 选项                                                              | 为什么否掉 / 为什么留                                                                                                                                                                            |
| ----------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 通道继续持有各面（`registerRule` / `registerSkill` / 按会话修剪） | 官方两行 + 官方 `ctx.skills` + `session-mode` 的收口各自已经有了；自建一份就得跟上游的 kind 认领、目录 digest、工具可见性判据一一对齐，维护面远大于一处文本转换                                  |
| 只留 `suppress`、把 `replace` 交给各注册方自己改文案              | 上游 section 的文本不在我们手里：同名遮蔽跨不了平面，同层重复注册抛错——换文案只能发生在装配结果上                                                                                                |
| 降级送达交给上游（例如把要降级的内容注册成官方 skill）            | 官方 skill 的正文来自注册表（静态），而降级内容来自**本步装配结果**（随会话变）；官方目录与正文的送达判据是它自己注册的工具身份                                                                  |
| 每步重发全部降级文本                                              | 幂等按键（`section:<section 名>`）+ 逐字比较，重发只来自压缩与内容变化                                                                                                                           |
| 把 `keep` 缩到只留规则声明（persona 也降级）                      | 降级发生在插值之前，带 `{{cwd}}` 的 persona 会漏出字面量令牌；且 persona 是每个模式的权威提示词位置                                                                                              |
| 收口留在本包（`./scope` 出口发布服务）                            | 收口的输入与唯一消费者都是模式：留在本包就得发布一个只有那一行用的进程级服务，还要把"模式定义"的形状跨包定义一遍（`rows` 出口里也没有它那一行）                                                  |
| 包根保留组装语义（`capabilities` 表）                             | 只剩一项时它是同义反复；包根直接就是通道本体最薄，装配行的 config 也随之消失                                                                                                                     |
| 通道公开面按消费者收窄（只导出三个面）                            | 是（接口就是测试面：跨包消费者只有 `tool-guidance` 的 `suppressSection` 与 `session-mode` 收口的 `setInstructions`），但 `isSuppressed` / `replacement` / `collect` / `sync` 由同包的 `apply` 用 |
| 收口把白名单与黑名单分头算                                        | 三处判据（目录投影、`tool:` section、执行 guard）只要有一处分头算就会漂移；合成一份、`apply` 时算一次，判定函数只读它                                                                            |

决策与理由的 home 是各自 ADR：
[ADR-提示词注入只有一个通道且按需内容走skill](../adrs/20260921-提示词注入只有一个通道且按需内容走skill.md)、
[ADR-通道作为全局服务装配不隔离](../adrs/20260923-通道作为全局服务装配不隔离.md)。
