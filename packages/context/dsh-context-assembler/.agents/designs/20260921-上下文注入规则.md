# 上下文注入规则（`packages/context/` 各包注入给模型的形态与覆盖语义）

状态：已实现
范围：`packages/context/` 各包注入给模型的形态、覆盖语义与分层，以及本层的装配面（只有通道一行）。各包的内部算法
（引用发现、正文渲染、工具分组）在包内；按会话的工具收口与三个注入开关归
[`@morlay/dsh-session-mode`](../../../../profile/dsh-session-mode/README.md)。本层只做转换的职责边界与取舍见
[设计 通道只做转换](./20260929-通道只做转换.md)。
约束：上游 `@deepseek-ai/*` 只读；规则块只有注入通道一个写入口。

## 结论摘要

| 议题   | 结论                                                                                                          | 一句话理由                                             |
| ------ | ------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------ |
| 两类块 | 规则块（持久的系统级指令，id 必带、参与覆盖）与内容块（这一刻要看的材料，不参与覆盖）                         | 信封与语义不同，混用会让覆盖失去边界                   |
| 写入口 | 本层只有通道写规则块（降级 section）；工作区指令与技能目录由官方行自己的送达面写                              | 官方行自带注入方式，"这一面归谁"不是我们能收的事实     |
| 幂等   | 键（规则块用 id、内容块用 skill 名）相同且正文**逐字相等**才不重发                                            | 重发只来自压缩与内容变化，与轮次、进程无关             |
| 分层   | 目录常驻、正文按需（官方 `tool-skill`）；工具用法由 `tool-guidance` 自己常驻送达；降级 section 由通道按步送达 | 每类内容谁产生谁送达，通道只对装配结果上剩下的那段负责 |
| 包边界 | 通道就是包根，`rows` 只出那一行；引用展开独立成包                                                             | 通道消费者跨包，隔离会把它们挡在组外                   |
| 装配   | 通道一行装一次、不隔离；按会话的收口归 `session-mode` 行本身（没有单独一行）                                  | 同一份通道服务供整个部署                               |

## 事实基线

### 两类块与 id

规则块是持久的系统级指令（参与覆盖），内容块是这一刻要看的材料（一次性，不参与覆盖）：

```html
<!-- 规则块：本层只有通道写它，id 必带，同 id 覆盖 -->
<system-reminder id="section:plan:policy">…</system-reminder>

<!-- 内容块：技能正文与引用的材料，不带 id -->
<skill_content name="tool-group-base">
  <skill_instructions>…</skill_instructions>
</skill_content>
<file_content path="src/a.ts">…</file_content>
```

官方那两行也写 `<system-reminder>`，但**不带 id**，覆盖由它们自己的账本判定
（[`agent-instructions/src/render.ts`](../../../../../vendor/deepseek-harness/packages/context/agent-instructions/src/render.ts)、
[`tool-skill/src/index.ts`](../../../../../vendor/deepseek-harness/packages/skill/tool-skill/src/index.ts)）——系统提示词里的
规则声明因此按"带 id 的块以 id 为准、其余按来源"说
（[`rules.ts`](../../src/rules.ts)）。

规则块 id 的解析规则是「第一个冒号前是 owner，key 可含 `:` 与 `/`」
（信封渲染见 [`reminder.ts`](../../src/reminder.ts)）；id 只放稳定标识，不放 seq / 时间 / digest
这类易变值：

| 注入方                                      | 规则块 id                                          | 覆盖粒度     |
| ------------------------------------------- | -------------------------------------------------- | ------------ |
| 降级 section（本层通道）                    | `section:<section 名>`（如 `section:plan:policy`） | 每个 section |
| 工作区指令（官方行）                        | 不带 id（自带账本按 kind 与 baseline 身份认领）    | 整份基线     |
| 技能目录（官方 `tool-skill`）               | 不带 id（按它自己注册的工具身份判可见性）          | 整份目录     |
| 工具用法常驻正文（`tool-guidance`，内容块） | 不带 id，幂等键是 skill 名                         | 每个组       |

内容块两种：**skill 正文一律是 `<skill_content>`**——官方目录与按需加载、`tool-guidance` 的 `base` 组常驻送达同一形态，
区别只在「谁触发」；引用展开的文件是 `<file_content>`
（[`dsh-reference/src/file-content.ts`](../../../dsh-reference/src/file-content.ts)）。

组 skill 是**虚拟 skill**（运行时注册、没有资源目录），所以正文只有 `<skill_instructions>`，不带上游
`<skill_resources>` 那段；官方目录按名字与摘要发布，正文由 `skill` 工具按需取。

### 覆盖与幂等

**覆盖只适用于规则块**：同 id 的最新一条取代更早的同 id 条目，不重写会话历史。规则在系统提示词里声明一次
（[`rules.ts`](../../src/rules.ts)，随 `assembler:rules` section 常驻），因此任何一条 reminder 都只带
id 与正文，不重复解释。

- **幂等键 = id**：同 id 最近一条的文本未变就不注入，变了才追加一条；
- **顺序**：同一步的多条按 id 字典序注入，不随注册顺序抖动；
- **压缩后**：早期 reminder 进摘要 checkpoint 时，按 id 逐条补回。

判据落在**已注入正文与本次要注入正文逐字相等**上（`latestReminderText` 读的是 surface 上同 id 的最近一条，
[`reminder.ts`](../../src/reminder.ts)）。所以重发只有两个来源，都不是「轮次」或「进程」：

| 情况              | 会不会重发 | 为什么                                                                                            |
| ----------------- | ---------- | ------------------------------------------------------------------------------------------------- |
| 服务重启后 resume | **不会**   | surface 由完整会话日志折叠而来，旧条目仍在 surface 上，逐字比得上                                 |
| 压缩              | 会         | 早期节点被摘要 checkpoint 覆盖，不再在 surface 上，属于「模型真的看不到了」（重试请求还会再补投） |
| 内容变了          | 会         | section 文案变了——旧正文对新事实已经过期                                                          |

### 分层：谁把什么送到模型

| 内容                              | 到达方式                                                                                                                                      | 归谁                                                        |
| --------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------- |
| 工作区指令（`AGENTS.md`）         | 每步自行 append（`agent/pre-step`）                                                                                                           | 官方 `@deepseek-ai/dsh-agent-instructions`                  |
| 技能目录                          | 目录常驻一行摘要、正文按需（`skill` 工具与用户手势）                                                                                          | 官方 `@deepseek-ai/dsh-tool-skill`                          |
| 工具用法（组）                    | 注册进官方 `ctx.skills`（目录由官方行发布）；`base` 组正文由 `tool-guidance` 自己挂 `agent/pre-step` 常驻，按该会话装配结果的最终工具目录过滤 | `@morlay/dsh-tool-guidance`（包根即运行时）                 |
| 降级 section（含规则类）          | 规则块，按 section 一条（`section:<名>`），紧随本步认领的消息之后                                                                             | 本层通道                                                    |
| 引用展开（skill 正文 / 文件内容） | 内容块：`<skill_content>` / `<file_content>`，当次材料                                                                                        | [`@morlay/dsh-reference`](../../../dsh-reference/README.md) |

**工具投影的收窄与文本转换都在装配结果上做**：`tool-guidance` 改工具描述与参数 schema，本层通道丢 section、
换 section 文本，`session-mode` 的收口按会话过滤工具目录与 `tool:<工具名>` section。没有一处去注册同名 section 遮蔽上游。

模式的两个注入开关**不止通道这一侧**（收口归 [`@morlay/dsh-session-mode`](../../../../profile/dsh-session-mode/README.md)
的 [`scope.ts`](../../../../profile/dsh-session-mode/src/scope.ts)）：

- `instructions: false` 丢掉**官方 `agent-instructions` 的每步注入**（在 `agent/pre-step` 上过滤掉那条消息），**并**拨
  通道的 `setInstructions(agent, false)` 关掉降级注入（`collect` 直接返回空，
  [`channel.ts`](../../src/channel.ts)）；
- 技能目录另有开关 `skills`（不写时按模式的工具名单推导）：`false` 丢掉官方 `skill-catalog` 的注入；
- 动态快照是第三个开关（`runtimeContext: false` → `agent.ctx.systemPrompt.suppressRuntimeContext()`），与上面两条
  不是一件事。

**收不到的**（都在官方行自己的送达面里，我们没有可收的地方）：官方 `tool-skill` 注册的**正文**（`skill` 工具按需取，
目录可以丢、正文只在模型调用时由工具返回）、`tool-guidance` 的工具投影与 `base` 组常驻正文（它按"常驻就是常驻"定义
自己，不读那三个开关）。

### 装配约束

| 约束                                   | 为什么                                                                                                                | 踩到时的样子                                                                         |
| -------------------------------------- | --------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------ |
| preset 里的行**不能发布进程全局服务**  | 上游 `agent-presets` 的 `leakedServices` 校验会拒绝装载整块 preset（`preset/agent-preset-registry/src/invariant.ts`） | `row(s) published process-global service(s) [contextAssembler]`，新建会话直接失败    |
| **按模式给提示词只能走 section**       | preset 里的行不能发布进程全局服务（上一条），而 `system-prompt` 正是发布 `ctx.systemPrompt` 的那一行                  | 用 `persona` 行（在 agent 作用域注册同名 `deployment:persona-*` section 遮蔽部署级） |
| **通道住 host 平面、不 isolate**       | 消费者跨包（`tool-guidance` 的包根在别的 patch 里 `inject` 它）                                                       | `tool-guidance: pending (waiting for service: contextAssembler)`，汉化与分组全不生效 |
| **读 skill 注册表要带 `cwd` 与作用域** | 本地发现是 preset 层的行，不带作用域只看得见全局层                                                                    | `~/.agents/skills` 与 `{cwd}/.agents/skills` 全都不进目录                            |
| **注入跟着工具走**                     | 不能用 `skill` 工具就没有技能目录，没有 `read` 就没有 `@path` 展开                                                    | 各注入方在送出前看工具可用性，而不是让每个模式去列「不要哪些」                       |
| `ctx.get(X)` 与 `ctx.X` 是两回事       | `ctx.get(X)` 不需要 `X` 在 `inject` 里声明，未提供时返回 `undefined`；只有属性访问 `ctx.X` 才要求声明，否则抛         | 「可选搭档」用 `ctx.get` 取——一个可选服务缺席不该让整行不激活（收口取通道就是这样）  |

装配形态（行清单的真源在代码里，不放 patch 副本）：

- 通道那一行写包名 `@morlay/dsh-context-assembler`（包根就是通道本体，config 是 `keep` / `suppress` / `replace` 的
  缺省，[`src/index.ts`](../../src/index.ts)、[`rows.ts`](../../src/rows.ts)）；**没有第二行**——按会话收口由
  `session-mode` 行内部持有（`SessionScope`），模式定义就是它的输入；
- 本部署把这一行渲染进 [`@morlay/session-mode-profile`](../../../../bundles/session-mode-profile/cordis.patch.yml)
  的 patch；
- 真装配的判据是
  `pnpm exec tsx packages/desktop/dsh-desktop-host/tool/verify-session-mode.mts`：装配层可见一份通道、`ctx.sessionToolScope`
  **不存在**、官方 preset 会话不受影响。

验证分三层：**包内静态校验**（`src/__tests__/`：信封、幂等、降级与改写、那一行的形状）、**装配静态校验**
（`dsh-session-mode` 的 `preset-plane.spec.ts` 与 `dsh-tool-guidance` 的 `guidance-inventory.spec.ts`：真 Loader + 真上游行
下的平面归属与工具面）、**真装配探针**（上面那条 `verify-session-mode.mts`）。测试落点在 `src/__tests__/`（根 vitest 的
include 是 `packages/**/src/__tests__/**`）；读上游文件的覆盖性测试用 `process.cwd()`（vitest 从仓库根跑）。

## 取舍

| 选项                                                   | 为什么否掉 / 为什么留                                                                                                                                    |
| ------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 保留一个注册面（注册 section / 注册 skill）            | 官方行与官方 `ctx.skills` + `tool-skill` 各自已经有了；自建一份就得跟上游的 kind 认领、目录 digest、可见性判据一一对齐                                   |
| 只留 `suppress`，把 `replace` 交给各注册方自己改文案   | 上游 section 的文本不在我们手里：同名遮蔽跨不了平面，同层重复注册抛错——换文案只能发生在装配结果上                                                        |
| 降级送达交给上游（例如把要降级的内容注册成官方 skill） | 官方 skill 的正文来自注册表（静态），而降级内容来自**本步装配结果**（随会话变）                                                                          |
| 每步重发全部降级文本                                   | 幂等按键（`section:<section 名>`）+ 逐字比较，重发只来自压缩与内容变化                                                                                   |
| 把 `keep` 缩到只留规则声明（persona 也降级）           | 降级发生在插值之前，带 `{{cwd}}` 的 persona 会漏出字面量令牌；且 persona 是每个模式的权威提示词位置                                                      |
| 包根只做组装（按 config 装能力，`capabilities`）       | 只剩一项时它是同义反复，包根直接就是通道本体最薄                                                                                                         |
| 收口在本包留一个出口                                   | 收口的输入（模式定义）与唯一消费者都在 `session-mode`：留在本包就得发布一个只有那一行用的服务                                                            |
| 收口走 `tools.restrict()`                              | 会触发 `tools/change`，与上游的 composition reconcile 互相触发（实测见 `session-mode` 的设计）                                                           |
| 让通道去关官方那两行的注入                             | 它们不经通道：官方每步重算 desired、自己往 `agent/pre-step` 里 append，通道那一侧没有这个接缝——要收只能在瀑布上丢（`session-mode` 的抑制面就是这么做的） |

决策与理由的 home 是各自 ADR：
[ADR-提示词注入只有一个通道且按需内容走skill](../adrs/20260921-提示词注入只有一个通道且按需内容走skill.md)、
[ADR-通道作为全局服务装配不隔离](../adrs/20260923-通道作为全局服务装配不隔离.md)。
