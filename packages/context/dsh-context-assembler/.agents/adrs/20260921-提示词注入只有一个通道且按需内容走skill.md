# 提示词注入只有一个通道，按需内容走 skill

状态：已采纳（实施于 [`assembler` 出口](../../README.md)，与 [`@morlay/dsh-agent-toolkit` 的 `guidance` 出口](../../../../profile/dsh-agent-toolkit/README.md) 的分发面一起工作）

背景：改动前，注入分散在三个地方——`dsh-context-assembler` 把 section 降级为 reminder，
`dsh-agent-toolkit` 的 `guidance` 出口自己注册「能力目录 / 按组提示」两个 section 并遮蔽上游逐工具说明，
两段部署文案的中文改写还得靠「本插件的 listener 排在 reminder 内层」这种顺序耦合。
同时上游逐工具说明（本部署实测约 7400 字符）被整段丢弃：既不常驻，也不可及。

**决定**

系统提示词只留 `keep` 名单内的 section；其余内容一律经 `ctx.contextAssembler` 一处登记与送达，
送达方式按内容声明为 **自动注入**（走 reminder 的 append 通道）或 **按需注入**（注册成 runtime skill，
目录常驻、正文按需加载）。分发方只给内容与可用条件，不再自己注册 section、不再遮蔽同名 section。

**考虑过的选项**

- **维持各插件自注册 section**：注入逻辑分散在两处，遮蔽要靠 agent 作用域的同名空文本，于是清单不能含
  任何按 agent 作用域注册的说明（`team:policy` 就这么炸过一次），且改动顺序敏感。
- **用 cordis 事件让分发方广播内容**：耦合更松，但契约不显式、调试时看不到谁登记了什么。
- **全部常驻 reminder（不注册成 skill）**：省一轮请求，但每个组的用法都常驻，注意力与 token 都不划算，
  且"渐进"无从谈起。
- **全部按需 skill（base 组也按需）**：最省常驻，但每个会话第一步都要先加载一次基础组用法才敢动手文件。
- **上游说明继续丢弃**：省 token，但把上游已经写好的工具知识白白浪费，模型只能靠 schema 猜边界。

**后果**

- 注入只有一处 home：`keep` / `suppress` / `replace` / 降级 / 物化都在 [channel.ts](../../src/assembler/channel.ts)
  一条流水线上；分发方改内容不动通道，通道改到达方式不动分发方。
- 同名空文本遮蔽机制删除：改为在装配结果上过滤，于是「清单不能含 agent 作用域注册的说明」这条约束消失，
  覆盖性测试不再需要扫全树判断注册层。
- 顺序耦合消失：改写与降级都发生在通道自己的瀑布里，不再要求调用方排在内层。
- 上游逐工具说明从丢弃变为可及：要点写进对应组的 skill 正文，按需加载；代价是正文由本仓库维护
  （`drops` 清单要跟上游 section 名，覆盖性测试兜住）。
- 常驻内容按条目幂等：档位变化只重发受影响的那一条 reminder，不是整段重发。
- 已知限制：`on-demand` 的正文由声明方按会话现算（`contentFor`），装配期注册进 skill 注册表的那份是
  不按会话过滤的全量；正文变化只更新加载结果，不改目录摘要，所以不会触发 skill 目录重发。
