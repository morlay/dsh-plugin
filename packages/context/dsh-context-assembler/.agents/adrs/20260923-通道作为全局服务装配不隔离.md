# 通道作为全局服务装配，不隔离

状态：已采纳

背景：通道的消费者**跨包**：工具说明那一行（`@morlay/dsh-tool-guidance`）由 `session-mode-profile` 的 bundle patch
装、汉化与用法分组数据也归那个包。它 `inject` 通道，却拿不到被关在 `isolate` 组里的服务——症状是行停在
waiting 且不报错：`tool-guidance: pending (waiting for service: contextAssembler)`，描述替换、schema 精简与
用法分组全不生效。

**决定**

1. 通道由本包那一行装**一次**、**不 isolate**（[`rows.ts` 的 `contextChannel()`](../../src/rows.ts)），
   profile 平面的任何行、任何包都能 `inject` 到它。
2. 模式之间的差异不在通道上表达，改由 `@morlay/dsh-session-mode` 的收口登记（它由模式行内部持有，不是服务）：工具面（工具目录 + 与之同源的
   `tool:<工具名>` 说明 section，白名单与黑名单合成一份）、`instructions`、`runtimeContext`。
3. 探针 `verify-session-mode.mts` 的判据：装配层必须可见**一份**通道，任何 preset mount 里不得再有第二份；
   模式差异仍按成对判据守（chat 无动态快照、coding 有）。preset 子树的形态退出装配见
   [ADR 模式是preset的会话级扩展](../../../../profile/dsh-session-mode/.agents/adrs/20260928-模式是preset的会话级扩展.md)。

**考虑过的选项**

- **让 tool-guidance 行插进隔离组**（`- id: <组 id> insert: [...]`）：保住隔离，但要求别的包往这个组的 id
  里插行——跨包的装配耦合进一个组名，且以后每加一个消费者都要记得插进去（漏了就是静默 waiting）。
- **通道注册按 scope 分层**（`registerRule(ctx, …)` 之类）：能把"谁注册的只对谁的会话生效"做对，但要动
  通道整个公开面，改动面大于收益，且当前装配不需要。
- **每个模式各装一份通道**：模式之间确实不串，但跨包消费者解析不到服务（行停在 waiting，不报错）。

**后果**

- 通道全局一份：跨包消费者直接 `inject`；`tool-guidance` 激活，汉化（描述替换 / schema 精简 / 用法分组）
  真正生效——`just custom dev --web` 的启动 audit 没有 pending，端口与 URL 照常。
- 官方 shipped preset 的会话同样吃到我们的注入，这一层由会话级判据分开：工作区指令与技能目录都归官方行
  (`agent-instructions` / `tool-skill`)，我们的通道只做装配结果上的文本转换与降级送达
  （[设计 通道只做转换](../designs/20260929-通道只做转换.md)）。
- 模式差异的守卫落在 `@morlay/dsh-session-mode` 的收口：同一个名单集合同时管工具目录与 `tool:` 说明 section，避免
  "工具没了、说明还在"。
