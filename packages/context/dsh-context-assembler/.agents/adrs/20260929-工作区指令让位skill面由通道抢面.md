# 工作区指令让位，skill 面由通道抢面

状态：已采纳

背景：官方 preset 的行清单里有 `agent-instructions` 与 `tool-skill` 两行，住在注册表持有的 scope 里
（[`standard.patch.yml:16-37`](../../../../../vendor/deepseek-harness/packages/bundle/web-app/presets/standard.patch.yml)；
`ptc` 同；[`cordis.patch.yml:19-20`](../../../../../vendor/deepseek-harness/packages/bundle/web-app/presets/cordis.patch.yml)
与 [`:148-149`](../../../../../vendor/deepseek-harness/packages/bundle/web-app/presets/cordis.patch.yml)；`minimal` 两者都没有），
而官方 web-app 把 host 平面的同名三行设成 `disabled: true`
（[`web-app/cordis.patch.yml:485-488`](../../../../../vendor/deepseek-harness/packages/bundle/web-app/cordis.patch.yml)、
[`:549-550`](../../../../../vendor/deepseek-harness/packages/bundle/web-app/cordis.patch.yml)）。本部署保留官方 preset
整套，同时在 host 平面装一份本包的通道
（[`session-mode-profile/cordis.patch.yml`](../../../../bundles/session-mode-profile/cordis.patch.yml) 的
`context-assembler` 行），于是同一个会话两侧都注入。真装配一步（`standard` 行清单，`#` 后面是 source 的 `id`）：

```
['user', 'agent-instructions#agent-instructions:<rootTag>:AGENTS.md', 'skill-catalog',
 'agent-instructions#-', 'skill-catalog#-']
```

两条工作区指令的口径与幂等键都不同（上游一条模板盖全部文件，我们一条文件一条 id），两份技能目录同理——
模型无法把后一条读成"作废前一条"。

**决定**

1. **工作区指令让位**：该会话的 preset 行清单里启用着 `@deepseek-ai/dsh-agent-instructions` 时，这一面我们
   一条都不注入（[`preset-owner.ts`](../../src/agent-instructions/preset-owner.ts)）。判据取注册表的两个公开只读口：
   `composedPreset(agent.ctx)` 与 `compositionInventory()` 的 `rows[].moduleName` / `enabled`
   （[`agent-preset-registry/src/index.ts:290`](../../../../../vendor/deepseek-harness/packages/preset/agent-preset-registry/src/index.ts)、
   [`:354-357`](../../../../../vendor/deepseek-harness/packages/preset/agent-preset-registry/src/index.ts)）。
2. **skill 面抢面**：`skill` 工具按**会话**注册进 agent 自己那一层
   （[`agent.ctx.tools.register`](../../src/skill-catalog/index.ts)，随 agent 收回）。最近的一层赢，遮蔽 preset
   那一份（[`core/tools/src/index.ts:1185-1207`](../../../../../vendor/deepseek-harness/packages/core/tools/src/index.ts)），
   上游的目录发布判据是"它自己注册的那个工具是本会话可见的那个"
   （[`skill/tool-skill/src/index.ts:213-236`](../../../../../vendor/deepseek-harness/packages/skill/tool-skill/src/index.ts)），
   被遮蔽之后它不发目录，目录由我们发布。
3. **目录那条消息的 kind 是我们自己的**（`context-assembler` + `form: 'catalog'` + `entries`），不是上游那个
   `skill-catalog`：上游的目录监听器把任何 `kind: 'skill-catalog'` 且条目可读的消息当成**它自己的**账本
   （`catalogMessage` / `catalogHistory`）。抢面之后它的 skill 集为空，于是首步它会**删掉我们这一条**
   （`!history.published && skills.length === 0` 分支，
   [`tool-skill/src/index.ts:237-241`](../../../../../vendor/deepseek-harness/packages/skill/tool-skill/src/index.ts)），
   会话里已有可见目录之后它会补一条 `No skills are currently available…` 把目录顶掉——这就是它文档里写的
   visibility-loss 语义（[`tool-skill/README.md:59`](../../../../../vendor/deepseek-harness/packages/skill/tool-skill/README.md)、
   [`:84`](../../../../../vendor/deepseek-harness/packages/skill/tool-skill/README.md)）。kind 归我们之后它两个扫法
   都看不见我们，本会话彻底闭嘴；`form: 'catalog'` 与 `entries` 保住客户端那张条目表（客户端按 `form` 选呈现、
   条目读 source，[`event-projection.ts:48-58`](../../../../../vendor/deepseek-harness/packages/client/ui-chat/src/client/conversation-nodes/event-projection.ts)）。

**考虑过的选项**

- **由上游认领我们那条**（把 `baselineIdentity` 当主机制）：上游的认领判据只看本步 claimed 的消息与会话 surface
  （[`agent-instructions/src/index.ts:46-63`](../../../../../vendor/deepseek-harness/packages/context/agent-instructions/src/index.ts)），
  首步两侧各自算注入、谁都看不见对方那一条，重复照旧。身份保留，但它管的是另一件事：我们注入过基线的历史
  会话在 preset 会话里恢复时，上游认得出那条、不再补一份自己的模板。
- **skill 面也让位**（工具与目录都归上游）：最省事，但 preset 会话里模型的 `skill` 工具是上游那个（英文描述、
  正文不按会话修剪），本仓库要的中文描述与 `contentFor` 修剪在那类会话里就不生效——这正是要改的那件事。
- **保持上游 kind，让它的 digest 等于我们那份**（它就会保住我们这条、不发自己的）：它的 digest 只覆盖名字与
  截断后的描述，而我们的目录还会按 `requires` 隐藏 skill、描述按 `…` 截断——一处不一致它就补一条空目录把
  我们顶掉，判据太脆。
- **按装配层裁 `capabilities`**：`capabilities` 是装配期的一份 config（[`src/index.ts:32-42`](../../src/index.ts)），
  而"这一面归谁"是**会话级**事实（同一个部署里 `minimal` 会话要、`standard` 会话不要），装配期裁不出来。

**后果**

- 官方 shipped preset 会话（`standard` / `ptc` / `cordis` 带上游 `agent-instructions`，用户显式选它们时）：
  工作区指令由 preset 提供（我们让位）；`skill` 工具与技能目录由我们提供（中文描述、正文按会话修剪）。
- 本部署自己的 `mode-switch` 会话（两个模式共享它）：行清单里没有上游那两行，所以两条面都由我们提供；
  `chat` 的模式定义不收这两样（`instructions: false`、白名单里没有 `skill`）：白名单把它挡在模型目录外、执行层
  guard 拒绝调用（用例见
  [`skill-catalog.spec.ts`](../../src/__tests__/skill-catalog/skill-catalog.spec.ts)）。装配开关只收得住我们这一侧：
  目标 preset 自己带了注入行时，那份注入在它之外——所以切模式时该换的 preset 还要换
  （[ADR-自己注册preset](../../../../bundles/session-mode-profile/.agents/adrs/20260929-自己注册preset.md)）。
- 客户端：那条注入行的标签从 `skill-catalog` 变成 `context-assembler`（标签取 source 的 kind，
  [`event-projection.ts:60-77`](../../../../../vendor/deepseek-harness/packages/client/ui-chat/src/client/conversation-nodes/event-projection.ts)），
  条目表照旧。
- 这一行重挂（HMR / 设置面）：按会话的注册随 agent 留在 agent 那一层，重装时同一份定义不再注册第二次
  （同一层重复注册会抛），工具与目录照旧。
- 判据：[`preset-plane.spec.ts`](../../src/__tests__/preset-plane.spec.ts)（真注册表 + 真上游行 + 真 fs，两个装配顺序
  各跑一遍）与 [`skill-catalog.spec.ts`](../../src/__tests__/skill-catalog/skill-catalog.spec.ts)（重挂、chat 会话）。
