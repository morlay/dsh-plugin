# 文件引用内容注入（`@path` 在 pre-step 展开成 read 同形内容块）

状态：已实现（`@path` 起手的引用在 `agent/pre-step` 注入 read 同形内容块，读不出就保持普通文本）。
范围：`@morlay/dsh-context-reference` 的文件一半；引用解析器与渲染转换仍归
`@morlay/dsh-client-ui-primitives`（判定见 [ADR-引用的统一解析与渲染转换](../../../ui-conversation-message-actions/.agents/adrs/20260917-引用的统一解析与渲染转换.md)）。
约束：上游 `@deepseek-ai/*` 只读；本包不得依赖上游源码子路径（发布产物不含 `src/`）。

## 结论摘要

| 议题           | 结论                                     | 一句话理由                                                                                                      |
| -------------- | ---------------------------------------- | --------------------------------------------------------------------------------------------------------------- |
| 触发形态       | 只认 `@` 起手的 file 引用                | 注入跟随用户显式引用的手势（手打或选择器 pick）；`file:` 与 `[label](x)` 的官方语义是链接、不是「给我内容」     |
| 读取路径       | `ctx.fs`（resolve → stat → 文本）        | 与 read 同一个执行世界，沙箱与后端策略一并生效                                                                  |
| 读取能力       | `ctx.fs` 按可选能力取                    | 部署没有文件系统时，skill 注入不该跟着整个插件一起失效                                                          |
| 内容格式       | 本包按 read 信封自行渲染                 | 上游渲染函数不在发布面，跑工具运行时会多出一次模型没发起的调用                                                  |
| 内容之外的说明 | 注入消息里带一条中文 `<system-reminder>` | 不说明来源，模型会再 read 一遍同一段内容；中文与 persona 一致，`<system-reminder>` 是本部署 reminder 的既有形态 |
| 窗口上限       | 常量取 read 默认值                       | 同一条引用在 read 与注入两条路上看到同一个窗口                                                                  |
| 注入分组       | 本步的文件合成一条消息                   | 说明只说一次；`references` 只列这条消息里真的装了的引用                                                         |
| 读不出的引用   | 静默保持普通文本                         | 引用是手势、不是断言；一步不因读失败而中断                                                                      |

## 事实基线

- 解析面已经给出 file 引用与行窗口：`@a.ts`、`@a.ts:12`、`@a.ts:12:5`、`@a.ts#L12-L40`、`@[label](a.ts)`、
  `@"my file.ts"`（含空格路径的引号 mention）都归一到
  `{ protocol: 'file', path, lineStart?, lineEnd?, column? }`，且 `ReferenceSpan.start` 指向书写起点
  （`@` 或 `[`）——`packages/client/ui-primitives/src/reference.ts`。
- 插入侧把引用源给什么写法都归一到同一形态：`referenceTextOf` 先解析回结构化引用，再用
  `formatReferenceMention` 写出 `@path` / `@"path"`（`packages/session/ui-conversation/src/client/input/reference-text.ts`），
  所以「选择器选的引用」与手打同形同待遇——形态由 `ui-primitives` 这一份规则定义，与本包或选择器无关；
  行号不在生成侧（read 的窗口起点只由手写 fragment 提供）。
- read 的模型面输出是一个 text 块，正文为 `<path>` / `<type>file</type>` / `<content>` 信封 + `N: 行` + 续读
  footer；窗口语义（扫到 EOF 数总行、单行与整窗字节上限、`offset` 越过 EOF 报错）在
  `vendor/deepseek-harness/packages/fs/tool-fs/src/read-render.ts:102-170`。
- 本部署的 reminder 形态：`<system-reminder>` 包裹的文案作为一条注入 user 消息（
  `packages/context/dsh-context-assembler/src/reminder.ts`）——文件引用的说明跟随这一形态，只是与内容同处一条消息。
- 上游工具包不导出这些渲染函数：`vendor/deepseek-harness/packages/fs/tool-fs/src/index.ts` 的公开面只有
  `name` / `inject` / `Config` / `apply`；`package.json` 的 `files` 只含 `lib/**`，所以 `./src/*` 出口在已发布包里
  解析不到。
- 上游明确不做这件事：`dsh-file-reference` 的 Known Limitations 写着「No file-content reference object — 选中的
  文件只是普通提示文本，模型需要显式调用工具才能看到内容」（
  `vendor/deepseek-harness/packages/context/file-reference/README.md`）。

## 取舍

- **把 `fs` 放进 `inject`**：装配面看起来更严，但缺文件系统的部署会连 skill 注入一起失效——用一个可选能力换
  整个插件不加载，不划算。改为运行时取，缺了就只做 skill。
- **跑 `read` 工具运行时**：最保真，但会把一次模型没发起的调用送进 pre-execute / 审批 / 守卫管线，并触发
  `tool/result` 通知——凭空多出一条工具调用记录，且守卫与审批语义都会被误触。否掉。
- **复用 `@deepseek-ai/dsh-tool-fs/src/read-render.ts` 的 `buildWindow` / `formatReadOutput`**：源码面能引，但发布
  产物不含 `src/`，消费方解析不到；把上游源码拉进本包（薄壳 fork）成本远高于这 60 行窗口逻辑。否掉。
- **走 `ctx.tools.get('read')` 的 `output.render`**：仍要自己造结构化窗口，还要自带一套 caps 解析，等于两份逻辑都
  留下。否掉。
- **每个文件一条注入消息**：说明随每条重复（本步 3 个文件就重复 3 遍），消息数随引用数增长；合成一条后说明
  只说一次，信封块各自带着 `<path>` 仍可定位。否掉。
- **把说明单独发一条 reminder 消息**（照 `context-assembler` 的形态）：同一步有多个引用时说明会重复，模型还要
  自己把「说明」与「内容」对上；跟随内容同处一条消息更近。否掉。
- **把说明裹进信封里**（如 `<file_content note="…">`）：那就不是 read 的信封了，信封块要保持与 read 逐字同形
  （测试逐字锁着），说明只能落在信封之外。否掉。
- **认领 `file:`、`[label](x)` 与 inline code 里的路径**：会把用户写的链接、代码示例里的路径变成长文注入，且
  `[label](x)` 连原文都要改写。否掉。
- **把 caps 暴露成 Config**：目前没有部署侧要调的诉求，先按 read 默认值写死常量；真出现诉求再加 Config。
- **`column` 参与窗口**：read 的窗口只有行语义，列号无处可放（只能塞进提示文本），先丢弃。

## 开放问题

UI 侧的注入行标签不在本次范围：上游 client 对未知 source kind 的默认呈现是 `role: 'inject'` + 标签等于 kind
