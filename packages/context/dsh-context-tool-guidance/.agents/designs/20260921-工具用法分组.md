# 工具用法分组（dsh-context-tool-guidance）

状态：已实现
范围：本包的分组表、注入方式、回收清单与短描述投影。注入形态与 id 规则在
[上下文注入规则](../../.agents/designs/20260921-上下文注入规则.md)。
约束：上游 `@deepseek-ai/*` 只读；用法说明走 append 通道，判定依据见
[ADR-工具schema恒定而说明动态化](../adrs/20260920-工具schema恒定而说明动态化.md)。

## 结论摘要

| 议题     | 结论                                                 | 一句话理由                                                   |
| -------- | ---------------------------------------------------- | ------------------------------------------------------------ |
| 门控     | **不设**：所有工具始终可见可调用                     | 工具 schema 本就恒定可见；拒绝一次再教它解锁，不如直接让它用 |
| 分组     | `base`（常驻）/ `flow` / `team`（按需）              | 分组只决定用法说明怎么分批送达                               |
| 常驻判据 | 这一步不用它就没法开工的组（`base`）常驻，其余按需   | 基础工具每轮都可能用，等一轮加载不划算                       |
| 回收     | 每组的 `absorbs` 把上游工具说明与规则收进 skill 正文 | 那些说明既不常驻也不丢掉，拿到这组能力时一起读               |
| 短描述   | 装配投影里换成一行中文                               | 工具 schema 常驻，描述值得压；改投影不碰注册表               |

## 事实基线

- 工具定义走请求的 `tools` 参数，位置在 system 文本之后、全部 messages 之前；它的任何扰动（改标点、
  加参数、换序、增删）都让该请求整段重算（实测命中率 94% → 0~3.2%），而说明走 append 通道几乎不付代价。
- 上游逐工具说明注册成 `tool:<name>` section（`fs/tool-fs/src/read.ts:69` 等），`team:policy` 注册在
  **agent 作用域**（`experimental/tool-agent-team/src/index.ts:164`）。
- 改 `assembly.tools` 而不是注册同名工具：在 agent 作用域注册会同步触发 `tools/change`，而上游
  `tool-subagent` 用该事件做 composition reconcile（`subagent/tool-subagent/src/index.ts:710`）——
  两边互相触发会让装配风暴式重入，把 session 创建卡死。

## 取舍

- **取消门控**：门控需要元工具（`enable_tools`）、用户命令（`/tools`）、档位重建与"未归组工具"例外，
  而它换来的只是"模型先撞一次墙"。取消后模式（标准/协作）的差别也随之消失。
- **`base` 组常驻、其余按需**：判据是"这一步不用它就没法开工"。`web_search` 因此归 `base`——
  它与 `web_fetch` 是同一件事的两半，拆在不同层会让提示跨组指路。
- **正文自建 + 上游说明回收**：授权/使用单位是组，提示就以组为单位；上游已有的细节知识搬进正文按需加载，
  而不是丢进垃圾桶。代价是 `absorbs` 清单要与上游 section 名对齐（覆盖性测试兜住）。
- **短描述覆盖 `description`**：只换描述、转发执行与渲染。代价是描述与上游语义脱钩（上游改职责时要跟）。

## 已知限制

- **全量 schema 常驻**：短描述只压住描述那段，参数 schema 省不了。
- **`base` 组正文常驻**：它含回收来的上游说明，每会话进上下文一次；要改成按需只需在组表里改 `injection`。
- **回收清单要跟随上游**：上游新增说明或改 section 名时覆盖性测试变红，必须把新名字归到某个组或通道的丢弃清单。
- **正文按实际装配渲染**：装了 Agent Teams 才讲 `spawn_teammate` 那一套；本部署禁用 `planning`，
  正文里不提 `exit_plan_mode`。
