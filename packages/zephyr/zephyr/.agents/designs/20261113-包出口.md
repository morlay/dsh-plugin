# 包出口（zephyr 的三个面，按用途分、不按运行环境分）

状态：已实现——三个出口（`. ` / `./compat` / `./testing`），**包根两端共用**。
范围：本包对外几个面、每个面装什么，以及「不按运行环境分面」这条判据。
非目标：上层怎么装配、怎么在浏览器里挂载（上层文档引用本包，本包不反向解释）；上游只读副本。
关联：[公开接口](./20261104-zephyr-是-cordis-plugin-的语法糖.md) · [类型约束](./20261113-类型约束.md) · [如何写](../standards/how-to-write.md) · [如何验证](../standards/how-to-verify.md) · [术语](../GLOSSARY.md)

## 一、决定

| #   | 议题       | 决定                                                                            | 一句话理由                                      |
| --- | ---------- | ------------------------------------------------------------------------------- | ----------------------------------------------- |
| 1   | 面的划分   | 按**用途**分三个面：`. `（全集）、`./compat`（上游适配）、`./testing`（测试面） | 面是「谁用」，不是「跑在哪」                    |
| 2   | 运行环境   | 包根**两端共用**：DSL 与装配内核是同一份；cordis 在浏览器是合法运行期           | 浏览器的装配入口调的就是 `bootstrapApplication` |
| 3   | 内核用法   | 两端的装配入口都调同一个 `bootstrapApplication`；本包不判定自己在哪种运行时     | 内核只有一份，分面等于列两遍                    |
| 4   | 前端宿主角 | 不在本包：本包对 cordis 只有一个运行期引用（`bootstrap.ts`）                    | 边界要能被 grep 判                              |
| 5   | 判据       | 出口形状由 `src/__tests__/entry-shape.spec.ts` 四条钉住                         | 边界没有测试就是注释                            |

## 二、现状事实

**三个出口，`exports` 与 `tsdown` 的 `entry` 同名**：`.`、`./compat`、`./testing`（见 `package.json` 与 `tsdown.config.ts`）。

**包根把内核与 DSL 装在一起**：`bootstrapApplication` / `App` / `mountRow` / `Injectable` / `inject` / `EventEmitter` / `provide` / `configure` / `without` / `Logger` / `Debugger` 全在 `src/index.ts`。

**两端装的都是这份内核**：装配入口（无论跑在哪）调的是同一个 `bootstrapApplication`；本包不读运行环境，也不提供第二份。

**包根对 cordis 的运行期引用只有一处**：`src/bootstrap.ts` 的 `Context`；`injection.ts` / `logger.ts` / `compat/from-cordis.ts` 都是 `import type`（判据：`grep -rn 'from "@deepseek-ai/cordis' packages/zephyr/zephyr/src` 里只有 bootstrap.ts 不带 `import type`）。

## 三、模块边界与接口

| 面          | 拥有（职责与不变量）                                         | 不拥有（明确排除）         | 依赖方向   | 接缝 / 适配器                                |
| ----------- | ------------------------------------------------------------ | -------------------------- | ---------- | -------------------------------------------- |
| `.`（包根） | 令牌与注入、装配清单、装配内核、诊断与日志契约；**两端共用** | 运行环境判定、任何领域概念 | ← cordis   | `bootstrapApplication` / 各域 `provideXxx()` |
| `./compat`  | 适配行工厂（`fromCordis`）与行入口（`toCordis`）             | 域实现、行配置持久化       | ← 包根令牌 | 一条适配行接一个上游插件                     |
| `./testing` | 框架内部表示（令牌元数据、契约面标记）                       | 装配 API                   | ← 令牌     | 测试断言                                     |

**接口**（调用方要知道的）：

- 两端都只经包根取 DSL 与内核；**没有**第二个「浏览器专用」说明符，也没有「按环境选说明符」的分支。
- 上层怎么用本包（装配顺序、浏览器挂载、契约覆盖断言）归上层文档；本包只保证「一个包根、三个面」。
- `./compat` 的 `toCordis` 只属于「按 cordis 行装配」的部署面；行内适配用 `fromCordis`。

## 四、行为与边界

- 正常路径：两个运行时里的装配入口都把清单交给 `bootstrapApplication`，同一份内核跑在两种运行时。
- 错误：上层把只属于宿主的包根引进了浏览器图 → 构建期 `MISSING_EXPORT`（`node:*` 的具名导出在替身里不存在）。本包的处置只有一条：不拿「浏览器专用面」去掩盖它。
- 边界桥：`bootstrap.ts` 与 `compat/from-cordis.ts` 里对 cordis ctx 的双断言（`as unknown as`）是设计，不是逃逸。
- 顺序：`provide` 清单先于内核调用；内核按 `inject` 声明拓扑排序（见[公开接口](./20261104-zephyr-是-cordis-plugin-的语法糖.md)）。

## 六、取舍（被否掉的选项）

- **按运行环境给本包分面（加一个 `./client` 子路径）**：否掉——两端的装配入口调的就是 `bootstrapApplication`，分面后装配侧仍要引包根，等于把同一份内核列两遍。代价却是长期的：每个消费面各记一套说明符，判据还要多守一条。
- **把 `toCordis` 从 `./compat` 拆成独立子路径**：否掉（本轮）——`fromCordis` 是浏览器槽位行天天用的，拆面要动 40 多个文件；而 `to-cordis` 树摇后对产物无增量（内核本来就在）。
- **用 lint 规则禁止某个说明符**：否掉——要禁的是「宿主专属包根」，那是逐包的语义，不是一条 specifier 规则。守它的是 `just audit` 的面边界与构建期 `MISSING_EXPORT`。

## 七、不做与已知债

- **产物里有 cordis**：设计如此（内核就是它在跑）；体积优化是另一条话题，不进本设计的判据。
- **`./compat` 的 barrel 把 `fromCordis` 与 `toCordis` 混在一起**：可拆，当前无收益（见六）。
