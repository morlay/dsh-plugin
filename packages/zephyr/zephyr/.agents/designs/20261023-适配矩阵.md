## 本轮修掉的框架缺陷（都是「先红后绿」暴露的）

1. **失败不回滚**：`onInit` 失败时已启动的 provider 没被卸载 → 加 `rollback()`；
2. **卸载不幂等**：`dispose()` 两次会跑两遍清理 → 加 `disposed` 标记；
3. **异步 apply 没等**：`callPluginWithInstance` 返回 `{ result: Promise }`，调用方 `await` 对象不会等内部 promise → 晚到的 `provide` 丢在 `published` 之外（`provided nothing`）→ 改 async 函数、三条分支都 `await`；
4. **只有构造函数的类被当函数插件**：`class X extends Service { constructor(){} }` → 用 `Function.prototype.toString` 的 `^class` 判定；
5. **`providerContext` 越狱**：从 `protected` 改 `private`、从出口移除；适配类改走 Proxy 转发 + `providerInstance`。

## 未覆盖 / 已知边界

- 裸 cordis 插件（`app.plugin(...)` 装载的 fiber）只验了「能装、服务可解析」，其失败回滚沿用同一 `rollback()`，没有单独用例；
- `Service` 子类的 `[Service.init]()` 异步阶段与 `published` 的时序只覆盖了「晚 provide」，更细的中途状态未测。
