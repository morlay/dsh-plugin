# 双向适配与 dsh 行装配（框架层）

状态：已定稿（2026-10-23 按当前实现重写；现行细节见[契约面转发方案](./20261023-契约面转发方案.md)
与[适配矩阵](./20261023-适配矩阵.md)）

范围：`@morlay/zephyr` 如何同时承载「上游 cordis 插件」与「我们自己的 Provider」，以及 `@Module` 如何装配。
约束：上游 `@deepseek-ai/*` 与 `vendor/**` 只读；dsh 的行 id / Config / volatile / locale / 设置页是用户可见契约，不改。

## 结论摘要

| 议题 | 结论 |
| --- | --- |
| 容器 | Cordis 根 ctx 即唯一容器；zephyr 的服务表绑 `ctx.root` 共享，行卸载只注销自己注册的服务 |
| 行身份 | 行 id = token 名（类名 hyphenate），包名从 `package.json` 读，Config 由包显式定义 |
| 我们 → dsh | 能力包写 `@Injectable()` class Provider；`toCordis(ProviderClass, { Config })` 转成 cordis 插件对象 |
| 上游插件 | `fromCordis(契约, 上游)` 适配行：`onInit` 里 `mount(ctx, deps)`；令牌指向契约面（见转发方案 D） |
| 依赖 | 一律字段 `inject(契约)` / `inject.optional(契约)`；**可被 `inject` 的必须是契约** |
| 装配 | `@Module({ imports, providers })` 是唯一装配面；imports 在 providers 之前、按声明顺序串行 |
| 根名字视图 | 只由 `provideService`（令牌）与 `publishServiceName(契约名)` 写；上游 `provide` 的名字只进行内 `local` |
| 生命周期 | `onInit` 失败即回滚（逆序卸载已启动的）；`dispose` 幂等；卸载顺序「使用方 → 提供方」 |
| client | 浏览器半是普通 `@Module`，由 `bootstrapApplication({ imports })` 装配（不再有 cordis 手写装配） |

## 契约声明

**判定标准**：按「服务面」声明；被 `inject` 消费的服务面必须声明契约抽象类，纯实现行只作为 `@Module` 的
`providers` 条目（不能被 `inject`）。

命名：

- **契约 = 服务语义名**，不加 `XxxContract` 后缀，不写 `static serviceName`；类名连字符化就是上游兼容名
  （`SessionStore` → `session-store`、`SessionProjections` → `session-projections`）。
- **默认实现 = `XxxDefault`**：`WebDefault`、`StorageDefault`、`SessionStoreDefault`、`WebServerDefault`。
- 契约写 `<domain>/<x>.contract.ts`（`@Injectable() abstract class`），实现写同目录 `<x>.service.ts`。
- 适配行写 `fromCordis(契约, 上游)`；消费方 `inject(契约)`；实现类只出现在 Module 装配里。

| web / web-server / connection | `Web`、`WebServer`、`Connection`、`WebStartup`、`UiRenderer` |

## 行运行时

- 一行一个 `RowRuntime`：构造 → 解析依赖 → 发布 → `onInit`；卸载逆序。依赖由装配方就地启动被依赖的行。
- **同层行并行启动**：声明顺序不决定「谁先等谁」；依赖失败时优先报「提供者自己」的错误。
- `onInit(ctx)` 的 ctx 是行作用域：属性读只认注入过的依赖与作用域成员，未声明直接抛
  `cannot get property "x" without inject`；`get` / `inject` / `reflect` 是显式读面；`provide` 只落行内 `local`。
- 等待上限 3s：提供者已启动却没兑现 → 立即 `service "x" is not available`；本批没有提供者且不在计划表 →
  同样立即报错；依赖环在装配期抛错（带路径）。
- 裸 cordis 插件对象可以直接作为 `providers` 的一项：等它 `inject` 声明的名字就绪后 apply，卸载跑它的 disposer。
- 同一份源码被两条解析路径载入时类身份不同、令牌名一致：依赖解析与计划表先按身份、再按令牌名兜底。
- `@Module` 合并时，同一 token 的覆盖者占据自己的声明位置（先删后插）。

## 开放问题

- 行卸载时，跨行依赖方仍在等待/使用该服务的语义（报错还是继续挂起）。
- 同一上游服务类出现多个实例时取第一个；类扫描的超时语义要按真实装配定。
- client 浏览器半的 Slot 声明层与全量迁移顺序。
