# 根名字视图没有同名守卫

状态：未销账（`publish` 直接覆盖，同名的第二个发布者静默夺走键）

**现象**

`packages/zephyr/zephyr/src/service-table.ts` 的 `publish` 是三处写入共用的唯一入口：

```ts
into.set(key, value);
wake(table, key);
return () => { into.delete(key); };
```

它不检查 `key` 是否已存在，撤销也不判断「删的是不是自己发布的那个值」。

写根名字视图（`table.names`）的有两处：

- `provideService`：令牌自带的 `serviceName` 一并写进名字视图；
- `publishServiceName`：行作用域的 `provide` / 上游 `ctx.reflect.provide` 走这条。

`bindNamedTokens` 只写令牌表，不写名字视图；`resolveServiceName` / `serviceNamesOf` / `serviceInstanceOfType` 都从名字视图读，
后两者还按实例类型在名字视图里找服务。

今天每个 `serviceName` 只有一个声明者：`packages/agent/dsh-session-persistence/src/contract/session-persistence.contract.ts`
的 `sessionPersistence`、`packages/agent/dsh-session/src/contract/session-projection-store.contract.ts` 的 `sessionProjections`。

**影响**

名字视图里「谁拥有这个名字」不可判定。两个发布者共用一条键时，后发布者把前者的值覆盖；先卸载者的撤销无条件 `delete(key)`，
会把后发布者仍活着的条目删掉。症状是某个服务在某个时刻突然读成 `undefined`，没有任何报错，也没有可追的失败点。

**触发条件**

出现第二条 `static serviceName` 声明同一个名字；或新增的 `serviceName` 与既有发布名重合；或同一个名字同时被
`provideService`（令牌名）与 `publishServiceName`（行作用域的 `provide` / `ctx.reflect.provide`）写入。

**销账条件**

Done when：`publish` 对名字视图加「已存在且发布者不同 → 抛错」，撤销只删自己发布的那一份，并有 spec 覆盖两条：

- 两个声明同一 `serviceName` 的契约同时装配 → 第二个 mount 抛错（而不是静默覆盖）；
- 先发布者卸载后，名字视图里仍是后发布者的值。

**不修的理由**

加守卫之前要先确定「同一次装配里同名重复发布」是否合法：`service-scope.ts` 的 `provideName` 把撤销压进 `effects`，
同一名字被 provide 两次时两次撤销共用一条键；`provideService` 与 `publishServiceName` 也可能对同一个名字各登记一次。
没有真实冲突时加守卫，容易把现在的合法路径写死成抛错。
