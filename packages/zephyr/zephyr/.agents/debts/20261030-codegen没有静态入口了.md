# codegen 没有静态入口了

状态：触发中（`@Module` 已随 Standalone 装配面删除，`bundlePatchOf` 失去入参）

**现象**

装配面已收口成 `providers` 清单（`bootstrapApplication({ providers })`），域包导出 `provideXxx()`，
`@Module` / `moduleMetaOf` / `moduleFileOf` / `providersOfModule` 全部从 `@morlay/zephyr` 删除。

`devpackages/zephyr-codegen` 原来的入口是 `bundlePatchOf({ module, from })`——读 `@Module` 上的
`kModuleFile`（包名）与 `providers`。这两样现在都没有了：`provideXxx()` 是运行期函数，返回值无法静态分析。

**影响**

`cordis.patch.yml` 的生成链在 zephyr 这侧断掉：bundle 不能再靠「一个 Module 类」告诉生成器
「我属于哪个包、我装哪些行」。`devpackages/zephyr-codegen` 的 spec 仍用自己那份 `Module` 声明跑绿，
但它服务不了真实的 bundle。

**触发条件**

任一条成立就必须还：给某个 bundle 加/删行；`cordis.patch.yml` 需要重新生成；发布前要核对 bundle 的行清单。

**销账条件**

Done when：codegen 有一个**静态**入口替代 `moduleFileOf`（例如 bundle 声明文件里写明「包名 + provider 清单」，
名字按设计取，不沿用旧实现的内部叫法），`bundlePatchOf` 换到新入口，且
`grep -rn "@Module(" packages apps devpackages | grep -v __tests__` 零命中。

**不修的理由**

这是「运行期装配」与「构建期生成」的分离：静态入口要定形状（谁声明、声明什么、怎么定位包），
不适合在装配面迁移的同一次改动里顺手定。先让运行期那半干净（已做），构建期这半单独设计。
