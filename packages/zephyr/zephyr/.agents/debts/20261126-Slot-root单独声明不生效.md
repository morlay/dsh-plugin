# 债：`@Slot({ root })` 单独声明时 root 标准源不生效

状态：**未修**（2026-11-26 收尾记录；已排除五个假设，根因收窄到 vendor 的一处传递）。

## 症状

只声明 root 标准源（不带 `scope`）的贡献行，root 组件拿不到 `use<Name>`：

```
slot entry crashed in 'root': TypeError: useSessions is not a function
  at DocumentTitle (ui-layout/src/client/DocumentTitle.tsx:11)
  at AppFrame (ui-layout/src/client/AppFrame.tsx:150)
```

root 树被 error boundary 换成空占位（`<div data-slot="root" style="display: contents"><div data-slot-error="root"></div></div>`）。
同样的贡献放进 `@Slot({ scope, root })`（`SessionScopeContribution`）就正常——差别只在「有没有同时声明 scope」。

## 已排除的五个假设（别再重复走）

| # | 假设 | 证据 |
| --- | --- | --- |
| 1 | `@Slot({root})` 不调 `provideRoot` | 探针：`provideRoot` 调了 5 次，其中 2 次 `keys=hooks` |
| 2 | 贡献没进 `rootContributions` | 探针：`rootContribs=5` |
| 3 | 合并丢失（`Object.assign` 来源不对） | 探针：`rootSnapshot.hooks=panelInfo,sessions,sessionStatus` |
| 4 | hooks → `use<Name>` 映射分岔（root vs scope） | `materializeStandardBinding` 无条件映射，两分支共用 |
| 5 | `standardProps` 按对象身份缓存命中旧值 | `slots.service.ts:286` 的 `rootSnapshot` 是 `hostFace()` 内局部 `let`，每次新建 |

另外确认：`standardHookPropName('sessions') === 'useSessions'`（`ui-slots/src/renderer.ts:42`），`DocumentTitle` 取的就是这个键。

## 下一步唯一方向（读 vendor，只读不写）

`ui-renderer` 的这条链，看 `rootBinding` 到底被传了哪一份：

1. `renderRoot(host, owner)`（`scoped-slots.tsx`）内部是否**又取一次** `host.root.getSnapshot()`；
2. `RootStandardProvider`（`bindings.tsx:156`）是否把它原样透传给 `SlotOutlet`；
3. `SlotOutlet` 里 `standardProps('root', rootBinding, undefined)` 的 `rootBinding` 是不是**那一个**。

读完先报结论，**别直接改**：五轮排除的教训是，每个「显然的修法」都可能是绕过（例如「给 root 分支补特例」「按贡献数量做缓存 key」「自动装空 scope」都不行）。

## 判据

- `packages/zephyr/zephyr-app/src/client/renderer/__tests__/slot-root-only.spec.dom.tsx`（**现红**，可稳定复现：mount 后 `data-shell-overlay` 不出现、`useSessions is not a function` 出现在 console.error）；
- 右栏端到端夹具 `dsh-conversation/src/ui/__tests__/rightbar-seats.spec.dom.tsx` 是**症状现场**（同一条红因）。

## 顺带（同源但无害）

`slots.service.ts` 的 `get root()` 每次读都返回**新的** `{ getSnapshot, subscribe }` 对象，旧 listener 会留在旧的 `rootListeners` Set 里。
不影响正确性（旧 Set 随旧 face 丢弃），但将来若有人按 observable **身份**做缓存会踩；修这条 bug 时顺带看一眼是否要稳定化这个对象。
