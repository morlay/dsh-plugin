# 行 id 由 token 派生，不写行元数据

状态：已采纳

背景：dsh 的行 id 是设置页 namespace、配置写回与 locale 的键；现有能力包的行 id 与 Provider 类名同形（`WebSearchOllama` → `web-search-ollama`、`SandboxLocal` → `sandbox-local`）。zephyr 的 `getTokenName` 已经按类名做 hyphenate。

**决定**

不引入 `static dsh` / 装饰器参数 / 独立行清单这类行元数据。能力包的 Provider 类名即行身份：`toCordis()` 与 bundle 生成器都从 token 名取行 id；包名从 `package.json` 读；Config 由包显式定义并由 `toCordis` 的 `Config` 选项引用。

**考虑过的选项**

- `static dsh = { id, name, config }`：多一份与类名重复的事实，且框架类耦合 dsh 概念。
- Module 条目包装 `row(Provider, {...})`：行信息与 Provider 分居两处，生成器要同时读两边。
- 独立清单文件：回到手写行清单，正是要消除的重复。

**后果**

- 改类名即改行 id；现有包迁移时需保持类名与现有行 id 同形（试点两个包已满足）。
- 行 id 冲突/例外（一个类多行、行 id 与类名不同形）需要在生成器里显式支持例外；当前不支持，遇到时再定。
- Config schema 仍是显式定义的真源，不从 Provider 推导。
