# 事件令牌的订阅作用域（`zephyr` 的事件面）

状态：已对齐——形态定了，实现另排一票（见「八、开放问题」）。
范围：`EventEmitter` 的订阅口子（`on` / `onWaterfall` / 新增的 `onIn` / `onWaterfallIn`），以及「订阅作用域」由谁决定。
非目标：不动派发语义（`emit` / `parallel` / `serial` / `bail` / `waterfall` 归 cordis）；不引入事件名之外的第二处命名；不做「历史帧的跨作用域重放」。
关联：`packages/zephyr/zephyr/src/event-emitter.ts`、`packages/zephyr/zephyr/src/bootstrap.ts`、上游 `docs/architecture.md` 的 scope-filtered dispatch。

## 一、决定

| #   | 议题              | 决定                                                                             | 一句话理由                                                |
| --- | ----------------- | -------------------------------------------------------------------------------- | --------------------------------------------------------- |
| 1   | 订阅作用域        | 由**订阅时的显式参数**给出（`onIn(ctx, listener)`），不藏在字段绑定的那次 ctx 里 | 上游造的 ctx（`agent.ctx`）拿不到我们的 `onInit` 时机     |
| 2   | `on` 的默认作用域 | **本行 ctx**（`onInit(ctx)` 收到的那一个），不是应用根 ctx                       | 行卸载即清；否则订阅活到 app 结束，退订要每个消费者自己记 |
| 3   | 名字与参数表      | 仍只来自令牌（`this.name` / `TArgs`）；`onIn` 不接受第二个名字参数               | 名字只有一个 home，listener 签名不退回手写                |
| 4   | 两种替代形态      | 否掉：调用点 `ctx.on(令牌.name, …)`；否掉：记成债永久例外                        | 前者丢掉参数表校验（waterfall 尤其弱），后者把清零留洞    |

## 二、现状事实

订阅口子只有 `on` / `onWaterfall` / `once`，它们都走 `this.target`——**字段绑定那一刻** `onInit(ctx)` 给的 ctx（`packages/zephyr/zephyr/src/event-emitter.ts`）。

那次绑定传的是**应用根 ctx**：`bootstrap.ts` 的 `fillInjections(instance, instances, multi, ctx)` 在 `ctx.plugin` 之前跑，第二个参数就是装配入口的 `ctx`。而 `event-emitter.ts` 的类注释写的是"事件是 Provider，装配时 `onInit(ctx)` 拿到本行 ctx"——**两者不一致**。

后果已经量到：`agent-ex/better-session/src/storage/projection-cache.service.ts` 的三条会话事件改令牌后，订阅不再随行卸载，得在 `onDispose` 里自己收回三条 disposer。

两条真实消费点卡在这里（都是上游 `Agent` 造的 `agent.ctx`，我们拿不到它的 `onInit` 时机）：

| 位置                                                 | 事件            | 为什么必须是那个作用域                                                              |
| ---------------------------------------------------- | --------------- | ----------------------------------------------------------------------------------- |
| `agent-ex/session-mode/src/tool-guidance.service.ts` | `tools/change`  | 团队、schedule 这些行在该会话建好**之后**才把工具注册进 agent scope，根作用域看不到 |
| `agent-ex/session-mode/src/session-mode.service.ts`  | `agent/request` | 上游是 `Scoped<Agent>` 的 scope-filtered dispatch，挂别处会收到所有 agent 的请求    |

## 三、模块边界与接口

| 模块           | 拥有（职责与不变量）                     | 不拥有（明确排除）                       | 依赖方向        | 接缝 / 适配器                  |
| -------------- | ---------------------------------------- | ---------------------------------------- | --------------- | ------------------------------ |
| `EventEmitter` | 事件名、参数表、返回类型、**订阅作用域** | 派发语义（cordis）、scope filter（上游） | 各域 → `zephyr` | 无：cordis 的 ctx 就是既有接缝 |

```ts
onIn(ctx: Context, listener: (...args: TArgs) => TResult, options?: EventOptions): () => boolean
onWaterfallIn(ctx: Context, listener: (...args: [...TArgs, Next<TResult>]) => TResult, options?: EventOptions): () => boolean
```

不变量（调用方正确使用它需要知道的全部）：

1. `ctx` 只决定**能否收到**，不改参数表，也不改派发顺序（同一作用域内仍按注册序）。
2. disposer 归该 `ctx`：ctx 卸载后不再调用 listener；不需要调用方额外记。
3. 名字取 `this.name`，没有第二个参数可以覆盖它。
4. `on` / `onWaterfall` 与 `onIn(本行 ctx, …)` 是同一实现的两个入口，行为不得分叉。
5. `onIn` 不依赖本行 ctx 已就位（它只用传入的那个 ctx），因此可以在 `onInit` 之外、拿到 `agent.ctx` 之后随时订阅。

## 四、行为与边界

- 正常路径：`onIn(agent.ctx, listener)` 收到该 agent scope 的 `tools/change`，收不到别的 agent 的。
- 生命周期：`agent.ctx` 随会话收起后 listener 不再被调用；`on` 的行 ctx 卸载同理。
- 顺序：`onIn` 不改变同一作用域内的注册序，也不与默认作用域的监听混排。

## 五、验收判据

| #   | 判据（Done when）                                               | 测试面                                 | 证据                                                                                |
| --- | --------------------------------------------------------------- | -------------------------------------- | ----------------------------------------------------------------------------------- |
| 1   | `onIn` 只在目标 scope 收到事件（另一个 scope 的同名事件不进来） | `event-emitter.spec.ts`                | 用例：两个 scope 各订阅，各自只收到自己的                                           |
| 2   | 目标 scope 卸载后 listener 不再被调用                           | 同上                                   | 用例：dispose 该 scope 后派发，计数不增                                             |
| 3   | `on` 的作用域是行 ctx：行卸载后静默                             | 同上                                   | 用例：装两行、卸一行、派发                                                          |
| 4   | 生产面事件字符串订阅只剩注释                                    | 装配面 grep                            | `grep -rn '\\.on("[a-z]' packages --include='*.ts'` 去掉测试与 node/electron 后为空 |
| 5   | 层回归                                                          | `pnpm exec vitest run packages/zephyr` | 同左                                                                                |

判据 3 与判据 1 是两件事：前者定**默认**作用域，后者定**显式**作用域；只做 1 会留下"默认仍是根 ctx"的旧事实。

## 六、取舍

| 选项                                        | 否掉的理由                                                                               |
| ------------------------------------------- | ---------------------------------------------------------------------------------------- |
| 调用点 `ctx.on(令牌.name, …)`               | 名字的 home 保住了，但 listener 签名回到手写；`agent/request` 这种带 `next` 的瀑布尤其弱 |
| 记进债，保留两处字符串订阅                  | 「清零」永久留两个洞，且下一个订阅者会照抄；债只该给明知不好但确有成本的事               |
| 让令牌字段自己接受一个 ctx 参数（构造期传） | 构造期还没有 `agent.ctx`，等于把"拿不到时机"的问题挪个位置，没解决                       |

## 七、不做与已知债

- 不做 `onceIn` / `serialIn` / `bailIn`：没有消费方（YAGNI），需要时按同一形态加。
- 已知不一致（不是债，是待改的缺陷）：`fillInjections` 给事件字段的是应用根 ctx，与类注释写的「本行 ctx」不符；它由判据 3 销账，改法与风险见「八」。

## 八、开放问题

- 判据 3 要求把事件字段的绑定挪到拿到 child ctx 之后（`bootstrap.ts` 的 `ctx.plugin({ apply })` 里）。**这会不会改变注入可见时机**——适配行是在自己 `onInit` 里 `mount` 之后才发布契约面，后面的行才注入到真值而不是空壳——需要单独一票验证，不随本设计一起动。
- 这份设计落地前，那两处消费点的字符串订阅保持现状，形态按本文件写。
