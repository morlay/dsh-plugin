# 债：右栏 tab 状态不跨会话保留

状态：已知且被接受（2026-11-26）。

## 事实

右栏的内核是上游的（`SidebarRightTabRegistry` + `createSidebarRightController` + 上游 store），
但**会话级的 surface 只在被渲染到时才建**：`SidebarRightDefault.surfaceOf(sessionId)` 懒建 store 实例、
`adopt` 给控制器，之后就不再管它。

上游的做法是每个会话一份 `SidebarSessionViews`（跟着会话目录走，含后台会话），store 里的 tab 布局按会话
持久化（`persistence.ts` 写 `localStorage`），切回来时原样恢复。我们只服务「在屏的那一个会话」，所以：

- 切走再切回**同一**会话：surface 还在 `surfaces` map 里，布局保留（这部分是对的）；
- 关掉会话再打开、或换个窗口：tab 布局不恢复（上游的 `readSidebarLayout` 没接）；
- 后台会话里的 tab（比如 agent 在别的会话里开终端）不会被 `adopt`，那些 tab 的记录不跟进、
  `openResourceIn` / `openTabIn` 对它们没有落点（上游能，因为每个会话的 store 都 adopt 了）。

## 为什么现在不补

补它需要「所有会话的视图列表」与「按会话的持久化」，也就是上游 `session-views.ts` + `persistence.ts`
那两件；而当前产品里右栏没有跨会话的用法（没有后台会话开 tab 的路径），补了也没有消费方验证。

## 若产品需要，最小设计

1. **会话目录**：从会话域要一份「当前所有会话的 SessionReference」的读面（上游是 `ctx.sessions` +
   `uiSession.adapter.current`）；右栏座位行订阅它，为每个会话建 surface 并 `adopt`。
2. **持久化**：`createSidebarRightStore` 已经带 `persist` 轴（上游 `stores.ts` 调 `readSidebarLayout` /
   `writeSidebarLayout`），只需要给 store 的 `create(scopeKey)` 传会话 id 并让座位行在卸载时 `clearPersisted`。
3. **重放**：切回某会话时 surface 已存在即可（`adopt` 会 `sync` 一次 tab 域）；不需要额外的恢复步骤。

判据：两个会话各开一个 tab，来回切换后 tab 与活动项都还在；关掉窗口再开也还在（持久化）。
