# 债：右栏 UI（容器/座位）应归会话域

状态：已知，后续单独一票（2026-11-26）。

## 事实

右栏的**服务内核**已经是我们自己的（上游 `SidebarRightTabRegistry` + `createSidebarRightController` + 上游 store，
只调工厂），但**容器与座位**仍是本仓 `zephyr-ui` 里自己写的：`Rightbar`（标签条 + 正文外壳）、
`RightbarPaneTab`、`RightbarTabTitle`。

上游那两个座位组件（`RightbarRoot` / `RightbarSeat`）依赖的不是框架令牌，而是**会话域与 dockkit**：

- `RightbarRoot` 的构造是 `new SidebarSessionViews(ctx.sessions)`（`session-views.ts`），`sessions` 是
  `@morlay/dsh-session/endpoint` 的会话域契约；`SessionReference` 只能由 `sessions.binding()/reference()` 造，
  `SlotScopeAdapter` 给不出——所以框架层无法为它提供 `views` / `mountView`。
- `RightbarSeat` 用 dockkit 的 `DockLayout`（拆分 / 浮动 / 停靠 / 拖拽 / 房间测量）与 store 的完整布局模型，
  还要 `SidebarRightInjected` 里的 `flashOf(sessionId)`（契约没声明）与 `tabDomain.occurrence`。

按判据「零业务语义 → 框架；有业务语义 → 各域」，右栏 UI 属**会话域**（它认识会话与 pane）。

## 后续一票要做的

1. 把右栏的槽位声明（`rightbar` / `rightbar.session` / `sidebar.right.pane.tab` / `.title`）与座位组件
   搬到 `@morlay/dsh-conversation`（它有 `sessions` / `uiSession` / `shortcuts` / `contextMenus`）；
2. `zephyr-app` 只留 `SidebarRight` / `SidebarRightTabs` 服务内核与契约；
3. 给 `dsh-conversation` 加 `@deepseek-ai/dsh-client-ui-dockkit` 依赖；
4. 契约补 `flashOf`（`SidebarRightController` 上有，当前只在实现类转发）；
5. `rightbar.session` 的 store 由渲染器按 session 作用域 `create`（等于回到上游的两层座位结构），
   guide 的标题座位注册 `GuideTitle`（它要 `useTabInfo` 的 `hookContext`，只有上游 seat 会传）。

判据：`rg 'RightbarRoot|RightbarSeat' packages/zephyr/zephyr-app` 为 0；右栏展开后容器与 pane 的 DOM 结构
与上游一致（同一份组件）。

## 实测方式（留给 A 票那一轮；本轮沙箱起不了浏览器）

本轮试过三次 headless Chrome，全部崩在沙箱层（`Failed to initialize sandbox`、crashpad 写 dump 被拒、
CDP 通道在 `Runtime.enable` 处无响应、随后 `Trace/BPT trap: 5`）。所以「未实测」不是懒，是环境不允许。

探针已就绪：`.scratch/probe-rightbar.mjs`（连 `127.0.0.1:9333` → 等 `#root` → `click('[data-sidebar-right-expand]')`
→ 采 container / expandButton / strip / chip / body / notice 的 `getBoundingClientRect` 与指定 computed 属性，
输出 `.scratch/rightbar-ours.json`）。

**我们这一侧**：

```sh
just custom dev --no-open                     # 127.0.0.1:3081
"/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" \
  --headless=new --remote-debugging-port=9333 --remote-allow-origins='*' \
  --user-data-dir=/tmp/rb-chrome --no-first-run about:blank &
node .scratch/probe-rightbar.mjs
```

**上游基准侧**：不要用 `git stash push -- <右栏两条路径>`——`sidebar-right.provide.ts` 会被一起 stash 走，
而 `dsh-conversation/src/ui/shell/index.ts` 还引用 `provideSidebarRight`，装配直接缺件。用 worktree：

```sh
git worktree add /tmp/rb-base 74bbf26c          # 74bbf26c = 右栏还是上游插件的那版
cd /tmp/rb-base && pnpm install --offline && just custom dev --no-open   # 换一个端口
node <这个仓库>/.scratch/probe-rightbar.mjs      # 探针指向基准端口时改一下 URL
```
