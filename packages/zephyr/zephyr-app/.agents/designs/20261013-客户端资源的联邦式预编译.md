# 客户端资源的联邦式预编译

状态：已实现——dev 与构建两条链共用一套「一个包一份产物」的规则，产物落盘缓存、按出口命中。
范围：`packages/zephyr/zephyr-app/src/{internal,federation,node-stub,rows}/` 里的资源解析、构建、服务与 dev 白名单。
非目标：页面路由与骨架、槽位与渲染、行清单本身、vite 的 HMR 实现。
关联：[设计 宿主装配面与 client-modules](./20261022-client-modules-重写.md)、[债务 vite dev server 与宿主同进程](./../debts/20261013-vite与宿主同进程.md)、[ADR-不fork上游前端组件只做插槽扩展](../../../../../.agents/adrs/20261001-不fork上游前端组件只做插槽扩展.md)。

## 一、决定

| #   | 议题            | 决定                                                                                               | 一句话理由                                                                           |
| --- | --------------- | -------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------ |
| 1   | 地址形态        | `/_zephyr/@modules/<pkg>@<version>/<file>?v=<BUNDLER_REV>`；包名的 `/` 转成 `+`                    | 一个包一份产物，浏览器按 URL 取即可                                                  |
| 2   | 出口名 ↔ 文件名 | 只有一条规则：出口产物文件名 = `<出口名>.js`（`entryFileNameOf` / `exportNameOfFileName`）         | 生成地址与解析地址各写一遍就会漂成 `remote` 与 `remote.js`                           |
| 3   | 构建            | 直接调 `rolldown`（不经 `vite build`），一次构建产出该包要的出口 + 共享 chunk                      | 插件本来就是 rolldown 接口，少一层被吞掉的配置                                       |
| 4   | 外置            | 外置名单 = 「这个包声明的依赖 ∩ 能解析到」，独占给 `esmExternalRequirePlugin`                      | 顶层 `external` 也列同一模块会让插件整块跳过、产物里留下 `__require`                 |
| 5   | 缓存            | 按包聚合（`<cache>/<pkg>@<ver>/`），命中判据 = 世代相同且**这次要的出口**都在；指纹变了也不删目录  | 缓存跨进程共用，删目录会带走另一个进程刚写的产物                                     |
| 6   | 缓存头          | 联邦产物一律 `public, max-age=31536000, immutable`；`?v=` 只随构建器规则变                         | 内容变了不换 URL，否则同一个包两个 URL = 两份模块实例                                |
| 7   | dev 白名单      | 正向白名单 `Federation.dev.include`（缺省 `["@morlay/*"]`）：点名的包逐文件走 vite，其余 prebundle | 上游 client 之间有循环 re-export，逐文件服务会 `Detected cycle while resolving name` |
| 8   | URL 空间        | 对外统一 `/_zephyr/@…`，进 vite 前 strip、出站补前缀                                               | vite 只认自己的 `/@…`，浏览器只看得到一个前缀                                        |

## 二、现状事实

- **地址与出口名**：`packages/zephyr/zephyr-app/src/internal/resolve.ts`（`entryFileNameOf` / `exportNameOfFileName` / `exportTargetOf` / `packageRootOf` / `fileInPackage` / `clientHalfOf`）。出口名与文件名不同构（`./client-module` → `src/client/index.ts`），所以寻址只能按清单的 `exports`。
- **构建**：`packages/zephyr/zephyr-app/src/federation/bundle.ts` 的 `bundlePackage`。入口补偿按 `moduleKindOf`（扩展名 + 最近的 `package.json` + Node 的语法检测）分三路：直通 / CJS 具名导出包装 / CSS 包装。
- **产物布局**：`<出口>.js`、`chunks/<name>-<hash>.js`、`assets/<name>-<hash>.<ext>`，加一份 `.files.json`（`{ rev, files, resolved }`，`files` 的键就是这些文件名）。
- **缓存根**是 `AppEnv.cacheDir`（缺省 `<dataDir>/cache`，dev 即 `<工作区>/.dsh-store/cache`）；`bundle.ts` 里的 `CLIENT_MODULES_CACHE` 常量已无调用点。
- **并发与上限**：同包构建排队串行（`building` 表），全局同时在跑的上限由 `DSH_BUNDLE_CONCURRENCY`（缺省 8）给，排队/构建等待上限由 `DSH_BUNDLE_TIMEOUT_MS`（缺省 30s）给，超时如实抛。
- **服务**：`packages/zephyr/zephyr-app/src/federation/federation.service.ts` 的 `serve` / `depsUrl`。资产与块按清单回文件；出口优先看缓存（世代前缀匹配 + 文件在），否则解析入口再构建；入口解析不到 → 404 + `[federation-miss]`（不再回空模块）。
- **裸说明符 → 地址**：`depsUrl(specifier, importer)` 从**引用方**的清单解析（`findPackageJSON`），解析不到记 debug `[prebundle-miss]` 并返回 `undefined`（退回 vite 的文件链）。
- **dev 侧**：`src/internal/serve-vite.ts`（起 vite 的 middleware、`optimizeDeps.noDiscovery`、`cacheDir` 显式给）与 `src/internal/vite-plugin.ts`（`enforce: "pre"`，必须早于 `vite:resolve`）。白名单判定在 `src/rows/dev-files.ts`（`isDevFile`）。
- **URL 空间**：`src/internal/hmr-path.ts`（`FEDERATION_PREFIX` / `HMR_PATH` / `stripZephyrPrefix` / `addZephyrPrefix`）。
- **宿主专有模块替身**：`src/node-stub/index.ts`（dev 的 ESM 形态）与 `src/node-stub/node-stub.cjs`（构建的 CJS 形态）；`node:*` 整串匹配，不做前缀替换。
- **样式与资产**：`.module.css` 与 `url()` 的编译在 `src/cordis-assets/styles.ts`（与 tsdown 构建链共用一份实现），资产走 `threshold` 策略。

## 三、模块边界与接口

| 模块                                                         | 拥有（职责与不变量）                                               | 不拥有（明确排除）                                            | 依赖方向                                          | 接缝 / 适配器                                                |
| ------------------------------------------------------------ | ------------------------------------------------------------------ | ------------------------------------------------------------- | ------------------------------------------------- | ------------------------------------------------------------ |
| 地址与出口名（`src/internal/resolve.ts`）                    | 出口名 ↔ 文件名、包根解析、包内越界校验、client 半定位             | 产物长什么样（归构建）；谁是 client 行（归 `client-modules`） | ← `node:module` / 文件系统                        | 纯函数，可单测                                               |
| 联邦构建（`src/federation/bundle.ts`）                       | 一次构建多出口、外置名单、入口补偿、缓存命中与增量合并、排队与上限 | vite dev 的模块图；包清单的语义（只读）；页面                 | ← `rolldown`、`internal/resolve`、`cordis-assets` | `BundleOptions`（测试注入 `cacheRoot` / `nodeStub` / `log`） |
| 产物服务（`src/federation/federation.service.ts`）           | 一份 URL → 200/404、MIME、缓存头、按清单回文件                     | 路由表的注册顺序与 fallback（归 `client-modules`）；构建规则  | ← `bundle.ts`、`AppEnv`                           | `Federation` 契约（`serve` / `depsUrl`）                     |
| dev 资源面（`src/internal/serve-vite.ts`、`vite-plugin.ts`） | 把 vite 的中间件挂进宿主 http、裸说明符 → 联邦地址、前缀 strip     | HMR 的 ws 实现（vite 自己）；页面骨架                         | ← `Federation`、`AppEnv`                          | `ViteHandoff` 契约                                           |
| 当文件名单（`src/rows/dev-files.ts`）                        | glob → 正则、命中判定                                              | 名单的取值（装配面给）                                        | 无                                                | 纯函数                                                       |
| 宿主专有替身（`src/node-stub/`）                             | `node:*` 在浏览器里可求值的空实现（两种模块形态、同一语义）        | 真的 node 行为                                                | 无                                                | 按链选形态（ESM / CJS）                                      |

**接口**：`bundlePackage(options): Promise<{ rev, files } | undefined>`；`urlOf(specifier, tables): string`；`Federation.serve(url, req, res): Promise<boolean>`（`false` = 没接管，交回上层）；`Federation.depsUrl(specifier, importer?): Promise<string | undefined>`。
不变量：产物文件名与出口名同一条规则；外置名单只有一个 home；`?v=` 一次会话内所有地址一致。

**深度**：删掉这条链，每个消费方都要自己决定「按文件还是按包」、「谁外置」、「缓存放哪」——浏览器里就会出现同一个包的两份实例。

## 四、行为与边界

- 正常：首次请求某出口 → 构建 → 落盘并写清单 → 回文件；再次请求 → 缓存命中直接回。
- 错误：入口解析不到 → 404 + `[federation-miss]`；构建失败 → `[bundle-failed]` 打原始错误、请求不接管；构建拿到空产物 → `[bundle-empty]`。
- 超时：排队或构建超过 `DSH_BUNDLE_TIMEOUT_MS` 如实抛，不让请求挂在 pending。
- 生命周期：产物目录与清单跨进程共用，指纹变了只覆盖写、不整目录删。
- 并发：同包串行、跨包并行（上限见上）。
- 缓存头：产物一律 `immutable`；页面（`WebServe`）用 `no-cache`。

## 六、取舍

- 不用 `base: "/@/"` 统一前缀：vite 会给所有绝对 URL 再补一层，联邦地址变成 `/@/@…`。
- 不把 `?v=` 当内容指纹：引用方写下的指纹会停在旧值，同一个包两个 URL 就是两份实例（react 报 `useContext` 读 null）。
- 不给「仓库内的包」单独设 `no-cache` + `ETag`：联邦产物是静态字节、文件名带出口名，`immutable` 就够；协商缓存留给 dev 的逐文件链。
- 不猜 `.pnpm` 目录名算版本：版本一律读包清单。
- 不把仓库路径写进 import（`@/vendor/…` 或相对跳级）：开发态看着对，闭包形态深度对不上会当场报 `failed to import`。
- 该报错就报错：解析不到回 404 而不是空模块，缺什么一眼看见。

## 七、不做与已知债

- 不做「客户端产物的版本元数据注入」「profile 种子」这类发布式 profile 的东西。
- 桌面形态的自定义协议由壳提供（`zephyr-desktop-shell` 的 `protocol.ts`），本链不参与。
- 已知债：[vite dev server 与宿主同进程](./../debts/20261013-vite与宿主同进程.md)。

## 八、开放问题

- `bundle.ts` 的注释说「服务端对指纹不匹配的请求一律重定向到当前指纹（见 `serveFederation`）」，而 `federation.service.ts` 的 `serve` 里没有重定向，只有 `cached()` 的世代前缀比对。注释与实现不一致，二者要选一个。
- `CLIENT_MODULES_CACHE` 常量已无调用点（缓存根来自 `AppEnv.cacheDir`）：删常量还是改注释，未定。
- 拆分配置没有任何下限（`rolldown` 默认）：`@shikijs/langs` 这类按语言一个文件的包会不会切出几千个块，还没有用例盯着。
