# 我们的 `Slots` 与上游渲染器的接缝契约（核对表）

状态：**进行中**（2026-11-26 首版）。每次改 `slots.service.ts` 都对着这张表核。

背景：`@Slot({ root })` 单独声明时 root 标准源不生效（`useSessions is not a function`），排查中逐个排除假设，
结论是「我们的 `Slots` 包装层没有严格满足上游 `SlotRendererHost` 的隐含约束」。这张表把约束穷举出来。

## 1. 已排除的假设（别再重复走）

| # | 假设 | 证据 |
| --- | --- | --- |
| 1 | `@Slot({root})` 不调 `provideRoot` | 探针：调了 5 次，2 次带 `hooks` |
| 2 | 贡献没进 `rootContributions` | 探针：`rootContribs=5` |
| 3 | 合并丢失 | 探针：`rootSnapshot.hooks=panelInfo,sessions,sessionStatus` |
| 4 | hooks → `use<Name>` 映射分岔 | `materializeStandardBinding` 无条件映射，root/scope 共用 |
| 5 | `standardProps` 缓存命中旧值 | `rootSnapshot` 是 `hostFace()` 内局部 `let`，每次新建 |
| 6 | `host.root` 每次新建 observable → `observableHook` 缓存失效 | **已按契约修**（`rootObservable` 提为常量），修后仍红 → **非根因** |
| 7 | `getVersion: () => 0` → 渲染器认为 roster 没变 | **已按契约修**（接 `core.getVersion`），修后仍红 → **非根因** |

两次修改都保留（都是真违约，只是不是这条 bug 的根因）。

## 2. 契约核对表

| # | 上游约束（出处） | 我们的实现 | 结论 | 症状 / 证据 |
| --- | --- | --- | --- | --- |
| 1 | observable **身份**在装配内稳定（`observableHook` 按 source 身份缓存；`useSyncExternalStore` 要求 `subscribe`/`getSnapshot` 稳定） | `hostFace()` 的 `root` 已提为常量 ✅；但 `hostFace()` 每次 `renderSlot` 新建整个 face | 半满足 | 修后仍红 → 非本 bug 根因；listener 泄漏已顺手修掉 |
| 2 | `getSnapshot()` 同值返回同一引用 | `rootSnapshot` 每次 `rebuildRoot()` 换新（值变才换） | ✅ | — |
| 3 | `subscribe` 的 unsubscribe 真摘掉 | `rootListeners.delete` | ✅ | — |
| 4 | root 与 scope 的 binding 形状一致 | 同一 `StandardSourceBinding` | ✅ | — |
| 5 | children 声明 → 位置就绪的时序 | `core.subscribeDeclaration` + `reconcile` | ✅ | 判据 `slots-late-declaration.spec.dom.ts` 绿 |
| 6 | `renderSlot` 返回契约（`ReactNode`，不是 kit） | 返回 `<SlotOutlet>` 包装 | ✅ | 探针踩过：`tree.props` 只有 `value,children` |
| 7 | `getVersion(key)` 反映注册变化 | 已接 `core.getVersion(key)` ✅ | ✅（修前违约） | 修后仍红 → 非本 bug 根因 |
| 8 | `scopeRevision` 随 scope 安装/替换变化并**通知** | `private scopeRevision = 0`，`installScope` 里**从不递增、从不 notify** | ❌ **违约** | 切会话（scope adapter 变化）不会触发重渲染——独立的下一个 bug，待单独验 |
| 9 | `getFactoryVersion` / `isFactoryLive` 真实实现 | 已转发 `core.factoryVersion` / `core.isFactoryLive` | ✅ | — |

## 3. 仍未验的

- `hostFace()` **每次 `renderSlot` 新建整个 face** 的影响（是否让渲染器拿到的 host 身份在两次渲染间变掉）；
- 第 8 条（`scopeRevision`）的实证：切会话时是否真的不重渲染；
- `reportEntryError` 的 `abdicate` 语义我们只是透传，未验证 error boundary 的降级路径。
