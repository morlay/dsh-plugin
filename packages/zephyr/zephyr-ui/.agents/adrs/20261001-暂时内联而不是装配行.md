# 决定：本包是内联库，不是装配行

状态：已采纳——本包没有 `provide([...])` 清单、没有 `./client` 出口、不写 `dsh.bundle`；装配入口 `apply(ctx)` 由内联它的 client 行调用。
背景：本包是**库**：官方组件转出与自有控件、布局原语、设置表单原语、按 schema 生成配置页的模型与组件、引用解析与渲染。它要在每个用到它的 client 行里各带一份代码，而不是作为一个服务常驻。

三件事让它更适合当库：

- **它是随消费方一起进页面的代码**（样式与组件），不是一项常驻服务——每个消费方的 client 半都要 import 它；
- **它的装配面只有一份**（`schemaFormHints` 服务与 `settings.schema-form.form` / `settings.schema-form.field` 两个槽），却要由「谁在场」决定谁触发；
- **每个 bundle 都要插一行**，装配清单里因此多出一条与 bundle 职责无关的重复行。

**决定**

本包不作装配行：出口只有 `.`（浏览器组件库）、`./reference`（host 侧引用解析）与 `./brand-font.css`，**没有 `./client`**——没有那个出口，消费方的打包器就把它当普通库内联，而不是当 client 行去装载。

装配入口 `apply(ctx)` 由**内联本包的 client 行**在 `onInit` 里调用。多份副本各带一份代码，所以装配必须幂等：多份副本同时装配会各自 `locale.register("settings.schema-form")`，第二次抛 `locale namespace "settings.schema-form" already has locale "zh"`。

幂等靠一条：**`schemaFormHints` 挂在根 ctx 上，并且在 `locale.register` 之前提供**——检查与占用在同一步，兄弟副本进来时立刻看到它并让位。

**考虑过的选项**

| 选项                              | 否掉的理由                                                                                                            |
| --------------------------------- | --------------------------------------------------------------------------------------------------------------------- |
| 保留装配行，只把样式层拆出来内联  | 装配行与库两个出口并行，消费方仍要在清单里排它——重复行没消掉，只是换了个名字                                          |
| 让每个消费方在清单里写内联名单    | 构建与开发态都要各自维护这份名单，漏一处就是「页面 require 不到模块」或「注册两次」；标在被内联的包自己身上，一处生效 |
| 开一个 `exports["./client"]` 出口 | 本仓库的 client 行判据按它认浏览器半，开了就等于把本包当装配行                                                        |

**后果**

- 消费方少一条装配行：用到它的 client 行只 import 并调一次 `apply(ctx)`。
- **多份副本是常态**：同一页面上每个消费方产物里各有一份本包代码，判据是「装配只发生一次」——由 `src/client/__tests__/apply.spec.ts` 守着。
- **`apply` 的调用时机由调用方负责**：要在依赖（`slots` / `locale` / `configForms` / `settingsSchema`）已就位之后调——也就是那一行的 `onInit` 里。
- 要恢复成装配行的话，需要：加 `./client` 出口 + `toCordis` 行入口，并让至少一个 client 行插回那一行；消费方的 `apply(ctx)` 调用可留（幂等，重复无害）。
