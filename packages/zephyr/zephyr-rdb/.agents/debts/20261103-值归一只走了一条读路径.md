# 值归一有一个 home，手写片段那条读路径仍不归一

状态：未销账——表句柄的投影与 `RETURNING` 已同归一处；手写片段（`database.read` / `iterate`）原样返回驱动的值，只有显式打 `readBigInts` 标记才按 BigInt 读。
位置：`packages/zephyr/zephyr-rdb/src/table/normalize.ts`（唯一的归一规则）、`src/table/select.ts`（投影）、`src/table/handle.ts`（`RETURNING`）、`src/database/create.ts`（`iterate` / `read` 只做取消与错误分类）、`src/database/postgres.ts`（int8 解析器）、`src/database/sqlite.ts`（语句级 `setReadBigInts`）、`src/fragment.ts`（`readBigInts` 标记）。

**现象**

- 表句柄的两条路径一致：`select({a: t.f_active})` 与 `insert(..., ["f_active"])` 都给 `true` / `false`，bigint 都给 `BigInt`，JSON 列给结构化值。
- 手写片段不一致：`database.read(fragment(...))` / `iterate` 不带标记时原样返回驱动的值——SQLite 的 INTEGER 是 `number`、BOOLEAN 是 `0`/`1`；PostgreSQL 的 int8 因连接上装了解析器而是 `BigInt`、BOOLEAN 是 `true`/`false`。
- 打了 `readBigInts` 标记的手写片段：整条语句的整数列都是 `BigInt`（片段没有列定义可还原），调用方要自己按列类型还原。
- SQLite 上不带标记读超过 `2^53` 的整数仍会抛 `RangeError`（驱动在归一见不到那个值之前就失败）。

**影响**

写原始片段（报表、迁移读取、跨表统计）的人会拿到驱动的值：同一列在 SQLite 与 PostgreSQL 上类型不同，TypeScript 看不出来。

**触发条件**

在 `database.read` / `iterate` 上直接读 bigint / boolean 列（手写片段、迁移、统计）之前，先确认值的来源；需要精确大整数时用 `readBigInts(fragment(...))`。

**销账条件**

Done when：`read` / `iterate` 能按片段携带的列元数据归一（不需要调用方标记），且 `src/__tests__` 里有一条「同一列走 `select`、`RETURNING`、`read` 三条路径、类型相同」的用例。

**不修的理由**

- 片段里只有 SQL 文本与参数，列定义在表句柄那一侧：要收口得让片段携带列元数据，属于接口改动。
- 现有消费方（`packages/agent-ex/better-session`）读写都走表句柄，撞不上第三条路径。
