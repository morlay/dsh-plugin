# 值归一有两个 home

状态：未销账——`bigint` 列在表句柄的投影里归一，在 `database.read` / `iterate` 上不归一。
位置：`packages/zephyr/zephyr-rdb/src/table/select.ts`（`normalize`）、`packages/zephyr/zephyr-rdb/src/database/postgres.ts`（int8 解析器）、`packages/zephyr/zephyr-rdb/src/database/create.ts`（`iterateWrapped` 只包错误分类）。

**现象**

同一条 `bigint` 列，走两条读路径拿到两种值：

- `table.select(...)`：`table/select.ts` 按投影里的列定义把值归一成 `BigInt`（SQLite 的驱动给 `number`，这一步是必需的）；
- `database.read(fragment)` / `database.iterate(fragment)`：原样返回驱动的值。PostgreSQL 侧因为连接上装了 int8 解析器，仍然是 `BigInt`；SQLite 侧就是 `number`。

聚合值同样如此：`count` / `sum` 走投影路径时按表句柄的规则算，手写片段读回来的值由驱动决定。

**影响**

- 写原始片段（报表、迁移读取、`storage-takeover` 那种跨表统计）的人会拿到 `number`，一旦超过 2^53 就静默丢精度。
- 类型声明是 `bigint` 的地方，实际可能是 `number`——TypeScript 看不出来，只有大 ID 那天才发现。

**触发条件**

- 在 `database.read` / `iterate` 上直接读 `bigint` 列（手写片段、迁移、统计）之前，先确认值的来源。
- 要给 `read` 加归一（或统一收口）之前，先看这条。

**销账条件**

Done when：`bigint` 列的归一只有一个 home——`read` / `iterate` 与表句柄的投影都经过它，两条路径对同一列给出同一个 JS 类型，且 `src/__tests__` 里有一条「同一列走两条路径、类型相同」的用例。

**不修的理由**

- 现有消费方（`packages/agent-ex/better-session`）读写都走表句柄，撞不上第二条路径；PG 侧又恰好由驱动解析兜住。
- 收口要先决定「归一发生在渲染层还是连接层」——SQLite 没有驱动级钩子，答案只能是把归一放进 `createDatabase` 的迭代包装里，那会让投影与迭代各归一次（幂等但重复）。这件事该和接口面收敛一起做，不单独动。
