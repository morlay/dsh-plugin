# 结构漂移不报孤儿表

状态：未销账——「库里有、catalog 没有」的表还没有报告面：`planSchema` / `ensureSchema` 只算「缺表建表 / 缺列补列 / 缺索引补索引（可删列）」这些以 catalog 为基准的变更，`ensureSchema` 返回的是执行的语句清单；反向的「多出来的表」没有出口。
位置：`packages/zephyr/zephyr-rdb/src/migrate.ts` 的 `planSchema`（`kind` 只有 `create-table` / `add-column` / `create-index` / `drop-column`）与 `ensureSchema`（返回 `string[]`）；目标形状与已写好的用例在 `packages/zephyr/zephyr-rdb/src/__tests__/schema-drift.spec.ts`（`drift` 条目带 `kind` / `fix`，orphan 一条断言 `["t_legacy", "orphan", "manual"]`、只报告不执行 DDL）；消费方口径写在 `packages/agent-ex/better-session/.agents/designs/20261120-完整设计.md` 决定 9。

**现象**

- catalog 是唯一基准：多出来的表不参与比对，改名或删表定义之后旧表留在库里且无声。
- 结构漂移报告本身（「同名不同形」的列 / 索引差异 + `fix` 分级）在实现中：`schema-drift.spec.ts` 已按 `{ statements, drift }` 的新形状写好用例，其中两条就是 orphan（SQLite 与 PostgreSQL 各一条）。

**影响**

- 结构演进后库里堆积无人使用的表：备份变大、`VACUUM` 变慢，排障时分不清「这张表还在用吗」。
- better-session 把「漂移报告列 orphan」写进了设计决定 9，但拿不到这份清单，只能人工拿 `objectNames()` 对表定义。

**触发条件**

结构演进要先看清「库里多了什么」之前必须先还：改名表、删表定义、把某张表搬去别的库，这三件事都会留下孤儿表。

**销账条件**

Done when：`ensureSchema` 的 `drift` 里出现 orphan 条目（`objectNames()` 减 catalog，排除迁移账本、视图与方言自有表如 `sqlite_sequence`，`fix: "manual"`），不进 `statements`、`allowDestructive` 也不删；`schema-drift.spec.ts` 的 orphan 两条（SQLite / PostgreSQL）转绿。

**不修的理由**

边界要先定两条：哪些表算方言自有（SQLite 的 `sqlite_*`、PG 的系统 schema 与视图），以及报告与阻断的取舍；这两条正在与漂移报告一起落，单独先做 orphan 会把同一份差集算两遍。
