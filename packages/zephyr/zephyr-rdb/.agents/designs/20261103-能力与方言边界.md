# 能力与方言边界

状态：已实现——业务只拿注入的 `Database` 与 `E`；方言、连接、SQL 文本都不出这个包。
范围：`packages/zephyr/zephyr-rdb/`（`@morlay/zephyr-rdb`）的公开能力：表定义、表句柄、表达式、事务、库级操作与 `./testing`。
非目标：业务语义（哪些表、怎么查）；部署与连接管理（装配层给 `openDatabase` 的配置）；迁移脚本的内容。
关联：[设计 zephyr-rdb 的包内分层](./20261103-文件内分层.md)、[ADR-PostgreSQL 的 schema 跟着连接配置走](./../adrs/20261109-PostgreSQL-schema跟随连接配置.md)、[如何验证](./../standards/how-to-verify.md)。

## 一、决定

| #   | 议题           | 决定                                                                                                                 | 一句话理由                                                      |
| --- | -------------- | -------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------- |
| 1   | 业务侧接口     | 表句柄（`select` / `insert` / `update` / `delete`）加 `E.*` 表达式；`Database` 只给 `table` / 读写 / 事务 / 库级操作 | 语义由业务表达，SQL 由本包算                                    |
| 2   | 方言相关表达式 | 片段层用 `only(dialect, …)` 分流（JSON 提取、本地日、`SUM` 的 cast）                                                 | 渲染时只保留本方言那支，连绑定参数一起丢弃，不会串位            |
| 3   | 事务           | 顶层按实例串行；事务内嵌套走 `SAVEPOINT`；「是否已在事务里」用 `AsyncLocalStorage` 判                                | 并发调用的上下文不能靠计数器区分                                |
| 4   | 值类型         | `bigint` 列 ↔ JS `bigint`；聚合给 `number` 或 `bigint`；写入时 `bigint` 列接受安全整数范围内的 `number`              | int64 超过 2^53 用 `number` 会悄悄丢精度                        |
| 5   | 库级操作       | `objectNames` / `vacuum` / `sqlitePragma` / `setSqlitePragma` 挂在 `Database` 上                                     | `PRAGMA`、`VACUUM`、`sqlite_master` 不该出现在业务包里          |
| 6   | 测试辅助       | `./testing` 出 `openSqliteHandle` 与 `createPostgresTestDatabase`                                                    | 驱动能力留在这一层，业务包不必为测试再依赖 `pg` / `node:sqlite` |

## 二、现状事实

- **表定义是唯一来源**：`defineTable` 给出 DDL 与行类型（`RowOf` / `InsertRow`）；`ensureSchema` 按 `catalog` 算差异，`runMigrations` 跑数据迁移（账本是 `t_schema_migrations`）。
- **表达式两类**：条件（`eq` / `inList` / `and` / `exists` / `inSubquery` …）与值表达式（`coalesce` / `add` / `localDay` / `jsonText` …），都从 `E` 取；两者都能进投影、条件、分组与 upsert 赋值。
- **`Database` 的面**（`src/database/types.ts`）：`dialect` / `catalog` / `schema` / `table` / `iterate` / `read` / `write` / `run` / `transaction` / `objectNames` / `vacuum` / `sqlitePragma` / `setSqlitePragma` / `close`。`write` 当前就是 `read`（见[包内分层](./20261103-文件内分层.md)的已知债）。
- **方言原语**：`Executor`（`iterate` / `run` / `transaction` / `close`，`src/database/types.ts`）。SQLite 走 `node:sqlite`（`src/database/sqlite.ts`，`BEGIN IMMEDIATE` + 保存点 + `AsyncLocalStorage`），PostgreSQL 走 `pg` + `pg-cursor`（`src/database/postgres.ts`）。
- **串行队列**：`src/database/queue.ts` 的 `createSerialQueue`（事务外的写排队）与 `savepointName`（`zephyr_rdb_sp_<n>`）。
- **库级操作**在 `src/database/capabilities.ts`；`objectNames` 查配置的 schema（见 ADR）。
- **入口**：`.` → `src/index.ts`（`defineTable` / `openDatabase` / `ensureSchema` / `runMigrations` / `E` / `count` / `sum` / 复合查询与 `wrapDatabase` 等），`./testing` → `src/testing.ts`。

## 三、模块边界与接口

| 模块                                         | 拥有（职责与不变量）                                                              | 不拥有（明确排除）                                    | 依赖方向                | 接缝 / 适配器                               |
| -------------------------------------------- | --------------------------------------------------------------------------------- | ----------------------------------------------------- | ----------------------- | ------------------------------------------- |
| 表定义（`src/defs.ts`）                      | 列 / 索引 / 约束的类型面、DDL 与行类型的唯一来源                                  | 连接；业务查询                                        | 无                      | 纯数据                                      |
| 表句柄（`src/table/`）                       | 读写渲染、投影 / join / 分组 / 排序、聚合、值归一                                 | 方言差异（走 `Dialect`）；事务                        | ← `Fragment`、`Dialect` | 契约 `TableHandle`（不造第二个适配器）      |
| 表达式（`src/expr.ts`、`src/fragment.ts`）   | 条件与值表达式的构造、`only(dialect, …)` 分流、占位符渲染                         | 具体方言的 SQL 文本（归 `Dialect`）                   | 无                      | 纯函数                                      |
| 方言（`src/dialect.ts`）                     | 两种方言的列类型、标识符与表名的引号、DDL、`readShape`、`tableName` / `indexName` | 连接怎么开；业务逻辑                                  | 无                      | `Dialect` 接口 = 接缝（两个实现，是真接缝） |
| 连接与执行（`src/database/`）                | 打开连接、四个原语、事务语义、`onQuery` 观测、catalog 装配                        | 业务的 SQL；schema 的存在性（不自动 `CREATE SCHEMA`） | ← `node:sqlite` / `pg`  | `Executor` 接口                             |
| 迁移（`src/migrate.ts`、`src/migration.ts`） | 结构差异、加列 / 建索引 / 删列、迁移账本                                          | 迁移脚本的内容                                        | ← `Dialect`、`Database` | —                                           |
| 测试面（`src/testing.ts`）                   | 同步 SQLite 句柄、PostgreSQL 测试库                                               | 生产路径                                              | ← 驱动                  | `./testing` 出口                            |

**接口**：`openDatabase(config: OpenConfigWithCatalog): Promise<Database>`；`TableHandle<TableDef>` 的读写方法与列访问器；`E` 命名空间；`transaction(fn)`。
不变量：业务侧拿不到 SQL 文本与连接；`bigint` 列读回 `BigInt`；`vacuum` 不得在事务内调用；方言查询一律写 `?` 占位符，由 `render` 按方言重编号。

**深度**：删掉这个包，每个存储型的包都要自己写两种方言的渲染、事务串行、值归一与迁移——复杂度会在 N 个包各出现一次。

## 四、行为与边界

- 正常：`table.select(...)` 渲染成 SQL + 参数 → `iterate` 流式读 → 值归一 → 行。
- 错误：SQL 失败包成 `DbError`（`classifyError` 给分类）；方言不支持的操作直接抛。
- 取消：无显式取消面；读用 `iterate`，调用方 break 即停止（游标随连接关闭）。
- 生命周期：连接生命周期由创建方管（装配层）；`transaction` 的 `fn` 拿到的是同一个 `Database` 面（catalog 跟着走）。
- 并发：同一实例的写与事务排队串行；事务内的写不排队（它属于那次事务）；嵌套事务走保存点。
- 边界：`objectNames` 与 `readShape` 按 `database.schema` 限定；`public` 里不会再出现副本。

## 六、取舍

- 否掉「SQLite 一份 SQL、PostgreSQL 一份 SQL」的字符串三元：两个分支在渲染时只保留一支，能连参数一起丢弃。
- 否掉「直接透传驱动的值类型」：同一份表定义在两种方言下会得到不同的 JS 类型。
- 否掉「业务自己维护写队列」：串行与保存点是本包的职责。
- 否掉「连接上下 `SET search_path`」：隐式状态会和连接串的 `options` 互相覆盖（见 ADR）。
- 否掉「只按最小建议传 schema 参数」：表句柄的读写仍会跟着 `search_path` 跑偏。

## 七、不做与已知债

- 不自动 `CREATE SCHEMA`：schema 的存在性与所有权归部署方。
- 不做连接池：一个 `Database` 就是一条连接（事务串行是它的语义前提）。
- 已知债：值归一与类型映射的多个 home，见[设计 zephyr-rdb 的包内分层](./20261103-文件内分层.md)的「不做与已知债」。

## 八、开放问题

- 聚合值类型是 `number` 或 `bigint`，调用方要自己 `Number(x)`：是否给一个显式的 `asNumber` 投影，未定。
