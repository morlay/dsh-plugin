# zephyr-rdb 的包内分层

状态：已实现——文件按概念切开，`index.ts` 只做转出；值归一有一个 home，手写片段那条读路径仍不归一（见已知债）。
范围：`packages/zephyr/zephyr-rdb/src/`的文件划分与「一件事住哪个文件」。
非目标：公开接口的形状（见[业务侧接口与不做项](./20261103-业务侧接口与不做项.md)）；SQL 语义本身。
关联：[业务侧接口与不做项](./20261103-业务侧接口与不做项.md)、[完整库设计](./20261120-完整库设计.md)、[ADR-PostgreSQL 的 schema 跟着连接配置走](./../adrs/20261109-PostgreSQL-schema跟随连接配置.md)、[债务 值归一只走了一条读路径](./../debts/20261103-值归一只走了一条读路径.md)。

## 一、决定

| #   | 议题           | 决定                                                                                                                                               | 一句话理由                                   |
| --- | -------------- | -------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------- |
| 1   | 文件的粒度     | 一个文件一个概念：表定义、方言、片段、表达式、表句柄、连接与执行、迁移、复合并发、错误、测试面                                                     | 找东西靠名字而不是记忆；改 A 不会顺手碰到 B  |
| 2   | 表句柄拆五件   | `table/types.ts`（类型）/ `handle.ts`（句柄与列访问器）/ `render.ts`（DML）/ `select.ts`（查询）/ `normalize.ts`（值归一）                         | 类型面、渲染面、查询面、值归一的变化节奏不同 |
| 3   | 连接按概念拆   | `database/{sqlite,postgres}.ts` 各给四个原语；`queue.ts` 给按库身份共享的队列与保存点名；`lifecycle.ts` 给关闭与游标；`capabilities.ts` 放库级操作 | 事务语义两方言各自实现，改一处就够           |
| 4   | 入口只转出     | `index.ts` 只 re-export；唯一的改写是 `columnSql as columnRefSql`（见开放问题）                                                                    | 门面不该有实现                               |
| 5   | 测试只走出入口 | spec 一律 `import ... from "@morlay/zephyr-rdb"` / `"./testing"`                                                                                   | 出口面顺便被测到                             |

## 二、现状事实

`packages/zephyr/zephyr-rdb/src/`的当前布局：

| 文件                                 | 装什么                                                                                                                              |
| ------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------- |
| `defs.ts`                            | `Catalog` / `TableDef` / 列（含枚举 `values`、`json` 类型）/ 索引（含 `where`）/ 约束；`defineTable` / `defineCatalog`              |
| `dialect.ts`                         | `Dialect` 接口与两种实现：列类型、引号、DDL、`readShape`（含列与索引细节）、`supports`、`tableName` / `indexName`、`columnSql`      |
| `fragment.ts`                        | 片段与渲染：`fragment` / `concat` / `only` / `readBigInts` / `render`                                                               |
| `expr.ts`                            | 条件与值表达式（`eq` / `inList` / `coalesce` / `localDay` / `jsonText` …）、窗口函数（`rowNumber` / `rank` / `lag`）、`keysetAfter` |
| `table/types.ts`                     | `RowOf` / `InsertRow` / `UpdatePatch` / `ColumnValue` / `JsonValue` / `Projected` / `Aggregate`                                     |
| `table/handle.ts`                    | `createTableHandle` 与列访问器（`table.f_xxx`）                                                                                     |
| `table/render.ts`                    | `insert` / `insertMany` / `upsert` / `update` / `delete` 的渲染、列与枚举校验、JSON 绑定值转换                                      |
| `table/select.ts`                    | 查询渲染（投影 / join / 分组 / 排序 / 分页）、`count` / `sum` 的聚合渲染、投影侧的 bigint 归一                                      |
| `table/normalize.ts`                 | 一列值读回来的唯一规则（bigint / boolean / integer 还原 / JSON 解析）                                                               |
| `database/types.ts`                  | `Database` / `OpenConfig` / `QueryEvent` / `QueryOptions` / `Executor` / `SqlitePragmaName`                                         |
| `database/create.ts`                 | `createDatabase`（拼 `Database` 面、观测、取消检查、`transaction` 转发）+ `openDatabase` 入口                                       |
| `database/sqlite.ts` / `postgres.ts` | 两方言的连接与四个原语（SQLite：`node:sqlite`、`BEGIN IMMEDIATE`、保存点；PG：驱动池 + 游标、int8 → BigInt、真取消）                |
| `database/queue.ts`                  | `createSerialQueue` / `serialQueueFor`（同进程同库共享的写队列）、`savepointName`                                                   |
| `database/lifecycle.ts`              | 关闭状态、在飞游标登记、`interruptAll` / `drain`、`closedError`                                                                     |
| `database/library.ts`                | 库身份键（SQLite `dev:ino` / PG 连接串 + schema）与身份指纹                                                                         |
| `database/identity.ts`               | `readIdentity` / `writeIdentity`（SQLite PRAGMA / PG schema 注释）与打开时校验                                                      |
| `database/capabilities.ts`           | `objectNames` / `vacuum` / `sqlitePragma` / `setSqlitePragma` / `explain`                                                           |
| `database/wrap.ts`                   | `wrapDatabase`（把一条 `Executor` 包成 `Database`）与 `shapeReader`                                                                 |
| `migrate.ts` / `migration.ts`        | `ensureSchema` / `planSchema`（含漂移报告）与 `runMigrations` / `MigrationRegistry` / 账本表 / 迁移锁                               |
| `catalog.ts`                         | `indexCatalog`（表名 → 定义）                                                                                                       |
| `compound.ts`                        | `union` / `intersect` / `except` / `withCtes` / `forUpdate` / `aliasedTable`                                                        |
| `error.ts`                           | `DbError` / `classifyError` / 本包自造码与工厂                                                                                      |
| `testing.ts`                         | `openSqliteHandle` / `createPostgresTestDatabase`（`./testing`）                                                                    |
| `index.ts`                           | 只 re-export                                                                                                                        |

## 三、模块边界与接口

| 模块                          | 拥有（职责与不变量）                                  | 不拥有（明确排除）      | 依赖方向                 | 接缝 / 适配器              |
| ----------------------------- | ----------------------------------------------------- | ----------------------- | ------------------------ | -------------------------- |
| `defs.ts`                     | 表定义的形状与 DDL / 行类型的推导                     | 任何渲染与连接          | 无                       | 纯数据                     |
| `dialect.ts`                  | 方言差异的**唯一**出口（类型、引号、DDL、探测、能力） | 业务语义；事务          | ← `defs.ts`              | `Dialect` 接口（两个实现） |
| `fragment.ts` / `expr.ts`     | 片段的构造与渲染、`only` 分流、窗口与 keyset          | 具体方言文本            | ← `dialect.ts`           | 纯函数                     |
| `table/`                      | 表句柄的类型面、语句渲染与值归一                      | 连接、事务、方言细节    | ← `expr` / `dialect`     | `TableHandle`              |
| `database/`                   | 连接、四个原语、事务、串行与库身份、取消、观测        | 业务 SQL；schema 存在性 | ← 驱动                   | `Executor` 接口            |
| `migrate.ts` / `migration.ts` | 结构差异与漂移报告、迁移账本与并发锁                  | 迁移脚本内容            | ← `dialect` / `database` | —                          |
| `index.ts` / `testing.ts`     | 两个出口的形状                                        | 实现                    | —                        | —                          |

**接口**：跨文件只经具名导出；`database/` 不 import `table/` 的渲染，`table/` 不 import 驱动的类型。
不变量：`dialect.ts` 是方言差异的唯一 home（新增方言只改它 + `database/` 的一个文件）；渲染只在 `table/render.ts` 与 `table/select.ts` 里发生；值归一只在 `table/normalize.ts`。

**深度**：删掉这层划分（回到两个大文件），改事务要读整条链路，加一个列类型要翻五处——这正是它存在的原因。

## 四、行为与边界

- 正常路径、错误、生命周期：见[完整库设计](./20261120-完整库设计.md)第四节（本层只规定「住哪个文件」）。
- 顺序：`createDatabase` 先定 schema（PG 缺省 `public`、SQLite 恒 `undefined`），再拼 `Database` 面；`transaction` 把同一个 catalog 带进事务。
- 并发：队列与保存点在 `database/queue.ts`，两方言各自决定何时入队；库身份键在 `database/library.ts`。

## 六、取舍

- 否掉「一个 `sql/` 目录再拆 DML / DDL / SELECT」：现在的 `table/render.ts` 与 `table/select.ts` 已经按这个边界分好，多一层目录只是多一跳。
- 否掉「contracts/ 目录」：契约就是 `Database` / `TableHandle` 两个类型，放在 `database/types.ts` 与 `table/types.ts`，与实现同层。
- 否掉「给 `TableHandle` 造第二个适配器」：它是深模块的接口，不是接缝。
- 否掉「关闭状态、库身份键、游标登记各塞进方言文件」：三种方言共用同一套语义，塞进去会复制三份。

## 七、不做与已知债

- 不改 `Database` / `TableHandle` 的核心接口形状（方法只增不改名）。
- 已知债：[值归一只走了一条读路径](./../debts/20261103-值归一只走了一条读路径.md)（表句柄两条路径经 `table/normalize.ts`；手写片段要 `readBigInts` 标记才按 BigInt 读）。

## 八、开放问题

- 接口面比真实使用宽：`wrapDatabase`（生产零调用）、`onQuery`（没有生产调用方传它）、`aliasedTable` 都没有真实消费者。收敛还是保留，未定。
- `columnSql` 同名两义：`dialect.ts` 的是列定义 DDL、`expr.ts` 的是列引用；出口里把后者改名为 `columnRefSql` 只是遮住了重名，源头仍有两个函数叫同一个名字。是否重命名其中一个，未定。
- `E.inSubquery(ref, Fragment)` 要求调用方先 `.toFragment()`：表达式接口漏了实现细节。改成接受查询对象要先看消费方（`packages/agent-ex/better-session` 的 `repository.ts`）怎么用，未定。
