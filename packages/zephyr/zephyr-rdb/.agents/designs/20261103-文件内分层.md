# zephyr-rdb 的包内分层

状态：已实现——文件按概念切开，`index.ts` 只做转出；值归一仍有第二个 home（见已知债）。
范围：`packages/zephyr/zephyr-rdb/src/`的文件划分与「一件事住哪个文件」。
非目标：公开接口的形状（见[设计 能力与方言边界](./20261103-能力与方言边界.md)）；SQL 语义本身。
关联：[设计 能力与方言边界](./20261103-能力与方言边界.md)、[ADR-PostgreSQL 的 schema 跟着连接配置走](./../adrs/20261109-PostgreSQL-schema跟随连接配置.md)、[债务 值归一有两个 home](./../debts/20261103-值归一有两个home.md)。

## 一、决定

| #   | 议题           | 决定                                                                                                      | 一句话理由                                  |
| --- | -------------- | --------------------------------------------------------------------------------------------------------- | ------------------------------------------- |
| 1   | 文件的粒度     | 一个文件一个概念：表定义、方言、片段、表达式、表句柄、连接与执行、迁移、复合并发、错误、测试面            | 找东西靠名字而不是记忆；改 A 不会顺手碰到 B |
| 2   | 表句柄拆四件   | `table/types.ts`（类型）/ `handle.ts`（句柄与列访问器）/ `render.ts`（DML）/ `select.ts`（查询）          | 类型面、渲染面、查询面的变化节奏不同        |
| 3   | 连接拆两方言   | `database/{sqlite,postgres}.ts` 各给四个原语；`queue.ts` 只给队列与保存点名；`capabilities.ts` 放库级操作 | 事务语义两方言各自实现，改一处就够          |
| 4   | 入口只转出     | `index.ts` 只 re-export；唯一的改写是 `columnSql as columnRefSql`（见开放问题）                           | 门面不该有实现                              |
| 5   | 测试只走出入口 | spec 一律 `import ... from "@morlay/zephyr-rdb"` / `"./testing"`                                          | 出口面顺便被测到                            |

## 二、现状事实

`packages/zephyr/zephyr-rdb/src/`的当前布局：

| 文件                                 | 装什么                                                                                                                            |
| ------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------- |
| `defs.ts`                            | `Catalog` / `TableDef` / 列 / 索引 / 约束；`defineTable` / `defineCatalog`                                                        |
| `dialect.ts`                         | `Dialect` 接口与两种实现：列类型、引号、DDL、`readShape`、`tableName` / `indexName`、`columnSql`（列定义）                        |
| `fragment.ts`                        | 片段与渲染：`fragment` / `concat` / `only` / `render`                                                                             |
| `expr.ts`                            | 条件与值表达式（`eq` / `inList` / `coalesce` / `localDay` / `jsonText` …）、`column` / `value` / `excluded`；`E` 就是它的命名空间 |
| `table/types.ts`                     | `RowOf` / `InsertRow` / `UpdatePatch` / `ColumnValue` / `Projected` / `Aggregate`                                                 |
| `table/handle.ts`                    | `createTableHandle` 与列访问器（`table.f_xxx`）                                                                                   |
| `table/render.ts`                    | `insert` / `insertMany` / `upsert` / `update` / `delete` 的语句渲染                                                               |
| `table/select.ts`                    | 查询渲染（投影 / join / 分组 / 排序 / 分页）、`count` / `sum` 的聚合渲染、投影侧的 bigint 归一                                    |
| `database/types.ts`                  | `Database` / `OpenConfig` / `QueryEvent` / `Executor` / `SqlitePragmaName`                                                        |
| `database/create.ts`                 | `createDatabase`（拼 `Database` 面、`observe` 观测、`transaction` 转发）+ `openDatabase` 入口                                     |
| `database/sqlite.ts` / `postgres.ts` | 两方言的连接与四个原语（SQLite：`node:sqlite`、`BEGIN IMMEDIATE`、保存点；PG：`pg` + 游标、int8 → BigInt 的解析器）               |
| `database/queue.ts`                  | `createSerialQueue`（事务外的写排队）、`savepointName`                                                                            |
| `database/capabilities.ts`           | `objectNames` / `vacuum` / `sqlitePragma` / `setSqlitePragma` / `shapeReader`                                                     |
| `database/wrap.ts`                   | `wrapDatabase`（把一条 `Executor` 包成 `Database`）                                                                               |
| `migrate.ts` / `migration.ts`        | `ensureSchema` / `planSchema` 与 `runMigrations` / `MigrationRegistry` / 账本表                                                   |
| `catalog.ts`                         | `indexCatalog`（表名 → 定义）                                                                                                     |
| `compound.ts`                        | `union` / `intersect` / `except` / `withCtes` / `forUpdate` / `aliasedTable`                                                      |
| `error.ts`                           | `DbError` / `classifyError`                                                                                                       |
| `testing.ts`                         | `openSqliteHandle` / `createPostgresTestDatabase`（`./testing`）                                                                  |
| `index.ts`                           | 只 re-export                                                                                                                      |

## 三、模块边界与接口

| 模块                          | 拥有（职责与不变量）                            | 不拥有（明确排除）             | 依赖方向                 | 接缝 / 适配器              |
| ----------------------------- | ----------------------------------------------- | ------------------------------ | ------------------------ | -------------------------- |
| `defs.ts`                     | 表定义的形状与 DDL / 行类型的推导               | 任何渲染与连接                 | 无                       | 纯数据                     |
| `dialect.ts`                  | 方言差异的**唯一**出口（类型、引号、DDL、探测） | 业务语义；事务                 | ← `defs.ts`              | `Dialect` 接口（两个实现） |
| `fragment.ts` / `expr.ts`     | 片段的构造与渲染、`only` 分流                   | 具体方言的文本（`Dialect` 给） | ← `dialect.ts`           | 纯函数                     |
| `table/`                      | 表句柄的类型面与语句渲染                        | 连接、事务、方言细节           | ← `expr` / `dialect`     | `TableHandle`              |
| `database/`                   | 连接、四个原语、事务、观测、库级操作            | 业务 SQL；schema 存在性        | ← 驱动                   | `Executor` 接口            |
| `migrate.ts` / `migration.ts` | 结构差异与迁移账本                              | 迁移脚本内容                   | ← `dialect` / `database` | —                          |
| `index.ts` / `testing.ts`     | 两个出口的形状                                  | 实现                           | —                        | —                          |

**接口**：跨文件只经具名导出；`database/` 不 import `table/` 的渲染，`table/` 不 import 驱动的类型。
不变量：`dialect.ts` 是方言差异的唯一 home（新增方言只改它 + `database/` 的一个文件）；渲染只在 `table/render.ts` 与 `table/select.ts` 里发生。

**深度**：删掉这层划分（回到两个大文件），改事务要读整条链路，加一个列类型要翻五处——这正是它存在的原因。

## 四、行为与边界

- 正常路径、错误、生命周期：见[设计 能力与方言边界](./20261103-能力与方言边界.md)第四节（本层只规定「住哪个文件」）。
- 顺序：`createDatabase` 先定 schema（PG 缺省 `public`、SQLite 恒 `undefined`），再拼 `Database` 面；`transaction` 把同一个 catalog 带进事务。
- 并发：队列与保存点在 `database/queue.ts`，两方言各自决定何时入队。

## 六、取舍

- 否掉「一个 `sql/` 目录再拆 DML / DDL / SELECT」：现在的 `table/render.ts` 与 `table/select.ts` 已经按这个边界分好，多一层目录只是多一跳。
- 否掉「contracts/ 目录」：契约就是 `Database` / `TableHandle` 两个类型，放在 `database/types.ts` 与 `table/types.ts`，与实现同层。
- 否掉「给 `TableHandle` 造第二个适配器」：它是深模块的接口，不是接缝。

## 七、不做与已知债

- 不改 `Database` / `TableHandle` 的接口形状（调用方零感知）。
- 已知债：[值归一有两个 home](./../debts/20261103-值归一有两个home.md)（`table/select.ts` 的投影归一 vs PG 驱动的 int8 解析；`database.read` 走原样）。

## 八、开放问题

- 接口面比真实使用宽：`write`（就是 `read`）、`wrapDatabase`（生产零调用）、`onQuery`（没有生产调用方传它）、`aliasedTable` 都没有真实消费者。收敛还是保留，未定。
- `columnSql` 同名两义：`dialect.ts` 的是列定义 DDL、`expr.ts` 的是列引用；出口里把后者改名为 `columnRefSql` 只是遮住了重名，源头仍有两个函数叫同一个名字。是否重命名其中一个，未定。
- `E.inSubquery(ref, Fragment)` 要求调用方先 `.toFragment()`：表达式接口漏了实现细节。改成接受查询对象要先看消费方（`packages/agent-ex/better-session` 的 `repository.ts`）怎么用，未定。
