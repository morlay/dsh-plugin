# 业务侧接口与不做项

状态：已实现——业务只拿注入的 `Database` 与 `E`；方言、连接、SQL 文本都不出这个包。
范围：`@morlay/zephyr-rdb` 给业务侧的那一面：表定义、表句柄、表达式、`Database`、`./testing`。
非目标：方言能力矩阵与失败面（见[完整库设计](./20261120-完整库设计.md)）；包内文件划分（见[包内分层](./20261103-文件内分层.md)）；事务与值归一的细节（见[读写通道的作用域与失败面](./20261120-读写通道的作用域与失败面.md)）。
关联：[完整库设计](./20261120-完整库设计.md)、[包内分层](./20261103-文件内分层.md)、[ADR-PostgreSQL 的 schema 跟着连接配置走](./../adrs/20261109-PostgreSQL-schema跟随连接配置.md)、[如何验证](./../standards/how-to-verify.md)。

## 一、决定

| #   | 议题       | 决定                                                                                                                                    | 一句话理由                                                        |
| --- | ---------- | --------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------- |
| 1   | 业务侧接口 | 表句柄（`select` / `insert` / `update` / `delete`）加 `E.*` 表达式；`Database` 只给 `table` / 读写 / 事务 / 库级操作 / 身份 / `explain` | 语义由业务表达，SQL 由本包算                                      |
| 2   | 值类型     | 列类型 → 固定 JS 类型：`bigint` ↔ `bigint`、`boolean` ↔ `true`/`false`、`json` ↔ 结构化值、枚举 text ↔ `string`                         | 同一份表定义在两方言给同一个类型，不跟驱动走                      |
| 3   | 库级操作   | `objectNames` / `vacuum` / `sqlitePragma` / `setSqlitePragma` / `explain` 挂在 `Database` 上                                            | `PRAGMA`、`VACUUM`、`sqlite_master`、`EXPLAIN` 不该出现在业务包里 |
| 4   | 测试辅助   | `./testing` 出 `openSqliteHandle` 与 `createPostgresTestDatabase`                                                                       | 驱动能力留在这一层，业务包不必为测试再依赖 `pg` / `node:sqlite`   |

## 二、现状事实

- **表定义是唯一来源**：`defineTable` 给出 DDL 与行类型（`RowOf` / `InsertRow`）；`ensureSchema` 按 `catalog` 算差异并返回漂移清单；`runMigrations` 跑数据迁移（账本是 `t_schema_migrations`）。
- **`Database` 的面**（`src/database/types.ts`）：`dialect` / `catalog` / `schema` / `table` / `iterate` / `read` / `write` / `run` / `transaction` / `explain` / `readIdentity` / `writeIdentity` / `objectNames` / `vacuum` / `sqlitePragma` / `setSqlitePragma` / `close`。
- **入口**：`.` → `src/index.ts`（表定义、片段、表达式、表句柄、`Database`、迁移、错误）；`./testing` → `src/testing.ts`。
- **表达式两类**：条件（`eq` / `inList` / `and` / `exists` / `inSubquery` …）与值表达式（`coalesce` / `add` / `localDay` / `jsonText` / 窗口函数 `rowNumber` / `rank` / `lag` …），都从 `E` 取。
- **分页**：`limit` / `offset` 与 keyset（`keysetAfter` 给「从上一页最后一行之后取」的行值比较条件）。

## 三、不做（明确）

- **业务不写 SQL**：查询、写入、DDL、迁移都从定义算出来；方言相关的东西（JSON 提取、本地日、PRAGMA、`EXPLAIN`）由本包渲染；`raw(sql, params)` 是唯一逃生口。
- **不做 ORM 的关系映射、查询缓存、跨库事务编排、迁移回滚、自动建 schema**。
- **业务不认数据库**：`Database` 是注入项，方言只在装配层出现；换库不改业务代码。
- **不承诺跨进程一致性**：单实例写串行 + 同进程同库共享队列；跨进程由库自己的锁（SQLite 写锁 / PostgreSQL advisory lock）兜底。
