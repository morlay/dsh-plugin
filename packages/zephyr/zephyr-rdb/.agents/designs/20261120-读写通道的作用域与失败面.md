# 读写通道的作用域、值类型与失败面（zephyr-rdb）

状态：已实现——判据见 `src/__tests__/{transaction-scope,write-channel,robustness,lifecycle}.spec.ts`；`pnpm exec vitest run packages/zephyr/zephyr-rdb` 全绿。
范围：事务执行面的归属、写通道的排队、值归一的 home、写语句的列校验、分页参数、片段占位符校验、错误分类、打开失败与关闭的收尾。
非目标：连接池参数与超时（配置面）、跨进程写仲裁、结构漂移报告（见[完整库设计](./20261120-完整库设计.md)的判据 3）。
关联：[业务侧接口与不做项](./20261103-业务侧接口与不做项.md)、[包内分层](./20261103-文件内分层.md)、[完整库设计](./20261120-完整库设计.md)、[债-值归一只走了一条读路径](../debts/20261103-值归一只走了一条读路径.md)、[ADR-PostgreSQL 的 schema 跟着连接配置走](../adrs/20261109-PostgreSQL-schema跟随连接配置.md)。

## 一、决定

| #   | 议题          | 决定                                                                                                                                    | 一句话理由                                                                         |
| --- | ------------- | --------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------- |
| 1   | 事务内的读写  | 事务给的执行面必须被读与写**同时**使用（PostgreSQL 的 `iterate` 先看 `AsyncLocalStorage`）                                              | 从池里另取一条连接读不到本事务未提交的写入，位点校验会误报「另一个写者」           |
| 2   | 写通道        | `Database.write` 走 `Executor.write`：事务外与 `run` 共用写队列，事务内走事务连接                                                       | 带 `RETURNING` 的写不能插进别人未提交的事务里                                      |
| 3   | 值归一的 home | `src/table/normalize.ts` 一处；投影查询与 `RETURNING` 都过它；bigint 的读取开关由片段标记驱动                                           | 同一个 `RowOf<T>` 两条路径给两种值的类型声明是假的                                 |
| 4   | 写语句的列    | 列不在表定义里即 fail loud（`insert` / `insertMany` / `update`）；枚举列的值也在这里校验                                                | 静默过滤等于把写错列名的数据悄悄丢掉，可空列最难发现                               |
| 5   | 分页参数      | `limit` / `offset` 只收非负安全整数；单独 `offset` 在 SQLite 侧补 `LIMIT -1`                                                            | 负数在 SQLite 是「无限制」、单独 `OFFSET` 在 SQLite 是语法错误，两方言不能各说一套 |
| 6   | 片段占位符    | `fragment(sql, params)` 的 `?` 个数与参数个数必须相等，否则构造期抛错                                                                   | 少给参数让 PostgreSQL 的 `$n` 出现空洞，多给参数被静默丢弃                         |
| 7   | 错误分类      | `DbErrorKind` 含 `retryable` / `canceled` / `connection` / `closed` / `unsupported` / `identity`；`DbError` 带原始 `code` 与 `sqlState` | 调用方按 `kind` 分支、按 `code` 精确判定，不认文案                                 |
| 8   | 打开失败收尾  | `openSqlite` 的 PRAGMA 抛错时自己 `close()`；`openDatabase` 的身份校验失败也自己 `close()`                                              | 打开失败的调用方拿不到 executor，没人能关这个句柄                                  |
| 9   | 关闭          | `close()` 幂等；关闭后的语句抛 `DbError("closed")`（`ZEPHYR_RDB_CLOSED`）；在飞游标先关                                                 | 关两次不该炸；关掉后的查询是「用错生命周期」，不是驱动裸错                         |

## 二、现状事实

- 事务作用域：`src/database/postgres.ts` 的 `iterate` / `write` / `run` 都从 `AsyncLocalStorage` 取事务连接；`src/database/sqlite.ts` 的事务内读写就是同一条连接。
- 写通道：`Executor.write`（`src/database/types.ts`）返回 `RETURNING` 的行；两个方言都在事务外用 `serialQueueFor(libraryKey)` 排队，事务内直接用事务连接（`src/database/{sqlite,postgres}.ts`）。
- 值归一：`src/table/normalize.ts` 的 `normalizeValue`（bigint、boolean、integer/serial 的 BigInt 还原、JSON 解析）与 `normalizeReturning`；`src/table/select.ts` 的投影归一与 `src/table/handle.ts` 的三个 `RETURNING` 写方法都只调它们。
- bigint 读取开关：`src/fragment.ts` 的 `readBigInts(fragment)` 标记 → `render` 汇总成 `readBigInts` → `ExecutorOptions` → SQLite 的 `statement.setReadBigInts(true)`；表句柄按列定义自动标记（投影与 `RETURNING`）。
- 写语句的列与枚举校验：`src/table/render.ts` 的 `assertKnownColumns` / `assertEnumValues`。
- 分页：`src/table/select.ts` 的 `assertCount` 与 `LIMIT -1` 的方言片段；keyset 由 `src/expr.ts` 的 `keysetAfter` 给行值比较条件。
- 片段：`src/fragment.ts` 的 `fragment` 在构造期比对占位符与参数个数。
- 错误：`src/error.ts` 的 `POSTGRES_STATES` / `SQLITE_CODES` / `CONNECTION_CODES` 三张表 + socket 码映射 + 本包自造码（`ZEPHYR_RDB_CLOSED` / `ZEPHYR_RDB_UNSUPPORTED` / `ZEPHYR_RDB_IDENTITY_MISMATCH`）。
- 生命周期：`src/database/lifecycle.ts`（关闭状态、在飞游标登记、`interruptAll` / `drain`）。
- 用例：`src/__tests__/transaction-scope.spec.ts`（假 `Executor`，不需要真库）、`write-channel.spec.ts`（事务外的 `RETURNING` 写不落进未提交事务）、`robustness.spec.ts`（占位符、分页、RETURNING 值类型、未知列、错误分类）、`lifecycle.spec.ts`（幂等关闭、关闭后报 `closed`、在飞游标）。

## 三、模块边界与接口

| 模块                      | 拥有（职责与不变量）                               | 不拥有（明确排除）         | 依赖方向               | 接缝 / 适配器               |
| ------------------------- | -------------------------------------------------- | -------------------------- | ---------------------- | --------------------------- |
| `database/`（连接与执行） | 事务执行面的归属、写语句排队、错误分类、关闭与游标 | 值归一、分页语义           | ← `node:sqlite` / `pg` | `Executor` 接口（两个实现） |
| `database/lifecycle.ts`   | 关闭状态与在飞游标登记                             | 方言细节                   | ← `error.ts`           | 纯状态机                    |
| `database/library.ts`     | 库身份键（`dev:ino` / 连接串 + schema）与指纹      | 连接                       | ← `node:fs`            | 纯函数                      |
| `table/normalize.ts`      | 一列值读回来的唯一规则                             | 哪些列要归一（由列定义定） | ← `defs.ts`            | 纯函数                      |
| `table/render.ts`         | 写语句的列校验与渲染                               | 值归一                     | ← `defs.ts`、`expr.ts` | 纯函数                      |
| `table/select.ts`         | 查询渲染、分页参数、投影归一                       | 事务                       | ← `normalize.ts`       | `TableHandle` 的方法        |
| `error.ts`                | 驱动错误到 `DbErrorKind` 的翻译 + 本包自造码       | 重试策略（调用方定）       | ← 驱动错误             | 三张表（可加不改语义）      |

接口（调用方要知道的）：

- `database.transaction(fn)` 的 `fn` 拿到的 `Database` 面上，读与写都在这次事务里；事务外的写排队、事务外的读不排队（读的一致性靠隔离级别与快照）。
- `RETURNING` 与 `select` 对同一列给出同一个 JS 类型；手写片段要同类型就带 `readBigInts(fragment(...))` 标记。
- `limit` / `offset` 传负数或非整数抛错；SQLite 上单独 `offset` 合法。
- `DbError.kind` 的 `retryable` 表示「整段可重跑」，`canceled` 表示「语句被取消/超时中断」，`connection` 表示「连接层失败」，`closed` 表示「库已关闭」，`unsupported` 表示「方言缺能力」，`identity` 表示「库身份不符」。

## 四、行为与边界

1. 正常路径：事务内 `table.select` / `insert(...returning)` 与事务外的读写出自同一条实现，差别只在执行面。
2. 错误：写错列名、非枚举值、分页参数非法、占位符与参数不匹配都是构造期抛错（不是驱动错误）；驱动错误一律经 `classifyError`。
3. 并发：事务外的写与事务在同一条队列里串行（同进程同库共享队列）；事务内的写属于该事务，不排队。
4. 生命周期：打开失败自己关句柄；`close()` 幂等，关闭后新语句抛 `closed`；PostgreSQL 在 `pool.end()` 前先关在飞游标，SQLite 延迟到在飞迭代退出后关连接。

## 六、取舍

- 否掉「事务外的读也进队列（SQLite）」：排队会把读推迟到事务之后并让结果集物化；它暴露的是消费方「用读面做存在性判断」的竞态，不是本包该承担的语义。
- 否掉「对含 bigint 列的语句统一 `setReadBigInts(true)`」：那会把同一语句里的 INTEGER 列一起变成 BigInt；改用片段标记 + 列定义归一，只让 bigint 列是 BigInt。
- 否掉「`write` 与 `read` 同一原语」：带 `RETURNING` 的写会绕开写队列，和别的事务交错；独立的 `Executor.write` 让排队对写成立。
- 否掉「`close()` 不等在飞游标」：PostgreSQL 的 `pool.end()` 会永久 pending；登记游标让关闭有确定的顺序。
- 否掉「`delete()` / `update()` 无条件的调用改成显式入口」：破坏既有接口，且消费方都带条件；先记在开放问题里。

## 七、不做与已知债

- 已知债：[值归一只走了一条读路径](../debts/20261103-值归一只走了一条读路径.md)（`boolean` 与未打 `readBigInts` 标记的手写片段仍原样返回驱动的值）。
- 不做跨进程写仲裁：同进程同库共享队列，跨进程靠库自己的锁（SQLite 写锁 / PostgreSQL advisory lock）。

## 八、开放问题

- `delete()` / `update()` 的 `condition` 可选，一条不带参数的调用就是全表写；要不要改成 `deleteAll` / `updateAll` 的显式入口。
- `columnSql` 同名两义（列定义 DDL 与列引用）仍未改名。
