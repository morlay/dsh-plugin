# 完整库设计：能力面、方言矩阵与判据（zephyr-rdb）

状态：已实现（除 §八 两个开放问题）——判据见 §五；`pnpm exec vitest run packages/zephyr/zephyr-rdb` 全绿，PostgreSQL 用例在真库上全绿。
范围：`@morlay/zephyr-rdb` 作为**通用库**的功能面（SQLite + PostgreSQL，含 schema）、公开接口形状、方言适配、事务与并发语义、迁移与结构、失败与观测、测试策略。
非目标：第三种方言的实现（只保留 `Dialect` 接缝）；跨库/分布式事务；跨实例写仲裁；软删除、审计、触发器、视图、行级安全、分区表。
关联：[业务侧接口与不做项](./20261103-业务侧接口与不做项.md)、[包内分层](./20261103-文件内分层.md)、[读写通道的作用域与失败面](./20261120-读写通道的作用域与失败面.md)、[ADR-PostgreSQL 的 schema 跟着连接配置走](../adrs/20261109-PostgreSQL-schema跟随连接配置.md)。

## 一、决定

| #   | 议题     | 决定                                                                                                      | 一句话理由                                                                  |
| --- | -------- | --------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------- |
| 1   | 定位     | 通用库：统一适配多方言的数据库操作；开发版本，允许 breaking，但每条 breaking 必须有判据用例               | 对外承诺的代价由判据消化，而不是靠兼容层                                    |
| 2   | 方言范围 | 本版只承诺 SQLite + PostgreSQL；`Dialect` 是唯一方言接缝，不承诺第三方言                                  | 一个接缝一个实现是假接缝，两个才是真接缝；第三种方言等真需求                |
| 3   | 能力矩阵 | 缺能力时**运行期抛带 `code: "unsupported"` 的 `DbError`**，不静默降级                                     | 静默降级会让同一份业务代码在换库后悄悄少做事                                |
| 4   | schema   | 一个 `Database` 绑定一个默认 schema；DDL/DML/账本/探测/身份同一口径                                       | schema 是连接上的事实，不各自猜                                             |
| 5   | 事务归属 | 库只承诺**单实例内**一致性（写排队、事务内读写同一执行面、隔离级别透传、可重试码）；跨实例不承诺          | 跨实例仲裁需要域层知识；库给出可组合工具（行锁 + 版本列）                   |
| 6   | 串行粒度 | **同进程同库**共用一条写队列：SQLite 取解析后文件的 `dev:ino`，PostgreSQL 取连接串 + schema；跨进程不承诺 | 每个实例一条队列时，同进程两个实例仍会撞 SQLite 写锁 / PG serializable 冲突 |
| 7   | 重试     | 只提供「可重试判定 + helper（带退避）」，不隐式重试                                                       | 隐式重试会把不可预期的重复副作用藏起来                                      |
| 8   | 交付     | 设计先行 → 票据实施 → 收敛过宽接口面                                                                      | 接口先定，判据才能先写；否则测试追着实现跑                                  |

### 能力面（进 / 不进）

| 组   | 进                                                                                                                               | 不进（理由）                                                                  |
| ---- | -------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------- |
| 类型 | 枚举（受检 text）、JSON（SQLite `json` / PG `jsonb`）、整型毫秒时间 + 派生本地日                                                 | 原生 `date`/`timestamp`（方言差异大且与时区语义纠缠）、数组、生成列、地理类型 |
| 约束 | 单列唯一、表级唯一、复合主键、外键 + `ON DELETE`、`CHECK`、部分索引                                                              | 触发器、物化视图、行级安全、分区表（属部署或域层）                            |
| 查询 | 投影/别名、全部 join、`IN`/`EXISTS` 子查询、递归 CTE、分组 + `having`、排序、`limit`/`offset`、keyset 分页、`distinct`、窗口函数 | `grouping sets`/`rollup`/`cube`（用多次查询或视图表达）、全文检索、向量检索   |
| 写入 | 单条/批量插入、`upsert`（含表达式赋值）、`INSERT … SELECT`、条件 `update`/`delete` + `RETURNING`、显式全表写入口                 | 软删除、审计日志、`UPDATE … FROM`/`DELETE … USING`（用子查询表达）            |
| 事务 | 顶层串行、嵌套保存点、隔离级别、`FOR UPDATE [NOWAIT｜SKIP LOCKED]`、乐观版本列约定                                               | 跨库/分布式事务、两阶段提交、跨实例写仲裁                                     |
| 运维 | 结构差异 + 漂移报告、迁移账本、并发迁移锁、`EXPLAIN` 观测、慢查询事件、`VACUUM`、库身份读写                                      | 迁移回滚（只前进）、自动建 schema、自建连接池、SQL 审计与权限系统             |
| 失败 | 分类 + 原始码、可重试判定、超时、取消（`AbortSignal` 贯通）、幂等 `close`                                                        | 自动重试、熔断、限流                                                          |

### 方言能力矩阵

代码事实是 `src/dialect.ts` 的 `supports(capability)` 与两个能力集合；用例是 `capability-matrix.spec.ts`。

| 能力             | SQLite                                          | PostgreSQL                                          | 缺能力时                                                               |
| ---------------- | ----------------------------------------------- | --------------------------------------------------- | ---------------------------------------------------------------------- |
| `schema`         | 无（表名不带前缀）                              | 有（`"schema"."table"`）                            | —                                                                      |
| `row-lock`       | 无                                              | `FOR UPDATE [NOWAIT｜SKIP LOCKED]`                  | `DbError("unsupported")`，`code: ZEPHYR_RDB_UNSUPPORTED`（不静默丢弃） |
| `advisory-lock`  | 无（迁移靠 `BEGIN IMMEDIATE` 写锁）             | 有（`pg_advisory_xact_lock`）                       | 迁移改走立即事务                                                       |
| `json`           | JSON1（列存 TEXT）                              | `JSONB`                                             | —                                                                      |
| `explain`        | `EXPLAIN QUERY PLAN`（取 `detail`）             | `EXPLAIN (FORMAT TEXT)`（取 `QUERY PLAN`）          | —                                                                      |
| `partial-index`  | `CREATE INDEX … WHERE`                          | `CREATE INDEX … WHERE`                              | —                                                                      |
| `savepoint`      | 有                                              | 有                                                  | —                                                                      |
| `vacuum-analyze` | 无（只有 `VACUUM`）                             | 有（`VACUUM ANALYZE`）                              | —                                                                      |
| bigint 读取      | 语句级 `setReadBigInts`（片段标记驱动）         | 连接级 int8 解析器（OID 20 → BigInt）               | —                                                                      |
| 取消             | 语句前后 + 迭代行间检查（同步驱动不能中途打断） | 真取消（`pg_cancel_backend`）+ 游标批次间           | —                                                                      |
| 事务             | `BEGIN IMMEDIATE` / `SAVEPOINT`                 | `BEGIN [ISOLATION LEVEL …]` / `SAVEPOINT`           | —                                                                      |
| 类型系统         | `INTEGER` / `TEXT`（bigint 与 integer 同类型）  | `BIGINT` / `INTEGER` / `TEXT` / `BOOLEAN` / `JSONB` | —                                                                      |

## 二、现状事实

- 公开面：`defineTable`/`defineCatalog`、DDL 与 `planSchema`/`ensureSchema`（返回 `{ statements, drift }`）、`MigrationRegistry`/`runMigrations`（PostgreSQL advisory lock / SQLite 立即事务）、片段与 `render`、条件与值表达式（含窗口函数与 `keysetAfter`）、`TableHandle` 的读写与 `RETURNING`、`Database` 的 `table`/`iterate`/`read`/`write`/`run`/`transaction`/`explain`/`readIdentity`/`writeIdentity`/库级操作、`DbError`/`classifyError`、`./testing`。
- 事务与写通道：`Database.write` 是独立执行面（`Executor.write`），事务外与 `run` 共用写队列、事务内走事务连接；SQLite 走 `BEGIN IMMEDIATE` + 保存点；PostgreSQL 走驱动池 + 保存点（`src/database/{sqlite,postgres}.ts`）。写队列按库身份共享（`src/database/queue.ts` 的 `serialQueueFor`、`src/database/library.ts`）。
- 生命周期：`close()` 幂等、关闭后语句抛 `DbError("closed")`（`code: ZEPHYR_RDB_CLOSED`）、在飞游标在关闭前被关（PostgreSQL `pg-cursor`；SQLite 延迟到迭代退出后关连接）（`src/database/lifecycle.ts`）。
- 结构：`planSchema` 报「同名不同形」的漂移（索引列、索引唯一性、列类型/可空/默认值、唯一约束缺失），可自动修的进 `changes`、只报告的进 `drift`（`src/migrate.ts`）；反向差集（库里有、catalog 没有的表，排除视图、迁移账本与方言自有表）列为 `kind: "orphan"`、`fix: "manual"`，只报告不生成 DDL，`runMigrations` 把它随 `{ executed, drift }` 一起交回。
- 值类型：`select` / `RETURNING` / 打了 `readBigInts` 标记的手写片段三条路径同类型；SQLite 的 bigint 列按片段标记打开语句级 `setReadBigInts`，INTEGER 列由 `src/table/normalize.ts` 退回 `number`。
- 观测与取消：`onQuery` 覆盖流式读（含行数、提前 break 与出错）；`Database.explain` 返回计划行数组；`read`/`iterate`/`run`/`write`/`transaction` 收 `{ signal }`。
- 库身份：`readIdentity`/`writeIdentity`；SQLite 用 `application_id`（指纹）+ `user_version`，PostgreSQL 用 schema 注释；打开时给 `identity` 即校验，不符抛 `DbError("identity")`。

## 三、模块边界与接口

| 模块                          | 拥有（职责与不变量）                                                          | 不拥有（明确排除）      | 依赖方向               | 接缝 / 适配器                  |
| ----------------------------- | ----------------------------------------------------------------------------- | ----------------------- | ---------------------- | ------------------------------ |
| `defs.ts`                     | 表/列/索引/约束的形状与 DDL、行类型推导                                       | 渲染、连接              | 无                     | 纯数据                         |
| `dialect.ts`                  | 方言差异的唯一出口：类型映射、引号、DDL、结构探测、能力矩阵                   | 业务语义、事务          | ← `defs.ts`            | `Dialect`（两个实现）          |
| `fragment.ts` / `expr.ts`     | 片段构造与占位符渲染、条件与值表达式、窗口函数、keyset                        | 具体方言文本            | ← `dialect.ts`         | 纯函数                         |
| `table/**`                    | 表句柄：投影/join/分组/分页/写入/`RETURNING`/值归一                           | 连接、事务、方言细节    | ← `expr`/`dialect`     | `TableHandle`（深模块接口）    |
| `database/**`                 | 连接、四个原语（读/写/执行/事务）、串行与保存点、取消、观测、库级操作、库身份 | 业务 SQL、schema 存在性 | ← 驱动                 | `Executor`（方言侧唯一实现点） |
| `migrate.ts` / `migration.ts` | 结构差异与漂移报告、迁移账本、并发迁移锁                                      | 迁移脚本内容            | ← `dialect`/`database` | —                              |

接口（调用方必须知道的）：

- 事务内读写同一执行面；事务外的写排队（同进程同库共享一条队列）、读不排队。
- 同一列在 `select`、`RETURNING`、`read`（片段带 `readBigInts` 标记）三条路径给同一 JS 类型；表句柄按列定义自动标记。
- 缺能力时抛 `DbError("unsupported")`，带方言与能力名；`FOR UPDATE` 在 SQLite 上构造期即失败。
- `close()` 幂等；关闭后的查询抛 `DbError("closed")`。
- 库身份：`readIdentity()` 返回 `{ fingerprint, version }`（名字只存 32 位指纹）；打开时 `identity` 不符即拒绝。

## 四、行为与边界

1. 正常路径：定义 → 对齐结构 → 读写 → 迁移；方言差异只在 `dialect.ts` 与 `database/*` 两处。
2. 错误：驱动错误转 `DbError`（分类 + 原始码）；编程错误（未知列、非法分页、占位符不匹配、非枚举值、缺能力）构造期即抛。
3. 取消：`AbortSignal` 贯通到语句级别；PostgreSQL 用 `pg_cancel_backend` 真取消，SQLite 在语句前后与迭代行间检查（同步驱动不能中途打断）。
4. 生命周期：打开失败自关句柄；`close()` 幂等并先关在飞游标；SQLite 的连接延迟到在飞迭代退出后关（不在迭代中关连接）。
5. 并发：同进程同库的写与事务共用一条队列；嵌套走保存点；`FOR UPDATE` 与版本列是可组合工具，跨实例仲裁由调用方组合。

## 六、取舍

- 否掉「一次性支持第三种方言」：没有真实消费方时，能力矩阵会退化成猜测。
- 否掉「静默降级」：同一份业务代码换库后少做事，比直接失败更难排查（`FOR UPDATE` 抛 `unsupported`）。
- 否掉「自动重试」：重试是业务语义（幂等性），库只给判定与 helper。
- 否掉「库内建连接池」：PG 侧复用驱动池，SQLite 单连接；池化参数由配置透传。
- 否掉「迁移回滚」：只前进，破坏性变更走显式开关 + 人工决策。
- 否掉「每个 `Database` 一条写队列」：同进程两个实例仍会撞 SQLite 写锁；按库身份共享后不再撞。
- 否掉「把 bigint 列的开关做成整库 / 整连接」：SQLite 的开关是语句级，整库打开会把 INTEGER 列也变成 BigInt；片段标记 + 列定义归一是唯一不扩散的做法。

## 七、不做与已知债

- 不做：触发器、视图、行级安全、分区、全文检索、分布式事务、迁移回滚、自动建 schema。
- 已知债：[值归一只走了一条读路径](../debts/20261103-值归一只走了一条读路径.md)（`boolean` 与未打 `readBigInts` 标记的手写片段仍原样返回驱动的值）。
- 限制（不是债，是驱动事实）：SQLite 的同步驱动不能中途打断一条在飞语句，取消只能在语句前后与迭代行间生效；SQLite 的 `bigint` 与 `integer` 在库里同一类型，类型漂移检测分不出这两者。

## 八、开放问题

- `delete()` / `update()` 的 `condition` 可选，一条不带参数的调用就是全表写；要不要改成 `deleteAll` / `updateAll` 的显式入口。
- `columnSql` 同名两义（列定义 DDL 与列引用）仍未改名。
