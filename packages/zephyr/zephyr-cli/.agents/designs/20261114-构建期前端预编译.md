# 构建期前端预编译（方案，未实施）

状态：草稿——只出方案；等确认后再改 `zephyr-cli` 与 `zephyr-app`。
范围：`zephyr build` 增加第四步「前端预编译」、`zephyr preview` 复用同一份产物、缓存根的取舍。
非目标：dev 服务期的即时预编译（保留现状）、联邦产物格式、CJS 互操作。
关联：[目录契约](../../zephyr-app/.agents/designs/20261114-目录契约.md) · [客户端资源的联邦式预编译](../../zephyr-app/.agents/designs/20261013-客户端资源的联邦式预编译.md)

## 一、决定（提案）

| #   | 议题              | 提案                                                                                                                                          | 一句话理由                                                                            |
| --- | ----------------- | --------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------- |
| 1   | 第四步            | `build` 三步之后加「前端预编译」：按清单把整棵 client 图的模块预先打成联邦产物                                                                | 产物固定，可直接 grep 检查，不必等 dev 服务期生成                                     |
| 2   | 入口来源          | 与 dev 同源：`clientModules.include`（packaged 形态为空 = 全量）+ 应用的 client 入口图；由 `Federation` 契约给，不在 CLI 里另写一份清单       | 两种形态必须同构，否则又是两条链                                                      |
| 3   | 复用逻辑          | 抽 `zephyr-app` 的公共函数（如 `prebundleAll(options)`），内部复用 `bundlePackage` 与 `entryOf` 的解析；CLI 只传布局与清单                    | 不在 CLI 重写一遍预编译                                                               |
| 4   | 缓存根            | **写 `<dataDir>/cache/client-modules`**（`AppEnv.cacheDirOf("client-modules")`），preview 直接读同一处                                        | 服务期与构建期共用一份缓存；`node_modules/.zephyr/cache` 是「构建可重建物」，语义不同 |
| 5   | build 时的 AppEnv | 由 `build` 的部署参数给：`--data-dir` / `zephyr.config.ts` 的 `dataDir`（与 dev/preview 同一套 `resolveDataDir`），缺省 `<工作区>/.dsh-store` | 路径只有一个来源，不在 CLI 里另算                                                     |
| 6   | preview 校验      | 启动时按清单校验 `client-modules`：缺任何一个产物 / 指纹不符即**报错退出**，不静默回退到服务期预编译                                          | 回退会让「build 有问题」变成「preview 偶发慢/偶发错」                                 |
| 7   | 与 dev 的差异     | dev 仍按需预编译（首屏快）；build/preview 用构建期产物（确定性）。两者共用 `bundlePackage` 与缓存目录                                         | 差异只在「何时构建」，不在「怎么构建」                                                |

## 二、现状事实

- `build` 三步在 `packages/zephyr/zephyr-cli/src/build/builder.ts`：`buildClient`（vite 静态面）、`buildRuntime`（`pnpm deploy`）、`bundleEntry`（rolldown 单文件）。`runBuild` 每次先 `rm(layout.root)`。
- 服务期预编译在 `zephyr-app/src/federation/federation.service.ts::serve`：`entryOf`（入口解析）+ `bundlePackage`（打包 + 落盘 `clientModules` 命名空间）+ `cjsShimOf`/`cssShimOf`（入口包装）。
- 缓存根：`AppEnv.cacheDirOf("client-modules")` = `<dataDir>/cache/client-modules`；`layout.cache` = `<workspace>/node_modules/.zephyr/cache` 只给 vite/rolldown 用。
- 目前没有任何「离线预编译」入口：产物只由 dev/preview 的请求触发产生，所以排查必须起服务。

## 三、模块边界与接口

| 模块                           | 拥有                                           | 不拥有                      | 依赖方向                  | 接缝              |
| ------------------------------ | ---------------------------------------------- | --------------------------- | ------------------------- | ----------------- |
| `zephyr-cli` 的第四步          | 何时跑、传什么清单、失败即构建失败             | 预编译算法本身              | ← `zephyr-app` 的公共函数 | 命令行与布局      |
| `zephyr-app` 的 `prebundleAll` | 遍历清单、调用 `bundlePackage`、汇总产物与错误 | 何时被调用                  | ← `Federation` 契约       | 纯函数 + 缓存目录 |
| `preview` 的校验               | 清单齐全性、指纹一致、失败即退出               | 重建产物（那是 build 的事） | ← 同一份清单              | 启动自检          |

## 四、判据

| #   | 判据                                       | 证据                                                                                                                                                                    |
| --- | ------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | build 后 `cache/client-modules` 有全部产物 | `ls <dataDir>/cache/client-modules                                                                                                                                      | wc -l` 与清单条数一致 |
| 2   | preview 页面 200、无 404                   | 起 preview 后 `curl -o /dev/null -w %{http_code} /`、浏览器 console 无 404                                                                                              |
| 3   | 无 config-forms / use-sync / CSS 报错      | 同一次 preview 的日志与页面                                                                                                                                             |
| 4   | 产物可 grep 比对                           | 例：`grep -l useSyncExternalStoreWithSelector <cache>/client-modules/use-sync-external-store@*/shim/with-selector.js`；`grep -rl morlay.zephyr.inject` 只剩 zephyr 自己 |
| 5   | 缺产物即失败                               | 删掉一个产物再 preview → 启动报错退出（不静默预编译）                                                                                                                   |

## 五、取舍与风险

- **缓存根选 dataDir 而不是 layout.cache**：preview 要在「产物被清掉」时仍能复用；`layout.root` 每次 build 都删，放那儿等于每次重建。代价：缓存与构建产物生命周期不同，文档要写清「可整目录删」。
- **build 变慢**：预编译整棵 client 图（几十个包）会显著拉长 build；可用 `clientModules.include` 收窄范围（dev 同款开关）。
- **不在 preview 里回退**：宁可红，也不要「有时能跑」。
- **风险**：build 时没有运行期 ctx（`FederationDefault` 是 Provider），所以公共函数必须做成「参数进、结果出」的纯函数（清单 + 布局 + 版本表），不能靠 `inject`。
