# 薄壳 fork 的接管面与保留文件（dsh-subagent）

状态：**已实现**（接管官方 `subagent` 行、保留文件与偏离登记都有守护）
范围：`packages/subagent/dsh-subagent/` 的接管面——行怎么被复用、保留哪几个文件、哪些结构性偏离是必须的、
配置页归谁；门面与用法见该包 [`README.md`](../../README.md)。
约束：上游只读。保留文件里指向未复制文件的 import 走相对路径指向 `vendor/deepseek-harness/packages/subagent/subagent/src/...`，
构建时内联进 `dist/index.mjs`（发布物自包含）。

## 结论摘要

| 议题     | 结论                                                                                                 | 一句话理由                                                                                  |
| -------- | ---------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------- |
| 行复用   | 插 `{id: "subagent", name: "@morlay/dsh-subagent", config: {...}}`                                   | Loader 对同 id 复用同一个 Entry，行 id 与 settings namespace 都不用换                       |
| 文案判定 | 按会话选：`composedPreset(parent.ctx)` 命中 `localizedReturnGuidancePresets`；名单不配 = 不限 preset | 文案是模型可见的，判定只能留在 host 平面（`subagents` 是进程单例）；默认不挑会话            |
| 委派说明 | `subagent:delegation` 在**装配瀑布**里替换文本（`delegation-context.ts`）                            | 上游把它注册在子代理自己的 agent 作用域，同层遮蔽会抛错、fork `child-agent.ts` 也不改运行期 |
| 保留面   | 3 个上游文件（`continuation-messages` / `manager` / `index`）                                        | 静态 import 链决定复制面：替换中间那份就得接管引用它的两个                                  |
| 偏离登记 | `upstream-wiring.spec.ts` 的 `DELTAS` 表逐条登记                                                     | 偏离是同步纪律的守护面，片段没命中就红                                                      |
| 配置页   | 全部留在**官方**那张卡上，本包没有 client 半                                                         | 接管没换行 id；再注册一套 `settings.subagent` 字典会让 `locale.register` 直接抛错           |
| 格式化   | 三个保留文件排除在 oxfmt 之外（`.oxfmtrc.json`）                                                     | 它们与上游逐行对照是本包唯一的价值，重排就失去意义                                          |

## 事实基线

### 接管面（装配）

行数据在本包 `./rows` 出口（`src/rows.ts` 的 `subagentRows()`）：插一条
`{id: "subagent", name: "@morlay/dsh-subagent"}`——**按官方行 id 复用**；只有给了 `localizedReturnGuidancePresets`
名单时才带上 `config`（不给就是"不限 preset"），
Loader 对同 id 复用同一个 Entry、后者替换入口 options，所以行 id 与 settings namespace（namespace 就是行 id）都还是
`subagent`，官方设置卡（`ui-settings-subagent`）与它的服务行（`subagent-model-selection-settings`）都不动。
顺序前提：本包排在 `@deepseek-ai/dsh-base` 之后。

采用它的部署 bundle 是 [`@morlay/session-mode-profile`](../../../../bundles/session-mode-profile/README.md)：它按 `./rows`
展开行、**不传** `localizedReturnGuidancePresets`（默认对任意 preset 生效，见它的 `tsdown.config.ts`；app 的
`dsh.profile.bundles` 列的是那个 bundle）。
理由与被否的路线见 [`ADR-接管官方行按id复用而非换id`](../adrs/20260928-接管官方行按id复用而非换id.md)。

### 保留文件与复制面

薄壳 fork 只留**有意改过**的文件，其余上游文件不复制：

| 保留文件（`src/`）         | 保留什么                                                                                               |
| -------------------------- | ------------------------------------------------------------------------------------------------------ |
| `continuation-messages.ts` | 中文文案 + 判定函数 `localizedReturnGuidance`（"这个会话要不要本包那份文案"；名单不配 = 任意会话都用） |
| `manager.ts`               | 接线 + 调用点按会话选文案（读 `ctx.agentPresets` 的 `composedPreset(parent.ctx)`）                     |
| `index.ts`                 | 接线 + 装配面配置字段（`localizedReturnGuidancePresets`）+ 两处结构性偏离（见下）                      |

`src/delegation-context.ts` 是**本包自有**文件（不在上游对照集内），见下节。

静态 import 链决定了复制面：`continuation-messages` ← `manager` ← `index`，要替换中间那一份就得连同引用它的
两个文件一起接管。原因、被否掉的路线与后果见
[`ADR-薄壳fork接管subagent行只改文案`](../adrs/20260923-薄壳fork接管subagent行只改文案.md)。

上游 0.2.1-alpha.2 把这套编排重写过一次：alpha.1 的 `continuation.ts`（continuable 编排）与
`continuation-activation.ts`（Activation 图，902 行、当时未被复制）合并成 `manager.ts`（1475 行，激活生命周期
与派发入口都在里面）+ `activation.ts`（执行期记录与容量槽）。中间那份从此是 `manager.ts`——**复制面因此从
约 1375 行涨到约 2270 行**，`activation.ts` 仍直接引用上游源码。同一版上游还统一了派发面：`start` /
`startContinuable` 两个入口合成 `startActivation(spec)`（本地与外部 backend 同一条路），回报指引只在
"通知父智能体"的派发上加（`delivery !== 'caller'`）；服务多一条 `static inject = ['workingDirectory']`
（测试装配要挂 `vendor/.../subagent/subagent/tests/working-directory-fixture.ts`）。

### 委派范围说明（`subagent:delegation`）

上游 `child-agent.ts` 的 `applyChildComposition` 在**子代理自己的 agent 作用域**上注册这条运行时上下文，两条常规接管
手法都不通（都实测过）：

- **同名遮蔽**：同一 scope 里重复注册同名 context 会抛错（`NamedEntries.insert` →
  `prompt context "subagent:delegation" is already registered in this scope`）。装配用的 scope 就是子代理自己
  （`assembleContextFor(agent)` → `scope: agent`），与上游那次注册同层，没有"更近"的位置可站。
- **fork `child-agent.ts`**：它得再复制一份 290 行、并让本包那份 `manager.ts` 的接线改指向它；而外部 backend
  （`subagent-acp` / `subagent-dsh-sdk`）的子代理在别的进程里装配，那份 fork 对它们无效。改文本的瀑布替换不复制
  代码，一次覆盖本装配里所有子代理。

这两条都是实测否掉的，结论落在上游真源上可复核：注册点是
`vendor/deepseek-harness/packages/subagent/subagent/src/child-agent.ts` 的 `applyChildComposition`（收到的是子代理的
`childCtx`），报错原文在 `vendor/deepseek-harness/packages/core/system-prompt/src/index.ts` 的 `NamedEntries`，
装配 scope 在 `vendor/deepseek-harness/packages/core/agent/src/dispatch.ts` 的 `assembleContextFor`。0.2.1-alpha.2 起
本地与外部派发统一进 `manager.ts`，上游那份一次性 driver 包（`subagent-in-process-driver`）随之消失，所以唯一的
注册调用方是 `vendor/deepseek-harness/packages/subagent/subagent/src/manager.ts`。

所以本包改的是**装配结果**：`SystemPrompt.assemble()` 先 merge 好 `contexts`、再进 `system-prompt/assemble` 瀑布，
`src/delegation-context.ts` 在瀑布里把该名字那条的文本换成中文（只对 `parentSession` 非空的装配动手——这条本来只
对子代理注册）。它在**该次**装配内生效（第一次装配就是中文），continuable 与一次性两条派发路径一起覆盖，且不碰父
agent 的装配。判据在 `src/__tests__/delegation-context.spec.ts`。

### 偏离登记（可执行）

`src/__tests__/upstream-wiring.spec.ts` 的 `DELTAS` 表逐条登记上面每处偏离（新增块、改过的行、装配面字段），
偏离表里的片段没命中就红——加偏离必须同时登记。

### 两处结构性偏离

- **`index.ts` 不复述 cordis 合并接口**：上游此处 `declare module '@deepseek-ai/cordis'` 声明 `Context.subagents`
  与 `subagent/*` 事件；本包 `import type {} from '@deepseek-ai/dsh-subagent'` 引用上游那一份（同形声明复述两遍
  会在同一个 program 里撞 `TS2717`）。
- **标准装饰器在构建期降级**：`@Remote(...)` 是 TC39 标准装饰器，rolldown/oxc 不降级它（上游管线里这步由 tsc
  完成），所以 `tsdown.config.ts` 里有一个 esbuild 预转换（vitest 侧用 devkit 的同一份，见根
  [`债务 标准装饰器降级分居两套机制`](../../../../../.agents/debts/20260923-标准装饰器降级分居两套机制.md)）。

### 配置面

**子代理用哪个模型不在这张卡上**：它跟着**父会话的模式**走（`@morlay/dsh-session-mode` 里「模式 → 服务商 / 模型」
那两个选择器）。

限额两个字段（`maxDepth` / `maxActiveSubagents`，标了 `.volatile()`）由**官方**那张设置卡承担：接管没换行 id，
`subagent` namespace 照旧，`ui-settings-subagent` 与 `subagent-model-selection-settings` 都不动。

本包**没有 client 半**：卡片由官方那行承担，再注册一套 `settings.subagent` 字典会让 `locale.register` 对同
namespace 同 locale 直接抛错（官方卡片那一行随之加载失败）。`Config` 的 `localizedReturnGuidancePresets` 是
**装配面**字段（`.hidden()`）：它不进设置页，由装配那一行给。

## 取舍

- **不换行 id、不自己注册 settings 字典**：换 id 会带走官方设置卡与它的服务行；注册同 namespace 的字典直接抛错。
- **只留 3 个上游文件、不整包复制**：整包 fork 会让上游每次升级都要人工对齐全部文件，而本包只改文案。
- **委派说明走装配瀑布替换，不 fork `child-agent.ts`**：注册它的调用方都在上游未复制的文件里，fork 不改变运行期，
  只会白添一份实例与跟随负担；瀑布替换覆盖 continuable 与一次性两条路径，代价是"改装配结果"而不是"注册一条更近的
  同名项"。
- **偏离用可执行清单守，不用注释守**：注释在上游改动时不会红。
- **保留文件排除格式化**：逐行对照是同步纪律的判据，重排后这条判据失效。
