# 停掉官方设置卡的两条入口行

状态：已采纳

本包接管官方 `subagent` 行后，官方那两条设置行都落空：`ui-settings-subagent` 读的 settings namespace 是
**行 id** `subagent`，而本部署那行已被禁用（namespace 不存在），页面本身立不住；`subagent-model-selection-settings`
是给那张卡片第二段（模型白名单）供数的服务行，卡片没了它就没有消费者。

**决定**

两条行都在本包 patch 里 `disabled: true`。本行自己的配置页由 `@morlay/dsh-client-ui-schema-form` 按
volatile 字段生成，字段文案由本包 client 半经字段槽 `settings.schema-form.field` 给出。

**考虑过的选项**

- **把官方行换个 `name` 而不是插新行**：namespace 会跟着行 id 走（仍是 `subagent`），官方卡片照旧可用——否掉的
  原因是文案锁在官方包里，且本包还改回报指引，行本来就要接管。
- **只停第一条**：第二条没有消费者仍会注册一个模型白名单服务，白占一行且与模式白名单那套重叠。
- **留一条官方行做兜底**：官方卡片没有"只有限额一段"的形态，留着就要连它的模型白名单段一起用。

**后果**

- 这一行的配置面只剩两处依赖：`Config` 的 volatile 标注（与上游逐行一致，不改）与装配行存在。
- 模型白名单归 `@morlay/dsh-session-mode` 的模式定义；官方 `subagent` 的模型选择面在装配里不存在。
