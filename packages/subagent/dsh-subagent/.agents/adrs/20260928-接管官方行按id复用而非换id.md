# 接管官方 `subagent` 行走"按 id 复用"，不换行 id

状态：已采纳

官方 `subagent` 行（`ctx.subagents` 服务定义）要换成我们的薄壳 fork，装配上有两条路：

1. **禁官方行 + 插我们自己的行**（原做法）：行 id 成了 `subagent-fork`；
2. **按官方行 id 复用**（本决定）：插一条同 id 的条目，`name` 指本包。

## 事实基线

- **patch 的 `name` 只校验、不改实现**：`applyEntryPatches` 里 `name && name !== target.name` 就 warn 并跳过该层
  （`@deepseek-ai/cordis-plugin-include` 的 `src/index.ts`）——所以"照官方 id 改 name"这条路 patch 层面不存在。
- **settings namespace 就是行 id**：volatile 表单按 plugin entry 挂 namespace
  （`packages/settings/settings/src/index.ts` 的 `describe()` / `volatileForm`，`Plugin entry "${ns}" has no
volatile fields`）。禁掉官方行、换成 `subagent-fork` 之后，官方设置卡 `ui-settings-subagent`（它读 `subagent`
  与 `subagent-model-selection` 两个 namespace）就没有可读的东西了。
- **Loader 对同 id 复用 Entry、后者替换入口 options**：`EntryGroup.create` 是
  `this.tree.store[id] ??= new Entry(...)` 然后 `entry.update(options, true, true)`（`create: true` 即替换
  options）；`update(config)` 建 map 时同 id 后者胜。所以"插一条同 id、不同 name 的条目"就是换实现，
  行位置 / id / namespace 全留着。

## 决定

装配数据插一条 `{ id: "subagent", name: "@morlay/dsh-subagent", config: {…} }`：

- 官方 `ui-settings-subagent` 与 `subagent-model-selection-settings` **都不再停**——卡片读的两个 namespace 都在；
- 行 id 与官方一致，升级上游时"我们接管的是哪一行"由 id 对上号；
- 顺序前提：本 bundle 排在 `@deepseek-ai/dsh-base` 之后（app 的 `dsh.profile.bundles` 已如此）。

## 考虑过的选项

- **禁官方行 + 插自己的行 id**（原做法）：行 id / namespace 跟着走样，官方设置卡必须一并停（上一份 ADR 的
  决定），且"上游那一行还在不在"只能靠 name 对上。
- **只改回报文案、不接管行**：文案是上游内部常量，没有 config / settings / hook 面（见
  [ADR 薄壳 fork 接管 subagent 行](./20260923-薄壳fork接管subagent行只改回报文案.md)），做不到。
- **本地 patch 改 vendor 树**：patch 留给构建约束与上游缺陷，不用于常规接管。

## 后果

- 行 id 的**所有权不在我们手里**：上游改了这个 id，我们那条会变成"孤儿插入"（多一行、官方行还在）——探针与
  装配测试盯着"`subagent` namespace 在场且只有一份"。
- 官方设置卡回来了；本包 client 半（字段文案槽 + `settings.subagent` 字典）**随之删掉**：它与官方卡片是重复面，
  两套都注册同一字典 namespace 时 `locale.register` 直接抛错（同 namespace 同 locale），官方卡片那一行会
  `failed`。
- `Config` 多一个装配面字段（`localizedReturnGuidancePresets`，`.hidden()` 不进设置页）：回报指引按会话挂的
  preset 选文案，见 [ADR 薄壳 fork 接管 subagent 行](./20260923-薄壳fork接管subagent行只改回报文案.md)。
