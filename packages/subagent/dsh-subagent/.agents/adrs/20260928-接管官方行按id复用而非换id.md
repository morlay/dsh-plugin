# 接管官方 `subagent` 行走"按 id 复用"，不换行 id

状态：已采纳

背景：官方 `subagent` 行（`ctx.subagents` 服务定义）要换成我们的薄壳 fork，装配上有两条路：**插一条自己的行**
（行 id 变成 `subagent-fork`）或**按官方行 id 复用**。约束来自三处：

- **patch 的 `name` 只校验、不改实现**：`applyEntryPatches` 里 `name && name !== target.name` 就 warn 并跳过该层
  （`@deepseek-ai/cordis-plugin-include` 的 `src/index.ts`）——所以"照官方 id 改 name"这条路 patch 层面不存在。
- **settings namespace 就是行 id**：volatile 表单按 plugin entry 挂 namespace
  （`packages/settings/settings/src/index.ts` 的 `describe()` / `volatileForm`）。插自己的行 id 之后，官方设置卡
  `ui-settings-subagent`（它读 `subagent` 与 `subagent-model-selection` 两个 namespace）就没有可读的东西了。
- **Loader 对同 id 复用 Entry、后者替换入口 options**：`EntryGroup.create` 是
  `this.tree.store[id] ??= new Entry(...)` 然后 `entry.update(options, true, true)`（`create: true` 即替换 options）；
  `update(config)` 建 map 时同 id 后者胜。

**决定**

装配数据插一条 `{ id: "subagent", name: "@morlay/dsh-subagent", config: {…} }`
（`src/rows.ts` 的 `subagentRows()`）：行位置 / id / namespace 全留着，换掉的只是实现包。

**考虑过的选项**

- **插一条自己的行 id**：行 id / namespace 跟着走样，官方设置卡必须一并停，且"上游那一行还在不在"只能靠 name 对上
  → 否。
- **只改文案、不接管行**：文案是上游内部常量，没有 config / settings / hook 面（见
  [ADR 薄壳 fork 接管 subagent 行](./20260923-薄壳fork接管subagent行只改文案.md)）→ 做不到。
- **本地 patch 改 vendor 树**：patch 留给构建约束与上游缺陷，不用于常规接管 → 否。

**后果**

- 行 id 的**所有权不在我们手里**：上游改了这个 id，我们那条会变成"孤儿插入"（多一行、官方行还在）——装配测试盯着
  "`subagent` namespace 在场且只有一份"。
- 官方设置卡照常可用（`ui-settings-subagent` 与 `subagent-model-selection-settings` 都不动）；本包不再有 client 半：
  与官方卡片是重复面，两套都注册同一字典 namespace 时 `locale.register` 直接抛错（同 namespace 同 locale），官方
  卡片那一行会 `failed`。
- `Config` 多一个装配面字段（`localizedReturnGuidancePresets`，`.hidden()` 不进设置页）：回报指引按会话挂的 preset
  选文案，**不配就是不限**（默认对任意 preset 生效），见
  [ADR 薄壳 fork 接管 subagent 行](./20260923-薄壳fork接管subagent行只改文案.md)。
- 顺序前提：本 bundle 排在 `@deepseek-ai/dsh-base` 之后（app 的 `dsh.profile.bundles` 已如此）。
