# 壳独立成包（dsh-desktop-shell 的边界与理由）

状态：已实现（`@morlay/dsh-desktop-shell` 承接壳，`@morlay/dsh-desktopify` 只做 CLI；dev / bundle 两条路径都已验证）
范围：`packages/desktop/dsh-desktop-shell/` 与 `packages/desktop/dsh-desktopify/` 之间那条边——谁持有壳、谁持有工具、两侧怎么互相解析。
约束：壳可达模块只 import node 内建 / `electron` / 内联面（[守卫](../../src/__tests__/shell-import-boundary.spec.ts)）；工具里不写死任何包路径（一律由 node 解析壳包）。

## 结论摘要

| 议题        | 结论                                                                                              | 一句话理由                                                                                                                              |
| ----------- | ------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------- |
| 包边界      | 壳独立成 `@morlay/dsh-desktop-shell`；`dsh-desktopify` 只发 CLI（`bin` + `./dev-client-bundles`） | 一个包不该同时是「npm 消费者眼里的工具」与「Electron 眼里的应用」：两份语义压在同一份 `package.json` 上，删掉壳要的 `main` 就静默炸 dev |
| 壳的形态    | 壳主进程 ESM（`dist/index.mjs`）+ preload CJS（`dist/preload-app.cjs`），两遍构建                 | sandboxed preload 只能是 CJS，这一条与主进程的 ESM 形态无法在一次构建里同时满足                                                         |
| dev 起壳    | `dsh-desktopify dev` 以**壳包目录**为 Electron app 启动                                           | Electron 只看目录清单的 `main`，所以壳包保留 `legacy`（`main` / `module` 由构建写回）                                                   |
| bundle 起壳 | 拷壳包 `dist/` 成最小壳目录（`shell/`）+ 一份自写的壳清单，再交 electron-builder                  | 打包形态要的是「只有壳字节」的 app 目录，工具自己的依赖与源码都不该进 `app.asar`                                                        |
| 共享事实    | 种子、官方包清单、home 解析、`appconfig`、profile 工程住壳包，工具按子出口引                      | 这些事实壳运行期也要用；放工具侧会成环（工具依赖壳），放第三包则多一层无收益                                                            |
| app 的依赖  | 示例工作区只 `peerDependencies` 引工具，运行时闭包不含壳与工具                                    | 依赖的是 CLI（`pnpm exec dsh-desktopify …`）；`dsh.profile.bundles` 里没有它们                                                          |

## 事实基线

### 谁在哪

- **壳包**（壳闭包，构建期从 `src/index.ts` 与 `src/preload-app.ts` 沿相对 import 可达）：`index.ts`、
  `preload-app.ts`、`ipc.ts`、`directory-picker.ts`、`document-marks.ts`、`stream-uplink.ts`、`shell-env.ts`、
  `shortcuts.ts`、`keybindings.ts`、`appconfig.ts`、`dshhome.ts`、`host-process.ts`、`official.ts`、
  `official-packages.ts`（+ 生成的清单）、`profile-project.ts`、`seed.ts`；
- **工具包**：`src/cli/*`（dev / dev-web / bundle / electron-builder / prepare-runtime / prepare-seed /
  official-deps / workspace / shell / icon / index）与 `src/dev-client/*`；
- **两侧的接口**：工具按 `@morlay/dsh-desktop-shell/{appconfig,dshhome,official,profile-project,seed}` 引共享事实；
  工具按 `@morlay/dsh-desktop-shell/package.json` 解析壳包根（`src/cli/shell.ts` 的 `SHELL_PACKAGE_ROOT`）。

### 出口面

| 出口                | 用途                                                                |
| ------------------- | ------------------------------------------------------------------- |
| `.`                 | 壳入口（`dist/index.mjs`，Electron 主进程），由 `main` 与它一起指到 |
| `./appconfig`       | `appconfig.json` 读写与 profile patch 文件名                        |
| `./dshhome`         | `dshHome` 语义解析（`xdg` / `env` / 路径）                          |
| `./official`        | 官方包清单与 host 变体包名（壳与工具的同一份事实）                  |
| `./profile-project` | profile 工程（`pnpm-workspace.yaml`、overrides、清单）              |
| `./seed`            | 种子布局与指纹                                                      |

后五个是工具侧复用同一份实现的入口——种子、官方包清单、home 解析都只有这一份，壳与 CLI 都引它。

### 依赖边界

壳产物整份进 `app.asar`，解析面只有构建期内联的那几个包：**壳入口可达的模块只能 import node 内建、`electron` 与内联
面**——上游裸引用能过类型检查、能打出产物，但装进 asar 后解析不到，只在真机启动时炸。内联清单与理由见
[设计 桌面无端口传输与窗口对齐](../../../dsh-desktopify/.agents/designs/20260920-桌面无端口传输与窗口对齐.md)「壳产物的依赖
边界」；守卫在 `src/__tests__/shell-import-boundary.spec.ts`。

preload 必须是 CJS（sandboxed preload 的约束），所以它单独一遍构建；壳主进程与它产在同一次 `pnpm build`。

### 两条启动路径

- **dev**：以壳包目录为 Electron app（清单的 `main` 指 `dist/index.mjs`），工具不复制壳；
- **bundle**：`prepareShellAppDirectory` 另写一份最小壳清单 + `dist/`，再交 electron-builder。

## 取舍

- **得到的**：包边界即壳的模块边界（守卫从「同一包里的相对路径约定」变成「包与包之间的依赖」，更硬）；
  Electron 要的 `main` 只出现在壳包，工具清单不再承载壳语义；app 的依赖面收窄到「工具」一个。
- **付出的**：多一个发布包与一条 `workspace:*` 依赖（发布顺序：先壳后工具）；壳包多五个子出口（共享事实）；
  `dev` / `bundle` 都要先 `pnpm build` 壳包（源码比产物新的警告仍在，见
  [设计 桌面化工具](../../../dsh-desktopify/.agents/designs/20260917-桌面化工具.md)）。
- **否掉的选项**：壳与工具同包（`main` / `module` 同时是「工具的清单」与「壳 app 的清单」，两条路读不同清单来源
  ——`bundle` 另写一份壳清单，`dev` 读包自己那份；删掉 `main` 这类改动会让两条路一死一活）。

## 开放问题

无（壳与工具的边界已定；两条启动路径的产物形态由工具侧的测试守护）。
