# 桌面档不含登录与账号面

状态：已采纳

背景：桌面档的传输是**无端口字节管道**——`config/desktop.cordis.patch.yml` 禁掉上游 `webserver` 行、插入宿主内的
无端口替身（见[设计 桌面无端口传输与窗口对齐](../../../dsh-desktopify/.agents/designs/20260920-桌面无端口传输与窗口对齐.md)）。
而 DeepSeek 账号登录是「系统浏览器授权 + **回环地址回调**」：登录实现把 `/oauth/callback` 注册在 `webServer` 上
（`packages/credentials/deepseek-account-platform/src/index.ts:522-549`），授权页要回到 `redirect_uri`，而这个
origin 必须形如 `http://localhost:<非零端口>`
（同包 `src/protocol.ts:241-252` 的 `loginOrigin`）；client 半给出的回调来源是页面来源或 transport 的
`streamBaseUrl`（`packages/client/ui-settings-account/src/client/index.ts:214`）——桌面下就是自定义协议来源，
协议校验必然失败。于是装着的那几个面（设置页账号页、侧栏账号菜单、桌面首次引导覆盖层、充值页宿主）点进去全是死路。

**决定**

桌面 overlay（`config/desktop.cordis.patch.yml`）按 id 停掉整条账号面：`deepseek-account`、`account-controller`、
`llm-deepseek-account`、`ui-settings-account`；`credentials`（通用凭据服务）、`authorization`（凭据获取流程的通用
接缝）、`llm-deepseek`（官方 API key 路由）都不动。本部署的模型路径仍在 `credentials` → `apiKeyEnv:
OLLAMA_API_KEY` → `ollama` provider。

**考虑过的选项**

- **只停 client 面（`ui-settings-account`）**：账号实现与它的 Remote 名册还在、`/oauth/callback` 仍会在登录时
  注册；能力留着没人能用，还多一条等不到回调的路径 → 否。
- **顺手把 `authorization` 一起停**：它不是账号面（注册的是「靠人机对话拿凭据」的流程，上游 README 明确
  headless/ACP 可以安全挂载），且 `llm-pi-ai` 把自家 provider 的登录流程挂在它上面
  （`packages/llm/llm-pi-ai/src/index.ts:235`，用 `ctx.inject` 软注入）——停它动的是另一条面 → 否。
- **留着 `llm-deepseek-account`（它单独看无害）**：登出状态下它的目录本来就是空、行会被设置页过滤掉
  （`packages/llm/llm-deepseek/src/adapter.ts:34-36` → `packages/llm/llm-deepseek-account/src/index.ts:44-49`
  返回空目录）。但它的唯一凭据来源就是上面那条登录，桌面档永远拿不到 token，留着是一条只报
  `ACCOUNT_SIGN_IN_REQUIRED` 的死路由 → 否，一并停。
- **在桌面预置 `ui-settings-account` 的引导进度为已完成**：桌面档本来就不卡（见后果），预置是多余的 → 否。

**后果**

- 得到：桌面档没有账号入口、没有等不到回调的登录路径、没有死路由；设置页只剩 general / models / plugins
  （`account` 段唯一的注册者是 `packages/client/ui-settings-account/src/client/index.ts:289-295`）。
- 放弃：桌面档拿不到 DeepSeek 账号 token / 额度页（本部署模型走 ollama、key 走 `credentials`）。要恢复得先给
  桌面造一条回调通路（壳的原生页或深链），不是改 overlay 能补回来的。
- 首次引导不需预置：`ui-settings-models` 的 welcome notice 在桌面**不注册**（`'dshDesktop' in globalThis`
  为真，`packages/client/ui-settings-models/src/client/index.ts:81,147`），官方 key 步骤在 `automatic` 为假时立即
  `complete()` 且不渲染（`automatic: credentialOnboarding` 见同文件 `:100`，`complete()` 见
  `client/DeepSeekOnboardingDialog.tsx:68-77`）；桌面那份「首次引导」覆盖层属于账号 client 面
  （`client/ui-settings-account/src/client/index.ts:230-241,254`），随它一起消失，工作区直接可见。开发者工具偏好
  `ui-settings.enabled` 默认就是 true（`packages/client/ui-settings/src/developer-tools-settings.ts:15`），引导
  没写也不会变严。
- `ui-settings-account` 这个 settings namespace 不再注册；profile 用户层里可能残留的引导进度是惰性数据，装配读不到它。
- 验证：`tool/verify-desktop-account-plane.mts` 装配一次真 desktop profile，判账号面不在、装配健康、模型路径仍在。
