# 桌面档无产品遥测

状态：已采纳

背景：上游 web-app bundle 的产品遥测面是两行——`desktop-product-telemetry`
（`@deepseek-ai/dsh-host-product-telemetry-otel`）与 `product-analytics`（`@deepseek-ai/dsh-client-product-analytics`）。
两行都只在 **profile 名为 `desktop`** 时激活（`disabled: !!js "ctx.get('profileContext')?.name !== 'desktop'"`），
并且都靠构建期环境变量 `DSH_CLIENT_VERSION` 取值：host 行的 `serviceVersion` 是**必填**项
（`packages/host/product-telemetry-otel/src/index.ts:50`），client 行的 `appVersion` 同源；上游桌面应用在运行期把
这个变量交给 host，自研壳（[桌面无端口传输与窗口对齐](../../../dsh-desktopify/.agents/designs/20260920-桌面无端口传输与窗口对齐.md)）
没有它。

后果是一串可观测的噪声：host 侧 `dsh: warning: 2 entries did not activate`——遥测行配置校验失败
（`$.serviceVersion missing required value`），依赖它的 `product-analytics` 行随后 pending；页面启动时那条
`productAnalytics/watchPolicy` 流拿 502，前端在非 JSON 响应上抛 `Uncaught Error: Unexpected token 'y', "typert gate"...`。
另一条路是默认 endpoint（官方 collector）——本地部署没有上报对象，也不该默认往外发。

**决定**

桌面 overlay（`config/desktop.cordis.patch.yml`）按 id 停掉这两行。

**考虑过的选项**

- **壳给 host 补 `DSH_CLIENT_VERSION`**：两行会激活并真的往官方 collector 上报（`endpoint` 有默认值），
  本地 ollama 部署没有上报对象、还依赖网络；而且自研壳手里的版本号（appconfig 的应用版本）不是上游 client 版本语义
  → 否。
- **只停 host 那一行**：client 行仍然加载并调用 `productAnalytics/watchPolicy`，502 与那条未捕获错误照旧 → 否。
- **留着行、只关 `config.enabled`**：`product-analytics` 有 `enabled` 开关，但 host 行仍会因 `serviceVersion` 缺失不激活，
  装配警告与 pending 链都不消失 → 否。

**后果**

- 得到：桌面档没有遥测上报路径，启动日志与页面控制台不再有那条 502 与未捕获错误；与「桌面档不含登录与账号面」
  （[ADR](../adrs/20260928-桌面档不含登录与账号面.md)）同一取向：本地部署不挂没有对象的面。
- 放弃：桌面档没有「发送使用数据」这类设置项与遥测数据（web 档不受影响，那两行在 web 档照常激活）。
- 停用只写在桌面 overlay 里，由 `src/__tests__/desktop-patch.spec.ts` 锁定：清单就是传输接管那一行加上产品遥测与
  登录/账号面，且这些 id 与模块名不出现在 bundles 与 profile 层。
