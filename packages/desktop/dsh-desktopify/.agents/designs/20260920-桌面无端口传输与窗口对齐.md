# 桌面无端口传输与窗口对齐（dsh-desktop-shell + dsh-desktop-host 的运行形态）

状态：已实现（host 不监听任何应用端口；管道分帧、替身路由、transport 装配与流契约有单测守护；调试面见「调试面」一节）
范围：桌面形态（Electron 壳 + host 子进程）的运行事实——传输与认证、客户端 transport 与流契约、壳与 host 的契约（argv / IPC / 字节管道）、启动链、窗口与平台标记、壳产物的依赖边界。
约束：`vendor/**` 只读；插件注册面统一走 `webServer`（没有 `connection.fetch` 双注册）；壳可达模块只 import node 内建 / `electron` / 构建期内联面（[守卫](../../../dsh-desktop-shell/src/__tests__/shell-import-boundary.spec.ts)）。

本文引到的 `apps/…` / `packages/…` 路径都是上游真源，位置在 `vendor/deepseek-harness/`；本仓库自己的包一律写 `packages/<family>/<pkg>`。

## 事实基线

### 传输与认证

- **替身服务面**（`packages/desktop/dsh-desktop-host/src/webserver.ts`）：与上游同名的路由载体，不 `listen`；
  同接口面 + 宿主用的 `dispatch(Request)`（合成 node 风格 req/res，响应体流式回帧）。`port` 固定返回 `0`
  （`surfaceContext` 关掉后没有读者需要真实端口）。
- **管道分帧**（`packages/desktop/dsh-desktop-host/src/wire.ts`，壳侧复用同一份）：请求帧
  （start/data/end/cancel）与响应帧（start/data/end/error），FD 3/4，64 KiB chunk。壳侧载体是
  `packages/desktop/dsh-desktop-shell/src/host-process.ts`（五元组 stdio、`fetch(Request)`、背压、退出收敛时在途
  请求回 503）。
- **认证接管**（`packages/desktop/dsh-desktop-host/src/transport.ts` 的 `takeOverDesktopAuthentication`，在
  `src/index.ts` 的 `runProfile` 之后调用）：`requestRejection` → 恒 `undefined`、`authorizeIndex` → 恒 `true`；
  能力探测失败就 fatal 上报。理由与代价见[债务 桌面宿主覆写 connection 的两个认证方法](../debts/20260920-桌面宿主覆写connection认证方法.md)。
- **上游侧为什么必须接管**：`connection` 行在 `ctx.inject(['webServer'])` 内注册 `/api` 前缀路由
  （`packages/client/connection/src/index.ts:140-153`），handler 先过 `requestRejection`（Host/Origin 栅栏 +
  签名 cookie）再走 `connection/request` waterfall；`session-rdb` 的五条 `/api/session.*` 与
  `ui-conversation-message-actions` 的 `/api/session-editor` handler 内部也自查 `requestRejection`；
  `frontend-static` 的 index 分支先 `ctx.connection.authorizeIndex(req,res)`
  （`packages/host/frontend-static/src/index.ts:132-139`）。
- **上游自己也有「不监听」的形态**（不可直接复用，只作参照）：`packages/experimental/webworker-runtime`
  的假 `node:http` + 合成 req/res，`packages/host/webserver/src/index.ts:104-107` 也为「res 无 socket」留了口。

### 客户端 transport 与流契约

- **注入**：`webserver/index-inject` 的 `script` 行注入 `__DSH_TRANSPORT__`（`DESKTOP_TRANSPORT_SCRIPT`，
  `dsh-desktop-host/src/transport.ts`），宿主注册 exact 路由 `/.dsh/remote-stream`。上游契约是五参
  （`endpoint, payload, uplink, peer, signal`，`packages/api/gateway/src/types.ts:96-101`），peer 传 `undefined`
  ＝ operator。
- **双向 NDJSON**：请求体首行是 `{endpoint, payload}`（`encodeDesktopStreamOpen`），后续每行是一道上行项
  （`encodeDesktopStreamItem`）；宿主用 `DesktopStreamBodyDecoder` 增量解析（先过 `StringDecoder`，字节边界会
  切开多字节字符）。没有 uplink 的流（如 `$events`）直接结束请求体，宿主不必等一个永不来的 end。
- **页面侧链路**：页面 `openStream` 的第 4 参 uplink → preload `__DSH_DESKTOP_STREAM__.send` →
  `createStreamUplink`（排队等 `stream-open` 的 id）→ IPC `streamUplink` / `streamUplinkEnd` → 主进程写进宿主
  请求体；响应体逐块推回页面。页面不用 `fetch` 打自定义协议：Chromium 对带 POST body 的 `dsh-app://` 请求不返回
  响应头。
- **取消语义**：注入脚本的 `onAbort` 置 `ended=true` 并唤醒迭代（队列剩余数据仍先交付），`addEventListener`
  之后再对已经 abort 的 signal 补一次 `onAbort()`——上游 `RemoteStream.dispose()` 会 `await iterator.return()`，
  不唤醒迭代就会永久挂住 `ClientSession.resync()`。
- **不暴露 `dshDesktopBoot`**：上游 `apps/web/src/main.ts:18-36` 只在它存在时覆盖 transport，无端口下
  `streamBaseUrl` 无处可指。代价是页面级失败上报走控制台 / 壳对话框。
- **index 渲染**：宿主注入行（`__DSH_BOOT__`、`__DSH_TRANSPORT__` 等）与 `__DSH_BOOT_READY__` 的 settle 脚本
  在同一份 HTML 里（`packages/host/webserver/src/injections.ts:86` 的 `READY_MARKUP`），页面不依赖 boot IPC；
  客户端在 `packages/client/web/src/boot.ts:58` 等这个 gate。

### 壳与 host 的契约

- **argv**：`[entry, runtimeDir, projectDir, pnpmEntry?, nodeBin?]`——host 在自己的入口 `main` 里读
  `process.argv[2..5]`（`dsh-desktop-host/src/index.ts`），壳按同一顺序拼 args
  （`dsh-desktop-shell/src/host-process.ts`）。`pnpmEntry` / `nodeBin` 缺省时不带这两格；上游契约里
  `projectDir` 之后那格 `primaryRuntime` 桌面档不要，见
  [设计 桌面host的运行时面与依赖边界](../../../dsh-desktop-host/.agents/designs/20260929-桌面host的运行时面与依赖边界.md)。
- **stdio 五元组**：FD 3/4 是管道，FD 5 是 Node IPC（`host-process.ts:145-150`）；宿主入口路径固定为
  `<runtimeDir>/node_modules/@morlay/dsh-desktop-host/lib/index.js`。
- **IPC**：`ready {protocolVersion}` / `fatal {message, diagnostic}` / `inspected {url, message?}`（`diagnostic` 是完整
  `util.inspect` 的错误，与上游同形；壳的 dialog 用 `message`，完整诊断走 stderr），命令是 `shutdown` 与调试端点的
  `inspect {port}` / `inspect-off`。
- **进程名**：壳给 host 子进程加 `node --title=<app name>-server`（见[设计 桌面标识取自 app 名](./20260921-桌面标识取自app名.md)）。
- **崩溃与退出**：host 非预期退出 / 管道断开时经 `onFailure` 通知壳——打印 `[dsh-shell] backend stopped: …`
  （含 host stderr 尾部）、原生错误框、`app.exit(1)`，页面不会停在「前端已加载、所有请求 503」的半死状态；
  退出确认只在打包形态拦一次（`app.isPackaged`），开发形态关窗即退。

### 调试面

- **后端**：菜单项勾选 ⇔ 端点开着 ⇔ 窗口在。勾选后壳经 IPC 发 `inspect {port: 0}`，host 用 `node:inspector` 在
  `127.0.0.1` 上开一个随机端口（已经有端点就复用，例如 dev 的 `--inspect=127.0.0.1:9231`）并回报 `inspected {url}`；
  壳把端点拼成 `<scheme>://app/node-devtools/devtools_app.html?ws=<host:port>/<uuid>`，在独立窗口里加载。
- **前端产物**：那份 DevTools 前端取自上游 `@deepseek-ai/dsh-experimental-inspector` 的 `lib/devtools`，但由 host
  自己托管（`src/devtools-assets.ts` 挂在 `/node-devtools` 上；候选根是随包运行时与 profile 工程目录）——不依赖上游
  inspector 行，也就不必装 `inspector-profile`。窗口里的前端靠显式 `ws` 参数连端点，不走上游那条同源的
  `/inspector/devtools/cdp`——桌面档没有 WebSocket 通路，见
  [ADR 桌面档调试面用 Node inspector](../../../dsh-desktop-shell/.agents/adrs/20261008-桌面档调试面用Node-inspector而非跨realm面板.md)。
- **页面**：Electron 自带 DevTools（dev 形态默认开，`DSH_DESKTOP_OPEN_DEVTOOLS=0` 可关）。
- **菜单**：`Menu.getApplicationMenu()` 在真机上可能是 null，所以菜单项优先插进现有 View 子菜单，插不进去就自建一套
  （app / file / edit / view / window）；macOS 的 app 与 window 菜单省不得（Cmd+Q、Cmd+W）。

### 启动链

- **顺序**：先 `startHost()`（等到 `ready`）再 `loadURL(`${SCHEME}://app/`)`（scheme 由 app 名派生，见
  [设计 桌面标识取自app名](./20260921-桌面标识取自app名.md)）；host 未就绪时页面拿 503 且不自动重载。
- **协议分派**：app 自己的协议 `<name>://app/*` 的应用路径全部进管道（`protocol.handle`），壳不自己服务文档、
  不做 cookie 认证、不重写 WebSocket 头。
- **DSH_HOME 显式设置**：host 经 shell 注入启动会继承用户 shell 里残留的 `DSH_HOME` export，壳启动 host 时
  显式传 `DSH_HOME`（`dsh-desktop-shell/src/index.ts`）。
- **窗口**：macOS `hiddenInset` + 交通灯内嵌 + 侧边栏 vibrancy（`visualEffectState:'active'`、透明底），
  Windows 自绘 caption（`titleBarOverlay` 高 40），其余平台无边框；`ipc.ts` 的 `nativeThemeSet` 让 macOS
  vibrancy 跟随主题。产物 `dist/index.mjs` + `dist/preload-app.cjs`（sandboxed preload 必须是 CJS，负责打平台
  标记与转发主题来源）。
- **preload 暴露面**：只在派生 scheme 的 `<scheme>://app` 上暴露 `__DSH_DIRECTORY_PICKER__`、
  `__DSH_DESKTOP_STREAM__` 与 `window.dshDesktop.{keyboard,shortcuts}`（`dsh-desktop-shell/src/preload-app.ts`）；
  native 目录选择仍是 Electron 侧实现（`dsh-desktop-shell/src/directory-picker.ts`）。

### 壳产物的依赖边界

壳（`dsh-desktop-shell/src/index.ts` 与它沿相对 import 可达的模块）打出来的 `dist/*.mjs` 会整份进 `app.asar`，
那里的解析面只有 Electron 自带的东西：tsdown 只内联 `@local/*`、`@morlay/dsh-desktop-host` 与快捷键桥用的四个
上游包（`dsh-client-shortcuts`、`dsh-atomic-write`、`dsh-util-values`、`dsh-util-crypto`，见
`packages/desktop/dsh-desktop-shell/tsdown.config.ts`），其余包一律留成裸 `import`，装进 asar 后**解析不到**。
所以壳可达的模块只能 import node 内建、`electron` 与那几个内联面——**上游包的常量也不行**（`src/seed.ts` 若为
拿 profile patch 文件名而 import 上游包，壳加载即 `ERR_MODULE_NOT_FOUND`）。

约束由 `shell-import-boundary.spec.ts` 守：从壳入口沿相对 import 遍历模块图，白名单之外一律红。profile 文件名
这类共享常量因此放在 `packages/desktop/dsh-desktop-shell/src/appconfig.ts`（纯 node import，壳与 CLI 共用）。
CLI 侧（`dsh-desktopify/src/cli/**`）跑在工具环境里，不受这条约束。

### 上游侧的既有机制（路线 B 的前提）

- `web-app` 的 `web-runtime` 行 `inject:['webServer']`（`packages/bundle/web-app/src/index.ts:41`），内部挂
  `frontend-static` → 替身一到位，dist 静态、index 渲染（含 `<base href="/">`）、注入行、`/plugins` bundle 服务
  全部照常。
- 注入脚本一旦带 `openStream`，Gateway 便不启动 WS mux（`packages/api/gateway/src/client/index.ts:161`）。
- `client-hmr` 的 `/plugins/events` SSE、`open-in-app` 的路由、`directory-picker-auto` 读 `webServer.host`
  都只依赖服务面，不依赖端口。

## 取舍

- **替身 `webServer` 而非禁掉 `webserver` 行**：禁行会让所有注册到 `webServer` 的插件静默 404 或 PENDING
  （`dev-client` 的即时打包直接没有挂载点），还得连带禁用关联行、改写 `connection.inject`；替身只替换 `listen`
  那一环。
- **所有路径走替身路由表，而不是 `/api` 直连 shared handler**：插件注册面既然统一到 `webServer`，就不要再开
  第二条道；`/api` 走路由表后 `connection/request` waterfall 等语义也在。
- **认证用「宿主接管」而不是自铸 cookie**：少一层签名 / cookie 管道与头改写，且与「页面由壳独占」的事实一致。
- **替身自写路由表而非 `extends WebServer` 覆盖 `[Service.init]`**：后者依赖 TS 私有成员，上游重构会静默破坏；
  自写并复用公开导出（`renderIndexInjections`、`serveStatic`）。
- **不暴露 `dshDesktopBoot` 而非给上游 `apps/web` 打本地 patch**：不改上游就成立；代价是页面级失败上报回到
  控制台 / 壳对话框。
- **页面流走 IPC 而不是页面 `fetch` 打自定义协议**：Chromium 对带 POST body 的自定义协议请求不返回响应头；
  主进程自建标准 `Request` 喂宿主，响应体逐块推回页面。
- **桌面不做侧边栏兜底**：上游 `shell.leading` 席位已恒挂展开入口，兜底脚本会与它叠出两套入口。

## 开放问题

- `client-hmr` 的 `/plugins/events` SSE 在管道下的表现（响应要流式回帧）未单独实测；坏了就在桌面 patch 里
  禁该行并记债。
- 替身的 `port` 固定返回 `0`（`surfaceContext` 关掉后没有读者需要真实端口）；上游若新增读 `webServer.port`
  的行，需要重新评估。
- Windows 分支（`titleBarOverlay` 高 40 + `data-windows-titlebar`）只按上游实现对齐，未在 Windows 实测。
- 桌面流的上行项只在有 uplink 的流上才有流量（`$events` 这类 Gateway 自己的流由上游 `releaseUplink` 释放）；
  业务里目前没有返回流且带 uplink 的 Remote 方法，那条路只在单测里跑过。
