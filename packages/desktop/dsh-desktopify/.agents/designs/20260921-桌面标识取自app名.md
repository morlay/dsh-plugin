# 桌面标识取自 app 名（自定义协议与后端进程名）

状态：已实现（scheme 与后端进程名都由 app 工作区 `package.json` 的 `name` 派生）
范围：Electron 壳对外自称的两处标识——页面用的自定义协议 scheme，与后端 host 子进程在 `ps` 里的名字。
约束：`vendor/**` 只读；壳的身份标识只有一个来源（app 工作区 `package.json` 的 `name`，经 `appconfig.json` 递给壳），
显示名（`dsh.desktop.name` → `appconfig.json` 的 `displayName`）不参与标识；不新增配置文件字段。

## 结论摘要

| 议题        | 结论                                                                                                                                                         | 一句话理由                                                                                                                                                                   |
| ----------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 协议 scheme | 由 app 名派生：去 scope 前缀（`@morlay/x` → `x`）、转小写、非法字符换成 `-`；派生不出合法 scheme 则启动即报错（原生错误框 + `app.exit(1)`）                  | 写死的 scheme 会与官方桌面应用撞名；app 名是壳本来就有的唯一身份（`appconfig.json` 的 `name`）                                                                               |
| scheme 传递 | 主进程顶层 `await` 读 `appconfig.json` → `desktopScheme(name)` → 顶层 `registerSchemesAsPrivileged`；页面的 `additionalArguments` 把它递给 sandboxed preload | `registerSchemesAsPrivileged` 只有「`ready` 之前」一个窗口期，而 Electron 会等入口模块的顶层 await 跑完才 emit `ready`；preload 是 sandboxed（读不到文件），只能从 argv 认领 |
| 后端进程名  | 壳给 host 子进程加 `node --title=<app name>-server`                                                                                                          | 只加 scheme 区分不出桌面后端与其他 `node …/lib/index.js` 进程；名字由壳（唯一知道 app 名的一侧）给，host 包不必新增契约                                                      |
| hostname    | 仍是 `app`（`<scheme>://app/*`）                                                                                                                             | 只换 scheme 就能错开官方；路径面（`protocol.handle`、`assertDesktopSender`、preload 的 `location.hostname`）一个字都不用动                                                   |

## 事实基线

- **派生**：`packages/desktop/dsh-desktop-shell/src/ipc.ts` 的 `desktopScheme(name)`；`DESKTOP_SCHEME_ARGUMENT`
  是主进程与 preload 共用的参数名；`assertDesktopSender` 收运行期 scheme。
- **传递**：`packages/desktop/dsh-desktop-shell/src/index.ts` 顶层 `await` 读 `appConfig`（打包分支的 userData
  设置复用这一份）→ `registerSchemesAsPrivileged`；窗口 `additionalArguments` 把 scheme 递给 preload；
  `packages/desktop/dsh-desktop-shell/src/preload-app.ts` 从 `process.argv` 的 `--dsh-desktop-scheme=` 读回。
- **进程名**：`packages/desktop/dsh-desktop-shell/src/host-process.ts` 的 `options.processTitle` 落在 args 的
  `--title=<title>`。
- **目录选择**：`packages/desktop/dsh-desktop-shell/src/directory-picker.ts` 的
  `installDesktopDirectoryPicker(getWindow, scheme)`，发送者校验用运行期 scheme。
- **上游不读 scheme**：`vendor/deepseek-harness/apps/desktop` 与 Web 前端都不读它，host 只把 URL 透传
  （`dsh-desktop-host/src/wire.ts` 的 `url`、`src/webserver.ts` 只取 `pathname` / `search`）——所以 scheme 完全
  是壳的自称，换名不动 host 与协议版本。
- **守护**：`src/__tests__/ipc.spec.ts`（派生规则、非法名报错、发送者校验不再认写死的 scheme、参数名一致）与
  `src/__tests__/host-process.spec.ts`（`processTitle` 落在 `--title`、不影响既有 argv 顺序）。
- **真机核对**（dev 形态）：页面 URL 是 `<scheme>://app/`，`pgrep -fl <name>-server` 命中后端进程，随包 Node 的
  `--title=<name>-server -p process.title` 回显一致。

## 取舍

- **显示名与标识分开**：`appconfig.json` 的 `displayName`（工作区 `dsh.desktop.name`，缺省包名）只落在人看得到
  的地方——macOS 的 `.app` 名与 Windows exe 名（electron-builder 的 `productName`）、Linux 启动器 `Name=`、退出确认
  文案；协议 scheme 与后端进程名仍只取 `name`。改显示名因此不会换协议、不会换 `DSH_HOME` 目录（那条路径取
  `dshHome` + `name`），也不会让已装应用的 `userData`（`appconfig.json` 的 `id`）搬家。
- **macOS 安装认领产物里的 `.app`**：`.app` 名由 electron-builder 从 `productName` 派生并替换其中的非法字符，
  安装侧因此读产物目录里那一个 `.app`，不重写一遍命名规则（重写就会与产物名失配）。
- **派生而非新增配置字段**：协议 scheme 是 `name` 的一次纯函数变换，工作区不另设 scheme 字段；设了会让「改名忘了改
  scheme」变成可能（`displayName` 不属于此列：它不参与任何标识派生）。
- **规范化而非拒绝非法名**：包名允许 scope 与下划线，scheme 不允许——去 scope + 转 `-` 让 `@morlay/dsh_custom`
  也能起；但派生结果若不以字母开头（`1app`、空名）仍大声失败，不猜一个前缀。
- **顶层 `await` 而非同步读**：`node/no-sync` 是本仓的 lint 规则；Electron 明确「入口模块的顶层 await 跑完才
  `ready`」，所以 await 同样能赶在 `registerSchemesAsPrivileged` 的窗口期之前。
- **`--title` 而非 host 侧读环境变量**：随包 Node 与 dev 的系统 Node 都支持 `--title`，host 包零改动；代价是该
  flag 成了壳与 Node 之间的一个隐性依赖（node < 21.2 会启动失败，属于大声失败）。
- **只给 Electron 壳的子进程改名**：`dev --web` 起的 `dsh web` 是浏览器形态的另一条路（不起壳、不起 host）。

## 开放问题

- 两处标识都取自 `name`；若将来要按 `dsh.desktop.id`（反向域名）派生，`id` 已经是合法的 scheme 形状，但会与
  `name` 分成两套叫法，需要重新取舍。
- Windows 上 `process.title` 的可见性（任务管理器 / `tasklist`）未实测。
