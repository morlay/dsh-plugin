# 桌面侧边栏兜底依赖客户端 DOM 标注

状态：未销账（上游没给「无会话时也能重开侧边栏」的入口，我们在桌面层补）

**现象**

macOS 桌面形态下侧边栏收起时列宽为 0（完全隐藏，没有 rail），唯一的重开入口是会话头部 leading 槽
（`packages/client/ui-sidebar/src/client/HeaderLeadingControls.tsx`，挂在
`conversation.session.header.leading`）。而该槽只在有会话时渲染
（`packages/client/ui-conversation/src/client/skeleton/ConversationMainPanel.tsx`：
`sessionId === undefined ? null : renderSlot('conversation.session.header', {})`）——没开会话时收起侧边栏，
页面上就没有任何入口能再打开它。

桌面 host 因此注入一段兜底脚本（`packages/desktop/dsh-desktop-host/src/layout-fallback.ts`，随
`installDesktopTransport` 一起进 index）：macOS + `[data-sidebar-collapsed]` 存在 +
`[data-conversation-header-leading] button` 不存在时，把 `style` 里的 `grid-template-columns: 0px` 换成
`56px`，让客户端渲染 rail（rail 自带展开按钮）；有会话头部入口时保持官方的完全隐藏。

**影响**

兜底靠三样客户端事实：`data-sidebar-collapsed`、`data-conversation-header-leading`、以及 React 写在
`style` 属性里的 `grid-template-columns` 文本。上游重命名任一标注、改用 CSSOM 写样式、或给空态也提供
重开入口后，兜底会静默失效（表现为：收起后又一次没有任何入口）。

**触发条件**

同步 `vendor/deepseek-harness` 后（尤其 `packages/client/ui-layout`、`ui-conversation`、`ui-sidebar`），
必须在桌面 dev 形态复验一次：**不打开任何会话**时收起侧边栏，仍能看到 56px rail 并能点开。

**销账条件**

Done when：上游在空态也提供重开入口（或客户端自己保证收起后始终有可见入口），我们删除这段注入。

**不修的理由**

改客户端要有 `ui-layout` 的 fork（上游只读，我们只有 ui-conversation 的薄壳 fork），成本远大于一段
注入脚本；注入只在桌面形态生效，浏览器形态不受影响。
