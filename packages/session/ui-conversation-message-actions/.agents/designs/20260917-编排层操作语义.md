## 结论摘要

| 议题     | 结论                                                                               | 一句话理由                                                                                                                                               |
| -------- | ---------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 编辑落点 | edit / retry / reroll 就地重写**同一会话**（session id 不变）                      | 用户要改这条消息，不是开新会话（[ADR-就地编辑重写同一会话而非新建会话](../adrs/20260917-就地编辑重写同一会话而非新建会话.md)）                           |
| 编辑入口 | 只要消息存在可编辑文本块就能撤回，不要求轮次归属                                   | 消息自身 `eventSeq` 已能定位边界（[ADR-编辑入口不依赖轮次归属](../adrs/20260917-编辑入口不依赖轮次归属.md)）                                             |
| 重放     | 经 `agents` 服务驱动（duck-typed）；缺失时退化为「已 durable 的就地版本」          | 回复必须由模型生成、不能绕过轮次状态机（[ADR-重放经agent驱动而非直接append回复](../adrs/20260917-重放经agent驱动而非直接append回复.md)）                 |
| rewind   | 截断前先停住运行中的 loop（`cancel({kind:"user"},{keepInbox:true})` → `whenIdle`） | 截断与运行中的 loop 并发会写穿边界（[ADR-rewind前主动停止运行中的loop](../adrs/20260917-rewind前主动停止运行中的loop.md)）                               |
| 压缩     | 被截断丢掉、但在重放目标之前的完整压缩事务在重写时补回                             | 否则摘要失效且压缩不可再触发（[ADR-压缩事务在重写时补回](../adrs/20260917-压缩事务在重写时补回.md)）                                                     |
| 传输面   | 一条 exact `POST /session-editor`（web 与桌面共用同一张路由表）                    | 单一入口，无 `/api` 前缀重复注册                                                                                                                         |
| 浏览器半 | 只保留 `retry` / `recall` 两个动作，刷新由动作驱动                                 | 常驻刷新的消费方不存在，且被重放期间的快照抖动放大（[ADR-浏览器半只保留动作面不挂常驻刷新](../adrs/20260920-浏览器半只保留动作面不挂常驻刷新.md)）       |
| 操作历史 | 不记录：版本效果事件与它的读侧投影都不存在                                         | 没有读者的写入不值得留（[ADR-20260920-删除版本树投影并停止写版本效果](../../../session-branch/.agents/adrs/20260920-删除版本树投影并停止写版本效果.md)） |

## 事实基线

### 服务面（`ctx.sessionEditor`）

| 操作     | 语义                                                                              |
| -------- | --------------------------------------------------------------------------------- |
| `edit`   | 编辑已落定文本块（用户消息 / 助手块），**就地**（rewind + 重写，session id 不变） |
| `reroll` | 重生成最后一条已落定助手回复（使用原用户输入）                                    |
| `retry`  | 重试任意历史回合（`truncate` 只重放目标输入 / `preserve` 重放后续全部）           |
| `rewind` | 截断式回退：原会话回退到闭合 `turn/end` 边界                                      |
| `recall` | 撤回 user 消息到输入框：只 `rewind` 截断，不重写、不重放（交给用户改后重发）      |
| `fork`   | 从任意闭合边界派生**新会话**（唯一产生新 id 的操作）                              |

传输面一条：宿主 `webServer` 上的 exact 路由 `POST /session-editor`——web 与桌面共用同一张路由表（无端口
形态见
[设计 20260920-桌面无端口传输与窗口对齐](../../../../desktop/dsh-desktopify/.agents/designs/20260920-桌面无端口传输与窗口对齐.md)）；
浏览器半恒定请求该路径，不按 `__DSH_TRANSPORT__.ownsHost` 加前缀。注册必须等 `webServer`
（`ctx.inject(["webServer"])`）：它可能比本行晚激活，而 `ctx.get` 取到 undefined 之后不会再试一次。

### 就地编辑语义

- **edit / retry / reroll 是就地操作**：`rewind` 截断到目标轮之前的闭合 `turn/end` 边界，再 `append` 手工
  回合 / 重放输入回**同一会话**——session id 不变。
- **重放复用目标轮号**：轮首 user 编辑（含未闭合轮）整轮截断，重放接回原轮号；编辑 assistant 写入
  manualTurn 后同步 agent 的轮次游标。
- **空轮吸收**：目标轮之前的空轮（`turn/start` 后直接 `turn/end`，历史数据里可能存在的形状）随截断一并
  删除，重放按保留前缀续号——轮次导航不再出现点不开的空项与轮号空洞；manualTurn 的轮号同样按保留前缀收敛
  （正常会话等于目标轮号）。
- **只有 `fork` 创建新 id**（`ForkOperation` / `forkFrom`，纯 append 派生）。
- **`recall` 只截断不重写**：轮内消息沿用 `edit` 的轮首规则（轮首整轮截断到前一轮 `turn/end`，无前轮则清空
  全部；轮内 followup exclusive drop），轮外 user 消息（`location` 无轮次归属的排队落定消息）按消息自身位
  置 exclusive drop（截断该消息及其后全部），但只 `rewind` 即返回——不重放；被撤回的 user 文本由浏览器半回
  填到 composer，用户修改后自行发送。
- **操作历史不留痕**：`session-branch/version` 事件没有生产方与消费者，类型定义只作为历史形状保留在
  `@morlay/session-branch`（[ADR-20260920-删除版本树投影并停止写版本效果](../../../session-branch/.agents/adrs/20260920-删除版本树投影并停止写版本效果.md)）。

### agent 驱动（重放排队输入）

`agents` 服务以 duck-typed 接口使用（不硬依赖 `@deepseek-ai/dsh-agent`），缺失时退化为「已 durable 的就地
版本」（可随时 resume 续跑）：

- **live agent**（会话驻留 / 已恢复）：直接 `followup` 排队，不重建、不换 id；
- **rewind 前必须停止运行中的 loop**：每次 rewind（edit / retry / reroll / recall / HTTP `rewind`）都先对
  驻留 agent `cancel({ kind: "user" }, { keepInbox: true })` 再 `whenIdle()`，然后才截断——截断会重写 agent
  的 session 内存 log，不能与运行中的 loop 并发；`keepInbox` 表示停止本身不丢弃待处理输入，残留排队输入由
  rewind 在截断后强制 durable 取消（session-rdb 的 live 会话钩子 `inbox.clear`）；实现无 `cancel` 能力时退
  化为等待其自然停下
  （[ADR-rewind前主动停止运行中的loop](../adrs/20260917-rewind前主动停止运行中的loop.md)）；
- **cold 会话**：`resume` 已持久化会话（`create` 对已持久化日志必失败），resume 后 agent 驻留（不 dispose，
  避免 session 被移出 store 破坏客户端窗口）；
- 模型 provider / model 在 **rewind 之前**从 `request/header` 解析（就地编辑可能截断掉 header，编辑第一轮
  boundary = −1 时尤甚）。

### 浏览器半（client bundle）

`dist/client.cjs`（单文件，运行期按 `/plugins/??<pkg>/client.js` 服务）经 `__ModuleLoader__.load` 手递，替换
`conversation.chat.node` 的 `user` / `steering` 渲染：

- **shadow 注册**：`user` / `steering` 两个 key 以 `priority: -1` 重新注册（最低优先级渲染，shadow 上游默认
  注册）；其余 key 沿用上游渲染器。
- **composer 统计行不再覆盖**：官方 `ui-chat` 自带同一套统计行（`StatsPills` + `stat-dialog` + `token-format` +
  `turn-reading`，连根节点的 **shrink-wrap** 形态都是同一份），我们原先 fork 了一份同源副本去 shadow 官方同 id 的
  `stats`——现已删除，`conversation.composer.dock` 交回官方（[ADR-不fork上游前端组件只做插槽扩展](../../../../../.agents/adrs/20261001-不fork上游前端组件只做插槽扩展.md)）。
- **编辑 / 重试按钮只挂在 user 消息**（`UserMessageNodeView`）：编辑只要消息存在可编辑文本块就显示（不要求
  轮次归属——`location` 无 turn/step 的已落定消息同样可撤回），点击后不打开编辑弹窗，而是确认（`Modal` +
  `Button`）后调用 `recall`——服务端只 `rewind` 截断，客户端把消息文本 `setDraft` 回填到主输入框
  （`conversation.input`），交给用户修改后自行发送；重试仍先弹确认，且只对已闭合轮次开放
  （[ADR-编辑入口不依赖轮次归属](../adrs/20260917-编辑入口不依赖轮次归属.md)）。
- **操作后重建窗口**：动作成功后探测会话窗口的重建入口——`binding(id).session.resync()`（上游 ClientSession
  的重建入口，类型面没暴露，运行时探测）→ 退而 `sessions.refresh()`（只刷列表元数据）→ 都拿不到就记一条
  warn。**不整页重载**（打断用户），也不做投影截断（`ProjectionsFace` 没有截断入口；rewind 的删除经窗口重
  建表达）。rewind 的删除无法经 append-only 事件流表达，seq 回退只做增量会残留旧节点，所以必须重建；实现
  见 [`src/client/controller.ts`](../../src/client/controller.ts) 的 `rebuildWindow`，守护用例
  `client-controller.spec.ts`。
- **撤回后视口回底**：rewind 把窗口换短，而上游 `ChatView` 只在读者已经贴底时才自动跟随
  （`tipMoved && atBottom`），停在中途的视口会悬在被截断的位置上；撤回的下一步是改完再发，所以动作面在**
  窗口重建落定之后**无条件把 `[data-conversation-scroll]` 写到底（等两帧，让窗口替换先渲染——写早了会被下
  一轮布局覆盖）。容器契约沿用上游既有标注（`ConversationContent` 定义，`ChatView` /
  `ConversationWidthControls` / `StatsPills` 同用）；重试不参与（它之后会重新产出内容，跟随语义交回上游）；
  守护用例同 `client-controller.spec.ts`。
- **构建约束**：client bundle 必须是**单文件**，devkit 的 client 入口插件保持平台 seed 与其余
  `@deepseek-ai/*` client 插件行 external（内联会把别的插件的 `__ModuleLoader__.load` 嵌进来导致 duplicate
  factory），契约层与第三方依赖全部内联，动态 import 合并；CSS Modules 经 lightningcss 内联 +
  `<style data-plugin>` 注入
  （[ADR-客户端bundle单文件与shadow渲染替换](../adrs/20260917-客户端bundle单文件与shadow渲染替换.md)）。

### 分层边界

- 数据层（`forkFrom` / `rewind` / `readBranchPrefix`）来自 `ctx.sessionBranch`（provider 实现，如
  `@morlay/session-rdb`）；
- 本服务只做**编排**：闭合轮次扫描、派生 seed 组装、rewind 命令透传、agent 驱动、HTTP 面。
