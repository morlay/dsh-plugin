# 对话 UI 客户端半的装配面缺测试辅助

状态：触发中（上游已有可用的 client harness，但 fork 的收窄声明与官方类型撞 TS2717，装配面行为用例开不了）

**现象**

对话 UI 接管面（`session/ui-conversation`）与编排层（`session/ui-conversation-message-actions`）的**行为
逻辑**已按接缝测（接缝清单见 [本包规范 how-to-verify](../standards/how-to-verify.md) 与
[接管包的 how-to-verify](../../../ui-conversation/.agents/standards/how-to-verify.md)），但 **slot 装配面**
仍无测试：

- `session/ui-conversation`：[`src/client/apply.ts`](../../../ui-conversation/src/client/apply.ts)（插件装配
  - slots 注册，含 `ConversationController` 注册，取自 vendor 上游）、`src/client/index.ts` 与
    `src/client/contract/input.ts`（`Context.input` 收窄）；
- `session/ui-conversation-message-actions`：[`src/client/index.ts`](../../src/client/index.ts) 的 `apply`
  （slot 注册）。

已覆盖、不在此结算的部分：`conversation.composer.dock` 的 `stats` 覆盖注册
（`client/composer-stats/register.ts`）由 `composer-stats.spec.ts` 直接驱动真实的 `SlotCore`
（`@deepseek-ai/dsh-client-ui-slots`，纯注册表，不需要浏览器运行时）——声明槽、注册官方同 id 行、再跑我们
的注册，断言赢家 id / priority / locale / 组件；fork 的 `apply` 对 slots / locale / configForms 的订阅由
[`upstream-wiring.spec.ts`](../../../ui-conversation/src/__tests__/upstream-wiring.spec.ts) 对着上游守（不
加载 client 类型图，所以不受 TS2717 影响）。核心纯逻辑（事件→视图投影、消息定位、输入 / 队列状态机、引用
检测与菜单）与用户可见组件（气泡、队列行、引用菜单）也都有接缝测试。

**影响**

这些模块需要 **cordis client 运行时**：`slots` 的声明者与注册表、`locale`、`renderer`、`sessions` 面
（binding / scope），以及浏览器模块图。vitest 的 `@morlay/*/client` alias 只把本仓库包的 `/client` 回源到
TS 源码，而**上游 client 半是浏览器模块工厂**（`window.__ModuleLoader__.load`），node 侧不可加载——所以
不能直接装配真实的 slot 运行时，强行逐份 stub 只能得到「实现镜像」式的断言，验证不了装配契约。

**触发条件**

动到这些 `apply` / 装配面之前——没有测试就改装配，slot key / priority / locale 与注入面的回归只能靠人工跑
GUI 发现。眼下的阻塞点不是「没有 harness」：上游 0.1.7 起提供 `@deepseek-ai/dsh-client-test-runtime` 的
`SlotTestRuntime`（在 `vendor/deepseek-harness/packages/test-support/client-runtime/`），本仓库已把它跑通
（一个真实装配面用例能红能绿）；但 harness 的 `fixtures.ts` 会把官方 `ui-conversation` 的类型拉进同一个
program，与 fork 的收窄声明撞 TS2717（3 条，`just lint` 立刻变红；把声明搬进 `.d.ts` 靠 `skipLibCheck`
覆盖、或就地加 `@ts-ignore` 两条路都试过，都让收窄类型失效）——细节与后果见
[接管包规范 how-to-write](../../../ui-conversation/.agents/standards/how-to-write.md) 的「类型面」。

**销账条件**

Done when：装配面有真实用例守护。落地动作：

1. 把这处收窄从「占用官方属性名」改成 fork 自己的服务 / 类型面（契约变更，落 ADR）——TS2717 消失后官方类型
   才能与我们的声明同处一个 program；
2. 给上面列出的 `apply` / 装配面补 jsdom 用例：断言 slot 注册的 key / priority / locale、注入面方法可用、
   渲染出用户可见结构；
3. 结算本记录，并同步更新两个包 `.agents/standards/how-to-verify.md` 的未覆盖清单。

harness 的接法（已验证可行）：按 vendor `tsconfig.base.json` 的 paths 把上游 **client 半**解析回 TS 源码，
host 半仍走构建产物（其源码含标准装饰器，vite 的 oxc 在 esnext 下不转译）；vitest 的解析 alias 要**精确匹
配** key（字符串 find 是前缀匹配，会吃掉 `.../renderer/src/client/bind.ts` 这类深路径），且只覆盖 client 面。

**不修的理由**

在收窄声明改掉之前写不出有验证力的用例（只能镜像实现），所以现在补的是断言之外的东西——先改一处契约。已覆
盖的部分（核心纯逻辑与用户可见组件的接缝测试）是有效的，装配面的空白可以等这处契约改动。
