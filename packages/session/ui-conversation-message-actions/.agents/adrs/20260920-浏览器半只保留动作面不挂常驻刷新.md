# 浏览器半只保留动作面，不挂常驻刷新

状态：已采纳

背景：浏览器半曾有一条「订阅会话列表 + 会话快照 → 全量 `GET /session-editor` → 装进 store」的刷新管路，连同一套 store / hooks / 引用计数（`acquire` / `release` / `revive` / `dispose`）与四个没有任何调用方的动作（`edit` / `reroll` / `rewind` / `openVersion`）。实测与查证下来：`acquire` 全仓无调用方 → `dispose` 是死代码 → `sessions.list` 与快照两处订阅从不释放、`controllers` 只增不减；`invalidate` 的门（`status === "idle"` 才跳过）在第一次 `load` 之后形同虚设 → 每一次快照抖动都换成一次全量 GET，而编辑 / 重试 / 撤回恰好触发重放（agent 持续运行 → 快照与列表高频变化），访问过 N 个会话时一次列表更新就是 N 次 GET。同时 `MessageItem` 只从 inject 面取 `recall` / `retry`，门控全部来自上游 chat node 的 props——那条管路没有任何 UI 消费方，唯一的实质消费点（撤回靠 timeline 反查消息块）反而依赖从未被接线的 `load`，导致首次撤回只回填第一个文本块。

**决定**

浏览器半只保留消息渲染面真正用到的动作（`retry` / `recall`），刷新只由动作驱动：动作成功后 `resync()` + `projections.truncate(-1)`，不可用时回退整页 `reload()`；撤回回填的文本由渲染面给出**该消息的全部文本块**；host 侧 `ctx.sessionEditor.timeline` 与 `GET /session-editor` 保留，但浏览器半不再常驻消费——将来接版本导航时按需拉取。

**考虑过的选项**

- 保留管路并补 `dispose` 接线 + revision 门 + 请求代次：把 bug 修掉但保留一条没人消费的管路，刷新策略仍然由「快照抖动」而不是「用户动作」定义。
- 连 host 侧的 timeline / `GET /session-editor` 一起删：客户端与 host 都瘦身，但版本导航要重建契约面，且 `session-branch` 的版本树投影（[ADR-版本树接受就地编辑的自身逆操作](../../../session-branch/.agents/adrs/20260920-版本树接受就地编辑的自身逆操作.md)）失去透出通道。
- 改成按需拉取但仍常驻订阅事件：风暴源（订阅）留着，只是少发几次 GET。

**后果**

- 请求只剩动作 POST，`SessionEditorFace` 缩到两个方法；`hooks.sessionEditor` / store / `acquire` / `openVersion` 一并删除。
- `conversation.session.header.utilities`（版本导航入口）与 `GET /session-editor` 目前在浏览器半**没有消费方**，设计文档「接管与禁用清单」已按实际改记；接版本导航时用**按需拉取**，不要恢复常驻订阅。
- 撤回的文本来源从 timeline 反查改为消息自身内容：多文本块消息不再丢块（原先首次撤回只回填首块）。
- 守护：`client-controller.spec.ts`（动作 POST + 窗口重建、全部文本块回填、失败不阻塞下一次、列表 / 快照变化不发请求）。

已被 [ADR-20260920-删除版本树投影并停止写版本效果](../../../session-branch/.agents/adrs/20260920-删除版本树投影并停止写版本效果.md)
取代——读面连同版本效果一起删除，`/session-editor` 只剩 POST；「浏览器半不常驻消费」的决定不变。

**后续变化（2026-09-20）**：动作成功后的刷新改成**运行时探测窗口重建入口**：`binding(id).session.resync()`
（上游 ClientSession 的内部入口，类型面 `SessionFace` 没暴露，所以逐个探测）→ 拿不到时退而 `sessions.refresh()`
（只刷列表元数据）→ 都没有就记一条 warn。**不回退整页重载**（打断用户），也不做投影截断（`ProjectionsFace`
只有 `faceOf`）。实测撤回后旧节点会残留在窗口里，所以重建这一步是必须的；守护用例
`client-controller.spec.ts` 断言「先 resync、拿不到才 refresh、不 reload」。
