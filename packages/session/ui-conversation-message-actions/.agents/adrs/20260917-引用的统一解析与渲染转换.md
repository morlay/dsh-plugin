# 引用的统一解析与渲染转换

状态：已采纳

背景：引用在输入框与消息里都是**文本**，而两侧要的东西不同：输入框要保留 raw markdown（不建 chip
节点、不装饰），消息与队列行要渲染成 chip。官方渲染器只给了一个 chip 钩子（`fileMentions`，只认
inline code），渲染内部件又不在公共面——把「引用长什么样」和「怎么渲染」绑在一起，就会在输入侧要结构
化、在渲染侧要自造 chip 的两头落空。

**决定**

解析与渲染分离：解析产出统一结构的引用，渲染再做转换。

- **解析（一份，host 与 client 共用）**：用 markdown 解析器（`mdast-util-from-markdown` + GFM + 我们的
  micromark/mdast 扩展）把所有合法书写（`skill:x` / `@x` / `@x#L12-L40` / `@x:1:2` / `@"x y.ts"` /
  `[label](uri)` / `@[label](dsh-session:…)`）归一到同一个 `Reference` 结构，`protocol` 默认 `file`。裸
  形态由 micromark 扩展在文本构造层认领（词边界起手、已知 scheme 才吃 `x:y`、`#L12-L40` fragment 一并
  吃掉），link / mention 形态由 mdast 转换层认领（label → `title`），代码块与 inline code 内的同形文本由
  解析器天然排除（**不做文本层全局正则替换**）。书写形态与归一结果的对照表、`Reference` 类型见
  [设计 20260917-对话UI重构](../designs/20260917-对话UI重构.md)。
- **入口与产出**：`findReferences(text): readonly ReferenceSpan[]`；产出侧只有两个形态函数
  `formatReferenceMention`（`@` 前缀 mention，草稿与消息文本用）与 `formatReference`（scheme 形态，chip
  的 hover / aria-label 用）——产出与认领同一份规则，`findReferences` 读得回 `formatReferenceMention`
  写出的每一个 mention。
- **渲染转换（复用官方渲染器，不 fork）**：官方包 `@deepseek-ai/dsh-client-ui-primitives` 的公共面只有
  `MarkdownText` / `CodeBlock` / `extractMarkdownPlainText`，且它在 client 侧是平台 baseline external
  （模块表按**精确包名**注册，子路径 require 必 miss）——「自组 context + renderBlocks」在浏览器里跑不
  起来。官方唯一的 chip 钩子是 `fileMentions`（只认 inline code）→ **本地引用**
  （`isLocalReference`：非 http/https/mailto）的原文切片换成 inline code，**显示文本省略 protocol**（图标
  已经表示协议：有 label 用 label，否则用 path + 行号 fragment），hover 与 aria-label 是完整引用；http(s)
  / mailto 保持 link 原文、官方照常出锚点。判定不靠文本形态：转换同时产出「显示文本 → Reference」映射
  交给 `fileMentions.resolve`，所以 `code-review` 这种没有路径特征的 skill 名也能稳定成 chip，普通
  inline code 不会被误判。入口 `ReferenceMarkdown({ text, labels, actions })`（内部
  `referenceMentions(actions, 映射)` 接 `fileMentions`）；点击 file → `openFile(path)`、skill →
  `openSkill(name)`（owner props，打开右侧栏）——**keyed 渲染器也要从 owner props 取这两个动作并透传**，
  否则点击无反应。
- **其余面沿用的三条**：输入框保留 raw markdown（插入的引用先解析回结构化引用、再按**预定形态**写回草稿
  ——file / folder 是 `@` 前缀 mention（含空格加引号，`formatReferenceMention` 产出），skill 选择器是
  `skill:name`（`insertTextOf`），粘贴只落 `text/plain` 原文；编辑器里不建 chip 节点、不装饰）；提交回单
  content block（草稿原文即一个 text 块）；host 侧引用后注入（`@morlay/dsh-reference` 用**同一个**
  `findReferences` 找 `protocol === 'skill'`，渲染 `<skill_content>` 注入，手写的 `` `skill:x` `` 由
  `parseReferenceToken` 再兜一次；同一入口也认 `@` 起手的 file 引用，见
  [设计 20260920-文件引用内容注入](../../../../context/dsh-reference/.agents/designs/20260920-文件引用内容注入.md)）。

**考虑过的选项**

| 选项                                            | 代价                                                                                              |
| ----------------------------------------------- | ------------------------------------------------------------------------------------------------- |
| 保持 XML 资源块 + 内容内联                      | 输入框结构化 + 渲染要解析 XML + 消息膨胀                                                          |
| 自造 chip 渲染（切分文本 + 自己的 chip 组件）   | 行内引用会把一行切成多块（`MarkdownText` 是块级），markdown 结构断裂；与官方文件 mention 两套视觉 |
| fork 官方 markdown 渲染器                       | `render.tsx` 685 行 + `CodeBlock`/shiki/katex + CSS module，成为一个长期 fork 面                  |
| 打上游 patch 让官方导出渲染内部件               | 与「`vendor/**` 不可改」的红线冲突，且要重建 vendor                                               |
| **统一解析 + 渲染转换到官方 chip 钩子（选定）** | chip 的显示文本要省 protocol（图标已表示协议）；`dsh-session` 等其它 protocol 暂无点击目标        |

**后果**

- **规则只剩一份**：host 与 client 用同一个 `findReferences`。
- **两个渲染消费点**：编排层 keyed shadow 的 `user` / `steering` 气泡与 `QueueDock` 的队列行（host 侧另由
  `@morlay/dsh-reference` 用同一份解析做 skill / file 后注入）。
- **chip 语义**：显示省略 protocol 的文本（有 label 用 label，否则 path + 行号范围）、hover 完整引用、点击
  file/skill 打开右侧栏（点击目标来自 owner props `openFile` / `openSkill`）；没有 `actions` 时照常渲染但
  点击无效果；队列行的 chip 没有 owner 动作（点击无效果，视觉一致）。
- **已知取舍**：`[label](uri)` 的 label 只进 `title`，chip 显示的是 token（要显示 label 就得改渲染器）；
  目录 token（`file:src/dir/`）由官方 `classifyLinkPath` 按扩展名判定 → 通用纸张图标而非文件夹图标；转换
  每帧对全文解析一次（官方渲染器的增量缓存不受影响）。
- **旧消息兼容**：旧消息里的 `@path` 文本由同一解析认领（无行号也成 file chip——本 UI 没有 cue 人，
  `@handle` 不回退成普通文本）；`/name` 仍是普通文本。
- **依赖**：`mdast-util-from-markdown` / `mdast-util-gfm` / `micromark-*` 进
  `@morlay/dsh-client-ui-primitives` 的 `dependencies`（host 面运行时也要解析）；`vendor/**` 未改，未打
  patch。
