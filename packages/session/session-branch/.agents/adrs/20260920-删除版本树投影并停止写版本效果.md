# 删除版本树投影并停止写版本效果

状态：已采纳

背景：版本树投影（timeline）服务的是「编辑了什么、从什么改成什么」与撤销 / 重做链，读侧链路是
`buildTimeline` → `ctx.sessionBranch.timeline` → `SessionEditor.timeline` → `GET /session-editor` →
浏览器半的 `SessionEditorController`。浏览器半只保留动作面、不拉任何读取面
（[ADR-20260920-浏览器半只保留动作面不挂常驻刷新](../../../ui-conversation-message-actions/.agents/adrs/20260920-浏览器半只保留动作面不挂常驻刷新.md)），
这条读面没有消费方；而版本效果事件是每次就地编辑多写的一条记录，写它依赖读侧「一个会话只有一个版本
效果」的不变量，该不变量与写路径矛盾（fork 子会话上做一次就地编辑会让读侧恒 409）。

**决定**

不保留版本树投影与版本效果的写入：`session-branch` 不含 `timeline.ts`、`BranchTimeline` /
`BranchVersionNode` / `BranchSnapshot` 类型、`SessionBranch.timeline` 抽象方法与 `buildTimeline` 导出；
`session-rdb` 不含 `SessionBranchRdb.timeline`；`ui-conversation-message-actions` 不含
`SessionEditor.timeline`、`GET /session-editor` 路由、`toTimelinePayload` / `VersionSummary` /
`depthOf`，edit / retry / reroll 不产出 `session-branch/version`（`plan.ts` 的 `pairVersionEffect` 与
seedSuffix 里的版本效果也一并去掉）。`session-branch/types.ts` 保留 `SessionBranchVersionEvent` 等
**历史形状**定义（旧数据里已落库的事件仍可被识别），它们没有生产方与消费者。

**考虑过的选项**

- **只删读侧、保留写侧落库**：留一条只写不读的事件——每次编辑多一条永久记录，价值为零。
- **保留 timeline 并接上版本导航 UI**：能力本身没问题，但当前没有需求，且它的读侧不变量与写路径矛盾
  （要先修），成本落在无人使用的面上。
- **保留 `GET /session-editor` 作为将来入口**：GET 只服务 timeline，留着就是死路由。

**后果**

- `GET /session-editor` 不存在（只剩 POST）；宿主内嵌那条 `/api` 前缀重复注册也没有，传输面统一在
  webServer 的 exact 路由上。
- 会话不记录操作历史：旧会话里已落库的 `session-branch/version` 事件原样保留（写路径零转换），新操作
  不写。
- 将来要做版本导航要重建读侧（并把「同一会话多个版本效果」当正常形态）：届时应重开这条 ADR。
