# 删除版本树投影并停止写版本效果

状态：已采纳

背景：`session-branch/version` 事件（edit / retry / reroll 的版本效果）当初为版本树投影（timeline）服务——把会话的操作历史与派生关系投影成一棵树，供 UI 展示「编辑了什么、从什么改成什么」与撤销 / 重做链。落地后的实际链路是：写侧每次就地编辑追加一个 version 事件 → 读侧 `buildTimeline` 折叠成 `BranchTimeline` → `ctx.sessionBranch.timeline` → `SessionEditor.timeline` → `GET /session-editor` → 浏览器半的 `SessionEditorController`。后来浏览器半的刷新管路被摘掉（[ADR-浏览器半只保留动作面](../adrs/20260920-浏览器半只保留动作面不挂常驻刷新.md)），`GET /session-editor` 与整个 timeline 面**没有任何消费方**；而写侧仍在每次编辑多写一条没有读者的记录。同时读侧「一个会话只有一个版本效果」的不变量与写路径矛盾——fork 子会话上做一次就地编辑就会让 timeline 恒 409，维护成本全落在没人用的能力上。

**决定**

删除版本树投影与版本效果的写入：`session-branch` 去掉 `timeline.ts`、`BranchTimeline` / `BranchVersionNode` / `BranchSnapshot` 类型、`SessionBranch.timeline` 抽象方法与 `buildTimeline` 导出；`session-rdb` 去掉 `SessionBranchRdb.timeline`；`ui-conversation-message-actions` 去掉 `SessionEditor.timeline` / `editableMessages` / `retryableTurns`、`GET /session-editor` 路由、`toTimelinePayload` / `VersionSummary` / `depthOf`，并且 edit / retry / reroll 不再产出 `session-branch/version`（`plan.ts` 的 `pairVersionEffect` 与 seedSuffix 里的版本效果一并删除）。`session-branch/types.ts` 保留 `SessionBranchVersionEvent` 等**历史形状**定义（旧数据里已落库的事件仍可被识别），但没有新事件产生、也没有读者。

**考虑过的选项**

- 只删读侧、保留写侧落库：留一条只写不读的事件——每次编辑多一条永久记录，价值为零。
- 保留 timeline 并接上版本导航 UI：能力本身没问题，但当前没有需求，且它的读侧不变量与写路径矛盾（要先修），成本落在无人使用的面上。
- 保留 `GET /session-editor` 作为将来入口：GET 只服务 timeline，留着就是死路由。

**后果**

- `GET /session-editor` 不再存在（只剩 POST 动作）；宿主内嵌那条 `/api` 前缀重复注册也一并去掉，传输面统一在 webServer 的 exact 路由上。
- 会话不再记录操作历史：旧会话里已落库的 `session-branch/version` 事件原样保留（写路径零转换不变），新操作不写。
- 将来要做版本导航要重建读侧（并把「同一会话多个版本效果」当正常形态）：届时应重开这条 ADR，旧语义仍在本目录的两条已废弃 ADR 里。
- 同步废弃：ADR-版本效果以 ignorable 事件原样落库、ADR-版本树接受就地编辑的自身逆操作（均被本 ADR 取代）。
