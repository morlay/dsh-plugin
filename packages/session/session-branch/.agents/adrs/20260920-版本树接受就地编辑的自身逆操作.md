# 版本树接受就地编辑的自身逆操作

状态：已废弃（被 [ADR-20260920-删除版本树投影并停止写版本效果](20260920-删除版本树投影并停止写版本效果.md) 取代：这条决定服务的是已删除的读侧投影，写侧也不再产出该事件）

背景：`session-branch/version` 事件的 `inverse.sessionId` 有两条真实来源。fork 派生把效果写在**派生子会话**里、inverse 指向**父会话**；就地编辑（edit / retry / reroll）原地重写**被编辑的会话自己**（session id 不变），效果写在它身上、inverse 指向**该会话自身**（`pairVersionEffect(operation.sessionId, …)`）。原读侧把「inverse 必须等于 `header.parentSession`」当不变量，于是 fork 子会话上做一次就地编辑之后，`GET /session-editor` 恒 409（`INVALID_BOUNDARY`），编辑 / 重试 / 撤回入口整条失效；同一处还把「同一会话累积多个版本效果」当损坏抛错——而 rewind 只截断边界之后的事件、边界之前的版本效果本来就会留在会话里。

**决定**

版本树投影接受两种 inverse：指向**本会话自身**（就地编辑）或**它的父会话**（fork 派生），其余仍 fail loud；同一会话的多个版本效果取**最近一次**（按 seq），并且普通（无父）会话的自有效果同样参与投影——不再只写不读。

**考虑过的选项**

- 保持「inverse 必须等于 `parentSession`」：实现简单，但写路径与读侧不变量互相矛盾，fork 子会话编辑面不可用，问题只是被 `parentSession !== undefined` 这个读取条件藏在普通会话之外。
- 节点携带 `effects[]` 有序列表：保留多次编辑的历史，但要改契约类型与 timeline payload，客户端消费面（`VersionSummary` 单值）也要跟着改；当前没有消费多次历史的需求。
- 普通会话继续不读自有效果（原状）：版本效果只写不读，编辑历史在版本树里不可见，与「版本效果原样落库、读侧按信封投影」的既有 ADR 相悖。

**后果**

- `BranchVersionNode.effect` / `inverseSessionId` 的语义确定为「该会话**最近一次**版本操作」，多次编辑的中间历史不投影；将来要展示完整历史时再升到 `effects[]`。
- `timeline.spec.ts` 的旧用例（rejects a session carrying multiple own version effects）随行为改写；判据变成「多效果取最近 / 自身 inverse 合法 / root 会话参与投影」。
- 守护两层：`session-branch` 的 `timeline.spec.ts`（投影不变量）与 `ui-conversation-message-actions` 的 `branch.spec.ts`（fork 子会话就地编辑后 timeline 仍可读，覆盖真实写路径）。
