# 临时接管上游对话 UI 的 client 半

状态：未销账（`@morlay/dsh-client-ui-conversation` 是官方 `ui-conversation` 行的**薄壳 fork**、由我们维护；
装配里官方该行 `disabled: true`，insert 我们的一对一行）

**现象**

对话外壳的改造点全在组件内部——粘贴决策与插入路径在编辑器与 InputBar 里、队列行自己算文本——而插件面只有
「整格 shadow keyed slot」，没有 wrap 上游组件的机制。所以这一行由我们接管，**我们是它的发布方**。

装配在 `bundles/better-session/cordis.patch.yml`：官方 `ui-conversation` 行 `disabled: true` + insert 我们的
`ui-conversation-fork` 行。`disabled` 停掉的是官方那行的装配（槽声明与渲染），它声明的全部 target-neutral
槽（`main.conversation` … `conversation.input.model`）由我们的 `client/apply.ts` 同形承担（`children` 既声明
子槽也授权 `renderSlot`）；槽、locale 命名空间与设置命名空间都与上游同名同形。上游已发布包反过来依赖 fork 的
槽面——`ui-subagent` 的 `conversation.content` 工厂、`ui-agent-preset` 的 `conversation.session.header.actions`、
`ui-open-in-app` / `ui-schedule` 的 `conversation.session.header.utilities`、`ui-sidebar-right` 的
`conversation.session.header.corner`——fork 少声明一个席位就静默失效。接线面（slots / locale / configForms
的订阅、固定快捷命令、提交埋点）与上游同形，由
[`upstream-wiring.spec.ts`](../../src/__tests__/upstream-wiring.spec.ts) 守着（漏跟随不会报错、只会静默少刷新）。

形态是**薄壳**：只复制我们**有意改过**的文件，其余上游文件不复制——保留文件里指向它们的 import 走相对路径指
向 `vendor/deepseek-harness/packages/client/ui-conversation/src/...`，构建时由 tsdown 内联进 `dist/client.cjs`
（发布物自包含，`files: ["dist"]`），开发态由 `dev-client-bundles` 现场打包。包级写法约束（根 `tsconfig.json`
保持 `composite: false`、合并接口只能一份实例、槽覆盖方式、`Context.input` 收窄带来的 `TS2717`）见
[本包规范 how-to-write](../standards/how-to-write.md)，测试口径见
[本包规范 how-to-verify](../standards/how-to-verify.md)。

保留文件共 11 个非测试源 + 6 个守护测试；同步上游时只按这张表保留我们的实现，其余文件不复制、直接引 vendor
源：

| 保留文件（`packages/session/ui-conversation/src/`）                 | 保留什么                                                                                                                                                                                                                                                                                                         |
| ------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `client/input/reference-text.ts`                                    | 纯逻辑：引用插入形态归一（`@` mention / `skill:` token）                                                                                                                                                                                                                                                         |
| `client/input/facade.ts`、`client/input/hub.ts`                     | `insertReference` 走纯文本、`restoreDraft` 收窄、scoped 事件归一（`referenceTextOf` / `insertTextOf`）、提交埋点（`submission-analytics`）                                                                                                                                                                       |
| `client/input/editor/runtime.ts`、`client/input/editor/span-map.ts` | chip 插入路径删除、纯文本引用装饰关闭（输入框保留 raw markdown，`@path` / `@dir/` 等高亮不再产生）、外部焦点与草稿选区不被后台协调拉回                                                                                                                                                                           |
| `client/queue/QueueDock.tsx`                                        | 仅**编辑 = 撤回**一处偏离：点编辑按钮 → `remove` 成功后 `restoreDraft` 原文（无确认）——上游自带 inline edit，我们采用「撤回该条到输入框」（撤回后能在完整输入框里带着上下文改）；呈现（`projectUserText(previewOf(...))` 行文本、折叠头、发送中行、动作门控）与样式（直接吃上游 `QueueDock.module.css`）都照上游 |

| `src/index.ts`（薄壳转出上游 host 入口）、`src/css-modules.d.ts`    | host 半整体转出 vendor；vendor 组件的 `*.module.css` ambient 声明                                                                                                                                                                                                                                                |

保留文件的守护测试 6 个在 `src/__tests__/`（落点与判据见[本包规范 how-to-verify](../standards/how-to-verify.md)）。

**决策点**：`ReferenceInsert.appearance` 的 `| 'skill'` 去掉（全仓库无生产者）；`contract/slots.ts` /
`contract/draft-editor.ts` 不保留——复制会让合并接口出现第二份实例（`TS2717`）。

**影响**

- 这些文件不再随上游升级自动收益：每次同步都要人工判定冲突并保留我们的实现；
- 上游 client 契约换代（如队列面改由 `inbox` 投影承载）时 fork 必须跟随——不跟随不是「不一致」而是功能静默
  失效；
- fork 面收敛到「逻辑 + 一处交互偏离」：UI（InputBar、QueueDock 的呈现与样式）走上游，所以 composer 座位
  高度、进而滚动面与上游同形；
- 装配缺口（`client/apply.ts` 的 slot 注册、`Context.input` 收窄）登记在
  [债务 对话UI客户端半的装配面缺测试辅助](../../../ui-conversation-message-actions/.agents/debts/20260917-对话UI客户端半的装配面缺测试辅助.md)。

**触发条件**

- 每次同步上游（`just vendor prepare`）都要处理保留文件的冲突，此时是回退评估的时机。同步口径：fork 的
  `src/` **不是**上游的逐字快照，按差异项逐条判定「有意偏离」还是「落后于上游」；与我们的改动冲突时**保留我
  们自己的实现**，不回退、不迁就上游当前形态；只有「上游已支持」或「我们不再需要偏离」才执行回退动作；回写
  粒度按能力项、不按文件；每次同步注明当时的 `DEEPSEEK_HARNESS_VERSION`（基线见根 `mise.toml`）。
- 上游具备下面四项能力中的任一项时，逐项评估回退（不必等四项齐全）：
  1. **编辑器内部的插入决策可插**（当前插入路径在编辑器与 InputBar 内部，没有槽）→ 「引用按预定形态归一后原
     样保留」可改由**引用源**返回 `PickOutcome.text`（官方 `ui-reference` 是唯一产 `insert` 的源）；
  2. **composer 草稿模型结构化**：`InputState` 暴露有序的「文本 / 引用 / 附件」块序列（当前是
     `draft: string` + `attachmentIds` + `occurrences`）→ 回退 `restoreDraft` 收窄与「插入降级为纯文本」；
  3. **组件级替换 / 子区域开槽**（当前只有整格 shadow，样式机制只有上游 CSS Modules）→ 输入外壳与队列行的
     呈现层走上游（样式吃上游 `.module.css`，不复制 `skeleton/InputBar`），剩下的只有「编辑 = 撤回」
     这一处交互偏离与编辑器装饰面；
  4. **队列行按 `content` 渲染——上游已支持**（`QueueDock` 用 `useProjection('inbox')` 并按内容块派生
     `preview` / `text`）：这一项的**呈现半走上游**，剩下的只有 `ReferenceMarkdown` 的 chip 渲染差异与下面
     刻意保留的「编辑 = 撤回」。
- 当前**未跟随**（不是遗漏）：上游的 inline edit 面（我们采用「编辑 = 撤回」）、`addFiles` 的「桌面拖入文件
  夹 / 宿主路径 → 生成 `@path` 引用」分支（新增能力，等真有需求）、工具生命周期与过程节点呈现（不在保留文
  件表内，只在槽面上接它们）。

**销账条件**

Done when：上面四项里至少一项被上游支持，且对应回退动作执行完（逐项销账，不要求四项齐全）——**第 4 项的
「编辑」半除外**：上游的 inline edit 我们不采用，「编辑 = 撤回该条到输入框」是刻意的体验选择（见保留文件
表），哪怕上游已支持也不回退：

- 删掉 `bundles/better-session/cordis.patch.yml` 里对应的 `disabled: true` 行与 insert 行；
- 删掉 `packages/session/ui-conversation` 及其在 profile 依赖树中的声明；
- 该 fork 期间产出的能力改为经上游扩展面承载。

现状：四项里第 4 项的呈现半已回退（见触发条件），第 1 / 2 / 3 项上游仍不具备（插入路径仍在编辑器与 InputBar
内部、`InputState` 仍是 `draft: string` + `attachmentIds` + `occurrences`、插件面仍只有整格 shadow）。

**不修的理由**

上游没有组件级扩展面（见「现象」），不接管就做不了输入框 raw markdown 与队列行渲染的改造；代价只在上游同步
时结算，可以承受。
