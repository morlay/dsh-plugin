## 结论摘要

| 议题       | 结论                                                                                         | 一句话理由                                                                                                                      |
| ---------- | -------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------- |
| 事件与坐标 | `t_events` 存完整事件（全局实体），`t_session_events` 存会话专属信息（稠密 seq + surfaceOp） | 一个事件行可被多个会话引用，fork 派生不必复制事件                                                                               |
| 写入       | 零转换：事件内容、seq、surfaceOp 原样落库                                                    | 与上游 JSONL 同构，读写天然同坐标                                                                                               |
| 读取       | 集中转换：格式 / surface 修复与 provenance 重算都在读取视图做，不落库                        | 存储行与 revision 在读取前后完全一致                                                                                            |
| 分支       | fork 是纯 append（复用事件行），rewind 直接截断桥接行                                        | 上游 `SessionHandle` 只有 append-only                                                                                           |
| 表结构变更 | 破坏性变更走 `SCHEMA_VERSION` 门禁，升级由 `drizzle/` 手写迁移执行                           | 生成器输出与实体定义对不上（[债务 20260921-drizzle生成器与实体定义对不上](../debts/20260921-drizzle生成器与实体定义对不上.md)） |
| 孤儿的家   | 无引用的事件行统一归 GC 通道回收，删除会话不清孤儿                                           | 事件行跨会话共享，单次删除注定为全库付费                                                                                        |
| 配置门面   | 配置就是这一行的 config，整段 `volatile`，改完由 Loader 重挂这一行                           | 后端只在装配时建一次连接，没有运行期重连逻辑                                                                                    |

## 事实基线

### 仓库结构

本包位于 better-session monorepo 的 `packages/session/session-rdb/`，是三层 cordis plugin 的**实现层**：
契约层 `@morlay/session-branch`（provider 抽象）→ 本包（实现）→ 编排层
`@morlay/ui-conversation-message-actions`（完整 rewind / retry / fork 功能）。

```
packages/session/session-rdb/
├── .agents/                     # 本包记录树（designs / adrs / debts / standards，`<YYYYMMDD>-<slug>.md`）
├── src/                         # 实现（entities / adapters / 双方言后端 / storage-takeover / testing …）
├── drizzle/{sqlite,postgres}/   # 表结构迁移，每个方言 9 个目录（手写，见上述债务）
├── tool/pg/                     # PostgreSQL 测试实例（compose + justfile）
├── locale/{en,zh}.json          # 插件清单文案
└── README.md                    # 门面（一句话定位 + 用法 + 链接）
```

装配声明不在本包：`cordis.patch.yml` 由 `@morlay/better-session` 的构建生成
（`packages/bundles/better-session/tsdown.config.ts`，禁用官方 `session-persistence-jsonl` /
`session-projection-cache` / `session-query-sqlite` / `storage-json` 并插入本包），本包只提供包出口。

### 坐标模型（单一稠密坐标）

**核心不变量：写路径零转换（忠实存储原始事件），读取集中转换（有据可查）。**

- `t_session_events.f_sequence` 是**稠密持久化 seq**：事件原样落库（与上游 JSONL 一致，无过滤无重编号），
  **连续递增、无空洞**（`src/entities/v3/session-events.ts`）。
- `t_events` 是**全局事件实体**，`f_data` 存**完整事件**（type/seq/time/data/ignorable 信封，与 JSONL
  每行同构）——忠实存储，读回时整体解析（`src/entities/v3/events.ts`、`rowToEvent` 在 `src/log.ts:97`）。
  不含任何 session 专属信息：一个事件行可被多个会话的桥接行引用（fork 派生会话复用父会话事件行，不复制）。
- session 专属信息（稠密 seq、surface 元数据 `surfaceOp`）全部在 `t_session_events` 桥接行上；
  `sourceEventSeqs` 不落库，读取时按需重计算（`src/log.ts:168`）。

### 核心不变量

1. **写路径零转换**：事件内容、surfaceOp 原样落库；写路径当前格式校验（`validateStoredEvents`）只拒绝
   未知类型（非 ignorable）与非法消息形状，不做坐标转换（[设计 写路径](20260917-写路径.md)）。
2. **上游 seq 与稠密 seq 恒等**：原样存储下事件 seq 即稠密 seq，写读天然对齐，无需坐标映射
   （[设计 写路径](20260917-写路径.md) / [设计 读路径](20260917-读路径.md)）。
3. **fork 坐标自洽**：fork 前缀经 `readLog` 读取视图（replace range 已是稠密坐标），重编号后子会话坐标
   与父稠密坐标数值相同，无需额外坐标重映射；子会话桥接行的 `f_sequence` 是**子会话自己的上游空间**
   （不复制父值，避免两段空间重叠）（[设计 分支能力](20260917-分支能力.md)）。
4. **rewind 保留区 range 完整性**：replace range 引用更早事件 ⇒ 截断尾部不破坏保留区 range
   （[设计 分支能力](20260917-分支能力.md)）。
5. **SCHEMA_VERSION 门禁**：破坏性表结构变更必须 bump；表结构级升级走 `drizzle/` 里的手写迁移
   （运行时 drizzle `migrate()` 执行），同版本内数据格式差异（含 surface 语义损坏）在读取 / 导出视图修复，
   不落库（[设计 表结构](20260917-表结构.md) / [设计 旧数据修复](20260917-旧数据修复.md)）。
6. **孤儿事件行由 GC 通道回收**：`deleteSession` 只落该会话的桥接行 / workspace 归属行 / 投影行 / 会话行，
   无引用的事件行成为孤儿，由 `POST /api/session.gc` 回收
   （[ADR-删除不再清孤儿与vacuum独立成gc通道](../adrs/20260918-删除不再清孤儿与vacuum独立成gc通道.md)）。

### 配置门面

- **配置就是这一行的 config**（聚合层 `@morlay/better-session` 的 `session-rdb` 行、profile patch，或设置页
  改的那份 entry config）。`path` 在 schema 上必填，装配默认值由 bundle patch 给：
  `!!js dshHomePath('sessions', 'sessions.sqlite')`
  （`packages/bundles/better-session/cordis.patch.yml`）。
- **判别式 union**：`type` 是各分支的常量字段（`sqlite` / `postgres`），页面据此给切换控件、host 侧校验
  也按它选支（`src/index.ts:531`）。`Config` **整段标 `.volatile()`**（`src/index.ts:595`；schemastery 不许在
  union 分支内部标 volatile）——host 的 `volatileForm` 因此会投影这一行，守卫在
  `src/__tests__/config-surface.spec.ts`。
- **默认值都在 schema 上**：`journalMode: wal`、`busyTimeout: 5000`、`schema: public`、
  `projectionCache` 默认 `{ writeEveryEvents: 200, writeIntervalMs: 5000 }`
  （`src/index.ts:90-91`、`src/index.ts:503-523`）；页面清空即回到这些默认。
- **生效方式**：装配时取一次快照（`this.config = config.get()`，`src/index.ts:629`），改配置由 Loader 重挂
  这一行——新实例、新快照、新连接（`src/index.ts:1532`）。因此**没有运行期重连逻辑**；换后端 = 换库，
  旧数据留在旧后端。

## 取舍

- **本包同时实现持久化与分支两面，而不是拆成两个包**：两面共用同一数据库连接与同一写路径（rewind 直达后端
  事务、fork 复用事件行），拆包只会在两者之间再插一层转发（[设计 分支能力](20260917-分支能力.md)）。
- **事件实体全局化而非按会话复制**：代价是写路径要处理「事件行已存在则复用」，换来 fork 不复制事件、
  同一事件多引用一致（[ADR-事件实体全局化与桥接行承载会话专属信息](../adrs/20260917-事件实体全局化与桥接行承载会话专属信息.md)）。
- **原样存储而非过滤 + 稠密重编号**：与上游 JSONL 语义一致、读写同坐标；代价是历史数据的旧形状要在读取视图
  逐类修复（[ADR-写路径零转换与原样存储](../adrs/20260917-写路径零转换与原样存储.md)）。
- **同版本内的数据差异用读取视图修复，不做原地数据迁移**：不破坏零转换，历史加载失败的会话也能导出
  （[ADR-旧数据导出即修复而非原地迁移](../adrs/20260917-旧数据导出即修复而非原地迁移.md)）。

## 开放问题

- 配置里 `path` 的装配默认值由 bundle patch 提供（`dshHomePath('sessions', 'sessions.sqlite')`）；不经过
  bundle 的裸装配必须自己给绝对路径，是否给本包加一个「默认落在 `$DSH_HOME`」的回落尚未定。
