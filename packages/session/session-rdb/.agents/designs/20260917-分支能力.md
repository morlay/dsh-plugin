# 分支能力（forkFrom / rewind）

状态：已实现
范围：本包分支能力的实现与不变量；契约面在 `@morlay/session-branch`，编排在
`@morlay/ui-conversation-message-actions`。

## 结论摘要

| 议题         | 结论                                                                                                  | 一句话理由                                                                                                                |
| ------------ | ----------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------- |
| 面           | `SessionBranchRdb` 实现 `@morlay/session-branch` 的 provider 抽象，构造时自动注册 `ctx.sessionBranch` | 与持久化共用同一连接与写路径，形成 rewind / retry / fork 闭环                                                             |
| fork 派生    | 纯 append：新 id + `parentSession` + `seedLength`，不触碰源会话                                       | 上游 handle 只有 append-only，派生本来就是追加一个新会话                                                                  |
| fork 事件行  | 复用源会话已有的事件行（全局实体），只插新桥接行                                                      | 复制事件行会让 fork 的存储代价与源会话长度成正比                                                                          |
| fork 坐标    | 前缀重编号后子会话 seq 与父稠密 seq 数值相同，无需重映射                                              | 稠密坐标 + 原样存储让两段空间天然对齐                                                                                     |
| rewind 落点  | 直接操作后端事务（删桥接行 + head 回退 + bumpRevision），绕过 handle 模型                             | 上游 `SessionHandle` 没有回退原语（[ADR-rewind绕过handle模型直接截断](../adrs/20260917-rewind绕过handle模型直接截断.md)） |
| rewind 读面  | 只读边界那一行的类型与尾部窗口的类型，不拉全量日志                                                    | 排他面（先停 loop 再截断），全量读 + 修复是白付                                                                           |
| 保留区 range | 截断尾部不破坏保留区 replace 的 range（数学保证）                                                     | replace range 只引用更早事件，保留区节点全部 `< toBoundary`                                                               |
| 配平         | rewind 只按尾部窗口配平；整段日志路径（fork seed / 导出 / 导入）前向自愈                              | 全量扫描不该出现在每次 rewind 上                                                                                          |

## 事实基线

本包在 `SessionPersistenceRdb`（handle 模型，append-only 面）之上实现 `SessionBranchProvider`（分支面：
`rewind` / `forkFrom` / `readBranchPrefix`），注册面在 `src/index.ts:634`，实现面在 `src/branch.ts`。

### forkFrom：纯 append + 事件行复用

- 读源会话（`readLog`）→ `locateTurnEnd` 定位闭合边界（`after` 包含目标轮 / `before` 排除目标轮）→ 取前缀；
- 前缀按**新会话 log 保序重编号**（`map((e, i) => ({ ...e, seq: i }))`）；
- **坐标无需重映射（关键论证）**：原样存储下事件 seq 即稠密 seq，前缀 `slice(0, boundary + 1)` 从父稠密
  seq 0 开始（稠密连续），重编号后子会话 seq 与父稠密 seq **数值相同**（0..boundary）——replace range 数值
  不变，`Session.create` 的 seed 校验（range 存在于 surface、provenance 的「引用更早事件」）天然成立。
- `create(childMeta)` + `append(childId, seed)` 走上游 handle——派生是纯 append（新 id / `parentSession` /
  `seedLength`），不触碰源会话；
- **事件行复用**：`t_events` 是全局实体，派生会话的桥接行直接引用源会话已存在的事件行（`f_event_id` 复用），
  **不复制事件行**——只插入 `t_session_events` 桥接行（新 `f_sequence` + `f_surface_op`）。轮次编号
  **延续**（`f_data` 完整保留 turn/step，复用事件行即延续），子会话后续 append 从边界处继续编号；
  **例外**：源会话是 legacy（读视图由迁移链重建，`storedCount` 与视图长度不等）时**复制事件行**——
  读视图的 seq 与存储行的 `f_sequence` 不是一回事，按 seq 复用会把桥接行挂到语义不符的行上（子会话前缀读出
  的内容与它自己的 seed 对不上），所以那种源会话宁可多写几行；复用映射的生命周期跟着「一次 append」：
  append **成功之后**才丢，fork 失败时显式丢弃（`dropReuseEventIds`，否则同一个 childId 之后的落写会复用
  父会话的事件行）；
- `seedSuffix`（调用方构造）按需追加；携带 `ignorable: true` 的事件**原样落库**（与 JSONL 一致），
  live 会话的内存 log 与 canonical log 一致。写侧不产出版本效果事件（`session-branch/version` 只出现在既有
  日志里，类型定义用于识别它）（[ADR-20260920-删除版本树投影并停止写版本效果](../../../session-branch/.agents/adrs/20260920-删除版本树投影并停止写版本效果.md)）。

#### fork 子会话的 f_sequence 语义

子会话桥接行的 `f_sequence` 是**子会话自己的上游空间**（重编号后的 0..n-1 及后续 append 的 n..），与父会话
无关——`f_data` 里的坐标在 fork 时已重编号到子空间，读取时 per-session 恒等自洽。**不复制父会话的
`f_sequence`**（复制会导致两段空间重叠、映射歧义）。

### rewind：绕过 handle 模型的直接截断 + 状态同步

上游 `SessionHandle` 模型只有 append-only，没有显式回退原语。rewind 直接操作后端事务：经 `internals()`
（暴露 `backend` / `writeGuard` 与便捷方法面）访问后端，不经上游 handle 面；live 会话的 write handle 经
`tracker.writerOf()` 取出（`src/branch.ts:335`）。

**调用方前置**：截断会重写 live 会话的内存 log，与运行中的 agent loop 并发会写穿边界，因此调用方必须先停止
loop（`cancel` + `whenIdle`）。会话编辑编排层（[ui-conversation-message-actions](../../../ui-conversation-message-actions/README.md)）
的三处 rewind 入口（edit / retry / reroll、recall、HTTP `rewind`）统一执行该停止；覆盖导入
（`session.import`）在 `persistImport` 的 rewind 前注入同一停止端口
（[编排层 ADR-20260917-rewind前主动停止运行中的loop](../../../ui-conversation-message-actions/.agents/adrs/20260917-rewind前主动停止运行中的loop.md)）。

rewind 直接操作后端事务的步骤：

1. **边界校验（有界读）**：`toBoundary` 落在存储 head 之内且是闭合 `turn/end`
   （或 `-1` 空前缀）；live 会话先落盘 write-behind 缓冲，保证后续读取与后端事务同视图。rewind 不走
   持久化抽象的全量读（`readLog` 会拉全部事件 + legacy 转换 + 读视图修复）：直连 DB，按
   `(session_id, f_sequence)` 只读**边界那一条的类型**（`getEventTypeAt`）与**尾部窗口的类型**
   （`getEventTypesBefore`，只取 `f_sequence` / `f_type`，窗口不够就翻倍重读，`src/branch.ts:454`）；
   只有 legacy（非当前格式）会话因持久化坐标与视图 seq 不一致，才回退到 `readLog` 路径
   （`src/branch.ts:347`）；
2. **事务内截断**：`deleteBridgeTail(toBoundary + 1)` + head 游标回退（`getPrevBridge` 或初始 `-1`）+
   `bumpRevision`——Abort 整体回滚。**只删桥接行**，事件行保留（全局实体，可能被其他会话引用）；
   截断进入继承前缀（或清空）时把 `f_seed_length` **收缩**到保留事件数（只收缩、不扩张）——否则存储出现
   「继承前缀超过存储事件数」的矛盾，上游 load 拒绝（见 [设计 旧数据修复](20260917-旧数据修复.md)）；
3. **更新 `WriteGuard` 确认 head**：下一次 append 的并发写入者校验以截断后 head 为基准；
4. **live 会话同步**：截断内存 log 并重置派生缓存（`truncateLiveSession`）、失效 `ctx.sessionProjections`
   的单元缓存（投影按 `observedSeq` 增量驱动，水位不回退会让截断后的重放事件被 `drive()` 跳过）、丢弃
   `ctx.tokenMeter` 对该会话的重放折叠（meter 只按 seq 前进，水位停在被删除的 seq 空间会让续写事件从错位处
   折叠——压缩测量报 `step/end` 无配对 `step/start`）、重置 agent 轮次游标、`resetAfterRewind()` 对齐 write
   handle 的 cursor 与继承前缀，最后强制 durable 取消 agent 的排队输入（`inbox.clear()`；落在保留区的
   pending 同样取消——否则 agent 会继续处理 rewind 已放弃的输入）。两个失效调用都做**能力探测**：服务缺失或
   其内部结构（投影的 `cells` / meter 的 `states` WeakMap）不符时记一条明确告警（每插件实例一次），
   不再静默跳过——上游改内部结构时这个失效不会无声失灵。覆盖导入（`persistImport` →
   `replaceLiveSessionLog`）复用同一钩子（`resetLiveDerivedState`）；
5. **刷新持久化投影检查点**（`ctx.sessionProjectionCache`）：rewind 不产生事件，缓存行（及其水位）仍停在
   截断前。超前行有两个危害：cold 读的 `restore` 虽会因「行超出日志末尾」丢弃它，但列表 hints 的零 I/O 读
   （`cachedSnapshot`）直接返回旧值，且客户端投影 store 的 higher-seq-wins 规则让 rewind 后的低 seq 正确值
   永远覆盖不上——表现为轮次导航残留已删除的旧轮次。live 用截断后的会话重写检查点（`write`，内存 cell 就在
   手边）；cold 没有 live 会话也**不 fold 日志**，改为按新水位**截断缓存行**（`truncateTo`：丢弃水位超出新
   head 的投影单元、保留仍在截断前缀内的行），重建交给下一次读路径。缓存是派生数据：刷新失败只记日志，
   不影响 rewind。

### 保留前缀的 step 配平（尾部窗口）

保留前缀必须满足上游 token-meter 的折叠不变量——每个 `step/end` 都要有同 `turn/step` 的未闭合
`step/start`。rewind 只按**尾部窗口**配平（`rewindKeepLength`：从 `rawKeepLength` 往回读类型，遇 `turn/end`
即停，尾部未闭合的 `step/start` 一并丢弃），**不扫全量日志**；保留前缀内部既有的破损（孤儿 `step/end`）
**不由 rewind 自愈**。整段日志的路径（`forkFrom` 的 seed 前缀、导出 `readRaw`、导入 `persistImport`）用
`balanceRewindPrefix` 前向扫描自愈：遇到首个不平衡事件（`step/end` 无配对、或 `step/start` 撞未闭合）就从
该事件起丢弃尾部（rewind / fork 各记一条明确告警）；导出与导入用 `{ keepOpenTail: true }` **保留合法的**
未闭合尾部（中断运行的正常形状，由上游 resume 补 closers，见
[ADR-未闭合轮次原样保留补closers由消费方负责](../adrs/20260917-未闭合轮次原样保留补closers由消费方负责.md)），
只对「已不平衡」自愈；导入时 `inheritedEventCount` 随修剪收缩。口径与 `assistant/message` 的内部孤儿不在
自愈范围（另一类失败模式）。

### 保留区 replace range 完整性（不变量）

replace 的 range 引用**更早事件**（上游契约：range `startSeq` / `endSeq` 必须存在于当前 surface，即已提交
节点，`vendor/deepseek-harness/packages/core/session/src/surface.ts:414`），故 `range.endSeq < replace.seq`。
rewind 只删尾部（`toBoundary + 1` 起），保留区 replace（`seq ≤ toBoundary`）的 range 内节点全部
`< replace.seq ≤ toBoundary`，**全部保留**——映射完整、`startSeq` / `endSeq` 存在、重计算 provenance 覆盖
成立。「保留区 replace 的 range 引用被删事件」在数学上不可能发生。torn tail 截断同理安全。

## 取舍

- **`rewind` 扩上游 handle 模型加回退原语**（否）：违反上游只读红线
  （[ADR-rewind绕过handle模型直接截断](../adrs/20260917-rewind绕过handle模型直接截断.md)）。
- **用 append 表达删除（tombstone 事件）**（否）：append-only 事件流无法表达截断，客户端增量同步会残留旧节点。
- **fork 复制事件行**（否）：源会话是 legacy 时才不得不复制（读视图 seq 与存储 `f_sequence` 不同源），
  当前格式下复用事件行既省存储又保一致
  （[ADR-事件实体全局化与桥接行承载会话专属信息](../adrs/20260917-事件实体全局化与桥接行承载会话专属信息.md)）。
- **rewind 拉全量日志再截断**（否）：rewind 是排他面（调用方已停 loop），全量读 + legacy 转换 + 读视图修复
  是白付；有界读只取边界与尾部窗口的类型。
- **rewind 全量扫描配平保留前缀**（否）：破损前缀的自愈交给整段日志路径（fork seed / 导出 / 导入），
  rewind 只在尾部窗口内保证折叠不变量。

## 开放问题

- rewind 是 rdb 特有的直接截断，**未与 handle 模型的 per-id 串行链互斥**（那条链无法从外部访问）；文档要求
  对 cold 会话调用（无 live owner、无 in-flight append）。多实例共享数据库时 rewind 与并发 append 的交错由
  事务 + head 校验兜底，跨实例的排他协调未做。
- 保留前缀内部既有的破损（孤儿 `step/end`）不由 rewind 自愈，是否要扩到「保留区也扫一遍配平」取决于
  是否有真实数据撞上。
