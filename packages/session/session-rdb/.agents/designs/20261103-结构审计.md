# 结构审计：模块形状与文件划分

状态：已执行（2026-11-03，B1-B6 全部落地；执行结果见文末）

范围：`packages/session/session-rdb/src/`（审计时全量 18290 行；生产代码约 8.1k，测试 9.1k，测试夹具 1.1k）。
判据：`codebase-design` 的词汇——模块 / 接口 / 深度 / 接缝 / 适配器 / 杠杆 / 局部性。

本审计由三份独立只读审计交叉合成（模块形状、重复与散落、rdbkit 依赖面），数字均经 `wc` / `grep` 复核；
冲突处以复核结果为准。

## 模块形状

### `index.ts`：浅接口 + 超深实现

契约接口（`SessionPersistence` 的 8 个方法）本身是深的，实现里却混了八类互不相关的职责：

| 主题         | 行区间    | 行数 |
| ------------ | --------- | ---- |
| 配置 schema  | 484-570   | ~90  |
| 写者登记     | 154-266   | ~110 |
| 会话句柄     | 268-482   | ~215 |
| 服务实现     | 503-1472  | ~970 |
| live 路由    | 1328-1488 | ~160 |
| 统计折算     | 1502-1539 | ~38  |
| 写批次       | 1546-1629 | ~84  |
| 错误类型     | 139-152   | ~14  |

目标：句柄 / 写者登记 / live 路由 / 统计折算出栈，`index.ts` 只剩装配与契约实现。

### `backend-rdb.ts`：一个适配器 + 6 个直通

905 行里 6 个读方法（`getSession` / `getEventRows` / `getEventTypeAt` / `getEventTypesBefore` / `listSessions` /
`listOrphanSubagentSessions`）是 `#readModel` 的同名转发，`BackendTx` 的 14 个方法又只有 `branch.rewind` 与
写路径在用。目标：读路径直接依赖 `ReadModel`，`Backend` 收到 12 个方法以内。

### `branch.ts`：五个主题

分支语义（26-90 纯函数）、live 日志编辑（92-223）、provider（224-515）、poke 上游投影/计量注册表（538-581）、
以及 `SessionBranchRdb` 的装配。目标：`branch/{port,semantics,live-log-edits,provider}.ts`，
其中 `port.ts` 用 7 个动词替代 12 成员的 `internals()`。

### `log.ts`：五个主题、23 个导出、9 个零生产引用

行映射（23-150）、读视图修复（152-628，20 个函数）、JSONL 导出（629-706）、用量行（707-769）。
对外真正需要的只有 5 个动词：`repairReadView` / `needsShapeAdoption` / `sealOwnEvents` /
`normalizeToCurrentShape` / `orphanInboxSeqs`；其余 18 个导出应收回实现。

### `session-ops.ts`：fan-in = 1

444 行、16 个导出，只被 `backend-rdb.ts` 使用；其中 221-391（171 行）是纯算术的用量折算，与 SQL 读操作不同源，
应拆到 `stats-fold.ts`（纯函数、可单独测）。

### `storage-takeover/`：三个不同层挤在一个目录

`repository.ts`（332）里真正的 storage 接管只占约 110 行；`projection-cache.ts`（441）是一个 cordis Service；
`read-model.ts`（204）是会话读模型。目标：域存储、投影缓存、读模型各归自己的目录（见下面的目标结构）。

## 重复与散落（局部性）

1. **事件行形状 6 个 home**：`entities/v3/events.ts`（权威）、`backend.ts` 的 `EventRow` / `EventInsert`、
   `index.ts` 的写批次字面量、`backend-rdb.ts` 的插入映射、`read-model.ts` 的投影与 `eventRowOf`、
   `log.ts` 的 `rowToEvent`。桥接行的 4 字段匿名类型写了 3 遍。
2. **会话行形状 7 个 home**：「新建会话行」有两份字面量（`log.ts` 的 `sessionInsertColumns` 与
   `storage-takeover/repository.ts` 的 `insertIgnore`），后者字段集不同（没有 `f_agent_preset`）。
3. **用量折算 5 处**：`usage.ts`（口径与加总）、`index.ts`（桶构造）、`session-ops.ts`（SQL 聚合）、
   `backend-rdb.ts` 的 `usageReport`（又把 `addToken` / `addActivity` / `emptyTotals` 手写了一遍）、
   `backend-rdb.ts` 的回填（`countIf` 版）。本地日有两套口径（`localDayKey` 与 `E.localDay`），只靠注释对齐。
4. **「已物化」3 个判据**：句柄的 `materialized` 标志、`session-ops` 的 fail-loud、`repository` 的
   `f_head_sequence >= 0`。撕裂尾部的**判定**只有一处（`scanRows`），**处置**写了两遍。
5. **HTTP 样板**：6 个文件各写一遍 webServer 内联类型（10 行）、connection 内联类型（5 行）、鉴权块、500 块；
   `content-type: application/json` 合计 31 处；`import.ts` 缺 405。

## 目标结构

原则：按「变化的理由」切，不按「层」切；每个模块 ≤ 400 行，接口 5-8 个动词，接口里不出现 `Backend` / `Database` /
行形状。

```
src/
├── index.ts            装配 + SessionPersistence 实现（< 400 行）
├── handles.ts          句柄 + 写者登记（acquireWrite / adoptRead / writerOf / release / flushAll / closeAll）
├── write-path.ts       materializeEmpty / appendBatch / truncateTail / materializeRewind / recordStats
├── read-path.ts        readLog / readRaw / readStoredRevision / readTailWindow / rewriteIfMigrated
├── live-routing.ts     install / onEvent / onFlush / onDisposed / drainAll
├── stats-fold.ts       countBuckets / usageBuckets / addTotals / emptyTotals / localDayKey / resolveSince
├── deletion-error.ts   叶子（打破 index ↔ deletion 的运行时环）
├── log/
│   ├── rows.ts         行 ↔ 事件映射 + 插入列（唯一 home）
│   ├── repair.ts       读视图修复（对外 5 个动词）
│   ├── export.ts       scanRows / toJsonlArtifact / titleOfEventData
│   └── usage-row.ts    usageRowOf / EventUsageRow
├── branch/
│   ├── port.ts         7 动词（替代 internals()）
│   ├── semantics.ts    纯函数（locateTurnEnd / assertBoundary / renumber / keepLength）
│   ├── live-log-edits.ts
│   └── provider.ts
├── http/               一个注册口 + route() 助手，6 个路由文件只留业务
├── storage/            域记录 + 投影检查点（两个小接口，不是一个 14 方法的接口）
├── projection/         投影缓存服务（只留 Service 生命周期与快照视图）
├── db/                 backend（RdbBackend）+ open + read-model
├── artifact/           JSONL / zip 导入导出
└── entities/ testing/ routes.ts / version.ts / event-shape.ts / write-guard.ts   （不动）
```

## 执行批次

每批可独立回滚、可 grep 验收。前两批零行为变化。

### B1 纯搬移

拆 `log.ts` 为「行映射 / 读视图修复 / 导出 / 用量行」四个模块；拆 `branch.ts` 的纯函数部分为分支语义模块；
`index.ts` 的统计折算 + `session-ops.ts` 的用量算术 → `stats-fold.ts`；`SessionDeletionError` → 叶子模块。

判据：读视图修复模块的导出 ≤ 5（现 23）；`deletion.ts` 不再从 `index.ts` 值引入（运行时环 = 0）；
测试零改动全绿（唯一允许的例外：`__tests__` 里 6 处直接调用 `log.ts` 内部步骤的改为经 `repairReadView`）。

前提：`package.json` 的 9 个子路径出口（`index` / `artifact` / `storage` / `testing` / `usage` / `deletion` /
`export` / `gc` / `import`）不能动，已有跨包消费 `/artifact` 与 `/testing`。
`migrations.ts` 同时指向迁移与 storage，所以「拆迁移」与「拆 storage」必须同一提交。

### B2 收窄接缝、删死接缝

`internals()` → 分支端口模块（12 → 7 动词）；删 `injectedBackend`；`tracker` 转私有；
`SessionDeletionError` 的消费方改从叶子导入。

判据：`grep -rn "injectedBackend" src/` = 0；`internals()` 成员 ≤ 7 且不含 `Backend` / `WriteGuard`；
`branch/` 下不再出现 `SessionPersistenceRdb`；跨包 6 处 `internals()` 调用改走公开测试辅助。

### B3 live 路由出 index

`install(ctx)` 收口 5 个订阅与 4 张 live 表。

判据：`index.ts` ≤ 1300 行；`grep -c "liveBuffers\|liveReady\|liveFailures\|liveDropWarned" index.ts` = 0；
`live-routing.ts` 导出 ≤ 6 且不 import `branch/`。

### B4 句柄与写者登记出 index

判据：`index.ts` ≤ 950 行；`grep -c "RdbSessionHandle\|RdbBackendTracker\|PendingSession" index.ts` = 0。

### B5 收窄 `Backend`（唯一有行为风险，最后做）

删 6 个 `ReadModel` 直通；`BackendTx` 14 → 9；`branch.rewind` 改调 `write-path.materializeRewind`。

判据：`Backend` ≤ 12 个方法；`backend-rdb.ts` ≤ 700 行；`grep -n "return await this.#readModel" backend-rdb.ts` = 0；
两方言仍无 SQL 文本。

### B6 HTTP 收敛（可与 B3/B4 并行）

一个注册口 + `route()` 助手（鉴权 / JSON / 405 / 500），6 个文件只留业务。

判据：6 支路由用例零改动全绿；`grep -rc "content-type" http/` 合计 ≤ 8；`import.ts` 补上 405。

## 审计期间已修的缺陷

- `sum(bigint)` 在 PostgreSQL 上返回 `numeric`（驱动给字符串），与声明的 `number | bigint` 不符：
  rdbkit 的 `sum()` 在 PG 侧 cast 回 int8，并加了 PG 用例（见 [rdbkit 文件内分层](../../../../kit/rdbkit/.agents/designs/20261103-文件内分层.md)）。

## 不做

- 不删 `Backend` 再另造抽象：直接收窄到 12 个方法；`backend.ts` 是纯类型枢纽，不拆。
- 不动 `entities/`、`routes.ts`、`StorageRepositoryHost`——这三处是全包形状最正确的地方。
- 不为拆文件而拆文件：每个新模块要么有独立接口，要么是纯函数，否则留在原处。
