# 读路径流程（load / readFrom）

状态：已实现
范围：读路径的流程与规则——`readLog` 的两条分支（严格迁移链 / 回退视图）、读取视图修复与校验顺序；
写路径见 [设计 写路径](20260917-写路径.md)，旧数据的特征与修复策略见 [设计 旧数据修复](20260917-旧数据修复.md)。

## 结论摘要

| 议题             | 结论                                                                                                      | 一句话理由                                                      |
| ---------------- | --------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------- |
| 读取姿态         | 原样存储、原样读取：事件 seq 即稠密 seq，无坐标映射                                                       | 不变量见 [设计总览](20260917-设计总览.md)                       |
| 修复与校验的顺序 | `repairReadView` 先于 `validateStoredEvents`                                                              | 越界 replace 的 range 会被上游校验 fail loud，必须先夹取 / 降级 |
| 修复的作用域     | 只作用于读取视图，不落库（存储行与 revision 前后一致）                                                    | 与「写路径零转换」同一不变量                                    |
| 修复的溯源       | replace 的 `sourceEventSeqs` 优先取紧邻 metering 的 `shadowedSeqs`（权威），无 metering 时回退 range 扫描 | range 只是首尾边界对，压缩竞态下可能漏掉并发落地的节点          |
| 一条读取路径     | `load` / `open("read")` / `handle.read` 共用同一遍 `readLog`                                              | 最贵的读只付一次                                                |
| suffix 读        | `readFrom` 只取尾部事件、不重放 surface，也不补 provenance                                                | 没有 surface 上下文可重算                                       |
| 崩溃尾部         | last `turn/end` 之前的缺陷拒绝；之后的缺陷容忍为 torn tail（写 append 时物理截断）                        | 崩溃留下的半截轮次不该让整个会话打不开                          |
| 未闭合轮次       | 无 `turn/end` 的尾部**原样保留**，不补合成 closers                                                        | 补 closers 是消费方（Session 恢复 / agent-loop resume）的职责   |
| 混合世代 log     | `isLegacyVersion` 先走严格迁移链，链拒绝则回退为当前格式视图                                              | 旧写入器跨版本追加过的 log 不是任何单一已发布格式               |

## 事实基线

### 读取管线

```
readLog（src/index.ts:984）
  │
  ├─ isLegacyVersion(f_version < SESSION_FORMAT_VERSION)（src/legacy.ts:73）
  │    ├─ convertLegacyRows：严格迁移链（v0→v1→v2→v3→v4，子会话证据声明为空，src/legacy.ts:52）
  │    └─ 链拒绝 → adoptLegacyRows：回退为当前格式视图（字段级归一，src/legacy.ts:77）
  │
  └─ 当前格式（含版本号不可信的行）
       ├─ scanRows：崩溃尾部语义（last turn/end 切割、torn tail 截断，src/log.ts:666）
       └─ needsShapeAdoption 命中 → adoptLegacyRows（在扫干净的边界之内按内容再判一次，src/log.ts:559）

调用方（load / open / handle.read / readRaw）紧接着：
  repairReadView（src/log.ts:581）→ validateStoredEvents
  ├─ repairAssistantSettlement：assistant/message|attempt 缺 `stream` 补 `[]`
  ├─ repairRequestHeaders：旧格式 request/header 归一为当前格式（省略 `system` / 空 `tools` / 空 `adapterDefaults`）
  ├─ renameLegacyPtcEvents：v2 时代 PTC 词汇归一（`tool/code-dispatch-*` → `tool/ptc-dispatch-*`、
  │   `tools-code-mode` → `tools-ptc`、agent preset `code` → `ptc`）
  ├─ repairSurfaceOps：非法 replace 降级 append；end 落在旧坐标空间的 replace 按紧邻 metering 的
  │   shadowedSeqs 数量夹取到当前 surface 的同长区间；缺 surfaceOp 补标记；非 surface-eligible 清掉
  ├─ syncMeteringRanges：紧邻 replace 的 metering 事件 `shadowedRange` / `shadowedSeqs` 与该 replace 的
  │   稠密 range 不一致时重写
  ├─ recomputeReplaceProvenance：replace 的 sourceEventSeqs 重算（优先 metering 的 shadowedSeqs）
  └─ repairOrphanInboxSplices：孤儿 inbox splice 改写为 no-op
```

### 规则

- **原样存储、原样读取**：事件 seq 即稠密 seq，无坐标映射（不变量与坐标模型见
  [设计总览](20260917-设计总览.md)）。
- **修复先于校验**：`open` / `load` / `handle.read` 在 `validateStoredEvents` 之前应用 `repairReadView`
  （`src/index.ts:718`、`src/index.ts:1243`）。旧写入器重编号事件后，桥接行里的 replace range 可能仍落在旧坐标
  空间（`end` 远大于自身 seq），而上游以「startSeq and endSeq must reference earlier events」fail loud
  （`vendor/deepseek-harness/packages/core/session/src/surface.ts:414`）——夹取 / 降级必须在校验看到它们之前
  完成，否则历史会话无法加载。
- **一条读取路径**：`load` 的语义是「读一次完整快照」，直接 `readLog` + `repairReadView` + `validateStoredEvents`
  （`src/index.ts:1221`），与 `open("read")` / `handle.read` 走同一遍读；未落库的 live 会话没有磁盘视图，
  按 detached 口径返回空日志（`src/index.ts:1231`）。
- **surface 事件判据用上游同一份集合**：`repairSurfaceOps` 的「缺标记补 `append` / 非表面事件清掉」按上游
  `SURFACE_EVENT_TYPES`（`…/core/session/src/surface.ts`）判，含 `developer/message`（上游 agent-loop 在工具集
  增删时写的模型可见通知）。本地少一类会让它合法的 `surfaceOp` 被当非法清掉，`validateStoredEvents` 随即以
  「is surface-eligible and requires a surfaceOp marker」拒绝整条会话；同一集合还决定 replace 的溯源节点集，
  漏项会把覆盖到它的 replace 降级成 `append`（`src/log.ts:130`）。
- **修复的溯源一次建索引**：`repairReadView` 里 replace 的 `sourceEventSeqs` 与 metering 的 `shadowedSeqs`
  共用一份升序 surface seq 索引（range 用二分取切片，`src/log.ts:143`、`src/log.ts:152`），不每个 replace
  各扫一遍全量事件；前提是输入按 seq 有序（`readLog` 与 live snapshot 都如此）。
- **suffix 读取（`readFrom`）不补 provenance**：suffix 读只取尾部事件、不重放 surface
  （`src/index.ts:1261`），没有 surface 上下文可供重算。
- **replace 的 provenance 采用权威 shadowedSeqs**：`shadowedRange` 是 surface 位置跨度（首尾节点 seq），
  不是数值区间——压缩竞态下并发落地的节点可能落在 range 数值区间之外，range 扫描会漏掉它们，上游 provenance
  硬校验报 missing（`assertSourceEventReferences`，`…/core/session/src/surface.ts:543`；缺节点报
  `must include every shadowed surface node`，同文件 `:367`）。紧邻 metering 事件的 `shadowedSeqs` 显式列出
  全部被遮蔽节点，是权威来源；无 metering 事件时（历史数据 / 非压缩 replace）回退 range 扫描。
  `syncMeteringRanges` 只在 metering 与 replace 的 range 已经不一致时改写（旧坐标残留），当前写入器的权威
  `shadowedSeqs` 因此原样保留（`src/log.ts:381`、`src/log.ts:168`）。
- 读取结果 seq 稠密连续 → `ctx.sessions.create(id, { seed })` 直接通过上游 contiguous-from-0 校验，
  后续 append 从稠密 cursor 继续。
- 崩溃尾部语义：last `turn/end` 之前的缺陷（unparsable / seq gap）拒绝；之后的缺陷容忍为 torn tail
  （`tornFrom` 标记；物理删除在下一次写 append 时执行——写打开记下 `tornTruncateTo`（`src/index.ts:757`），
  该次 append 落库时先截断并重写 head（`src/index.ts:949`））。
- 未闭合轮次（无 `turn/end`）**原样保留**：持久化层不补合成 closers
  （[ADR-未闭合轮次原样保留补closers由消费方负责](../adrs/20260917-未闭合轮次原样保留补closers由消费方负责.md)）。
- **混合世代 log 回退**：`f_version < SESSION_FORMAT_VERSION` 的会话先走上游迁移链；迁移链拒绝（旧写入器跨
  上游版本追加、log 不是任何单一已发布格式）时回退为当前格式视图（header 版本归一 + 字段级归一），旧类型
  （`assistant/chunk` 等）仍由 `validateStoredEvents` fail-loud 拒绝
  （[设计 旧数据修复](20260917-旧数据修复.md)）。

## 取舍

- **校验前不修复、让历史会话直接报错**（否）：上游的 range / provenance 硬校验是对当前格式的正确要求，
  但它看的是旧坐标残留；不修复等于放弃这些历史会话，而 `readRaw` 导出也走同一路径，用户连导出都拿不到。
- **把修复结果落库（读取时顺手改写）**（否）：破坏零转换，且读取路径变成写路径的一部分——多实例下同一个库
  会被不同实例按各自视图改写。
- **replace 的 provenance 用 range 扫描**（否）：`shadowedRange` 只是首尾节点对，压缩与并发落地交错时漏节点，
  上游 provenance 校验直接拒绝。
- **读取时补合成 closers 让尾部看起来完整**（否）：合成事件没有上游 seq，每次 load 都要幂等重算，
  而且会把「运行中被中断」与「正常结束」两种形状抹平
  （[ADR-未闭合轮次原样保留补closers由消费方负责](../adrs/20260917-未闭合轮次原样保留补closers由消费方负责.md)）。

## 开放问题

- `readFrom` 的 consumer 目前不接受 provenance，若将来出现需要 surface 上下文的尾部读者，得让它改走完整读
  或显式带上 metering 上下文，形态未定。
