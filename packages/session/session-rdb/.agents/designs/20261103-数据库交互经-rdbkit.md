## 结论摘要

| 议题     | 结论                                                                    | 一句话理由                                             |
| -------- | ----------------------------------------------------------------------- | ------------------------------------------------------ |
| 交互面   | 本包只调 `Database` 的表句柄与 `E.*` 表达式，源码里不出现 SQL 文本       | SQL 是 rdbkit 的实现细节；散在业务包里就有第二份真相   |
| 后端实例 | 只保留 `RdbBackend` 一个实现（SQLite / PostgreSQL 同一个类）            | 原先两套同类实现语义漂移，同一件事要改两遍             |
| 行构造   | 直接用表定义的列名构造行；没有 camelCase → snake_case 的魔法映射         | 魔法映射会静默丢掉拼错的列，显式映射才受类型检查       |
| 装配     | 构造期只记配置，`init()` 里打开后端；取用方拿「打开后才有值」的读取口    | 不再需要 `Proxy` 把同步取值伪装成可用                  |
| 测试     | 同步句柄与临时 PG 库都来自 `@morlay/rdbkit/testing`                     | 驱动能力留在 rdbkit，本包不为测试依赖 `pg` / `node:sqlite` |

## 事实基线

后端只有 `src/backend-rdb.ts` 一处接触 `Database`：读模型（`storage-takeover/read-model.ts`）、会话读的小操作与
统计（`session-ops.ts`）、域存储（`storage-takeover/repository.ts`）、旧表搬运（`migrations.ts`）都从它拿到句柄。

统计回填 / 重算、用量引用标记、活动计数都只是「表句柄组合 + `select(...).toFragment()` 交给
`insertFromSelect`」；方言相关的部分（本地日、JSON 提取、条件计数、库身份）全在 rdbkit 的表达式与库级方法里。

## 决策与理由

### 方言相关的东西必须下沉，不能在本包里写字符串

迁移到 rdbkit 之后，本包里还留着四处方言分支：统计回填 / 重算的两条 `SELECT`、用量引用标记的 `EXISTS`、
本地日与 JSON 提取、库身份 `PRAGMA`。它们都以「SQLite 一份、PostgreSQL 一份」的形式出现——正是 rdbkit 要
收掉的东西。现在本包只表达语义（`E.localDay` / `E.jsonText` / `E.countIf` / `E.add(列, E.excluded(...))`、
`database.sqlitePragma` / `vacuum` / `objectNames`），渲染归 rdbkit。

### 只留一个后端实现

`SqliteBackend` 与 `PostgresBackend` 曾各写一遍同样的读模型与写事务（同一个语义两份代码），方言差异只有
表达式与几处 `VACUUM`。合并成 `RdbBackend` 之后，`kind` 只用于身份串与打开配置，读写路径共用一份。

### 装配顺序：先拿到后端，再装接管

`SessionPersistenceRdb` 在构造期只记下配置，`init()` 里 `await openRdbBackend(config)` 拿到后端；storage
接管与投影缓存拿到的是「打开后才有值」的读取口（`() => Promise<StorageRepository>`），分支能力先
`await internals().ready`。这样就没有「同步拿一个还没打开的对象」的伪装。

### 行为差异跟着 rdbkit 的约定走

64 位整数（`bigint` ↔ BigInt）、聚合的 `number | bigint`、`GROUP BY` 用列而不是参数化表达式、upsert 赋值的
列名要带表名——这几条都是 rdbkit 的边界，理由与验证见
[设计 能力与方言边界](../../../../kit/rdbkit/.agents/designs/20261103-能力与方言边界.md)。

## 验证

- 本包 `src/__tests__/`（含 `usage.spec.ts` 的统计、`rdb.spec.ts` 的初始化回滚、`multi-session.spec.ts` 的并发）
  全绿；两个方言共用同一个后端实现，所以契约与接管用例只在 SQLite 上跑，不按方言重复测。
- `grep -rn "SELECT \|fragment(\|raw(\|E.expr(\|PRAGMA" src --include=*.ts` 在本包只剩注释。
- PG 的方言能力（`PRAGMA` 库身份、`objectNames`、`VACUUM`、聚合的 int8、JSON 提取、本地日、事务串行与保存点）
  由 rdbkit 自己的用例覆盖，见[设计 能力与方言边界](../../../../kit/rdbkit/.agents/designs/20261103-能力与方言边界.md)。
