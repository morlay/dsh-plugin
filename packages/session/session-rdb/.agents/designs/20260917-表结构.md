# 表结构（t_ 语义表与 schema 升级）

状态：已实现（SCHEMA_VERSION = 3）
范围：本包的数据表设计与 schema 升级策略；同版本内的数据格式修复见
[设计 旧数据修复](20260917-旧数据修复.md)。
约束：改表先动 `src/entities/` 的纯定义（DDL 由适配器生成），迁移手写进 `drizzle/`。

## 结论摘要

| 议题           | 结论                                                                                  | 一句话理由                                                                                                                      |
| -------------- | ------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------- |
| 命名与实体     | 表 `t_` / 列 `f_` 前缀；实体在 `src/entities/` 纯定义，双方言 DDL 由适配器生成        | 一份方言无关描述喂两个后端，无手写建表 DDL                                                                                      |
| 主键与关联     | 键列外各表另带 `f_id` serial；多表关联一律走业务键                                    | 多实例共享库时只有业务键可寻址，不为不可达查询维护额外索引                                                                      |
| 破坏性变更     | bump `SCHEMA_VERSION` + `drizzle/` 里手写迁移                                         | 生成器输出与实体定义对不上（[债务 20260921-drizzle生成器与实体定义对不上](../debts/20260921-drizzle生成器与实体定义对不上.md)） |
| 同版本数据差异 | 读取 / 导出视图修复，不落库                                                           | 保住「写路径零转换」，历史加载失败的会话也能导出                                                                                |
| header 列      | 上游 `SessionHeader` 加字段 → 同时加列 + 加迁移                                       | 列式存 header，少一列字段静默消失（读回 `undefined`，消费方按缺失处理）                                                         |
| 1:1 的状态     | 不拆表：归档在 `f_archived_at`、钉住在 `f_pinned_seq`、标题在 `f_title`/`f_title_seq` | 三者都与会话行一起查询，拆表只多一层 join                                                                                       |
| 统计读侧       | 三张可销毁重建的派生表，读侧维度写入时物化                                            | 查询不做 `EXISTS`、不回连事件表（[ADR-统计衍生表物化归属与汇总](../adrs/20260923-统计衍生表物化归属与汇总.md)）                 |

## 事实基线

### 命名与实体

**实体在 `src/entities/` 纯定义**（每张表一个文件，方言无关；无任何实现逻辑），SQLite（`sqliteTable`）与
PostgreSQL（`pgTable`）的 drizzle 表对象以及建表 DDL 由 `src/adapters/` 从这些实体转化生成——无手写 DDL；
表结构级升级走 `drizzle/` 里的**手写**迁移（`src/entities/index.ts` 导出 `sqliteTableDefs` /
`postgresTableDefs`，`src/schema.ts:11` 起按它建表对象）。

除键列外各表另带 `f_id` serial 自增主键，例外是：单例表 `t_persistence_state` / `t_workspace_state`
（以 `f_singleton` 为键）、键值表 `t_schema_meta`（以 `f_key` 为键）、storages 域版本账本
`t_storage_units`（以 `f_name` 为键），以及三张派生统计表（见下「派生统计表」：`t_event_usage` 以
`f_event_id` 为键，两张会话汇总表以业务唯一键为键）。**多表关联一律用业务键、不用 `f_id`**。

### SCHEMA_VERSION 与升级

- `SCHEMA_VERSION = 3`（`src/schema.ts:5`）是**破坏性变更门禁**：表结构变更（列增删、列语义变化）必须 bump。
- SQLite 侧 `openDatabase` 接受空库 / v2 / 当前版本，其余拒绝打开；v2 先把 v2 baseline 标记为已应用、
  只执行 v3 之后的 diff（`src/sqlite.ts:359`、`src/sqlite.ts:286`、`src/sqlite.ts:316`）。
- 表结构级升级由 `drizzle/{sqlite,postgres}/` 里的迁移承担（每个方言 10 个目录，**手写**），运行时经 drizzle
  `migrate()` 执行（`src/sqlite.ts:288`）。
- 同版本内的数据格式差异（含 surface 语义损坏）在**读取 / 导出视图**修复，不落库
  （[设计 读路径](20260917-读路径.md) / [设计 旧数据修复](20260917-旧数据修复.md)）。

### PostgreSQL schema 配置

PG 后端支持 `schema` 配置（默认 `public`，`src/index.ts:577`）：

```yaml
session-rdb:
  type: postgres
  connectionString: postgres://user:pass@host:5432/db
  schema: sessions # 显式 schema，默认 public
```

- 表对象经 `toPostgresSchema(tableDefs, schema)` 构建，表名与 DDL 都**显式 schema 限定**
  （`src/postgres.ts:120`、`src/postgres.ts:849`），不依赖 `search_path`。
- schema 必须已存在（或连接角色可创建）；后端不自动创建。
- `identityBase` 含 schema（宿主 + 库 + schema），不同 schema 的写事务队列与 store 身份都不共享
  （`src/postgres.ts:95`、`src/postgres.ts:197`）。

**`SessionHeader` 的列要跟着上游字段走**：列式存的 header 少一列字段就静默消失（读回来是 `undefined`，

`src/__tests__/multi-instance.spec.ts`（跨实例读回 header）。

### 事件实体表（全局，忠实存储原始事件）

### 会话桥接表（session 专属信息）

**`t_session_events`** — 会话 ↔ 事件桥接：

| 列             | 类型                                          | 说明                                                                      |
| -------------- | --------------------------------------------- | ------------------------------------------------------------------------- |
| `f_id`         | serial PK                                     | 自增主键（仅存储内部）                                                    |
| `f_session_id` | text FK → `t_sessions.f_session_id` (CASCADE) | 会话                                                                      |
| `f_event_id`   | text FK → `t_events.f_event_id` (CASCADE)     | 事件实体（可被多会话引用）                                                |
| `f_sequence`   | integer                                       | **稠密持久化 seq**（连续递增、无空洞；原样存储下即事件 seq）              |
| `f_surface_op` | text                                          | surface 元数据（`append` / `replace`，JSON 文本；非 surface 事件为 NULL） |

表级约束：`UNIQUE(f_session_id, f_sequence)`（自动建唯一索引，覆盖全部访问模式：按 session 过滤 +
按 seq 范围 / 排序 / 取尾）。

**孤儿事件行**：rewind / torn-tail 截断只删桥接行，无任何桥接行引用的 `t_events` 行成为孤儿（事件实体全局
共享）。删除会话也**不**清孤儿（跨会话引用不可知，多实例共享数据库时尤甚），清理统一归 GC 通道
（`src/gc.ts`，全库扫描 + vacuum 分开跑，见
[ADR-删除不再清孤儿与vacuum独立成gc通道](../adrs/20260918-删除不再清孤儿与vacuum独立成gc通道.md)）。

### storages 接管表（workspace 与 schedule 两域、投影 checkpoint）

`$DSH_HOME/storages` 的这几份数据由本包接管（见
[ADR-接管storages到rdb语义表](../adrs/20260917-接管storages到rdb语义表.md)）：官方 `storage-json` 与
`session-projection-cache` 由 bundle patch 禁用，数据落在与事件日志同库的表中。

| 表                        | 键                                     | 说明                                                                                                                                                |
| ------------------------- | -------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------- |
| `t_storage_units`         | `f_name`                               | 域版本账本：域首次打开时写入 descriptor version，其后按 accepted 集合校验（不匹配以 `version-mismatch` fail loud）。                                |
| `t_workspaces`            | `f_workspace_id` UNIQUE                | workspace 记录：`f_path` / `f_title` / `f_created_at` / `f_updated_at`，`f_position` 是显示顺序（`workspaceIds` 的位次；不在顺序中的记录为 -1）。   |
| `t_workspace_sessions`    | `UNIQUE(f_workspace_id, f_session_id)` | 会话归属：一个归属一行，`f_position` 是归属显示顺序；`f_session_id` 有独立索引，可按 session 反查 workspace。记录删除时随外键 CASCADE。             |
| `t_workspace_state`       | `f_singleton`                          | workspace 单例的剩余状态：`f_initialized` 与拆列后的两写标记（`f_pending_operation` / `f_pending_workspace_id`）。                                  |
| `t_schedule_tasks`        | `f_id`（`ScheduleId`）                 | 官方 `schedule` 域（`dsh-schedule`）的提醒：`f_session_id` 是归属会话（有独立索引）、`f_status` 是 `active` / `inactive`，`f_record` / `f_last_delivery` / `f_delivery_history` 按上游契约存 JSON。 |
| `t_session_projcache_row` | `UNIQUE(f_session_id, f_key)`          | 投影 checkpoint 行：`f_ver`（投影单元 stateVersion）/ `f_seq`（日志水位）/ `f_val`（wire 值 JSON）；`f_key` 有独立索引，可按 key 直查（如 title）。 |

- **1:1 的状态不拆表**：归档是 `t_sessions.f_archived_at` 标记，钉住是同一行的 `f_pinned_seq`
  （非空即已钉住，值就是它在 `pinnedSessionIds` 里的位次；见
  [ADR-跟随上游session-format-v4](../adrs/20260922-跟随上游session-format-v4.md)），两者都与会话行一起查询；
  投影 checkpoint 的日志 identity 直接复用 `t_sessions` 的 `f_version` / `f_created_at` / `f_cwd` /
  `f_seed_length`，不另存记录头；投影行随会话行 `ON DELETE CASCADE` 清理。
- workspace 与 schedule 两域经 storage hub 的 `rdb` KV 后端写入（上游 `StorageBackend.kv` 契约，域到表的映射在
  `src/storage-takeover/storage-backend.ts`，未知域名 fail loud）：workspace 每次写入在同一介质事务内整体替换
  （记录 + 归属、顺序 + 归档不留部分应用的中间态），schedule 一个提醒一行（`put` 是行级 upsert，不重写别的提醒）；
  投影 checkpoint 由本包的
  `ctx.sessionProjectionCache` 服务读写——SQLite 下读路径直接查表（进程内不保留镜像），PostgreSQL 因驱动
  异步保留写穿镜像。
- 投影行是派生数据：版本不匹配按 cache miss 处理。
- **会话标题是会话数据**（`t_sessions.f_title` / `f_title_seq`）：写路径遇到 `session/title` 事件即刷新，
  rewind 截断后重算；列表消费在 checkpoint 行缺 title 时**直接取该列**
  （`readSessionTitleDirect`，`src/storage-takeover/repository.ts:443`）。
- 旧 `$DSH_HOME/storages` JSON 经包内 API `importStorages(repository, { dshHome })`
  （`src/import-storages.ts`）一次性导入（旧文件保留不删）；导入 checkpoint 行要求对应会话行已存在
  （外键 fail loud）。

### 派生统计表（可销毁重建）

统计报表（`usageReport`）的读侧维度全部物化在三张衍生表里，表结构与取舍见
[ADR-统计衍生表物化归属与汇总](../adrs/20260923-统计衍生表物化归属与汇总.md)：
**迁移先 DROP 再建**（`drizzle/sqlite/20260923120000_v3_usage_materialized`）、任一表为空时在打开库时全量
回填、随时可清掉重建。

**`t_event_usage`** — 事件级用量（一条 `assistant/message` 事件行一行，fork 共享行不重复）：去重口径的
总量 / subagent 拆分与「天 × 模型」的桶只读它。

| 列                       | 说明                                                                  |
| ------------------------ | --------------------------------------------------------------------- |
| `f_event_id`             | 事件行键（外键 → `t_events`，`ON DELETE CASCADE`）                    |
| `f_created_at`           | 事件时间（毫秒 bigint；范围过滤按它走，`idx_event_usage_created_at`） |
| `f_day`                  | host 本地日 `YYYY-MM-DD`（桶分组用，与 `localtime` 口径一致）         |
| `f_provider` / `f_model` | 模型归属（事件里模型报的 provider / model）                           |
| `f_referenced`           | 被任何会话桥接行引用（孤儿行 0，不计入统计）                          |
| `f_subagent`             | 被任何 `origin = 'subagent'` 的会话引用（拆「人类 / 子代理」两组）    |
| `f_*_tokens`             | input / output / cacheRead / reasoning / total 五个 token 列          |

**`t_session_usage`** — 会话 × 本地日 × provider × model 的 token 汇总；**按会话的行**读它，
因此保住「fork 子会话含继承前缀」的口径（各会话行之和 ≥ 总量）而不回连事件表。

| 列                       | 说明                                    |
| ------------------------ | --------------------------------------- |
| `f_session_id`           | 会话 id（外键 → `t_sessions`，CASCADE） |
| `f_day`                  | 本地日                                  |
| `f_provider` / `f_model` | 模型归属（未知模型落空串）              |
| `f_*_tokens`             | 五个 token 列（累加）                   |

**`t_session_counts`** — 会话 × 本地日的活动计数：轮次 / 步骤 / 用户输入 / 工具调用四列直接读，
不存事件类型、也不在读取时折。

- 两张会话汇总表各带业务唯一键（`(f_session_id, f_day, f_provider, f_model)` / `(f_session_id, f_day)`），
  写入走 `ON CONFLICT DO UPDATE` 累加（`src/entities/v3/session-usage.ts`、`src/entities/v3/session-counts.ts`）。
- **旁路写**：`appendBatch` 事务提交之后累加两张汇总表，不在写事务里、失败只 warn——派生数据，丢几次累加不影响
  可用性；用量行的物化列在写事务内落（新事件行的 `f_referenced` 必为 1）。
- **可销毁重建**：表为空时（首次 / 迁移后 / 手动清空）在打开库时全量回填；rewind / fork 之后按会话重算
  （`rebuildSessionStats`）并**全量重算** `t_event_usage` 的引用标记（`refreshEventUsageFlags`）；会话删除时
  清掉该会话的汇总行，同样重算引用标记（被删会话引用的用量行在 GC 之前也必须退出统计）。

## 取舍

- **事件行按会话复制**（否）：fork 派生大量会话时存储膨胀，同一事件的多个副本难保一致
  （[ADR-事件实体全局化与桥接行承载会话专属信息](../adrs/20260917-事件实体全局化与桥接行承载会话专属信息.md)）。
- **把关联改成 `f_id` 外键、并为不可达查询补索引**（否）：业务键（`f_event_id` / `f_session_id`）在
  多实例共享库下才可寻址，`f_id` 只在写入者进程内稳定。
- **把 `sourceEventSeqs` 落库**（否）：读取时按需重算即可满足上游 provenance 校验，落库反而多一列要跟随
  坐标修复（[设计 读路径](20260917-读路径.md)）。
- **归档 / 钉住单独建表**（否）：归档已用会话行的 `f_archived_at` 表达，钉住用同类的一列更省一层 join
  （[ADR-跟随上游session-format-v4](../adrs/20260922-跟随上游session-format-v4.md)）。
- **统计落一张更大的日聚合表**（否）：3 万行聚合实测 10–18ms 已不可感知，多一层旁路累加与前缀重建不划算
  （[ADR-统计衍生表物化归属与汇总](../adrs/20260923-统计衍生表物化归属与汇总.md)）。

## 开放问题

  当前按消费方需要补，没有「全量覆盖上游已知类型」的约束。
