# fork 不继承统计

状态：已采纳

背景：fork 复用父会话前缀的事件行（同一批 `t_events` 行被两条会话的桥接行引用），原先在 fork 之后按子会话
重算汇总表并全量重算引用标记，于是继承前缀那一段 token 同时算进父与子两条会话的按会话行；事件级统计里
共享行的 `f_subagent` 归属还会随「此刻有没有 subagent 会话引用它」漂移（父会话的真实消耗，fork 出子代理后
就被记到 subagent 头上）。

**决定**

fork 不动统计：不重算子会话汇总表，也不刷新引用标记。子会话只记**自己新产生**的消耗（写路径的事务内用量行 +
提交后旁路累加），共享事件行的引用标记保持写入时的判定——谁真实发起的那次请求，账就算在谁头上。

**考虑过的选项**

- **保留「含 fork 继承前缀」的按会话口径**（原实现）：同一笔消耗在两条会话里各算一次，总量与按会话行之和
  对不上；归属还会随 fork / 删除漂移。
- **fork 只补 `f_subagent`、不重算汇总**：总量口径对了，但按会话行仍是继承口径，两种口径混在一张报表里。

**后果**

- `POST /api/morlay/v1/session/usage` 的按会话行只列**真实产生过用量**的会话：fork 出来、还没跑过的子会话
  不出现（它没有自己的消耗）。
- subagent 拆分按「写入时的产生者」定，不再随 fork 变化；fork 之后想把它算成子代理的消耗，只能由子会话自己
  真实跑出来的那次请求承担。
- `rebuildSessionStats`（按会话重算汇总表）只剩「旧日志重写」一个调用点：迁移进来的会话没有旁路累加的历史，
  补算一次即回到正常口径。
