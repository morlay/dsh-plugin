# 旧数据导出即修复而非原地迁移

状态：已采纳

背景：同版本内的数据格式差异（`f_data` 纯 data 形状、旧 `surfaceOp` 字段名、越界 replace range）会让历史
会话加载失败；修好这些数据有两条路——改写存储行，或在读取路径上修。

**决定**

旧格式数据的修复**并入读取 / 导出路径**（`readRaw`），产出**完备可用**的 JSONL artifact；修复只作用于
读取 / 导出视图、**不落库**——「写路径零转换」不变量不变，存储行与 revision 在读取 / 导出前后完全一致。
现状与修复明细见 [设计 旧数据修复](../designs/20260917-旧数据修复.md) 与 [设计 读路径](../designs/20260917-读路径.md)。

**考虑过的选项**

- **原地修复数据行**：破坏写路径零转换不变量，修复逻辑与写路径耦合；加载失败的历史会话也无法修复。
- **单独修复脚本**：需要维护与导出路径重复的解析逻辑，且用户必须知道何时运行。

**后果**

- 表结构级迁移与门禁见 [设计 表结构](../designs/20260917-表结构.md)；导出即修复只处理同版本内的数据格式差异。
- 加载失败的会话仍可正常导出，导出的 zip 导入后即为可用的新会话（`parseJsonlArtifact` 带防御性收缩）。
- 例外是写打开时的落库迁移（`rewriteMigratedLog`）：那是坐标对齐（迁移链生成 / 合并过事件），不是修复
  （[设计 旧数据修复](../designs/20260917-旧数据修复.md)）。
