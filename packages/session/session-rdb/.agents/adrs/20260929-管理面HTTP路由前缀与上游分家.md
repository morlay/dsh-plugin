# 管理面 HTTP 路由统一前缀 /api/morlay/v1/session

状态：已采纳

背景：本仓库会话管理面的六条路由原先直接占 `/api/session.*`（`rows` / `export` / `import` / `delete` /
`gc` / `usage`），会话编辑面占 `/session-editor`。上游官方「下载会话日志」
（`@deepseek-ai/dsh-session-log-export`）把 `GET|HEAD /api/session.export` 注册在 `ctx.connection.fetch` 上，
而 connection 服务只注册一条 `/api` **prefix** 路由；webServer 派发 exact 优先于 prefix
（`packages/host/webserver/src/index.ts` 的 `match()`）。我们那条同路径的 exact 路由只认 POST，
于是把官方的 GET/HEAD 一起吃下——官方的下载按钮与 `/export` 命令拿到 405 method not allowed，
而本仓库自己的导出（POST）照常工作。

**决定**

管理面路由整族挂在一个前缀下：`/api/morlay/v1/session` 加 `/rows`、`/export`、`/import`、`/delete`、
`/gc`、`/usage`，会话编辑面按动作分六条路径（`{edit,reroll,retry,rewind,recall,fork}`，见
[ADR-会话编辑面按动作分路](../../ui-conversation-message-actions/.agents/adrs/20260929-会话编辑面按动作分路.md)）。
host 侧的路径 home 是
`packages/session/session-rdb/src/routes.ts`（六条都由同一前缀派生，各功能文件与既有的
`@morlay/session-rdb/{rows,export,import,deletion,gc,usage}` 出口 re-export 同名常量）；浏览器半的镜像常量在
`ui-conversation-manager` 的 `client/controller.ts` 与 `ui-conversation-message-actions` 的 `shared.ts`，
改前缀两侧一起改。上游的 `/api/session.export` 保持原样（官方通道，含 `includeDescendants` 与附件收集）。

**考虑过的选项**

- **保留原路径、让我们的 handler 同时接受 GET**：继续遮蔽官方通道，官方 GET 的查询参数与流式语义拿不回来。
- **把我们的路由也注册到 connection 的 `/api` fetch 面**：与上游同一个面争同一路径，仍是「谁先注册谁生效」的
  隐式冲突，只是把 405 换成 404。
- **删掉我们的导出、管理页改用官方下载**：官方通道走 sessionQuery / attachments 重建，管理页要的是 RDB
  直读的整段 artifact；管理页的批量面（rows / delete / gc）本来也得自有。
- **只给导出改名、其余留在 `/api/session.*`**：前缀这件事会分裂成两套命名，且 `/api/session.*` 这条与上游
  同族的隐式撞名风险还在。

**后果**

- 官方 `/export` 与下载按钮恢复；我们的管理面在独立前缀下不再遮蔽上游任何路由。
- 跨半的路径常量是两份（见债：管理面路径常量跨半两份），本次靠注释指向 `src/routes.ts` 人工同步。
- 路径不再跟上游 `/api/session.*` 的命名风格，看代码的人需要知道「上游的 `/api/session.export` 与我们的
  `/api/morlay/v1/session/export` 是两条通道」。
- `/session-mode` 未纳入本次改名（它不在会话数据面上）。
