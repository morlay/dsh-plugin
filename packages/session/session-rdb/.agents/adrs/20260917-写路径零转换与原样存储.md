# 写路径零转换与原样存储

状态：已采纳

背景：rdb 后端的存储要与上游 JSONL 写路径语义一致（无过滤、无重编号），而 `ctx.sessions.create` 的 seed
校验要求事件 seq 从 0 连续；读取侧还要满足上游的 surface 校验（range 与 provenance 只引用已提交的更早事件，
`vendor/deepseek-harness/packages/core/session/src/surface.ts:414`、同文件 `:367`）。

**决定**

rdb 持久化采用**原样存储**：事件原样落库（无过滤无重编号），事件 seq 即**稠密 seq**（连续递增、无空洞）；
事件内容与 `surfaceOp` 同样原样落库（写路径零转换），`f_data` 存完整事件（含 ignorable 信封，与 JSONL 每行
同构）。写路径的当前格式校验（`validateStoredEvents`）只拒绝未知类型（非 ignorable）与非法消息形状，不做
坐标转换。

**考虑过的选项**

- **瞬时事件过滤 + 稠密重编号**：`assistant/chunk` 与 ignorable 事件不入库，幸存事件压缩重编号，读取时经
  `f_original_seq` 映射重映射 replace range / shadowedRange——与上游 JSONL 语义不一致（上游无过滤），
  而 `assistant/chunk` 已被上游删除，原样落库反而会被 fail-closed 拒绝。
- **按上游 seq 原样落库（含空洞）**：读取视图与上游一致，但 `ctx.sessions.create` 的 contiguous-from-0
  校验会拒绝带空洞的 seed。
- **在写路径做 legacy 转换（写时就把旧格式改成当前格式）**：转换会改坐标，写坐标与存储坐标分叉，
  且历史数据里不可迁移的形状没有转换目标；转换集中在读取视图（[设计 读路径](../designs/20260917-读路径.md)）。

**后果**

- 读取路径无坐标映射（原样存储恒等）；replace 的 provenance 读取时重计算（优先权威 `shadowedSeqs`，
  回退 range 扫描）。
- fork 派生会话因前缀重编号后与父稠密坐标数值相同，无需额外坐标重映射。
- 上游 seq 与稠密 seq 恒等——写读对齐的关键不变量（[设计总览](../designs/20260917-设计总览.md)）。
- 代价：历史数据的旧形状（纯 data 形状、旧 surfaceOp 字段名、越界 range）要在读取视图逐类修复，不落库
  （[设计 旧数据修复](../designs/20260917-旧数据修复.md)）。
