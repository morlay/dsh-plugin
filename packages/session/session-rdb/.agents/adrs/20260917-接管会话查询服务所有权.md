# 接管会话查询服务所有权

状态：已采纳

背景：`ctx.sessionQuery` 是会话历史的统一查询面：精确读（list / read / filter / title / surface / event
window）、血缘与事件关系追踪（trace）、语义文档抽取，以及全文检索。官方实现（`@deepseek-ai/dsh-session-query`
契约 + `@deepseek-ai/dsh-session-query-sqlite` 后端）拆成两层：契约包的 `SessionQueryEngine` 里 15 个公开方法
有 13 个是与 backend 无关的具体实现（数据面经 `ctx.sessions` 与 `ctx.sessionPersistence`），只有
`searchSessions` / `searchEvents` 是 abstract（`vendor/deepseek-harness/packages/session-query/session-query/src/index.ts:153`、
同文件 `:164`）。官方 sqlite 后端另带一份**派生 SQLite 索引库**（FTS5 + per-record 文档表 + live 影子表），
那是我们要长期跟随的另一套存储。本部署的 `@morlay/better-session` patch 已把它整行禁用
（`packages/bundles/better-session/cordis.patch.yml`），所以这个服务键的实际职责只剩「提供 `ctx.sessionQuery`」，
具体方法全部应跑在我们的持久化数据上。

**决定**

**服务所有权归 rdb 本包**：由本包按 cordis class-plugin 装载
`SessionQueryRdb extends SessionQueryEngine`（`src/session-query.ts`，装载点 `src/index.ts:636`）提供同名
`ctx.sessionQuery`；精确读 / 过滤 / 血缘 / title / surface 全部复用上游基类，数据面继续走
`ctx.sessionPersistence`（rdb）与 `ctx.sessions`。**全文检索维持 disabled**：两个 abstract 方法与官方
禁用形态同形地抛 `SESSION_QUERY_SEARCH_DISABLED`（异步拒绝，不归一化请求、不做任何索引工作），不引入 FTS5
派生库、`node:sqlite` 或第三个介质文件。不 fork 契约包与 sqlite 后端的代码，只继承基类——升级时 15 个方法
签名与错误码闭集由编译期暴露（fail loud）。

**考虑过的选项**

- **保持官方 sqlite 后端装载**：服务可用，但为一份我们不维护的 FTS 索引库付装载成本与升级面积；它的
  `_reconcile` 观测状态机与派生库 schema 属于另一套要跟随的存储。
- **只禁用不接管**：`ctx.sessionQuery` 缺失会让 `api/session-controller`（`static inject`）、subagent
  listing、`session-log-export`、`ui-deliverables` 等一批消费者直接装载失败。
- **复制上游基类实现到 rdb**：927 行等价逻辑 + 契约测试长期跟随，收益为零。
- **用 rdb SQL 实现真搜索**：需要对齐上游的 snippet 码点截断、确定性排序、cursor generation / stale 语义与
  live 尾巴（rdb 批量落库 200ms 延迟，必须用内存快照做 live 影子）——作为独立变更评估，留待显式立项。

**后果**

- `SessionQueryRdb` 必须按 class-plugin 装载（`ctx.plugin`）：直接 `new` 不会执行 `[Service.init]`，
  服务生命周期与依赖等待都会失效。
- 搜索调用方（Web 侧边栏内容搜索、`tool-session-query`）继续得到 `SESSION_QUERY_SEARCH_DISABLED`。
- 官方 `session-query-sqlite` 由 `@morlay/better-session` 的 patch 禁用（同名 provide 会 fail loud，
  必须禁用）；装配面的登记在
  [设计 20260917-系统设计](../../../../../.agents/designs/20260917-系统设计.md) 与 `@morlay/better-session`。
- 列表侧另有本部署策略：官方 `session/list` 默认排除已归档
  （[ADR-会话列表两条路](20260922-会话列表两条路.md)）。
