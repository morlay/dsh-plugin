# 事件实体全局化与桥接行承载会话专属信息

状态：已采纳

背景：fork 派生会话要复用父会话的前缀事件（[设计 分支能力](../designs/20260917-分支能力.md)），而事件的
session 专属信息（稠密 seq、surface 元数据 `surfaceOp`）必须能在同一个事件被多个会话引用时分别表达。

**决定**

存储模型把事件拆成两层：`t_events` 是**全局事件实体**（`f_data` 存完整事件，不含任何 session 专属信息），
`t_session_events` 是**会话桥接行**（稠密 seq 与 surface 元数据 `surfaceOp` 在桥接行上）。一个事件行可被多个
会话的桥接行引用——fork 派生会话复用父会话事件行，**不复制事件行**，只插入新桥接行（新 `f_sequence`）。

**考虑过的选项**

- **事件行按会话复制**（每会话一份完整事件）：实现简单，但 fork 派生大量会话时存储膨胀，且同一事件的多个副本
  难以保证一致。
- **事件行内嵌会话信息**：一个事件被多会话引用时无法表达（需要复制或多值列）。

**后果**

- 写路径需处理「事件行已存在则复用、否则新建」（fork 派生经 seq → eventId 复用映射命中则跳过插入，
  [设计 写路径](../designs/20260917-写路径.md)）。
- 桥接行删除（rewind 截断、会话删除）会留下无引用的事件行，回收统一走 GC 通道
  （[ADR-删除不再清孤儿与vacuum独立成gc通道](20260918-删除不再清孤儿与vacuum独立成gc通道.md)）。
- 事件 id 关联与重建可行性分析见 [设计 事件重建](../designs/20260917-事件重建.md)。
