# 用量统计走专用用量日志表

状态：已采纳

背景：会话页要给出「全部对话」的 token 用量（总览 / 按天 / 按模型 / 按会话）。用量只有一处在库里：
`assistant/message` 事件的 `data.usage`（input / output / cacheRead / reasoning / total）。直接对 `t_events`
做 SQL 聚合（`json_extract` + 走现成的 `f_role` 索引以避开全表扫描），实测在真实库（11.9 万行事件、
1.99 万条用量）仍需 **1.6s**：瓶颈是逐行解析事件 JSON，而且每次切时间范围都要重付一遍。

**决定**

写路径把用量落进**专用表 `t_event_usage`**（一条 `assistant/message` 事件行 = 一行：事件时间、provider / model
与五个 token 字段），统计只读这张表；老库在**首次打开时一次性回填**：

- **写路径**：`insertEvents` 顺带解析该事件并插入用量行（`ON CONFLICT DO NOTHING`；fork 复用的事件行不重复记）。
- **回填**：migrate 之后若用量表为空，用一条 `INSERT ... SELECT` 从 `t_events` 补齐——两种 `f_data` 结构都认
  （老行只存 `data`、新行存完整事件），与读路径 `rowToEvent` 的兼容判定一致；幂等，表非空即跳过。
- **口径不变**：只算被会话引用的事件行（fork 共享行计一次、已删会话的孤儿行不计）；`subagent` 按「是否被任何
  subagent 会话引用」拆分（`human + subagent = totals`）；按会话的行是各会话自己的日志口径（fork 子会话含继承
  前缀，故各行之和 ≥ 总量）。
- **GC 顺带回收**：孤儿事件行被删后，外键 `ON DELETE CASCADE` 之外再显式清一次不再有事件行的用量行。

**考虑过的选项**

- **继续直接扫 `t_events`**（走 `f_role` 索引）：1.6s/次，每次都付 JSON 解析成本。
- **只给 `f_type` 加索引**：省掉扫描，省不掉 JSON 解析。
- **按会话维度建汇总表**：fork 派生会复制继承前缀，汇总行也要跟着复制，写路径更重——汇总表按「会话 × 本地日 ×
  模型」建才成立（[ADR-统计衍生表物化归属与汇总](20260923-统计衍生表物化归属与汇总.md)）。
- **用 drizzle-kit generate 建迁移**：本仓库的 schema 是运行期动态构造（`toSqliteSchema(tableDefs)`），
  drizzle-kit 静态分析不到表，generate 报「无变化」→ 迁移按 journal-less 格式手写（migration.sql +
  snapshot.json 的 id / prevIds 链）。
- **bump `SCHEMA_VERSION`**：不必要——迁移由 `__drizzle_migrations` 记录、与 `PRAGMA user_version` 无关；
  加表是向后兼容的（旧代码既不写也不读它），改版本号反而让现有库被判不兼容。

**后果**

- 统计不再逐行解析事件 JSON；读侧维度（本地日、是否被引用、是否子代理）与三张衍生表的形态见
  [ADR-统计衍生表物化归属与汇总](20260923-统计衍生表物化归属与汇总.md)。
- 报告含「token 用量 + 活动计数」两部分：活动计数（轮次 / 步骤 / 用户输入 / 工具调用）与 token 同一时间范围、
  同一会话集合（限定在有 token 用量的会话里，口径自洽）；`totals` / `subagent` / `human` 由 host 按「是否
  子代理」两组各自聚合一次得出；按天 × 模型的桶只有 token 用量（活动计数没有模型归属）。
- 时间范围是语义键（`all` / `day` / `week` / `7d` / `30d` / `90d`）：`day` 与 `week` 是 host **本地时区**的
  零点边界（周一起算），`7d` / `30d` / `90d` 是最近 N 个自然日（含今天）；边界计算留在 host，客户端只传语义。
- PG 侧 `f_created_at` 必须是 `bigint`：int4 装不下毫秒时间戳（报 `22003`）；实体与迁移都已按 bigint 落，
  守卫在 `src/__tests__/pg.spec.ts` 的用量用例。
- `t_event_usage` 是事件行的从属数据：外键级联 + GC 显式清理，不会长期堆积孤儿行。
- 首次打开旧库多一次一次性回填（全量 `json_extract`），此后不再发生。
