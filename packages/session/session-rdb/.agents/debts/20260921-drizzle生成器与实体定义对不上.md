# drizzle 生成器与实体定义对不上，迁移只能手写

状态：未销账（本次 `v3_agent_preset` 迁移是手写的；生成器输出不能直接用）

**现象**

`pnpm db:generate`（`drizzle-kit generate`，schema 源是 `src/drizzle/sqlite-v3.ts` /
`postgres-v3.ts`）当前不能直接产出可用的迁移：

- **SQLite**：diff 里混着与本次改动无关的 `t_event_usage` 重建（`CREATE __new_t_event_usage` →
  拷贝 → `DROP TABLE` → `RENAME`）。因为实体 `src/entities/v3/event-usage.ts` 的 tokens 列没有
  `default: 0`，而既有迁移建的表带 `DEFAULT 0 NOT NULL`；生成器想把 DB 的 default 去掉。
  重建在几十万行的库上要重写整表，不能应用。
- **PostgreSQL**：读既有快照直接失败（`drizzle/postgres/20260918120000_v3_event_usage/snapshot.json
data is malformed`），生成中断。
- 两个方言的 drizzle 视图都曾漏导出 `t_event_usage`（已补），漏导出时生成器会直接产出
  `DROP TABLE t_event_usage`——比重建危险。

**影响**

新加列/表时，迁移 SQL 要**手写**，并按惯例（见 `20260918120000_v3_event_usage` 与 commit
7f28371：改 TableDef + 改既有迁移 DDL）判断是补既有迁移还是新开一个目录。手写时要自己检查生成器
想做的其余改动是否该应用——本次 `20260921075855_v3_agent_preset` 就只保留了 `ALTER TABLE`
一行，并在文件里注明被略过的 `t_event_usage` 重建。

**销账方向**

让实体与既有迁移的 DDL 对齐（给 tokens 列补 `default: 0`），再修 pg 侧的快照（重生成或
按当前版本重建），使 `db:generate` 的 diff 只反映真实改动。做之前先确认 sqlite 侧剩余的
`f_event_id` 主键 `notNull` 表示差异是否也会消失（旧快照记 `true`、新生成记 `false`）。
