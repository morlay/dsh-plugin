# drizzle 生成器与实体定义对不上，迁移只能手写

状态：未销账（本次 `v3_agent_preset` 迁移是手写的；生成器输出不能直接用）

**现象**

`pnpm db:generate`（`drizzle-kit generate`，schema 源是 `src/drizzle/sqlite-v3.ts` /
`postgres-v3.ts`）当前不能直接产出可用的迁移：

- **SQLite**：diff 仍混着与本次改动无关的 `t_event_usage` 重建（`CREATE __new_t_event_usage` → 拷贝 →
  `DROP TABLE` → `RENAME`），重建在几十万行的库上要重写整表，不能应用。2026-09-21 补齐 tokens 列的
  `default: 0` 之后仍会重建，剩下的触发点是两处**表示差异**：
  `f_event_id` 的主键表示（生成器写 `text PRIMARY KEY`，既有 DDL 是 `text PRIMARY KEY NOT NULL`）与
  `f_created_at` 的方言映射（实体是 `bigint`，生成器 SQLite DDL 写 `integer`，既有 DDL 是 `bigint`）。
- **PostgreSQL**：读既有快照直接失败（`data is malformed`），生成中断。JSON 本身合法
  （`JSON.parse` 通过），是**结构**不被当前 drizzle-kit（`1.0.0-rc.5-ab785fc`）接受；该快照 `version: 8`，
  而 SQLite 侧快照是 `7`。
- 两个方言的 drizzle 视图都曾漏导出 `t_event_usage`（已补），漏导出时生成器会直接产出
  `DROP TABLE t_event_usage`——比重建危险。

**影响**

新加列/表时，迁移 SQL 要**手写**，并按惯例（见 `20260918120000_v3_event_usage` 与 commit
7f28371：改 TableDef + 改既有迁移 DDL）判断是补既有迁移还是新开一个目录。手写时要自己检查生成器
想做的其余改动是否该应用——本次 `20260921075855_v3_agent_preset` 就只保留了 `ALTER TABLE`
一行，并在文件里注明被略过的 `t_event_usage` 重建。

**销账方向**

让实体与生成器的期望一致，使 `db:generate` 的 diff 只反映真实改动：

1. tokens 列的 `default: 0` —— ✅ 2026-09-21 已补齐（`src/entities/v3/event-usage.ts`），与既有 DDL 的
   `DEFAULT 0 NOT NULL` 对齐；
2. SQLite 侧仍剩两处表示差异（主键 `NOT NULL`、`bigint` 映射），都会触发整表重建——先在实体 / 适配器层定性：
   是改实体，还是接受适配器的方言映射并在生成后人工剔除重建段；
3. PG 侧按当前 drizzle-kit 版本重生成或改写那份 `snapshot.json`（先解决它，PG 生成才跑得下去）。
