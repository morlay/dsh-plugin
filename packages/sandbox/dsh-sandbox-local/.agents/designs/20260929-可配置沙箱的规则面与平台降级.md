# 可配置沙箱的规则面与平台降级（dsh-sandbox-local 的机制）

状态：已实现（三类 `access` 条目替换官方两个服务后生效；Seatbelt 全表达，其余平台按方言降级并加载期告警）
范围：`packages/sandbox/dsh-sandbox-local/` 的机制——`access` 规则语义与命中优先级、两个服务入口、配置字段、平台方言、装配链路，以及两条运行时上下文（`sandbox:policy` / `approval:policy`）的接管。
本文引到的 `packages/…` 路径是上游真源（位置在 `vendor/deepseek-harness/`），本仓库自己的包一律写 `packages/<family>/<pkg>`。
约束：`vendor/**` 只读；官方 `sandbox` / `fs-sandbox` 两行必须由采用方禁用（同一 scope 重复注册同名服务 fail loud，而不是覆盖）。

## 结论摘要

| 议题              | 结论                                                                                               | 一句话理由                                                                                                                                                                                                           |
| ----------------- | -------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 替换面            | `ctx.sandbox`（进程沙箱）与 `ctx.fs`（文件围栏）两个服务一起换                                     | 上游把 `writableRoots` 同时喂给 Seatbelt profile 与进程内围栏（`packages/sandbox/sandbox-local/src/profiles.ts:53`、`packages/fs/fs-sandbox/src/index.ts:134`），只改一侧会造出「bash 能写、write 工具不能写」的裂缝 |
| 进程沙箱侧        | 继承官方 `LocalSandboxProvider`，`confine` 先走 `super.confine()`，再按方言把规则追加到返回的 argv | runner 探测与选择、Windows ACL 私有 temp、拒绝方言与 runner 失败规则全部保留，本包只加规则                                                                                                                           |
| Seatbelt 表达     | 规则追加在 profile 末尾                                                                            | SBPL 的后置规则覆盖先置规则，因此 `(deny file-read* file-write* …)` 能压过官方已写入的 `(allow file-write* (subpath …))`（`src/dialects.ts:61-75`）                                                                  |
| 降级              | 其余平台按方言降级，加载期对每种降级打 warn                                                        | 「能表达多少就说多少」，而不是静默失效                                                                                                                                                                               |
| `sandbox:policy`  | 那段运行时策略文本也由本包按 agent 作用域接管（**agent 创建时**注册）                              | 全局层同名注册会抛错（`NamedEntries.insert`），上游给的官方路径就是 scope 遮蔽；注册必须早于第一次装配，挂在装配瀑布里只能从第二次起生效（会话里"先英文后中文"）                                                     |
| `approval:policy` | 同上，换成中文的两段（按会话有效策略选段）                                                         | 上游在全局层注册英文，本部署要中文；有效策略读 `ctx.approval` 的公开面（`overrideOf` 优先，否则 `config.policy`），私有 `effectivePolicy` 不复述                                                                     |

## 事实基线

### 规则条目（`access`）

- 语法 `rw <path>` / `r- <path>` / `-- <pattern>`（`src/rules.ts:7` 的 `ACCESS_LINE`）；数组每项一条或多行文本
  每行一条两种写法等价，空行忽略。
- 缺前缀、或前缀后没有路径 → 加载即失败（`src/rules.ts:117-126`）；`rw` 带通配符 → 编译期报错
  （`src/rules.ts:172-176`）——可写根没有「通配」语义。
- `{{ env.NAME }}` 在加载期按进程环境展开，变量未设置或为空即失败（`src/rules.ts:13-23`）。
- 相对路径相对**会话工作区**解析（`src/rules.ts:148-150`），不是 `cwd` 配置项。
- glob：`*` / `?` 不跨 `/`，`**` 跨层级（`**/` 也匹配零层），`[!ab]` 取反（`src/rules.ts:25-66`）；生成的正则同时
  用于进程内匹配与 SBPL 的 `(regex #"…")`，所以只用两者共有的语法。
- 字面（无通配）的 `r-` / `--` 条目命中自身**及其全部后代**（`src/rules.ts:197-199`）。
- 命中优先级 `--` > `r-` > `rw` / 平台可写根（`src/fs.ts` 的 `assertNotDenied` → `isReadOnly` → 可写根）。
- `r-` / `--` 在 `danger-full-access` 下仍然生效（`ctx.fs` 侧）：它们是显式写下的用户规则，不是模式的推论
  （`src/fs.ts:101-118`）；进程沙箱侧在 `danger-full-access` 下不经过沙箱，本包无从施加。

### 两个入口的行为

| 条目        | `ctx.fs`（read / write / edit / list 工具）  | `ctx.sandbox`（bash 等子进程）                                                                      |
| ----------- | -------------------------------------------- | --------------------------------------------------------------------------------------------------- |
| `-- <path>` | 任何模式下读与写都拒（`resolve` 入口即拦截） | Seatbelt：读 + 写；bwrap：退化为只读（`--ro-bind-try`，等于只拒写）；Landlock / Windows ACL：无表达 |
| `r- <path>` | 任何模式下读放行、写拒绝（优先于可写根）     | Seatbelt：`(deny file-write* …)`；bwrap：`--ro-bind-try`；Landlock / Windows：无表达                |
| `rw <path>` | `workspace-write` 下计入可写根               | Seatbelt：`(allow file-write* (subpath …))`；bwrap：`--bind-try`；Landlock：`--rw`；Windows：无表达 |
| 无条目      | 与官方 `fs-sandbox` 行为一致                 | 与官方 argv 逐字一致（不做任何改写）                                                                |

方言能力表在 `src/dialects.ts:17-22`；`ctx.fs` 侧（read / write / edit 工具）在所有平台保持完整语义，降级只影响
bash 等子进程。

### 配置字段

六个字段都上设置页；`access` 可改（改完规则当场重算，不用重挂这一行），其余五个是**装配事实**，页面上只读可见
——它们在 `Config` 上标了 `.volatile().disabled()`。`volatile` 让解析后的值变成**引用**，而官方
`LocalSandboxProvider` / `LocalFileSystem` 在构造时读一次这些字段并做装配期校验，所以交给基类的那份配置先由
`upstreamConfigOf` 解包成值（`src/config.ts`）。

| 字段                      | 默认            | 含义                                                                 |
| ------------------------- | --------------- | -------------------------------------------------------------------- |
| `access`                  | `[]`            | 规则条目：`rw <path>` / `r- <path>` / `-- <pattern>`；数组或多行文本 |
| `runnerCommand`           | `[]`            | 透传官方 `sandbox-local`：替换 runner argv（配了它就不能用规则）     |
| `runnerFailureSignatures` | `[]`            | 透传官方 `sandbox-local`：自定义 runner 的失败签名                   |
| `probeTimeoutMs`          | `5000`          | 透传官方 `sandbox-local`：候选 runner 的探测超时                     |
| `cwd`                     | `process.cwd()` | 透传官方 `fs-local`：相对路径的解析基准                              |
| `diffBasisMaxBytes`       | `10485760`      | 透传官方 `fs-local`：overwrite diff 单侧字节上限                     |

### 装配

- **行数据在本包**：`./rows` 出口（`src/rows.ts` 的 `sandboxRows()`）给出「禁官方 `sandbox` / `fs-sandbox` 两行 +
  插入本包一行」，行不带 config（schema 默认是空规则）。
- **采用它的部署 bundle 是 `@morlay/sandbox-profile`**：它按 `./rows` 渲染出 patch（生成物就是那个包的
  `cordis.patch.yml`），并在同一份 patch 里按 id 给 `sandbox-local` 的 `access` 值——装配归能力包的 rows、值归
  bundle 的 `tsdown.config.ts`。
- **部署侧只需把那个 bundle 列进 `dsh.profile.bundles`**（
  [`apps/dsh-custom-next/package.json`](../../../../../apps/dsh-custom-next/package.json) 已如此）。
- 两种采用方式互斥：本包 rows 与 bundle 的 patch 同时上线会重复插入同一行。
- **启用规则的层必须同时做三件事**——禁用官方两行、插入本包行、写规则：只做后两件时官方实现仍在提供
  `ctx.sandbox` / `ctx.fs`，规则没有生效点，沙箱静默退回「只有工作区 + `/tmp` 可写」（命令照常跑，没有报错）。
  装配守卫见 `packages/bundles/sandbox-profile/src/__tests__/patch.spec.ts`。
- 规则与 `runnerCommand` 互斥：自定义 runner 的 argv 方言无法识别，此时配了规则会在 `confine` 抛错（宁可失败也
  不让规则静默失效）。

### 运行时快照的两条接管（`sandbox:policy` / `approval:policy`）

换了 `ctx.sandbox` / `ctx.fs`，模型看到的那段运行时策略文本也得跟着换；审批那条也要中文。上游
`@deepseek-ai/dsh-sandbox-policy` 与 `@deepseek-ai/dsh-user-approval` 都在**全局层**注册（`sandbox:policy` /
`approval:policy`），全局层同名注册会抛错，上游给的官方路径是**按 agent 作用域覆盖**：本包在 agent 的 `ctx` 上注册
同名 context，装配时近的作用域遮蔽全局那条（`src/policy.ts`）；没有 agent 的装配（agentless 调用）保持上游那条。

- **时机必须是 agent 创建时**：`SystemPrompt.assemble()` 先把 `contexts` merge 好、再进
  `system-prompt/assemble` 瀑布。早先挂在瀑布里注册的写法只能从**第二次**装配起生效——会话里表现为"先英文后中文"。
  改成 `agent/created`（创建期最后一步，早于第一次装配）**加上**遍历 `ctx.agents.list()` 覆盖已存在的 agent（本行
  晚于它们挂载时才走这条路径），第一次装配就是中文。
- **文本**：`sandbox:policy` 保留官方三种 mode 的语义（中文简化版），规则非空时追加本部署的额外可写根 / 只读项 /
  拒绝项；`approval:policy` 按会话的有效策略选两段之一——有效策略 = `ctx.approval.overrideOf(session)`（会话日志里
  最后一条 `approval/policy`）优先，否则 `ctx.approval.config.policy`，再退 `ask`。`effectivePolicy` 是上游私有的，
  这里复刻同一算法而不是读它。

## 取舍

- **规则追加到官方 argv，而不是自建 runner**：官方 runner 探测 / 选择、Windows ACL 私有 temp、拒绝方言与失败规则
  全部保留；自建 runner 要跟住平台链的每一次变化。
- **三类条目共用一个 `access` 列表**：用户一次写完，语义由前缀决定；拆成三组字段会让「同一个路径既声明只读又声明
  可写」这类冲突无处表达优先级。
- **可写根与拒绝项分开表达（`rw` 只做追加）**：`workspace-write` 的可写根来自 `writableRootsWith`，本包只在
  `workspace-write` 下追加 `rw` 条目（`src/rules.ts:189-195`）——`read-only` 下不追加，显式选定的只读边界不因额外
  可写根放松。
- **`ctx.fs` 侧是策略检查，不是内核边界**：与它替换掉的官方 `fs-sandbox` 同一威胁模型（受信代码 + 模型可控路径）；
  内核级隔离仍归 `ctx.sandbox`。
- **策略文本按 agent 作用域覆盖**：全局层同名注册会抛错，且 agentless 装配要保持官方那条，作用域遮蔽是上游给的
  官方路径。
- **接管注册提前到 agent 创建**：装配瀑布跑在 `contexts` merge 之后，在那里注册只能从第二次装配起生效；代价是注册
  时机与"agent 已知"绑在一起，所以本行晚挂载时用 `ctx.agents.list()` 补一遍。

## 开放问题

- **bwrap 参数顺序未实测**：`--bind-try` / `--ro-bind-try` 的「后挂载覆盖先挂载」与 `-try` 缺路径语义来自 bwrap
  文档而非本仓库的测试证据（本机为 macOS）。
- **Windows 额外授权未实现**：官方 `AclWriteGrant` 可以做预授权，但没有把它接进 `confine` 的现成路径，本版只告警。
- **`r-` / `--` 条目不隐藏目录项**：`ls` 仍能看到被保护文件的名字，被拦的是内容读取（仅 `--`）与写入。
- **策略文本要与上游措辞对照**：这段文本是照上游 `renderPolicyContext` 的语义重写的——上游改了模式集合或措辞时
  测试不会自动发现，同步上游时要读一眼
  `vendor/deepseek-harness/packages/sandbox/sandbox-policy/src/index.ts`。
