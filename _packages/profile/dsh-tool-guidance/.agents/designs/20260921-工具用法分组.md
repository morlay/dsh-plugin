状态：已实现
范围：本包的分组表、丢弃清单与短描述投影。**送达**（每组的正文怎么到模型）在
[工具说明与用法分组的送达](./20260929-工具说明与用法分组的送达.md)；注入形态与 id 规则在
[上下文注入规则](../../../../context/dsh-context-assembler/.agents/designs/20260921-上下文注入规则.md)。
约束：上游 `@deepseek-ai/*` 只读；用法说明走 append 通道，判定依据见
[ADR-工具schema恒定而说明动态化](../adrs/20260920-工具schema恒定而说明动态化.md)。

## 结论摘要

| 议题     | 结论                                                                    | 一句话理由                                                   |
| -------- | ----------------------------------------------------------------------- | ------------------------------------------------------------ |
| 门控     | **不设**：能力开关不做成元工具或档位                                    | 工具 schema 本就恒定；拒绝一次再教它解锁，不如直接让它用     |
| 分组     | `base`（常驻）/ `flow` / `delegation` / `team`（按需）                  | 分组只决定用法说明怎么分批送达                               |
| 常驻判据 | 这一步不用它就没法开工的组（`base`）常驻，其余按需                      | 基础工具每轮都可能用，等一轮加载不划算                       |
| 丢弃     | 每组的 `drops` 把上游说明与规则从提示词里摘掉，要点由我们自己写进组正文 | 上游原文不常驻也不原样进提示词，拿到这组能力时读我们写的那份 |
| 短描述   | 装配投影里换成一行中文                                                  | 工具 schema 常驻，描述值得压；改投影不碰注册表               |

## 事实基线

### 数据形态

- 数据以 **pack** 为单位（[`src/guidance/packs/index.ts`](../../src/guidance/packs/index.ts)）：一份文件一个
  pack，**加一份文件 + 在索引里登一行**。两类同一形态（[`types.ts`](../../src/guidance/types.ts)）：
  **工具族**（一组工具的一行中文——加一个工具 = 改它所属的族）与**用法组**（一段用法正文、成员工具与丢弃清单）。
- 汇总层是 [`src/guidance/groups.ts`](../../src/guidance/groups.ts)（组表、短描述表、正文渲染），它自己不放数据。
- 两处都有 fail-loud：同一个工具名出现在两个族、或两个 pack 声明同一个组 key 时当场报错（归类 / 命名错了，
  不是"后者覆盖前者"）。

### 上游的说明与我们的投影

- 上游把每个工具的跨调用说明注册成 `tool:<工具名>` section（`fs/tool-fs/src/read.ts:69` 等），Agent Teams 的
  协作规则注册成 `team:policy`、落在 **agent 作用域**（`experimental/tool-agent-team/src/index.ts:170`）。
- 出口做四件事：把 `description` 换成一行中文、剥掉 schema 里的说明性字段（它们常驻请求）、把用法按组送达、
  丢弃上游逐工具说明——后两件的形态与接缝见
  [设计-工具说明与用法分组的送达](./20260929-工具说明与用法分组的送达.md)。
- 正文按**这个会话装配结果里最终可见的工具目录**渲染：`base` 的常驻正文只列这个会话真的看得到的工具
  （收窄掉的 `bash` 就没有那一行），其余三组的正文在装配期定型。
- 丢弃按 section 名：`team` 组摘 `team:policy`，要点吸收进组正文。
- 代价的依据：工具定义走请求的 `tools` 参数，位置在 system 文本之后、全部 messages 之前，任何扰动让该请求整段
  重算（实测 94% → 0~3.2%）；改 `assembly.tools` 而不是注册同名工具——在 agent 作用域注册会同步触发
  `tools/change`，上游 `tool-subagent` 用该事件做 composition reconcile
  （`subagent/tool-subagent/src/index.ts:710`），两边互相触发会让装配风暴式重入。

## 取舍

- **取消门控**：门控需要元工具（`enable_tools`）、用户命令（`/tools`）、档位重建与"未归组工具"例外，
  换来的只是"模型先撞一次墙"。能力取舍改由模式的 `allowTools` 收口表达，判据见
  [设计 20260924-会话模式](../../../dsh-session-mode/.agents/designs/20260924-会话模式.md)。
- **`base` 组常驻、其余按需**：判据是"这一步不用它就没法开工"。`web_search` 因此归 `base`——它与 `web_fetch`
  是同一件事的两半，拆在不同层会让提示跨组指路。代价是 `base` 组正文每会话进上下文一次（要改成按需得连送达
  一起改，见送达那份设计）。
- **正文自建 + 上游说明摘掉**：授权 / 使用单位是组，提示就以组为单位；上游已有的细节知识由我们把要点写进组正文
  按需加载，原文由 `drops` 摘掉。代价是 `drops` 清单要与上游 section 名对齐（覆盖性测试兜住：上游新增说明或改
  名字时变红，必须把新名字归到某个组的 `drops` 或通道的 `suppress`）。
- **短描述覆盖 `description`**：只换描述、转发执行与渲染。代价是描述与上游语义脱钩（上游改职责时要跟），且参数
  schema 省不了——短描述只压住描述那一段。

## 开放问题

- `team` 组那条路径没有真装配判据：本部署那份 preset 不放团队行，`team` 正文与 `team:policy` 的丢弃只由覆盖性
  测试守着。要用团队的人加上游 `@deepseek-ai/dsh-experimental-agent-team-profile`。
