# 写路径流程（appendBatch）

状态：已实现
范围：写路径的流程与规则——`appendBatch` 落库、live 路由（缓冲 → drain）、统计衍生表的旁路累加；
读路径见 [设计 读路径](20260917-读路径.md)，并发写入者检测见 [设计 并发写入](20260917-并发写入.md)。

## 事实基线

### 落库流程

```
live log（上游 seq）
  │
  ├─ 当前格式校验：validateStoredEvents（未知类型非 ignorable / 非法消息形状拒绝）
  │
  ├─ f_data：完整事件原样落库（type/seq/time/data/ignorable 信封，与 JSONL 每行同构）
  │
  ├─ surfaceOp：原样序列化到桥接行 f_surface_op（append / replace 原样）
  │
  └─ 落库：t_events 行（完整事件）+ t_session_events 桥接行（f_sequence / f_surface_op），单事务
```

### 规则

- **写路径零转换**：事件内容、surfaceOp 全部原样落库；无过滤无重编号。
- **写路径当前格式校验（fail-closed）**：`validateStoredEvents` 拒绝未知类型（非 ignorable）与非法消息形状，
  新入库数据只能是当前格式形状。非当前格式（v0 / v1 / v2）数据只在读取时经 legacy 转换链动态转换；写打开时
  若迁移视图与存储桥接行数不一致（迁移链会生成 / 合并事件），先整体落库一次，使读写同坐标
  （[设计 旧数据修复](20260917-旧数据修复.md)）。
- **事件行已存在则复用**：fork 派生会话引用父会话事件行，经 seq → eventId 复用映射命中则跳过插入，否则新建。
- **事务**是原子性 + 持久性边界：mid-batch 失败（UNIQUE 冲突）整体回滚。
- **写锁**：SQLite `BEGIN IMMEDIATE`（busy_timeout 排队）；PG 依赖事务行锁 +
  `UNIQUE(f_session_id, f_sequence)` 拒绝冲突批次。
- **并发写入者校验**（`assertNoConcurrentWriter`）在落库**之前**执行——磁盘 head 必须等于本实例最后确认的
  head，否则 fail loud（[设计 并发写入](20260917-并发写入.md)）。

### live 路由（session/event → 缓冲 → drain）

live 会话的事件由 `installLiveRouting` 装到本进程的 write handle 上，先缓冲、再批量 drain 落库
（`src/index.ts:1343`）：

- `session/created` → `ensureLiveHandle`（create 或 adopt 已存储会话，落 seed）；
- `session/event` → 有 writer handle 时直接 `enqueueLive`（200ms 批量窗口，`src/index.ts:488`），
  否则进活跃会话的缓冲（`this.liveBuffers`）；
- `session/flush` → `drainLive` + `flush`（持久性屏障）；
- `session/disposed` → 等 handle 就绪后 close（drain 剩余缓冲）；
- HMR：插件 apply 时对 `ctx.sessions.list()` 里已存在的 live 会话补种（`src/index.ts:1351`）。

**初始化失败是终态（fail loud）**：`ensureLiveHandle` 的失败（cwd / 继承前缀冲突、id 碰撞、后端打不开）
不会自愈，所以记账一条 `error` 并丢掉该会话已缓冲的事件，之后它的事件**不再进内存缓冲**（每会话一条
`warn` 说明丢弃）——否则表现为「聊了一整轮、重启后全丢，内存里还留一份无界副本」；`session/flush` 把该失败
抛回上游，`session/disposed` / 删除 / 插件卸载各自清掉失败态。

`drainBuffered` 只过滤已由 `ensureLiveHandle` 落库的 seed 前缀（上游 seq 空间与 handle cursor 同空间），
**不过滤 delta / ignorable 事件**。

分支层与测试经 `internals()` 取 `backend` / `writeGuard` 与便捷方法面——rewind 用它直达事务
（[设计 分支能力](20260917-分支能力.md)）。

### 上游 seq 与稠密 seq 的关系

原样存储下事件 seq 即稠密 seq（`f_sequence`），写读天然对齐，无需坐标映射
（[设计 读路径](20260917-读路径.md)）。非当前格式会话经迁移链读取时事件数可能与存储行数不同（生成 end-seed /
合并 chunk），写打开会把迁移视图整体落库（`rewriteMigratedLog`，事务内删桥接行 + 按视图重建 +
head/revision 更新），此后该会话即普通当前格式会话。

### 统计衍生表（旁路累加 + 可销毁重建）

写路径把统计所需的全部维度物化下来（[设计 表结构](20260917-表结构.md) 的「派生统计表」，取舍见
[ADR-统计衍生表物化归属与汇总](../adrs/20260923-统计衍生表物化归属与汇总.md)）：

- **事务内**：新事件行的用量行直接带 `f_day` / `f_referenced = 1` / `f_subagent`（会话是否 subagent）——
  桥接行与它同事务，提交即被引用。
- **事务提交之后旁路累加**两张会话汇总表（`t_session_usage` 按「本地日 × 模型」、`t_session_counts`
  按「本地日」四项计数）：不参与写事务、失败只 warn。
- **变更后重建**：rewind / fork 之后按会话重算该会话的两张汇总行、并全量重算 `t_event_usage` 的引用标记
  （`f_referenced` / `f_subagent`）；会话删除后同样全量重算引用标记——被删会话引用的用量行必须在 GC 之前
  就退出统计。统计查询因此从不扫事件表、也不做 `EXISTS` 判定。

## 取舍

- **瞬时事件过滤 + 稠密重编号**（否）：与上游 JSONL 语义不一致，且 `assistant/chunk` 已被上游删除，
  原样落库会被 fail-closed 拒绝
  （[ADR-写路径零转换与原样存储](../adrs/20260917-写路径零转换与原样存储.md)）。
- **在写路径做 legacy 转换**（否）：转换会改坐标，写坐标与存储坐标分叉；转换集中在读取视图，写打开只在
  坐标真的不一致时整体重写一次（[设计 旧数据修复](20260917-旧数据修复.md)）。
- **初始化失败后继续缓冲自愈**（否）：失败原因（cwd 冲突 / id 碰撞）不会因为重试消失，缓冲只会无界增长，
  而且「重启后全丢」比当场报错更难查。
- **live 事件逐条落库**（否）：上游按条推送事件，逐条开事务会在长回答里把写放大到每秒数十次；
  200ms 批量窗口把批次拉齐，`session/flush` 仍是持久性屏障。

## 开放问题

- 200ms 批量窗口与 `projectionCache` 的节流参数（`writeEveryEvents` / `writeIntervalMs`）是两套节奏，
  当前都按常量 / 默认值走，未做过端到端调参。
