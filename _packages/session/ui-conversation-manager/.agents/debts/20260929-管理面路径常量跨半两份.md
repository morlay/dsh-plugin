# 管理面路径常量跨半两份

状态：未销账（host 与浏览器半各写一份字面量，靠注释同步）

**现象**

管理面六条路径的字面量在两侧各有一份，没有测试守护一致：

- host 侧的唯一来源：`packages/session/session-rdb/src/routes.ts`（六条由 `MORLAY_SESSION_API_PREFIX` 派生）；
- 浏览器半镜像：`packages/session/ui-conversation-manager/src/client/controller.ts`（删 / 导入 / 导出 / GC /
  用量 / 列表）与 `packages/session/ui-conversation-message-actions/src/shared.ts`（会话编辑面），
  两侧靠各自的注释指向 host 那份。

**影响**

改前缀或改某条路径时漏改一侧，该动作在页面上表现为「请求失败」（404 落到静态资源 fallback），
构建与测试都不会拦下来：host 侧的 spec 从常量取路径，浏览器半的 spec 只断言自己那份常量。

**触发条件**

下次动管理面路径（改前缀、加一条路由、改名）之前先决定是补测试还是收敛成一份常量。

**销账条件**

Done when：两侧路径由同一份常量派生（浏览器半 import 一个零依赖的路径模块，构建时内联），
或有一条测试断言两侧常量逐条相等。

**不修的理由**

跨包 import 纯常量要新增一个零依赖出口并让 client 构建内联它，而本次只改路径的值；
收益是一条断言，成本是一个新出口与发布态解析路径的确认。
