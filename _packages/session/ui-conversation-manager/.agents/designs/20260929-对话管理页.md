# 对话管理页（全局面板页的形态与数据位）

状态：**已实现**（侧栏「对话管理」页可跑：会话视图与统计视图、导入 / GC / 归档 / 导出 / 删除）
范围：`packages/session/ui-conversation-manager/` 的页面形态——两层视图、列表与统计的取数口径、`data-*` 标注面、
以及它对既有服务与路由的依赖；门面与用法见该包 [`README.md`](../../README.md)。
约束：不新增 host 面，只读既有服务与路由；数据动作全部经 `@morlay/session-rdb` 的路由。

## 结论摘要

| 议题       | 结论                                                                                                                                          | 一句话理由                                                                                           |
| ---------- | --------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------- |
| 注册形态   | `sidebar.panellist` 的 nav 行 + `main` keyed 面板                                                                                             | 与官方 ui-plugin-manager 同一种注册方式，不新造壳                                                    |
| 列表取数   | 走自己的 `POST /api/morlay/v1/session/rows`（完整语料，含归档）                                                                               | 官方 `session/list` 按部署策略默认排除已归档，管理动作需要完整集合                                   |
| 搜索与分页 | 都在后端（前端只渲染当前页，输入停 250ms 再发）                                                                                               | 归档集是全量语料，前端过滤会随会话数线性变慢                                                         |
| 统计视图   | 一次全库聚合（`POST /api/morlay/v1/session/usage`），维度切换本地折叠                                                                         | 聚合口径归 session-rdb，页面只做展示与折叠                                                           |
| 数据位     | 每个数据位带稳定 `data-*` 标注，只标「最小身份 + DOM 读不出的状态」                                                                           | 沟通与 e2e 要能指着某一行说，而不必复述页面文案                                                      |
| 形态       | 页面框架与上游一级页面同款（960px 居中列 + 标题行 + 过滤 chip 行 + 搜索行），切换与过滤一律是**筛选 chip**（`role="group"` + `aria-pressed`） | 上游没有这套框架的共享原子，它是各一级页面自己 CSS Modules 里的同一套度量；我们不另造一套 tab 条原子 |
| 状态态     | 读取 / 一份会话都没有 / 读列表失败三种状态**整屏居中**，此时不画框架（标题行、过滤行、搜索行都不出现）                                        | 这三种时候页面没有别的内容可做；搜索无结果不算（框架留着，用户要能改搜索）                           |

## 事实基线

### 页面结构

页面框架（`ConversationManagerPage.module.css`）与上游一级页面同款：`.page / .listPane / .pageScroll /
.pageContent`（960px 居中列）→ `.pageHeading`（`<h1>` + 右侧动作，28px 上内距 + macOS 顶栏让位）→
`.filters > .filterTabs > .filterTab`（28px 筛选 chip）→ `.searchField`（外层盒子负责那根细线，里面是官方
`Input` + 清空按钮）。**整列一起滚**：标题行、过滤行、搜索行、列表同在一个滚动层里，页面根不滚。

过滤 chip 行分两组：**视图**（会话 / 统计，`data-filter="view"`）与**会话筛选**（显示子代理会话，
`data-filter="subagents"`，只在会话视图里出现）。切到统计视图后，过滤行换成用量自己的两组 chip
（时间范围、用量维度），搜索行不出现——它筛的是会话列表。

会话视图给出全量会话的搜索、分页与归档 / 取消归档 / 导出 / 删除（确认弹窗），并带导入为新会话与孤儿数据
GC；统计视图给出全部对话的 token 用量。

### 会话视图

- 取 `POST /api/morlay/v1/session/rows` 的完整语料（含归档），按最近活动在前；搜索（标题或工作区名）、子代理
  开关与翻页都是**后端**请求；**已归档**的行带标记，也只有这些行的「删除」可用（未归档行提供
  「归档」，两者互斥）。
- 子代理派生会话（`origin: 'subagent'`）默认不列（既不可删也多数无意义，真实库里占七成），勾选
  「显示子代理会话」即真全量。
- 列表每页 20 条，搜索框复用官方 `Input`（连同官方图标与焦点样式）；有查询时右侧出现清空按钮（`clearSearch`），
  点它清空并把列表还原。
- 归档 / 取消归档 / 删除 / 导入 / GC 成功后重拉会话行；host 拒绝（未归档 / 正在使用 / 不存在）时
  按错误码给出可读文案。
- GC 是唯一会**停止所有运行中 agent** 的动作：确认后进入不可关闭的等待弹窗，避免用户在 VACUUM
  期间做别的操作。

### 统计视图

- 先按**时间范围**过滤（默认**本日**；**本周** / 近 7 天 / 近 30 天 / 近 90 天 / 最后是**全部**；
  换范围会向 host 重新聚合一次。**本日 / 本周**按 host 的本地时区算，本周从**周一 00:00** 起）。
- 二层 Tabs 再切维度：**总览**（「全部」与「其中子代理」两行）、**按模型**（人类与子代理**合并**成一行：
  同一模型不拆，用量是两个桶之和）、**按会话**（用量降序取前 20；行上标出子代理会话，并可切「只看子代理
  会话」——子代理会话单个用量小，混排时会被行数上限挤掉）。
- 每一行都是同一个形态：**label 在上，下面横向排布各个单项**，单项内部是「标签在上、值在下」。
  单项依次是：**输入（含缓存输入）· 缓存输入 · 缓存命中率 · 输出 · 推理 · 事件**——缓存输入占总输入
  （含缓存）的比例即命中率。**没有单独的合计项**；排序按「输入（含缓存）+ 输出」（不显示）。
- 只反映**库里现有**的用量：删掉的会话与 GC 回收掉的孤儿行都不再计入。

### 接缝（页面用到的既有面）

| 动作         | 接缝                                                                                                                  |
| ------------ | --------------------------------------------------------------------------------------------------------------------- |
| 列表与标题   | `POST /api/morlay/v1/session/rows`（`@morlay/session-rdb`：完整语料 + 标题 + 最后活动时间 + 工作区归属）              |
| 归档         | `ctx.uiWorkspace.archiveSession`（上游 ui-workspace，未归档行提供）                                                   |
| 取消归档     | `ctx.uiWorkspace.unarchiveSession`（上游 ui-workspace，已归档行提供）                                                 |
| 导出         | `POST /api/morlay/v1/session/export`（`@morlay/session-rdb`，直接下载 zip）                                           |
| 删除         | `POST /api/morlay/v1/session/delete`（`@morlay/session-rdb`，仅已归档行可用）                                         |
| 导入为新会话 | `POST /api/morlay/v1/session/import`（`@morlay/session-rdb`，不带 `sessionId` = 新建会话）                            |

### 数据位标注（`data-*`）

只标「最小身份 + DOM 读不出的状态」：视图 / 维度由 `data-view`、`data-tab`、`data-usage-tab` 表达，
行内合计与明细、行标题这类页面上直接可见的内容不再重复标注。

| 标注                                                        | 位置               | 含义                                                            |
| ----------------------------------------------------------- | ------------------ | --------------------------------------------------------------- |
| `data-view`                                                 | 页面根             | `sessions` / `usage`                                            |
| `data-tab`                                                  | 一层 tab 按钮      | 该按钮切到的视图                                                |
| `data-action`                                               | 按钮               | `import` / `gc` / `archive` / `unarchive` / `export` / `remove` |
| `data-filter`                                               | 过滤器             | `search` / `subagents` / `usage-subagents`                      |
| `data-scroll`                                               | 滚动容器           | `page`（会话列表与统计各一处）                                  |
| `data-session-id` / `data-archived` / `data-subagent`       | 会话行             | 该行的会话 id 与状态（`true` / `false`）                        |
| `data-pagination` / `data-page-current` / `data-page-total` | 分页条             | 当前页与总页数                                                  |
| `data-notice` / `data-failure` / `data-status`              | 顶部提示与空态     | 结果、错误、`empty` / `empty-search`                            |
| `data-usage-view` / `data-usage-tab` / `data-usage-range`   | 统计视图与二级 tab | 当前维度（`overview` / `models` / `sessions`）与时间范围        |
| `data-range`                                                | 时间范围选项       | 该选项对应的 range 值                                           |
| `data-usage-cell` / `data-usage-value`                      | 总览格子           | 维度键与原始数值（未格式化）                                    |
| `data-usage-key`                                            | 统计划表行         | 维度键（日期 / `provider / model` / 会话 id / `subagent`）      |
| `data-subagent`                                             | 统计的按会话行     | 该行是否子代理会话（`true` / `false`；其余维度不带）            |
| `data-usage-status`                                         | 统计状态行         | `loading` / `error` / `empty`                                   |

时间范围的按钮与维度 tab 共用**同一套官方 tab 条视觉**（文字 13/16 wt500、选中态品牌蓝 + 2px 下划线，
取自会话头部的 `ConversationRoot.module.css`）。

### 已知限制

- 只有「最近活动在前」一种排序，没有分组与批量操作；分页在后端（每次只取当前页 20 条，翻页与搜索
  都重新请求）。
- 子代理派生会话默认不列；勾选后出现并带「子代理」标记，但这些行不可删除（它们未归档）。
- 没有 summary 的成员（例如已从 host 消失的归档 id）不产生行。
- 导入只接受含会话日志 artifact 的 zip；导出只导出该 artifact（不含附件等旁路数据）。
- 统计是一次全库聚合，只在进入统计视图时请求一次；按会话的行是各会话自己的日志口径（fork 子会话含
  继承前缀），所以各行之和 ≥ 总量；「其中子代理」与另一侧相加正好等于总量。

### 判据

[`page.spec.tsx`](../../src/client/__tests__/page.spec.tsx)（jsdom，直喂 props 的组件用例）：

- **框架类名**：标题行、内容列、过滤 chip 行、搜索行带上 `ConversationManagerPage.module.css` 那几档类；
  过滤 chip 是 `role="group"` 里的 `aria-pressed`（不是 tab 条），选中那档带 `filterTabActive`；
- **滚动分区**：标题行 / 过滤行 / 搜索行 / 列表在**同一个** `.pageScroll` 层里（`data-scroll="page"`），
  统计视图同样在这一层；
- **状态态**：`data-status="loading" | "empty" | "failure"` 那三个状态带 `.status` 类且此时不画框架；
  搜索无结果（`data-status="empty-search"`）相反——框架留着，空态落在列表位置；
- **清空搜索**：有查询时出现，点了清空并还原列表。

**几何**（960px 上限、28px + macOS 顶栏让位、`.status` 的整屏居中）住在 `ConversationManagerPage.module.css`：
jsdom 没有布局，用例只钉结构与类名，真几何在浏览器里核对（与 `ui-primitives` 同一条规矩）。

## 取舍

- **页面框架不自造原子**：上游没有共享的 `pageHeading` / `filterTabs` 原子——它是各一级页面自己 CSS Modules
  里的同一套度量。我们照那套度量写一份页面自己的 module（而不是往 `ui-primitives` 里加我们自己的 tab 条 /
  搜索框原子）：本包是唯一消费者，进了基础面反而要多养一份没人共用的导出（`Tabs` / `SearchInput` 两件已随本
  次改动删除）。
- **归档集管理动作收敛到这一页**（理由见
  [`ADR-归档集管理动作归对话管理页`](../../../../bundles/better-session/.agents/adrs/20260918-归档集管理动作归对话管理页.md)）：
  上游设置页没有「已归档会话」入口，管理动作需要一个完整集合的落点。
- **不借官方 `session/list`**：它按部署策略默认排除已归档，且缺标题与最后活动时间；两条路混用会让
  「缺席即删除」的语义与归档集判定互相污染。
- **不做前端过滤 / 分页**：成本随会话数线性增长，而后端已经有完整语料与分页参数通道。**例外**是统计
  按会话维度的「只看子代理会话」：数据（全库聚合）已在手上，过滤不产生新请求。
- **按模型不拆子代理**：模型行的价值是「哪个模型花了多少」，子代理用的是同一个模型，拆行只会把同一模型的
  成本打散；子代理口径只在总览的「其中子代理」与按会话的标记 / 开关上体现。
- **不做常驻刷新**：页面是只读面板，动作成功后重拉一次即可。

## 开放问题

- 统计视图的分页与导出：按会话维度只取前 20，超过时目前只能靠时间范围收窄。
- 孤儿 GC 的进度反馈：现在只有不可关闭的等待弹窗，长库上的耗时不可见。
