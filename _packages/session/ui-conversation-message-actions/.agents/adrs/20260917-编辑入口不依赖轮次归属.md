# 编辑入口不依赖轮次归属

状态：已采纳

背景：`user/message` 自身的 `eventSeq` 已足够定位服务端撤回边界，客户端持有 `turn` 只是渲染面上的便利
字段；而轮外消息（`location` 无 turn/step 的已落定 user 消息）没有可用的轮次边界。

**决定**

编辑（`recall`）的入口条件只看消息是否存在可编辑文本块，不要求消息落在某个 turn/step：轮外消息同样显示
「编辑」按钮，服务端撤回边界取该消息自身 seq（`user/message` exclusive drop），截断该消息及其后全部内容，
与轮内 followup 的规则一致。

**考虑过的选项**

- **保持轮次归属作为入口条件**：轮外消息没有可用轮次边界、按钮不显示，这类已落定消息会失去就地编辑撤回
  入口。
- **轮外消息回退到「清空整个会话」（boundary -1）**：会连带删除轮外消息之前的已落定内容，超出「撤回该
  消息及其之后」的语义。
- **给未落定的排队气泡（inbox steering 投影 / 本地提交回显）加编辑入口**：这些气泡由上游 `ui-chat` 的
  ChatView 内部硬编码渲染，不经任何 slot，插件层无法注入按钮；替换方案（自定义 conversation node + CSS
  隐藏上游气泡）依赖上游 DOM 属性约定，风险不划算。不做，排队项继续走 composer 队列条。

**后果**

- `EditableMessageBlock.turn` 是可选字段：客户端编辑入口在无轮次归属时省略它；`plan.ts` 的
  `editableMessages` 对轮内消息仍填轮号。
- 撤回边界语义见 [设计 20260917-编排层操作语义](../designs/20260917-编排层操作语义.md) 的「就地编辑语
  义」；实现见 [`src/plan.ts`](../../src/plan.ts) 的 `recallBoundary`（轮内规则 + 轮外 exclusive drop）。
