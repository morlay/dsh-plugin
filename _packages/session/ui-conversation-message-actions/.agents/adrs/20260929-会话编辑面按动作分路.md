# 会话编辑面按动作分路

状态：已采纳

背景：会话编辑面原先只有一条 `POST /api/morlay/v1/session/editor`，动作写在 body 的 `action` 字段里
（`edit` / `reroll` / `retry` / `rewind` / `recall` / `fork`）。同一个 body 形状要按动作分派：路由表上
看不出这个面有几种能力，参数解码也只能在读到 `action` 之后才分岔。

**决定**

**一条动作一条路径**：`/api/morlay/v1/session/{edit,reroll,retry,rewind,recall,fork}`——**路径定动作**，
body 只带该动作的参数（不再有 `action` 字段）。host 侧按 `SESSION_EDITOR_PATHS` 注册六条 exact 路由
（`registerHttpRoutes`），解码按路径给的动作走（`decodeOperation(value, action)`）；浏览器半按
`operation.action` 取路径、发出的 body 去掉 `action`。路径 home 是 `shared.ts` 的 `SESSION_EDITOR_PATHS`
（host 与 client 同一份：client 半 import 同包模块，两侧不会漂移）。

**考虑过的选项**

- **RESTful 形状 `sessions/{id}/{verb}`**：webServer 只支持 exact / prefix 的**字面量**匹配，没有路径参数，
  要做得注册一条 prefix 再自己 split 路径段，把路由匹配与 404 语义都搬到本层；收益只是 URL 好看。
- **保留一条路径 + body 里的 `action`**：现状，路由表与能力清单对不上。
- **六条路径 + 保留旧 `/editor` 兼容入口**：两套路径并存，测试与文档都要覆盖两份，且旧入口没有真实调用方
  （本仓库的浏览器半同步改）。

**后果**

- 每条路径只接自己的参数；缺字段仍 400、编排冲突仍 409、非 POST 仍 405，逐条一致。
- 与上游官方路由分开的前缀不变（见 [ADR-管理面HTTP路由前缀与上游分家](../../../session-rdb/.agents/adrs/20260929-管理面HTTP路由前缀与上游分家.md)）。
- 编辑动作的清单从「解码函数里的 switch」变成「路由表 + 路径常量」，加一个动作要同时加路径与分支
  （`SessionEditorAction` 由 `SESSION_EDITOR_PATHS` 的键推导，漏一处编译就报）。
