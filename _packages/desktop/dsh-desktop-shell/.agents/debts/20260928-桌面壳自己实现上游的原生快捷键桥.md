# 桌面壳自己实现上游的原生快捷键桥

状态：触发中（桥在 `src/shortcuts.ts` / `src/keybindings.ts`，上游改契约就要跟着改）

**现象**

上游 `@deepseek-ai/dsh-client-shortcuts` 的 client 半按 `document.documentElement.dataset.platform` 判运行时
（`vendor/deepseek-harness/packages/client/shortcuts/src/client/dom.ts:17`）：该属性在（我们的壳会写）就是 desktop，
此时它**强制要求** `window.dshDesktop.keyboard`，缺了在构造函数里抛 `Desktop keyboard bridge unavailable`
（同包 `src/client/index.ts:44-46`）。这个服务是 `ui-layout`、`ui-sidebar-*`、`ui-approval`、`ui-settings-general`
等 client entry 的前置：它 failed 会让依赖它的 entry 一起不激活（前端只显示
`@deepseek-ai/dsh-client-shortcuts: failed` 加一长串 pending）。

自研壳不加载上游 `apps/desktop`
（[ADR-20260917-自研离线桌面打包器而非直接用上游桌面应用](../../../../../.agents/adrs/20260917-自研离线桌面打包器而非直接用上游桌面应用.md)），
这份桥只能自己实现——主进程侧是上游 `vendor/deepseek-harness/apps/desktop/src/keyboard.ts` 的裁剪移植（去掉菜单、
webview guest 拦截、overlay 输入阻塞）：

- 设备偏好：`src/keybindings.ts`（上游 `ShortcutPersistence` + 原子写，落在 `userData/keybindings.json`）；
- 原生按键转发：`src/shortcuts.ts`（按已绑定键过滤、支持两键组合、`revision` 不匹配即丢弃）；
- 契约暴露：`src/preload-app.ts` 暴露 `window.dshDesktop.{keyboard,shortcuts}`。

两个上游包（`dsh-client-shortcuts` / `dsh-atomic-write`，连带 `dsh-util-values` / `dsh-util-crypto`）靠
`tsdown.config.ts` 的 `inline` 进壳产物——`app.asar` 解析不到上游包，边界由
[`shell-import-boundary.spec.ts`](../../src/__tests__/shell-import-boundary.spec.ts) 守。

**影响**

- 上游改 `DesktopKeyboardApi` / `DesktopShortcutsApi`（新增必填方法、改手势字段、改 revision 语义）时，我们的
  实现不会编译报错，只在桌面真机表现为快捷键失灵或 boot 失败。
- 上游新增桌面能力（原生菜单加速键、webview guest 键拦截、编辑键注入）在我们壳里**没有**，属有意裁剪，不是缺陷。

**触发条件**

升级 `DEEPSEEK_HARNESS_VERSION` 后桌面形态起不来、或快捷键失灵时，先对照上游 `apps/desktop/src/keyboard.ts` /
`apps/desktop/src/preload-app.ts` 的契约与 `packages/client/shortcuts/src/native.ts` 的消费面。

**销账条件**

Done when：上游把这份桥做成与壳实现无关的形态（例如由 host 半承载、或 desktop runtime 不再强制要求原生桥），
或我们改为直接复用上游桌面应用（即 ADR-20260917 那条决定被推翻）。

**不修的理由**

裁剪版覆盖的是桌面日常路径（主窗口快捷键、Esc Esc 停止、关闭窗口动作）；菜单与 guest 拦截依赖上游桌面应用的整套
窗口 / 菜单结构，跟着移植等于把上游 `apps/desktop` 搬进来——那正是 ADR-20260917 否掉的路。
