# 开发态客户端：自研 web 层与统一资源路径

**一句话**：开发态的客户端不再用上游那套（模块表 `__ModuleLoader__` 工厂协议、combo `??`、`frontend-static`
的产物页面、token 认证），而是我们自己的「HTML + 入口 + 预处理」三件套。**所有包——仓库里的和三方的——
走同一个访问路径格式**：

```
/plugins/{pkg}/{version}/{export}?rev={hash}
        │     │         │        └─ 产物内容 hash；可省（服务端也算得出来）
        │     │         └─ 出口名，默认 `_default`（= 清单的 "." 出口）
        │     └─ 包清单的 version（三方包同样有）
        └─ 包名，`/` 转义成 `+`（`@scope/name` → `@scope+name`）
```

## prebundle：一个包的一个出口 → 一份产物

| 项         | 规则                                                                                                                                             |
| ---------- | ------------------------------------------------------------------------------------------------------------------------------------------------ |
| 键         | `(pkg, version, export)`——不是文件，也不是"整包"                                                                                                 |
| 入口       | `exports["./<export>"]`；`_default` → `exports["."]`；三方包无 `exports` 时取包入口                                                              |
| 打包       | rolldown 一份 ESM：**包内**（相对导入、同包引用）inline；**样式**（`.module.css`）与**资产**（`.svg`…）inline；**跨包**引用 → 对方**同格式 URL** |
| 跨包的 rev | **不带**：rev 由"对方的产物"算出，带了就是循环；URL 里可选，服务端每次算                                                                         |
| rev        | 产物**内容 hash**（源码改了 hash 就变，浏览器自然拿到新版）                                                                                      |
| 缓存       | `(pkg, version, export)` → `{ code, rev }`（dev 内存即可）                                                                                       |
| 解析不到   | **报错**，不静默                                                                                                                                 |

## 流程图

```
① 页面
   浏览器 GET /                              ← 我们注册的 exact 路由（上游 frontend-static 只服务构建产物，
   │                                            源码面没有 index.html，所以它那条是兜底 404）
   └─ 骨架 + <script type="module" src="/plugins/.app/entry.js">
      上游注入的引导器 / __DSH_BOOT__ / combo script 全部**剥掉**：那是模块表的协议，与 ESM 互斥
      （它期望每个 bundle 是 classic script 且体内调 `window.__ModuleLoader__.load({id, factory})`）

② 入口（我们生成）
   浏览器 GET /plugins/.app/entry.js
   └─ import { Context } from "/plugins/@deepseek-ai+cordis/0.2.1-alpha.2/_default"
      import "/plugins/<pkg-a>/<version>/client"
      import "/plugins/<pkg-b>/<version>/client"     …每行一份
      const ctx = new Context()
      for (const mod of [...]) await mod.apply(ctx)   ← 每个 client 入口导出 `{ apply, inject }`

③ 资源（统一路径：我们的包与三方包**同格式**）
   浏览器 GET /plugins/<pkg>/<version>/<export>?rev=<hash>
   │
   ├─ 命中缓存 ──────────────────────────────→ 直接下发
   │
   └─ 未命中 → 预处理（服务端）
        · 定位包：交给 node 解析（`createRequire(importer).resolve`）——pnpm 已按依赖关系把
          node_modules 摆好了，我们不扫目录、不自己建索引
        · 入口：仓库包取它 `exports` 的出口；三方包取它的包入口
        · rolldown 打包（一份 ESM）：
             包内（相对导入、同包引用）…… inline
             样式（.module.css）、资产（.svg 等）… inline
             跨包引用 ……………………………… → **又一条 /plugins/<dep>/<version>/<export>**（同格式，递归③）
             解析不到 …………………………………… → **报错**（静默 external 只会把问题推给浏览器变成 404）
        · rev = 产物内容 hash → 写缓存 → 下发

④ 变化
   源码改了 → ③ 重新预处理 → rev 变 → 引用带上新 rev → 浏览器自然拿到新版
   （`cache-control: no-store`，dev 不担心陈旧）
```

## 关键决定

| 决定                                                        | 原因                                                                                |
| ----------------------------------------------------------- | ----------------------------------------------------------------------------------- |
| **一个路径格式**（`/plugins/<pkg>/<version>/<export>?rev`） | 三方包与仓库包在"访问"这件事上没有区别；区分它们只会让规则分叉                      |
| **rev 是内容 hash**                                         | "有变化就更新"由 hash 自己表达，不需要额外的失效协议                                |
| **跨包引用 external 成同格式 URL**                          | 改一个包不必重打别的包；浏览器按 URL 递归取                                         |
| **包内 inline**                                             | 相对路径交给浏览器会被按根路径解析（`./x` → `/vendor/…` 那种 404）                  |
| **解析不到报错**                                            | 早暴露；静默降级会让问题在浏览器里以 404 的形式出现，更远                           |
| **依赖解析交给 node**                                       | pnpm 已经把依赖摆好，`createRequire(importer).resolve` 就是它的规则                 |
| **剥掉上游 boot/引导器/认证**                               | 模块表那套（classic script + 工厂 + `__DSH_BOOT__`）与按 ESM 直访互斥；我们自研装配 |

## 当前进度与差距

- ✅ 页面 HTML 接管、入口自研、按出口/包的预处理与缓存、样式与资产 inline、跨包 external、解析失败报错；
- ⏳ **统一路径**：现在仓库包走 `/plugins/<pkg>/<export>`（出口面），三方走 `/plugins/.deps/<file>`，
  要合并成上面①②③里的**同一个** `.deps/<pkg>-<rev>.js`；
- ⏳ **装配**：入口已经在 `apply(ctx)`，但还没验证页面真的挂载出内容（web 壳的 root 挂载）；
- ⏳ **HMR**：vite 那套机制（模块级替换 + 事件通道）还没做。
