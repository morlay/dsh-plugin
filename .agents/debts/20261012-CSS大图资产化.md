# CSS 里的图片资产：两条链都内联（已决策）

**现象**：`ui-chat` 的 `ChatView.module.css` 用 `url('./running-whale@2x.png')` 引用 21.6KB 掩膜图；上游
client 构建把它当**资产**产出（`apps/web/vite.config.ts` 的 `assetFileNames` → `assets/[name]-[hash][extname]`，
vite 默认 4KB 阈值以内的才内联）。本仓库的 `@local/devkit` 样式管线（lightningcss）不做 URL 解析，先前既
没内联也没产出资产——浏览器按当前页面去请求相对路径、404，鲸鱼掩膜不显示。

**现状**：两条链都先走**全内联**（`cssInlinePlugins({ assets: "inline" })`）。dev 形态的产物是自包含单文件，
内联是唯一选择；发布形态这样会把图片 base64 塞进引用它的每个 bundle（21.6KB → ~29KB/份）。

**决策（2026-10-12）**：**发布线也内联**——不为资产再开一条"产出 + 服务"的路，包体让 tree-shaking
与后续的 dev ESM 直访改造去解。下面记的是"不内联"为什么当时做不到，留作日后重启这条路的背景。

**为什么"都不内联"暂时做不到**：资产需要一个**运行时可达的 URL**，而两条路径都不通——

- 现场打包（`bundleClientFactory`）产的是**单文件 chunk**（`codeSplitting: false`，只取 `chunk.code`），
  没有放资产的位置；
- 上游的 `/plugins/<id>/<fileName>` 路由（`@deepseek-ai/dsh-client-modules`）把 `fileName` 固定成
  `client.js`，只服务 JS——没有资产位，而那是上游包（红线不可改）。

`threshold` 策略（`cssInlinePlugins({ assets: "threshold" })`，4KB 阈值 + `emitFile`）已实现但**未启用**：
启用它还得解决 URL 回填——`emitFile` 返回带 hash 的引用 id，CSS 里的相对 URL 要等 `generateBundle`
才知道最终文件名。

**判据**：上游路由支持资产（或我们有一条自己的资产路由）之后，发布产物里 `*.png` 落成资产文件、CSS 指向
它；在那之前两条链保持全内联。
