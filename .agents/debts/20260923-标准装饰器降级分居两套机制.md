# 标准装饰器降级分居两套机制

状态：未销账

**现象**

上游 typert 用标准（TC39）装饰器标记远程面（`@Remote('prompt')`），而 oxc（Vite 8 / rolldown）不降级标准
装饰器。本仓库三条链现在各走一套：

| 链 | 降级机制 |
| --- | --- |
| 开发与桌面 dev（`--import=@local/devkit/ts-loader`） | oxc **legacy** 降级 |
| 测试（vitest） | oxc **legacy** 降级（`oxc: { decorator: { legacy: true } }`——Vite 的 oxc 转换 Omit 了 `tsconfig`，但留下了 oxc 自己的变换选项） |
| 发布构建（tsdown 打包本仓库 dist） | `standardDecoratorsPlugin`（esbuild **标准**降级），dist 保持 TC39 语义并 external registry 官方包 |

两套降级语义能同时工作，是因为写端被 patch 成同时接受两种协议
（[decorator-dual-protocol.patch](../../patches/decorator-dual-protocol.patch)：typert 的
`Remote`/`RemoteScope` 与 cordis 的 `Inject`）。决策见
[ADR-开发与桌面消费上游源码面](../adrs/20261010-开发与桌面消费上游源码面而非lib产物.md)。

**影响**

- 装饰器语义分工在两套机制之间：动任一侧都要同时看另一侧（开发面 legacy、测试与发布面 TC39）。
- 测试链自己有两个落点，要一起看：`vitest.config.ts` 的 `oxc: { decorator: { legacy: true } }` 管 Vite
  模块图内的转译，`test.execArgv` 注入的同一个 oxc loader 管 cordis Loader 的运行期动态 import（缺它
  那些行报 `never started`）。它没有独立的预转换插件，也没有按包树列举的 scope。

**触发条件**

oxc 实现标准装饰器降级、或本仓库接入可用的 TS 转译 API 时，三条链可以统一降级语义；上游把 `@Remote`
改成命令式调用时，写端 patch 可以退场。

**销账条件**

满足任一条：三条链统一到同一套降级（例如 oxc 支持标准降级后全部走它）且写端 patch 删除；或测试链不再
需要预转换（插件与 scope 都可删）。

**不修的理由**

统一要等 oxc 的实现；写端 patch 是「开发面走 legacy」的必要代价，只改两个函数、随 `just vendor sync`
重放（失效即信号）。
