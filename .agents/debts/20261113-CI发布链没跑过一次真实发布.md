# CI 发布链没跑过一次真实发布

状态：未销账——publish job 已改到当前工具链（`just prepare` → `just dts` → `just build` → `just publish`），但还没有一次成功的真实发布记录
位置：`.github/workflows/release.yml`（publish job）；根 `justfile` 的 `publish` / `publish-npm`

**现象**

publish job 走 `just publish`：检测到 `GITHUB_ACTIONS` 后逐包 `pnpm publish --registry https://npm.pkg.github.com/`，
版本未发布的才发。发布集合的 25 个包版本仍是 `0.0.1`、npmjs 上一个版本都没有，说明这条链只在 `main` / `next`
推送时被触发过、没有一次走到「发布成功」。

**影响**

GitHub Packages 通道未经实证：认证（`GITHUB_TOKEN`）、`@morlay` 的 scope 映射、逐包权限都只在真跑时才会暴露。

**触发条件**

下一次 `main` / `next` 推送（工作流自动触发），或首次正式发版。

**销账条件**

Done when：CI 的 publish job 完成一次真实发布，`pnpm view @morlay/<包> --registry https://npm.pkg.github.com/` 能解析；
且 `just publish` 在本地仍恒 `exit 1`（红线不变）。

**不修的理由**

要等一次真实发版；GitHub Packages 的认证与权限在本地无法模拟。
