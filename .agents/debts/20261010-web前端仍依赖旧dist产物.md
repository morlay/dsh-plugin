# web 前端仍依赖旧 dist 产物

状态：未销账

**现象**

`just custom dev --web` 的首页由 host 的 `frontend-static` 从磁盘读 `@deepseek-ai/dsh-web-frontend/dist`
（`apps/web` 的 vite 构建产物）。源码面改造后 `lib/` 不再构建，但这份 dist 仍是**升级前留下的旧产物**：
vendor 里 `git reset` 不删未跟踪文件，所以它还在、页面也能打开——一旦缺失（新 clone、或显式清理），
首页会 404 白屏（`frontend-static` 把 `ENOENT` 吞成 404，静默失败）。

**影响**

- 升级流程里 `build:web` 跳过后，dist 既不重建也不删除——"能用"与"用的是哪一版"都不可见。
- 前端代码改动不会反映到页面（dist 是旧的）。

**触发条件**

按 [ADR-开发与桌面消费上游源码面](../adrs/20261010-开发与桌面消费上游源码面而非lib产物.md) 做
「host 内 prebundle 缓存 provider」时销账：新增 desktopify 的 `dev-frontend` 行（named route 抢
`/`、`/index.html`、`/assets/`，内容由 rolldown 现场编译 + 缓存），并放宽壳的启动断言
（`dsh-desktop-shell` 里对 `dist/index.html` 的存在性断言）。

**销账条件**

两个形态都不再需要 `apps/web/dist`：页面由 provider 提供，`frontend-static` 的 distIndex 只在打包形态
（registry 官方包）里生效。

**不修的理由**

provider 要复刻 vite 管线的等价物（CSS Modules、JSX、5 个静态链接库包、`__DSH_BOOT__` 注入的
`renderIndex` + `<base href="./">`），属于独立一段工作；当前 dist 在场，页面可用，先把它记成债而不是
半做一半。
