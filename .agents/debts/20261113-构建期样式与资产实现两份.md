# 样式与资产的实现有两份：构建期一份、运行期一份，同源不同家

状态：未销账——两份并存，各自被一条链用着，代码段今天逐行同源
位置：`devpackages/tsdown-plugin-cordis/src/css.ts`、`devpackages/tsdown-plugin-cordis/src/assets.ts`、
`packages/zephyr/zephyr-app/src/cordis-assets/styles.ts`、`packages/zephyr/zephyr-app/src/cordis-assets/assets.ts`；
调用点是 `devpackages/tsdown-plugin-cordis/src/cordis-host.ts`（tsdown 构建）与
`packages/zephyr/zephyr-app/src/federation/bundle.ts`（运行期联邦预打包）

**现象**

同一套能力有两份实现：样式编译（CSS Modules 的 `[hash]_[local]`、`?inline`、`url()` 的内联与阈值）与
资产内联（mime 表、`?raw`、`node:*` 替身、`inline` / `threshold` 两条策略）。两份的函数体今天逐行一致，
差异只有三处：文件头的说明、跨文件 import 的路径（`./styles.ts` → `./css.ts`）、`node:*` 替身的默认路径
（构建期那份指向本包自带的 `src/node-stub/node-stub.cjs`）。

**影响**

两份各自漂移时症状互不相同，而且都不指向这里：class 名或注入形态不一致 → 同一个包的 tsdown 产物与联邦
产物在页面上各注入一次、样式互相盖住；新增的资产扩展名只加在一份里 → 另一条链报 `PARSE_ERROR`
（rolldown 把未知扩展名当 JS 解析）。

**触发条件**

动这两条链的任何一侧（改 CSS Modules 的处理、加资产 mime、改阈值）之前必须同时看另一份；上游
`@morlay/dsh-cordis-assets` 换版时也是两份一起对。

**销账条件**

Done when：实现只有一处——`grep -rl 'cssModules: { pattern' packages devpackages` 只命中一个文件，
两条链都从它 import。

**不修的理由**

本步只迁构建期插件：让 `zephyr-app` 开出口或新建共享包都落在 `packages/**`（本次不改），而拆包要连带
改运行期那条链的 import 与 `nodeStub` 的传递方式——那是运行期的事，与"让清单不再手写"不是同一件事。
两份今天逐行同源，漂移一次就能被 `diff` 看见。
