# 债：`tsc` 的 9 条红

状态：**已销账**（2026-11-19）。

`pnpm exec tsc --noEmit -p tsconfig.json | grep -c '^packages/'` = **0**。
（`vendor/**` 里还剩它自己的几条，那是上游的，与我们的门禁无关。）

## 它原来是什么

9 条：`bootstrap.ts` ×2、`scoped-rows.spec.ts` ×1、`dsh-{job,ptc,sandbox,skill}` 的 spec ×4、`session-mode.service.ts` ×1。
全是 `Context` ↔ cordis `Context` 的单层断言报 TS2352（两个类型「不够重叠」）。

## 真因（记下来，别再踩）

`@deepseek-ai/cordis` 只解析到**一个**副本（`vendor/deepseek-harness/vendor/cordis`）——不是「两个副本」。
问题是**同一个文件的两种 specifier 会被 TS 当成两个模块**：

- 模块增强写在 `declare module './context.ts'`（**相对** specifier，见 `events.ts:34` / `fiber.ts:10`）；
- 我们的代码 `import … from "@deepseek-ai/cordis"`（**包名**）——拿到的 `Context` 是**没有增强的基础版**；
- 于是 `ctx as CordisContext` 两边对不上。

## 怎么销的

**我们的代码不直接引上游的 `Context`**——用 `@morlay/zephyr` 的 `Context`（它已经补了 `logger` / `root` / `reflect` / `get`，
并且是「我们的体系」里唯一该出现的那个）。深路径只允许留在**桥接层**（`zephyr/src/{injection,logger,compat/*}`，那里就是干这个的）。

这条与 `packages/zephyr/zephyr/.agents/standards/how-to-write.md` 的「依赖必须显式声明」同源：
**别直接把上游那种会污染类型的形状引进我们的代码**。
