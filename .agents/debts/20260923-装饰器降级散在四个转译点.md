# 装饰器语义（legacy）由四个转译点各自决定，写端还得替上游补一条类型面

状态：未销账——四条链各写着一次 `legacy`，改一处必须同时看其余三处与写端补丁
位置：`pnpm-workspace.yaml`（`nodeOptions`）、`packages/boot/dsh-oxc-node/register.mjs`、`vitest.config.ts`、`packages/zephyr/zephyr-app/src/federation/bundle.ts`、`tsconfig.json`、`vendor/patches/decorator-dual-protocol.patch`（由 `vendor/steps.ts` 登记）

**现象**

全仓只有一个装饰器语义：legacy（`experimentalDecorators`）。它被写了四遍——四个转译点各一遍，用的还是不同的转译器与不同的开关名字：

| 链                               | 转译者                                                       | `legacy` 从哪来                                                                                                        |
| -------------------------------- | ------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------- |
| 宿主与 dev 的 node 进程          | `@oxc-node/core/register`（工作区 `nodeOptions`）            | 就近的 tsconfig（根 `tsconfig.json` 的 `experimentalDecorators`）；该包自带 legacy 的 `__decorate` 助手                |
| 随包运行时（壳、`preview` 闭包） | `packages/boot/dsh-oxc-node/register.mjs` 的 `oxc-transform` | 硬编码 `decorator: { legacy: true }`（连同 `target: es2022`）                                                          |
| 测试                             | vitest 自己的 oxc 转译                                       | `vitest.config.ts` 的 `oxc: { decorator: { legacy: true } }`；测试模块走 vite 的管线，不经过 `nodeOptions` 那个 loader |
| 客户端 bundle                    | `zephyr-app` 的 `bundlePackage`（rolldown）                  | `transform.decorator = { legacy: true }`，加上摆正 cwd 与 `resolve.tsconfigFilename`（外置包祖先链里没有 tsconfig）    |

写端是我们自己的声明：`Injectable`（`packages/zephyr/zephyr/src/token.ts`）、`Remote` / `RemoteGroup`（`packages/zephyr/zephyr-app/src/remote/decorators.ts`）、`Slot`（`packages/zephyr/zephyr-app/src/client/renderer/slot.decorator.ts`）都返回 legacy 的 `ClassDecorator` / `MethodDecorator`。上游 typert 的 `Remote` / `RemoteScope` 与 cordis 的 `Inject` 只写了 TC39 签名，而根 `tsconfig.json` 开着 `experimentalDecorators`，于是 `@Remote(…)` 在根 program（`include` 覆盖 `vendor/**`）的类型检查里报 `TS1241`——本地补丁给这两个文件补上 legacy 调用签名（`RemoteTypedMethodDecorator` 与 `RemoteMethodDecorator` 各一条重载、`Remote` 的裸用法多一条 `(target, propertyKey, descriptor)` 分支、`Inject` 的返回类型多收 `(target)`）。

**影响**

漏一处只坏一条链，症状各不相同：dev/宿主编译漏了 → 进程起不来（装饰器原样留着，`SyntaxError: Invalid or unexpected token`）；随包运行时漏了 → 壳与 `preview` 跑不起来，同一条错；客户端 bundle 漏了 → 浏览器整块 `SyntaxError`、入口整条不执行（`packages/zephyr/zephyr-app/src/__tests__/bundle.spec.ts` 的两条用例守这条）；写端补丁没重放 → `@Remote(…)` 报 `TS1241`。

测试链那一处**没有用例守**：删掉 `vitest.config.ts` 的 `oxc` 块之后，`packages/zephyr/zephyr-app/src/__tests__/remote-client-forwarder.spec.ts`（读 `@RemoteMethod()` 的 descriptor）与 `packages/agent/dsh-agent-loop/src/__tests__/agent-module.spec.ts` 仍绿——今天它只被 tsconfig 的默认兜着。

**触发条件**

动上述任一转译点、升级 oxc / vite / vitest / rolldown、或做上游同步（补丁要重放）之前必须先看这条。眼下没有卡住的地方。

守护面：`packages/zephyr/zephyr-app/src/__tests__/bundle.spec.ts` 的「装饰器在产物里必须已被转译，且**不依赖进程 cwd**」（断言产物里没有 `@Remote`、有 `__decorate`）与「包住在没有 tsconfig 祖先的地方时，`resolve.tsconfigFilename` 也能让它转」；跑法 `just test packages/zephyr/zephyr-app/src/__tests__/bundle.spec.ts`。写端类型面没有独立命令：它随声明生成（`@local/dts-prepare`，根 `tsconfig.json` 为口径）走到 `tsc` 时才暴露。

**销账条件**

Done when：legacy 只剩一处声明（根 `tsconfig.json`），另三个转译点从它派生或直接删掉，且上游写端不再需要本地补丁。判据：删掉 `packages/boot/dsh-oxc-node/register.mjs` 的 `decorator` 选项、`packages/zephyr/zephyr-app/src/federation/bundle.ts` 的 `transform.decorator`、以及 `vendor/steps.ts` 里的 `decorator-dual-protocol.patch` 之后，`just test` 与声明生成仍绿。`vitest.config.ts` 的 `oxc` 块按实测现在就能删。

**不修的理由**

四条链的转译器不同（`@oxc-node/core`、自研的 `@morlay/dsh-oxc-node` 入口、vitest 的 oxc、rolldown），读配置的姿势也不同：随包运行时拿不到工作区的 `nodeOptions`，客户端 bundle 的 rolldown 按 cwd 找 tsconfig（所以还要摆正 cwd 与显式指一份解析用 tsconfig）。收敛到一处要先让这几个壳都吃同一份来源。写端补丁只改类型签名与一次协议判别，随 `just vendor patch` 重放，失效即信号。
