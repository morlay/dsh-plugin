# 上游对第三方依赖的补丁跟随进根工作区，只列运行路径上用得着的

状态：已采纳——根 `patchedDependencies` 列 5 条，补丁文件借 vendor 那份
背景：上游对**第三方依赖**也打补丁（[`vendor/deepseek-harness/pnpm-workspace.yaml`](../../vendor/deepseek-harness/pnpm-workspace.yaml) 的 `patchedDependencies`，文件在 `vendor/deepseek-harness/patches/`，当前 12 条）——`@deepseek-ai/*` 是 vendor 源码，第三方依赖却来自 registry。根工作区不跟随这份清单，同一个依赖就有两份实现：上游那份带修复、我们这份不带。

**决定**

根 [`pnpm-workspace.yaml`](../../pnpm-workspace.yaml) 的 `patchedDependencies` 列**我们运行路径上需要**的条目，路径直接指 `vendor/deepseek-harness/patches/`，随 `DEEPSEEK_HARNESS_VERSION` 一起换版；补丁文件不复制进本仓库。当前 5 条：`@earendil-works/pi-ai@1.3.0`、`@fortune-sheet/core@1.0.4`、`@fortune-sheet/react@1.0.4`、`exceljs@4.4.0`、`node-pty@1.2.0-beta.15`。

**考虑过的选项**

| 选项                        | 否掉的理由                                                                                                                                                                                                            |
| --------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 照抄上游全量清单            | 上游清单里有服务它自己其它链的条目（`@electron/osx-sign` 的签名、`@yao-pkg/pkg` 的单 exe、`app-builder-lib` 的打包器自身），也有版本线与我们不同的；条目的包名 + 版本必须命中依赖图，命中不了 `pnpm install` 直接失败 |
| 只带当下踩到的那一条        | 其余条目同源（同一个依赖、同一份上游修复），下次踩到还要重新判断一遍"与我们有没关系"                                                                                                                                  |
| 把补丁文件复制进 `patches/` | 双份维护，上游更新补丁时必然漂移                                                                                                                                                                                      |

**后果**

- **包名 + 版本号写在根清单里**是硬约束：上游换依赖版本或改补丁文件名，`pnpm install` 报错即信号（改一行即可）。
- 上游补丁被当作"上游认可的第三方修复"整体接受，不逐条评估其内容；上游删掉某条，我们随版本一起失去它。
- 这份清单只管**第三方依赖**；我们打给上游工作树的补丁住 `vendor/patches/`（由 [`vendor/steps.ts`](../../vendor/steps.ts) 的 `git` 步骤逐条重放），两条路的判据在 [`zephyr-upstream-sync`](../skills/zephyr-upstream-sync/SKILL.md)。
