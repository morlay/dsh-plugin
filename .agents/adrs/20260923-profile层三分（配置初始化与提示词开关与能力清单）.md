# profile 层三分：配置初始化 / 提示词与开关 / 能力清单

状态：已采纳（第 2 条自 2026-09-24 起改由
[`@morlay/dsh-session-mode`](../../packages/profile/dsh-session-mode/README.md) 承担，且模式不再是 Cordis 子树；
见 [ADR 模式不再是 Cordis 子树](../../packages/profile/dsh-session-mode/.agents/adrs/20260924-模式不再是cordis子树.md)。下面把它读作
「提示词与能力开关 → session-mode」）

背景：`packages/preset/` 下两个 bundle 把三件事混在一起——`@morlay/dsh-preset`（host 层：llm route、
搜索后端、**禁官方沙箱两行并插替换行**）与 `@morlay/dsh-agent-preset`（两个模式的行清单里内嵌约 25 条
功能行 + 上下文通道的 isolate 组）。混装的代价是每加一个能力都要动 preset 的清单，而"某能力属于哪个
模式"与"这个能力本身是什么"是两件事；上下文通道那套更特殊：它既能被模式引用，本身又是一套完整能力。

**决定**

三条边界，各自落到一个包：

1. **配置初始化** → `@morlay/dsh-profile`（原 `dsh-preset` 改名，目录 `packages/profile/`）：patch 里
   只有按 id 的 `config` 覆盖（llm route、欢迎提示版本、`web` 的 provider 选择、沙箱规则值、界面语言 /
   默认模型 / 对话视图）与**关掉官方内置的四个 preset**（`preset-standard` / `preset-ptc` /
   `preset-minimal` / `preset-cordis`——部署只要我们自己注册的两个模式），**一行都不插**。
   profile 的用户 patch 层在 bundle 层之后应用，所以这些是默认值，用户改设置仍压得住。
2. **提示词与能力开关** → `@morlay/dsh-agent-preset`：preset 定义里只剩 persona、模式自己的开关
   （scope 白名单、`capabilities` 裁剪、read-before-edit 的抵消行）与对下面两个包的**引用**。
3. **能力清单** → 各能力包自己的 bundle：功能行归
   [`@morlay/dsh-agent-toolkit`](../../packages/profile/dsh-agent-toolkit/README.md)，注入通道那套归
   [`@morlay/dsh-context-assembler`](../../packages/context/dsh-context-assembler/README.md)；沙箱与搜索后端
   各自的 bundle 早就存在（`@morlay/dsh-sandbox-local`、`@morlay/dsh-web-search-ollama`）。

**双形态**是配套约定：一个能力包既带 `cordis.patch.yml`（`dsh.profile.bundles` 直接列出 → 行装 host
平面），也导出 `rows`（preset 引用 → 行住进该 preset 的 `isolate` 组）。两者共用一份真源，
**同一部署只能选一种**，否则同一行会被插两次。

## 考虑过的选项

- **只把 preset 的清单拆文件、不拆包**：清单仍归 preset，加一个能力还是要动 preset；
  "能力包自己带装配"这条也就无从谈起。
- **功能行直接注册到 host 平面（profile 列出 toolkit）**：行对所有 preset 生效，官方
  standard / ptc / minimal / cordis 会多出我们的工具；模式白名单只管得住我们的模式。
- **通道清单继续写在 preset 里**（现状）：`dsh-context-assembler` 就无法"直接装配"，两种采用方式只能
  手工对齐。
- **`dsh-profile` 保留禁行/插行**：它就是装配层了，与"能力包自己带装配"重复（sandbox-local 的 patch
  注释早就警告过"两种采用方式同时上线会重复插入同一行"）。

## 后果

- **`dsh.profile.bundles` 的顺序有意义**：`@morlay/dsh-sandbox-local`、`@morlay/dsh-web-search-ollama`
  必须排在 `@morlay/dsh-profile` **之前**，否则配置层按 id 找不到那两个 bundle 插的行。
- 判据落在测试里：`dsh-profile` 的 `patch.spec.ts` 组合三层后断言"官方沙箱两行被禁、替换行拿到规则、
  `web` 行切到 ollama 且注册行带 key 引用"；`dsh-context-assembler` 与 `dsh-agent-toolkit` 各有
  `rows.spec.ts` 钉住清单形状，以及 patch 与清单同源。
- 三个包各自的 `README` 与设计文档按新边界重述；`dsh-agent-preset` 的生成物 `cordis.patch.yml` 在本次
  搬迁前后**逐字节等价**（只差生成路径注释与键序），证明这是纯结构搬迁。
