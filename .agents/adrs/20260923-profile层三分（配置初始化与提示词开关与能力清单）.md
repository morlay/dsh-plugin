# profile 层三分：配置初始化 / 提示词与开关 / 能力清单

状态：已采纳

背景：一个部署要回答三件不同的事——**这个部署的配置值是什么**、**这个会话拿到哪些提示词与开关**、**某个能力有哪些行**。三件事混在一处时，每加一个能力都要动配置清单；而"某能力属于哪个模式"与"这个能力本身是什么"本来是两件事。

**决定**

三条边界，各自落到一个包（或 bundle）：

1. **配置初始化** → `@morlay/mydsh-profile`（bundle）：patch 里只有按行 id 的 `config` 覆盖（界面语言、欢迎提示版本、默认模型、对话视图；沙箱与 ollama 的值归各自的 bundle），**一行都不插、也不禁官方行**。profile 的用户 patch 层在 bundle 层之后应用，所以这些是默认值，用户改设置仍压得住。
2. **提示词与开关** → `@morlay/dsh-session-mode`：模式是 shipped preset 的**会话级扩展**，只声明 persona、工具与
   policy 的名单（`allowTools` / `denyTools` / `allowPolicies` / `denyPolicies`）、`instructions` / `skills` /
   `runtimeContext` 三个开关与可选 `defaultModel`（`preset` 字段保留，写了才在切模式时换 preset；本部署不写），
   按会话应用、子代理继承父模式。按会话收口（工具面收窄 + 两个抑制面）也在它的 `scope.ts` 里，随模式定义一起装。
3. **能力清单** → 能力包自己的数据（`rows` 出口），由 bundle 展开：工具说明归
   [`@morlay/dsh-tool-guidance`](../../packages/profile/dsh-tool-guidance/README.md)（包根即运行时）的 `rows`，注入通道归
   [`@morlay/dsh-context-assembler`](../../packages/context/dsh-context-assembler/README.md) 的 `rows`，沙箱归
   `@morlay/dsh-sandbox-local`，搜索后端归 `@morlay/dsh-web-search-ollama`，会话模式与 subagent 各归自己的包；
   功能行清单（工具 / 命令 / 压缩 / 计划模式 / 委派）**不在我们这边**——归会话挂着的 shipped preset（见
   [ADR-不再持有行清单](../../packages/bundles/session-mode-profile/.agents/adrs/20260929-不再持有行清单.md)），
   行装在哪一平面由 bundle 的 patch 决定。

**一份数据、两种平面**是配套约定：能力包只发布实现与 `rows` 出口，patch 住在 bundle 里——同一个 bundle 可以直接进
`dsh.profile.bundles`（行装 host 平面），也可以在它声明的 preset 里引用那些 `rows`（行装 preset 平面；本部署的 bundle
不声明 preset，走的是 host 平面，preset 平面那几份是官方 shipped 的）；
**同一行只能选一种平面**，否则会被插两次。

**考虑过的选项**

- **只把清单拆文件、不拆包**：清单仍归配置层，加一个能力还是要动它；"能力包自己带装配数据"这条无从谈起。
- **能力行直接注册到 host 平面**：行对所有 preset 生效，官方 shipped preset 的会话会多出我们的工具；模式白名单只管得住我们的模式（现行是工具行归 preset 平面，见 `设计 官方AgentPreset恢复与会话级扩展`）。
- **通道清单写在 preset 里**：通道就无法"直接装配"，两种采用方式只能手工对齐（现行通道在 host 平面一份，
  见 [ADR-20260923-通道作为全局服务装配不隔离](../../packages/context/dsh-context-assembler/.agents/adrs/20260923-通道作为全局服务装配不隔离.md)）。
- **配置值层顺便插行 / 禁行**：它就是装配层了，与"能力包自己带装配"重复，两份清单会漂移。

**后果**

- **`dsh.profile.bundles` 的顺序有意义**：插行 / 禁行的 bundle 排在 `@morlay/mydsh-profile` 之前，
  否则配置层按行 id 找不到那些行（[`apps/dsh-custom-next/package.json`](../../apps/dsh-custom-next/package.json)）。
- 判据落在测试里：`bundles/mydsh-profile` 的 `patch.spec.ts` 钉住"只有 config 覆盖"、`bundles/session-mode-profile`
  的 `patch.spec.ts` 钉住"装配里没有 agent preset 行、两个模式都不写 `preset`"、`dsh-context-assembler` 有
  `rows.spec.ts` 钉住通道行形状、`dsh-tool-guidance` 的 `guidance-inventory.spec.ts` 对着 shipped `standard`
  的工具集查覆盖，`dsh-session-mode` 的 `preset-plane.spec.ts` 在真装配下钉住平面归属（行清单归 shipped preset、
  注入面归官方行）。
- 三个包各自的 `README` 与设计文档按这三条边界重述。
