# profile 层三分：配置初始化 / 提示词与开关 / 能力清单

状态：已采纳

背景：一个部署要回答三件不同的事——**这个部署的配置值是什么**、**这个会话拿到哪些提示词与开关**、**某个能力有哪些行**。三件事混在一处时，每加一个能力都要动配置清单；而"某能力属于哪个模式"与"这个能力本身是什么"本来是两件事。

**决定**

三条边界，各自落到一个包（或 bundle）：

1. **配置初始化** → `@morlay/mydsh-profile`（bundle）：patch 里只有按行 id 的 `config` 覆盖（界面语言、欢迎提示版本、默认 preset、默认模型、对话视图；沙箱与 ollama 的值归各自的 bundle），**一行都不插、也不禁官方行**。profile 的用户 patch 层在 bundle 层之后应用，所以这些是默认值，用户改设置仍压得住。
2. **提示词与开关** → `@morlay/dsh-session-mode`：模式是官方 preset 的会话级扩展，只声明 `preset`（挂哪一份行清单）+ persona、`allowTools` 收口、instruction / runtimeContext 开关与可选 `defaultModel`，按会话应用、子代理继承父模式。
3. **能力清单** → 能力包自己的数据，由 bundle 展开：功能行归
   [`@morlay/dsh-agent-toolkit`](../../packages/profile/dsh-agent-toolkit/README.md) 的 `TOOLKIT_PRESET_ROWS`，注入通道与工作区指令归
   [`@morlay/dsh-context-assembler`](../../packages/context/dsh-context-assembler/README.md) 的 `rows`，沙箱归
   `@morlay/dsh-sandbox-local`，搜索后端归 `@morlay/dsh-web-search-ollama`；行装在哪一平面由 bundle 的 patch 决定。

**一份数据、两种平面**是配套约定：能力包只发布实现与 `rows` 出口，patch 住在 bundle 里——同一个 bundle 可以直接进
`dsh.profile.bundles`（行装 host 平面），也可以在它声明的 preset 里引用那些 `rows`（行装 preset 平面）；
**同一行只能选一种平面**，否则会被插两次。

**考虑过的选项**

- **只把清单拆文件、不拆包**：清单仍归配置层，加一个能力还是要动它；"能力包自己带装配数据"这条无从谈起。
- **能力行直接注册到 host 平面**：行对所有 preset 生效，官方 shipped preset 的会话会多出我们的工具；模式白名单只管得住我们的模式（现行是工具行归 preset 平面，见 `设计 官方AgentPreset恢复与会话级扩展`）。
- **通道清单写在 preset 里**：通道就无法"直接装配"，两种采用方式只能手工对齐（现行通道在 host 平面一份，
  见 [ADR-20260923-通道作为全局服务装配不隔离](../../packages/context/dsh-context-assembler/.agents/adrs/20260923-通道作为全局服务装配不隔离.md)）。
- **配置值层顺便插行 / 禁行**：它就是装配层了，与"能力包自己带装配"重复，两份清单会漂移。

**后果**

- **`dsh.profile.bundles` 的顺序有意义**：插行 / 禁行 / 声明 preset 的 bundle 排在 `@morlay/mydsh-profile` 之前，
  否则配置层按行 id 找不到那些行（[`apps/dsh-custom-next/package.json`](../../apps/dsh-custom-next/package.json)）。
- 判据落在测试里：`bundles/mydsh-profile` 的 `patch.spec.ts` 钉住"只有 config 覆盖"、`bundles/session-mode-profile`
  的 `patch.spec.ts` 钉住 preset 声明与行清单同形、`dsh-context-assembler` 与 `dsh-agent-toolkit` 各有
  `rows.spec.ts` 钉住清单形状，`dsh-context-assembler` 的 `preset-plane.spec.ts` 在真装配下钉住平面归属。
- 三个包各自的 `README` 与设计文档按这三条边界重述。
