# 工具说明随工具清单归 toolkit（族索引与可选团队）

状态：已采纳

背景：`tool-guidance` 原先住在 `dsh-context-assembler` 里（第六个能力出口），但它的数据与"工具有哪些"
同源——一份工具清单、一份工具短描述与用法正文，加一个工具要在两处对齐；而 assembler 的职责本是**上下文
重排**（信封、id、幂等、顺序、覆盖），工具怎么被讲清楚不是它的事。

**决定**

三件事一起做：

1. `tool-guidance` 迁到 [`@morlay/dsh-agent-toolkit`](../../packages/profile/dsh-agent-toolkit/README.md) 的
   `guidance` 出口（**保留对注入通道的强依赖**：`inject: ["tools", "systemPrompt", "contextAssembler"]`，
   装配上与组装行同住那个 `isolate` 组）。assembler 的出口因此从 5 个减到 4 个，只做重排。
2. 汉化数据统一成 **pack**（一份文件一个 pack，[`src/guidance/packs/`](../../packages/profile/dsh-agent-toolkit/src/guidance/packs/index.ts)）：
   **工具族**与**用法组**同一形态，索引汇总并在同名工具跨族 / 同 key 跨 pack 时 fail loud。加一个工具 =
   改它所属的族，加一个组 = 加一份文件；`groups.ts` 退成汇总层（组表、短描述表、正文渲染）。
3. Agent Teams 作为**可选子出口**（`./agent-team`）：一组默认关闭的行
   （`!!js process.env.DSH_AGENT_TEAM !== '1'`），开关是运行期；团队装上来时工具清单里"直接派发"那几行让位
   （上游 `dsh-experimental-agent-team-profile` 同款换法）。

## 考虑过的选项

- **留在 assembler 里**：加一个工具要同时动"工具清单"与"说明数据"两处，且 assembler 继续背着工具语义。
- **解耦成"通道可选"**（没有通道时只做描述替换）**：** 工具说明的本质就是"把要点交给通道分批送达"，
  降级版会少掉用法分组与丢弃清单——两种形态各一套行为，不值得。
- **运行时注册 API**（`ctx.toolGuidance.register(pack)`）：更灵活，但要管生命周期与顺序，而静态族索引在
  编译期就能查、覆盖性测试也能对齐上游工具集；真出现第三方要加族再说。
- **agent-team 单独一个 bundle 包**：上游已经有那个 bundle；我们只是把它那三行做成"本包的一个子出口 +
  默认关闭的组"，省一个包。

## 后果

- preset 的通道组里现在有**两行**（组装行 + 工具说明行），`patch.spec.ts` 按 `["context-assembler", "tool-guidance"]`
  钉住；chat 的 `capabilities` 少一个 `tool-guidance`，它改用 `guidanceRow({ groups: false })`。
- 工具说明与工具清单同源：加工具改一族文件，覆盖性测试（`guidance-inventory.spec.ts`）对齐上游 standard
  preset 的工具集与 section。
- Agent Teams 的开关是**运行期环境变量**：同一个产物里两套派发行都在，装配时按 `DSH_AGENT_TEAM` 二选一。
