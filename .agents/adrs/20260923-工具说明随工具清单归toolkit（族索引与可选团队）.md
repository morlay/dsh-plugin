# 工具说明随工具清单归 toolkit（族索引与可选团队）

状态：已采纳

背景：`tool-guidance` 的数据与"工具有哪些"同源——一份工具清单、一份工具短描述与用法正文，加一个工具要在两处对齐；而 assembler 的职责本是**上下文重排**（信封、id、幂等、顺序、覆盖），工具怎么被讲清楚不是它的事。

**决定**

1. `tool-guidance` 住在 [`@morlay/dsh-agent-toolkit`](../../packages/profile/dsh-agent-toolkit/README.md) 的
   `guidance` 出口（`inject: ["tools", "systemPrompt", "contextAssembler"]`：用法正文分批交给注入通道），
   是**host 平面的一行**——它往通道这个 host 单例注册正文，两个平面各一份会互相顶掉；assembler 的出口因此只做重排。
2. 汉化数据统一成 **pack**（一份文件一个 pack，[`src/guidance/packs/`](../../packages/profile/dsh-agent-toolkit/src/guidance/packs/index.ts)）：
   **工具族**与**用法组**同一形态，索引汇总并在同名工具跨族 / 同 key 跨 pack 时 fail loud。加一个工具 =
   改它所属的族，加一个组 = 加一份文件；`groups.ts` 退成汇总层（组表、短描述表、正文渲染）。
3. Agent Teams 是**本包的可选装配数据**（`./agent-team` 出口的 `TEAM_ROWS`，默认关闭：`DSH_AGENT_TEAM=1` 才装），
   **不进本部署 preset 的行清单**：换法整套归上游 `@deepseek-ai/dsh-experimental-agent-team-profile` bundle
   （它自带"禁直接派发 + 插三行"），要用的人把它加进 profile 的 bundles，我们这边不单独配。

**考虑过的选项**

- **留在 assembler 里**：加一个工具要同时动"工具清单"与"说明数据"两处，且 assembler 继续背着工具语义。
- **解耦成"通道可选"**（没有通道时只做描述替换）：工具说明的本质就是"把要点交给通道分批送达"，
  降级版会少掉用法分组与丢弃清单——两种形态各一套行为，不值得。
- **运行时注册 API**（`ctx.toolGuidance.register(pack)`）：更灵活，但要管生命周期与顺序，而静态族索引在
  编译期就能查、覆盖性测试也能对齐上游工具集；真出现第三方要加族再说。
- **agent-team 单独一个 bundle 包**：上游已经有那个 bundle；我们只是把它那三行做成"本包的一个子出口 +
  默认关闭的组"，省一个包。

**后果**

- 工具行由 preset 平面提供（`TOOLKIT_PRESET_ROWS`），`tool-guidance` 留在 host 平面：注入面与工具行分居两个平面，
  判据由 [`bundles/session-mode-profile` 的 `patch.spec.ts`](../../packages/bundles/session-mode-profile/src/__tests__/patch.spec.ts)
  与 [`dsh-context-assembler` 的 `preset-plane.spec.ts`](../../packages/context/dsh-context-assembler/src/__tests__/preset-plane.spec.ts) 一起钉住。
- 工具说明与工具清单同源：加工具改一族文件，覆盖性测试（`guidance-inventory.spec.ts`）对齐上游 standard
  preset 的工具集与 section。
- 团队那三行不在本部署的 preset 清单里（`TOOLKIT_PRESET_ROWS` 不含团队那一族，直接派发那几行也不带让位门控）：
  要团队就用上游那份 bundle。
