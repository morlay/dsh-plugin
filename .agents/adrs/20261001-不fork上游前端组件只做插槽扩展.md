# 不 fork 上游前端组件：扩展只走官方槽位

状态：已采纳——对话外壳用官方 `ui-conversation` 行，我们的四处扩展都注册在官方已声明的位置上
背景：对话 UI 的改造点有的落在组件内部。接管官方行的做法（停掉它 + 薄壳 fork 一对一行）代价是持续的：每次跟随上游都要逐文件判定"有意偏离 / 落后上游"，上游 client 契约换代时 fork 不跟随就不是"不一致"而是功能静默失效。上游已经给出够用的扩展面：`ctx.slots` 的位置声明，以及 `conversation.input.for(scope).setDraft(text)` 这类组件级动作。

**决定**

不接管、不 fork 官方前端行，扩展只经官方槽位与官方契约。当前四处：`conversation.chat.node` 的 `user` / `steering` 两个 key（`priority: -1` 覆盖官方渲染，挂编辑与重试）、`conversation.input.left`（模式 chip）、`main` 的 `conversations` + `sidebar.panellist`（对话管理页）、`sidebar.right.pane.tab`（模式面板页，key 就是包名）。要上游**组件本身**的行为时，把那个组件按上游原样复制进 `src/vendor/<短名>/` 当快照（逐行可比、不改行为、不接管行）。

**考虑过的选项**

| 选项                           | 否掉的理由                                                                                 |
| ------------------------------ | ------------------------------------------------------------------------------------------ |
| 保留薄壳 fork 接管官方行       | 每次同步上游都要人工判定哪些偏离是有意的；契约换代时 fork 静默失效，成本是长期且不可预算的 |
| 只做整格 shadow 槽替换         | 改不到组件内部——而那正是当初 fork 的动机；现在要改的那些点官方槽位已经覆盖                 |
| 向上游提特性请求，等它给扩展面 | 周期不可控；真缺扩展面时再回到"复制一个组件当快照"这条最小的路                             |

**后果**

- **槽声明与外壳渲染归官方行**：位置清单在 `vendor/deepseek-harness/packages/client/ui-conversation/src/client/contract/slots.ts`，我们不重复声明、不拥有输入契约；撤回回填改走官方 `setDraft`（[`session-editor.store.ts`](../../packages/agent-ex/better-session/src/ui/session-editor/session-editor.store.ts)），纯文本、不重建引用 chip。
- **composer 的统计行不归我们**：`conversation.composer.dock` 的 `activity` / `usage` 由上游 `ui-chat` 注册，本仓库不覆盖它。
- **快照不是 fork**：[`src/ui/vendor/dsh-client-ui-chat/`](../../packages/agent-ex/better-session/src/ui/vendor/dsh-client-ui-chat/client/chat/MessageIconActions.tsx) 里是消息动作组件的按上游原样复制（4 个文件），判据是"与上游逐行一致"，同步清单在 [`vendored.ts`](../skills/zephyr-upstream-sync/scripts/upstream-sync/src/vendored.ts)。
- **判据**：位置台账与条目数按清单核对（**评审人工**；apps 不再有默认 spec，台账口径是官方位置声明 + 我们的注册行）；消息动作两条注册在 [`ui.provide.spec.ts`](../../packages/agent-ex/better-session/src/ui/__tests__/ui.provide.spec.ts)；模式 chip 的视图在 [`session-mode-seat.spec.tsx`](../../packages/agent-ex/session-mode/src/ui/__tests__/session-mode-seat.spec.tsx)；两个位置名只写在 [`session-mode-slots.ts`](../../packages/agent-ex/session-mode/src/ui/session-mode-slots.ts)。
- 装配顺序有硬约束：我们的两条前端扩展都排在官方会话界面之后（位置先声明，才有得注册），见 [`client.provide.ts`](../../apps/zephyr-custom/src/client/client.provide.ts)。
