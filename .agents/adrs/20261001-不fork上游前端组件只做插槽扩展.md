# 不 fork 上游前端组件：扩展只走官方槽位

状态：已采纳

背景：对话外壳的几处改造点落在组件内部，插件面当时只有「整格 shadow keyed slot」，于是我们**接管了官方
`ui-conversation` 行**（`disabled: true` + 薄壳 fork 一对一行）来改输入框与队列行。代价是持续性的：每次同步
上游都要逐文件判定「有意偏离 / 落后上游」并人工保留我们的实现，上游 client 契约换代（如队列面改由 `inbox`
投影承载）时 fork 不跟随就不是「不一致」而是功能静默失效。同时上游已经给出 recall 回填需要的扩展面：
`vendor/deepseek-harness/packages/client/ui-conversation/src/client/contract/input.ts` 的 `setDraft`。

**决定**

不再 fork 上游前端组件：删掉对话外壳的薄壳 fork 包，官方 `ui-conversation` 行照旧启用；bundle 里的前端扩展
**只做官方槽位能承载的那部分**（`conversation.chat.node` 的 `user` / `steering`、`conversation.composer.dock`
的 `stats`、`main` / `sidebar.panellist` 等），槽声明与外壳渲染归官方行。

**考虑过的选项**

- **保留薄壳 fork**：换来输入框 raw markdown / 引用插入归一与队列行「编辑=撤回」，代价是上游同步的人工判定与
  契约换代的静默失效；这两处改造的价值不值这份长期成本。
- **只做整格 shadow 的槽替换**（fork 期间的方案 B）：改不了组件内部——而那正是我们不再要改的部分，现在的做法
  等价于此，只是明确写下「不做」。
- **向上游提特性请求**：周期不可控；上游若真给出编辑器插入决策 / 草稿结构化 / 组件级替换这些扩展面，再按下面
  「回滚」评估。

**后果**

- **槽声明所有权回到官方行**：官方 `ui-conversation` 行声明的全部 target-neutral 槽（`main.conversation` …
  `conversation.input.model`）与渲染由上游负责，我们不再同形承担（那是 fork 期的义务）。
- **放弃的能力**（如实登记，别指望还在）：
  - 输入框的引用插入形态归一（`@` mention / `skill:` token 归一到同一 wire 形态）与「纯文本插入」——回上游行为；
  - 编辑器里关闭引用装饰、保留 raw markdown（上游会给 `@path` / `@dir/` 高亮与 chip），以及「外部焦点 / 草稿选区
    不被后台协调拉回」；
  - 队列行「编辑 = 撤回该条到输入框」——回上游自带的 inline edit
    （`vendor/deepseek-harness/packages/client/ui-conversation/src/client/queue/QueueDock.tsx`）；
  - 提交埋点（`submission-analytics`）与 `InputHub` 那套 scoped 事件归一；
  - 输入契约的 `restoreDraft` 扩宽（带引用出现项重建）。
- **recall 回填改走官方契约**：撤回后把该消息的全部文本块写回草稿用官方 `input.for(ctx).setDraft(text)`
  （纯文本，不重建引用 chip）——这是上游已有能力，不必 fork。
- **配置面回到官方行 id**：对话外壳的设置段由官方 `ui-conversation` 行注册（fork 期间我们按 `ui-conversation-fork`
  读写自己那一份的临时约定随之消失）。
- **`@morlay/dsh-client-ui-primitives` 的边界随之清楚**：它是被内联的 client 库（不是装配行），承载样式层、
  引用解析 / 渲染与设置表单原语；接管对话外壳时顺带做的那部分不再属于它
  （[ADR-基础面暂时内联而不是装配行](../../packages/client/ui-primitives/.agents/adrs/20261001-暂时内联而不是装配行.md)）。
- **回滚**：要拿回上面任何一项能力，都得重新引入一个接管官方行的客户端包（并在 `@morlay/better-session` 的
  bundle patch 里停官方行）。上游给出扩展面时，优先按扩展面做回来，而不是再分叉。

  操作语义见[设计 编排层操作语义](../../packages/session/ui-conversation-message-actions/.agents/designs/20260917-编排层操作语义.md)。
