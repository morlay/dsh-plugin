# 契约定名表（类名不动）

类名一律不改。每个契约只有两个名字：

- **派生名**：装配器自动生成 `zephyr-` + kebab(类名)，用于我们自己的服务注册；不需要手写。
- **alias（上游名）**：`@Injectable({ name })` 仅在「上游已声明**同名同义**」时写，用来按名字采纳宿主那份、也让上游按驼峰名读到我们。

判据：**上游有这个名字、且它是同一件东西** → 写 alias；否则不写，只留派生名（`zephyr-` 前缀本身就是我们的身份）。

## 两面同名的处理

`ClientConnection` / `RemoteAccess` 在 host 与 client 各有一份契约，**类名相同、alias 相同**，但分别活在 node 与浏览器两个进程里，装配作用域不重叠。
所以不需要改名——只要保证「同一进程内不出现两份同 alias 的契约」（由 bundle 的 host/client 入口物理隔离保证）。

| ------------ | --------------------------------------------------------------------- | ----------------------------------- |

| `shortcuts`  | `client/shortcuts/src/client/index.ts:55` `super(ctx, 'shortcuts')`   | ✔ 写 alias                          |
| `theme`      | `client/ui-theme/src/client/index.ts:609` `ctx.provide('theme', …)`   | ✔ 写 alias                          |
| `locale`     | `client/locale/src/client/index.ts:588` `ctx.provide('locale', …)`    | ✔ 写 alias                          |
| `resources`  | `ctx.provide('resources', …)`（多处消费方）                           | ✔ 写 alias                          |
| `slots`      | `client/ui-renderer/src/client/registry.ts:184` `super(ctx, 'slots')` | ✔ 写 alias（`UiRenderer` 契约不写） |
| `uiRenderer` | 无独立服务                                                            | ✘ 不写                              |

核对手段：`apps/dsh/target/home/debug/cordis.yml`（容器启动时 `--dump-config` 的 227 个行定义）交叉 `vendor/**` 的 `super(ctx, '<name>')` / `ctx.provide('<name>', …)`。

### 由此确认的一条规则

**上游一个行可能只发布一个服务**：`ui-renderer` 行发布的是 `slots`，`ui-theme` 行发布的是 `theme`。所以我们按行拆契约时，`UiRenderer` 这类「行概念」没有服务名——它应该由 `Slots` 承载，或者干脆删掉这个契约。
