# 上游 0.2.3-alpha.2 同步的适配决定

上游从 `dsh-v0.2.2-rc.3`（`38a6a5c965`）锁到 `dsh-v0.2.3-alpha.2`（`4b399c39a6`）。同步链本身
（`just vendor sync → patch → vendor → prebuild`）全通；下面是**上游行为变更**与本仓应对的登记，
判据见四个门禁（`just lint` / `just test` / `just build` / `just audit`）。

## 一、上游把 `connection` 拆成两个面

0.2.2 的上游 `connection` 是一个服务（`HostConnectionService` 同时带浏览器面成员），本仓因此只抄了一个
契约。0.2.3 拆成：宿主 `HostConnectionService`（服务名 `connection`，`apply` 在自己的 `ctx.inject` 回调里
才 `new`）与浏览器 client（本仓自研，不跑它的 `apply`）。

契约跟着各是各的：

| 契约               | 服务名              | 面                                                                           | 由谁提供                                                           |
| ------------------ | ------------------- | ---------------------------------------------------------------------------- | ------------------------------------------------------------------ |
| `Connection`       | `connection`        | 宿主：`rpc` / `fetch` / `createSharedFetchHandler` / `admit` / `browserPeer` | `ConnectionDefault extends fromCordis(Connection, HostConnection)` |
| `ClientConnection` | `client-connection` | 浏览器：`interactions` / `generation` / `isOpenLoopback` … `start`           | `ClientConnectionDefault`（自研）                                  |

- `HostConnection` 是 `HostConnectionService` 的子类，唯一职责是把 `trustedHosts` 固定成 `[]`（上游这个
  构造第二参是 trustedHosts 而不是 config），并在 `super` 之前 `new ConnectionAuthentication(ctx)`
  （上游构造里严格读 `connection.authentication`）。
- 浏览器面在 `onInit` 里"store 里没有 `connection` 时"按上游名发布自己：真实浏览器进程就该如此，
  混合装配（宿主面也在同一个 app）让位给已在场的那一面。
- 消费点按面注入：`mux` / `gateway` / `rpc-bridge` / 上传 / 交付物 / open-in-app 用宿主面；UI 与传输
  包装行用浏览器面（`ui-permission` / `ui-settings-general` / `ui-conversation`）。
- **不允许**再出现 `xxxOf(connection)` 这类结构化取面、或 `ctx.get("connection")` 式的按名兜底：
  面在契约上，消费方只按契约取。

## 二、`webServer` 与 `/api/remote.mux` 的所有者

- `WebServer` 契约声明上游名别名 `webServer`（派生名 `web-server` 照常），上游 `connection` 的信任围栏
  与 bundle 行按这个名字读。
- `/api/remote.mux` 的 upgrade **归自研 `MuxServer` 行**：`ApiGatewayDefault` 给上游 gateway 的 deps 里交
  一个只有空 `registerUpgrade` 的 `webServer` 面，上游那段注册因此不生效——两家并存时先注册的先赢，
  自研路由表的流式端点就永远接不到连接。

## 三、`deepseekAuth` 成为 DeepSeek 路由的必需服务

0.2.3 的 `llm-deepseek-api-key` / `llm-deepseek-account` / `web-deepseek-api` 都从 `ctx.deepseekAuth` 取凭据。
本仓在 `@morlay/dsh-auth` 补了宿主行：契约 `DeepSeekAuthToken`（`@Injectable({ name: "deepseekAuth" })`，
覆盖守卫对上游 `DeepSeekAuth` 的全部公开成员）+ `DeepSeekAuthDefault extends fromCordis(契约, DeepSeekAuth)`，
随 `provideAuth()` 装配。

## 四、浏览器侧 `Config` 变成 Host 同步的 `SyncedConfig`

上游 0.2.3 的 client 行按 `config.<field>.get()` 读 Host 同步下来的字段。本仓没有那条通道，装配时给
`fixedSyncedConfig([...字段名])`（`@morlay/zephyr-app/client` 导出）：每个字段恒 `undefined`，上游对"没配"
本就有兜底。已覆盖：`shortcuts`（`stopSequenceMs`）、`ui-workspace`（`recentViewLimit`）、
`ui-context-menu`（`resolutionTimeoutMs`）、`ui-sidebar-documentpreview`（`office` / `excel`）、
`ui-settings-models`（`credentialOnboarding`）、`ui-conversation`（`busyEnter` / `maxConcurrentFileUploads`）。

## 五、上游能力面变化的本仓对齐

- **`working_directory` 工具下线**：上游删了 `tool-working-directory` 包（模型不再改目录，改由宿主
  `ctx.workingDirectory.set`）。本仓删掉 `ToolWorkingDirectory` 行、`provideEnvTools` 与 guidance 里的那一条。
- **`SessionQueryEngine.inspectSession` 下线、`getListMetadata` 新增**：契约跟着换；rdb 实现按
  `sessionListMetadata` 投影缓存读（没缓存给上游 init 值）。
- **`SubagentRuntime` 新增 `capacityOf` / `maxActiveSubagents`**、`PermissionPresetService` 新增 `setPreset`、
  `NodePtcRuntime` 新增 `registerEnvironmentInitializer`：契约补齐（覆盖守卫强制）。
- **上游 `rankByName` 下线**：`zephyr-ui` 的 `SearchSelect` / `TagInput` 改用 `TextSearchIndex`。
- **`@deepseek-ai/dsh-llm/brand` 子路径下线**：消息 id 类型从 `SessionEvent<"user/message">["data"]["id"]` 派生。
- **上游 job UI 换位置**：`job-list` 从会话头部动作位搬到 `conversation.session.panel.section`
  （`id: background-jobs`）与 `.indicator`（`id: background-jobs.running`）。
- **`ctx.root` 属性下线**：框架层用上游符号 `rootContextKey`（`Symbol.for('cordis.root')`）表达，调用处
  写 `ctx[rootContextKey]`，不再有 `rootOf` 这类辅助。
- **上游新增 connector 的 CLI 依赖**（`@larksuite/cli` / `@tencentcloud/tmeet`）进 `allowBuilds`；
  `packages/client/remote-connection` 整包裁剪（它绑在已摘掉的 web-app 的 `webApp` 服务上）。

## 六、typert 生成器的三处修正（随上游类型面变化暴露）

1. `collectOwners` 的包切分：`@scope/name/sub` 不能再被切成 `@scope` + `/name/sub`（否则所有上游类型被并进
   一条 import、指向第一个包）。
2. 索引访问（`T['field']`）里的类型名要进产物的 import。
3. 递归 codec 的 `$schema` 加返回类型注解（否则隐式 any）。

## 六点五、上游 `inject` 声明是装配契约（装配期 fail loud）

上游 0.2.3 里 `ui-workspace` 的 `inject` 声明含 `uiSession` / `uiSession.sessionStatus`（未读标记）。
本仓原先只靠 `fromCordis` 的代理**回落成按名读**，于是缺口要到浏览器里才爆
（`cannot get property "uiSession" without inject`，白屏）。现在两件事：

1. `fromCordis.mount` 里 `assertInjectedDepsSatisfied`：上游 `inject` 声明里的每个名字，要么在本行
   deps 里、要么已在 store 里，否则**装配期抛错**并列出缺的名字。判据用例在
   `packages/zephyr/zephyr/src/compat/__tests__/from-cordis.spec.ts`（缺 → 失败；store 已就位 → 通过）。
2. 由此暴露并修掉的两处真实缺口：
   - `WorkspaceSlots`（`ui-workspace`）现在交 `uiSession` 与字面键 `uiSession.sessionStatus`；
   - 新增 `SessionStatusSlots`（`ui-session-status` 的 client 行，发布 `uiSession.sessionStatus`）；
     装配顺序因此固定为 `provideSessions()` → `provideSessionShell()`（出 `uiSession`）→
     `provideSessionStatusUi()` → `provideWorkspaceUi()`（读上两者），见
     `apps/zephyr-custom/src/client/client.provide.ts`。
   - `web-search-deepseek` 也从 `ctx.deepseekAuth` 取凭据：该行显式注入 `DeepSeekAuthToken` 并交 deps，
     `provideAuth()` 因此在装配里排在 `provideWebAccess()` 之前。
