状态：已实现（同步链、生成物与门禁都已落地；仓库自有面无需适配改动）
范围：`DEEPSEEK_HARNESS_VERSION` 从 `0.2.2-rc.2` 提到 `0.2.2-rc.3` 这一跳里，上游改动对**本仓库自有面**（vendor 步骤、本地补丁、插件包、profile 装配）的影响与结论。上游包内部的重构不在本文讨论范围。

## 结论摘要

| 议题 | 结论 | 一句话理由 |
| ---- | ---- | ---------- |
| 上游新增包 `packages/experimental/deepseek-chat-import`（可选 bundle，带 `deepseekChatImport` 服务） | 不装配：任何 profile 的 `dsh.profile.bundles` 都不加它 | 它是上游 `OPTIONAL_BUNDLES` 里的可选能力，本部署的装配面（`dsh-base` + `dsh-web-app` 与自有行）用不到；不装就没有它的服务面与客户端开销 |
| `ui-workspace` 新增 `workspace.picker` Factory 与第三个 directory-flow hole（`workspace.picker.directoryFlow`） | 不注册 | 本地插件注册的 slot 是 `main`、`sidebar.panellist`、`conversation.input.left`、`sidebar.right.pane.tab`；桌面的目录选择走 preload 暴露的 `__DSH_DIRECTORY_PICKER__`，由上游 native 半读取，新增 hole 不经过我们 |
| `ui-sidebar` 新增 `sidebar.session.action`（`hoc` 种类） | 不注册 | 纯新增能力、向后兼容；本地没有任何行要装饰 New-session 行 |

| 本地包的 `engines.dsh` 约束 | 跟到 `>= 0.2.2-rc.3 < 0.2.3`（24 个包） | 根安装按上游版本同步；约束与 peer 一样随上游锁版本走，不手写死 |

## 取舍

- **不把 `@deepseek-ai/dsh-deepseek-chat-import` 加进任何 profile**：它是"从 DeepSeek 官网导出文件导入会话"的一行，只在会话列表旁多一个入口；本部署的装配面由 `dsh-base` + `dsh-web-app` 与自有 bundle 组成，装了等于给一条用不到的路径付打包与维护成本（与 Office 面同一判据）。
- **不为三个新增 slot 写适配代码**：`sidebar.session.action`、`workspace.picker`、`workspace.picker.directoryFlow` 都是上游可选能力，本地插件没有对应行为；注册它们只会制造空实现，并把我们绑到上游刚定的接缝上。
