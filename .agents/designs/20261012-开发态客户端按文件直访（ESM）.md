# 开发态客户端：按文件直访（ESM）

**目标**：开发态的 client 资源不再走 combo 打包（`/plugins/??a/client.js,b/client.js&rev=…`），改成**按文件**
寻址 `/plugins/{pkgName}/{version}/{filepath}`，浏览器原生 ESM 直接 `import`。这样前端资源之间的依赖由
浏览器解析，**不再受 inject / 模块表的行集限制**——想引谁就引谁，跟真正的 ESM 语义一致。

**现状（起点）**：

- `packages/desktop/dsh-desktop-host/src/dev-client/index.ts` 是行内模块表的一条路由：`kind: "exact"` 只注册
  一个固定路径（`COMBO_PATH`），handler 里从 `req.url` 解析出 combo / 单包的 id 列表，逐个走
  `bundleClientFactory` 现场打包（CJS 工厂脚本），再拼起来下发；
- 打包器 `bundleClientFactory`（`devpackages/devkit/src/cordis-client.ts`）产 **CJS 单文件 chunk**，形态是
  `__ModuleLoader__.load(...)` 的工厂片段——这是上游模块系统（`@deepseek-ai/dsh-client-modules`）的契约。

**改造要点**：

1. **路由**：`register` 只支持 `kind: "exact"`，但 handler 拿得到完整 `req.url`——所以仍注册一条 exact 路由，
   在 handler 里按 `/plugins/` 前缀自己分发：`/plugins/<pkg>/<version>/<filepath>` → 仓库里的文件路径。
   `version` 取自包清单（同时天然给了 cache-busting，不必再挂 `?rev=`)。
2. **逐文件 ESM**：命中文件后按扩展名处理——`.ts`/`.tsx` 走 rolldown 单文件转译（内部是 oxc），
   `.css`/`.module.css` 走 `cssInlinePlugins` 的同一份实现，其它按 MIME 原样。整包 combo 打包不再发生。
3. **依赖改写**：转译后把裸导入换成绝对 URL（相对导入**不动**：URL 结构镜像文件结构，浏览器自己拼就对）——
   `import { X } from '@deepseek-ai/dsh-y'` → `from '/plugins/@deepseek-ai~dsh-y/<version>/src/index.ts'`，
   相对导入按同包同版本拼路径，`import.meta.url` 与 `new URL('./x', import.meta.url)` 也照此解析。
   （包名里的 `/` 要在 URL 段里转义；子路径出口（`@pkg/types`）按包清单的 `exports` 解析到源文件。）
4. **`inject` 不再约束资源**：行集只决定**入口**，资源之间的引用完全按上面的 URL 走；这也意味着模块表
   不必再为"行"提供 external，`devExternals` 那一层可以退场。
5. **三方依赖要过一层 CJS→ESM**：仓库自己的包都是 TS/ESM 源码，转译即可；但 `node_modules` 里的三方包
   大量是 **CJS**（`require` / `module.exports` / `exports.x` 交织，还有 `process`、`global` 这类 CJS 专属
   自由变量）。浏览器没有 `require`，所以这一步不能省——**vite 的做法是 `optimizeDeps`**：扫出裸导入，
   用 esbuild 把每个依赖**预打包成单个 ESM 文件**（顺带把 CJS 转成 ESM、把多个入口合并成一次请求），
   缓存到 `node_modules/.vite/deps/`，页面上按 `/@deps/<name>.js` 取。
   本仓库照这个形状做：预打包交给 rolldown（`format: "esm"` + `platform: "browser"`，
   CJS 由 rolldown 自己转），产物落在 profile 的缓存目录，URL 用 `/plugins/.deps/<name>-<hash>.js`；
   命中缓存就不再重建，依赖清单变化时按 hash 失效。这样"浏览器原生 ESM"与"CJS 依赖"就不再冲突：
   **我们自己的源码逐文件直出**（改哪看哪，不打包），**三方依赖整包预打包**（vite 的分界也是这条）。

6. **发布线不变形态**：发布仍是 `bundleClientFactory` 的工厂 + 内联 + tree-shaking（`clientEntryPlugin`
   换字节那条链），只是 CSS 资产继续内联（见债务「CSS 里的图片资产」）。

**判据**：dev 下页面里每个 client 资源都是独立 URL、浏览器原生 ESM 加载；不再有 `??a,b&rev=` 的 combo；
引用任意包的 client 源码不需要它出现在模块表的行集里。
