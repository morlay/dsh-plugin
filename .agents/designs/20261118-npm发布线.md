## 一、决定

| #   | 议题        | 决定                                                                                                                                                                                                                                                                                                                                                                                                                      | 一句话理由                                                       |
| --- | ----------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------- |
| 1   | 发布资格    | `packages/**` 全部发布（除 `apps/**`）；一次全翻 `private: false`；`devpackages/**` 保持 `@local` 私有                                                                                                                                                                                                                                                                                                                    | 一个发布集合、一条版本线，避免维护「哪些发了」的隐式状态         |
| 2   | 发布形态    | 有 TS 源码入口的包统一产物包（`dist` + `.d.mts`）；`@morlay/dsh-oxc-node` 保持手写 `register.mjs` 单文件                                                                                                                                                                                                                                                                                                                  | 消费方不需要 TS loader；单文件 loader 本身就是产物               |
| 3   | 清单真源    | `exports` / `publishConfig.exports` / `dsh.bundle` / `engines.dsh` 由 `devkit build` 按入口与产物写回，不手写                                                                                                                                                                                                                                                                                                             | 漏一个键就是发布包少一个面，手写挡不住                           |
| 4   | 出口规则    | `./ui` 是纯 ESM 浏览器面；`./dsh-bundle` 的入口是 `src/dsh-bundle.ts`（默认导出 cordis 插件、另导出 `rows`），**顶层 `exports` 与 `publishConfig.exports` 都列**；`./client` 与 `./cordis.patch.yml` 只进发布态                                                                                                                                                                                                           | 顶层那个键是构建认出 bundle 包的入口，删了就没有 patch 与 client |
| 5   | bundle 标记 | `dsh.bundle = { patch: "./dist/cordis.patch.yml" }`；行清单只有一处真源：`src/dsh-bundle.ts` 的 `export const rows`（`devkit build` 运行时读它写 patch）                                                                                                                                                                                                                                                                  | 装配声明只有一处真源，且要能表达禁用与配置                       |
| 6   | client 依赖 | client 半按上游 `dsh.client` 声明与模块表规则构建：基线外部 + `dsh.client.external`，其余内联；详见「四、client 半的上游要求」                                                                                                                                                                                                                                                                                            | client 的依赖面由上游运行时决定，不能按 host 的内外联猜          |
| 7   | 声明（dts） | dts 由 `devkit build` 内的进程锁全仓生成一次（首个进入的构建生成、其余等锁），再按包聚合成 `dist/<入口>.d.mts`；`just dts` 只是手动重建入口                                                                                                                                                                                                                                                                               | 单包 dts 成本高（实测占单包构建 82%），全仓一次只几秒            |
| 8   | 版本        | zephyr 家族与插件同一条版本线，首发 `0.2.0-alpha.0`；`@morlay/dsh-oxc-node` 独立版本线（首发须高于 npm 现有 `0.2.13`）                                                                                                                                                                                                                                                                                                    | 家族内互相依赖，同版让 `workspace:^` 的替换语义稳定              |
| 9   | 通道        | GitHub Packages 只走 CI（自动发未发布的新版本）；npmjs 只经本地 `just publish-npm` 手动发同一组、同版本；**落到哪个 registry 由 `--registry` 定，默认是本地模拟 registry（`tool/npr` 的 verdaccio，`http://127.0.0.1:7677/`），真 npmjs 必须显式给 `--registry https://registry.npmjs.org/`**；覆盖式重发（`--force-republish`：先 unpublish 再 publish）只对 loopback registry 开放（真 registry 上 unpublish 是真删除） | token 只在发布者本机；npmjs 需要人工卡点                         |
| 10  | dist-tag    | 稳定版 → `latest`；`-alpha.*` → `alpha`；其余预发布 → `next`                                                                                                                                                                                                                                                                                                                                                              | 预发布绝不落 `latest`                                            |
| 11  | 发布前验收  | `just verify-release` 判清单覆盖、目标存在、tarball 内容、等价安装冒烟、出口加载；任一红即停。真装一层依赖首发顺序（包先上 registry）                                                                                                                                                                                                                                                                                     | 发布是单向操作，验收必须在按下按钮之前                           |

## 二、现状事实

- **发布集合 37 个**：`packages/**` 全部 `private: false`、全部有 `files` 与 `publishConfig`；`engines.dsh` 37 个包里有 36 个（`@morlay/dsh-oxc-node` 无 TS 入口、无 `dist`，手写 `register.mjs` 单文件）。
- **版本**：36 个包 `0.2.0-alpha.0`、`@morlay/dsh-oxc-node` `0.2.14-alpha.0`（独立线）；`just version 0.2.0-alpha.0` 已把 `0.0.1` 那批拉上家族版本线，dry-run 全体落 `alpha`。
- **形态**：36 个包有 `dist`（入口产物 + `.d.mts`）；12 个包有 `./ui` 面；4 个 bundle 包（`agent-use` / `better-session` / `configurable-sandbox` / `session-mode`）各有 `./dsh-bundle` 与 `cordis.patch.yml`；`./client` 出现在 3 个包里（`better-session` / `session-mode` 是 CJS 工厂，`zephyr-app` 是普通 ESM 面）。
- **入口清单只有一份**：入口从各包 `package.json` 的 `exports` 推导（`planOf`），包内没有 `tsdown.config.ts` 与 `build` 脚本；例外是 `@morlay/zephyr-desktop-shell`（见「八、不做与已知债」）。
- **通道**：三条都已可执行——`just publish`（CI，本地恒 `exit 1`）、`just publish-npm [--registry <url>]`（默认本地模拟 registry）、`tool/npr` 的 verdaccio（`127.0.0.1:7677`）。
- **registry 现状**：本地模拟 registry 上发布过 `0.0.1` 那批与 `0.2.0-alpha.0` 的 11 个包；版本 bump 之后 25 个包的 `0.2.0-alpha.0` 还没发过（dry-run 列这批）。npmjs 上 24 个 agent 包与 `@morlay/zephyr*` 没有任何版本，`@morlay/dsh-oxc-node` 的 `latest` 仍是另一条线的 `0.2.13`。
- **验收现状**：`just verify-release` 六条判据全绿（判据 2 / 7 / 8 / 9 / 9 前置 / 10）。判据 9 的真装默认从本地模拟 registry 解析依赖；真发 npmjs 前用 `--registry https://registry.npmjs.org/` 再验一次。
- **发布前钩子**：37 个发布包都有 `prepublishOnly`，内容调 `devkit build --filter <包名>`（`zephyr-desktop-shell` 另接 `pnpm exec tsdown` 补 `preload.mjs`）；`just audit` 有一条判据守它。

## 三、模块边界与接口

| 模块                                                    | 拥有（职责与不变量）                                                                                                                                                    | 不拥有（明确排除）                              | 依赖方向                                                      | 接缝 / 适配器                                                    |
| ------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------- | ------------------------------------------------------------- | ---------------------------------------------------------------- |
| `justfile`                                              | 只做 trigger：一个配方一条命令，配方名就是红线里的入口名                                                                                                                | 任何逻辑（包列表、校验、循环都不在这里）        | 人 → 配方 → `devkit`                                          | `just build` / `just publish-npm` / `just verify-release`        |
| `devkit`（`workspace` / `build` / `audit` / `release`） | 构建编排、产物形态、清单写回、bundle patch；审计判据；发布（选包、清单覆盖判据、dist-tag、跳过已发布、loopback 守卫）；验收（判据 2 / 7 / 8 / 9 / 10）；版本 bump；清理 | 单个包的出口内容、产物长什么样；registry 的认证 | 各包 `package.json` 的 `exports` → 本模块；`pnpm -r` → 本模块 | `devkit <子命令>`                                                |
| `dts-prepare`                                           | 全仓声明树的生成、进程锁、完成标记与落位到各包 `dist`                                                                                                                   | 清单写回、包级出口                              | `devkit build` → 各包 `dist`                                  | `ensureWorkspaceDts` / `emitDts`                                 |
| CI publish job                                          | 认证与逐包发布到 GitHub Packages                                                                                                                                        | 本地发布、版本 bump                             | CI → GitHub Packages                                          | `just publish`（→ `devkit publish --github`）/ `NODE_AUTH_TOKEN` |

接口：

- `devkit build [--filter <包>]`：`pnpm -r --filter ./packages/*/* exec node build/one.ts`——包列表与并发都归 pnpm，工具里不自己遍历目录；每个包在自己的进程里从 `exports` 推导入口、把产物写 `dist`、清单写回 `package.json`（`build/package-exports.ts`）；bundle 包的行清单从 `src/dsh-bundle.ts` 的 `rows` 读；声明树在这一步内确保（进程锁、跨进程一次）。
- `devkit audit [--write]`：逐包判据 + 根上汇总；`--write` 删未用依赖。
- `devkit publish [--github] [--dry-run] [--force-republish] [--registry <url>]`：先跑清单覆盖判据（每个待发包的 `publishConfig.exports` 覆盖顶层 `exports`、目标文件都在；与 `devkit verify-release` 的判据 2 共用 `release/manifest-coverage.ts`），不通过即停；再按「版本未发布」发。`--dry-run` 只打印包名、版本与 dist-tag，不起发布子进程（仍 `pnpm view` 只读 registry）；真发走 `pnpm -r publish`（按依赖图拓扑、`--workspace-concurrency=1` 串行），`--dry-run` 只打印不发；`--github` 落到 GitHub Packages 且只在 CI 里允许；`--force-republish` 先 `unpublish --force` 再 `publish`，只对 loopback registry 开放。认证由发布者自己的 `~/.npmrc` 提供。
- `devkit verify-release [--filter <包>] [--registry <url>] [--keep]`：判据 2 / 7 / 8 / 9 / 10，只读 registry（`pnpm view` / `pnpm pack` / `pnpm add`）。真装默认从本地模拟 registry 解析依赖，`--registry` 换成别的 registry；`--ignore-scripts` 跳过依赖的 native 构建（只验证出口能加载）。人工门，不进 `prepare` / `lint` / `test` / `build` / CI。
- `devkit version <版本>`：只 bump 发布集合（zephyr 家族与插件同版），跳过 `@morlay/dsh-oxc-node` 与 private 包、跳过已是目标版本的包，带 `--no-git-checks`（本地 bump 不挑干净树）。
- `devkit clean`：删 `target/dts` 与各包 `dist`。
- `justfile`：每个配方一行 `pnpm exec devkit <子命令> {{args}}`；`just dts` 是 `dts-prepare` 自己的 CLI（声明树的正常入口是 `devkit build`，它只是手动重建）。

## 四、client 半的上游要求

结论：client 半按上游 `dsh.client` 声明与模块表规则构建，依赖面不能按 host 的内外联猜。

真源：`vendor/deepseek-harness/packages/client/tsdown.client.ts`、`vendor/deepseek-harness/packages/client/AGENTS.md`、`vendor/deepseek-harness/docs/subsystems/client-modules.md`。

| 面                | 上游要求                                                                                                                                                                                                                                      | 我们的落点                                                 |
| ----------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------- |
| 声明 `dsh.client` | `platform: 'web'`；`inject` 只表示包名依赖边（不排序激活）；`immediately` 只给基础设施预取；`external` 是模块表请求，功能插件不得用它拿别的插件的值                                                                                           | bundle 包的 `package.json` 声明；`platform` 由构建补写     |
| 产物              | CJS 工厂：`window.__ModuleLoader__.load({ id, factory })`，外部经注入的 `require` 解析                                                                                                                                                        | `./client` 的 `default` 条件                               |
| 外部与内联        | 外置只有两个来源：**baseline**（`PLATFORM_MODULES` 的精确键）与 `dsh.client.external` 点名的 specifier；**其余一律内联**，包括我们自己的 `@morlay/*`（di 里上游 client 插件由 `zephyr-app` 进程内挂载，不是独立 Loader 行，内联才是正确形态） | `clientRowExternals` + `clientBundleSpec`                  |
| baseline 子路径   | 模块表按精确键解析：`<baseline>/<子路径>` 既答不上、内联又会造出第二份身份 → **构建期报错**。`@deepseek-ai/cordis/src/*` 例外：根出口 `export *` 覆盖同符号，构建期折叠回包名键                                                               | `platformSubpathOf` / `foldSourceSubpath`                  |
| 依赖声明          | client 包 Cordis 在 `peerDependencies` + `devDependencies`；浏览器与类型依赖只在 `devDependencies`；Host 值导入按 `safeHostDependencyExports` / `peerRequiredHostExports` 分类；只有 Host 运行库进安装依赖                                    | bundle 包的清单；`devkit audit` 的依赖判据                 |
| 资产              | `src/client/assets/`；`exports["./assets/*"] = "./lib/assets/*"`；`files` 含 `lib/assets`；URL 带内容版本                                                                                                                                     | `clientAssetPlugin` 的策略参数（当前没有包开 assets 出口） |

- `zephyr-app` 的 `./client*` 不在 dsh-bundle 线上，保持纯 ESM，不按工厂构建。
- `./ui` 是纯 ESM 面，不参与 client 工厂与模块表规则。

## 五、行为与边界

- **正常路径**：`just build`（`devkit build` 内先确保全仓声明树——进程锁、全仓一次，再产 `dist` 与 `dist/*.d.mts`、写回清单、bundle 生成 patch）→ `just verify-release` → `just publish-npm` 逐包发布；CI 在 `main` / `next` 推送时自动发 GitHub Packages。
- **错误**：产物没齐时写回**不写也不报**（验收看清单键，不看构建退出码）；发布命令在进入任何发布子进程之前跑清单覆盖判据，缺键或目标不在即停——它与 `just verify-release` 是同一份实现。
- **顺序**：真发是 `pnpm -r publish --workspace-concurrency=1`——**依赖图由 pnpm 排（被依赖的先发），串行由这一个参数保证**；
  工具只按 dist-tag 分组，不自己排包序。
- **取消**：发布中途失败，已发成功的包不回滚；重跑按 registry 状态跳过已发布的包。
- **并发**：构建的包调度交给 pnpm（`pnpm -r exec`，默认按 CPU）；dts 由 `devkit build` 内的目录锁串行——多包并行构建时只有第一个进入的进程生成声明树（并写完成标记），其余等锁后直接取用；发布逐包串行。
- **幂等**：已发布版本跳过；registry 以「不能覆盖已发布版本」拒绝时按已发布处理，不让重复发布把任务判成失败。
- **认证**：CI 只用 `GITHUB_TOKEN`；npmjs 用发布者本机 `npm login` 的凭据，token 不进仓库、不进 CI。

## 七、取舍

| 选项                                | 否掉的理由                                                                             |
| ----------------------------------- | -------------------------------------------------------------------------------------- |
| 分批翻公开（框架 → 插件 → 桌面）    | 发布集合与版本线会多出一份「哪些发了」的状态；首发仍可内部按闭包推进，但不改变集合定义 |
| 源码包（`@morlay/zephyr-rdb` 现状） | 消费方要自备 TS loader；与「统一产物包」两套口径，装出来才发现少面                     |
| 手写 `publishConfig`                | 漏键即少面；`dsh-skill` 的悬空 `dist` 就是手写的代价                                   |
| 每包各自出 dts                      | 单包类型图重复建，实测占单包构建 82%；全仓一次只几秒                                   |
| npmjs 由 CI 自动发                  | token 进 CI、无法人工卡点；预发布与版本号抢占需要在发布者眼前决定                      |
| 两个 registry 各一套版本            | 同一份代码两个版本号，消费方按来源判断兼容性，徒增解释成本                             |
