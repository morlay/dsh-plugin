# npm 发布线（packages 全员发布）

状态：已对齐——发布集合、形态、通道、版本与验收已定；实施未开始
范围：`packages/**` 的 npm 发布线——发布资格、每个包的发布形态、清单真源、版本与 dist-tag、CI 与本地两条通道、发布前验收
非目标：`devpackages/**`（全部私有、`@local` 前缀、不发布）；`apps/**`（示例工作区）；上游 `@deepseek-ai/*` 的发布；桌面应用的签名与分发
关联：[系统设计](./20260917-系统设计.md) · [工具链层设计](../../devpackages/.agents/designs/20261113-工具链层.md) · [设计 20261118-构建与审计](../../devpackages/devkit/.agents/designs/20261118-构建与审计.md) · [ADR-npmjs 发布走本地命令](../adrs/20261118-npmjs发布走本地命令.md) · [ADR-插件与 dsh 运行时按同一版本线配套](../adrs/20260924-插件与dsh运行时按同一版本线配套.md) · [债务 CI 发布链引用已删除的 dshdev](../debts/20261113-CI发布链引用已删除的dshdev.md)

## 一、决定

| #   | 议题        | 决定                                                                                                                                                                                     | 一句话理由                                               |
| --- | ----------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------- |
| 1   | 发布资格    | `packages/**` 全部发布（除 `apps/**`）；首发一次全翻 `private: false`；`devpackages/**` 保持 `@local` 私有                                                                               | 一个发布集合、一条版本线，避免维护「哪些发了」的隐式状态 |
| 2   | 发布形态    | 有 TS 源码入口的包统一产物包（`dist` + `.d.mts`）；`@morlay/dsh-oxc-node` 保持手写 `register.mjs` 单文件                                                                                 | 消费方不需要 TS loader；单文件 loader 本身就是产物       |
| 3   | 清单真源    | `exports` / `publishConfig.exports` / `engines.dsh` 由 `devkit build` 写回，不手写                                                                                                       | 漏一个键就是发布包少一个面，手写挡不住                   |
| 4   | 出口规则    | `./ui` 是纯 ESM 浏览器面；只有 `exports` 含 `./dsh-bundle` 的包才处理 client；`./dsh-bundle` 的源是 `src/cordis-register.ts`，默认导出一个 cordis 插件，**只进 `publishConfig.exports`** | 开发态误引 `./dsh-bundle` 会走出第二条装配路径           |
| 5   | bundle 标记 | `dsh.bundle = { patch: "./cordis.patch.yml" }`；patch 的行清单（`id` / `disabled` / 配置）优先从 `cordis-register.ts` 读，读不到由 `tsdown.config.ts` 手写                               | 装配声明只有一处真源，且要能表达禁用与配置               |
| 6   | client 依赖 | client 半按上游 `dsh.client` 声明与模块表规则构建：基线外部 + `dsh.client.external`，其余内联；详见「四、client 半的上游要求」                                                           | client 的依赖面由上游运行时决定，不能按 host 的内外联猜  |
| 7   | 声明（dts） | `dts-prepare` 统一全仓生成一次（进程锁），`just dts` 跑并落位到各包 `dist`；tsdown 不再出声明                                                                                            | 单包 dts 成本高（实测占单包构建 82%），全仓一次只几秒    |
| 8   | 版本        | zephyr 家族与插件同一条版本线，首发 `0.2.0-alpha.0`；`@morlay/dsh-oxc-node` 独立版本线（首发须高于 npm 现有 `0.2.13`）                                                                   | 家族内互相依赖，同版让 `workspace:^` 的替换语义稳定      |
| 9   | 通道        | GitHub Packages 只走 CI（自动发未发布的新版本）；npmjs 只经本地 `just publish-npm` 手动发同一组、同版本                                                                                  | token 只在发布者本机；npmjs 需要人工卡点                 |
| 10  | dist-tag    | 稳定版 → `latest`；`-alpha.*` → `alpha`；其余预发布 → `next`                                                                                                                             | 预发布绝不落 `latest`                                    |
| 11  | 发布前验收  | 清单覆盖、目标存在、tarball 内容、临时项目安装冒烟；任一红即停                                                                                                                           | 发布是单向操作，验收必须在按下按钮之前                   |

## 二、现状事实

- **可发布包 4 个**：`@morlay/zephyr`、`@morlay/zephyr-rdb`、`@morlay/zephyr-desktop-shell`、`@morlay/dsh-oxc-node`（`private: false`）；其余 33 个为 `private: true`。
- **形态漂移**：`zephyr-rdb` 无 build、无 `publishConfig`（发布出去是 `src/*.ts`）；`zephyr` 的 `dist` 是空目录；7 个 `private` 包带 `publishConfig`（`dsh-fs` / `dsh-auth` / `dsh-setting` / `dsh-skill` / `dsh-web-access` / `dsh-workspace` / `zephyr-desktop-bundle`），其中 `dsh-skill` 的 `publishConfig.exports` 指 `dist/*`，但它既无 build 也无 `dist`。
- **bundle 与行入口零实现**：`packages/**` 没有任何 `dsh` 字段；`cordis-register.ts` 只在 `packages/zephyr/zephyr/README.md` 被提到，仓库里没有实现；`agent-ex` 4 个包是 dsh bundle 的落点。
- **浏览器面命名**：10 个包用 `./ui`（`src/ui/`）；只有 `zephyr-app` 用 `./client`（`src/client/`），它不在 dsh-bundle 线上。
- **工具包与声明**：`devpackages/tsdown-plugin-cordis` 的 `build:done` 硬调 `@local/dts-prepare` 与本仓 `target/dts`；`CordisPluginOptions.dts` 声明了但没被读。清单仍全部手写。
- **通道现状**：`just publish` 恒 `exit 1`（红线）；CI 的 publish job 仍调用已删除的 `dshdev`（[债务 CI 发布链引用已删除的 dshdev](../debts/20261113-CI发布链引用已删除的dshdev.md)）。
- **registry 现状**：npm 上 `@morlay/zephyr*` 没有任何版本；`@morlay/dsh-oxc-node` 已有 `0.2.13`（来自另一条发布线）；上游 `@deepseek-ai/dsh-session@0.2.2-rc.3` 与 `@deepseek-ai/cordis@4.1.0` 在 npm 可解析，`workspace:^` 的替换目标存在。

## 三、模块边界与接口

| 模块                        | 拥有（职责与不变量）                                                | 不拥有（明确排除）                   | 依赖方向                         | 接缝 / 适配器                            |
| --------------------------- | ------------------------------------------------------------------- | ------------------------------------ | -------------------------------- | ---------------------------------------- |
| 发布线（本文与 `justfile`） | 发布集合、版本线、dist-tag、两条通道、发布前验收                    | 单个包的出口内容、产物长什么样       | `justfile` → 各包 build          | `just publish-npm` / CI 的 publish job   |
| `devkit`                    | 构建编排、配置合成、产物形态、清单写回、bundle patch 生成；审计判据 | 发布集合、版本号、registry、声明内容 | 各包 `tsdown.config.ts` → 本模块 | `cordisPlugin(options)` / `devkit audit` |
| `dts-prepare`               | 全仓声明树的生成、进程锁、完成标记与落位到各包 `dist`               | 清单写回、包级出口                   | `just dts` → 各包 `dist`         | `ensureWorkspaceDts` / `emitDts`         |
| `just publish-npm`          | 选包、算 dist-tag、跳过已发布、`--access=public`、发布前校验        | 构建、版本 bump                      | 发布者 → npmjs                   | npmjs registry                           |
| CI publish job              | 认证与逐包发布到 GitHub Packages                                    | 本地发布、版本 bump                  | CI → GitHub Packages             | `NODE_AUTH_TOKEN` / `GITHUB_TOKEN`       |

接口：

- `cordisPlugin(options)`（`@local/devkit/build`）新增三项：`bundle`（声明 patch 的行清单，生成 `cordis.patch.yml`）、`publishOnly`（入口只进 `publishConfig.exports`，如 `dsh-bundle`）、`client`（按 `dsh.client` 声明与模块表规则打 client 半）。选项表与行为见[设计 20261118-构建与审计](../../devpackages/devkit/.agents/designs/20261118-构建与审计.md)。
- `just publish-npm [--dry-run]`：不带参数发发布集合里「版本未发布」的包；`--dry-run` 只打印包名、版本与 dist-tag，不触网发布。认证由发布者自己的 `~/.npmrc` 提供。
- `just dts`：全仓一次生成并落位声明；`just build` 之前跑（本地与 CI 同一条命令）。
- `just build`：调 `devkit build`（发现包、跑 tsdown、汇总）；`just audit`：调 `devkit audit`（逐包判据 + 根上汇总）。
- `just publish`：CI 的 GitHub Packages 发布（逐包、跳过已发布、按版本算 dist-tag）；本地直接跑时检测不到 `GITHUB_ACTIONS` 就 `exit 1`——红线仍在。
- `just version <x.y.z>`：只 bump 发布集合（zephyr 家族与插件同版）；`@morlay/dsh-oxc-node` 独立版本线，单独改。

契约变更：

| 契约                       | 现在                                | 谁必须跟着改                                             |
| -------------------------- | ----------------------------------- | -------------------------------------------------------- |
| `packages/**` 的 `private` | 4 个公开、33 个私有                 | 全部包清单；`just version` / CI 的过滤条件               |
| `engines.dsh`              | 无（清单里没有 `dsh` 字段）         | 每个 `private: false` 的包清单（构建写回）               |
| `dsh.bundle`               | 无                                  | `agent-ex` 4 个 bundle 包 + 生成器                       |
| `./dsh-bundle`             | 无                                  | `agent-ex` 4 个 bundle 包（新增入口）                    |
| `dsh.client`               | 无                                  | bundle 且有前端的包（`better-session` / `session-mode`） |
| `./client` 的发布态        | 只有 `zephyr-app` 的纯 ESM 源码出口 | 含 `./dsh-bundle` 且有前端的包                           |
| 红线的发布措辞             | 「严禁本地私自 `pnpm publish`」     | `AGENTS.md`、[如何验证](../standards/how-to-verify.md)   |

## 四、client 半的上游要求

结论：client 半按上游 `dsh.client` 声明与模块表规则构建，依赖面不能按 host 的内外联猜。

真源：`vendor/deepseek-harness/packages/client/tsdown.client.ts`、`vendor/deepseek-harness/packages/client/AGENTS.md`、`vendor/deepseek-harness/docs/subsystems/client-modules.md`。

| 面                | 上游要求                                                                                                                                                                                                                                      | 我们的落点                                           |
| ----------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------- |
| 声明 `dsh.client` | `platform: 'web'`；`inject` 只表示包名依赖边（不排序激活）；`immediately` 只给基础设施预取；`external` 是模块表请求，功能插件不得用它拿别的插件的值                                                                                           | bundle 包的 `package.json` 声明；`devkit build` 校验 |
| 产物              | CJS 工厂：`window.__ModuleLoader__.load({ id, factory })`，外部经注入的 `require` 解析                                                                                                                                                        | `./client` 的 `default` 条件                         |
| 外部与内联        | 外置只有两个来源：**baseline**（`PLATFORM_MODULES` 的精确键）与 `dsh.client.external` 点名的 specifier；**其余一律内联**，包括我们自己的 `@morlay/*`（di 里上游 client 插件由 `zephyr-app` 进程内挂载，不是独立 Loader 行，内联才是正确形态） | `clientRowExternals` + `clientBundleSpec`            |
| baseline 子路径   | 模块表按精确键解析：`<baseline>/<子路径>` 既答不上、内联又会造出第二份身份 → **构建期报错**。`@deepseek-ai/cordis/src/*` 例外：根出口 `export *` 覆盖同符号，构建期折叠回包名键                                                               | `platformSubpathOf` / `foldSourceSubpath`            |
| 依赖声明          | client 包 Cordis 在 `peerDependencies` + `devDependencies`；浏览器与类型依赖只在 `devDependencies`；Host 值导入按 `safeHostDependencyExports` / `peerRequiredHostExports` 分类；只有 Host 运行库进安装依赖                                    | bundle 包的清单；`devkit audit` 的依赖判据           |
| 资产              | `src/client/assets/`；`exports["./assets/*"] = "./lib/assets/*"`；`files` 含 `lib/assets`；URL 带内容版本                                                                                                                                     | 需要资产的 bundle 包                                 |

- `zephyr-app` 的 `./client*` 不在 dsh-bundle 线上，保持纯 ESM，不按工厂构建。
- `./ui` 是纯 ESM 面，不参与 client 工厂与模块表规则。

## 五、行为与边界

- **正常路径**：`just dts` → `just build`（`devkit build` 产 `dist`、写回清单、bundle 生成 patch）→ `just publish-npm` 逐包发布；CI 在 `main` / `next` 推送时自动发 GitHub Packages。
- **错误**：产物没齐时写回**不写也不报**（验收看清单键，不看构建退出码）；发布前校验失败即停，不进入发布子进程。
- **取消**：发布中途失败，已发成功的包不回滚；重跑按 registry 状态跳过已发布的包。
- **并发**：`just dts` 用目录锁串行；发布逐包串行（`--workspace-concurrency=1`）。
- **幂等**：已发布版本跳过；registry 以「不能覆盖已发布版本」拒绝时按已发布处理，不让重复发布把任务判成失败。
- **认证**：CI 只用 `GITHUB_TOKEN`；npmjs 用发布者本机 `npm login` 的凭据，token 不进仓库、不进 CI。

## 七、取舍

| 选项                                | 否掉的理由                                                                             |
| ----------------------------------- | -------------------------------------------------------------------------------------- |
| 分批翻公开（框架 → 插件 → 桌面）    | 发布集合与版本线会多出一份「哪些发了」的状态；首发仍可内部按闭包推进，但不改变集合定义 |
| 源码包（`@morlay/zephyr-rdb` 现状） | 消费方要自备 TS loader；与「统一产物包」两套口径，装出来才发现少面                     |
| 手写 `publishConfig`                | 漏键即少面；`dsh-skill` 的悬空 `dist` 就是手写的代价                                   |
| 每包各自出 dts                      | 单包类型图重复建，实测占单包构建 82%；全仓一次只几秒                                   |
| npmjs 由 CI 自动发                  | token 进 CI、无法人工卡点；预发布与版本号抢占需要在发布者眼前决定                      |
| 两个 registry 各一套版本            | 同一份代码两个版本号，消费方按来源判断兼容性，徒增解释成本                             |
