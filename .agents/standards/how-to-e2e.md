# 真装配与端到端

本仓**没有浏览器驱动层**：根 [`package.json`](../../package.json) 不装 playwright / stagehand。
**门禁只认包内用例**（能力层与扩展包的 `__tests__`，happy-dom 跑）；整装渲染与真机行为是**显式人工门**——
跑它们是加证据，不是交付门槛，`apps/*` 不设测试门禁。这一层管三件事：哪类证据落在哪、门控怎么写、什么不算证据。

## 证据分层：门禁内 vs 人工门

| 层            | 判什么                                                                    | 落点                                                                                             | 是不是门禁                 |
| ------------- | ------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------ | -------------------------- |
| 组件 / 域行为 | 一个视图或一个端点的输入输出、槽位注册、错误分支                          | 包内 ui 面的 `__tests__`                                                                         | **是**（随包级 vitest 跑） |
| 整装渲染      | 应用的**真实**服务端清单 + **真实** client 清单装起来后，`#root` 里有东西 | **不再有默认 spec**：要这条证据时自己起真后端 + 真 wire 跑一次（判据见下节）                     | **否**：人工门             |
| 真机门控      | 内核真的照我们生成的参数执行                                              | **不再有默认 spec**：要验时按下面「门控 e2e 的判据」新写一条（自带门控，`TEST_SEATBELT=1` 才跑） | **否**：人工门             |

框架自己的渲染骨架（链 → root slot → `mount`）在
[`render.smoke.spec.ts`](../../packages/zephyr/zephyr-app/src/client/__tests__/render.smoke.spec.ts)，
它不装业务行——骨架能力归框架，组合由装配层的构建与清单评审看。

## 整装渲染（人工门）的判据

这一节只在**显式要跑它**时适用：它不构成交付门槛，红绿也不作为「这份改动没验证」的理由。

- **两面都必须是真清单**：服务端用 `customProvidersOf({ dataDir })` 起 `bootstrapApplication`，浏览器侧用
  `appClientProviders()` 起 `bootstrapClient`；把某一面换成假件就不是这一层。
- **可判定的四条**：`document.getElementById("root")` 非空且 `innerHTML` 非空；运行期 `console.error` 为零；
  `Debugger.diagnostics().rows` 的每一行都是 `started`；`dispose` 后不留临时数据根。
- **端口与数据根由用例给**：`PORT=0`（内核分配），数据根用
  [`tempDataDir`](../../packages/zephyr/zephyr-app/src/testing/index.ts)，`afterEach` 里 `cleanupDataDirs`。
- **happy-dom 的缺口补桩，并写明是环境缺口**：`document.fonts` 缺失要让上游输入条能挂载，桩代码在
  `beforeEach` 里、注释说明「真浏览器有、这里没有」。
- **收尾给足预算**：`dispose` 用 `Promise.race` 兜底 10s，`afterEach` 给 `90_000`；否则一个卡住的行会把
  整轮测试拖成超时。

## 门控 e2e 的判据

- **文件名 `*.e2e.spec.ts`，位置在包内的 `__tests__/`**：`just test` 会收集它，所以它必须**自带门控**、
  默认 `skip`，不靠"记得别跑"。
- **文件头写清三件事**：门控变量（`TEST_SEATBELT=1`）、为什么默认跳过（内核行为随平台/版本变）、
  真机怎么跑（完整命令）。三件事缺一，这条用例就是噪音。
- **门控要探环境，不只看 `process.platform`**：Seatbelt 还要探 `/usr/bin/sandbox-exec` 是否可用——
  探针非零通常意味着「当前进程已经在沙箱里」，这时跳过是对的（跑下去只测到"沙箱不可用"）。
- **默认套件里只断言「我们生成了什么」**：profile 文本、argv 追加位置、拒绝项；「内核照不照做」只在门控里。

## 不算证据

| 反模式                                                   | 为什么                                                      |
| -------------------------------------------------------- | ----------------------------------------------------------- |
| 只断言「HTTP 200 / web ready」                           | 那只证明宿主起来了，不证明页面渲染                          |
| 用模型驱动的 `act()` / `extract()` 做断言                | 依赖模型、慢、不稳定；断言只读 DOM 与公开面                 |
| 在整装用例里重测组件交互 / 表单校验 / 纯函数             | 那是包内 happy-dom 用例的活                                 |
| 固定 `setTimeout` 等状态                                 | 单跑够、整批不够，表现是「单跑绿、整批红」；用 `vi.waitFor` |
| 把真机断言塞进默认集                                     | 红绿取决于跑它的是谁，不是信号                              |
| 为 e2e 加「调试用」的全局钩子（如 `globalThis.__CTX__`） | 当前**没有**这种钩子；要读装配结果就走 `Debugger` 的公开面  |

**引入浏览器驱动时的判据**（当前未引入）：驱动依赖进 `devDependencies`；单独一条命令（不进 `just test`）；
断言只读 DOM 与公开面；需要模型或密钥的步骤不进用例。
