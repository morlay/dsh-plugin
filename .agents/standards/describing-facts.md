# 描述事实

**描述**是任何声称事实的文本：`README.md`、记录树、manifest 文案、schema 的字段说明、给模型看的文案。
这一层管两件事：**承载描述的地方必须与真源一致**；**引用代码必须写成人能核对的形式**。

本仓库没有独立的文档检查命令（[justfile](../../justfile) 的 lint 注释即口径），下面两类判据靠评审时人工核对：

- 行内代码里的工作区路径必须存在，`just <recipe>` 必须在根 [justfile](../../justfile) 里；
- 相对链接必须可达。

## 一个描述只有一个真源

描述性载体不止 README 一种，**每一类各有自己的真源**——改描述 = 改真源，然后让载体跟上：

| 载体                                         | 真源                                     | 反例（都是真出过的形态）                                              |
| -------------------------------------------- | ---------------------------------------- | --------------------------------------------------------------------- |
| `README.md`、`.agents/**` 的叙述             | 代码（行为、接缝、依赖方向）             | 文档说某个包「收窄工具目录」，而该包代码里只是记了一笔、没拦          |
| `package.json` 的 `description`              | 包的门面：该包 `README.md` 的一句话定位  | README 换了定位，`description` 还留着上一轮职责（消费方看到的是后者） |
| schema 的 `description()`                    | 该字段**今天**的实际语义（含默认与边界） | 只写「配置为 `false` 时会丢掉」，不写「变化时也丢」                   |
| 给模型看的文案（工具说明、技能目录、注入面） | 它对应的机制                             | 文案说「按 X 分组」，而分组实际由另一处常量决定                       |

规矩：

- **描述不复制**：一处已定义的事实，别处只链接。home 表见 [`AGENTS.md`](../../AGENTS.md)。
- **给模型的文案与机制同源**：机制改了必须同一处改文案；文案里的行为、边界、默认值都要在代码里找得到。
- 判据：**只看载体，能回答「真源在哪」**——回答不了，说明这条描述没有真源，得先定真源再写。

## 底层不描述上层

**一条规则**：包 README 与包级记录只写本包的事实；「别人怎么用它」写在上层文档或层设计里——跨包关系只能**上层引用下层**。

- 该写的：本包的面与出口、令牌与配置、行为与不变量、本包的接缝与判据。
- 不该写的：上层入口怎么装（装配面装哪些行、剔哪一行、清单顺序）、兄弟包的客户端面与界面行在哪、上层应用的用例路径当本包判据。
- 允许一句**不拥有**指针（「X 不在本包」）与指向本包 `.agents/` 的链接；再往下解释去向、怎么用，就成越界。

典型形态：底层 README 里出现「装配面要…」「`apps/…`」「…的界面行住在兄弟包」「浏览器半只引某个兄弟包的面」——这些都是上层的事，写在上层文档里。

判据（**评审人工**）：只看这份包 README，每个跨包事实都应能改由上层文档或层设计承载；出现即越界，把那段挪上去，底层只留一句不拥有。线索：

```sh
grep -rnE "装配面要|装配面必须|由装配面|apps/|住在 @" packages/*/*/README.md
```

为什么：两边互相解释会互相打脸，改一处就得改两处，最后谁也说不出真源在哪。

## 引用代码：路径与行号

- **路径引用必须指向真实存在的文件**：写**全路径**（从仓库根起算的 `packages/<family>/<pkg>/src/x.ts`）；
  包内文档可写包内相对路径，跨包一律全路径。路径别只写在链接文本里——文本与链接目标要一致。
- **行号是债，能写文件名就别写行号**：引用优先写到文件名或小节名；真要指到片段，就**在同一笔改动里同步**。
- 上游文件的引用要能落到 `vendor/**` 里的真文件：写从上游仓根起算的相对路径，不按发布包的 d.ts 猜语义。
- **没有例外表**：没有机械检查，也就没有可维护的例外表。确实只能写成通式（省略前缀、「同包」指另一个包）的
  引用，就地写清上下文；能改成全路径或补链接的，先改。
- 反例（占位示意）：

  ```
  （引用写法 · 反例）
  src/<模块>.ts:112-140   ← 行号与内容绑死：挪一次就漂，读者也不知道该信谁
  src/<模块>.ts           ← 只引文件，读者按文件名 / 小节名找
  ```

## 注册顺序 = 瀑布嵌套顺序

cordis 的 `_hooks` 按插入序决定 waterfall 的嵌套：**先注册的在最外层**，站在内层 `next()` 之后看到的是
**内层**的结果。

- 要「别人的东西都跑完之后的最终结果」——收窄后的工具目录、或要丢掉别人 append 进来的注入——必须
  `{ prepend: true }` 抢最外层。**这不是优化，是正确性**：`session-mode` 的三处 `prepend` 就是这条
  （`src/session-mode.service.ts`、`src/session-scope.service.ts`、`src/context-assembler.provide.ts`）。
- **判据**：写「拿到最终 X」这类 hook 时，问一句「我注册在谁的外面」；判据用例是那条**最内层结果**的断言。
- 反例：hook 里读 `next()` 之后的 `ctx.tools` 记作「最终目录」——实际拿到的是被后续行收窄前的全量，
  记录与真实可见面从此不一致（而且不报错）。

## 抑制类开关：两侧都要写满

抑制 / 接管官方注入面的配置项，语义有**两个方向**，只写一半就是 bug：

- 配置 **`false`**：**无条件丢**——首次注入丢，**内容变化后再次注入也要丢**；
- 配置 **`true`**：**零干预**——官方「首次注入 + 有变化才注入」的机制照常放行，不要自己重放或提前注入。

判据：同一份配置在「首次」与「内容变化后」两条路径上表现一致（各配置档 × 两档 = 用例矩阵）。
反例：只实现「首次不注入」，变化时官方又注入一次；或把 `true` 实现成「主动补一次」，于是双重注入。
写文档的人同样容易只写一半：**写这类开关必须把 `false` / `true` 两侧的边界都写出来**。

## 包出口与代码布局

一个面（subpath export）对应一个入口文件，两者名字一致：

- `. -> src/index.ts`；`./server -> src/server/index.ts`；`./ui -> src/ui/index.ts`；`./testing -> src/testing/index.ts`；
  以此类推。加面 = 加入口文件 + 在 `exports` 加一项。
- **工作区里的 `exports` 指源码**（`./src/…`），开发态因此不需要构建；**发布态清单**写在 `publishConfig.exports`
  里，指 `./dist/**`（示例：`packages/zephyr/zephyr/package.json`）。private 包只写工作区那份。
- 入口里出现实现或定义就是放错了位置：入口只 re-export（应用侧写 `src/index.ts` 时同样用这条判据）。
- 判据：`src/<面>.ts`、`exports` 的键、`publishConfig.exports` 的键三处同名；改名的同一笔改动里一起改。
- 反例：手改发布态清单指一个不存在或与入口不同名的文件——工作区里能跑，装出来的包少一个面。

## 记录与边界

记录怎么写（命名、第一屏、小节名、只写现状、判据可判定）的判据只有一个 home：
[记录格式](./record-format.md)。这里只留两条与「描述事实」直接相关的：

- **边界写四行**：模块 / 拥有 / 不拥有 / 依赖方向 / 接缝。缺「不拥有」那一行，读者就分不清越界长什么样。
- **术语用定义它的包的词**（[定义权地图](../GLOSSARY-MAP.md)）；上游概念用上游真源的词并标注「上游概念」。
