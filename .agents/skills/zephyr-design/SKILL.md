# 设计（design）

设计先于实现，产出是**决策与词汇**，不是代码。**没与用户达成共识之前，不写盘、不写代码。**

本技能只定义流程与判据；记录树布局、命名、命令入口、红线与术语归属按**项目自己的约定**（工作区指令与项目记录）。
技能不复述项目事实。

## 一、先访谈：把决策交出去

设计是一棵**树**：每个决定下面挂着依赖它的决定。**前沿**是所有前置条件已经确定的决定——现在就能问、不必猜还没听到的答案的问题。

按轮次推进：一轮问完整片前沿；每个问题编号、给选项、给**推荐的答案**，措辞让「是」等于接受推荐。用户答完再重算前沿——已定的决定把前沿往外推；依赖本轮另一个开放问题的，属于**更晚**的一轮。

```
❓ **Q1** - **<问题标题>**：<正文，可多段，含选项>

➡️ <推荐的答案>

---
```

- **事实自己查，决策交用户**：需要环境事实（文件、工具、上游源码）时派子代理去查，不要问用户自己能查到的东西；一次进行中的探索只挡住它下游的问题，其余前沿照问。
- **前沿为空才算达成共识**。共识之后才动笔（记录、规格、票据）。

## 二、边访谈边建模

- **术语冲突当场摊开**：「术语表把 X 定义成 A，你说的是 B，哪个对？」
- **模糊词换规范词**：「会话」是上游的 `Session`，还是我们的编辑目标？
- **用具体场景压测**关系与边界；**交叉核对代码**：文档说 A、代码做 B，停下来问清。
- 借外部系统的词先核对真源（源码与它自己的文档），别按发布包的类型声明猜语义。
- 词定了**立刻**写进它该在的那份术语表（归属按项目约定），不批量补。

决策记录（ADR）只在三条**同时**成立时立：难逆、脱离上下文会困惑、真有取舍。任一不满足就不立。

## 三、模块与边界

**模块 / 接口 / 实现**：接口是调用方正确使用它所需知道的一切（签名、不变量、顺序约束、错误模式、配置要求），不只是类型表面。别用「组件」「服务」「API」替代。

**深度**：小接口后面的多行为。判据是**删除测试**——删掉这个模块，复杂度是消失（它只是透传），还是在 N 个调用点重新出现（它物有所值）。

**接缝**是行为可替换的位置；**适配器**是接缝处的具体实现。**一个适配器 = 假想接缝，两个 = 真接缝**。

**杠杆效应 / 局部性**：调用方从深度得到的能力；维护方把变更、知识、验证集中在一处。**接口就是测试面**——调用方与测试穿同一个接缝；想越过接口去测，说明接口形状不对。

**边界写四行，缺一行就没定边界**：

| 模块 | 拥有（职责与不变量） | 不拥有（明确排除） | 依赖方向 | 接缝 / 适配器 |
| ---- | -------------------- | ------------------ | -------- | ------------- |

判据：读者能回答「这块归谁、越界长什么样」。跨模块时边界靠接口与出口表达，不靠命名；一个能力只在一个模块里有 owner——两处各实现一半就是边界没划。

接口守三条：**接受依赖而不自己创建、返回结果而不产生副作用、表面尽量小**。定义一个契约时同时问它**能不能在局部被替换成假实现**（客户端半用 mock server、服务端半用 mock client）；做不到——依赖私有实例、必须真宿主才能跑——视为**接缝放错了**，重新设计接缝，而不是加探针。

依赖的实现耦合混乱、或它的形态无法被安全包装时，**按契约重新实现、只对齐行为**（wire 协议 / 帧格式 / 语义），不复制内部结构。判据：包装层是否需要在实现里猜对方的私有细节——需要猜，就重写。

## 四、扫候选（人工唤醒）

定范围：用户指了方向就用它，否则按近期提交找热点，变更分散就扩大范围并写明为什么。

先读涉及上下文的术语表与决策记录，再遍历代码，只记**确实遇到摩擦**的地方：理解一个概念要在许多小模块之间跳；模块只是薄薄包一层外部服务再注册；纯函数被抽出来可测试、真正的缺陷却藏在调用方式里（没有局部性）；紧耦合跨接缝泄漏；没有测试或难以从当前接口测试。对可疑项做**删除测试**。

候选报告写到项目约定的临时产物目录（缺省 `.scratch/`），格式与命名见 `references/architecture-review-format.md`。与既有决策冲突只在摩擦大到值得重开时提，并在卡片里标注。**用户选中一个之前不提接口**；选定后回到第一节的访谈。

## 五、产出落盘

- 一个事实只有一个 home：写之前先找它现在在哪，**找到就改那一份**，找不到才新建；别处要用就链接过去。
- 记录类型与判据：**术语**（只放词）、**设计**（取舍与边界）、**决策记录**（难逆 + 脱离上下文会困惑 + 真有取舍）、**债**（明知不好先这样 + 可判定的销账条件 + 不修的理由）。每类只写它该写的。
- 命名：三类记录都用 `<YYYYMMDD>-<标题>.md`（日期是采纳 / 创建日期；同一天多篇靠标题区分，没有序号）。H1 就是标题本身，不带日期或序号；designs 标题写主题、adrs 标题写结论句、debts 标题写现象。小节名照模板，不另创。
- 引用：**同层**写短名；**跨层**给相对链接，目标用完整文件名。
- **记录只描述现状**：不写取代链、不写「已废弃 / 被 X 取代 / 迁移 / 原来怎样」——历史由版本控制保证。决策变了就改那一份，不再成立就删掉。

## 六、写文档的底线

- 结论放最前（决定表 / 一句话），事实给可核查定位；**行号是债**，能写文件名就别写行号。
- 每节首句就是这节的结论；段落不超过三行；对比用表，不用长段落。
- 不写实现流水账、不写评审历史、不复述代码、不做设计说明式注释。
- 设计改了**先改文档再改代码**；状态行写当前状态，不写演变。
- README 只做门面：一句话定位、一段用法、其余链接到 home；超重的 README 记债，不就地扩写。
- 具体判据（路径可达、链接可达、术语归属、可读性）按项目规范；本技能不复述。
