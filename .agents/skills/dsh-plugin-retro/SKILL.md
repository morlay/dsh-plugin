# 复盘（retro）

把对话里说过、但只活在对话里的要求，沉淀成**以后还算数的流程与规范**。产出是记录改动，
不是总结这次做了什么；**没经用户逐条确认，一个字都不写**。

## 一、捞什么

只看**换个任务还成立**的要求：

- 用户明说的通用要求（「以后都…」「别再用…」「每次先…」）；
- 用户的纠正（「不是这样，应该…」）——纠正背后常是一条没写下来的规范；
- 跨多轮重复出现的偏好；只出现一次的先问一句「这条以后还算数吗」，不要自己升级成规则；
- 已经照做、但哪个 home 里都没写的做法。

不捞：这次的任务参数（改哪个文件、跑哪条命令）、只对当前任务成立的临时约定。

**先查再写**：一个事实只有一个 home——候选若已在某处写过，指出来、改那一份，不重复立项；
与既有 ADR 冲突的不写，按 [`dsh-plugin-design`](../dsh-plugin-design/SKILL.md) 的判据问用户
是否要重开那条决策。

## 二、流程还是规范

| 候选长什么样                             | 落到哪                                                            |
| ---------------------------------------- | ----------------------------------------------------------------- |
| 「必须 / 不许 / 一律」的约束，违反就是错 | 改动所属层的 `.agents/standards/`（如何写 / 如何验证 / 描述事实） |
| 「什么时候做、按什么步骤做」             | `.agents/skills/` 里的 `SKILL.md`                                 |

判据：**规范是判据，流程是步骤**。两者都够格的，判据留在 standards、步骤写进技能，技能只链接
不复述。不在这两类里的（术语、设计、ADR、债务）→ 不写，指给
[`dsh-plugin-design`](../dsh-plugin-design/SKILL.md) 按它的判据分流。

## 三、先出候选清单，再落笔

候选写进 `.scratch/`（不进仓库），一条一段，四件事齐全：

- **出处**：用户原话（引号）或轮次——别只写你的转述；
- **建议措辞**：能直接粘进目标文件的句子，用目标文件的口吻；
- **目标**：改哪个文件的哪一节，或新建（说明为什么没有现成的 home）；
- **判据**：换个任务为什么还成立。

清单**一次给全**，用 `ask_user_question` 逐条批：通过的才写；未通过的丢弃，不留 TODO、
不留半成品。

## 四、落笔

- 只改通过的那几条；措辞随目标文件的现有风格（standards 用「必须 / 判据 / 反例」那套），
  不新造一套说法；
- 规范里不写这次任务的沿革与流水账（记录只描述现状）；技能里只写流程，判据链接到 standards；
- 红线照旧：[`AGENTS.md`](../../../AGENTS.md)——上游 `@deepseek-ai/*` 与 `node_modules` 只读、
  本地不 `pnpm publish`；
- 自查按 [`how-to-verify.md`](../../standards/how-to-verify.md) 的「文档与记录」那行：相对链接
  可达、无悬挂引用（判据是 `just test` 里的 `doc-references` 与 `markdown-links` 两条 spec）。

## 五、收尾

回报改了哪些文件、每处加了什么、哪条候选被否掉；一条候选一笔改动，别顺手清理附近内容。
