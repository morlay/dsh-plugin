# 声明树生成失败：干净环境下清单写回跑不到

状态：触发中——眼下卡在单包试点：`packages/zephyr/zephyr` 接入后，干净环境拿不到清单写回
位置：`devpackages/dts-prepare/src/dts.ts`（`generateWorkspaceDts` 与它的 `run`）、`devpackages/tsdown-plugin-cordis/src/cordis-host.ts`（`buildDone` 先 `ensureWorkspaceDts` 再写回）；不可命名的类型在 `packages/zephyr/zephyr/src/compat/from-cordis.ts`；接入面见 [`20261113-迁移与接入边界.md`](../designs/20261113-迁移与接入边界.md) 第九节

**现象**

声明树生成用 `noCheck: true` 扫全仓，但 `tsc` 在当前树上**退出 1**：130 个 `TS2883`，其中 129 个是 `cannot be named without a reference to 'AdaptedClass'`，1 个是 `SessionFormatCatalog`；`run()` 把任何非零退出当失败，于是整个生成被判定失败（声明其实已落盘）。

```sh
pnpm exec node devpackages/dts-prepare/src/cli.ts    # exit 1（干净环境等价）
pnpm exec tsc -p .tmp/dts-host.json                  # 上一步写出的配置：exit 1；130 × TS2883
```

错误分布跨 15+ 包：`dsh-conversation` 35、`dsh-agent` 14、`dsh-agent-loop` 12、`dsh-workspace` 8、`dsh-sandbox` 8、`dsh-session` 6、`zephyr-app` 5 …；与接入无关——把试点配置复原后同一命令的计数与类型分布不变。

**影响**

接入本插件的包在 `build:done` 第一步就抛 `命令失败: pnpm exec tsc -p .tmp/dts-host.json`：**清单不写回**（`exports` / `publishConfig.exports` / `engines.dsh` 一个都不落），`just build` 在接入包这一行红。更糟的是产物此时已经写进 `dist/`，留下「产物是新布局、清单还是手写旧路径」的半成品。

**触发条件**

`target/dts/.complete` 不存在时（干净克隆、CI、`just clean-dist` 之后）第一次构建必触发——所以**任何包接入之前**都必须先还。本地有陈旧 `.complete` 时会假装正常，只有删掉它才看得见。

**销账条件**

Done when：干净环境（无 `target/dts/.complete`）下 `pnpm exec node devpackages/dts-prepare/src/cli.ts` 退出 0；等价判据：已接入插件的包在删掉 `.complete` 后 `mise exec -- pnpm --filter <包> run build` 退出 0 且 `package.json` 出现写回的键。

**不修的理由**

修法要同时动两处口径：`AdaptedClass` 能不能被命名（框架层的声明质量问题），以及 `TS2883` 这类「产物质量」诊断该不该让生成失败（`dts-prepare` 的判据）。按当前优先级（文档 > 类型约束 / 上游基础装配 > 构建接入 > 发布链），构建接入不推进实现；而今天没有任何 `packages/**` 的构建依赖本插件，这条债不阻断别处。
