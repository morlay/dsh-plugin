## 一、决定

| #   | 议题     | 决定                                                                                                                                                                           | 一句话理由                                         |
| --- | -------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | -------------------------------------------------- |
| 1   | 包结构   | `devpackages/tsdown-plugin-cordis` 改名 `devpackages/devkit`，`devpackages/audit` 并入；包名 `@local/devkit`，`private`，不发布                                                | 构建与判据共享包发现、汇总与日志，分两个包就要复制 |
| 2   | 命令面   | bin `devkit`，子命令 `build` / `audit`；`just build` 调 `devkit build`，`just audit` 调 `devkit audit`                                                                         | 两个命令同形：发现包、跑、汇总                     |
| 3   | 出口     | `.`（门面，只出类型与常量）、`./build`（`buildPackage` / `planOf` / `writeBuildManifest` / `writePackageManifest`）、`./audit`（规则与汇总）                                   | 构建与判据是两个面，按面开出口                     |
| 4   | 构建能力 | rolldown 构建（入口从包的 `exports` 推导，不依赖 tsdown）、产物形态、清单写回（private 分档、`publishOnly`、`bundle.patch`、`engines.dsh`）、client 半按上游 `dsh.client` 规则 | 发布态的清单与产物只在这里生成                     |
| 5   | 审计能力 | 面边界、声明未用、上游包唯一化、扩展边界；逐包 + 根上汇总；空输入退出 1                                                                                                        | 判据与构建同源，避免两套包列表                     |

| 7   | 依赖     | `oxc-parser`（audit AST）、`rolldown`（host 构建与 client 打包）、`lightningcss`（样式与资产）；不依赖 tsdown                                                                  | 原生/重依赖声明在运行期面；tsdown 由消费方提供     |
| 8   | 删除项   | 原 `@local/audit` 的两个 bin、原 `@local/tsdown-plugin-cordis` 的 `./dts` 悬空出口                                                                                             | 命令面统一到 `devkit`；悬空出口没有实现            |

## 二、现状事实

- 两个包各自有入口：`@local/audit` 的 bin 是 `dsh-audit-package` / `dsh-audit-report`；`@local/tsdown-plugin-cordis` 无 bin、出口只有 `.`。
- `justfile` 的 `audit` 直接 `node devpackages/audit/src/package-audit.ts | pnpm exec dsh-audit-report`；`build` 用 `pnpm -r ... run build`。
- 构建侧 `build:done` 硬调 `@local/dts-prepare` 与本仓 `target/dts`；`CordisPluginOptions.dts` 声明了但没被读。
- 测试面：`audit` 的 `rules.spec.ts`；构建侧 7 个 spec（清单写回、client 打包、样式与资产、依赖分流）。
- 工具链层设计把 `audit` 与 `tsdown-plugin-cordis` 列为两个模块。

## 三、模块边界与接口

| 子模块   | 拥有（职责与不变量）                                                | 不拥有（明确排除）             | 依赖方向                | 接缝 / 适配器                              |
| -------- | ------------------------------------------------------------------- | ------------------------------ | ----------------------- | ------------------------------------------ |
| `cli`    | 命令解析、包发现、并发与汇总；空输入即失败                          | 具体判据与打包规则             | 终端 → 本模块           | `devkit build` / `devkit audit`            |
| `build`  | rolldown 构建、产物形态、清单写回、bundle patch 生成、client 半规则 | 入口该有哪些、发布集合、版本号 | 各包 `exports` → 本模块 | `devkit build` / `planOf` / `buildPackage` |
| `audit`  | 判据规则、逐包 AST 检查、跨包汇总、`--write` 删未用依赖             | 判据语义（根规范持有）         | 本模块 → `oxc-parser`   | `devkit audit`                             |
| `shared` | 日志（`logOf`）、包发现与路径                                       | 业务规则                       | 各子模块 → 本模块       | 无                                         |

接口：

- `devkit build [--filter <pkg>]`：发现 `packages/*/*` 与 `devpackages/*`，逐包跑 build，汇总失败；**不生成声明**（先 `just dts`）。
- `devkit audit [--write]`：逐包判据 + 根上汇总；`--write` 删未用依赖；空输入退出 1。
- `devkit build [--filter <包>]`：从 `exports` 推导入口，rolldown 打 host 面，写回清单。
- 构建选项新增 `bundle`（patch 行清单）、`publishOnly`（只发布态入口，如 `dsh-bundle`）、`client`（`dsh.client` 声明驱动的 client 半）。

## 四、行为与边界

- **`devkit build`**：正常路径 = 发现包 → 逐包 rolldown → 写一次清单 → bundle 包写 patch；错误 = 构建失败时不写清单、不写 patch；并发 = 按 pnpm 的包调度，汇总按包名排序；幂等 = 清单只在内容变化时写。
- **`devkit audit`**：正常路径 = 逐包判据 + 根上唯一化汇总；错误 = 有违规退出 1，空输入也退出 1（防假绿）；`--write` 只删未用依赖，不改判据结论。
- **共同**：只读仓库、不发布；两个命令都不读环境变量做隐式配置（`DEEPSEEK_HARNESS_VERSION` 是构建写回的唯一输入，缺失时不写 `engines.dsh`）。

## 六、取舍

| 选项                                          | 否掉的理由                                                                    |
| --------------------------------------------- | ----------------------------------------------------------------------------- |
| 保留 `audit` 与 `tsdown-plugin-cordis` 两个包 | 包发现、汇总、日志要复制两份；命令面也不统一                                  |
| 把 `dts-prepare` 并进来                       | 声明树是独立生成物，`typert-generator` 也共用；并进来会让 devkit 背类型图成本 |
| 把 audit 做成 lint 规则                       | AST 结构判据与 oxlint 的类型规则是两套红灯，混在一起失败原因不可读            |
| 做 `devkit publish`                           | 发布命令归 `justfile`（两条通道）；工具包不持有 registry 凭据                 |
| `devkit build` 只合成配置、不跑构建           | 那样 `just build` 仍是 `pnpm -r` 的包装，包发现与汇总没有 owner               |

## 八、开放问题

- patch 行清单的提取优先级：`dsh-bundle.ts` 里导出 `rows` 字面量供工具静态读；读不到就生成空清单。具体的 `rows` 结构（`id` / `disabled` / 配置对象）由第一个 bundle 包的 `patch.spec.ts` 定。
